# 観点の配役 — 返信前チェック

主に判断を求める前に、必ず次の5手順を通す。過剰エスカレーション（下限違反）は過小と同格以上のプロセス違反。

## 5手順

1. **聖域か** → 自己統治物件（CLAUDE.md・hooks・権限設定）と破壊的操作は無条件で人間承認（観点判定を飛ばす。回復コストが判定できない操作は回復不能側に倒す）
2. **論点に必要な観点を特定する** → カタログの「この観点が要る論点の条件」に順に当て、Yes になる観点をすべて拾う
3. **担い手は主か** → 拾った観点を配役表（project.md → local.md → セッション宣言の順）で辿り、最終的な担い手を確認する
4. **主でないなら送らず自走で決め直す** → 全観点の担い手がエージェントなら、方針文・判断基準に従ってこの場で決める。主に上げるのは担い手が主の観点が1つでもあるときだけ
5. **結果を判例台帳に記録する** → `precedents.md` に観点・経路・帰結・還元を1判例1ブロックで追記する

## フィードバック規則

主から配役へのフィードバックを受けたら、**そのターンで**該当層（project.md / local.md /
セッション宣言）の該当行を更新し、判例台帳に記録する。カタログを変える場合は `casting-set.sh` 経由。

## 正本

- 観点カタログ（14観点・列定義・横断軸・変更手続き）: `plugins/casting/catalog/catalog.md`
- 配役表の作り方・判例の書き方・カタログ変更手続き: `plugins/casting/skills/casting/SKILL.md`
- 配役表の生成: `/casting:init`（`plugins/casting/commands/init.md`）
