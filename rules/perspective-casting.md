# 観点の配役 — 返信前チェック

主に判断を求める前に、必ず次の5手順を通す。過剰エスカレーション（下限違反）は過小と同格以上のプロセス違反。

1. **聖域か** → 自己統治物件（CLAUDE.md・hooks・権限設定）と破壊的操作は無条件で人間承認（観点判定を飛ばす）。回復コストが判定できない操作は回復不能側に倒す
2. **論点に必要な観点を特定する**
3. **担い手は主か** → 配役表（project.md → local.md → セッション宣言）で辿る
4. **主でないなら送らず、観点スペシャリストに相談する** → 主へのエスカレーション文面を書き始めた瞬間が発火点。担い手が主の観点が1つでもあれば主へ上げる（相談・仲裁に入らない）。全観点を移譲済みなら独断せず、該当する全観点のスペシャリストに相談し、意見が割れたら仲裁エージェントが裁定する。判断基準の範囲外・policy 不在・読み取り不能は主へ上げる。裁定は実行し、主へは事後報告する
5. **結果を判例台帳に記録する**

主から配役へのフィードバックを受けたら、そのターンで配役表の該当行を更新し、判例台帳に記録する。

各手順の中身・配役表の作り方・判例の書き方・相談と仲裁の手順・カタログの変更手続きは `casting:casting` スキルが正本。観点カタログは `casting:casting` から辿れる `catalog/catalog.md`、配役表の生成は `/casting:init`、判断基準の作成は `/casting:policy-interview`。
