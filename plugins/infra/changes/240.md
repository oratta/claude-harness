# S16a の走査に残る fail-open 2 経路（find の終了コード・シンボリックリンク）を塞ぐ（#240）

`plugins/infra/tests/infra-fixes.bats` の `check_third_party_pins` に残っていた、検査が黙って合格する 2 経路を塞いだ。

- `find` の出力を一時ファイルに落として終了コードを見るようにした。読めないサブディレクトリがあり `find` が非 0 で終了したら、列挙が不完全で違反の有無を判定できないので、戻り値 3 で fail する（以前は列挙できたファイルだけで合格していた）。テスト S16a-23。
- 走査対象に `-type l` を加え、`.yml.template` のシンボリックリンクはリンク先を追わず、リンク自体を違反（戻り値 1）として報告する。git はシンボリックリンクを追跡できるので、以前は違反入りの外部 yml へのリンクを置くだけで検査を迂回できた。リンク先が無いリンクも同様。テスト S16a-24。
- 戻り値の表に 3（find の列挙エラー）を追加した。
- issue 記載の診断性 3 件（複数の読めないファイルの一括報告・バイナリ検出・改行入りファイル名の表示）は任意項目のため今回は扱っていない。
- version は上げない（commit SHA が版。元の受け入れ条件の「version bump」は本ファイルの記録に読み替え）。
