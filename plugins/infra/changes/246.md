# S16a の uses: 抽出が alias キーと bare CR に対応する（#246 #247）

第三者 action の SHA 固定検査（S16a）の抽出部 `plugins/infra/tests/list-uses.rb` の穴を 2 つ塞いだ。どちらも検査が緩む方向の穴で、テンプレートの展開先は production のデプロイを動かすジョブ。

- alias キー（#246）: `anchors: { k: &u uses }` の後の `- *u: evil/action@v1` は YAML の意味論では `uses` キーで GitHub Actions が実行するが、Scalar のキーしか拾わない実装は 1 行も出さなかった。`uses` の Scalar に付いた anchor 名を先に集め、その anchor を参照する Alias もキーとして拾う。anchor の付け替えは追わず、一度でも `uses` に付いた名前は `uses` とみなす（多く拾う方向）
- bare CR（#247）: libyaml は bare CR も改行として数えるが、`String#lines` と `sed -n` は LF でしか切らないので、行番号がずれて別の物理行のコメントをバージョンコメントに採用していた。行を libyaml と同じ改行判定（CRLF・bare CR・NEL・LS・PS・LF）で切り、違反行の本文も `list-uses.rb` の出力列（コメントの次の 4 列目）に載せて、検査側の `sed -n` の行引きをやめた
- `infra-fixes.bats` に S16a-23（alias キー）と S16a-24（bare CR）を足した。spec の「対象外 — #246」の但し書き 2 箇所を外し、行の切り方の要件を足した

版は上げていない（plugin.json に version キーは無く、commit SHA が版）。
