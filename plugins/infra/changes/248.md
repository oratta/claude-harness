# S16a の spec にコメント境界の解釈 2 件と NUL 区切り列挙を書く（#248）

`openspec/specs/infra-actions-freshness/spec.md` の「Every third-party `uses:` ... version comment」Scenario に、実装が既に取っている解釈を 3 点足した。実装（`list-uses.rb`）とテストは変えていない。

- `uses:` のキーと値が別行のとき、「同じ行のコメント」は値のある行のコメント
- 値の行で開いて次行で閉じる flow collection の内側の `#` は、その値の行のコメントとして境界の判定対象になる。`origin/main` から変わらない挙動で、「実装で除外」ではなく「spec に書く」を選んだ（YAML 文法上は本当に値の行のコメントで、除外すると行を跨ぐ位置追跡が増えるだけ）
- ファイル列挙が NUL 区切り（S16a-19）で、改行入りファイル名のテンプレートを落とさない

`infra-fixes.bats` の戻り値コメントの `3` は #248 の着手時点で既に消えていた。要件が実装ファイル名 `list-uses.rb` と `ruby -ryaml` を名指ししている件は、Scenario を再現可能にする役に立つため直さない判断のままで、記録のみ。

版は上げていない（commit SHA が版）。
