# S16a の走査がディレクトリへのシンボリックリンクの下を読み飛ばすのを塞ぎ、テスト ID の重複を直す（#900）

PR #636（#240）のレビューで残った指摘の後始末。配布される実行物は変えていない（変えたのは `plugins/infra/tests/infra-fixes.bats` の検査と、その記録・spec）。

- `check_third_party_pins` の `find` を `\( -type l -o \( -type f -name '*.yml.template' \) \)` にした。`find` は既定でシンボリックリンクのディレクトリに降りないので、以前はディレクトリへのリンク（名前が `*.yml.template` でないもの）が列挙されず、その下の違反テンプレートが読まれないまま合格していた。走査対象の下にあるシンボリックリンクは、名前とリンク先の種類を問わず、リンク自体を違反（戻り値 1）として報告する。テスト S16a-27（名前が違うディレクトリへのリンク）・S16a-28（名前が違うファイルへのリンク・名前が違うリンク切れ・名前が `*.yml.template` のディレクトリへのリンク）。
- #240 で足したテスト 2 件の ID が、#246・#247 で足したテスト（S16a-23・S16a-24）と重複していたので、S16a-25（読めないサブディレクトリ）と S16a-26（シンボリックリンクのテンプレート）に振り直した。`changes/240.md` の ID も揃えた。
- `openspec/specs/infra-actions-freshness/spec.md` に、列挙が失敗したら fail する条件と、シンボリックリンクを違反にする条件を足した。
- `check_third_party_pins` の `local` の変数の並びを `read` の列の順（`comment body value`）に戻した。
