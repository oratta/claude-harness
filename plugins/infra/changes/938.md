# zsh でグロブが当たらないとinfra-phase-4 エージェント定義の探索ループが止まる不具合を直す（#938）

`plugins/infra/agents/infra-phase-4-github-actions.md` の探索ループは、`~/.claude/plugins/marketplaces/*/…` と `~/.claude/plugins/installed/*/…` の glob を `for` の単語に直接並べていた。zsh は glob が 1 件も当たらないと `no matches found` でコマンドごと失敗する。bash は一致なしを文字列のまま残すので止まらない。同じ bug を `/cost` で直した #913（PR #934）と同じ直し方にそろえた。

- 探索をループの直前に、zsh で `nullglob` が未設定のときだけ（判定は `[[ ! -o nullglob ]]`）`setopt nullglob` し、ループの直後に `unsetopt nullglob` で戻す（利用者が元から設定していれば触らない）。`[[ ]]` は `[ -n "${ZSH_VERSION:-}" ]` の短絡で bash・sh・dash では評価されない。変数名は `INFRA_NG`。ループの形（行頭の `for dir in`）と探索の順番、見つかったときの結果は変えない
- 検査は新規 `plugins/infra/tests/phase4-search-zsh.bats`（文書から `for dir in` を含む bash ブロックを取り出し、一時 HOME で、候補なし・空・installed だけに当たりの 3 通りを zsh と bash で。加えて zsh で、nullglob が元から無効なら無効・有効なら有効のまま。zsh が無い環境では skip）。CI（ubuntu）には zsh が無いので zsh の経路は CI で検査されない（手元で実測）
- 戻し方: 追加した 3 行（`INFRA_NG=…` ・`if [ -n "$INFRA_NG" ]…`・`unset INFRA_NG`）を消し、新しい bats を消す
