# secret-guard の Read の判定をファイル名に絞る (#1488)

Read の判定対象を、パス全体からファイル名（パスの最後の要素。末尾の `/` は先に取り除く）に絞った。`credentials-service/` や `.env/`（仮想環境のディレクトリなど）の下のふつうのソースファイルが止まらなくなる。ファイル名に当てる語とテンプレート類（`.env.example` など）の規則は変えていない。Bash の機密ファイル表示（`cat <path>`）の判定も変えていない。

## 止まり続けるもの・通るようになるもの

- 止まり続ける: `.env`、`credentials.json`、`*.token`、末尾に `/` を付けた `/x/.env/`。ファイル名に機密らしい語を含む `credential-guide.md`、`process.env.ts`、`credentials.ts` も止まる（ファイル名だけでは中身に値があるか区別できない既知の止めすぎ）。これらの誤検知の逃げ道は、これまでどおり hook の環境変数 `CAPABILITY_REGISTRY_SECRET_GUARD=off` だけ
- 通るようになる: `/x/credentials-service/src/index.ts`、`/x/.env/lib/site.py`
- 新しく止まる: パスの途中に `example`/`template`/`dist` を含む機密の形のファイル（`/x/foo.template/.env`、`/x/foo.template/credentials.json`、`/x/app.dist/.env.production`）。今まではパス全体にテンプレート類の語が当たって通っていた
- 値が画面に出る抜け道が増える: 機密らしい語がディレクトリ名にだけあるファイルの Read が通る。`/x/config/credentials/production.key`、`legacy_credentials/<account>/adc.json`、`~/.credentials/calendar.json`、`/x/service-account/prod.json`、`/x/.env/prod`、`/x/.env.d/db`。検査はセキュリティ境界ではなく、穴を塞ぎ切ることは完了条件にしていない。仕様の「検査の守備範囲」で通すことを許す一覧に足した。Bash が止めて Read が通るファイルがあるので、Bash で拒否されたあとに Read へ切り替えると値が出る場合がある

## 手で配線した旧 hook が残る環境

`~/.claude/settings.json` に手で配線した旧 secret-guard が残る環境では、旧 hook がパス全体で判定する。片方でも拒否すれば止まるので、この変更の効果は出ない（`/x/credentials-service/src/index.ts` は止まり続ける）。通常のセッションでは動作確認にならない。確認は `changes/1233.md` の手順 2 と同じ `claude -p --setting-sources project --plugin-dir <更新後のプラグインのパス>` で行う。旧 hook を外す手順は `changes/1233.md`。
