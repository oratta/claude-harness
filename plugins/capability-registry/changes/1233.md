# secret-guard をプラグインの hook で配る (#1233)

シークレットの値が画面（transcript）に出る形の Bash と Read を実行前に止める hook を追加した。これまで主の端末の `~/.claude/hooks/secret-guard.py` を `~/.claude/settings.json` で手で配線していたものを、capability-registry を入れるだけで有効になる形にした。`settings.json` の編集は要らない。

- 追加した部品: `scripts/secret-guard.sh`（無効化のスイッチと python3 の有無を見て本体を起動する。全経路 exit 0）、`scripts/secret-guard.py`（判定の本体）、`hooks/hooks.json` の `PreToolUse` の `matcher: "Bash|Read"` のエントリ、`plugin.json` の keywords の `secret-guard`
- 判定は移す前の hook と同じ。既知の止めすぎも見逃しも変えていない。既知の止めすぎは、ヒアドキュメントの本文の行をコマンドとして読むことと、パスのどこかに機密らしい語を含むファイルの Read を止めること（`credentials.ts` も、`credentials-service/` の下の全ファイルも。パスの途中のディレクトリ名でも止まる）。Read の拒否の理由には、誤検知のときに無効化の環境変数を利用者に相談する案内を足した
- 外した検査: `fmtoken.sh` の裸実行を止める分岐。個人の道具 1 本に専用の検査なので公開版に持ち込まない
- 無効化: hook プロセスの環境変数 `CAPABILITY_REGISTRY_SECRET_GUARD=off`（`settings.json` の `env` か起動時の環境で設定する）。コマンド文字列の前置きでは効かない。値を確かめるときは `[ "$CAPABILITY_REGISTRY_SECRET_GUARD" = off ] && echo disabled` と書く（`echo` で値を出す形はこの hook 自身が止める）
- python3 が無い・stdin が読めない・検査が例外で落ちるときは素通りする（fail-open）

## 手で配線した環境から外す手順

手の配線を外すと、`fmtoken.sh` の裸実行は止まらなくなる。そのため、次の順で進める。

1. この変更がマージされ、プラグインの更新が端末に届くのを待つ
2. 公開の hook の動作確認をする。capability-registry が有効なことを確かめ、手の配線を読まない条件（`claude -p --setting-sources project --plugin-dir <更新後のプラグインのパス>`）で `echo "$GH_TOKEN"` 相当が止まることを確かめる。手の配線が残った通常のセッションで止まっても確認にならない
3. 次のどちらかが成り立つまで手の配線を残す。個人版の代替の検査が有効になったことを確かめた、または `fmtoken.sh` の裸実行を止める保護を廃止すると本人の判断が確定した
4. 3 が成り立ったあとで、`~/.claude/settings.json` の `PreToolUse` から secret-guard のエントリを外し、`~/.claude/hooks/secret-guard.py` を消す

移行の間は手の配線とプラグインの hook が二重に走る。どちらも読み取りだけで、拒否は片方で足りる。拒否の理由が 2 回出ることと、python3 の起動が 1 回増えることのほかに害は無い。

戻し方: 手の配線を戻す。プラグインの hook だけを止めるなら `CAPABILITY_REGISTRY_SECRET_GUARD=off` を設定する。
