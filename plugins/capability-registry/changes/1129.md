# 個人版の部品を個人版のリポジトリのプラグイン capability-registry-oratta へ移す（#1129）

オーナーの 1Password の保管庫とトークンの取り出しにかかわる部品を、個人版のリポジトリ `oratta/claude-harness-oratta` の新しいプラグイン `capability-registry-oratta` へ写し、公開版から消した。写し元の公開版の commit は `647caaf088409abc68cc8c45587b1310e31e34f7`。公開版の capability-registry と同時に入れられるように、別の名前のプラグインにした。

移した部品と移した先（個人版のリポジトリの中のパス）:

- `scripts/fmtoken.sh` → `plugins/capability-registry-oratta/scripts/fmtoken.sh`
- `tests/fmtoken.bats` → `plugins/capability-registry-oratta/tests/fmtoken.bats`
- `skills/capability-registry/1password.md` → `plugins/capability-registry-oratta/skills/capability-registry-oratta/1password.md`
- `skills/capability-registry/SKILL.md` の節「表記規約（生成文にも適用すること）」「資格情報の階層（どこに置くかはプロジェクトごとに決めない）」（下の小節「ブラウザで捕獲した資格情報を env から昇格させる」を含む） → `plugins/capability-registry-oratta/skills/capability-registry-oratta/SKILL.md` の同じ見出しの節
- 仕様 `openspec/specs/capability-registry-fmtoken` → 個人版の `openspec/specs/capability-registry-fmtoken`（公開版からは archive の直前に消す）

公開版で直したもの:

- SKILL.md から 2 節を消し、原則に「env から恒久の置き場へ移す手順と、prod の書き込みキーの置き場も、オーナーの環境の索引（個人版）があればそちらを見る」を足した（`rules/browser-infra-env-capture.md` がこのスキルを昇格の手順の正本として案内しているため）
- `stripe.md` の「SKILL.md の「資格情報の階層」」への参照を、個人版があればそちらを見る書き方にした
- `tests/skill-registry.bats` は 2 節を切り出さず SKILL.md の全体を見る

オーナーの切り替えでは、個人版の marketplace を足したあと `capability-registry-oratta` を install する（手順の全体は `plugins/dev-workflow/changes/1218.md`）。公開版の capability-registry は入れたままにする。
