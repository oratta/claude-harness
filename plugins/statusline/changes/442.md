# active 行が記録を読まないことを確かめるテストを、回帰を検出できるようにする（#442 の 2 つ目）

`plugins/statusline/tests/statusline-multi-account.bats` の「active スロット自身の記録はライブ値を置き換えない」テストは、事前に置いた記録（週次 77%）が statusline の描画の前の記録書き込み（stdin の値での上書き）で消えるため、active 行が誤って記録を読む実装に変わっても通っていた。

- 記録を置いたあと記録ディレクトリを書き込み不可にして走らせ、上書きされず 77% が残ったまま描画されることを確かめたうえで、active 行が stdin の値（20%）で 77 を含まないことを検査する。teardown で権限を戻す。root など書き込み不可にできない環境では skip する。あわせて `setup()` に `export LC_ALL=C.UTF-8` を足した
- 変異確認: active スロットも記録・snapshot の突き合わせに回し、active 行をその結果で描く変更を入れると、新しいテストは落ち、変更前のテストは通ったままだった。確認後に戻した
- statusline.sh 本体は変更していない。版は上げない
