# accounts.json で Codex がオフなら Codex 行に off を出し、取得しない（#978）

`accounts.json` のトップレベルに `codex.enabled`（真偽値、省略時はオン）が足された（定義、置き場所を `accounts.json` にした理由、develop とレビューでの扱いは `plugins/dev-workflow/changes/978.md`）。ステータスラインは登録簿を自前で読んでいるので、同じ意味で読むようにした。

- `scripts/statusline-codex.py`: 最初に登録簿（`CLAUDE_ACCOUNTS_FILE`、未設定なら `${CLAUDE_CONFIG_DIR:-~/.claude}/accounts.json`）の `codex.enabled` を読む。JSON の `false`（オフ）なら `off` の 1 行だけを出して終わり、Codex CLI を起動せず、`.statusline-codex` のキャッシュも読み書きしない（残っているキャッシュは消さない）。`--refresh` で呼ばれたときは何も出さずに終わる。`dev-workflow` の `usage_view.py` は読まない（プラグインをまたいで依存しない）
- オフの判定を認証の確認より先に置いたので、Codex にログインしていなくても `off` は出る（オフにしたことを画面で確かめられる）
- `scripts/statusline.sh`: `off` を受け取ると、取得待ちの行と同じ組み立て（`Codex` のラベル・label 列の幅・DIM）で `  Codex  off` の 1 行を出す
- `STATUSLINE_CODEX=0` は従来どおり行そのものを出さず、オフの設定より優先する
- `codex` を書いていない登録簿、および `false` 以外の値（`true`・`"false"`・`0`・`null`）を書いた登録簿では、出力は 1 バイトも変わらない
- `README.md` の「Codex の利用上限」の節に、オフの書き方と `off` の表示を足した
- 戻し方: 利用者側は `codex` のキーを消すか `enabled` を `true` にする。コードはこの PR の差分を戻す
