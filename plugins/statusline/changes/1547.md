# 5 時間枠が返らなくても Claude の 7d の行を描き、snapshot と記録を書く（#1547）

Claude のアカウントで、サーバーの返すリミット情報から 5 時間枠が無くなった（2026-11-01 に実測）。`statusline.sh` は 5 時間の値があることを前提にしていたため、週次の値があっても Claude の行が丸ごと消え、`.rate-limit-snapshot` とセッション記録の更新も止まっていた。

## 変えたこと

- `scripts/statusline.sh`: snapshot・共有 snapshot・セッション記録を書く条件を「5 時間枠か週次の使用率のどちらかがある」にした。無い枠は `null` で書き、キーは省かず、0 も作らない
- `obs_sig` と記録の前回値の署名は、5 時間が無いと先頭が `null` になる。同じ週次の値の再表示では `observed_at` は進まず、5 時間枠が戻れば新しい観測として書かれる
- `render_slot`: 週次の値があれば、5 時間の値が無くても `7d All` の行（`Fable` の区画・残り時間を含む）を描く。`5h` の行は出さない。経過時間とリセット権の区画は `7d All` の行に付く
- `.headroom.json` の値を使える判定（`hr_use`）から 5 時間の値の要否を外した。週次だけのときもロケットモードとリセット権の表示が出る。週次だけのスロットで初めて値を使えるときは、他の Claude の行と Codex の行にも既存の規則どおり列が空く
- 複数アカウント時の `取得待ち` は、5 時間も週次も無いときだけにした
- `README.md`: 書く条件・`null` は欠測で 0 ではないという読み手との契約・5 時間枠が無いときの描画を足した
- テスト: `tests/` の bats 4 ファイルに週次だけの入力のケースを足した。読み手の動きを固定するテストは `plugins/dev-workflow/tests/` の `test_usage_view.py`・`test_headroom.py`・`usage-probe-reset-grants.bats` に足した

## 変えていないこと

- 読み手のコード（`usage_view.py`・`headroom.py`・`usage-probe.sh`・`select-account.sh` など）。読み手は `null` に耐えることをテストで固定しただけ
- すべてのスロットに 5 時間枠と週次の両方があるときの出力と書き出す内容、`obs_sig` の文字列
- `5h` の行のコードと `five_hour_*` のキー。5 時間枠の廃止が恒久か一時的かは不明なので、値がまた返れば元の表示に戻る

## 未確認の点

- Claude Code が status line に渡す生の stdin は取得していない。`rate_limits.seven_day.used_percentage` が来る前提が外れると、この修正では直らない。マージ後に `.rate-limit-snapshot` の更新が再開するかで確かめる

## 連携先の読み手

連携先の読み手は `five_hour_pct` の `null` で落ちないが、判定ログには使用率 0.0 と出る。これは `rate-snapshot` の契約（`null` は欠測で 0 ではない）に反するので、連携先の issue で直す。判定は 5 時間では止めず 7d が効くので、この修正のマージは待たせない。

## 戻し方

この PR の差分を戻す。既に書かれた `null` の snapshot と記録は読み手が欠測として読むので、消す必要はない。
