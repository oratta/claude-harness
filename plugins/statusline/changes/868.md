# 868: プロンプトキャッシュ区画のテストの穴を埋める

#714 のレビューで出た、マージを止めない指摘を `statusline-prompt-cache.bats` に反映した。実装（scripts）と仕様は変えていない。

- 「prompt_cache 無し」の否定検査を 2 行目以降（`tail -n +2`）に限定した。1 行目の一時ディレクトリのパスに `Cache` が含まれる環境（例: Linux で `TMPDIR` が `Caches` を含むパスの下。macOS では `mktemp -d` が `TMPDIR` を使わないので再現しない）で落ちていた
- 区画が API の区画より前に並ぶこと、`STATUSLINE_PROMPT_CACHE` が 0 以外（1・2・off）で区画が出ること、`causes` の 2 件目以降が文字列でなくても件数に数えることを検査するテストを足した
- 色の検査を 2 行目全体のエスケープ列の比較にした（数値だけの色分けも検知）
- 改行で終わる原因名を「原因の形が壊れている」の入力に足した
- 「従来と同じ出力」の比較をファイル＋`cmp` に変えた（末尾の改行の違いも検知）。基準出力は行数も固定した
- 並び順のテストで `STATUSLINE_SESSION_COST=1` を明示した。README の検査は環境変数の表の行に絞った
