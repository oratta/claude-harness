# 手を入れていないコピーはセッション開始時に新しい版へ揃え、手を入れたコピーには「更新あり」を出す（#1113）

`/statusline:setup` は本体を `<config>/statusline.sh` と `<config>/statusline-codex.py` にコピーして使う作りで、プラグインを更新してもコピーは古いまま残っていた（主の Mac では 2026-09-26 のコピーが動き続け、#976・#714・#978 が効いていなかった）。コピーを、利用者が手を入れていないものと手を入れたものに分けて扱うようにした。仕様は `openspec/changes/statusline-copy-auto-update/`（archive 後は `openspec/specs/statusline-copy-update/spec.md`）。

- `scripts/install.sh`: コピーを置いたあと（書き換えなかった実行でも）、2 つのコピーの SHA-256 を `<config>/.statusline-installed` に `<sha256>  <ファイル名>` の 1 行 1 件で書き、`<config>/.statusline-update-available` があれば消す。`--dry-run` ではどちらもしない。`shasum` も `sha256sum` も無い環境では警告を出して記録を書かない
- `hooks/hooks.json`（新規）と `scripts/statusline-update-hook.sh`（新規）: SessionStart（`startup|resume|clear`）で、コピーごとに次のとおり動く
  - プラグインの本体と同じ → 記録をその内容に合わせる
  - 本体と違い、記録どおり（手を入れていない）→ 黙って本体で置き換え、記録を書き直す
  - 本体と違い、記録と違う・記録が無い（手を入れた、またはこの仕組みより前に入れた）→ 上書きせず、印 `<config>/.statusline-update-available` にファイル名を書く。印を読めない古いコピーのときだけ、`systemMessage` で `/statusline:setup` を案内する
  - インストール済みのプラグイン（実体のパスが `<config>/plugins/` の下）から起動されたときだけ動く。`claude --plugin-dir` で読み込んだ開発中の版では何もしない。どの失敗でも exit 0 で、標準エラーは出さない。python3 は起動しない
- `scripts/statusline.sh`: 印があるとき、1 行目の末尾に `更新あり /statusline:setup` を足す（ファイルの有無だけを見て、描画のたびにハッシュは取らない）。印が無いときの出力は 1 バイトも変わらない。表示の中身（名前・オフ・リセット権など）は変えていない
- `plugin.json` は変えていない（`hooks/hooks.json` は既定の場所として自動で読まれる）
- `README.md` の「導入」「本体のセッションコストの記録」「カスタマイズ」「テスト」の節と、`commands/setup.md` の報告の案内を直した
- 利用者側: 今あるコピーは記録が無いので「更新あり」（古いコピーではセッション開始時の案内）が出る。一度 `/statusline:setup` を打ち直せば、以後は自動で揃う
- 戻し方: 利用者側は `<config>/.statusline-installed` を消せば自動の置き換えは止まる（全部「手を入れた」扱いになり、更新ありが出るだけになる）。コードはこの PR の差分を戻す
