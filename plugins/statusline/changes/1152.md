# /statusline:setup の探索が、名前順で先の古い marketplace dir を拾わないようにする（#1152）

`plugins/statusline/commands/setup.md` 手順 1 の探索ループは、`CLAUDE_PLUGIN_ROOT`（slash command の本文では空）の次に `~/.claude/plugins/marketplaces/*/plugins/statusline` を名前順に見ていた。旧運用の worktree の残り（例 `claude-harness-burn-63`。`.git` の指す先が無く壊れている）が `oratta-claude-harness` より先に並び、古い `install.sh` で `~/.claude/statusline.sh` を上書きしかねなかった。

- 候補の順を `CLAUDE_PLUGIN_ROOT` → `~/.claude/plugins/marketplaces/oratta-claude-harness/plugins/statusline`（固定）→ marketplaces の glob → installed の glob に変えた。glob は残し、固定候補が無い環境の最後の手段にする。`installed_plugins.json` の `installPath` は jq への依存と版の読み分けが増えるので採らない
- 同型の探索（dev-workflow・cost-ledger・worktree・casting・infra）は子 issue #1480 で扱う。この変更では触らない
- 検査: `plugins/statusline/tests/setup-command-zsh.bats` に、`aaa-stale` と `oratta-claude-harness` を並べた HOME で固定候補が選ばれること（zsh・bash）と、固定候補が無ければ glob で見つかることを足した
- 戻し方: setup.md の固定候補 1 行と、足したテストを消す
