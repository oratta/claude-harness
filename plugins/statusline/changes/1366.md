# statusline-multi-account.bats の teardown で rm -rf が競合する flaky を直す（#1366）

テスト「name: the codex.label row never becomes a slot」などが、ときどき teardown の `rm -rf "$WORK"` で `Directory not empty` で落ちていた。

- 原因: `codex_name_env` が書くキャッシュの `next_attempt` が 4102444800（2100 年）だった。`statusline-codex.py` の `read_json` は `next_attempt` が now+TTL(180)+5 を超えるキャッシュを破損扱いにして `{}` を返す。そのため描画のたびに `--refresh` の子プロセス（`start_new_session=True`）が起き、`atomic()` の `mkstemp` が `$WORK` 内に一時ファイルを書く。子はテスト終了後も残り、teardown の `rm -rf` と競合した
- 修正: テストの `next_attempt` を `int(time.time()) + 100`（範囲内）にした。変更はテストファイルだけで、スクリプトの振る舞いは変えていない
