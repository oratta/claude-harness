# オフのアカウントと Codex をステータスラインから消す（#1112, #1006）

`accounts.json` で `enabled: false` にした Claude アカウントと、`codex.enabled: false` の Codex を、`off` の行も含めてステータスラインに出さないようにした。#976・#978 の変更記録（`plugins/statusline/changes/976.md` / `978.md` / `1111.md`）にある「`off` の 1 行を出す」という説明は、この変更で上書きされた。

- `scripts/statusline.sh`: active の判定はオフを含む登録簿の全スロットで行い、そのあとで表示対象（active、またはオン）を決める。非 active のオフスロットは行を出さず、複数アカウント表示の判定と名前列の幅にも数えない。表示対象が 1 つなら従来の 1 アカウント表示（名前列も `▸` も無い）に戻る。オフでも active のアカウントはライブ値で出す。Codex helper が返す内部の `off` は、列幅の算出より前に捨てる（helper の出力と取得停止は変えない）
- `tests/`: オフの行が出ないこと、A と B が両方オフで A が active なら A だけの 1 アカウント表示になること、オフの B が active なら 2 アカウント表示に戻ることを検査する
- `README.md`（statusline・dev-workflow）: オフ時の表示を更新。#1006 として、登録手順を `CLAUDE_SECURESTORAGE_CONFIG_DIR` 未設定のシェルでの `accounts-init.sh --id a --label A`（`add b` の前）から始め、各コードブロックを単独で実行できる形（`$SCRIPTS` / `CLAUDE_HARNESS_SCRIPTS` の定義つき）にした
- 反映: 記録のある手を入れていないコピーは、次のセッション開始時に自動で揃う（#1113）。記録の無い古いコピーと手を入れたコピーは `/statusline:setup` の打ち直しが要る
- 戻し方: この PR の差分を戻して `/statusline:setup` を再実行する。登録簿の移行は無い
- #980 には、表示条件が `off` の行から「行を出さない」に変わったことをリンクで知らせる
