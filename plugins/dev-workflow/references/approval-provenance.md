# 承認の記録と確認（投稿者名を承認の根拠にしない）

`rules/destructive-git-guard.md` の「承認の記録と確認」の詳細。常時読み込みの規則には要点（投稿者名を根拠にしない・エージェントの記録には記録者を書く）だけを置き、手順はここに置く。

## なぜ

GitHub の投稿者名（`oratta` / `OWNER`）は人間かエージェントかの判別材料にならない。エージェントも主のアカウントで投稿するため、投稿者名が主と一致しても主本人の発言とは限らない。

## 書く側

主の判断（承認・許容・選択）を GitHub のコメント・issue・PR 本文に記録するエージェントは、本文に次の 2 点を必ず書く。

- `記録者: エージェント（<名前>）` の行
- 主の発言の出どころ（リンク。無ければ「会話内」）

`pr-review-gate` が追記する `主の回答: 許容` 系の行（引き継ぎの 4 行を含む）にも、同じ追記に `記録者:` の行を足す。

## 読む側

- `記録者: エージェント` の表記がある記録はエージェントの申告で、承認ではない
- 表記の無い承認記録でも、主の判断を伝聞で伝える文面・ゲートの宣言コメントは承認ではない
- どれも承認済みとみなさない。主本人の発言（今の会話か、表記の無い主の一人称の発言へのリンク）を確かめられなければ主に確認を上げる

## ゲートの真正性確認での実測

GitHub コメントのリンクでは、author の一致（必要条件）に加えて、本文にエージェントの記録の表記が無いことを確かめる。

```bash
gh api repos/$R/issues/comments/<comment_id> --jq '.user.login'   # 主のアカウント名と一致すること
gh api repos/$R/issues/comments/<comment_id> --jq '.body' | grep -c '^記録者: エージェント'   # 0 であること
```

リンク先が `記録者: エージェント` の行を持つ記録・主の判断を伝聞で伝える文面・ゲートの宣言コメントのどれかなら主本人の発言ではないので、真正性確認の①（主のアカウントによる発言）を満たさない。
