# 禁止語検査（forbidden-words-check.sh）

公開側のリポジトリに、オーナー固有の名前（辞書に登録した語）が混ざっていないかを調べる共有スクリプト `plugins/dev-workflow/scripts/forbidden-words-check.sh` の使い方と規則。plugin として install されていなくても、リポジトリの clone か checkout のパスから直接呼べる（`CLAUDE_PLUGIN_ROOT` に依存しない）。仕様の正本は openspec の capability `dev-workflow-forbidden-words-check`。

## 呼び出しの形

検査するファイルの一覧を標準入力に 1 行 1 パス（`--root` からの相対）で渡す。何を検査対象の集合にするかは呼び出し側が決める（このスクリプトは渡された一覧を検査するだけ）。

```
printf '%s\n' <ファイル一覧> | bash plugins/dev-workflow/scripts/forbidden-words-check.sh \
  --root <検査 root> --dict <辞書> [--dict <辞書>...] [--allow <allow>...] [--name <名前>] [--count-file <ファイル>]
```

| 引数 | 内容 |
|---|---|
| `--root <dir>` | 必須。検査の cwd。`--dict`・`--allow`・`--count-file` の相対パスもここから解く |
| `--dict <file>` | 1 回以上。複数回指定でき、引数の順・各ファイルの行の順に連結する（重複する語も保持する。同じ語が 2 つの辞書にあれば当たりは 2 件出る） |
| `--allow <file>` | 0 回以上。複数回指定できる。ファイルが無ければ何もしない |
| `--name <名前>` | 任意。既定 `forbidden-words-check`。`gh` が引けないときの通知の先頭に使う |
| `--count-file <file>` | 任意。違反の件数を 10 進数 1 行で書く（0 件でも `0`）。呼び出し側が自分の違反と合算して「違反 N 件」を出すために使う |

環境変数 `FORBIDDEN_WORDS_NO_GH` が空でなければ `gh` を呼ばない（期限付き allow の書式と未使用の検査だけを行う）。`gh` は呼び出し元の PATH から探し、`--root` を cwd にして呼ぶ。

終了コード: 違反が無ければ 0、あれば 1、引数の誤りなら 2。`--count-file` に書けないとき（ディレクトリを指すなど）も、違反の有無によらず 2 で、`<名前>: 件数を書けない: <パス>` を標準エラーに出す（件数が呼び出し側に渡らないまま 0 や 1 で終わらないため）。違反は 1 件 1 行で標準エラーに出し、標準出力には何も出さない。

## 辞書の書式と照合の規則

1 行 1 語の固定文字列。空行と `#` で始まる行は無視する。大文字小文字を区別しない部分一致で、一覧の各ファイルの本文とパス名の両方に当てる。バイナリの本文は見ない。

違反の文面（表示する語は辞書に書かれたとおりの大文字小文字）:

- 本文の当たり: `<パス>:<行番号>:<語>`
- パス名の当たり: `<パス>:path:<語>`
- 辞書が無い・読めない: `<辞書のパス>: 無い` / `<辞書のパス>: 読めない`
- 読めないファイル: `<パス>: 読めない`

出す順序は、辞書の読み込み、allow の書式、ファイルごとの当たり、未使用の allow、issue の状態の順。

## allow の 2 種類の書式

1 行 1 件で `<path>:<語>:<第 3 欄>`。`<path>` は一覧のパスと完全一致、語は大文字小文字を区別しない。空行と `#` で始まる行は無視する。第 3 欄（2 つ目の `:` から行末まで）で種類が決まる。

| 種類 | 書式 | 許す範囲 | 有効期間 |
|---|---|---|---|
| 期限付き | `<path>:<語>:#<issue番号>` | そのファイルの中のその語の当たり（本文の全行とパス名）をすべて | issue が OPEN の間だけ有効。CLOSED なら違反 |
| 恒久 | `<path>:<語>:=<行に含まれる固定の文字列>` | その語に当たった本文の行のうち、その固定の文字列を含む行だけ（パス名の当たりは許さない） | 期限なし。issue は引かない |

使い分け: 「いつか直す」予定の当たりは期限付きにして、直す issue を引く。出典や互換のために恒久的に残す当たり（過去の issue 番号の引用、互換のために残す識別子など）は恒久にして、残す行を固定の文字列で特定する。恒久の固定の文字列は `:` や `#` を含んでよい。

どちらの種類も、どの当たりも打ち消していない行は「何も打ち消していない」違反になる（許可の鮮度を保つ）。`#<issue番号>` と `=` の形のどちらでもない行は書式違反になる。

## 基準をコメント行に書く

恒久の行を足すときは、その直前の `#` で始まるコメント行に基準（出典・互換など、なぜ残してよいか）を書く。スクリプトは基準を検査しない。基準が許可の根拠として足りるかは人のレビューが見る。

## 検査の保証と責務

この検査の保証は「辞書に登録した語の混入を止める」までである。辞書の網羅（どの固有名を登録するか）、ファイル一覧の範囲の正しさ、辞書にない固有名や文の良し悪しは検査しない。辞書の整備と一覧の選定はリポジトリ側の責務で、人のレビューが見る。

公開リポジトリに置く辞書には、新たに固有名を足さない（辞書自体が固有名の一覧になるため）。個人版の辞書は公開リポジトリに置かず、`--dict` を 2 回指定して引数で足す。
