# owner-reply-check で圧縮後の要約の行を主の発言から除く（#756）

`owner-reply-check.sh` は、pr-review-gate が会話で受けたリスク許容の返事を「主の発言として会話ログに実在するか」で確かめる。会話の圧縮後にモデルが書いた要約の行は `type: "user"` で `isMeta` も `origin` も無いため、これまでの 7 条件をすべて通り、主の発言として数えられえた（PR #748 / issue #721 の 2 周目レビューの残差）。要約は過去の会話をモデルが言い換えた文なので、主が言っていない許容の言い回しが入りうる。

- `plugins/dev-workflow/scripts/owner-reply-check.sh`: 主の発言の判定に 8 条件目「`isCompactSummary` が true でない」を足した
- `plugins/dev-workflow/tests/owner-reply-check.bats`: 要約の行を通さない回帰テストを、本文の書き出しが違う 2 形で足した。`isCompactSummary: false` の行は通すテストも足した
- spec `dev-workflow-owner-reply-check`: 条件の列挙を ①〜⑧ にし、守備範囲の「7 条件」を「8 条件」にした

**本文の書き出しではなく属性で判定する。** 直近 14 日の実ログでは、要約 3 件のうち 2 件が `This session is being continued from a previous conversation` で始まり、1 件が `<artifact-content-authored-by-others/>` で始まっていた。書き出しで判定すると後者が漏れる。`isVisibleInTranscriptOnly: true` も要約の行に付いていたが、要約以外にこの属性が付くかを確かめていないので、除く材料にしていない（この属性だけが付いた行は主の発言として通りうる）。

呼び出し側（`skills/pr-review-gate/stages/pass.md` 手順 5・`hold.md` 手順 3-c）の手順と出力の形式は変わらない。要約の行が `MATCH:` に出なくなるだけである。
