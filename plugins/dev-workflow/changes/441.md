# main の取り込みだけで HEAD が動いたとき、前の HEAD の許容を引き継ぐ（#441）

pr-review-gate は取り直しのたびに main をブランチへ取り込んでから対象 HEAD を固定する。主がリスクを許容した PR でも、main の取り込みで HEAD が動くと新しい HEAD の宣言は回答リンクを持たず、中身が同じリスクを主に聞き直していた（PR #428 で 2 回起きた）。

- `scripts/risk-carryover-check.sh [--base <ref>] <前 HEAD> <新 HEAD> <根拠ファイル>...` を足した。ローカルの git だけを読み、差分が main の取り込み（2 親の merge commit で、第 2 親が base の祖先）だけか、衝突解消が許可リスト（`marketplace.json`・`plugins/<名前>/.claude-plugin/plugin.json` の `"version"` 行と `CHANGELOG.md` の並べ直し）に収まるか、根拠ファイルが前後で同一かを判定する。終了コード 0 = 引き継げる / 1 = 引き継げない / 2 = 引数・環境の不備（git 2.38 未満を含む）
- pr-review-gate SKILL.md 手順 3 の「主のリスク許容が必要」の雛形に `- 根拠ファイル:` の行を足した。この行の無い宣言からは引き継げない
- 手順 3-c を足した。前の宣言は `主の回答: 許容` 系の行と `真正性確認: 済` の両方を持つ最新 1 件。スクリプトの終了コード 0・根拠ファイルの行・元の直接の回答の真正性の再確認・`対象 HEAD:` 行を除いた本文の一致がすべて揃ったときだけ、`主の回答: 許容（引き継ぎ）` ほか 4 行を追記して主に聞かずに進む。省けるのは主への質問だけで、レビュー・動作確認の証拠・仕様宣言は新しい HEAD で出し直す
- 手順 5 の合格条件の表に引き継ぎで許容済みの行を、手順 6 の復帰の表と `gate-runner.md` の再開節に 3-c への参照を足した

`対象 HEAD:` 規約と auto-merge workflow は変えていない。
