# develop: reap が残したワークツリーを、親が価値を確かめて消すか残すか決める（#1095）

親の片付け（`epic-dispatch.sh reap`）が `kept <N> <理由>` で子のワークツリーを残したとき、develop の SKILL.md は「オーナーの判断に残し、手で消し直さない」としていた。2026-10-19 に親がこれに従い、マージ済みで未コミットの無いワークツリーを消すかを主に聞いて、「論点が無いのに聞くな」と言われた。

- `skills/develop/SKILL.md` Orca 経路の手順 3: `kept <N> <理由>`（`not-done` を除く）を、親が主に聞かずに確かめて決める。確かめるのは、`git status --porcelain` が空かつ `LLM/` が無いこと、HEAD が `launch` の起点ブランチ（`EPIC_DISPATCH_BASE`／`--base`、既定 main）のリモートの先端かマージ済み PR の HEAD に入っていること（squash は tree の一致）
- 満たせば `orca worktree rm --worktree path:<path>`（`--force` なし）で消し、エピックに `子 #N のワークツリーを確かめて消した（<理由>）` を残す。満たさないか `rm` が失敗したら残し、`子 #N のワークツリーを残した（<理由>） — <満たさなかったこと>` を残す。`ambiguous`・`not-child` は特定できないので確かめず残す
- 手順 2: 親が確かめて消した子を片付け待ちから外す。残した行の先頭は従来どおりなので、手順 2 の除外と `reply-after-idle.md` の復元は変わらない
- `tests/epic-dispatch.bats`: 手順 3 の文言を確かめるテストを更新
- `openspec/specs/dev-workflow-develop/spec.md`: 要件「Orca 経路の本体は印が付いた子のワークスペースを片付ける」を変更（archive で反映）
- `openspec/specs/dev-workflow-develop/spec.md`: 要件「develop の手順書に orca のコマンドを書かず、orca を呼ぶスクリプトは 1 本にする」も変更。手順 3 の `orca worktree rm --worktree path:<path>` 1 件だけを例外とし、同じ行に別の orca のコマンドを書くことと 2 回以上書くことは例外に含めない。シナリオ「出力は 0 行」を、許可した 1 件を取り除いてから探す形に改めた（PR ゲートの指摘。archive 済み change の delta spec にも MODIFIED として追加）
- `tests/epic-dispatch.bats`: 手順書の orca 検索を、許可した 1 件を行ごと除外する形から、出現ごとに 1 回取り除いてから残りを探す形（`orca_doc_violations`）に変えた。同じ行に置いた `orca terminal close --all` などを見逃さないことを合成入力のテストで確かめる。手順 3 の旧文言が無いことを見る `! cmd` の 2 行に `|| return 1` を付けた（付けないと失敗しても test が落ちない）
- `scripts/epic-dispatch.sh` は変えていない（reap の処理と端末を閉じる処理は #1094 の範囲）
- 受け入れること: 親が確かめを誤ると、マージ済みと取り違えたワークツリーを消しうる。`--force` なしの `rm` が未コミットの変更で止まる
- 戻し方: この PR の差分を戻す。消したワークツリーはブランチ・PR から作り直せる
