# ゲート合格後に PR の CI を見張る ci-watch.sh と共有 reference を足す（#522）

pr-review-gate の合格処理は `agent-review:passed` を付けて終わり、そのあと CI が落ちても誰も見ていなかった。合格後に本体が CI の決着を待ち、#521 の `pr-state.sh` の一手どおりにやり直すか直すかに進むようにした。

- `plugins/dev-workflow/scripts/ci-watch.sh wait <owner/repo> <PR番号> [--until-merged]` は、決着するまで標準出力に何も出さずに `gh pr view` を繰り返し、決着したら `{"result": merged|closed|settled|timeout|error, "obs": ...}` を 1 行出す。本体はこれを `run_in_background` で起動し、完了通知で起こされてから 1 回読むので、ポーリングの途中経過が会話に出ない。間隔と上限時間は `DEV_WORKFLOW_CI_WATCH_INTERVAL`（既定 30 秒）と `DEV_WORKFLOW_CI_WATCH_TIMEOUT`（既定 3600 秒）。annotation は決着した回だけ取る
- `ci-watch.sh next <owner/repo> <PR番号> [--unrelated <チェック名>]... [--after-fix]` は PR を取り直して `pr-state.sh` の `annotations` → `observe` → `decide` に通し、一手を出して状態ファイルを書き換える。一手の実行（`gh run rerun`・直し・マージの依頼）はしない。`--after-fix` は、`fix` を受けた実装者が関係ない失敗と判断して返したときだけ使い、前回の状態の `state` を `wait` に置き換えてから `decide` に渡す（同じ状態・同じ HEAD の `none` がやり直しより先に効くのを避ける）
- 状態ファイルは `${DEV_WORKFLOW_PR_STATE_DIR:-${XDG_STATE_HOME:-$HOME/.local/state}/dev-workflow/pr-state}/<owner>__<repo>__<PR番号>.json`。worktree の外に置き、直しで worktree を切り直しても修正回数と上げ済みの印が残る
- 見張りの手順の正本は `plugins/dev-workflow/references/ci-watch.md`。待つのは本体（メインセッション）だけで、サブエージェント（develop の G）は見張りを始めずに `passed` を return する（背景タスクの完了で起こされないため）。1 つの PR を見張るのは 1 セッションだけで、`CI 見張り開始:` / `CI 見張り終了:` のコメントで判定する。`ready` ではマージを止めるラベル 4 つを見てから自動マージを見届けるかオーナーに頼むかを決め、LLM はマージしない。直し方は flatmate の「止まった人間マージ待ち PR の見張り」から移した
- `--unrelated` は、本体が落ちた run のログの末尾と PR の変更ファイルを見て、「PR の変えたファイルに当たらない」と「PR の差分と因果を持たない」の両方を満たすチェックにだけ渡す
- pr-review-gate の手順 5 の末尾・develop の (4)・gate-runner.md の passed の return から、この reference を参照する
- 受け入れたリスク: 本体のセッションが閉じると見張りも止まる（開始のコメントで気づける）。`--unrelated` の読み違えで PR に関わる失敗をやり直すと CI 1 周分を失う（同じ HEAD で 1 回だけ）。push や `gh run rerun` の直後に GitHub が古い失敗を返すと、1 間隔待っても古い観測で決着しうる

## ゲート 1 周目の指摘を直す

- 直しを push したあとの順番を変えた。前はゲートを取り直して合格してから見張りを再開していたため、直した HEAD で一時的な CI の失敗が起きると、CI の結論を見るゲートが合格できず、やり直しに進めなかった。今は `agent-review:passed` を外したまま、本体が同じ状態ファイルで `wait` → `next` を続けて CI のやり直し・再度の直しを済ませ、`ready` になってからゲートを取り直す。取り直したゲートに合格するまでマージ待ち・マージ依頼に進まない（reference の `fix` の行・「`ready` を受けたあと」・直し方の 6、develop の (4)、pr-review-gate の手順 5 の末尾）
- `ci-watch.sh wait --until-merged` は `ready` だけを待ち続け、`ci-fail`・`conflict` は `settled` で返すようにした。前はマージ待ちの間に CI が落ちても上限時間まで待ち、`timeout` からマージを頼んでいた
- 見張りの再開で `raised` を消すだけにしないようにした。状態ファイルと PR の記録から中断した一手を確かめ、同じ HEAD で未実行の `fix` は `next` を呼ばずに実装者への修正依頼から、未実行の `rerun` は `gh run rerun` から再開する。`escalate` のあとは、オーナーの具体的な指示を実行してから見張りに戻る
