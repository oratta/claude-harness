# 作業待ちの子へ親が外から声かけを送り、子は自己タイマーを持たない（#1777）

Orca で動く子の本体が agent・CI・Monitor などを 60 分以上待つあいだ、キャッシュの維持を子の自己タイマーではなく親の既存ポーリング（`wait --watch-stopped`）からの声かけで行うようにした。予約文・受信・child-log の除外は #1792 / #1793 のものをそのまま使い、作り直していない。

- `scripts/epic-child-state.sh`: Stop が、最終状態行の直前の `作業待ち: <wait-id> <started-at>` を、作業報告で依存待ちでないときだけ `turn_state.background_wait={id,started_at}` として保存する。不正な行・依存待ちとの併存は Stop を拒否する。新しい通常入力と marker の無い通常終了で消える
- `scripts/epic-dispatch.sh`: 停止済み子の経路とは別に、作業待ちの子（launcher=orca、入力の送り手が parent か startup、同世代・同セッション）へ `background` の固定文を送る経路を足した。会話は `turn_input.transcript_path` の一本だけを読み、stop_uuid・停止印・150k 除外・質問の判定を使わない。子の発言と usage は sessionId 一致かつ entrypoint=cli の行だけ、入力の行は項目が欠けていても数える。送信窓は停止済み子と同じで、前回未応答なら送らない。部品を呼ぶ直前に記録と会話を読み直す
- `scripts/epic-launch-orca.sh`: dispatch が作業待ちの一呼び出しだけに渡す `EPIC_DISPATCH_KEEPALIVE_BACKGROUND_WAIT=1` のときに限り、最後の既知の背景待機行と入力枠の間が空行と recap だけなら、その行による busy を外す。送信後の観測では使わない。停止済み子と tmux では外さない
- `skills/develop/references/child-background-wait.md`: 子は自分の記録で Orca・parent/startup の入力を確かめたときだけ外部起こしを選び、自己タイマーを作らない（移行前のものは取り消してから marker を出す。取消に失敗したら marker を出さない）。owner の入力のあとは #1743 の自己通知に戻る。tmux・worker は今までどおり
- `skills/develop/references/epic-keepalive-watch.md`: 親の正本に、二つの経路・12 時間の基点・Orca の許可とその限界を足した
- `tests/develop-epic-scene-budget.txt`: 親の止まりの場面（parent-stopped とそれを含む 3 場面）の予算を、親の正本に足した 1593 バイトだけ上げた。新しい経路の手順は親がこの場面で読む正本にしか置けないため

12 時間の基点: 初回開始（`started_at`）だけ。min(43200, `EPIC_DISPATCH_OWNER_WAIT_SEC`) 秒を過ぎたら維持だけをやめ、元作業の通知を待つ。wait の掛け直し・親の再開・声かけ・待ちの延長、owner の入力をはさんだ経路の切り替えで基点は動かない。

互換性: 項目の無い旧記録は読み続けるが、作業待ちには格上げしない。停止済み子の声かけ（固定文・条件・150k 除外・期限）と tmux の経路は変えていない。稼働中の旧い子には親から marker を補わない。

## 後の PR のリスク宣言へ引き継ぐこと（誤送信）

- 作業中の子に予約文が届きうる条件: 古い作業待ちの記録と既知の待機行が画面に残っている場合と、親の最後の観測から send までのあいだに子が再開した場合。キューへの割り込み、余分な応答とリクエスト、元作業との競合が起きうる
- 狭めた手段: 記録と現行会話の作業待ちの行・状態行の一致、記録後の入力・通知・発言・ツールがあれば送らない、部品を呼ぶ直前の読み直し、二回の画面観測、待機行と入力枠の間が空行と recap だけのときだけの許可、前回未応答なら送らない、同じ待ちで 12 時間まで、send は一回だけ。原子性は保証しない
- 形式が正しくても実態と合わない marker（作業は終わっている・別の作業を待っている）は通る
- 頻度は未計測。送信試行数・誤送信数は実エピックで分母付きで測る
