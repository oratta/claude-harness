# accounts: 8 スロット上限を超える追加の拒否と、add の id 位置のハイフン始まりの拒否（#1031）

スロットが 8 個ある登録簿に `accounts.sh add z` や `accounts-init.sh --id z` を実行すると、exit 0 で 9 個目が載っていた。使用量を読む `usage_view.read_slots()` は先頭 8 個で打ち切るので、9 個目は自動選択にも使用量取得にも入らず、エラーも警告も出なかった。

- `accounts.sh add` / `accounts-init.sh`: `accounts` 配列が 8 要素以上のとき、登録簿にまだ無い id の追加を、理由を stderr に出して exit 2 で拒否する。何も書かず（`.bak` も作らず）、`add` は認証情報のディレクトリも作らない。判定は要素の数で行い、要素の形は見ない。既存 id の `accounts-init.sh` での登録し直しは 8 個でもできる
- `accounts-init.sh`: python 部の終了コードを `|| exit $?` で保つ（以前は `|| exit 1` で exit 2 が 1 になる形だった）。壊れた JSON の exit 1 は変わらない
- `accounts.sh add`: id の位置に来たハイフン始まりの引数（`--help` / `-h` 以外。`--lable`、`--version`、`-H`、`--`、`-` など）を exit 2 で拒否する（PR #1483 のレビュー指摘 F1）。以前は id として登録され、ディレクトリとログインコマンドまで作られていた
- 副作用: ハイフンで始まる id（`-a` など）は `add` で登録できなくなる。`on` / `off` と `accounts-init.sh` は従来どおりこの形の id を受ける
- オフのスロットも 8 個に数える。拒否の文面と README（dev-workflow・statusline）に、枠を空けるには登録簿の要素を手で消すことを書いた
- spec: `usage-account-registry` に要件「登録できるスロットは 8 個まで」を足し、要件「登録簿を一覧・追加・オン・オフするコマンド」を直した
- 戻し方: この PR の差分を戻す。登録簿の形は変えていないので移行は要らない。すでに 9 個以上になった登録簿は書き換えない（読み取り側が先頭 8 個を使うまま）
