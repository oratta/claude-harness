# 破壊的 git 操作を Bash の実行前に止める PreToolUse hook（#710）

`rules/destructive-git-guard.md` は承認なしに実行しない git 操作の一覧を常時注入していたが、止める仕組みが無く、ルールを読み飛ばした Claude がそのまま打てた。一覧のうちコマンド文字列で判定できる 9 種を、Bash の実行前に hook で止める。

- `scripts/git-destructive-guard.sh` を足し、`hooks/hooks.json` の PreToolUse の末尾に `matcher: "Bash"` で登録した。対象は `git checkout -- <path>` / `git checkout .`、`git restore`（`--staged` だけを除く）、`git reset --hard`、`git clean -f`（dry-run を除く）、main / master への `git push`、force push、`git branch -D`、`--no-verify`（`git commit -n` を含む）、`--no-gpg-sign`。連結・`$(...)`・`bash -c`・`eval`・git の大域オプションを挟んだ形も見る。判定はスクリプトに一本化し、`if` では絞らない（bats で検査でき、一覧が 1 か所に置けるため）
- 返す値は payload の `permission_mode` で決める。`default` / `acceptEdits` / `plan` / `bypassPermissions` は `ask`（対話セッションでは確認画面、`claude -p` では実行されない）、`auto`・`dontAsk`・未知・欠落は `deny`
- `ask` / `deny` の確定結果: `claude -p` で使い捨てリポジトリに `git reset --hard` を頼んだ。hook を外した対照実験では、`--dangerously-skip-permissions` と `--permission-mode default` のどちらでも実行されて書き換えが消えた。hook ありでは、`default` と `bypassPermissions` で `ask`、`auto` で `deny` が返り、どれも書き換えが残った。対話セッション（`--dangerously-skip-permissions`）では、`ask` で主が承認できる確認画面が出て、No を選ぶと実行されなかった。このため当初 `deny` にしていた `bypassPermissions` を `ask` に移した。目的は主に確認を回すことで、確認画面はそれを直接満たし、`-p` の無人セッションでも `ask` は実行を止める。入力欄の `!` で打った git は hook を通らないことも確かめた。`--permission-mode` を付けない起動は settings.json の `defaultMode` が効き、主の環境では `auto` になる
- 理由には、主に承認を求め、承認されたら主が自分で実行する（入力欄の `!` か主の端末。`ask` では確認画面が出ないセッションのとき）ことを書く。コマンドに付けて通す目印は作らない（Claude が自分で付けられるため）。セッション全体で外すときは起動時の環境に `DEV_WORKFLOW_GIT_GUARD=off`
- ヒアドキュメントの本文と引用符の中の改行より後ろは読まない。commit メッセージや issue コメントの本文に書いた git の行で止まらないようにするため
- `rules/destructive-git-guard.md` は既存の文を 1 つも外さず、hook との分担（hook が止めること、拒否されたら承認後も主が実行すること、hook で止まらないもの）を足した。`always-on-injection-scope` が一覧と目印を本文に残すことを求めており、縮めるなら移設先と移設表が要って、21 行のルールでは手間に見合わない。hook の効かない場面（スクリプト経由、dev-workflow を外したプロジェクト、`off` のセッション）ではルールの文章が唯一の歯止めになる。常時注入の実測は 39,291 から 39,908 バイトに増えたが、予算 40,260 の内に収まったので予算ファイルは動かしていない
- wt-clean のブランチ削除（`git branch -D`）は、主の `cld` セッションでは確認画面が出て、断られたときと cron の `claude -p` では止まるので、同じ change の中で worktree プラグインの wt-clean に拒否されたときの扱いを足した（`plugins/worktree/changes/710.md`）。別の issue に切ると、マージから直すまでの間 wt-clean が拒否のたびにどう振る舞うか決まっていない状態になる
- `tests/git-destructive-guard.bats` で 9 種・対象外・モード別の値・拒否理由・`off`・fail-open・hooks.json の登録を固定した
