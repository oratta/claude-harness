# 主の委任のリスク許容を、主が会話で任せると言った発言そのものを確認にして受けられるようにする（#1609。エピック #1826 の子）

これまでの主の委任は、親が委任の記録を投稿してから主に「この記録で任せてよいか」と問い、主の返事を確認として受ける形（問いの形）だけだった。主が会話で「子の止まりは任せる」と言っても、その場で止まっている子には効かず（委任の確認より後に止まった子にしか効かない）、主はもう一度返事を打つ必要があった。主の会話の 1 回の発言で、以後の止まりと、そのとき止まっていたリスク許容の止まりの両方が親経由で通るようにした。

- `scripts/owner-reply-check.sh`: `--delegated-trigger <セッション ID> <uuid> <委任の記録の作成日時> <きっかけの全文>` を足した。その uuid の行が主の入力で、委任の記録より前で、全文が記録の `きっかけ:` の値と空白をまとめて同じで、その発言から記録までに別の主の発言が無いことを確かめる（落ちたときの REASON は `not-found` → `not-owner` → `not-before-record` → `not-same` → `not-adjacent` の順。全文が空白だけなら終了コード 2）。`--delegated` の 5 番目の引数（停止の記録の作成日時）に `-` を受け、`-` のときは `not-before` を確かめない。`-` でも日時でもなければ終了コード 2
- `skills/develop/references/epic-delegation.md`: 委任の記録にきっかけの形（4 行目の `期間:` の定型と、5 行目の `きっかけ:` に主の発言の全文）を足し、「委任が有効か」と「確認・期間・失効」をきっかけの形に合わせた。リスク許容の止まりからは委任の確認との前後の条件を外した（確認より前に止まった子にも効く）。聖域の変更・破壊的な git 操作の止まりとマージ待ちは今までどおり確認より前の止まりには効かない
- `skills/develop/references/epic-stop.md`: 親がきっかけの形で受ける条件（全文だけから子の止まりを親に任せる旨が読め、直前の親の発言を読まないと対象が決まらない発言でなく、除外・期限・条件を付けていない）、そのとき親が先に `--delegated-trigger` を回すこと、同じターンに `pending-owner` が返す子へ今回の停止の記録を見て送ること、事後の報告に送った子の番号と停止の記録の URL を書くことを足した。条件に当たらない発言は今までどおり問いの形か、元の問いへの答えとして扱う
- `skills/develop/references/epic-child-stop.md`: 子が委任の返事を受けたとき、委任の記録の 4 行目で形を見分けて照合を選ぶ（問いの形のリスク許容は停止の記録の引数 `-` の `--delegated`、きっかけの形は `--delegated-trigger`）ようにした
- `skills/pr-review-gate/stages/authenticity-delegated.md`・`carryover.md`・`hold-resume.md`（聖域）: G の真正性確認・手順 3-c の引き継ぎの確かめ直し・手順 6 の復帰手順を、委任の記録の形に合った照合で確かめる文にした。真正性確認の行は使った照合の名前を書く。きっかけの形では `MATCH:` の全文がこの子を除く・定型と違う期限を付ける・子の止まりを任せる旨が読めないときは合格させない
- テスト: `owner-reply-delegated-scenario.bats`・`develop-skill.bats`・`owner-escalation-narrowing.bats`・`pr-review-gate-skill.bats` に足し、直した。ゲートの文言の控え（`tests/fixtures/gate-contracts/prose.json`・`blocks.json`）を書き換えた文にした
- 読込予算（`tests/gate-reading-budget.txt`）: 外れた 82 件だけ実測値に直した。`stages/carryover.md` の条件 3 が約 483 バイト増えて 3-c を読む件（`*-carryover*`・`*-judge*`）が、`stages/hold-resume.md` のリスク許容待ちの行が約 86 バイト増えて復帰手順を読む件（`*-resume`・`*-split`）が、`stages/authenticity-delegated.md`（約 2,570 バイト増）と、それが判定前に読む `skills/develop/references/epic-delegation.md`（約 2,570 バイト増）で委任の形を読む件（`*-delegated`・`*-max`）が上限を超えた。ほかの件・コメント・判定式は変えていない
- 受け入れること: 主の会話の 1 回の発言で、以後のリスク許容の止まりと、そのとき止まっていたリスク許容の止まりが親経由で通る。そのぶん、主が任せたつもりの無い発言をきっかけの形で拾う誤りは、照合（全文の一致・記録との隣接）と、親・子・G がそれぞれ全文を読む確認で止める
- 戻し方: この PR の差分を戻す。投稿済みのきっかけの形の委任の記録は、エピックに `主の委任: 取り消し` を投稿すれば効かなくなる
