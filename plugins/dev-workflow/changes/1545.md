# epic-dispatch: 声かけの判定が通知・ローカルコマンドを主の返事に数えない／child-log の時刻を本文の時刻にする／wait の mktemp 失敗で止まる（#1545）

元の PR #1466（記録先 #1382）のレビュー指摘を束ねた follow-up。

- `scripts/epic-dispatch.sh` の `keepalive_candidate`: 会話ログの user の行のうち、背景タスクの通知（`origin.kind` が `task-notification`、または本文が `<task-notification` で始まる）、`<local-command-`・`<bash-input>`・`<bash-stdout>`・`<bash-stderr>` の行、Claude Code が自分で処理した `<command-name>` の行（次の行がローカルコマンドの出力のもの）を主の返事に数えない。判定は `child-log-read.py` の `is_notification`・`NOT_INPUT_PREFIXES`・`local_command` と同じ読み方。モデルへ送ったスラッシュコマンド（`/dev-workflow:develop` など）は今までどおり返事に数える。これらの行だけが最後の質問のあとにある止まりが、声かけの対象から外れなくなる
- `scripts/child-log-read.py`: `walk` の戻り値に `text_at`（子の最後の本文を書いた時刻）を足した。質問ツールだけで本文が無いときは質問の時刻（今までの表示と同じ）。`epic-dispatch.sh child-log` の子の時刻の列は `text_at` を使う。本文のあとに質問ツールを呼んだ子で、古い本文に質問ツールの時刻が付いていた表示の誤りが直る。`at`（最後の子の発言の時刻）は変えていない
- `scripts/epic-dispatch.sh` の `wait`: `mktemp -d` が失敗したら、一時ファイルを消し、`could not create a temporary directory` を stderr に出して exit 1 する。以前は `STOP_DIR` が空のまま `rm -f "$STOP_DIR"/*` が `rm -f /*` になりえた
- 戻し方: この PR の差分を戻す。状態の記録・ログの形は変えていない
