# 親経由で受けた主のリスク許容を、親の会話ログで確かめて子のゲートで受け付ける（#1059）

Orca 経路のエピックでは、主は普段は親のセッションと話している。子が主のリスク許容を待って止まり、主が親のタブで「許容」と書いても、子のゲートはそれを主本人の返事として受け取れず、主が子のタブを開いて打ち直す必要があった。子の会話ログに残る親の打ち込みは主の発言と区別できないので、根拠を親の会話ログの主の発言の行そのものに移した（親エピックは #1038）。

- `scripts/owner-reply-check.sh`: 主の発言として数えない 9 つ目の条件を足した。本文が `主の返事（親エピック #` か `親エピック #` で始まる行と、`<command-args>` の中身が `#<数字> （エピック #<数字> の子。` で始まる行（`epic-dispatch.sh` の `launch` と `reply --relaunch` が打つ起動の指示）は数えない。既定の使い方にも効くので、子のセッションで親の打ち込みを指した `会話で受領` は通らなくなる
- `owner-reply-check.sh --locate <セッション ID> <原文>`: 主の発言のうち原文を含む行を `MATCH: <timestamp> <uuid> <全文>` で出す（親が主の答えの行の uuid を引く）
- `owner-reply-check.sh --relayed <セッション ID> <uuid> <停止の記録の作成日時> <停止の記録の URL>`: その uuid の行が主の入力で（`not-found` / `not-owner`）、停止の記録より後で（`not-after`）、そのあいだに停止の記録の URL を本文に書いた親の発言がある（`not-asked`。URL は前後の区切りつきの完全一致で探し、`…#issuecomment-123` は `…#issuecomment-1234` に一致しない）、URL を書いた最後の親の発言と主の発言のあいだに別の主の発言が無い（`not-direct`。報告のあとに主が別の件へ返した名指しの無い答えを通さない）ことを確かめる。通れば `MATCH: <timestamp> <全文>` と exit 0
- pr-review-gate `stages/pass.md` 手順 5: 合格条件の表に `親経由で受領` の行と、その真正性確認の段落（停止の記録のコメントの 1 行目・`author_association`・記録先の確かめ方、`--relayed` の終了コード 0、全文の読み方、宣言コメントの作成日時との比較）を足した。名指しが無い許容と、この子とほかの子をまとめて名指しした答えは通し、別の子だけを名指しした答えは落とす。「会話で受領」の守備範囲の文を、決まった頭の打ち込みは数えない・頭の無い文は区別できない、に直した
- pr-review-gate `stages/hold.md`: 手順 3-c の引き継ぎの元に `親経由で受領` の形を足し（`--relayed` で確かめ直し、最初の宣言より後の発言であること）、引き継いだ宣言の 1 行目の置き換えの形と、手順 6 のリスク許容待ちの復帰手順に同じ形を足した
- develop `SKILL.md`: Orca 経路の手順 8 で、親は止まった子を本文で報告し（質問ツールで聞かない）、`--locate` で引いた uuid を ` [主の発言: セッション <ID> / uuid <uuid>]` として主の答えの末尾に添えて `reply --as owner` に渡す。子は「親から届いた返事」で添え書きを `--relayed` で確かめてから保留の解除の G に渡し、`--relayed` が通って全文から不許容と読めるときは主本人の不許容として G に渡す（主に子のタブで打ち直してもらわない）。どちらとも読めないか確かめられなければ G を起こさず主に子のタブでの返事を理由付きで頼む。親の `--locate` の全文比較は空白をまとめて比べ、報告と主の答えのあいだに主の別の発言が挟まったら報告を出し直す。起動し直しの最初の指示に付いて届いたときも同じに扱い、「新しいセッションでの再開」の手順 2 より先に当てる。保留の行からこの手順を参照した
- `scripts/epic-dispatch.sh` は変えていない（添え書きは主の答えの末尾に足すだけ。エピック #1038 の並行する子 #1043・#1045・#1054・#1055・#1057・#1058 の範囲に出ないため）
- 受け入れること: 親が決まった頭を付けずに自由な文で打ち込んだ許容は、子の会話ログでは今までどおり主の発言と区別できない。名指しの無い「許容」は、親がまとめて報告した別の子への答えと区別しない。親の報告のあとに主が聞き返してから答えたもの（あいだに主の発言が挟まる）は `not-direct` で落ち、主に子のタブで打ってもらう。会話ログの改変は検知しない。親の会話ログを読めない PC（別の PC・別の `CLAUDE_CONFIG_DIR`）では exit 2 になり、主に子のタブで打ってもらう今の動きに戻る
- 移行: この変更より前の形で送られた添え書きの無い親経由の返事は、今どおり主に子のタブで打ってもらう。戻し方はこの PR の差分を戻す
