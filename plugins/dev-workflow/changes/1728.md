# Orca の現行画面から keepalive の送信可否を判定する（#1728）

- `result.terminal` 配下の read 応答を検査し、画面の入力領域全体と任意の draft から空欄を判定する。実測の bypass-permissions フッター、複数 statusline、フッター下の既知のエージェント一覧を扱い、不正な構造は `failed observe shape` として診断する
- バックグラウンドエージェント完了待ちは `skipped busy` とするが、後続の既知の前景完了行（最後の完了行から入力枠までは空行と recap のみ）があれば古い待機として解除する。入力済み・実行中・ダイアログ・未知の画面では送信せず、送信後の補助確認にも前景実行と空欄の両方を必要とする
- 現行 read の匿名化 fixture と回帰テストを追加した。Orca 1.4.263 の実画面の読み取り確認は、画面全体の待機行を busy とする旧分類での過去の検証（ready 5 台・busy 9 台）で、停止中なのに履歴の古い待機行で busy になる子 4 件を見逃していた。待機行を後続の既知の完了行で解除する今回の修正後は、停止中の子 4 件が ready、待機中の子 7 件が busy になる。入力済みの実画面は未観測で、fixture で確認した
- 実際の停止中の子への到達、予約された返事、次の request のキャッシュ利用、実測 send receipt の回帰反映（tasks 3.2）はマージ後の確認として未完了。実機への送信成功を確認済みとはしない
- 戻し方: この変更の差分を戻す。バージョンは変更しない
