# review-partitions.sh が、先頭が 0 行のファイルのとき中身の無い区画 1 を作る不具合を直す（#620）

`plugins/dev-workflow/scripts/review-partitions.sh` は、先頭が 0 行のファイル（空ファイルの追加・モード変更・リネームだけなど）の次が 400 行を超えるファイルのとき、0 行だけの区画 1 を作っていた。例: `0 a.png / 500 b.md / 200 c.md` は `区画 1/3（0 行）` を出し、その区画のレビュアーは読むハンクが無いまま起こされて固定分が 1 体ぶん無駄になった（壊れはしない）。

- 先頭から続く 0 行のファイルは、区画を新しく作らず、最初の変更行を持つファイルが作る区画に入れる。上の例は `区画 1/2（500 行）`（a.png と b.md）、`区画 2/2（200 行）` になる。全ファイルがどれかの区画に入ることは変わらない
- 0 行のファイルを含まない入力では、区画の番号・総数・各区画のファイルの割り当ての出力は直す前と同じ（origin/main の版との出力の比較で確認した）。0 行のファイルが先頭以外にある入力も同じ
- `openspec/specs/dev-workflow-pr-review-gate/spec.md` の規則「先頭から 0 行のファイルが続くときは、最初に作られる区画（区画 1）に入れる」は、最初に作られる区画を最初の変更行を持つファイルの区画と読めば今の直し方と矛盾しないので、規範は変えていない
- 検査は `plugins/dev-workflow/tests/review-partitions.bats`。旧い「先頭の 0 行のファイルは 0 行の区画 1 に入る」の検査（今回直す振る舞いそのものを固定していた）を、新しい出力の検査に置き換え、0 行のファイルが 2 つ続く入力で空の区画が無く全ファイルがどれかの区画に入ることを足した。直す前の版では両方落ちる。さらに、先頭の 0 行のファイルの次が 400 行以下のファイルのとき（`0 z / 100 a / 300 b / 300 c`）に、全ファイルが出力に残り区画 1 が 400 行になることの完全一致の検査を 1 件足した（0 行の分岐が区画を開いたままにする変異を検知する）
- 戻し方: `review-partitions.sh` の 0 行の分岐を元に戻し、bats を元に戻す
