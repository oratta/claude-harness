# auto-merge: hook が実行するスクリプトを聖域に含め、hooks.json との突き合わせを CI で検査する（#1163）

claude-harness の自動マージの聖域（`.github/workflows/auto-merge.yml` の `SACRED`）は `^plugins/[^/]+/hooks/` だけを数え、hook の本体である `plugins/<name>/scripts/` のスクリプトは対象外だった。そのため `plugins/dev-workflow/scripts/git-destructive-guard.sh` だけを変えた PR #1157 が、主のマージを待たずに自動マージされた。

- `.github/workflows/auto-merge.yml` の `SACRED` に、全 `plugins/*/hooks/hooks.json` の `command` が呼ぶスクリプト 24 本（capability-registry 2・cost-ledger 3・dev-workflow 13・statusline 1・worktree 5）と、許可を判定する hook が判定の本体として直接読み込む補助 3 本（`git-guard-scratchpad.py`・`usage_view.py`・capability-registry の `secret-guard.py`）を、ファイル名ちょうどで足した。これらに触れる PR には `human-merge` が付く
- `scripts/test-auto-merge-workflow.sh` に、全 hooks.json の `command` が指すパスを `SACRED` に当てる検査を足した。hook を足して `SACRED` に書き忘れたとき、`command` が `${CLAUDE_PLUGIN_ROOT}/<パス>` の形で読めないとき、`command` を 1 件も拾えないときに CI（必須チェック shellcheck のジョブ）が落ちる。代表パス（`git-destructive-guard.sh` などが聖域に一致し、`ci-watch.sh`・`epic-dispatch.sh` は一致しない）も足した
- `MERGE_CONDITION` は変えていない。hook の本体は `plugins/*/hooks/` と同じく、親の判断の印で `human-merge` を外せる
- 原本（`plugins/dev-workflow/templates/auto-merge/`）の正規表現・テスト・README は変えていない。hook の置き場はリポごとに違うため
- `docs/auto-merge.md` の聖域パスの表に hook の本体の行を足し、残る限界を書いた
- 残る限界: 補助ファイルは手で選ぶので CI の検査は拾わない。補助がさらに読み込むものと、hook が実行しない親が許可を書くスクリプトは聖域に入らない
- 戻し方: この PR の差分を戻す。状態ファイルやラベルの形は変えていないので移行は要らない
