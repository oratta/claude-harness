# 714: モデル切替の直前に再キャッシュのトークン数と推定費用を知らせる

セッションの途中でモデルを切り替えると、今のモデルのプロンプトキャッシュ（同じ前置きを安く再利用する仕組み）は使えなくなり、会話全体を切替先のモデルで読み直す費用がかかる。`hooks/hooks.json` に `PreModelSwitch` のエントリを足し、新規の `scripts/model-switch-recache-notice.sh` が、切替の直前に次のような 1 文を `systemMessage` で返すようにした。

```
モデル切替（claude-sonnet-5 → claude-opus-5）: 会話の約 182,340 トークンを切替先のモデルで読み直します。キャッシュ書き込みの推定費用は $1.14（定価）。今のモデルのキャッシュはまだ有効で、切り替えると使えなくなります。
```

- 出す条件: hook の入力の `context_tokens`（読み直すトークン数）か `estimated_cache_write_usd`（キャッシュ書き込みの推定費用）のどちらかが使える値のとき。片方しか無ければある方だけ出す。金額のうしろの括弧は推定に使った単価（`pricing`）で、定価・組織の設定単価・単価が不明なため既定の単価で計算、の 3 通り
- 出さない条件: `prompt_cache_warm` が `false`（捨てるキャッシュが無い）、`context_tokens` が `0`（最初の応答の前で読み直すものが無い）、使える数字が 1 つも無い、`hook_event_name` が `PreModelSwitch` でない
- 切替は止めない。返すのは `systemMessage` だけで、`decision`・`hookSpecificOutput`（`permissionDecision`）・`continue` は返さない（本体の確認画面も飛ばさない）。この event では exit 2 と時間切れが切替を止めるので、入力が壊れている・`python3` が無い・スクリプトの中で例外が起きた、のどの場合も無出力・exit 0・標準エラー空で終える。stdin だけを読み、ネットワークにもファイルにも触らない。`matcher` と `timeout` は付けていない
- `PreModelSwitch` は Claude Code 2.1.251 以降の hook。`/model`・モデルの選択画面・`/config`・fast mode の切替・Agent SDK からの切替で走り、Claude Code 自身による切替（自動フォールバックなど）では走らない
- 未確認の 2 点: `systemMessage` が本体の確認画面の前後どちらに出るか（文言は順序に依存しない形にしてある）。2.1.251 より前の Claude Code が、知らないイベント名 `PreModelSwitch` を持つ hooks.json をどう扱うか（手元の 2.1.294 の `claude plugin validate` は通る）
- 問題が出たときは、`hooks/hooks.json` の `PreModelSwitch` のエントリを外せば元に戻る
- `tests/subagent-stop-guard.bats` の、hooks.json のイベント名の集合を完全一致で見る検査に `PreModelSwitch` を足した
