# dev-workflow: `cld` のアカウント選択と develop の構成選択を headroom の値で決める（#1301）

#1300 で余りの計算を `scripts/headroom.py` に置いたが、`cld` のアカウント選択（`scripts/select-account.sh`）と develop の構成選択（`scripts/codex-develop.py`）はまだ自分で margin（週の経過率 − 使用率）を数えていた。設計の正本 genetta-inc/flatmate#1711 に沿って、どちらも headroom の行から取るようにした。

- `select-account.sh` の自動選択は、`headroom.compute(now)` の `best_by_provider.claude`（Claude で余り `surplus_pct` が最大のスロット。同点は宣言順）を選ぶ。リセット権を持つスロットは margin が小さくても余りが大きければ選ばれる。Codex が全体で一番余っていても Claude のスロットを選ぶ（`best` は使わない）。`.headroom.json` は読まず、その場で数える
- 理由行の理由は `max-weekly-margin` から `max-surplus` に変わった。`margins=` の値は headroom の行の `margin`（経過率を 0〜100 に切り詰めない値）
- 週次の実効値の取得時刻が今より 60 秒を超えて未来のスロットは `stale` と表示して候補から外す。縮退の理由は `missing` と同じ `default-due-to-missing-usage`
- 5 時間の使用率が分からないスロットは、これまでの `missing` ではなく候補に残す（headroom の best と同じ）
- `HEADROOM_7D_CAP_PCT`・`HEADROOM_NORMAL_RATE_PCT_PER_DAY` が不正なときは、既定アカウントへ縮退して `default-due-to-invalid-headroom-setting margins=-` を出し、exit 0 で終わる（`cld` を起動できなくしない）
- `codex-develop.py` の `usage_margin`（Codex）と `claude_usage_evidence`（Claude の起動アカウント）は、headroom の行が `ok` のときの `margin` を使う。未来の取得時刻は 1 秒でも欠測にしていたのをやめ、60 秒以内は時計のずれとして数え、61 秒先から欠測にする（Claude 側も同じ規則で見るようになった）。headroom の設定が不正なときは自動選択を止め、設定の名前を含むエラーで blocked（終了コード 2）になる。構成選択の規則（margin ≥ 0 の表）は変えていない。オフ（`enabled: false`）のスロットで起動したセッション（`CLAUDE_SECURESTORAGE_CONFIG_DIR` を手で設定した場合）では、headroom の行が `off` なので Claude の margin は欠測になる（以前はそのスロットの実効値から数えていた）。Codex の行には対応表の account 名を渡す
- `headroom.py` に行を返す公開関数を 2 つ足した: `claude_rows(now, snapshot_path=None)`（Claude の各スロットの行）と `codex_row(account, cache, now)`（読み込み済みの Codex の cache 1 件から 1 行）。`compute` もこれを使い、出力は変わらない。Codex の home を解決できない（親ディレクトリに実行権が無い等で例外が出る）ときは、`compute` は止まらず Codex の行を `missing` にする（`cld` を起動できなくしない）
