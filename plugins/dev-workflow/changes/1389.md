# pr-review-gate: 受け入れ条件に要らない指摘を今の PR で直さない（#1389）

ゲートの振り分けが「今回触ったファイルの中で直せるなら直す」（段 A）と「受け入れ条件の外でも小さければ直す」（順 4）で動いていて、issue の完了に要るかを問うていなかった。提案程度の指摘でも小さければ PR に取り込まれ、小さな issue が膨らんでいた。

- `stages/triage.md` の止めない指摘の振り分け表の段 A: 当たるのを、直さないと受け入れ条件（記録先の受け入れ条件、またはこの PR の change の delta spec。順 2 と同じ範囲）を満たせない指摘と、例外 3 種（安全機構の穴・データ破壊・無言の機能不全）に当たる指摘だけにした。どちらでもない指摘は、触ったファイルの中でも行数が小さくても段 B から当てる
- 受け入れ条件も delta spec も求めていない新しい部品・機能を足す提案は、行数によらず範囲外とした。今の PR で直せるのは例外 3 種に当たるときだけ
- `stages/triage.md` の止める指摘の仕分け表の順 4: 当てられるのを、止める判定の根拠が例外 3 種の指摘に限った。今直す 3 条件と 30 行の閾値は残す。例外 3 種に当たるかは根拠欄の書き方によらず G が決める。PR が触れる spec を引用するが、受け入れ条件でも delta spec でも例外 3 種でもない止める指摘は、順 5 で主に聞くようになる
- `stages/reviewer-brief.md`: 起こす側が受け入れ条件の全文を依頼文に入れることを区画の有無によらず書いた。固定書式に `受け入れ条件の要否`（`要る: <受け入れ条件 ID または delta spec の要件名>` / `要らない`）を足し、根拠の欄は引用できる指摘でも例外 3 種に当たれば併記する形にした。印でレビュアーが見る範囲は狭めない
- 印は深刻度ラベルと同じく参考にとどめ、判定は G が受け入れ条件の文と照らして決める。印が無くても補足は頼まず、三表の機械照合の対象にも足さない
- 振り分けの記録と return の仕分け欄に、段 A の要る受け入れ条件の ID か delta spec の要件名か例外 3 種のどれかと、順 4 の例外 3 種のどれかを足した
- `README.md`: 固定書式の欄の列挙に `受け入れ条件の要否` を足した
- 変えていないもの: レビュアーが見る範囲、マージを止めるかの判定（全周共通）、段 B 以降の流れ、周の歯止め、W の記録の文字列（「受け入れ条件の外・その場で直した・直し方 N 行」）
- 受け入れること: 段 A の例外 3 種には行数の上限が無く、裏取りの無い指摘が大きな直しになりうる（1 周目に限られ、差分はレビューを通る）
- 重なり: #1436（#580）は `stages/triage.md` を分割するので、あとから入る側が移動先へ同じ文を移す
- 戻し方: この PR の差分を戻す。データの移行は無い
