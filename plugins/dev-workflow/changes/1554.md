# keepalive: 止まった子への声かけを本体の会話ログ 1 本で判定し、結果を記録に残す（#1554）

止まった子（`stop` が `stopped-seen`）への声かけは、子の会話ログの置き場に `.jsonl` がちょうど 1 本のときしか送られなかった。SDK が起こした短いセッションや過去のセッションが混ざると、声かけも `wait --resolve` の起動し直しの判定も無言で外れていた。送らなかった理由はどこにも残らなかった（親エピック #1557）。

- 本体の会話のログを内容から 1 本に決める（`scripts/child-log-read.py --main-log <置き場> <stop_uuid>`）。`entrypoint` が `cli` で sidechain でない assistant の行を持つファイルのうち、最終活動が最新の 1 本。記録の `stop_uuid` がそのログに無い・`stop_uuid` が空・最終活動が同時刻のときは決めず、声かけを送らない。`session` はログの選択に使わない
- `epic-dispatch.sh`: `main_transcript` を足し、声かけの判定（`keepalive_candidate`）と起動し直しの判定（`decide_relaunch`）が使う。`cache_ttl_of` は選んだログ 1 本を第 2 引数で受けられる（引数なしは今までどおり全ログ。`wait` の待ち時間の上限の既定はこちら）。`decide_relaunch` の「ログがちょうど 1 本」の条件はやめた
- 子の記録に任意の文字列 `keepalive`（`<UTC の時刻> <結果>`）。`sent`・`skipped <理由>`・`failed <理由>`。前回と同じ結果は書き直さない。書けなくても `wait` の stdout の行と exit code は変わらない（stderr に 1 行だけ）。`epic-state.sh` の検査に `keepalive` が文字列であることを足した
- 受け入れること: `/clear` や再開の直後で選んだログがまだ `stop_uuid` の行を持たない回、本体と過去のセッションの最終活動が同時刻の回、`stop_uuid` が空の記録（候補が 1 本でも）は送らない。running の子にも `skipped not-stopped` が 1 回記録される
- 戻し方: この PR の差分を戻す。`keepalive` は知らない項目として読み飛ばされるので、状態の記録の移行は要らない
