# develop: Codex 消費の印に開始・終了の時刻を書く（#1321）

codex-worker の前景実行の結果 JSON に、実行の開始 `started_at` と終了 `ended_at`（UTC の ISO8601・秒まで・末尾 `Z`）を足した。開始は依頼を読む前、終了は一時領域を片付けて結果を出す直前に取るので、成功・失敗・ターンが始まらなかった場合のどれでも値が入る。

develop の本体は、executor が `codex` の委譲の `Codex 消費:` コメントの印に、この 2 つを `開始=` `終了=` として写す。結果 JSON に無いか `null` なら省いて推測で埋めない。G の full レビューで呼んだ Codex の分と、description・`develop 開始` コメントの印には時刻を書かない。これまでの「時刻の `開始=` `終了=` は書かない」の規則はこれに置き換えた。

読み取り側は flatmate の `burn_consumption.py`（genetta-inc/flatmate#1776 で、rollout から時刻が取れない thread にだけ印の `開始=` `終了=` を使う契約が入った）。develop の Codex 委譲は使い捨ての CODEX_HOME で動き rollout が残らないため、これで Codex 行の時刻が null でなくなり、リセット期間をまたいだかを判定できる。

起動時に読むファイルの予算（`tests/develop-startup-budget.txt`）は、SKILL.md を 92996 → 93433 バイト、`references/codex-develop.md` を 18565 → 18593 バイトに上げた。どちらも余りが 1 バイト以下で、書き足した規則（時刻の書き方の 1 文と結果 JSON のキー名 2 つ）を最小の文に縮めても収まらなかったため、増えた分だけ動かした。
