# pr-review-gate: 件数の多い語の照合表を全ヒット要約で返す（#1457）

- 一周目の `照合表` で全ヒットが 50 行を超える語は、全行の代わりに `全ヒット要約: <行数> 行 <ハッシュ>` で返す。食い違いの行だけを 4 列の表に置き、食い違いが無ければ表を省ける。語が大量にヒットするとレビュアーの返答に全行が収まらず、補足でも直らず `review-incomplete` で止まっていた
- `scripts/review-hit-set.py`: 新しい option は足さず、`全ヒット要約:` の行で判別する。検索コマンドは今と同じ検査を通し、固定 SHA で再実行して行数（標準出力のバイト列の `\n` の数）とハッシュ（復号しないバイト列の `git hash-object --stdin`）を比べる。全ヒットが 50 行以下の語の要約・`--head` との併用・`一致` の行は契約違反。全行の表の経路は変えていない
- 4 列の行の検査では `Binary file` の行を除き、本文の行末の `\r` を無視する。どちらも行数とハッシュには含める
- ハッシュは大文字に正規化せず、文字列比較のままにする。写し間違いと同じく `summary: digest differs` で止まる側に倒れ、指示ブロックには出力をそのまま貼ると書いた
- `stages/reviewer-brief.md`: 全ヒット要約の段落（作り方・`<rev>` に 40 桁・標準出力だけで完結・件数の多い語の読み方）と保証範囲の文を足した。`roles/gate-runner.md`: 要約の表も同じコマンドに渡し、全行の本文が無いことを表の欠落として扱わないと書いた
- 順 3（`stages/triage.md`）は全行のままで変えていない。version は変更しない
