# リスク許容の引き継ぎで、main の取り込みだけで HEAD が動いたら条件を付けずに引き継ぐ（#1329）

主が許容した PR で main を取り込んだだけなのに、衝突解消が根拠ファイルに当たったために主に聞き直す場面があった（PR #1313。`risk-carryover-check.sh` が終了コード 4 と許可リスト外の衝突解消を返し、判定役の前に PR 全体を見た取り直しのレビューを求められた）。主の判断（2026-10-25）で、前の HEAD のあとに積まれたのが main を取り込む merge commit だけなら、衝突解消の中身・根拠ファイルの差分・取り直しのレビューの範囲・判定役・新しい HEAD の宣言本文によらず許容を引き継ぐことにした。主が許容したのはどう変わるかで、衝突しないように main を取り込むことは条件にしない。

- `scripts/risk-carryover-check.sh`
  - `PR_COMMITS=0`（前 HEAD のあとに merge commit でない commit が無い）のときは、判定 4 の根拠ファイルの PR 自身の差分の比較を行わない。`EVIDENCE_MAIN_ONLY=` / `EVIDENCE_PR_CHANGED=` の行も、判定 4 のバイナリと merge-base の `NG:` も出さず、`EVIDENCE_DIFF_LINES=0` にする。根拠ファイルがどちらの HEAD にも無いときの終了コード 2 は残す
  - `PR_COMMITS=0` で履歴の `NG:` が無ければ、許可リストの条件を満たさない衝突解消があっても `CARRYOVER=yes` と終了コード 0 を返す。`RESOLVED_OUTSIDE_ALLOWLIST=` の行は記録のため今どおり出す
  - 履歴の判定（前 HEAD が祖先でない・merge commit が 2 親でない・main 以外のブランチの merge・第 1 親が PR の履歴の外）は `PR_COMMITS=0` でも残す。これらは「main の取り込みだけ」であることそのものを確かめる判定のため
- `skills/pr-review-gate/stages/hold.md` 3-c: 冒頭の目的の文に、main の取り込みだけなら取り直しのレビューの範囲・判定役などによらず引き継ぐことを足した。呼び方のブロックの終了コード 0 の説明、条件 1 の括弧書き（終了コード 0 の意味）、条件 1 の「`PR_COMMITS=0` なら PR 全体を見た取り直しのレビューを求めない・判定役も起こさない」、条件 4 の「`PR_COMMITS=0` なら求めない」、本文は前の宣言のまま投稿すること、引き継ぎの根拠の行の根拠ファイルの欄の選択肢「PR_COMMITS=0 のとき: 比べず（PR 自身の commit 0 件）」を足した。4 行の構造・行頭と「終了コード 4 の判定役」の節は変えていない
- 外した条件は 3 つで、どれも `PR_COMMITS=0` のときだけ外す: 終了コード 3 の PR 全体を見た取り直しのレビュー、終了コード 4 の判定役の判定、新しい HEAD の宣言本文が前と同一であること（条件 4）。条件 2（前の宣言に根拠ファイルの行がある）と条件 3（元の回答の真正性の確かめ直し）は残す
- `PR_COMMITS` が 1 以上のときの判定と終了コード（優先順 1・4・3・0）は変えていない。PR 自身の commit と許可リスト外の衝突解消が重なったときの終了コード 3 も残す
- `stages/pass.md` は変えていない。合格条件の表の引き継ぎの行は 4 行が揃っているかだけを見ており、develop の合格処理で `needs-carryover-judge` を返すのは終了コード 4 の判定役に回るときだけなので、`PR_COMMITS=0` の終了コード 0 はそのまま合格可になる
- 主が受け入れたリスク: main の取り込みの衝突解消が PR の変更の意味を変えても主に聞き直さない（取り直しのレビューと CI が衝突解消を見る）。merge commit の中に衝突していないファイルへの手入れを入れても終了コード 0 になる（`RESOLVED_OUTSIDE_ALLOWLIST=` の行で記録には残る）
- **読み方の変更**: `PR_COMMITS=0` で今まで終了コード 3・4、またはバイナリ・merge-base の `NG:` で終了コード 1 を返していた取り込みは、終了コード 0 を返す。`EVIDENCE_MAIN_ONLY=` / `EVIDENCE_PR_CHANGED=` の行は `PR_COMMITS=0` では出なくなる
- テスト: `tests/risk-carryover-check.bats` に main の取り込みだけの場面（衝突解消が根拠ファイルの PR の行を変えた・許可リスト外の衝突解消・バイナリの根拠ファイル・merge commit だけでも main 以外の merge）を足した。今まで main の取り込みだけで終了コード 3・4・1 や `EVIDENCE_*` の行を確かめていたテストは、根拠ファイルに触れない PR 自身の commit を積む形（`pr_own_commit`）に直して意味を保った。`tests/pr-review-gate-skill.bats` に 3-c の文言のテストを足した
- openspec change `carryover-main-merge-only` で `dev-workflow-pr-review-gate` の Requirement「前の HEAD の許容を新しい HEAD に引き継いでよい条件」「risk-carryover-check.sh が差分の範囲と根拠ファイルの PR 自身の差分を判定する」「引き継いだ宣言の書式と合格条件」「終了コード 4 は作業の文脈を持たない判定役に比べさせる」を更新。最後の要件の場面「main の取り込みだけなら判定役を起こさない」は、openspec が場面の題名の変更を受け付けないため題名を残して `PR_COMMITS=0` の場合に直し、PR 自身の commit がある場合を別の場面として足した
