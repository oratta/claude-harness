# epic-dispatch.sh launch の SKILL.md の書式に --base と EPIC_DISPATCH_BASE を載せる（#429）

PR #428 のレビューで見つかった should 指摘（F1）の follow-up。`openspec/specs/dev-workflow-develop/spec.md` の launch の既存要件（MUST）は `launch [--note <text>] [--base <branch>] <epic> <child>...` の書式と、`<base>` の既定は `main` で `EPIC_DISPATCH_BASE` で既定を変えられ `--base` が優先する、を既に持っていた（`plugins/dev-workflow/scripts/epic-dispatch.sh` も実装済み）。一方 `plugins/dev-workflow/skills/develop/SKILL.md` の「エピックの扱い」→「回し方」手順 1 はこの書式のまま古く、`--base` も `EPIC_DISPATCH_BASE` も出てこなかった。本体は SKILL.md の手順どおりに呼ぶので、既定ブランチが `main` でないリポジトリでは `git fetch origin main` が失敗して子が 1 件も起動されない、または `main` が残っているだけの古いブランチから子が切られるおそれがあった。

- SKILL.md 手順 1 の書式を `scripts/epic-dispatch.sh launch [--note <text>] [--base <branch>] <エピック番号> <子>...` に置き換え、同じ項目の末尾に「起点は `origin/main`。既定ブランチが `main` でないリポジトリでは `--base <既定ブランチ>` を付ける（環境変数 `EPIC_DISPATCH_BASE` でも既定を変えられ、`--base` が優先する）」を足した
- `plugins/dev-workflow/tests/epic-dispatch.bats` に「回し方」節の該当行を検査するテストを 1 件追加した（`skill: epic run section's launch line documents --base and EPIC_DISPATCH_BASE`）
- 既存の spec.md（launch の要件）・epic-dispatch.sh 本体は変えていない。SKILL.md を既存仕様に追従させるだけの記録同期で、設計判断・振る舞い変更を含まないため仕様化しない（コード直行）と判定した（判断記録: https://github.com/oratta/claude-harness/issues/429#issuecomment-5844070379）
