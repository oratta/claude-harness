# git-destructive-guard: git のオプションの読み方を git 本体に揃える（#821）

破壊的 git 操作を止める hook は、オプションを git 本体と違うように読む箇所があり、実際には push・削除・reset が起きる 4 種の入力を無出力で通していた（PR #794 のレビューで見つかったもので、どれも #794 以前から同じ挙動）。この 4 種を止める。

- `env` の値を取るオプション（`-u` / `--unset`、`-C` / `--chdir`、`-P`、`-a` / `--argv0`）の値を読み飛ばしてからコマンドを決める。`env -u FOO git reset --hard` の `FOO` をコマンド名と読んで git に辿り着かなかった。`-S` / `--split-string` は一覧に入れない（後ろの字句がコマンドとして実行されるので、値として飛ばすと今止まっている `env -S git reset --hard` が通ってしまう）
- `git push` / `git clean` の dry-run は、オプションを左から読んで最後に効いているもので決める。`git push -n --no-dry-run origin main` は `-n` があるだけで dry-run として除外していた。`--no-dry` などの省略形も打ち消しとして読む。`git commit` の `-n` は `--no-verify` なので、`--no-dry-run` があっても止まる
- 値を取る長いオプションは、hook が持つ一覧の中で一意に決まる省略形も同じオプションとして読む。`git push --push-opt -n origin main` と `git clean --excl -n -f` の `-n` はオプションの値で、dry-run ではない
- `--end-of-options` を `--` と同じに扱う。`git push --end-of-options -n origin main` の `-n` は送り先のリモート名になる
- 本当の dry-run（`git push --no-dry-run -n origin main` のように打ち消しの後ろで dry-run に戻したものを含む）と、`env -u FOO git status` のような無害なコマンドは従来どおり何も出さない
- 直していないもの: `env` 以外の wrapper の値を取るオプション（`sudo -u root git reset --hard`）、1 字句にクォートした `env -S 'git reset --hard'`、値を取らないオプションの省略形（`git reset --har`）は今までどおり通る。`--no-force` などの他の打ち消しは読まないので、`git push --force --no-force origin feature-x` は今までどおり止まる。spec `destructive-git-hook` の「守備範囲」に書いた
- `tests/git-destructive-guard.bats` に `@test` を 6 本足した。既存のテストは書き換えていない
