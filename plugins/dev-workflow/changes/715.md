# dev-workflow の作業役・レビュー役・ゲート役に、起動時から運用情報を渡す（#715）

`session-tripwires.sh` が SessionStart で注入する Fable 残量モード・共有枠モード・コンテキスト量の閾値は親セッションにしか入らず、サブエージェントは自分の指示書が参照する値の現在値を知らずに起動していた。

- `hooks/hooks.json` に SubagentStart のエントリを足した（matcher `^dev-workflow:(worker|reviewer|gate-runner)$`）。起動するのは新規の `scripts/subagent-start-context.sh`
- worker / gate-runner には残量モード 2 つと途中計測の閾値の現在値、reviewer には途中計測の閾値の現在値だけを `hookSpecificOutput.additionalContext` で返す。対象外の役（Explore・decider・他プラグイン）には何も返さない（スクリプト側でも `agent_type` を照合する）
- 残量モードの導出は複製せず、`session-tripwires.sh` に `TRIPWIRES_SCOPE=subagent-budget`（残量ブロックだけを本文テキストで出す。usage-probe は走らせない）を足して呼ぶ。未設定時の出力は変えていない
- 途中計測の行は hook 実行時の env の値と正本（decision-criteria「コンテキスト上限（サブエージェントの手渡し）」）への案内だけで、規則は言い換えていない
- 全経路 fail-open（判定できなければ無出力・exit 0）
- 戻し方: hooks.json の SubagentStart エントリを消す（スクリプトと `TRIPWIRES_SCOPE` の分岐は残っていても呼ばれない）
