# epic-dispatch: 止まった子を親の側で判断し、通すものは返事を送り、通せないものを主に分かる形で上げる（#1034）

Orca 経路のエピックで子が主の返事を待って止まると、これまでは親が `stopped` で起こされて、子の番号・理由・推奨・記録の URL をそのまま主に報告していた。hook が止めたファイルの読み取りのように、推奨どおり進めて構わない止まりでも主の手が要り、子の会話を読んでいない主には報告だけでは判断しにくかった。

- `skills/develop/references/parent-pass-criteria.md`（新規）: 親の側で通してよい範囲の基準。9 つの通す条件（先頭は「既存の規則が主に聞くと定めている止まりでない」）、判断できなければ主に上げること、通る例 3 つと通らない例 6 つ（PR トークン上限の引き上げを通さない理由つき）、モデルの出力の 3 行の形を書いた。**この基準は案で、中身は主がこの PR で決める**。#1030（子の PR のマージ）の「合理性があり危険が低い」はこの基準を参照する
- `scripts/stop-judge.sh`（新規）: `stop-judge.sh <epic> <child>`。エピックと子の本文、投稿者が OWNER・MEMBER・COLLABORATOR の注意書き・最新の `子の停止: 主の返事待ち`・同じ子への過去の `親の判断:`、基準のファイル、あれば配役表だけを集め、モデルを 1 回呼んで `判断:`・`理由:`・`返事:`・`記録: <停止の記録の URL>` の 4 行を出す。親や子の会話は渡さない。形が崩れた出力・停止の記録が無い・`gh` の失敗は exit 1。停止の記録と過去の判断も投稿者で絞るのは、子 issue には誰でもコメントできるので、偽の停止の記録で確認画面なしで動く子に返事を送らせないため
- `scripts/epic-dispatch.sh reply [--relaunch] --as <parent|owner> <epic> <child> <text>`（新規）: 子の端末に送り手の頭（`親エピック #<E> の判断（主の承認ではない）:` / `主の返事（親エピック #<E> 経由）:`）を付けて送る。端末があれば子のセッションの端末に送り、端末が無いか `--relaunch` なら（`--relaunch` は先に端末を全部閉じて）`launch` と同じ起動コマンドで起動し直す。Orca は子のワークツリーにシェルの端末（`Terminal 1`）も必ず作るので、子のセッションの端末は、`launch` と起動し直しが `orca terminal create` で得たハンドルを子のワークツリーの `git rev-parse --git-path epic-dispatch-terminal`（git の管理外）に記録したものを優先し、記録が無いか一覧から消えていれば `agentIdentity` が `claude` かタイトルに `Claude Code` を含む端末がちょうど 1 つのときだけそれにする。決まらない（シェルの端末だけのときを含む）・ワークツリーが 0 件か 2 件以上は送らずに `failed`。起動コマンドの組み立ては `launch` と共通にした
- `scripts/epic-dispatch.sh wait --resolve <epic>`: `--watch-stopped` で止まった子ごとに判断を呼ぶ。通すなら `reply --as parent` と同じ処理で送り、送れたらエピックに `親の判断: 子 #N 通した — <理由> <記録>` を残して親を起こさない。エピックに残せなければ `unrecorded <N>` で親を起こす。主に上げる・判断できなかった・通すが送れなかった（1 行目 `親の判断: 通すが送れなかった`）件は子 issue に `親の判断:` と `停止の記録: <URL>` を残して `stopped` で返す。出力は `closed`・`done`・`stopped`・`unrecorded` の 1〜4 行。`--resolve` を付けなければ従来どおり 1〜3 行で、判断は呼ばない
- `skills/develop/SKILL.md`: Orca 経路の手順 2 の `wait` に `--resolve` を足し、`unrecorded` の扱いを書いた。手順 8 を、今回の止まりへの `親の判断:` だけを読み、送信だけが失敗した件は送り直し、それ以外は目的から推奨とリスクまでの順で主に上げ、主の答えを `reply --as owner` で届ける手順に書き換えた。「エピックの子が主の返事を待って止まるとき」に、親から届いた返事を止まった件への返事として受け取り、親の判断を聖域や破壊的操作の承認にしない項目を足した
- `skills/develop/references/reply-after-idle.md`: 子の端末の有無を `reply` が確かめることにし、親の状態の復元の表に `親の判断: 子 #N 通した` を足した（「親が通した判断はまだ記録されない」の段落を消した）
- 判断のモデルと費用: 既定は `claude -p --model sonnet --tools "" --no-session-persistence`（`EPIC_DISPATCH_JUDGE_MODEL` でモデルを、`EPIC_DISPATCH_JUDGE_CMD` でコマンド全体を変えられる）。止まり 1 件につき 1 回呼ぶ。入力は基準のファイル（約 6.5KB）とエピック・子の本文と記録で、#1038 規模のエピックでおよそ 1 万トークン前後の見積もり（実測ではない）。親のセッションを起こして判断するより、親の会話を読み込まない分だけ安い
- 戻し方: この PR の差分を戻す。差分を戻さずに判断を止めるなら、親の手順 2 の `wait` から `--resolve` を外せば従来の動き（止まった子を全部主に報告する）に戻る
