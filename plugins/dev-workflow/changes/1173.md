# 許可を書くスクリプトが形の理由で断ったら、親が子に 1 回だけ打ち直させる（#1173）

子が一時領域の後始末を準備のコマンドとまとめて打つと（`準備 && git -C <repo> checkout -- a.txt` や変数・引用符を使う形）、許可を書くスクリプトは行き先を確定できないとして 1 で断り、develop の本体はすぐオーナーに上げていた。実パスの単独のコマンドに打ち直せば親が許可を書ける操作でも、オーナーの手が止まっていた（エピック #1137 の完了条件の実機確認で起きた。親のエピックは #1476）。

- 許可を書くスクリプト（`scripts/` の下の permit の .sh）: 一時領域の判定に落ちたとき、記録の `command` が単独のコマンドの形（使う判定が許す文字だけで、`;`・`&`・改行を含まない）でなければ、今の理由の行に「形の理由で断った。実パスで単独のコマンドに打ち直せば、新しい拒否の記録で判定し直せる」旨の 1 行を足して 3 で終わる。単独の形なのに落ちたもの・記録の置き場所や中身の確かめに落ちたものは、今までどおり 1。文字の集合と git 用か rm 用かの決め方は共通ファイル `git-guard-scratchpad.py` のもの（`_ALLOWED_CHARS`・`_RM_ALLOWED_CHARS`・`is_rm_command`）を読んで使い、取り出せなければ 1 に倒す。許可を書くかどうかは変えていない
- `skills/develop/SKILL.md`「1 ループ」: `returned no output` を含む段落の、オーナーに上げる条件「0 以外で終わった」に、終了コード 3 で打ち直しの条件を満たし、同じ W の同じ操作についてまだ打ち直しを指示していないときの例外を足した。許可や打ち直しで同じ W を再開することは、同じ指示での起こし直しに数えないことも足した。直後に打ち直しの段落を足した（(1)・(3)・(4) と対象のパスが scratchpad の下の形なら同じ W を再開し、準備は別の呼び出しで先に、破壊的な操作だけを実パスの単独のコマンドで 1 回、拒否されたら 5 項目を報告して返るよう指示する。新しい記録で許可の手順をやり直す。打ち直しのあとの空の return には報告を改めて 1 回だけ求めてよい。打ち直しは同じ W の同じ操作について 1 回までで、また 0 以外ならオーナーに上げる）
- `tests/develop-startup-budget.txt`: SKILL.md の予算を 87349 から 89762 に上げた（足した段落の分。打ち直しの手順は spec で SKILL.md の「1 ループ」の節に書くことになっていて、references に逃がせない）
- テスト: `tests/git-destructive-guard.bats` に 3 件（形の理由で 3・単独の形や記録の確かめで 1・打ち直した単独のコマンドで許可を書いて hook が allow）、`tests/develop-skill.bats` に 2 件（空の return の例外、打ち直しの段落）を足し、#1135 のテストに終了コード 3 の例外の確かめを足した
- 受け入れること: 形と場所の両方で落ちるもの（`cd <外> && git reset --hard`）も 3 になり、打ち直したあとの場所の判定で 1 になってオーナーに上がる。往復が 1 回増えるが、許可は書かれない
- 範囲外: 一時領域の判定（何を許可するか）、hook と子への拒否の理由文、拒否の回数の数え方
- 戻し方: この PR の差分を戻す。終了コード 3 を受けていた呼び出しは 0 以外を失敗として読むので、戻しても壊れない
