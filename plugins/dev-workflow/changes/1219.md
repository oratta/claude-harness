# develop: エピックの 2 節を SKILL.md から references/ へ移す（#1219）

`/develop` の本体は起動のたびに `skills/develop/SKILL.md` を全部読む。そのうち「エピックの扱い」節と「エピックの子が主の返事を待って止まるとき」節は、エピック番号で起動したときかエピックの子として動くときにしか使わないのに、単発の issue や会話依頼でも毎回読み込まれていた（エピック #1225 の子）。

- `skills/develop/references/epic.md`（新規）: 「エピックの扱い」節（条件・作り方・回し方・完了条件）をそのまま移した。中の参照は、子の側の手順を `references/epic-child-stop.md` に向け直しただけで、本文は変えていない
- `skills/develop/references/epic-child-stop.md`（新規）: 「エピックの子が主の返事を待って止まるとき」節をそのまま移した。中の参照は、SKILL.md に残る節（「保留で止まるときの引き継ぎ」「新しいセッションでの再開」）に `SKILL.md の` を付け、「エピックの扱い」→「回し方」を `references/epic.md` の「回し方」に向け直した
- 2 つのファイルに分けた理由: 子の側の手順（約 4,300 字）は、主の返事を待って止まる子と、親から返事が届いた子が読む。親の手順（約 29,000 字）は、エピックを回す親が読む。1 つのファイルにまとめると、止まるだけの子も親の手順を読み込むことになるので分けた
- `skills/develop/SKILL.md`: 2 つの節の見出しは残し、本文を「どの場面で移設先を Read するか」の短い案内にした。エピックの扱いは、`/develop <エピック番号>` で起動したとき・依頼をエピックにするか決めるとき・`nested` の子として W を並列に起こすときか自分の記録先がエピックだったとき。子の停止は、`nested` の子が主の返事を待って止まる前と、`親エピック #` / `主の返事（親エピック #` で始まる入力が届いたとき。「参照」節にも 2 つのファイルを足した。他の節の参照（前提の表の orca/tmux の行、issue を切るときの説明、1 ループの保留の解除、1 ループの W の並列、channel の違い）は移設先を指すように直した。「channel の聞き方」の読み替えの対象の一覧に `skills/develop/references/epic-child-stop.md` を足した（AskUserQuestion に触れる文が移ったため。件数を 8 から 9 にした）
- SKILL.md に残したエピック関係の記述と理由:
  - 「ループの終わり」の `epic-dispatch.sh mark` の段落・`nested` の完了報告の 1 行目・PR を伴わない記録先 issue を閉じたときの `mark`: ループの終わりに必ず通る手順で、`mark` を呼ぶ・呼ばないの判定（PR がマージ済みか、記録先が Draft PR か）は単発 issue でも行うため
  - 「前提」の表の `gh` の行（`dependencies/blocked_by`）と `orca` / `tmux` の行: 起動時に前提を確かめる表で、無いときに何ができなくなるかを単発 issue の develop でも読むため（`orca` / `tmux` の行の参照先だけ移設先に直した）
  - 「実行モード」の unmanned の `blocked_by`（複数 change に割れたら子 issue を作って順序付ける）: 単発 issue の unmanned でも W の分割判定で起きるため
  - 「channel の主への発言」の `epic-dispatch.sh` の失敗の報告: channel の主への発言の宛先の規則で、エピックの手順ではないため
- 他のファイルの参照を移設先に向け直した（本文は変えていない）: `skills/develop/references/decision-criteria.md`（境界の一言定義）、`skills/develop/references/parent-merge-criteria.md`（親の手順の場所）、`skills/develop/references/reply-after-idle.md`（手順 8 の場所）、`references/ci-watch.md`（停止の記録の手順の場所）、`scripts/epic-dispatch.sh`（冒頭のコメント）
- 直していない参照: `commands/develop.md` の 16 行目と 73 行目（「SKILL.md「エピックの扱い」に従い」など）はエピック #1225 の別の子が書き換えるファイルなので触っていない。`openspec/specs/dev-workflow-develop/spec.md` と `openspec/specs/dev-workflow-ci-watch/spec.md` が置き場所を SKILL.md と名指ししている件は #1241 で扱う
- テスト: `tests/develop-skill.bats`・`tests/epic-dispatch.bats`・`tests/parent-merge.bats`・`tests/develop-channel-mode.bats` の節の切り出し（`section` / `subsection`）に読むファイルを渡せるようにし、移した節を読む箇所を移設先に向けた。`tests/develop-skill.bats` に、SKILL.md の案内の文・移した節の固有語句が SKILL.md に無く移設先にあること・移設先の中の参照の向きを確かめるテストを足した
