# rm-permission-guard: `cd <一時領域> && rm <相対>/*` の形にも親の許可を効かせる（#1159）

#1134 の rm 用の判定は、`cd` を含むコマンドの相対の削除先を、`cd` の移り先と、`cd` が失敗して `rm` が元の cwd で走る場合の cwd の両方を基準に解決し、両方が一時領域の中であることを求めていた。区切りが `&&` でも同じに見ていたので、cwd が一時領域の外（普通はワークツリー）の子が `cd <一時領域> && rm -f x/*` で後始末すると、親は許可を書けず毎回オーナーに上がっていた（#1134 の実機確認で判明）。

- `scripts/git-guard-scratchpad.py` の `check_rm`: `cd` を含み、コマンドに `;` も改行も無い（区切りが `&&` だけ）ときは、`cd` の移り先を基準にした解決だけで削除先を判定する。`&&` では `cd` が失敗すると後ろの `rm` は走らないため
- `;` か改行が 1 つでもあれば（`cd ./a && rm x; rm y` のように混ざる形を含む）、今までどおり両方の基準で判定する
- hook（`rm-permission-guard.sh`）と許可を書くスクリプトは同じ判定を使うので、両方の振る舞いが同時に変わる。どちらのスクリプトも、使える文字・`cd` と `rm` の引数の規則・許可の形・拒否の記録も変えていない
- `tests/rm-permission-guard.bats`: 判定を直接かけるテスト 1 件と、hook と許可を書くスクリプトを通すテスト 2 件を足した
- 仕様: openspec の `rm-permission-hook`「rm の一時領域の判定」（change `rm-cd-and-success-base`）
- 受け入れること: `;` と `&&` が混ざる形は、`&&` の側の `rm` も 2 つの基準で見るので止めすぎる（絶対パスで書けば基準によらず判定できる）
- 戻し方: この PR の差分を戻す。置き場所やファイルの形は変えていないので移行は要らない
