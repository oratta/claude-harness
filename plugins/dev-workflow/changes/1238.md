# リスク許容の引き継ぎを、根拠ファイルの PR 自身の差分で判定する（#1238）

pr-review-gate 手順 3-c（前の HEAD の許容の引き継ぎ）は、main の取り込みで根拠ファイルが変わったときと、PR 自身の commit（W の修正・CI の直し）が積まれたときに、リスクの中身が同じでも `risk-carryover-check.sh` が終了コード 1 を返し、主に同じリスクを聞き直していた。判定の基準を「ファイルが変わったか」から「リスク宣言の中身が前と同じか」に移す（主の決定、issue #1238 のコメント）。

- `scripts/risk-carryover-check.sh`
  - 判定 2: merge commit でない commit を `NG:` から外し、件数を `PR_COMMITS=` で出す。merge commit の条件（2 親・第 2 親が base の祖先・第 1 親が PR の履歴の中）は残す
  - 判定 4: 根拠ファイルが前後で変わっても、PR 自身の差分（各 HEAD と base の merge-base からの差分の、`-U0` の削除・追加の行を順序のまま）が同じなら `EVIDENCE_MAIN_ONLY=<ファイル>` で出して引き継げる側にする。違えば `EVIDENCE_PR_CHANGED=<ファイル>` と `EVIDENCE_DIFF_LINES=<前後の diff の追加と削除の合計>` を出す。前後で変わったバイナリの根拠ファイルと、merge-base が 1 つに決まらないとき（criss-cross merge）は `NG:`
  - 終了コード 4（`CARRYOVER=if-judged`）を足した: `NG:` が無く、PR 自身の差分が前後で違う根拠ファイルがある。優先順は 1 → 4 → 3 → 0。スクリプトは引き継げるかを決めない
- `skills/pr-review-gate/stages/hold.md` 3-c: 冒頭の目的を「main の取り込みや PR 自身の修正で HEAD が動いても、リスク宣言の中身が前と同じなら聞き直さない」に直した。呼び方のブロックに新しい出力と終了コード 4 を足し、終了コード 4 は引き継がず手順 6 で主に聞き、`EVIDENCE_PR_CHANGED=` の行を理由に添えると書いた。引き継ぎの根拠の行に PR 自身の commit の件数と、根拠ファイルが「diff は空」か「main からの変更だけ」かの欄を足した（4 行の構造と行頭は変えていない）。3-c 以外の節は変えていない
- **読み方の変更（BREAKING）**: 今まで終了コード 1 だったもののうち、main からの変更だけで根拠ファイルが動いた場合と、根拠ファイルに触れない PR 自身の commit の場合は 0 か 3 に、PR 自身の差分が変わった場合は 4 になる。この版のスクリプトを古い 3-c の文面（0 / 3 以外は主に聞く）と組み合わせても、4 は主に聞く側に倒れるだけ
- 本文の前提との食い違い: issue 本文は「根拠ファイルの変更だけが `NG:` の理由のとき」に判定役を呼ぶ案だったが、今までのスクリプトでは PR 自身の修正が判定 2 で必ず `NG:` になり、その状態が起きなかった。そのため判定 2 も直した（記録先にコメント済み）
- 1 本目の change（上の 2 項目）の時点では終了コード 4 は主に聞いていた。2 本目の change `risk-carryover-decider-judge`（次の項目）で判定役に比べさせる経路を足した
- 2 本目の change `risk-carryover-decider-judge`: 終了コード 4 を、作業の文脈を持たない判定役（`dev-workflow:decider`・`opus`）に比べさせ、判定が「同じ」なら主に聞かずに引き継ぐ
  - `skills/pr-review-gate/stages/hold.md` 3-c に「終了コード 4 の判定役」の小節を足した。回す条件は、条件 2〜4 を満たし、`RESOLVED_OUTSIDE_ALLOWLIST=` があれば終了コード 3 と同じ PR 全体を見たレビューの確認も満たし、`EVIDENCE_DIFF_LINES=` が 100 以下で、使える判定の記録が無いとき。渡すのは前後の HEAD の根拠ファイルの diff と前の宣言の本文だけで、記録先の本文・レビューの指摘・W の return・作業の会話は渡さない。返答の 1 行目は `引き継ぎ判定: 同じ|変わった|判断できない` のどれかちょうどにさせ、外れたら「判断できない」として依頼し直さない。判定の記録（1 行目 `引き継ぎ判定:`、`前 HEAD:`・`新しい HEAD:`・`前の宣言:`・`根拠ファイル:`（カンマ区切り 1 行。順序を問わず同じ集合で照合）・`差分の行数:`・`判定役:`・`理由:`。`対象 HEAD:` は使わない）を PR に代理投稿し、前後の HEAD と根拠ファイルが一致する最新 1 件だけを使う。条件 1 の終了コード 4 の段落・引き継ぎの根拠の行（終了コード 4 と判定の記録のリンクの欄。4 行のまま）・引き継げないときの理由の添え方も直した
  - 判定役を起こすのは、develop の外のメインセッションではゲート自身、develop では本体。develop の合格処理の G は Status `needs-carryover-judge`・`次の段: 合格処理` で返し、本体が判定役を起こして記録を投稿し、合格処理の G を新しく起こす（`stages/hold.md` の return の欄、`stages/pass.md` の入口、`skills/develop/references/roles/gate-runner.md` の Status と段の表、`skills/develop/SKILL.md` の (4) とモデルの表）。従来経路の一括の G は判定役を起こさず主に聞く
  - `SHARED_BUDGET_MODE=depleted` では判定役を起こさず、起こす側（ゲート自身か本体）が `引き継ぎ判定: 判断できない` の記録を投稿して主に聞く。sonnet で判定させる案は採らなかった（主の承認を省く判定を、主が指定したより弱いモデルで行わないため）。develop の合格処理の G は depleted でも `needs-carryover-judge` で返し、記録を自分で投稿しない
  - 行数の上限 100 は実測ではない。過去の引き継ぎの宣言で根拠ファイルの差分の行数を数えれば見直せる
  - Requirement 名「risk-carryover-check.sh が差分の範囲と根拠ファイルの無変更を判定する」を「…根拠ファイルの PR 自身の差分を判定する」に変え、`skills/pr-review-gate/declarations.md` の根拠ファイルの説明と `tests/risk-carryover-check.bats` のコメントの旧い言い方を直した
  - Codex の G は変えていない。`scripts/codex-develop.py` の `PHASES['gate']` が `gate-runner.md` を指し、`if phase == 'gate':` のブロックが `stages/pass.md`・`stages/hold.md` を含む pr-review-gate の段のファイルを正本に入れていること、prompt の「needs-reviewer/needs-decider を返す」が一般の言い方であることを確かめた
