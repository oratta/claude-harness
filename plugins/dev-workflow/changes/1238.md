# リスク許容の引き継ぎを、根拠ファイルの PR 自身の差分で判定する（#1238）

pr-review-gate 手順 3-c（前の HEAD の許容の引き継ぎ）は、main の取り込みで根拠ファイルが変わったときと、PR 自身の commit（W の修正・CI の直し）が積まれたときに、リスクの中身が同じでも `risk-carryover-check.sh` が終了コード 1 を返し、主に同じリスクを聞き直していた。判定の基準を「ファイルが変わったか」から「リスク宣言の中身が前と同じか」に移す（主の決定、issue #1238 のコメント）。

- `scripts/risk-carryover-check.sh`
  - 判定 2: merge commit でない commit を `NG:` から外し、件数を `PR_COMMITS=` で出す。merge commit の条件（2 親・第 2 親が base の祖先・第 1 親が PR の履歴の中）は残す
  - 判定 4: 根拠ファイルが前後で変わっても、PR 自身の差分（各 HEAD と base の merge-base からの差分の、`-U0` の削除・追加の行を順序のまま）が同じなら `EVIDENCE_MAIN_ONLY=<ファイル>` で出して引き継げる側にする。違えば `EVIDENCE_PR_CHANGED=<ファイル>` と `EVIDENCE_DIFF_LINES=<前後の diff の追加と削除の合計>` を出す。前後で変わったバイナリの根拠ファイルと、merge-base が 1 つに決まらないとき（criss-cross merge）は `NG:`
  - 終了コード 4（`CARRYOVER=if-judged`）を足した: `NG:` が無く、PR 自身の差分が前後で違う根拠ファイルがある。優先順は 1 → 4 → 3 → 0。スクリプトは引き継げるかを決めない
- `skills/pr-review-gate/stages/hold.md` 3-c: 冒頭の目的を「main の取り込みや PR 自身の修正で HEAD が動いても、リスク宣言の中身が前と同じなら聞き直さない」に直した。呼び方のブロックに新しい出力と終了コード 4 を足し、終了コード 4 は引き継がず手順 6 で主に聞き、`EVIDENCE_PR_CHANGED=` の行を理由に添えると書いた。引き継ぎの根拠の行に PR 自身の commit の件数と、根拠ファイルが「diff は空」か「main からの変更だけ」かの欄を足した（4 行の構造と行頭は変えていない）。3-c 以外の節は変えていない
- **読み方の変更（BREAKING）**: 今まで終了コード 1 だったもののうち、main からの変更だけで根拠ファイルが動いた場合と、根拠ファイルに触れない PR 自身の commit の場合は 0 か 3 に、PR 自身の差分が変わった場合は 4 になる。この版のスクリプトを古い 3-c の文面（0 / 3 以外は主に聞く）と組み合わせても、4 は主に聞く側に倒れるだけ
- 本文の前提との食い違い: issue 本文は「根拠ファイルの変更だけが `NG:` の理由のとき」に判定役を呼ぶ案だったが、今までのスクリプトでは PR 自身の修正が判定 2 で必ず `NG:` になり、その状態が起きなかった。そのため判定 2 も直した（記録先にコメント済み）
- 後続の change `risk-carryover-decider-judge` で、終了コード 4 を判定役（`dev-workflow:decider`）に渡して比べさせる経路と、判定役に渡す行数の上限を決める。この change では終了コード 4 は主に聞く
