# pr-review-gate: 段 C の親の取得の手順の文を直す（#1519）

PR #1513（#1011）の独立レビューで出た、段 C の親の取得の手順の止めない指摘 8 件の文言を直した。判定の骨格・Gate Result の形式は変えていない。

- `stages/triage.md` 段 C: 親の取得コマンドの末尾に ` 2>&1`（`HTTP 404` は標準エラーにしか出ないため）。取得は「段 B の前に済ませる」（候補探しの前では段 B の範囲の読みが親を知らないまま当たるため）。やり直しの出力も同じ判定にかける。親の取得が失敗し続けたときの答えは記録先の本文に足す。子に足す要求の形（`-X POST repos/<親のリポジトリ>/issues/<親の番号>/sub_issues -F sub_issue_id=<id>`）を書いた
- 守備範囲の許す誤りに 2 件を足した: 親が見えず 404 になる場合を「親が無い」と読むこと、別リポジトリの親ですでに親の子である同じ場所の issue があっても新しい子 issue ができること
- `gate-runner.md` と `reviewer-brief.md`: `## 条件の答え` の読み書きに「親が別リポジトリなら親のリポジトリの本文（`stages/triage.md` の段 C の段落）」を足した（spec の同じ文も同じ語句。archive で main の spec に入る）
- `tests/pr-review-gate-skill.bats`: 上の語句が triage.md・spec・gate-runner.md・reviewer-brief.md で揃っている検査を足した
- 項目 1 の選択: 手順の文で直さず、守備範囲の許す誤りに足した。`/parent` の 404 は `No parent issue found` と、親は有るが読めない場合で応答が同じで、G は区別できないため。既存の「記録先 issue 自体が見えない 404」の許容と同じ型
- 戻し方: この PR の差分を戻す
