# dev-workflow: 1 行目の質問のあとに文が続くマージの依頼でも、主への確認の番号を Stop の hook が確かめる（#1370）

`owner-message-number-check.sh`（Stop の hook）が確かめる発言の判定を広げた。1 行目の `？` のあとに同じ行で説明が続くマージの依頼（「PR #1330 を GitHub でマージしてもらえますか？ マージすると、子 #1303 の修正が main に入ります。…」）が、区切りより上に番号を残したまますり抜けていた。

- 1 行目が `？` か `?` で終わる従来の条件は残し、1 行目の最初の文が `？` か `?` で終わる場合も対象にした。最初の文は、1 行目から引用（`「」` `『』` `“”` `""` の中身。入れ子は外側の閉じまで、1 行目で閉じない引用は 1 行目の終わりまで）と URL を 1 回の走査で隠し、`。` `！` `!` `？` `?` の最初までで数える。URL の中で開いて閉じる引用の記号は URL の一部、外で開いた引用の閉じが URL の中に来たら URL はその手前で終わる、URL の中で閉じない開きは引用にしない
- 質問を引用した答え・作業報告（「表示は「PR #1330 をマージしますか？」です。」など）は、従来どおり対象にしない。引用の中に URL がある答え、URL の中に引用の記号がある参照先の答え（「#1330 の参照先は https://example.com/「入門」?lang=ja です。」）、次の行で閉じる引用、入れ子の引用も同じ
- 差し戻しの文面、答え方の語、他の hook は変えていない
- 受け入れること: 引用を伴わない説明の途中に `？` を含む 1 行目の発言（最初の文が `。` で終わるもの）は、従来どおり対象外。引用の閉じ記号で終わった URL の直後に空白なしで `?lang=ja` のような文字が続く書き方（「#1330 の参照先は「https://example.com/x」?lang=ja です。」）は対象になる
- 戻し方: この PR の差分を戻す
