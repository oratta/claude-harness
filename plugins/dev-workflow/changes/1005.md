# select-account.sh: オフのスロットを明示選択したときの案内を accounts.sh on に合わせる（#1005 #987 #988）

`accounts.sh off b` のあとに `cld-account b` を実行すると、stderr で「登録簿を手で書き換えろ」と案内されていた。README が案内する戻し方は `accounts.sh on <id>` なので、実際に目にする文面を合わせた。

- `scripts/select-account.sh`: オフのスロットの明示選択（exit 2）の stderr が `account b is off (enabled is false in <登録簿のパス>): run accounts.sh on b` の 1 行になった。id・オフであること・`enabled`・登録簿のパスは残してあり、1 行のまま。stdout、終了コード、使用量による選択の振る舞いは変えていない。この文面を grep している呼び出し側があれば、`set "enabled" to true` の文字列は無くなる
- `tests/account-selector.bats`: `accounts.sh off b` のあとの `select-account.sh b` の stderr に `accounts.sh on b` が含まれるテストと、既定スロット a がオフ・b がオンで使用量が欠測のとき `selected=a reason=default-due-to-missing-usage margins=a:off,b:missing` になるテスト（#987）を足した。既存のテストは変えていない
- 仕様: `usage-account-registry` の明示選択の戻し方を `accounts.sh on <id>` に、`enabled` 判定の入力に `accounts.sh on|off` の出力を、レジストリを読む箇所に `accounts.sh list` を足した（5 か所 → 6 か所）。`dev-workflow-escalation-tripwires` の usage-probe の実行条件にオフのスロットの扱いを 1 行足した（#988）
- Codex 側（#978）は変えていない
- 戻し方: この PR の差分を戻す。登録簿や状態ファイルの形は変えていないので移行は要らない
