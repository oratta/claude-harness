# develop: エピックの手順書を読む場面で分ける（#1684）

`references/epic.md` に集まっていた親の操作を場面別に分け、子の入口から親専用の操作本文を外した。経路・停止・権限・委任の判定条件、スクリプトと出力語は変えていない。

- 通常進行は epic-loop、停止は epic-stop、マージ待ちは epic-merge-wait、別 repo は epic-multirepo、subagent は epic-subagent に移した。
- 委任の定型・有効性・種類別条件は epic-delegation、声かけの受信契約は epic-keepalive、親の送信判定は epic-keepalive-watch、W の枠規則は epic-worker-slots に分けた。時間分類は reply-after-idle、子の重複例は parent-pass-criteria の例を読む。
- 文言の存在検査を移動に耐える形にし、固定した 10 場面の全文集合と独立した bytes 予算、参照削除・親操作混入・正本一本化の検査を追加した。初期予算は最終実測ちょうどで余白 0。startup と injection の予算は変えていない。
- ゲートの変更は pass.md の参照パスだけ。判断基準の例は維持し、移した節への参照を付け替えた。main specs への反映は finish の archive で行う（delta 6 件は対応確認済み）。
- 戻す場合はこの変更の差分を戻す。状態ファイル・保存済みコメントの移行は要らない。

## 残した互換分岐

| 分岐 | 残す根拠 |
|---|---|
| 更新前の子の停止記録を先に読む | 保存済み GitHub コメントと旧子プロセスを排除できない |
| 旧 `親の判断: 判断できなかった` の送信失敗の再送 | producer が変わっても旧コメントは残る |
| 記録導入前の子の adopt | 記録の無い既存の子がすべて消えた保証が無い |
| 権限コメントの無い再開の既定値投稿 | 過去のエピックを再開できる |
| closed 時の子エピック除外 | 旧状態からの復元と手動変更を排除できない |
