# subagent-context-audit.sh と epic-launch-tmux.sh も会話記録の探索で CLAUDE_CONFIG_DIR を見る（#1481）

`CLAUDE_CONFIG_DIR` で `~/.claude` 以外の設定を使うセッションで、`subagent-context-audit.sh` は別の設定の会話記録を集計し、`epic-launch-tmux.sh` は送った文が会話ログに現れたかを確かめられなかった。#1231（PR #1489）で `subagent-context.sh` と `pr-token-budget.sh` に入れた探索先の順を、この 2 本にも入れた。

- `scripts/subagent-context-audit.sh`: 走査対象の既定が `${CLAUDE_PROJECTS_DIR:-${CLAUDE_CONFIG_DIR:-$HOME/.claude}/projects}` の順で決まる。cache の既定も `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/.subagent-context-audit` になった（`SUBAGENT_CONTEXT_AUDIT_CACHE`、`--cache`、`--projects` の明示は従来どおり優先する）
- `scripts/epic-launch-tmux.sh`: `log_has_prompt` が読む会話ログの場所が同じ順で決まる
- `CLAUDE_CONFIG_DIR` と `CLAUDE_PROJECTS_DIR` がどちらも未設定のときの挙動は変わらない（`$HOME/.claude` の下）
- 仕様: `dev-workflow-execution-strategy`「サブエージェントのコンテキスト量の母集団集計」と `dev-workflow-epic-state`「tmux の部品は子を独立した Claude Code のセッションとして tmux のウィンドウに起動する」の該当箇所を直した
- 戻し方: この PR の差分を戻す。状態ファイルの形は変えていないので移行は要らない。`CLAUDE_CONFIG_DIR` を使っていて、すでに旧 cache（`~/.claude/.subagent-context-audit`）がある場合、新しい cache は別の場所に作られる（旧 cache は読まれなくなるだけ）
