# #1743 子の本体の長い背景作業待ち

## 選んだ扱い

再開可能な外部依存は、既存の依存登録と途中経過・再開条件の保存が成功し、子所有の実行中作業が残らないと確認してから停止へ移す。実行中の agent・自分の CI・Monitor・Codex コマンドはセッションと実行 ID を保持する。

本体の現行会話が TTL 1h、最後の成功リクエストから 3600 秒未満で、既存の通知や有限待ちが 45 分以内に本体へ返る保証がない場合だけ、一回限りの 45 分タイマーを一つ置く。5m / unknown は維持対象外。維持は最初のタイマーを置いた時刻を基点に 12 時間までで、再設置で基点を更新しない。12 時間に達したら次のタイマーを置かず、元作業と実行 ID を保持して完了通知を待ち、上限後に届いたときは一度の書き直しを受け入れる（親が停止済み子を保つ上限 changes/1556.md と同じ 12 時間）。元作業の通知を優先し、不要になったタイマーを取り消す。入口と詳細は develop の SKILL.md と child-background-wait.md、雛形と契約の検査は child-background-wait.bats に追加した。

## 費用比較と採用理由

出典: https://github.com/oratta/claude-harness/issues/1743#issuecomment-7087935739

12 時間上限の追記: https://github.com/oratta/claude-harness/issues/1743#issuecomment-7089486648

API 定価換算で会話 20 万トークンを比較した。維持ごとに通知受信と再設置の結果応答で少なくとも二回の cache-read があり、新規入力・出力、初回設置・取消・TTL 確認のツール往復も加算される。旧会話部分だけでも、24 時間無上限で維持して最後に一度だけ再開する旧方針は約 $2.52 で、一度の 1h 書き直し $1.60 より高い。12 時間で維持を打ち切る新方針では、維持 16 回と最後の再開で約 $1.32 となり $1.60 を超えない。上限後にキャッシュが切れてから完了する場合の一度の書き直しは別にかかる。単にキャッシュが失効しただけでは課金されず、再開リクエストで書き直したときに費用が生じる。サブスク枠の消費率や常に最安になることを保証する比較ではない。

数時間の実作業待ちでは作業を保持して書き直しを避ける余地があるため 12 時間を上限とする条件付き維持を採用し、日単位の再開可能な外部依存は保存して止める。一律の再起動や 5m 向けの頻回の起床は採らない。
