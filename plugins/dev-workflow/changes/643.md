# 同じ窓の実効値は取得時刻が新しい方を採る（#643）

週の枠を手動でリセットすると、リセット時刻は変わらずに使用率だけが下がる。「同じ窓は大きい方」の規則ではリセット前の古い snapshot の 100% が新しいセッション記録の 0% に勝ち、`cld`（`select-account.sh`）がリセット済みのアカウントを避けていた。

- `scripts/usage_view.py`: `_combine` は同じ窓（リセット時刻の差 3600 秒以内）で両方の取得時刻があり値が違えば、取得時刻の新しい情報源の値（使用率・リセット時刻とも）を採る。取得時刻が等しい・片方無しのときだけ大きい方を採り、リセット時刻と取得時刻もその情報源のものを使う
- `select-account.sh` は `usage_view.build_view` を使うのでコード変更なし。snapshot 100%・新しい記録 0% のアカウントを週 0% として選ぶテストで固定した
- `skills/develop/references/decision-criteria.md`: 実効値の規則の説明を新しい規則に合わせた
- 記録の `observed_at` が「値が変わった時刻」になる（statusline 側の変更）ため、usage-probe が API を呼ぶ頻度は上がる
