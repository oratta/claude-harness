# dev-workflow: CI の見張りで止まったエピックの子の停止の記録に、止まった時点の PR の HEAD の短い SHA を書かせる（#1298）

#1271 で、上限で止まった子を親が通すときの `理由:` に PR 番号・落ちたチェック名・HEAD の短い SHA を子の停止の記録から取って書くと決めたが、記録の形には HEAD を書く決まりが無く、親はいつも `不明` と書くことになっていた。

- `skills/develop/references/epic-child-stop.md` の「記録の形」に、CI の見張り（`references/ci-watch.md`）の `escalate`、`obs.state` が `wait` でない `none`（前回と同じ状態・同じ HEAD の決着。親が追加のやり直しを許したあと同じ HEAD でまた落ちたときはこれになる）、直し方の手順 7 のどれかで止まったときは、`再開に要る途中経過:` に PR の URL・落ちたチェック名・止まった時点の PR の HEAD の短い SHA（PR の HEAD のコミット SHA の先頭 7 文字。`ci-watch.sh next` の `obs.head` か `gh pr view --repo <owner/repo>` の `headRefOid` から取る）を書くことを足した。取れなければ `HEAD 不明` と書く
- 項目は 7 つのまま。HEAD のための 8 つ目の項目は足していない（CI に関係しない止まりで常に `なし` になり、「7 つの項目」の記述と記録を読む部品のテストを広く直すことになるため。`再開に要る途中経過:` はもともとコミット・PR を書く項目）
- `references/ci-watch.md` の 6 の表の `escalate` と `none` の行に、エピックの子のセッションは止まる前に `epic-child-stop.md` の手順どおり記録を残して `mark stopped` で止まる（書き方はそこが正本）ことを 1 文ずつ足した。桁数や取り方は写していない
- 記録を読む部品（`scripts/stop-judge.sh`・`scripts/epic-dispatch.sh`・`parent-merge-criteria.md`）と `parent-pass-criteria.md` は変えていない。スクリプトの動きも変わらない
- `openspec/specs/dev-workflow-develop/spec.md` の要件「エピックの子の停止の記録は…」と、`openspec/specs/dev-workflow-ci-watch/spec.md` の要件「CI の見張りの手順は共有 reference に 1 本置く」に同じことを足した（change: epic-child-stop-ci-head-sha）
- テスト: `tests/epic-dispatch.bats` に記録の形の節の確認を、`tests/ci-watch.bats` に `escalate` と `none` の行の確認を足した
- 戻し方: この PR の差分を戻す。状態ファイルや記録の項目は変えていない
