# 子のターン状態フックを対象セッションに限定

同じ worktree で別セッションや `claude -p` を動かしても、本来の子の `turn_input`・`turn_state`・更新時刻を上書きしない。対象外 Stop は状態行を求めず、既存の番号・URL 検査の結果を返す。対象外の識別は詳細検査・ログ読取・ロック待ちより先に行い、入力のロック内でも再確認する。

初回登録と別 ID への切替は、記録の子・親・エピックのリポジトリと一致する既存 launcher の起動指示に限る。初回は世代1、切替は旧世代+1。同 ID の通常入力と Stop は従来どおり扱う。エピックの repo 省略は子とエピックが同じ repo の場合だけ許す。同 ID への起動指示の再送は `owner` とする。

未登録の旧記録や誤った ID が保存された記録には、本来の子のセッションへ一致する `/develop #<子> （エピック #<親> の子。…）` を送り直す。任意入力や Stop では登録しない。起動形は認証ではなく、別セッションへの意図的な一致起動指示も切替として受理する。

schema=1・親の読取項目・launcher の API・フック配線・版は変更しない。戻す場合はこの実装と後続の仕様反映を revert する。記録の手動移行や任意拡張の削除は不要だが、別セッションの誤更新も戻る。

repo の照合は子・親・記録側を双方小文字化し、省略時の同一 repo 判定も同様とする。記録の表記は保つ。

対象外入力の無出力の限定例外として、両ターン項目が無く有効な ID の通常入力や不一致起動指示には、`hookSpecificOutput.hookEventName=UserPromptSubmit` と `additionalContext` で非ブロック通知を返す。記録パス・親子識別子と、未登録で入力記録・状態行検査が適用されていない旨、本来の子ならその子へ一致する起動指示を再送して登録を確認する手順、別用途なら対応不要と案内する。受信者を子と断定せず、自動登録・再送しない。予約文完全一致と登録済み別 ID は無通知。通知ではロック・記録更新・ログ読取を行わない。

移行は本来の子へ一致する起動指示を再送し、`turn_input.session_id` がその子の ID、`sender=startup`、世代が初回1または切替前+1であることを確認してから通常作業へ戻る。不一致は登録成功扱いにしない。更新直後に入力なしで Stop する旧セッションには通知が届かないため、稼働中の旧記録は移行時に確認する。未登録 Stop は既存検査の出力・終了コードを保ち、完全防止は保証しない。過去のリスク宣言は保存する。
