# PR の状態の分類と次の一手を決める pr-state.sh を足す（#521）

flatmate の住人（`scripts/pending-mirror.sh` の pr-watch）が持っていた「止まった PR をどう分類し、次に何をするか」の判断を、住人の状態ファイル・依頼の列・あなた待ちに依存しないスクリプトとして `plugins/dev-workflow/scripts/pr-state.sh` に置いた。セッションと住人が同じ判断を呼べるようにするためで、セッションへの配線（#522 / #523）と flatmate 側の置き換え（genetta-inc/flatmate#976）は別の change で行う。

- `observe` は `gh pr view --json mergeable,statusCheckRollup,headRefOid` の JSON を `conflict` / `ci-fail` / `ready` / `wait` に分類し、落ちたチェックごとに原因を `runner-lost`（annotation に実行マシンの通信切れの文言）→ `unrelated`（`--unrelated` で渡したチェック名）→ `real` の順で仕分ける。annotation の手がかりはジョブ ID で引き、別ワークフローの同名チェックに移さない
- `decide` は観測と前回の状態から一手（`none` / `ready` / `rerun` / `fix` / `escalate`）と次の状態を返す。やり直しは HEAD ごとに 1 回、修正回数は PR ごとの累計で 3 回目に `escalate`。`wait` の観測は HEAD が同じなら前回の状態を上書きしないので、`UNKNOWN` を挟んだ再観測で修正回数が増えない（flatmate#899）
- `annotations <owner/repo>` だけが `gh api .../check-runs/<job>/annotations` を呼ぶ。Actions ではジョブ ID とチェックラン ID が同じ値であることを oratta/claude-harness と genetta-inc/flatmate の実物の失敗ジョブで確かめた。1 件の取得に失敗しても警告して残りを続ける
- 状態のキー（`state` / `head` / `reran_head` / `fixes` / `raised`）は flatmate の状態ファイルと同じで、知らないキー（`last_done` など）は引き継ぐ。置き換えたときに既存の修正回数と上げ済みの印がそのまま効く
- flatmate の pr-watch から見て変わる点は 2 つ。手がかりの無い CI 失敗はやり直さずに直しに回す（flatmate は run ID があれば 1 回やり直していた。不安定なテストをやり直したいときはそのチェックを `--unrelated` で渡す）。一手の名前は住人の仕組みの名前（`queue` / `stall`）をやめて `fix` / `escalate` にした
- 受け入れたリスク: GitHub が通信切れの文言を変えると通信切れも直しに回る（文言は定数 1 か所）。PR に関わる失敗を呼び出し側が `--unrelated` で渡すと CI 1 周分を失う（同じ HEAD では 1 回だけ）
