# エピックの子が 1 件ずつしか着手できないときも、子ごとに別のセッションで回す（#844）

`/develop <エピック番号>` は、同時に着手できる子が 2 件以上のときだけ Orca の子ワークツリーの別セッションで子を回し、1 件のときは親のセッションの中で子の作業者・レビュアー・ゲート担当を順に動かしていた。1 件ずつ進むエピックでは、エピックの進行と子の作業の報告が 1 つの会話に混ざり、Orca 経路を通らないので実機確認もできなかった（エピック #811 自身がこの形で回った）。

- `scripts/epic-dispatch.sh route` は、`nested` でなく、`orca` が PATH にあり、`orca worktree current --json` が exit 0 で、子が 1 件以上あれば、子が 1 件でも `orca` を返す。`orca` が無い・Orca 管理外・無人実行（`--unmanned`）はサブエージェント方式のまま。子 0 件は今までどおり `subagent`
- 「1 件以上」という下限を spec の `route` の文に残したのは、子 0 件を `subagent` に保つため。「件数の条件が残っていない」とは、2 件以上という条件が無いことを指す
- develop の SKILL.md「回し方」の「経路の決め方」の段落、README.md、plugins/dev-workflow/README.md の 1 行から件数の条件を外した。Orca 経路の手順 2〜4 と `reap` / `wait` は別の子 #827 の範囲なので触っていない
- すでに `回し方: サブエージェント` と記録したエピックを途中で切り替える規則は作らない。経路は最初の開始時に 1 回だけ決め、再開時は `回し方:` の最新のコメントから引き継ぐ（変更なし）。この変更より前に記録した進行中のエピックは、終わるまでサブエージェント方式のまま進む。切り替えたいときはオーナーが `回し方:` のコメントを手で書き直し、サブエージェント方式の子が全部終わってから再開する
- 受け入れた制約: 子ごとに `/develop` を丸ごと回すセッション（既定で opus）が、着手できる子が 1 件のときも 1 本増える。状況の見やすさと引き換えにする（2026-10-08、オーナーの指示）
