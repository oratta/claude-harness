# Stop hook: 主への発言に issue・PR の番号が残っているかリンクが無ければ、ターンを終える前に 1 回だけ書き直させる（#1215）

正本（`~/.claude/output-styles/readable.md` の節 3）は、主に判断・確認・操作を求める発言で、issue・PR を番号で指さず中身で書き、番号は末尾の URL にだけ置くと決めている。それでも、1 行目が「PR #1712 のリスクを許容しますか？」でリンクも無い報告が送られた（2026-10-22）。#1184 の hook は主が「わからん」と返したあとにしか働かないので、ターンの終わりに発言を機械で確かめ、書き直させる。

- `scripts/owner-message-number-check.sh` を足し、`hooks/hooks.json` に `Stop` のキーを足して 1 件のエントリで登録した（dev-workflow が `Stop` を持つのは初めて。matcher と timeout は付けない。既存のエントリは変えていない）
- 読むのは payload の `last_assistant_message` だけ。逆引用符 3 つのブロック（閉じが無ければ最後まで）と空の行を除いて並べる。`agent_id` のある payload（サブエージェント）は見ない
- 対象: 1 行目が `？` か `?` で終わる発言と、区切り（`-` が 3 つ以上だけの行）より上の最後の行が `と打って`・`を押して`・`と返して`・`と答えて` を含む発言。1 行目が `主がすること: なし`（太字・全角のコロン・空白なしを含む）の報告は対象にしない
- 止める条件: URL を取り除いた本文で、区切りより上に `#数字`（`owner/repo#数字` を含む）がある、または `#数字` があるのに `/issues/<数字>` か `/pull/<数字>` を含む URL が 1 本も無い。`{"decision":"block","reason":…}` を返す
- 理由の文は、どの行のどの番号か（またはリンクが無いこと）と、正本の節 3 の「ほかの決まり」の段落と 1 行目の書き分けの段落の場所だけを書き、正本の文言を写さない。最後に「主に判断・確認・操作を求める発言でなければ、そのまま終えてよい」を置き、誤検出の害を 1 回の追加の応答に抑える
- 1 ターンに 1 回: `stop_hook_active` が真なら通す（書き直した発言は確かめない）。全解除は `DEV_WORKFLOW_OWNER_NUMBER_CHECK=off`。壊れた入力・python3 が無い環境・本体を読めないときは無出力・exit 0。`#数字` を含まない発言では python3 を起動しない。状態ファイルは持たない
- 正本の `output-styles/readable.md` と `rules/communication-style.md` は変えていない。常時注入の固定分も変えていない
- 守らないもの: `#` の付かない番号（「PR 1712」）、Discord などへツールで送った発言、サブエージェントの return、書き直しの出来。対話の画面では、最初の発言が表示されたあとに書き直しが続けて出る（発言を出す前に走る hook が無いため）
- テスト: `tests/owner-message-number-check.bats` を足した。`tests/subagent-stop-guard.bats` の hooks.json のイベント名の集合に `Stop` を、`tests/hook-python-invocation.bats` と `tests/hook-python-isolation.bats`（リポジトリ直下）の Python 本体を `-c` で渡す hook の一覧にこのスクリプトを足し、本数を書いたテスト名を数字の無い名前に直した
- hooks は聖域（人の承認なしに変えてはならない設定）なので、PR のマージは主が行う
- 戻し方: この PR の差分を戻す（hooks.json の `Stop` のキーとスクリプトを消す）。後片付けは要らない。急いで止めるときは `DEV_WORKFLOW_OWNER_NUMBER_CHECK=off` を設定する
