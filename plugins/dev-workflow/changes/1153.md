# #1153 無人の印のあるセッションで AskUserQuestion を hook で拒否する

## 変更

- `scripts/unattended-ask-guard.sh`（新規）と `hooks/hooks.json` の PreToolUse（matcher `AskUserQuestion`）への登録: 環境変数 `DEV_WORKFLOW_UNATTENDED` に印があるセッションでは、どのスキルから呼ばれた AskUserQuestion も `deny` で拒否する。印の読み方は git ガードと同じで、前後の空白を除いて未設定・空・`0` は印なし、それ以外は印あり。印が無ければ何も出さずに通す
- 拒否理由は develop の `references/channel.md`「channel の聞き方」に沿い、develop 以外のスキルから呼ばれても理由文だけで次の行動が決まるようにした（打ち直さない・依頼の届いたチャンネルの `chat_id` に返信ツールで送ってターンを終える・チャンネル以外の依頼は運用の連絡先、分からなければ記録先にコメントして `needs-approval`・選択肢は本文に番号付き・サブエージェントは本体への return に書く）
- 判定は印だけで行う。payload（呼んだスキル・`permission_mode`・`agent_id`）、git ガード専用の印 `DEV_WORKFLOW_GIT_GUARD_NO_ASK`、git ガードの逃げ道 `DEV_WORKFLOW_GIT_GUARD=off` では変わらない。hook を無効にする環境変数は足していない
- 印が無く、チャンネルの依頼だけで develop が channel になったセッションは止めない。hook はプロンプトの本文を見られず、そうしたセッションにはオーナーが画面の前にいる場合も含むため。そこは develop の文面の規則が担う。印も付かず依頼もチャンネル以外から届く住人は、印が付く経路（#1123・genetta-inc/flatmate#1663）で塞ぐ
- `skills/develop/references/channel.md`: 「channel の聞き方」に hook の項目を 1 つ足し、AskUserQuestion に触れるファイルの列挙の除外に hook の 2 ファイル（`hooks/hooks.json`・`scripts/unattended-ask-guard.sh`）を足した
- `.github/workflows/auto-merge.yml` の聖域の一覧（`SACRED` の `^plugins/dev-workflow/scripts/(...)$`）に `unattended-ask-guard\.sh` を足した。#1163 が足した「hooks.json が呼ぶスクリプトはすべて聖域に載っていること」の検査（`scripts/test-auto-merge-workflow.sh`）に合わせるためで、足さないとこの hook の本体だけを変える PR が自動マージされる
- `scripts/git-destructive-guard.sh` は変えていない（印の読み方は共有部品にせず、同じ規則を bash で書いた）。常時注入の rules と予算も変えていない。版は上げない

## 検証

`tests/unattended-ask-guard.bats`（新規）で、登録・印のある拒否（`default`/`bypassPermissions` × `agent_id` の有無）・印の値の表（git ガードと同じ 8 通り）・git ガードの印と逃げ道・読めない payload・理由文の要素を確かめる。`tests/develop-channel-mode.bats` の列挙の検査は hook の 2 ファイルを名指しで飛ばす。実機（2026-11-10、tmux の対話セッション、`claude --plugin-dir <worktree>/plugins/dev-workflow --model haiku`）: 印あり（`DEV_WORKFLOW_UNATTENDED=1`）では選択肢の画面が出ず `PreToolUse:AskUserQuestion hook error: [dev-workflow unattended-ask-guard] …` が Claude に届き、Claude は打ち直さず本文に番号付きで質問を書いてターンを終えた。印なし（`env -u DEV_WORKFLOW_UNATTENDED`）では従来どおり選択肢の画面が出た。
