# accounts.json の codex.enabled で Codex をオフにできるようにする（#978）

Codex を使わない期間（契約していない、枠を別の用途に回したいなど）でも、develop の自動選択は Codex の使用量を取りにいき、pr-review-gate の従来経路は full 判定のたびに Codex を探して呼んでいた。設定 1 つで Codex を使わないようにできるよう、`accounts.json` のトップレベルに `codex.enabled`（真偽値、省略時はオン）を足した。`schema` は `1` のまま。既定の挙動（Codex がオンのときの投げ先の選択と、full 判定の既定が Codex であること）は変えていない（エピック #980 の決定）。

```json
{ "schema": 1, "accounts": [ ... ], "codex": { "enabled": false } }
```

## 置き場所を accounts.json にした理由

`accounts.json` に載せる案と、別ファイル（たとえば `codex.json`）にする案を比べて、前者にした。

| 観点 | `accounts.json` に載せる（採用） | 別ファイル |
|---|---|---|
| 切り替えの入口 | 切り替えのコマンド（#977）が 1 つのファイルだけを扱えば、Claude のスロットも Codex もオンオフできる | コマンドが 2 つのファイルを扱い、利用者も 2 か所を覚える |
| 場所の解決 | `CLAUDE_ACCOUNTS_FILE` → `${CLAUDE_CONFIG_DIR:-~/.claude}/accounts.json` の規則が読み手の間で既にそろっている | 環境変数と既定パスを新しく決めて全部の読み手に配る |
| 既存の読み手への影響 | 既存の読み手は `accounts` だけを読み、未知のトップレベルのキーを無視する。`accounts-init.sh` は文書全体を読んで書き戻すので `codex` を消さない | 影響なし |
| 意味の混在 | 登録簿が「Claude のスロット」と「Codex の提供元の設定」の両方を持つ | Claude の登録簿が Claude だけのまま保たれる |

決め手は、オンオフを切り替える入口と、読み手がファイルの場所を解決する規則を 1 つにそろえられること。意味の混在は、`codex` を `accounts` とは別のトップレベルのキーにしてスロットの配列には何も混ぜないことで、スロットを読む処理に影響しないようにした。別ファイルへ移すのは、Codex 側にもアカウントの一覧や使用量の取得先を持つ登録簿が必要になったとき。そのときは `codex.enabled` をその登録簿へ移す。

## 変更点

- オフになるのは `codex.enabled` が JSON の `false` のときだけ（#976 のスロットの `enabled` と同じ規則）。`codex` が無い・オブジェクトでない・`enabled` が無い・`true`・`"false"`・`0`・`null` はオン。登録簿が無い・読めない・トップレベルが配列のときもオン。書き損じを黙ってオフと読むと、使っているはずの Codex レビューが無言で外れるので、オンの側に倒した
- `scripts/usage_view.py`: `read_codex_enabled(path)` と、`on` / `off` の 1 行を出して常に exit 0 で終わる `--codex-enabled` を足した。`read_slots` / `read_registry` の戻り値と `--json` の出力は変えていない
- `scripts/codex-develop.py` の自動選択: オフなら Codex の使用量を読まず、構成 `claude-default`・reason `codex-off` を返す。selection evidence の `codex` は `{"account": null, "margin": null, "fetched_at": null, "enabled": false}`。オンのときの evidence に `enabled` キーは足していない
- `scripts/codex-develop.py` の明示指定: オフのあいだ、Codex の role を含む `--profile` と旧形式（`--account` / `--model`）は依頼ファイルを作らず exit 2 で終わり、標準出力の JSON の error フィールドに `codex is off: set "codex"."enabled" to true or remove it in <登録簿のパス>` を入れる（stderr は空）。黙って Claude に差し替えない。この拒否は account-home の対応表の検査より先に行う。executor が全部 `claude` の profile はオフでも通る
- `skills/pr-review-gate/stages/review-run.md`: 従来経路で full と判定したあと、Codex を試す前に `usage_view.py --codex-enabled` を実行し、`off` ならバイナリ探索も呼び出しもせず Task サブエージェントでレビューする。オフは設定であって、Codex を使えないと実測する三条件とは別に扱う。証拠は `レビュー実行者: Task サブエージェント（full・Codex オフ）` と `未実行（Codex オフ）`。`stages/triage.md` の「レビュー実行者:」の書式にも同じ値を足した。adapter 経路は変えていない
- `scripts/accounts-init.sh`: 変更なし。スロットを上書きしてもトップレベルの `codex` が残ることをテストで固定した
- `codex-develop.py` は、develop のモデルの格を決めるエピック #616 の子が同じ箇所を触る予定なので、差分を `select_configuration` の引数 1 つと冒頭の分岐 1 つ、`automatic_selection` と `build_request` の分岐に限り、モデルの格・役ごとのモデルには触れていない
- `codex` を書いていない登録簿では、自動選択・明示指定・レビューのいずれも変わらない
- ステータスラインの表示は `plugins/statusline/changes/978.md`
- 切り替えは当面 `accounts.json` を手で書き換える（切り替えのコマンドは #977）
- 戻し方: 利用者側は `codex` のキーを消すか `enabled` を `true` にする。コードはこの PR の差分を戻す（`codex` を書いたままの登録簿は、古い読み手では未知のキーとして読み飛ばされ、Codex はオンに戻る）
