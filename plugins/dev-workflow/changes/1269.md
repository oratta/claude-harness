# develop: openspec validate の --type change の結果が版で違うことを指示書とテストに反映する（#1269）

文言合わせの通し方の指示書（`worker/implement.md`・`worker/spec.md`）と `dev-workflow-develop` の要件は、「`--type change` を付けないと change を見つけられず `Unknown item` で終了コード 1」「`validate --changes --strict` は検査せず終了コード 0」と断定していた。openspec 1.14.1 ではどちらも当たらず（delta だけの change は `--type change` なしでも終了コード 0、`--changes` も検査する）、実測テストが手元で落ちていた（CI は openspec CLI が無く skip）。

- 直したもの: `--type change` を付ける指示は残し、付けない形の結果は版で変わる（`Unknown item` で終了コード 1 の版も、終了コード 0 の版もある）と書いた。`--changes --strict` は検査しない版があるので使わない、に変えた。実測テストは、付けた形の終了コード 0 を必須にし、付けない形は終了コード 0 か `Unknown item` と終了コード 1 のどちらでも通す
- spec（`dev-workflow-develop`）: 要件「W の仕様化経路は openspec CLI だけで進める」の文言合わせの段落とシナリオを同じ内容に直した（change と同名の spec があると `Ambiguous item` で終了コード 1 になる版があることも書いた）
- 戻し方: この PR を revert する。文書とテストの変更だけで、移行の手順は無い
