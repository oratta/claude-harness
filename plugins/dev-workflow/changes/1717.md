# エピックの子が途中で見つけた依存待ちで終わり、依存が解けたら親が起こし直す（#1717。エピック #1682 の子）

エピック #1682 の子 #1693 は、作業の途中で別 issue #1713 の完了待ちだと分かり、「あとで親から連絡するので待機」と書いて止まった。依存が登録されておらず、親の `wait --resolve` はその止まりを「問いではない」として `resumed` に戻したので、#1713 が閉じたあとに `reply --relaunch` を打っても `not-stopped` で送れなかった。この変更で、途中で分かった待ちを既存の依存（`blocked_by`）と再起動の操作につなぎ、待つだけの子のセッションを動かし続けないようにした。

## 足したもの

- `skills/develop/references/epic-child-stop.md` に節「依存待ちで終了する」を足した。`route` が `nested` の子が別 issue・PR の完了待ちを見つけたら、自分の issue の `dependencies/blocked_by` に前提 issue を登録して GET で確かめ、`子の停止: 依存待ち` で始まる再開記録（依存先・待つ理由・再開条件・再開に要る途中経過・再開手順）を子 issue に投稿し、最後の発言の末尾を `止まった理由: 依存待ち: <依存先 URL>` にして終える。PR 待ちは完了を表す issue を特定する。対応 issue が分からない・登録や投稿に失敗したときは成功扱いせず親へ返す。主の返事待ちの 7 項目の記録とは別の形で、停止の印（mark）を付ける操作は要らない
- `skills/develop/references/parent-pass-criteria.md`: 親の判断が「あとで親から連絡するので待機」を返すことを禁じ、依存の登録・再開記録・終了まで含めて返すようにした（例: main の CI 修正 issue を前提に張って終える）。主の承認待ち・human-merge・CI のやり直し上限の条件は緩めていない
- `skills/develop/references/epic-loop.md`: 「依存待ちの照合」を通常の進行と手順 4・7 より先に置いた。`stopped` / `pending` の子は、主の返事待ちとして扱う前に、最新の `子の停止: 依存待ち` コメント・今回の発言・現在の `blocked_by` を照合する（末尾の行だけで登録や解消を認めない）。依存待ちの子は動いている子から外し、`mark done` / `reap` をせず、前提 issue を既存の `wait` の位置引数で見張る。依存待ちが残る間は `clear` しない。前提が閉じたら依存を読み直し、未起動の子は `launch`、既存のワークツリーがある子は `reply --relaunch --as parent` で起こし、`relaunched <N>` と送信結果を確かめてから動いている子へ戻す。`not_planned`・読めない依存・再起動の `failed` / `not-stopped` の扱いも書いた
- `scripts/epic-dispatch.sh` の `resolve_stopped`: 止まりの発言の最後の行が `止まった理由: 依存待ち: ` で始まるときは判断のモデルに渡さず、停止記録を保ったまま `stopped` として親へ返す（7 行の分岐）。この行は合図として使うだけで、登録や解消の証拠にはしない
- `tests/epic-dispatch.bats`: 文書の検査と、依存待ちの会話ログ fixture から `wait` での停止保持・前提が open の間は何も送らない・closed の通知・依存の読み直し・`relaunched` と `/develop #<子>`・続行指示の送信までを再現する検査を足した。末尾の行が無い通常の no-question は従来どおり `resumed` になることも確かめる

## 変えていないもの

- 新しいサブコマンド・状態の値・状態ファイルの形・親の依存を見張る常駐部品は作っていない（`launch`・`wait`・`reply --relaunch` をそのまま使う）
- 主の返事待ちの記録の 7 項目、自分の PR のマージ待ち・CI の止まりの定型、no-question を `resumed` に戻す既存の扱い（依存待ちの行が無い止まり）

## 戻し方

この PR を revert する。データの移行は無い。revert 後は、依存待ちの行を持つ止まりも従来どおり判断のモデルに渡る。既に子 issue に登録した `blocked_by` と `子の停止: 依存待ち` のコメントはそのまま残る。
