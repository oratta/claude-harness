# git ガード: 子が許可の置き場所に分かりやすく書く 2 つの形を止める（#1155）

子（サブエージェント）は、git ガードに拒否されたあと親に返らずに、許可の置き場所（`${TMPDIR:-/tmp}/dev-workflow-git-guard` の下の許可のフォルダ）に許可を自分で書けた（issue #1155 の指摘 1。親のエピックは #1476）。子・hook・親は同じ uid で動くので塞ぎ切れない。ルールを読み飛ばした子が分かりやすく書く 2 つの形だけを、実行の前に止める。

- 新しい hook `scripts/git-guard-base-write-guard.sh` を、`hooks/hooks.json` の PreToolUse に `Write|Edit|NotebookEdit` で配線した（git ガードの Bash のエントリの前。末尾は git ガードのまま）。子の書き先を、`..` を畳んだパスと symlink を辿ったパスの両方で部品に分け、大文字小文字を区別せずに置き場所の名前と一致すれば deny する。許可のフォルダに限らず、置き場所の中はすべて止める（回数や拒否の記録を書き換える用事も子には無い）。置き場所を作らず、回数・拒否の記録・許可に触れない
- `scripts/git-destructive-guard.sh`: 子の Bash のコマンドに、置き場所の名前と許可のフォルダの名前が両方含まれれば（部分文字列・大文字小文字を区別）、書き方を読み分けずに種類 `permit-store` で deny する。拒否の記録を書かず、許可も探さない。ほかの種類（破壊的 git 操作・判定しきれなかったもの・許可を書くスクリプトの子からの呼び出し）に当たらなければ、回数も数えず置き場所も作らない。当たれば今までどおり数える（2 つの名前を書き足すだけで打ち切りを外せないようにするため）
- 子への理由文には 2 つの名前を並べない（子が理由文を報告用のコマンドに写したとき、そのコマンドが止まらないようにする）
- `.github/workflows/auto-merge.yml` の聖域に新しい hook のスクリプトを足した（hooks.json が呼ぶスクリプトは聖域、#1163）
- 止めないもの: 変数や置換で組み立てたパス・グロブ・置き場所に `cd` してから許可のフォルダの名前を書かずに書く形・スクリプトファイルや Makefile の中から書く形・大文字小文字を変えた名前の Bash のコマンド・MCP など他のツールで書く形・主の呼び出し。通っても、許可が効くのは使う時点の一時領域の判定を満たす scratchpad の中だけ
- HMAC などの秘密の印を使わない理由: hook が読める秘密は、同じ uid で動く子も読める。印は子が自分で付けられるものにしかならず、名前の判定より強くならない
- 止めすぎの頻度: 2026-11-10 時点の会話ログで、Bash の呼び出し 109,484 件のうち 2 つの名前を両方含むものは 8 件（約 0.007%）。すべて #1155 の作業そのものだった。止まった子は打ち切られず、親に返って親が打てる
- 戻し方: この PR を revert する。置き場所の中のファイルの形は変えていないので移行は要らない
