# 残量モードの導出を usage_view.py の 1 か所にし、注入の効果の文を格の規則に合わせる（#1622）

#614（PR #1621）のあと、残量モード（`FABLE_BUDGET_MODE` / `SHARED_BUDGET_MODE`）を導く式が `usage_view.py` と `session-tripwires.sh` の 2 か所にあった。片方だけを直すと、セッション開始時に注入されるモードと、`codex-develop.py request` が格に当てるモードが食い違う。また `depleted` の効果の文が「全役割 sonnet 固定」のままで、#614 の規則（最安の役はそのまま、それ以外は中位が上限・昇格なし）と合っていなかった（エピック #616 の子）。

- **scripts/usage_view.py**: モードごとに `mode`・`shown`・`source` を返す `budget_mode_details` を足し、式の置き場をここ 1 か所にした。`budget_modes` はその結果のモード名だけを返す包みにした（`codex-develop.py` の結果 JSON は変わらない）。週経過の割合を返す関数を公開名 `elapsed_pct` にした
- **scripts/session-tripwires.sh**: 導出の写しを除き、スクリプト自身のディレクトリの `usage_view.py` から得る形にした。読めないとき（または例外のとき）は明示 env も読まず、`conserve` / `ok`・出どころ `既定（usage_view.py を読めない）` を出す。各モードの効果の文を decision-criteria の表と格の語に合わせた（`depleted` は最安の役（explore と summarize）はそのまま・それ以外は中位（sonnet）が上限で昇格なし、`throttled` は中位に落として上限は上位（opus）・最安はそのまま）
- **scripts/subagent-start-context.sh・skills/develop/references/decision-criteria.md**: 式の置き場の注記を `usage_view.py` に直した
- **テスト**: `test_codex_develop.py` の `BudgetModeDerivation` に出どころ付きの導出のテストを足した。`tripwire-hook.bats` に、偽の `usage_view.py` から導出を得ること・読めないときの既定・未知の明示値の表示・各モードの効果の文を固定する bats を足した
- **仕様**: change `unify-budget-mode-derivation` を archive し、`dev-workflow-escalation-tripwires`・`dev-workflow-execution-strategy`・`model-tier-resolution` の該当要件を更新した

範囲外として #1625（`agent-model-guard.sh` の fork 判定に残る導出の写し）と #1626（`dev-workflow-develop` の scenario 見出しの語）に切り出した。
