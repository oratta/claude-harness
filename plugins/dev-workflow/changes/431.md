# epic-dispatch.sh wait の error gh で gh の stderr を本体に見せる（#431）

`epic-dispatch.sh wait` の `cmd_wait` は `gh api … --jq .state 2>/dev/null` で gh の stderr を捨てていたため、`error gh <N>` で終わったとき本体が受け取れる情報は子の番号だけで、原因（認証切れ・404・rate limit・ネットワーク断）がどこにも残らなかった。

- ポーリングごとに空にする一時ファイル（`mktemp`、`trap … EXIT` で後始末）に gh の stderr を集め、`error gh${failed}` を出す直前にその内容を stderr へ出すようにした。閉じた子が見つかった・タイムアウトした通常経路は変えていない
- PR #428 レビューの should 指摘（F3）の follow-up。直し方は issue #431 本文に diff レベルで明記されており、設計判断を含まないため仕様化しない（コード直行）と判定した
