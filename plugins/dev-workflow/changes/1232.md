# dev-workflow: `cld` / `cld-account` を `.zshrc` の関数から harness の実行ファイルに移す（#1232）

マルチアカウントの起動時選択の入口 `cld` / `cld-account` は、README の zsh function を各端末の `~/.zshrc` に貼る方式だった。端末を増やすたびに手で写す必要があり、harness を直しても各端末に届かず、`epic-dispatch.sh` の子セッション起動の既定もログイン zsh の関数 `cld` に頼っていた。

## 変えたこと

- `plugins/dev-workflow/bin/cld` と `bin/cld-account` を実行ファイルとして置いた。挙動は旧関数と同じ（probe を best-effort で実行 → `select-account.sh` → 空なら `env -u`、非空なら設定して `claude`。selector が非 0 なら同じ status で終わり `claude` を起動しない）。`CLAUDE_HARNESS_SCRIPTS` が未設定なら自分の位置（symlink を解いた先）から `../scripts` を使う
- 個人の既定フラグは環境変数 `CLD_DEFAULT_ARGS`（空白区切りの語。`eval` しない）で渡す。`CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` は上書きも既定値の追加もしない
- `epic-dispatch.sh` の起動コマンドの既定を `bin/cld` の絶対パス（常に単一引用符で包む。実行ファイルが無い clone では従来の `cld`）にした。`EPIC_DISPATCH_CLAUDE_CMD` の指定は今までどおり優先する
- `launch`（と `reply`）は、親の環境の `CLD_DEFAULT_ARGS` を `EPIC_DISPATCH_PARENT_EPIC=<epic>` の直後に `CLD_DEFAULT_ARGS='<値>'` の代入として子の起動コマンドへ付ける。Orca の既存シェルへの送信でも tmux の新しいウィンドウでも、子の `--dangerously-skip-permissions` が `.zshrc` の読み込みに頼らず届く。親に値が無ければ付けず、子は許可の確認画面で止まる
- README「Claude アカウントの起動時選択」を新方式の説明に置き換えた（#501 の食い違いもここで解消）。`epic.md` の `cld` の説明も合わせた

## 主の端末でやること（`~/.zshrc`）

1. `cld()` / `cld-account()` の関数定義と `unalias cld cld-account` の行を消す（関数は PATH の実行ファイルに勝つので、残ると古い挙動のまま動く）
2. 次の 2 行を足す。個人のフラグ（Pro の `.zshrc` にある `--dangerously-skip-permissions --remote-control` など）は `CLD_DEFAULT_ARGS` に移す

   ```zsh
   export PATH="$HOME/.claude/plugins/marketplaces/oratta-claude-harness/plugins/dev-workflow/bin:$PATH"
   export CLD_DEFAULT_ARGS="--dangerously-skip-permissions --remote-control"
   ```

3. `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` の既定 120000 を使っていた端末は、`.zshrc` に `export CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS=120000` を書く（実行ファイルは既定値を持たない）
4. Pro の `.zshrc` にだけあった `_cld_launch` は個人設定なので取り込んでいない。要るなら `.zshrc` 側に残す

## 範囲外として残したこと

- `EPIC_DISPATCH_CLAUDE_CMD` が前置きの代入を受け付けない形（`exec` で始まる文字列など）のときは `CLD_DEFAULT_ARGS` が渡らない
- 他の要件（`dev-workflow-develop` の「エピックの並列起動は 1 段で止める」など）のシナリオに書かれた `cld` は、既定の `bin/cld` の絶対パスを指す（spec の読み方の文で定めた）
