# epic-dispatch.sh launch の同一呼び出し内重複を skipped にする（#434）

PR #428 のレビュー指摘 F6 の follow-up。`launch` は起動前に `orca worktree list --json` を 1 回だけ読むので、`launch 400 11 11` のように同じ呼び出しで同じ子番号を 2 回渡すと、1 回目の `create` で作ったワークツリーは一覧に無く、2 回目も `create` が呼ばれて同じ子が二重に起動していた。

- `cmd_launch` の子番号ループに `seen` を足し、同じ呼び出しの中で既に処理済み（`launched`・`skipped`・`failed` のいずれか）の番号が再び現れたら `orca worktree create` を呼ばずに `skipped <N>` を出す
- 1 回目が `failed` でも 2 回目以降の重複は `skipped` になる（`seen` はループ内の分岐結果に関わらず先頭で記録するため）
- 呼び出しをまたいだ重複（既存のワークツリー一覧チェック）はそのまま。`route` が重複した番号を通す既存の引数検査も変えていない
- 仕様: `openspec/changes/epic-dispatch-launch-dedupe-inline/` で ADDED 要件として追記（既存の `skipped` 規定は書き換えていない）
