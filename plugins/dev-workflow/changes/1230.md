# epic-dispatch: wait --watch-done が記録先の閉じた止まった子の完了を推定する（#1230）

エピックの子が主に PR のマージを頼んで見張りを終えると、主がマージして記録先 issue が閉じても、子はもう動いていないので `epic-dispatch.sh mark done` を呼ばない。親は `closed` を受けて `notify-closed` を呼ぶが、止まった印（`stop` が `stopped` / `stopped-seen`）の無い子には効かず `skipped <N> not-stopped` になり、以後 `wait --watch-done` で完了の印を待ち続けて、主が気づくまでワークツリーが片付かなかった（実例: genetta-inc/flatmate#1658、PR genetta-inc/flatmate#1740。`human-merge` が付き、flatmate の `auto-merge.yml` に `parent-merge-approved` が無いので子は主に直接マージを頼んだ）。子は完了報告で「マージしたら教えてください、ステータスを変えます」と主に頼んでおり、この往復を無くす。

- `scripts/epic-dispatch.sh wait --watch-done <N>`: 次の 5 つをすべて満たす子を、LLM なしで完了と推定して `done <N>` を返す。記録の `status` が `running`・`stop` が `stopped` / `stopped-seen` でない・記録の `worktree` のトランスクリプト（`${CLAUDE_PROJECTS_DIR:-~/.claude/projects}/<ワークツリーのパスの英数字以外を - にした名前>/*.jsonl`）が 1 本以上あり、全ファイルを通した最後の活動（`timestamp` の最大値）が `EPIC_DISPATCH_DONE_IDLE_SEC` 秒以上前・子 issue が `closed` で `state_reason` が `completed`。推定した子は排他つきで記録の `status` を `done` にし、Orca の印へ写し、stderr に `inferred done <N>: ...` を出す。`status` が `waiting` の子・止まった印の子・トランスクリプトが無い子は推定しない
- 新しい環境変数 `EPIC_DISPATCH_DONE_IDLE_SEC`（秒・既定 1800）。空か数字でなければ `wait` は使い方を出して exit 1 で終わる（`--watch-done` を付けたときだけ確かめる）
- 記録（`scripts/epic-state.sh` の形）に、推定したときだけ `done_inferred_at`（推定した時刻）と `done_inferred_last_activity`（推定の根拠にした最後の活動の `timestamp`）を足す。`schema` は 1 のまま。知らない項目は今までどおり残る
- トランスクリプトの置き場の求め方を `decide_relaunch` から関数に切り出し、推定と共有した。`decide_relaunch` の挙動（「ちょうど 1 本」の判定）は変えていない
- 片付けの安全確認は `reap` がそのまま行う（`reap` は変えていない）。推定の `done` も子の付けた `done` と同じ確認を通る
- `skills/develop/SKILL.md`「回し方」の手順 2〜4: 推定の条件と `EPIC_DISPATCH_DONE_IDLE_SEC`、推定の `done` も同じに `reap` すること、同じ子が `closed` と `done` の両方に出たら手順 4 を処理してから `reap` すること、`notify-closed` が `skipped <N> not-stopped` を返した子は推定で片付くので主にステータスを変えるよう頼まないことを書いた
- `skills/develop/SKILL.md`「ループの終わり」と `references/ci-watch.md`「`ready` を受けたあと」: エピックの子（`nested`）が主にマージを頼んで終えるときは、マージ後の連絡を頼まず「マージしたらこのタブは放っておいてよい。記録先が閉じれば親が完了にしてワークツリーを片付ける」と書くことにした。`ci-watch.md` の 4 の表の `timeout` の行からその段落を指す。エピックの子でないセッションの文面は変えていない
- 受け入れること: 1 回のツール呼び出しを閾値より長く動かしている子は、記録先が閉じていれば完了と推定されうる（`reap` の安全確認で片付けが止まらなければワークツリーが消える）。閾値は `EPIC_DISPATCH_DONE_IDLE_SEC` で延ばせる。`--watch-done` の子 1 件あたり、推定の候補になったポーリングでだけ `gh api` の呼び出しが 1 回増える
- 戻し方: この PR の差分を戻す。推定で足した記録の項目は知らない項目として残るだけなので、移行は要らない
