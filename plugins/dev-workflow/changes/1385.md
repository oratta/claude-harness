# #1385: develop の待っている間の自動コンパクトを切る

親・子・単発を分けず、Claude の本体が develop 開始時（新セッションの引き継ぎ・compact 後の再読も含む）に worktree-local の idleCompaction を false にする。通常の上限近くでの自動 compact と手順書再読み込み hook、子の既存 `--settings '{"idleCompaction":false}'` は維持する。Codex worker は Claude の実設定を変更しない。

適用点を既存シェルの `cld` でなく共通入口にしたのは、plugin 更新では利用者の関数定義を置換できず、直接 claude で起動する経路もあるため。親の要約後に手順書を読み直す費用も含め、比較相手を手順書と引き継ぎを読む新セッションとし、親だけ compact を残す方針を改めた。監視停止の原因が compact だったとは断定しない。

## 継続適用の承認範囲

PR 本文と正式なリスク宣言に「develop 開始時、現在の worktree の `.claude/settings.local.json` の idleCompaction だけを false にする。他の設定値は保持し、ホーム・共有設定には書かない」と記し、主のマージ承認（リスク宣言の許容）をこの仕組みへの一度の承認として記録する。無い設定への当該キーだけのファイル作成、新しい worktree・新セッション・interactive / unmanned への継続適用を含む。承認後は worktree ごとに操作承認を確認・質問しない。現時点では承認待ちであり、R1 APPROVE やエージェントのコメントは主の承認の代わりにならない。

他キー・別ファイル・symlink 先への変更は範囲外で、従来の聖域承認を要する。部品は symlink を追わず、permissions/hooks は保持する。同じ worktree の develop 以外のセッションにも残り、自動復元しない。実装検証は一時ディレクトリの git repo で行い、実ホームと本 worktree の実 settings.local.json は変更していない。

## 適用と長時間後の再開

`python3 <plugin>/scripts/develop-idle-compaction.py --check <worktree>` は、disk 上で false なら exit 0（byte/mtime 不変）、変更が必要なら exit 2、不正・破損・重複キー・読めない入力や symlink なら無変更で exit 1。承認された入口が exit 2 に対してだけ `--apply <worktree>` を呼び、単一キーを atomic に置換する。エラーには対象パスと原因だけを出す。

disk 成功だけで live 反映を断定しない。主が `/config` の Idle compaction が off か確かめ、未反映なら状態を issue に残して同じ worktree の新セッションで再起動し、develop の入口から再確認する。再起動でも off でなければ開始を止め、理由を #1385 に記録する。

親は待機前の最後のリクエスト（起床の API リクエストを除く）から60分以上なら、timeout・各通知・主の返事より再起動を優先する。旧親は再調査・送信・wait の掛け直しをせず、既知の状態と未処理出力（stderr/exit code を含む）、主の元発言の識別情報をエピックに残す。旧親の引き継ぎ・再開案内と記録失敗時の停止報告だけ状態表・child-log を省略する。記録失敗を再開可能とは報告しない。

新親は同じ worktree の `/develop <エピック番号>` で入口・手順書を読み、adopt/reap/pending-owner と停止記録 URL で復元する。元発言を確認した主の返事→現在の状態と照合した通知→純粋な timeout の順で処理し、送信済みの判断や完了を二重処理しない。復元後にログ確認→状態表の報告を行う。60分未満の純粋な timeout だけは従来の短い掛け直しを維持する。5m の長い timeout・スリープ後は時間分類が優先し、片付け待ちだけの timeout は条件 (d) と終了直前確認を保持して新たな6時間待ちへ戻さない。

## マージ後の実機確認（担当: 主 oratta、未実施）

Bats 成功は以下の実機受け入れ条件の代用にしない。親・子の60分観測、単発の実効 off、通常 compact の観測はいずれも未実施。

- Claude Code の版、plugin 適用 commit、確認方法（`/config`）と off の結果を親・子・単発ごとに #1385 へ記録する。子は `ps` 等で既存 --settings も確認する。親は develop 前に on のセッションから off への変化を含め、live 反映か再起動かを書く
- 親・子の対象 jsonl、観測開始時刻・行位置、最後のリクエスト時刻、`subagent-context.sh --file` の会話量を記録する。ログや秘密値は repo に置かない
- その機械で idle が有効なら compact 対象となる会話量（実際の idle 閾値。未設定なら利用版の既定値）に達した親・子をそれぞれ使う。旧規定の120000は仮定しない。PC を起こしたまま追加 API リクエストなしで最後のリクエストから60分以上待ち、経過秒・スリープなし・リクエストなしを記録する
- 観測開始位置より後の JSON の type/subtype から新規 compact_boundary が0件であることを親・子別に報告する。会話文中の単語は数えない。会話量不足・スリープ・追加リクエスト・通常または手動 compact のあった試行は未検証としてやり直す
- 別区間で、会話が上限近くに達した通常利用の自動 compact と reread hook による SKILL 再読み込みを記録する。実装差分には DISABLE_AUTO_COMPACT 等を追加していない

#1264 の親 idle 閾値の再集計は不要になった旨を同 issue に記録し、上記の実機結果を主が確認した後に不要として閉じる。現時点では閉じない。

## 戻し方

追跡コードは PR 差分を戻す。worktree 設定は自動復元しないため、主が当初の差分を確認・承認して idleCompaction だけ元の値に戻すか、元々無ければそのキーを削除する。後続の他キー変更を失うファイル全体の復元はしない。ホーム設定・共有設定・外部シェルは変更していない。
