# pr-review-gate の SKILL.md を索引にし、手順を段ごとのファイルに分ける（#553）

マージ前の検査担当（develop の G）は、どの段で起こされても `skills/develop/references/roles/gate-runner.md`（28,359 バイト）と `skills/pr-review-gate/SKILL.md`（83,538 バイト）を全部読み、作業を始める前に約 45K トークンを使っていた。1 回の起動で使うのはその一部だけで、直近 10 日で G の 5 割強がコンテキスト上限 150K を超えていた。作業担当（W）も仕様宣言の書式を確かめるためだけに SKILL.md 全体を読んでいた。

- `skills/pr-review-gate/SKILL.md` を索引にした（6,019 バイト）。索引が持つのは段の表（目的・読むファイル・入口と出口の条件）と、手順番号（1・2・2-0・2-1・2-2・3・3-b・3-c・4・5・6）から見出しとファイルを引く対応表、develop 以外で本体が直接使うときの読み方だけで、手順の本文とコードブロックは持たない。`description` は変えていない
- 手順の本文を `skills/pr-review-gate/stages/` の 6 本（`prepare.md` 前提確認と重さ判定・`review-run.md` レビューの起動・`reviewer-brief.md` レビュー担当向けの指示・`triage.md` 照合と指摘の振り分け・`pass.md` 合格処理・`hold.md` 保留）に移した。手順 2-1 は読み手ごとに 3 本（実行者・レビュアー向け指示・止める判定と仕分け）に分かれ、対応表に 3 行で載る。手順 3-c（前の HEAD の許容の引き継ぎ）は保留の段に置いた
- リスク宣言（手順 3）と仕様宣言（手順 3-b）の書式を `skills/pr-review-gate/declarations.md` に移し、G の合格処理と W の (3b) の両方がこのファイルを指す
- 冒頭の「前提と理由」は、それを使う段のファイルの「前提と理由（この段で使うもの）」節に分けて移した。段をまたぐ手順番号の参照は、各段のファイルの冒頭 1 行（他の段の手順番号は索引の対応表で引く）で解決する
- `gate-runner.md` から「SKILL.md を Read して手順 1〜5 を実行する」指示を消し、G が時点ごとに読むファイルを表で示す形にした（13,877 バイト）。G の段ごとの差分（needs-reviewer の payload・従来経路の実行者の表・Status ごとの return 書式・段に固有の再開）は、その段のファイルの「G として動くとき（develop）」節に移した。gate-runner.md には、時点ごとに読むファイルの表・レビュー経路の判別・一周目の三表の照合と補足レビュー結果の受領・return の共通欄・段をまたぐ再開（レビュアーの要約受領）・モデルと、待ちでターンを終えないことを残した
- 手順の中身（規則・閾値・雛形・コマンド）は変えていない。同じ手順を 2 か所に書いていない
- develop の `SKILL.md`・`references/*.md`・`worker.md` のうち SKILL.md のパスを直接指していた行と、`scripts/codex-develop.py` が Codex の gate / review phase に渡す正本の一覧を段のファイルに付け替えた（`tests/test_codex_develop.py` の期待値も合わせた）
- 索引の構造を検査する `tests/pr-review-gate-index.bats` を足した（段のファイルの実在・索引の各行が段のファイルを 1 つずつ指すこと・索引にコードブロックが無いこと）。pr-review-gate の文言を検査していた既存の bats は、その文言が移った段のファイルを見る形に付け替えた。段をまたぐ順序の検査は索引の対応表の並びと各ファイルの見出しで見る。索引だけを見て素通りしていた否定の検査（その文言がどこにも無いこと）は、索引と段のファイル全部で見る形に広げた。背景起動と前景ポーリングの併記はスキル全体で見る
- 受け入れたリスク: 手順を移しただけでは G の指示書の読み込み量は約 19K トークンになる見込みで、目標の 15K と両立しない（2026-09-28 に受け入れ条件を「読み込み量とファイルごとの内訳を記録し、15K を超えたら文言を縮める follow-up issue の URL を書く」に改定した）。実測値は PR 本文に記録する
