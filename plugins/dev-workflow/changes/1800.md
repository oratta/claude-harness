# モデル別トークンしきい値の共通部品と再検証手順を足す（#1800、3 分割の 1 本目）

#1799 の結論を使い、固定モデル ID ごとの既定値と根拠を持つ表、表を引く共通処理、検証をやり直す手順を追加した。#1800 は 3 つの change に分けて進め、この変更は change 1（`model-threshold-foundation`）に当たる。

- `references/token-thresholds.json`: `claude-opus-5-5` / `claude-sonnet-5-5` と fallback の各指標に、値・測定対象モデル・判断日・実測の出典を持たせた。#1799 の上限値と、混在標本・品質未測定という限界を引き継ぐ。
- `scripts/token_thresholds.py`: import API と CLI から同じ解決処理を使える。固定 ID の完全一致、未知・不明モデルの安全側の既定値、根拠モデルとの違いを知らせる再検証診断、明示の数値環境変数による上書きを扱う。GitHub 投稿や状態保存は行わない。
- `skills/develop/references/token-thresholds.md`: CLI/API の利用契約と、#1799 の集計を再実行し、値の変更ごとに結果と出典を残す手順をまとめた。原スクリプトは repo に無く、取得できない場合は再現未完として扱う。
- `skills/develop/references/decision-criteria.md`: 共通部品の表と利用契約を許容する配置規則に直し、表・手順への入口と未配線の注記を足した。
- `tests/test_token_thresholds.py`: 表・根拠・fallback・診断・環境変数・エラー・API/CLI の契約を確認する単体テストを追加した。

既存 3 スクリプトへの接続は後続の change 2・3 で行う。change 2 は `subagent-context.sh`・`context-tripwire.sh` とそのテスト、change 3 は `pr-token-budget.sh` とそのテスト・`pr-token-budget.md` が対象。この PR のマージ後、それぞれ main から開始する。この変更だけでは既存 hook の通知・停止・権限・fail-open は変わらず、issue の受け入れ条件はまだ揃わない。
