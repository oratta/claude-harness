# git ガード: 子のコマンドが読むか表示するだけのコマンドだけでできていれば、許可を書くスクリプトの名前で止めない（#1166）

git ガードは、子のコマンド文字列に許可を書くスクリプトの名前（`git-guard-permit`）が 1 文字でもあれば `permit-self` で拒否し、2 回目で子を打ち切っていた。harness を直す W が名前を grep のパターン・`cat` の引数・ヒアドキュメントの本文に書くだけで止まり、作業が進まなかった（issue #1166。親のエピックは #1476）。

- `scripts/git-destructive-guard.sh`: 子のコマンドに名前があるときだけ、今の字句読みでコマンドを読み直し、すべての単純コマンド（`$(...)` の中・ヒアドキュメントの引用されていない本文の中の `$(...)` を含む。バッククォートの中身は読み直す）の先頭の語が一覧 `READ_ONLY`（`grep`・`egrep`・`fgrep`・`cat`・`head`・`tail`・`wc`・`ls`・`echo`）のどれかと文字列ちょうどで一致するときだけ `permit-self` にしない。字句読みの関数（`join_words`〜`judge`）は変えず、呼ぶだけにした
- 止め続ける形: 一覧に無いコマンドを 1 つでも含むもの（`echo <パス> | bash`・`cat > x.sh <<EOF` のあとの `bash x.sh`・`grep x "$(bash <パス>)"`・バッククォートの中の実行など）。先頭の語にパスを付けた形（`/usr/bin/grep`）・前置き（`command`・`env`）・変数の代入を前に置いた形・`{`・関数定義・プロセス置換。引用符が閉じていないもの、入れ子が深すぎるもの、仕事量の上限を超えたものも止める側に倒す。`$'`・`((`・`$[`・`${` のどれかを含むコマンドには例外をかけない（字句読みが bash と違う読み方をする `$'..'` の中の `\'`・算術（`$((..))`・`((..))`・`for ((..))`・`$[..]`）の中の `<<`・`${..}` の中の引用と置換で、実行される名前を引用符の中や本文と読み違えるため。commit 後の自動セキュリティレビューの指摘と 2 回の続報）。同じレビューの「`<<` を含むか複数行なら例外にしない」案は、ヒアドキュメントで名前を書く形を止めないことがこの issue の目的なので採らない。続報が挙げた extglob（`@(` など）・`case`・`[[` も並べない。この一覧は、食い違うと分かっていて、ふつうの作業でも出やすい構文だけを並べるもので、塞ぎ切るためのものではない（この判定はセキュリティの境界ではなく、差を突く子は今の規則でも名前を引用符で割れば届く。spec の守備範囲の「穴を塞ぎ切ることを完了条件にしない」に従う）
- 一覧に入れなかったもの: `sed`（`e` / `w` 命令）・`awk`（`system()`）・`rg`（`--pre`）・`find`（`-exec`）・`xargs`・`git`（設定・alias・pager）・`less`・`printf`（`-v`）・`cd`（一覧を最小にするため）。これらで名前を扱うコマンドは今までどおり止まる（止めすぎとして残す）
- 偽造の経路の検討: 止めなくなる形（一覧のコマンドで読む・名前を含む中身をファイルに書く・リダイレクトでスクリプトを上書きする）は、どれも今の規則でも名前を引用符で割るかグロブにすれば届く結果にしか届かないので、新しい種類の経路は開かないと判断した。ただしこれは「今も別の書き方で届く」という比較で、防御力が変わらないことの証明ではない。名前をそのまま書いた中身をファイルに書き、別の呼び出しでそのファイルを名前を書かずに実行する 2 段の形は、1 段目が新たに止まらなくなる。2 段目は名前を含まないので今も止まらない。git ガードはセキュリティ境界ではなく、残る歯止めは許可を使う時点の一時領域の判定と `permit-log.jsonl` の記録で、どちらも変えていない
- 打ち切りの数え方: `permit-self` に当たった拒否は今までどおり回数に数え、拒否の記録を書く。読み分けのあとに当たるのは一覧に無いコマンドで名前を含むものだけになり、スクリプトを自分で呼ぼうとした子は、打ち切って親に返すべき子にあたるため。一覧のコマンドだけの形は、拒否される前に書き方を選ぶときに使うもので、拒否されたあとは今までどおり打ち直さず親に返す
- 置き場所の名指し（`permit-store`）と組み合わさったとき: 一覧のコマンドだけで名前と置き場所の 2 つの名前を書いた形は、`permit-store` だけの拒否になり、回数を数えず記録も作らない
- テスト: `tests/git-destructive-guard.bats` の「permit: a child calling the permit script is denied」から `cat` の形を外し、一覧に一覧外のコマンドが混じる形 11 件と字句読みの扱わない構文 3 件を足した。「permit: a child mentioning the permit script name only in read-only commands is not stopped」と「permit: the read-only exception is not applied to ANSI-C quoting or arithmetic」を足した。「store: with the permit script name …」を実行の形に差し替え、`cat` の形は「store: the permit script name only in read-only commands is denied as store only, not counted」として残した
- 範囲外: 子への拒否の理由文（PR #1615 のレビューの nit）、拒否後に親が打ち直しを指示して許可する仕組み（#1173）、`cd` と `rm` の形への親の許可（#1159）
- 戻し方: `self_permit` の判定を `is_child and PERMIT_NAME in command` に戻し、`READ_ONLY`・`LEX_DIFFERS`・`Heads`・`read_only` と bats の該当テストを戻す。記録や回数の形式は変えていないので移行は要らない
