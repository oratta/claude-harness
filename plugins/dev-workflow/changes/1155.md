# git ガード・rm ガード: 拒否の記録・回数・許可の置き場所を確かめてから使い、symlink を辿らずに読み書きする（#1155）

git ガードと rm ガードが拒否の記録・回数・許可を置くフォルダ `<base>`（`${TMPDIR:-/tmp}/dev-workflow-git-guard`）と、その中のファイルを、symlink でも・他人の持ち物でも・誰でも書けるモードでも、確かめずに使っていた。TMPDIR が未設定で `<base>` が `/tmp` の下になる環境では、同じ機械の別のユーザーが `<base>` を先に作るか symlink を置くと、許可を偽造でき（scratchpad の中だけ）、ファイルを上書き・追記させられた（issue #1155 の指摘 2。親のエピックは #1476）。

- `scripts/git-guard-scratchpad.py`: `check_base` を足した。`<base>` とその下の `denied/`・`permits/` を、symlink でない・ディレクトリ・自分の uid の持ち物・グループと他者に書き込み権が無い、の 4 条件で lstat で確かめ、無ければ 0700 で作る。`<base>` の親が無ければ作らずに満たさないものとする。既にあるフォルダのモードは変えない（0755 の `<base>` はそのまま使う）
- 同じファイルに、symlink を辿らずに読む `read_json_nofollow`・`read_int_nofollow` と、予測できない名前の一時ファイルを `O_CREAT|O_EXCL|O_NOFOLLOW`・0600 で作って `rename` で置く `write_text_atomic` を足した。`write_json_atomic` はこれを使う形に、`append_log` は `O_APPEND|O_CREAT|O_NOFOLLOW`・0600 で開く形にした。どちらも `<base>` を自分で作らなくなった
- `scripts/git-destructive-guard.sh`: 子の経路で、許可を使う前に `check_base` を呼ぶ。満たさなければ許可を探さず、拒否の記録も回数も書かずに `deny` を返し、理由文に「拒否の記録を作れなかった」・`<base>` のパス・満たさなかった条件・報告にコマンドの全文を書くことを入れる。この `deny` は打ち切りの回数に数えない（`"continue"` のキーを出さない）。判定のファイルを読めないときも回数を数えなくなった（今までは数えていた）。回数のファイルと取った許可は symlink を辿らずに読む
- 子に拒否の記録のパスを示せないとき、`<base>` の問題でない場合（判定のファイルを読めない・記録を書けない）も理由文に「拒否の記録を作れなかった。親に返す報告にコマンドの全文を書く。」を足した（rm ガードと揃えた）
- 主の呼び出しの経路は変えていない。`<base>` を作りも確かめもせず、`<base>` が symlink でも `ask` と理由文は変わらない
- `scripts/rm-permission-guard.sh`: 許可を使う前に `check_base` を呼び、満たさなければ許可を探さず、記録も `permit-log.jsonl` の行も書かずに `deny` を返す。message に `<base>` のパスと満たさなかった条件を足した。取った許可は symlink を辿らずに読む
- 許可を書くスクリプト（`scripts/` の下の permit の .sh）: 記録の場所から求めた `<base>` を `check_base` で確かめ、満たさなければ許可も `permit-log.jsonl` の行も書かず、回数のファイルも消さずに、条件と場所を stderr に書いて 1 で終わる。拒否の記録は symlink を辿らずに読む（symlink の記録は読まずに 1 で終わる）
- テスト: `tests/git-destructive-guard.bats` に `base:` の 11 件、`tests/rm-permission-guard.bats` に symlink の 3 件を足した。`tests/hook-python-invocation.bats` は setup で TMPDIR を作業ディレクトリの下に差し替え、本物の `<base>` に拒否の記録を書かないようにした
- 受け入れること: 既に `<base>` を他のユーザーに取られている環境では、子の破壊的操作は親が許可を書いても通らない（許可を書くスクリプトが 1 で終わるので、親は今までどおりオーナーに上げる）。祖先のフォルダ（TMPDIR・`/tmp`）は確かめない
- 範囲外: 同じ uid の子が `permits/` に許可を書く形（指摘 1）は別の change で扱う
- 戻し方: この PR の差分を戻す。`<base>` の中のファイルの形は変えていないので移行は要らない
