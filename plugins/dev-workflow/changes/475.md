# epic-dispatch launch が子セッションを指定したモデルで起動する（#475）

`epic-dispatch.sh launch` は `orca worktree create --agent claude` で子セッションを起動しており、モデルを指定していなかった。`orca worktree create` にはモデルを指定する口が無く、子は Claude Code の既定モデルで動くため、既定が Sonnet のときは子がすべて Sonnet で起動した。

- `orca worktree create` に `--agent` を渡さずワークツリーだけを作り、`result.worktree.path` に対して `orca terminal create --command "cld --model '<model>'"` で子セッションを起動する。起動完了待ちと最初の指示の送信（#458）は `terminal create` の `result.terminal.handle` に対して行う
- `<model>` の既定は `opus`（子は `/develop` の 1 ループを丸ごと回すオーケストレーターなのでメインセッションと同じ扱い）。環境変数 `EPIC_DISPATCH_MODEL` で変えられ、空文字なら子を作らずに exit 1
- 子のワークツリーのパスが取れない・端末を作れない・端末のハンドルが取れない子は `failed`。端末を作れなかった子は、端末の作り直しと最初の指示の送信のコマンドを stderr に出す（再実行ではその子は `skipped` になるため）
- コマンド部分の既定は `cld`（アカウントの自動選択・`--dangerously-skip-permissions`・`--remote-control` を付けて `claude` に渡すシェル関数）で、以前 `--agent claude` で Orca の Agent 設定を通っていたときと同じ起動経路になる。環境変数 `EPIC_DISPATCH_CLAUDE_CMD` で差し替えられ（クォートせずそのまま置くので引数付きも書ける）、空文字なら子を作らずに exit 1。`epic-dispatch.sh` が足すのは `--model` だけで、許可の確認を飛ばすかどうかは `cld` 側が決める
- 受け入れたリスク: Orca に設定したエージェントのコマンドはハーネスから読めないので、Orca 側のコマンドを変えたら `EPIC_DISPATCH_CLAUDE_CMD` も合わせて変える必要がある
- develop の SKILL.md（Orca 経路）に、子セッションのモデルとコマンドの決め方と、`--dangerously-skip-permissions` を付けているのが `cld` であることを書いた
