# develop: 消費の記録に工程・試行・アカウントの印を書く（#1158）

develop が使った Claude と Codex の消費を、工程・試行・アカウントごとに分けて数えられるようにする。flatmate の `scripts/burn_consumption.py`（genetta-inc/flatmate#709）は、これらを記録の印からだけ読み、印が無ければ「欠測」と出す。

- `skills/develop/SKILL.md`「PR トークン上限」節に「消費の記録の印」を足した。印は `[消費記録 工程=<工程> 試行=<n> アカウント=<provider>:<登録名> 引継ぎ=<k>]`。工程名 11 語、試行と引継ぎの数え方、置き場 3 か所（`Codex 消費:` コメントの 2 行目以降／サブエージェントの description／`develop 開始` コメント）を書いた。「Role profile の選択」節の develop 開始コメントの記述にも起動アカウントの印を足した
- `Codex 消費:` コメントの 1 行目の形は変えていない（`codex-records.sh` と `pr-token-budget.sh` は変更なし）
- 同じ W を SendMessage で別の工程・試行へ再開しうるとき、description の印には `アカウント=` だけを書き、`工程=` と `試行=` は書かない。読み取り側は 1 体を 1 行にして description の印から 1 つだけ読むため、書くと再開後の消費が起動時の工程・試行へ誤帰属する。その W の工程・試行は欠測で出る。再開のたびに指示文の先頭へその再開の印を 1 行置く（今の読み取り側は読まない）
- G の工程は本体が起こした段（G の名前）から決め、G が要求したレビュアーは `impl-review`。G の名前の `<n>` は起動回数で試行ではなく、手渡しでは試行を変えず `引継ぎ=` を増やす
- 範囲外: 印への時刻（`開始=` `終了=`）。読み取り側の契約に無いキーで、flatmate 側の変更が先に要る。Codex 行の時刻は当面 rollout が登録 CODEX_HOME に残らないため取れず、`reset_unknown` になる
- 後続（flatmate 側の変更を要する）: 再開の印でサブエージェント 1 体の消費を工程・試行ごとの行に分けること、印への時刻の追加
- 検査: `tests/develop-skill.bats` の `consumption mark:` の 5 件
- 戻し方: この PR の差分を戻す。記録済みのコメントの印は読み取り側が読むだけなので、移行は要らない
- 実機確認の扱い: 検証用 issue は立てず、#1158 の develop 自身を使った。`claude --plugin-dir` では起動していない。本体がこのブランチの SKILL.md の規約を読んで印を書いた実行で、flatmate の `burn_consumption.py 1158` に `stage`・`attempt`・`account` が欠測でない `claude_work` の行（finish・1・`claude:default` など）が出ることを確かめた。Codex の 2 行は印を足す前の記録で欠測のまま
- `tests/develop-startup-budget.txt` の `skills/develop/SKILL.md` の予算を 85900 にした。main が 81962 バイトまで育ち、この change が約 3.9 KB 足して 85855 バイトになる（100 単位に切り上げ）。規約は本体が spawn のたびに使い、仕様も SKILL.md に書くと定めているので、条件付きの reference へ逃がさない
