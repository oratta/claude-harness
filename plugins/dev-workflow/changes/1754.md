# 子の Stop の処理失敗による差し戻しループを防ぐ（#1754）

別セッション方式の子の Stop で、入力情報・会話ログ・設定・予約文の読み取り、記録の複数一致、保存や無効化などの処理が失敗した場合、初回は従来どおり block する。JSON の真偽値 `stop_hook_active: true` の再停止では、理由と記録パス（複数一致では状態保存ルート）を stderr に残し、stdout 空・exit 0 で停止を通す。文字列の `"true"` は免除しない。

- 状態行の欠落・形式不備は、同じ入力の既存状態の無効化が成功する限り再停止でも差し戻す。無効化自体が失敗した場合は処理失敗の契約を優先する。
- 再停止フラグだけでは保存を省かず、復旧後は同じ世代に通常どおり保存する。停止許可を保存成功や作業完了とは扱わず、元の JSON・親の停止情報・新しい入力世代を保護し、残存ロックを自動で消さない。
- 入力フックの失敗時の exit 2、既存 Stop ガードの呼び出しと対象外セッションへの出力・終了コード転送は維持する。

初回と再停止の対、stdout/stderr の分離、形式不備、保存・無効化失敗、復旧、世代競合を Bats で検証する。schema・依存・version は変更しない。
