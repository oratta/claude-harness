# epic-dispatch.sh reap: 別名ブランチの PR で入った子を片付け、端末の片付け失敗を区別して返す（#1037）

エピックの親が `reap` で子のワークツリーを片付けるとき、squash マージで子が別名のブランチの PR として入った子は `kept <N> no-merged-pr` で残り、Orca が端末の片付けを確かめられず `orca worktree rm` が落ちたときは他の失敗と同じ `kept <N> rm-failed` になっていた（エピック #1038 の子）。

- `scripts/epic-dispatch.sh reap`: `gh pr list --head <ブランチ>` に HEAD と一致する先端の PR が無いとき、`gh pr list --state merged --search <HEAD>` でブランチ名を問わずに探す。最終判定は `headRefOid` と HEAD の完全一致のまま。一致が無ければ、両方空なら `no-merged-pr`、どちらかに出力があれば `head-mismatch`。検索の失敗は `pr-lookup-failed`。1 段目で一致したときは検索を呼ばない
- `orca worktree rm` が失敗し stderr に `terminal sweep failed` を含むときは `kept <N> rm-failed-terminal-sweep`。それ以外の失敗は `rm-failed` のまま。`--force` は付けず再試行もしない。stderr は従来どおり親の stderr にも流れる
- 受け入れること: マージ直後に GitHub の検索の索引が追いついていない子は、その回は `kept` で残り、あとで `reap` をやり直せば通る。Orca が `terminal sweep failed` の文言を変えると `rm-failed` に戻る（消す側には倒れない）。`kept <N> rm-failed-terminal-sweep` の子は、Orca を再起動してから `reap` をやり直す
- 変えていない: launch / wait / mark / route、develop の SKILL.md、印の無い子を片付けないこと
- 戻し方: この PR の差分を戻す。状態ファイルや設定は変えていない
