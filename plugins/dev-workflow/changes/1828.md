# エピックの親の見張り: dismiss の条件・未回答の停止の記録・owner-away の文面とテストを揃える（#1828）

エピックの親の見張りで、止まりの扱いに 3 系統の穴が残っていた（元は #1541・#1759・#1789。エピックは #1826）。

- `scripts/epic-dispatch.sh pending-owner`: `status != done` の子だけを対象にする（`told` と同じ）。再起動した親が、終わった子の古い止まりを主に上げ直さない
- `skills/develop/references/epic-stop.md` 手順 8: `dismiss` は、今回の停止の記録・止まった理由・主への問い・読めない止まりのどれも無いときだけ使う。未回答の停止の記録（`子の停止: 主の返事待ち`）の定義を `stop-judge.sh` と揃えて書き、その止まりは `dismiss` しないと明記した。`owner-away` で起こされた親は、同じ出力のほかの行を処理し終えてから `wait` を掛け直す
- `skills/develop/references/epic-multirepo.md`: 別リポジトリの子へ渡す列挙に `dismiss` を足した
- `scripts/stop-judge.sh`: `判断: 問いではない` を出す前に未回答の停止の記録を確かめ、記録があり needs-approval 付きで子を指す PR があれば形の崩れ（exit 1）にする。モデルを通る経路と、完了見出しでモデルを呼ばない早期 return の両方。`gh pr list` が失敗したときも exit 1。これで、子が説明だけを返したターンに `resumed` へ書き換わって親の返事が拒まれることが無くなる
- `scripts/epic-dispatch.sh` のヘッダー: `wait` の出力行数を `owner-away` が増えた分に直した（`--resolve` あり 1〜5 行、なし 1〜4 行）。`--help` に行数の記述は無く変えていない
- テスト: `stop-judge.bats`・`epic-dispatch.bats`・`develop-skill.bats` に追加。`owner-away` の閾値後の `--resolve` と排他取得失敗のテストも足した
- 受け入れること: 未回答の止まりを持つ子の最後の発言が説明だけでも、親の `reply --as owner` が届く。モデルが `問いではない` と返したとき、該当する止まりでは親が止まりを見送れず、形の崩れとして扱われる（再判定になる）
- 戻し方: この PR の差分を戻す。状態ファイルの形は変えていないので移行は要らない
