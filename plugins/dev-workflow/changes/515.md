# 主の返事を 1 時間以上待つときは、本体を引き継ぎから新しいセッションで再開する（#515）

develop の本体は、`needs-approval` を付けて主の返事を待って止まる。返事が 1 時間以上あとに来ると、20 万トークン前後の会話をそのまま再開するので、1 時間有効のキャッシュが切れていて会話全体を書き直す代金がかかっていた（#509 の実測でマージ済み PR 12 本中 10 本、1 PR あたり 1.36 ドル）。止まる前に記録先へ引き継ぎを残し、主の返事は新しいセッションの `/develop <記録先>` と一緒に渡してもらう。

- `skills/develop/SKILL.md` に「保留で止まるときの引き継ぎ」の節を足した。1 行目 `引き継ぎ: 主の返事待ち`（完全一致）と 11 項目の書式、投稿の順序（依頼コメント → 引き継ぎ → 主への案内。依頼は PR のコメントでもよい）、前任 W の手渡し可否（`可` / `不可` / `不要`。保留に入る前に本体が「手渡しの許可」を満たして記録する）、新しいセッションでの再開手順 6 項目、守備範囲の段落
- 保留の行・「PR トークン上限」の exit 2・レビューの 2 周キャップ超えは、どれも同じ節を指す。場面ごとの書式は作っていない
- 再開手順は、`needs-approval` を引き継ぎの「ラベルの付け先」で見る（記録先が issue でも保留の PR にラベルがある）。実行先は、最初の phase は develop 開始コメント、以降は dispatch 記録に選択結果があればそれを続け、どちらにも無い phase だけ選び直す。`手渡し: 不要`（最初の W を起こす前に止まった）のときは初回の W を起こす
- `commands/develop.md` は、引き継ぎのコメントがある記録先を、ラベルの有無によらず再開手順へ進める。記録先より後ろの文字列は主の返事として扱う
- `skills/pr-review-gate/stages/hold.md` 手順 6 の依頼文に、新しいセッションで返事を渡せる案内を足した。引き継ぎの項目一覧は持たず、書式は develop/SKILL.md を指す
- issue が「触るファイル」に挙げた `pr-review-gate/SKILL.md` は索引で、保留処理の実体は `stages/hold.md` にあったため、直したのは `stages/hold.md`
- `tests/develop-handover.bats` を足した
- 受け入れ条件 2・3（実機での再開・`--cap` を小さくした停止）は PR 本文に、条件 4（マージ後 5 PR の書き直し代）はマージ後にエピック #511 にコメントして記録する
