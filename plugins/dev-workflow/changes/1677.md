# develop: Codex の余裕が基準以上なら、Claude の余裕を問わず全工程を Codex に渡す（#1677）

`/develop` の投げ先の自動選択は、Claude の余裕（週の経過率 − 週の使用率）が 0 以上なら、Codex の余裕がどれだけ大きくても実装を Claude に渡していた（構成 `claude-write-codex-review`）。2026-11-18 の実測では Claude +6.9・Codex +65.3 ポイントで実装が Claude に回り、Codex の枠は期限で消えていた。2026-11-18 のオーナーの決定で、Codex の余裕が基準以上なら全役割を Codex に渡す。親エピックは genetta-inc/flatmate#698。

- `scripts/codex-develop.py`: `select_configuration` が、Codex オフ（`codex-off`）の次に「Codex の余裕が欠測でなく基準以上 → `codex-standard`・reason `codex-headroom-meets-threshold`」を判定する。Claude の余裕は見ない。残りの判定（`both-providers-have-headroom`・`only-codex-has-headroom`・`only-claude-has-headroom`・`no-provider-has-headroom`）は今と同じで、Codex が基準未満のときだけ当たる。比較はどれも「以上」（基準ちょうどは `codex-standard`）
- 基準は環境変数 `DEVELOP_ALL_CODEX_MIN_MARGIN_PCT`（既定 10。flatmate の `ACCOUNT_ALLOC_MIN_SURPLUS_PCT` の既定と同じ値）。`~/.claude/settings.json` の `env` で変える。未設定・空白は既定値。数でない・有限でない・0 未満・100 超は既定値に倒さず、自動選択が `status: blocked`・exit 2 で止まる（headroom の設定と同じ扱い）。読むのは自動選択のときだけで、明示 profile・旧形式では読まない
- 置き場を `accounts.json` の `codex` にしなかった理由: そこを読む `read_codex_enabled` は書き損じをオンと読んで止めない規則で、「不正なら止める」値を同じブロックに置くと読み方が逆向きに混ざる。headroom の設定は環境変数で、不正値で止める経路がすでにある
- selection evidence の形は変えていない（基準の値は載せない）。dispatch のコメントの reason に新しい値 `codex-headroom-meets-threshold` が出る。reason の値を列挙して扱っている呼び出し側は、この値を受け取る
- 開始済みの工程を途中で切り替えない動き、余裕の値の計算（headroom）、代表 Codex account の選び方は変えていない
- `references/codex-develop.md`「起動と role 解決」と `docs/codex-develop.md` の構成の選び方の文を直した。仕様は `codex-role-profiles` の要件「明示指定が無い工程では provider の週次余裕から構成を選ぶ」
- 受け入れること: Codex の余裕が大きい間は、Claude に余裕があっても実装が Codex になる。flatmate のバーンの子もこの自動選択で動くので、同じ規則で Codex に寄る（バーンの起動の判定は genetta-inc/flatmate#2217）
- 戻し方: この PR の差分を戻す。設定は任意で、状態ファイルの形は変えていないので移行は要らない。基準だけ戻したいときは `DEVELOP_ALL_CODEX_MIN_MARGIN_PCT=100` にすると、余裕が 100 ちょうどのときを除き今までの選び方になる
