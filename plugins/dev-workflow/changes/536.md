# dev-workflow: CI やり直し直後の古い失敗を待つ（#536）

`pr-state.sh decide` は、CI のやり直しを決めたときに失敗したジョブ ID の並びを `reran_jobs` に保存する。同じ HEAD で同じジョブ ID の失敗を再び観測したら、古い結果として `none` を返し、前回の状態を保つ。やり直し直後の反映待ちで修正回数を増やしたり、上限時間の打ち切りをオーナーに上げたりするのを防ぐ。

受け入れること: 観測のジョブ ID がすべて保存済みの古いジョブ ID に含まれる間は古い失敗として待つ（呼び出し側の起動し直し上限は下記）。新しいジョブ ID の失敗には従来どおり `fix` または `escalate` を返す。`reran_jobs` が無い旧状態・空の並び・`null` を含む並びは待ちの対象にせず、従来の判定を続ける。

仕様レビュー R1 の反映: decide 要件に入力元・防ぐ誤判定・許容する見逃しの守備範囲を記録し、別ジョブ ID を `fix` にするシナリオの原因を `unrelated` に限定した。`dev-workflow-ci-watch` の打ち切り要件にも、同じジョブ ID の再観測は `none`、別ジョブ ID の打ち切りは `escalate` とする例外とシナリオを明記した。

戻し方: #536 の `pr-state.sh`・対応テスト・`dev-workflow-pr-state` と `dev-workflow-ci-watch` の仕様差分を戻す。保存済み状態の `reran_jobs` は旧実装では未知のキーとして引き継がれるだけなので、状態ファイルの移行は不要。

独立レビューの反映: `next.state=wait` の古い失敗は呼び出し側で `wait` を起動し直し、続けて 3 回でも決着しなければ終了して通知する。rerun の実行エラーは `needs-approval` を付けて上げ、同じ／別の打ち切りジョブ ID を確認する結合テストを追加した。

守備範囲の追記: ci-watch の手順 6（`next.state=wait` の `none` を連続 3 回まで待つ判定と `rerun` 失敗の扱い）に、入力・拾いたい誤り・許容する入力・完了条件にしない旨の段落を reference と仕様に足し、存在確認のテストを追加した。

コードレビュー F1〜F3 の反映: 規則 5 を「並びの一致」から「観測のジョブ ID が 1 件以上あり、すべて `reran_jobs` に含まれる」に変え（一部の run だけ反映された観測でも `fix` に回らない）、`reran_jobs` が配列でない状態では落とさず従来の判定に進むようにし、冒頭コメントに規則を足した。テストと scenario を追加した。
