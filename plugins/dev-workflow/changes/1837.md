# エピックの親の見張りの穴を塞ぐ（#1827。元の issue #1084・#1182・#1598・#1620・#1815）

エピック #1826 の子 #1827 として、元の issue 5 本の受け入れ条件の和集合を 1 本で満たした。OpenSpec change `epic-wait-watch-gaps` を archive した。

- `scripts/epic-dispatch.sh` `notify-closed`: 止まった印の有無によらず、完了の印の無い completed の子に完了を促す（`skipped <N> not-stopped` を廃止）。`deliver_reply` に引数 `closed_notify` を足し、止まっていないと決まった子には `--relaunch` を当てず端末に送るだけにする（#1182）
- `wait --watch-done` の完了推定は `stopped-seen` の子も対象にし、`stop`・`stop_uuid` は残す（#1598）
- `scripts/stop-judge.sh` と `wait --resolve`: 判断に `判断: 親が動く` を足した。推奨が親の操作を含む止まりは子に送らず、子 issue に `親の判断: 親の操作が要る` と `送るはずだった返事:` を残して `stopped` で返す。`parent-pass-criteria.md` に親の操作の定義を、`epic-stop.md` 手順 8 に段落「親の操作が要る子」と pending-owner の復元の扱いを足した（#1620）
- owner-away: 子が新しいセッションで再開し、`turn_state.recorded_at` より新しい主の入力があれば知らせない（#1815）
- `epic-loop.md`・`reply-after-idle.md` を上に合わせた。場面予算（`tests/develop-epic-scene-budget.txt`）の 9 場面を実測に合わせて上げた
