# モデル別の PR トークン累計上限を計測へ接続する（#1800、3 分割の 3 本目）

PR #1804 で追加した共通処理を、PR トークン累計の計測 `pr-token-budget.sh` へ接続した。#1800 の change 3（`wire-pr-token-cap-thresholds`）に当たり、これで文脈上限・強制停止・累計上限の 3 経路がすべてモデル別の表から決まる。

- `scripts/pr-token-budget.sh`: 数えたサブエージェントの各リクエストの `message.model` から累計上限を解決する（値が分かれたら最小、Codex は集合に入れない、数えたリクエストが 0 件なら診断なしで fallback）。優先順は `--cap` > `DEV_WORKFLOW_PR_TOKEN_CAP` > モデル行 / fallback。`unknown_model` と対象 `pr_token_cap` の `revalidation_required` を上書き時も stderr に出し、同じ配布物の `token-thresholds.md` を絶対パスで案内する。表・上書きの不正と共通処理の欠損は stderr の理由と error の 1 行 JSON で exit 1。stdout の JSON のキーと exit code の意味は変えない。
- `tests/pr-token-budget.bats` に、モデル・上書き・診断・配布物の写し・共通処理の欠損のケースを追加した。
- `skills/develop/references/pr-token-budget.md`（既定はモデル別の表の値、新上限は直前の計測の出力 `cap`、診断では止めず最後の主への報告に書く、解決の失敗も exit 1）、`token-thresholds.md`（未配線の記述を接続済みの事実へ）、`decision-criteria.md`（累計上限の接続）を更新した。`pr-token-budget.md` は参照予算内に収めるため一部の言い回しを詰めた。
- OpenSpec の主仕様を同期し、change を archive した。

共通処理・表の数値と版は変えない（今はどのモデルも 30,000,000 なので既定の上限は変わらない）。戻す場合はこの PR の差分を revert する。状態ファイルやデータの移行は無い。
