# 許可リスト外の衝突解消でも、PR 全体を見た取り直しレビュー済みなら許容を引き継げるようにする（#694, #478, #480）

pr-review-gate 手順 3-c（前の HEAD の許容の引き継ぎ）は、main の取り込みで衝突を解いたファイルが許可リスト（`marketplace.json` / `plugin.json` の版の行・`CHANGELOG.md`）の外にあると、リスク宣言の本文も根拠ファイルも変わっていなくても引き継げなかった。genetta-inc/flatmate PR #1388 では衝突解消が `openspec/specs/client-package/spec.md` に及んだだけで `risk-carryover-check.sh` が終了コード 1 を返し、主は同じリスクに 3 回「許容」と答えた。衝突解消の結果は base との差分に現れ、新しい HEAD で PR 全体を見たレビューが読んでいるので、許可リストによる制限は二重になっていた。

- `scripts/risk-carryover-check.sh`: 許可リストの条件（ファイル名と中身）を満たさない衝突解消を `NG:` にせず、ファイルごとに `RESOLVED_OUTSIDE_ALLOWLIST=<ファイル>` の行で出す。終了コードは 0 = 無条件で引き継げる、3 = 新しい HEAD で PR 全体を見たレビューを経ていれば引き継げる（`CARRYOVER=if-rereviewed`）、1 = 引き継げない（`NG:` あり。根拠ファイルの変更・main 以外の commit など）、2 = 引数・環境の不備
- 同じスクリプトの follow-up を同じ change で直した（同じ Requirement を 2 つの change が並行して変えると archive で衝突するため）
  - #478: 根拠ファイルが前後どちらの HEAD にも無ければ終了コード 2。pathspec をリポジトリのルート相対に固定し、サブディレクトリから呼んでも根拠ファイルの変更を拾う
  - #480: 衝突解消ファイルの列挙を `git diff --no-renames` にし、merge commit の中で消して別名で作り直したファイルを取りこぼさない
- `skills/pr-review-gate/stages/hold.md` 3-c: 条件 1 を「終了コード 0、または終了コード 3 で、最新の `レビュー重量:` コメントの `固定 HEAD:` が新しい HEAD と一致し、その周が PR 全体を見たレビューである」に直した。全体を見た周と読めるのは、前の段の Gate Result の `周回:` が 1 の周か、`（全体レビュー: …）` の注記がある周だけで、読めなければ引き継がない。引き継ぎの根拠行に終了コード・許可リスト外のファイル・取り直しのレビューの固定 HEAD と周回とコメントのリンクを書く欄を足した（4 行のまま）。3-c 以外の節は変えていない
- **読み方の変更（BREAKING）**: 許可リスト外の衝突解消は終了コード 1 ではなく 3 になる。この版のスクリプトを古い 3-c の文面（終了コード 0 以外は引き継がない）と組み合わせると、終了コード 3 は引き継がない側に倒れるだけで、誤って引き継ぐことはない
- 残る限界: CI の見張りのあとの取り直しは `周回:` を引き継ぐため、二周目以降で合格したあとの取り直しは全体を見た周と読めず、主に聞く経路に残る（一周目で合格したあとの取り直し＝flatmate #1388 の形は救える）
- openspec change `risk-carryover-rereviewed-resolution` で `dev-workflow-pr-review-gate` の 3 つの Requirement を更新
