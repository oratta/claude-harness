# epic-child-state: 裏の作業の通知などで始まる子の入力を主の入力と記録せず、直前の送り手を引き継ぐ（#1821）

エピックの子の入力フックは、予約文・起動形・`親エピック #` で始まる入力以外をすべて送り手 `owner`（主）として記録していた。裏の作業の終わりの通知（`<task-notification`）や Claude Code 自身の出力（`<local-command-` / `<bash-input>` / `<bash-stdout>` / `<bash-stderr>`）で始まるターンも主の入力と記録されたため、親の判断で始めた作業が通知のターンで `主の返事待ち` に止まっても、親の見張りは主が打った返事待ちとみなして `stopped` を返さなかった。

- `scripts/epic-child-state.sh`: 定数 `NOT_OWNER_PREFIXES`（`epic-dispatch.sh` の `not_input` と同じ 5 つ）を足し、送り手が `owner` になる入力のうち、同じセッションの直前の `turn_input` があり、先頭の空白を除いた本文がそのどれかで始まるものは、直前の送り手を引き継ぐようにした。世代・受付時刻・`transcript_offset`・`turn_state: null` の扱いは通常入力と同じ。本文の途中にだけ接頭辞がある入力と `<command-name>` で始まる入力は `owner` のまま
- `skills/develop/references/epic-child-stop.md`: 送り手の説明に、5 つの接頭辞で始まる入力は直前の送り手を引き継ぐことを 1 文で足した
- `tests/develop-epic-scene-budget.txt`: `epic-child-stop.md` を読む 6 場面の予算を、1 文を縮めたうえでの実測に合わせて 127 バイト上げた（nested-stop 60244→60371、parent-stopped 165707→165834、nested-delegated 66700→66827、parent-delegated 172163→172290、parent-merge-wait 177028→177155、parent-merge-delegated 183484→183611）
- 仕様: `openspec/specs/dev-workflow-epic-state/spec.md` に送り手の引き継ぎの要件を足した（change `child-notification-turn-sender`）
- 戻し方: この PR の差分を戻す。状態ファイルの形は変えていないので移行は要らない
