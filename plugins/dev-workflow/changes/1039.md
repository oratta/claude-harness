# epic-dispatch: 子の待っている間の自動コンパクトの閾値を 120,000 にし、時間がたった子・親への返事の規則を置く（#1039）

エピックの子と親は、止まってから 1 時間以上たって返事を受けることが多い（会話 100k 以上の止まった点のうち、子 3.2%・親 40.6%）。会話のキャッシュは 1 時間で切れるので、そのまま返事を送ると会話全体を書き込み直す。Claude Code の待っている間の自動コンパクトはこの費用を減らせるが、既定の閾値 200,000 では、返事の直前の会話の中央値（子 159k・親 152k）の大半で走っていなかった。値と条件の根拠は https://github.com/oratta/claude-harness/issues/1039#issuecomment-6182988861 にある。

- `scripts/epic-dispatch.sh launch`: 子の起動コマンドを `EPIC_DISPATCH_PARENT_EPIC=<epic> CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS=<値> <cmd> --model <model>` にした。値の既定は 120000 で、環境変数 `EPIC_DISPATCH_IDLE_COMPACT_MIN_TOKENS` で変えられる。空か数字でなければ使い方を出して exit 1（`orca` も `git` も呼ばない）。100,000 未満の値は拒まない（下限の扱いは Claude Code が持つ）。端末の作り直しのコマンドにも同じ前置きが入る
- `skills/develop/references/reply-after-idle.md`（新規）: 子 120,000・親 100,000 の閾値と付ける場所、そのまま送るか起動し直すかを分ける条件（端末が無い／60 分未満／コンパクトが走った／会話が 150,000 以上か未満）と判定に使う事実、親への適用と親の状態の復元、根拠と限り、1〜2 週間後の再集計を書いた。送り方と起動し直し方の手順本体は #1034 が書く
- `skills/develop/SKILL.md`「回し方」: 子の起動コマンドに閾値が付くことを 1 文、時間がたった子・親に返事を送る前に上のファイルで決めることを 1 段落足した。他の節は変えていない
- 親の値は harness からは付けられない。主が親を起動するコマンドの先頭に `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS=100000` を付ける（`~/.claude/settings.json` の `env` には置かない。主の全セッションに効くため）
- 受け入れること: この変更より前に起動された子には前置きが無く、既定の 200,000 のまま動く。返事が来ないまま子の端末が開いていると、コンパクトの費用が無駄になる（返事なしで終わった子の端末が全部開いたままの想定では、既定より損になる。Orca 経路の子は `reap` で端末が閉じるので当たりにくい）
- 戻し方: この PR の差分を戻す。差分を戻さずに既定と同じ値にするなら `EPIC_DISPATCH_IDLE_COMPACT_MIN_TOKENS=200000` を付けて `launch` する
