# epic-dispatch launch: 子のワークツリーの端末を 1 つに保つ（#1055）

`epic-dispatch.sh launch` で起動した子のワークツリーには、空のシェルの端末「Terminal 1」と子のセッションの端末の 2 つが残っていた。Orca 1.4.226 の `orca worktree create`（`--agent` なし）が空のシェルの端末を作り、launch がそのあと `orca terminal create` で 2 つ目を作っていたためで、端末が 2 つあると `reply` が `failed <N> ambiguous-terminal` で止まった。issue: https://github.com/oratta/claude-harness/issues/1055

- `scripts/epic-dispatch.sh launch`: worktree create のあと `orca terminal list` で端末を数える。ちょうど 1 つなら新しい端末を作らず、その端末へ従来と同じ起動コマンド（`EPIC_DISPATCH_PARENT_EPIC=<epic> CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS=<値> <cmd> --model <model>`）を `orca terminal send --enter` で打ち込み、端末が Claude Code になるまで一覧を引き直して待ってから、従来どおり `terminal wait` と指示の `terminal send` に進む。0 個のときだけ従来どおり `terminal create`。一覧が読めない・2 個以上・打ち込めない・Claude Code にならないときは端末を作らず `failed <N>`
- 案 (b)（`worktree create --agent claude`）を採らなかった理由: Orca 設定のコマンドで起動するため `EPIC_DISPATCH_CLAUDE_CMD` / `EPIC_DISPATCH_PARENT_EPIC` / `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` / `--model` を渡せない
- `tests/epic-dispatch.bats`: 偽の orca で worktree create が端末を 1 つ作る場面を再現するテストなどを足した
- 戻し方: この PR の差分を戻す。この変更より前に起動した子の端末はそのまま動く
- 確認は残り 1 件: 実機の Orca で launch した子のワークツリーの `orca terminal list` が 1 行で Claude Code であること
