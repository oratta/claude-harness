# pr-review-gate: 三表と順 3 の一覧がコメント長の上限を超えるときの分け方と読み方を決める（#1249）

PR #1243 で照合表が約 120KB になり、照合と振り分けの G がその場の判断で 3 つのコメントに分けたが、分け方も次の段の G の読み方も決まっていなかった。順 3 の `## 一覧（順 3）` は全行のままなので、全ヒットが数十万字ある語で順 3 に当たると、W が投稿できず止まる。

- `skills/pr-review-gate/stages/triage.md`: `## 出口` の前に節「コメント長の上限を超えるとき（三表と順 3 の一覧）」を足した。`wc -c` のバイト数が 65,536 を超えるコメントは、本文を行の境界で切って部分のコメントに置き、見出しの行と `部分 k/n: <コメントの URL>` の行だけを持つ親のコメントで結ぶ。部分を先に、親を最後に投稿する。読む側は確かめたうえで部分の本文を連結し、分けないときと同じ照合に通す
- 同じファイルの順 3 の書式の箇条に、上の節への案内を足した。「1 つの PR コメントに投稿」の文は変えていない
- `skills/develop/references/roles/worker/implement.md`: 一覧が上限を超えるときの規則への案内と、1 行だけで部分に収まらない行があれば投稿も push もせず return することを足した
- `tests/pr-review-gate-long-comment.bats` を足した
- 読めないときは新しい Status を足さない。三表の部分が読めなければ `review-incomplete`、順 3 の部分が読めなければ照合をせず差し戻し 1 回
- `scripts/review-hit-set.py`・`gate-runner.md`・`reviewer-brief.md` は変えていない（照合と振り分けの G は `stages/triage.md` を全部読むので規則に届く）
- 上限に収まるコメントの書式と読み方は変えていない
- 受け入れること: 2 番目以降の部分は表の見出しが無いので、GitHub の画面では表に見えない。日本語の本文は字数では収まってもバイト数で分かれることがある。親のコメントの偽造、補助表の行だけが部分の中で欠けることは拾わない
- 戻し方: この PR の差分を戻す。保存される状態は増えていないので移行は要らない
