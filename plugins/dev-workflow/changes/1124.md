# git-destructive-guard: 画面を見ている人のいないセッションでは確認画面を出さずに拒否する（#1124）

flatmate の住人は `--dangerously-skip-permissions`（= `bypassPermissions`）の対話 TUI として tmux に常駐し、オーナーは Discord だけを見ている。`git-destructive-guard.sh` は `bypassPermissions` の主の呼び出しに `ask` を返すので、確認画面が誰にも押されず、セッションが無期限に止まっていた（2026-10-20 に flatmate #1637 の子セッションで、レビュアーの `git checkout -q -- <path>` で止まった）。payload の値では住人とオーナーの対話セッションを見分けられないので、起動する側が付ける環境変数を印にした。

- `scripts/git-destructive-guard.sh`: 環境変数 `DEV_WORKFLOW_UNATTENDED` を「このセッションの画面を見ている人がいない」という印として読む。前後の空白を除いて空（未設定を含む）か `0` なら印なし、それ以外は印あり。印のあるセッションの主の呼び出しには、`permission_mode` にも `DEV_WORKFLOW_GIT_GUARD_FORCE` にもよらず `deny` を返す。判定の順は 子 → 印 → FORCE → `permission_mode`。子の呼び出しは今までどおり子の規則と理由文。`DEV_WORKFLOW_GIT_GUARD=off` は印があっても全許可のまま。印の無いセッションの振る舞いは変えない
- 印のあるセッションへの拒否理由: 実行していない／何を・なぜ・いつ実行するかをチャンネル（Discord など）でオーナーに伝えて承認を求め、承認されたらオーナーが自分で実行する。確認画面と入力欄の `!` の話は書かない。拒否の回数は数えず、`continue: false` も返さない
- `rules/destructive-git-guard.md` の「hook との分担」節と `rules/README.md` の該当行に、画面を見ている人のいないセッション（起動時に無人の印を付けたもの）でも確認画面を出さずに拒否され、チャンネルで主に承認を求めることを足した
- 印を付けるのは起動する側。flatmate の住人の起動で付ける作業は genetta-inc/flatmate#1663
- 受け入れること: 印の付かないセッション（住人が tmux などで別に起動したセッションを含む）は今までどおり確認画面で止まりうる（印の引き継ぎは #1123・#1126）。印のあるセッションをオーナーが画面で見ていても確認画面は出ず、オーナーが自分で実行する
- 戻し方: この PR の差分を戻す。印を付けた起動側は、戻したあとは印が読まれないだけで害はない
