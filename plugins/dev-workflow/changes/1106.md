# develop: エピックの子を同時に動かす数に上限を入れ、枠が空いたら後回しの子を起動する（#1106）

`epic-dispatch.sh launch` は着手できる子を件数にかかわらずすべて起動していた。オーナーの環境では 2026-10-19 に genetta-inc/flatmate#1615 で子を一度に 12 件、合わせて 15 件まで同時に動かした。子 1 件ごとに Claude Code のセッションが 1 つ立ち、さらにサブエージェントやテストを動かすので、メモリの少ない Mac ではメモリを使い切って PC ごと落ちうる。flatmate の構築代行の第3版（genetta-inc/flatmate#1633）で客の Mac でも `/develop <エピック>` が子を並列に起動しうるため、上限を入れた。

- `scripts/epic-dispatch.sh`: 同時に枠を使う子の上限を、環境変数 `EPIC_DISPATCH_MAX_PARALLEL`（1 以上の整数。空・0・数字以外は使い方を出して exit 1）か、無ければ物理メモリから決める。既定値は物理メモリの GiB を 4 で割って切り捨てた値（最小 1）。物理メモリは `sysctl -n hw.memsize`、読めなければ `/proc/meminfo` の `MemTotal` で読み、どちらも読めなければ 2 にして stderr に出す
- 新しいサブコマンド `max-parallel`: 上限を数字 1 行で出す（orca / gh / git を呼ばない）。サブエージェント方式の本体が同じ上限を使うため
- `launch`: `orca worktree list --json` から、今の親ワークツリーから作られた子のうち、完了の印（`workspaceStatus` が `completed`）・止まった印（`comment` が `epic-stopped` / `epic-stopped-seen`）が無く、issue が閉じていない子を「枠を使っている子」と数える（子ごとに `gh api repos/{owner}/{repo}/issues/<N> --jq .state` を 1 回呼ぶ。読めない子は数える側に倒す）。空き枠（上限 − 使用中、0 未満は 0）の分だけ起動し、残りは `orca worktree create` も注意書きも行わずに `deferred <N>` の 1 行で出す。`deferred` は失敗ではなく exit code に影響しない。create に進んだ子は `failed` でも 1 枠を使う。stderr に `max parallel <上限> (<出どころ>); in use <数>: #<N>...` を 1 行出す
- `skills/develop/SKILL.md`「エピックの扱い」→「回し方」: Orca 経路の手順に、後回しの子を `wait` に渡さないこと、`done`・`closed`・`stopped` を処理したあと後回しの子があれば `launch` に渡し直すこと、後回しの子だけが残ったら `launch` の stderr を添えて主に報告することを書いた。新しい段落「同時に動く子の上限」に、変数・既定値の式・根拠の実測値・数え方を書いた。サブエージェント方式は、`max-parallel` の値で子をまたいだ W の総数を抑え、新しい子の W・同じ子の別の change の W・保留から戻る W の再開の前に毎回空き枠を確かめ、枠が空いたら再開 → 別の change → 新しい子の順で起こす。本体が `needs-approval` を付けて主の返事を待つ場面（W の停止・G の保留）で枠を返し、コンテキスト上限で手渡した後任の W は前任の枠を引き継ぐ
- 既定値の根拠（2026-10-20、オーナーの Mac、物理メモリ 32 GiB）: 同時に動いていた Claude Code のセッション 36 個の RSS は本体のプロセスのみで 146〜404 MB（中央値およそ 215 MB）、子プロセスを含めて最大 564 MB。子 1 件に 2 GiB（実測の最大を切り上げた 0.5 GiB と、測れていないテスト・ビルドの山の見込み 1.5 GiB）を見込み、物理メモリの半分を子に充てる。8 GiB → 2、16 GiB → 4、32 GiB → 8、64 GiB → 16
- 受け入れること: Orca 経路では、主の返事待ちで止まった子を数えないので、戻った子の分だけ一時的に上限を超えうる（止まっていた子の数まで）。サブエージェント方式の W は、R1 や G の結果を待って動いていないあいだも 1 枠を使い続ける。R1・G・決める役は枠に数えない
- 範囲外: 客の Mac で `EPIC_DISPATCH_MAX_PARALLEL` を置く場所（住人の `.env` など）の配線は flatmate 側の子 issue で行う
- 戻し方: この PR の差分を戻す。状態はどこにも保存していないので移行は要らない。上限だけを外したいときは `EPIC_DISPATCH_MAX_PARALLEL` に大きな数を設定する
