# agent-model-guard: fork の可否を決める共有枠モードを usage_view.py から得る（#1625）

`scripts/agent-model-guard.sh` の fork 判定は、週経過率と週次使用率から共有枠モード（`SHARED_BUDGET_MODE`）を導く式の写しを持っていた。#1622 で式を `scripts/usage_view.py` の `budget_mode_details` の 1 か所に寄せたが、guard だけ写しが残っていて、片方を直すと fork を止めるかどうかと注入されるモード・`codex-develop.py request` が当てるモードが食い違うおそれがあった。

- fork 判定は `usage_view.budget_mode_details` の結果で決める。guard から週の秒数・90 のしきい値・週経過との比較・明示 env の優先の判定が無くなった
- まず空のスロットで呼び、出どころが「明示 env」ならその結果で判定して `build_view` を呼ばない（明示 env のときは記録と snapshot を読まない。記録が壊れていても明示値が効く）。そうでなければ active スロットの実効値でもう一度呼ぶ
- 判定は正規化後のモード（未知の明示値は `throttled`）で行い、拒否理由には明示値をそのまま出す
- 変わる挙動: `usage_view.py` を読み込めない（無い・import で例外）ときは、明示 `SHARED_BUDGET_MODE` も読まず fork を通す（以前は明示 env だけは効いた）。`session-tripwires.sh` の扱いにそろえた
- 現在時刻の取り方（`USAGE_PROBE_NOW`、無ければ現在時刻）と fork 以外の判定は変えていない
- 戻し方: この PR の差分を戻す。設定や保存データの移行は無い
