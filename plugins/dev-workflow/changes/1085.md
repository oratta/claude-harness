# dev-workflow: 起動し直したセッションで切れた CI の見張りを再開する（#1085）

見張りの待ちの途中でセッションが落ち、会話を持ったまま起動し直したときの手順を `references/ci-watch.md` の 9 に足した。自分の待ちの `stopped` / `killed` の通知が会話に残った状態で次のターンが来たら、PR の状態と開始・終了のコメントを全ページ確認し、未決着なら聞き返さずに `next` から続ける。自分で TaskStop で止めた待ちは対象外。

- 決着済みの見張りは再開しない。終了のコメントがあれば何もせず、終了のコメントが無い merged / closed の PR は終了のコメントで記録を閉じる
- 同じ見張りの続きなので開始の判定・コメントは繰り返さない。2 のオーナーの指示を求める再開を、通知を受けていない別のセッションが引き継ぐ場合と書き分け、develop の `SKILL.md` から 9 を参照する
- SessionStart hook は足さない。hook で文脈を足しても入力なしのターンは起こせず、起動ごとの問い合わせの費用も増えるため。入力なしでセッションを起こす部分は #1084 が受け持つ
- 起動し直らない子を親が検知する経路も #1084 に残す。子の手順では落ちたままの子は救えず、親の待ちが会話ログの止まった時間を拾う経路で扱えるため
- 6 件の文面検査を追加。実機の再現は tasks 3.1 / 3.2 で別途行う
- develop の起動時予算に収めるため、CI の見張りの行の重複説明を短縮した。起動時・常時注入とも予算ファイルは変えない
