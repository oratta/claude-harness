# 依存待ちで終了した子の終了状態に依存待ちの印を保存する（#1775）

依存待ちで正常に終了した子は `状態: 作業報告` を残すため、状態記録だけを読む親が通常の作業報告と区別できなかった。生成側だけを先に直し、親が読む側は #1744 で別に接続する。

- `scripts/epic-child-state.sh`: 子の Stop が保存する `turn_state` に、任意の boolean `dependency_wait` が増えた。今回の発言が、世代・セッション・指定ログの対応と状態行（値が `作業報告`）と既存 Stop の許可をそろえ、かつ末尾が `止まった理由: 依存待ち: <URL>`（`--dependency-wait` と同じ末尾の規則）のときだけ `true` を保存する。それ以外は項目を省く（`false` は書かない）。引用・コードブロック内の印、通常の作業報告、`主の返事待ち` / `完了` には付かない
- 型検査: 項目があるときは boolean でなければならない。文字列・数・null・配列・オブジェクトは既存の「ターン項目が不正」と同じ扱い（通常入力は exit 2）。項目の無い旧終了状態と、ターン項目の無い旧記録は従来どおり読める
- 無効化は `turn_state` 全体と同じ経路。次の通常入力（主・親・起動形）で `turn_state: null` になり、Stop の差し戻しでも消える。同じ世代で通常の作業報告に書き直せば持ち越さない。ロック・世代の再照合・予約文の扱い・保存失敗時の診断は変えていない
- `--dependency-wait` の判定は共通の関数にしたが、状態行の無い形も含めて結果と終了コードは同じ。`scripts/epic-dispatch.sh` と親の期待値は変えていない。新項目の付いた記録を変更前の親が読んでも結果が変わらないことを子側のテストで確かめた
- `skills/develop/references/epic-child-stop.md`「依存待ちで終了する」: Stop が状態値 `作業報告` のまま `dependency_wait: true` を保存して親へ渡す説明に変えた。登録・確認・停止コメントと失敗時の手順は変えていない
- この項目は依存登録の成功や依存の解消を保証しない。旧記録に遡って付けることもしない。親が読んで再開・承認につなげる側は #1744
- 戻し方: この PR の差分を戻す。親は任意項目を無視するので、保存済みの記録の変換や削除は要らない
