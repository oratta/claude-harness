# 子への reply の起動し直しを自動判定する（#1742）

`epic-dispatch.sh reply --as parent` / `--as owner` は `--relaunch` を付けなくても、`wait --resolve` と共通の判定で、会話量 150000 以上または最後の assistant から 3600 秒以上なら起動し直す。記録の worktree・stop_uuid で本体ログを選び、片方の計測ができなくても他方が真なら起動し直す。両条件を確認できなければ通常送信に戻る。閾値の非負整数検査、明示 `--relaunch` の強制実行、再開済みの not-stopped 抑止、記録の launcher による送信を維持する。`notify-closed` は従来の手動分類のまま。

親だけの片付けは全対象には足りない。既に done の子は reap、running・止まりの印なしなど既存の完了推定条件を満たす子は wait --watch-done → done → reap で足り、「終えて」だけの reply を省ける。一方、waiting / stopped / stopped-seen の子は完了推定の対象外で、reap は not-done で残す。completed で閉じた停止中の子には notify-closed で完了報告と mark done を促す。親の done 強制や reap の安全条件の緩和は追加しない。

結論と理由は [issue の仕様化判断](https://github.com/oratta/claude-harness/issues/1742#issuecomment-7087835723) に記録した。両送り手の境界・計測不能・閾値上書きと不正値・明示指定・再開済み抑止を fixture で検査する。この検査は自動判定と既存経路の互換性を確認するもので、実機の費用削減を実証したものではない。launcher・状態スキーマの移行は不要。戻す場合は本変更を revert する。
