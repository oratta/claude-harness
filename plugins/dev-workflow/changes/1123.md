# develop: エピックの子の状態を Orca の印からローカルの状態の記録に移す（#1123）

エピックの子の状態（完了・レビュー待ち・主の返事待ちの止まりとその受け取り）の正本を、Orca のワークツリーのメタデータ（ボードの列・コメント欄・`parentWorktreeId`）から、`${EPIC_STATE_ROOT:-~/.claude/epic-state}/<owner>.<repo>-<エピック番号>/<owner>.<repo>-<子の番号>.json` に子ごと 1 ファイルで置く記録に移した。Orca の画面の印は記録を書いたあとに写すだけにした。起動部品を Orca 以外にも広げるエピック #1122 の 1 段目で、出力の行と exit code は変えていない。

- `scripts/epic-state.sh`（新規）: 置き場の組み立て（origin の 3 つの形から小文字の `<owner>/<repo>` を読む。GitHub 以外は exit 1）・読めない記録の判定・一時ファイルからの `mv`・`mkdir` の排他（`EPIC_STATE_LOCK_TIMEOUT`）・項目の読み書き・今のワークツリーでの記録の検索・親の側の照合。`orca` の語を含まない
- `scripts/epic-dispatch.sh`:
  - `mark` は今のワークツリーを `worktree` に持つ自分の記録を書き換えてから Orca の印へ写す。`route` と `launch` の子のセッションの判定は記録で行い、`parentWorktreeId` を見ない
  - `wait`・`pending-owner`・`notify-closed`・`reply`・`wait --resolve`・`reap` は、今のワークツリーを `parent_worktree` に持つ記録だけで子を見つけて判定する。読めない記録は `wait` では失敗したポーリング、`reap` は `kept <N> state-unreadable`、`pending-owner` は飛ばす、`notify-closed`・`reply` は `failed <N> state-unreadable`。`reap` は `kept <N> not-child` を出さなくなり、片付けた子と `gone` の子の記録を消す
  - `launch` は子のワークツリーを作る前に記録を書き、作成の失敗で消す。作ったあとの失敗は `launch_failed` に段（`create`・`terminal`・`ready`・`send`）を書く。エピックと別リポジトリの子は `failed <child> other-repo`。`worktree` が空の自分の記録は、Orca の一覧にワークツリーがあれば path と branch を書き足して `skipped`、無ければ上書きして作成に進み、その記録の 1 枠を使う（枠を 2 重に使わない）。同じ子を番号と `<owner>/<repo>#<N>` で重ねて渡しても 1 回だけ起動する。#1120 の同時に枠を使う子の数え方を記録に置き換えた（上限の値と `deferred` の出し方は変えていない）
  - 新しいサブコマンド `adopt <epic> <child>...`（記録の無い Orca の子を Orca の印から記録に取り込む。読めない記録の子は `failed <N> state-unreadable`、記録を書けなければ理由の無い `failed <N>`）と `clear <epic>`（エピックの状態ディレクトリを消す。番号の検査・`/` と `..`・空の置き場・`/` と `$HOME` そのもの・シンボリックリンクでは消さない）
  - 子の引数に `<owner>/<repo>#<N>` も受ける（エピックと同じリポジトリなら番号と同じ扱い）
- `skills/develop/SKILL.md`: 回し方の手順 7 で `reap` の前に `adopt` を呼び、手順 3・4・7 で `wait` を呼ばずに待ちを終える前に `clear` を呼ぶ。手順 3 から `not-child` を外し `state-unreadable` を足した。手順 6 の「`wait` が stdout 空で exit 1 なら親ワークツリーで開き直す」を `launch` と `adopt` の exit 1 の報告に書き直した。子の状態の正本が記録で Orca の印は写しであること、完了条件で状態ディレクトリが消えていることの確認を足した
- `skills/develop/references/reply-after-idle.md`: 主の返事待ちの子を記録の `stop` が `stopped-seen` で見分ける
- `tests/epic-dispatch.bats`・`tests/develop-skill.bats`: Orca の一覧の `workspaceStatus` / `comment` を置いていたテストを記録を置く形に直し、記録の書式・排他・`adopt`・`clear`・`launch` の記録・枠の数え方・手順書の照合のテストを足した。記録は `EPIC_STATE_ROOT` を一時ディレクトリに向けて書く
- `openspec/changes/archive/2026-10-20-epic-state-files`（archive 済み）: 要件の差分。capability `dev-workflow-epic-state` を `openspec/specs/dev-workflow-epic-state/spec.md` に新設し、`dev-workflow-develop` に読み替えの要件を足した
- 変えていないもの: 各サブコマンドの出力の行と exit code（`reap` の `not-child` を除く）、`--resolve` の判断と送り方、`reap` の安全確認の中身、`gh pr list`・`git ls-remote` の呼び出しの形、上限の値の決め方
- 受け入れること: この変更の前に起動した子は記録を持たないので、親の見張りは記録が無い子として扱う（`reap` は `gone`、`wait --watch-done` は印を見ない）。再開時に手順 7 の `adopt` で取り込めば今までどおり見張れる。オーナーが Orca の画面で印を手で変えても親には効かない
- 戻し方: この PR の差分を戻す。戻したあとは `~/.claude/epic-state/` の下の記録は誰も読まないので、ディレクトリごと消してよい

## 2/3: エピックと別のリポジトリの子（change `cross-repo-children`）

エピックの子がエピックと別のリポジトリにあっても、`launch` が子の clone にワークツリーを作り、親の `wait`・`reap` で見張れるようにした。同じリポジトリの子の呼び出しの形・出力・書式は変えていない。

- `scripts/epic-dispatch.sh`:
  - `launch`: 別リポジトリの子の `failed <child> other-repo` をやめ、子の clone を探す（環境変数 `EPIC_DISPATCH_CLONES`＝`<owner>/<repo>=<絶対パス>` を改行か `;` で区切る、無ければ `orca repo list --json` の `path`。`git -C <候補> remote get-url origin` で照合）。見つからない・2 つ以上は `failed <child> no-clone` / `ambiguous-clone`、Orca に無い clone は `not-in-orca`。`gh api repos/<o>/<r>` の `permissions.push` と `default_branch` を 1 回で読み、`no-push` / `permission-lookup-failed` / `base-lookup-failed` で止める（記録も枠も使わない）。起点は `--base` / `EPIC_DISPATCH_BASE`、無ければ子のリポジトリの既定ブランチ。判定の順は 記録の読み取り → clone → 書き込み権 → 子のリポジトリの Orca の一覧 → 空き枠 → 記録 → `git -C <clone> fetch origin <base>` → `orca worktree create --repo id:<id> --parent-worktree path:<親>`。親の clone の fetch は同じリポジトリの子が 1 件以上あるときだけ
  - 書式: 起動の最初の入力・`EPIC_DISPATCH_PARENT_EPIC=<owner>/<repo>#<E>`・注意書き（`gh issue comment -R <子のリポジトリ>`）・返事の頭（`親エピック #<E>（<owner>/<repo>）の判断（主の承認ではない）: ` と `主の返事（親エピック #<E>（<owner>/<repo>）経由）: `）にエピックのリポジトリを足す
  - `reap`: 別リポジトリの子だけ `gh pr list -R <記録の repo>`、base の名前を記録の `base`、base の照会と `cat-file`・`fetch` を `git -C <子のワークツリー>`、ブランチの片付けを子の clone（`git rev-parse --path-format=absolute --git-common-dir` を `orca worktree rm` の前に控える）に向ける。base の先端はリポジトリと base の組ごとに 1 回読む
- `scripts/stop-judge.sh`: 子の引数に番号か `<owner>/<repo>#<N>` を受ける。後者は子の本文・コメントを子のリポジトリから読み、過去の判断を `親の判断: 子 <owner>/<repo>#<N> ` で探す
- `skills/develop/SKILL.md`・`references/ci-watch.md`: 複数リポジトリの読み替えの表、`--base` の注意、`nested` を受けたセッションの `-R`、サブエージェント方式で別リポジトリの子を W に渡さないこと、手順 6 の新しい `failed` の理由、返事の頭の新しい形
- `tests/epic-dispatch.bats`・`tests/stop-judge.bats`・`tests/owner-reply-check.bats`・`tests/develop-skill.bats`: 上の挙動のテスト。`epic-dispatch.bats` の git スタブは `-C` 付きの `ls-remote` / `cat-file -e` / `worktree list` / `rev-parse --verify` / `branch -D` を `-C` なしと同じ答えに落とし、`--git-common-dir` に答える
- PR ゲート一周目の指摘の修正: `launch` のリポジトリ別の解決結果と `reap` の base の先端の控えを、名前を 16 進にしたキー（`var_key`）で引く（`a/b-c` と `a-b/c` が同じキーになっていた）。`launch` の同じリポジトリの子は起動コマンドをエピックの番号だけに戻す（別リポジトリの子のあとに前の子の `<owner>/<repo>#<E>` が残っていた）
- 実機確認（2026-10-20、Orca 1.4.232）: 別リポジトリの親で `--parent-worktree path:<親>` が通る。`orca repo list --json` は `.result.repos[]` の `id` と `path`
- 受け入れること: 別リポジトリの子は、clone が `EPIC_DISPATCH_CLONES` か Orca に登録されていないと起動できない。`gh` の認証アカウントが子のリポジトリに書き込み権を持たないと起動を止める。サブエージェント方式では別リポジトリの子を起こさない
- 戻し方: この PR の差分を戻す。記録の `repo` が別リポジトリの子が残っていても、戻したあとの `reap` は `gone` か `kept` で止まるだけで何も消さない

## 3a: Orca の呼び出しを起動部品に切り出す（change `epic-launcher-split`）

`epic-dispatch.sh` が直接呼んでいた `orca` のコマンドを、Orca の起動部品 `scripts/epic-launch-orca.sh` に移した。`epic-dispatch.sh` の stdout・exit code・stderr の文言・記録の中身と、`orca`・`git`・`gh` の呼び出しの順と回数は変えていない。tmux の部品と、記録の `launcher` で部品を選ぶ処理は 3b。

- `scripts/epic-launch-orca.sh`（新規）: `epic-dispatch.sh` が `bash <同じディレクトリ>/epic-launch-orca.sh <サブコマンド> <引数...>` で別のプロセスとして呼ぶ。状態の記録は読み書きしない。サブコマンドは `available`・`here`・`prepare`・`list`・`repos`・`unregistered`・`create`・`start`・`deliver`・`close`・`remove`・`mirror` の 12 個で、stdout は決まった語か 1 行 1 件の JSON だけ。知らないサブコマンドと引数の数の違いは exit 2。`list` は Orca の印（`workspaceStatus`・`comment`）を記録の語（`status`・`stop`）に読み替え、archive 済みを除く。`deliver` は端末の一覧を 1 回だけ読んで、送るか閉じて起動し直すかを決める（`send` と `restart` に分けると一覧を 2 回読むため 1 つにした）
- `scripts/epic-dispatch.sh`: `command -v orca` を `available`、`orca worktree current` を `here`、`set --issue` を `prepare`、`worktree list` を `list`、`repo list` を `repos`（1 回の `launch` で 1 回だけ）、`worktree create` を `create`、端末の起動から最初の送信までを `start`、`deliver_reply` の端末の扱いを `deliver`、`reap` の閉じと削除を `close`・`remove`、`mark`・`wait --watch-stopped` の印の写しを `mirror` に置き換えた。待ち時間（`EPIC_DISPATCH_READY_TIMEOUT_MS`・`EPIC_DISPATCH_SUBMIT_WAIT`・`EPIC_DISPATCH_REAP_CLOSE_RETRY_WAIT`）は今と同じ位置で検査して既定を当て、同じ名前の環境変数で部品に渡す
- `tests/epic-dispatch.bats`: 「orca を呼ぶスクリプトは 1 本だけ」の照合を、`orca` をコマンドとして書いた行の検索（`(^|[;&|(!]|(if|then|do|else|while|until) )[[:space:]]*orca [a-z]+`）で `epic-launch-orca.sh` の 1 本だけになることを確かめる形に変え、`epic-dispatch.sh` の写しに `orca terminal list --json` を足すと拾うことを確かめるテストを足した。部品を直接呼ぶテストを足した。ほかの既存のテストは書き換えていない
- 戻し方: この差分を戻す。記録の書式は変えていないので、戻したあとも記録はそのまま読める

## 3/3: 起動部品を tmux にも広げる（change `epic-launcher-tmux`）

3a で切り出した起動部品を、Orca のほかに tmux でも選べるようにした。親が tmux の中にいて Orca 管理下でなければ、子を tmux の新しいウィンドウで独立した Claude Code セッションとして起こす。使う部品は新しい子を起こす操作（`launch`・`adopt`）の時点で選び、子の記録の `launcher` に書く。`reply`・`notify-closed`・`reap`・`wait --resolve` は子ごとに記録の `launcher` の部品を呼ぶ。

- `scripts/epic-launch-tmux.sh`（新規）: 12 個のサブコマンドは Orca の部品と同じ。ワークツリーは `<リポジトリ>/.claude/worktrees/issue-<N>`、ブランチは `worktree-issue-<N>`（`git worktree add -b`）。`start` は `new-window` にコマンドを渡さず `send-keys -l` で打ち、入力待ちの画面（先頭の定数 `READY_PATTERN`）を待ってから指示を打ち、会話ログ（`~/.claude/projects/<パスの英数字以外を - にした名前>/*.jsonl`）に指示の先頭 40 文字を含む user の行が現れたことで送信を確かめる。シェルだけのペイン（`#{pane_current_command}` がシェル）には送らない。`remove` は `git worktree remove`（`--force` なし）。
- `scripts/epic-dispatch.sh`: `route` は `tmux` を返す（順は Orca 管理下が先、次に tmux の中）。環境変数 `EPIC_DISPATCH_LAUNCHER=orca|tmux` で部品を固定でき、使えなければ別の部品に振り替えず `launch` は exit 1。`xrepo_resolve` は `unregistered` が `ok` を返せば登録を要求しない。`reply`・`reap` などの入口は、対象の子の記録の `launcher` の部品の `available` を呼び、使えない部品の子だけ `kept <N> launcher-unavailable`。`mirror_state` は記録の `launcher` が `orca` のときだけ。
- `scripts/epic-state.sh`: 記録の `launcher` が `orca` か `tmux` でなければ読めない記録として扱う。
- `skills/develop/SKILL.md`: 回し方を、起動・待ち・閉じた子・止まった子・片付け・完了の 1 本の手順にし、Orca・tmux・サブエージェント方式で違う点を「部品ごとの欄」の表にした。`回し方: tmux` を足し、再開時は最新の `回し方:` の部品名を `EPIC_DISPATCH_LAUNCHER` で `launch`・`adopt` に渡し、使えなければ振り替えず報告して止まる。channel と unmanned の規定は意味を変えていない。
- `tests/epic-launch-tmux.bats`（新規）・`tests/epic-dispatch.bats`・`tests/develop-skill.bats`・`tests/develop-channel-mode.bats`: 上の挙動のテスト。`epic-dispatch.bats` に tmux のスタブと `git show-ref` の答えを足した。既存の Orca のテストは書き換えていない。
- 実装で埋めた決定: tmux の `create` のリポジトリの最上位は `git -C <clone か親> rev-parse --path-format=absolute --git-common-dir` の末尾の `/.git` を除いたもの。記録の無い子はゲートでは orca として扱う。
- 戻し方: この差分を戻す。tmux の記録の子が残っていると、戻したあとの `reap` はその子を読めない記録として止まるだけで何も消さないので、先に `reap` で片付けるか、記録のファイルを手で消す。
