# develop: エピックの子の状態を Orca の印からローカルの状態の記録に移す（#1123）

エピックの子の状態（完了・レビュー待ち・主の返事待ちの止まりとその受け取り）の正本を、Orca のワークツリーのメタデータ（ボードの列・コメント欄・`parentWorktreeId`）から、`${EPIC_STATE_ROOT:-~/.claude/epic-state}/<owner>.<repo>-<エピック番号>/<owner>.<repo>-<子の番号>.json` に子ごと 1 ファイルで置く記録に移した。Orca の画面の印は記録を書いたあとに写すだけにした。起動部品を Orca 以外にも広げるエピック #1122 の 1 段目で、出力の行と exit code は変えていない。

- `scripts/epic-state.sh`（新規）: 置き場の組み立て（origin の 3 つの形から小文字の `<owner>/<repo>` を読む。GitHub 以外は exit 1）・読めない記録の判定・一時ファイルからの `mv`・`mkdir` の排他（`EPIC_STATE_LOCK_TIMEOUT`）・項目の読み書き・今のワークツリーでの記録の検索・親の側の照合。`orca` の語を含まない
- `scripts/epic-dispatch.sh`:
  - `mark` は今のワークツリーを `worktree` に持つ自分の記録を書き換えてから Orca の印へ写す。`route` と `launch` の子のセッションの判定は記録で行い、`parentWorktreeId` を見ない
  - `wait`・`pending-owner`・`notify-closed`・`reply`・`wait --resolve`・`reap` は、今のワークツリーを `parent_worktree` に持つ記録だけで子を見つけて判定する。読めない記録は `wait` では失敗したポーリング、`reap` は `kept <N> state-unreadable`、`pending-owner` は飛ばす、`notify-closed`・`reply` は `failed <N> state-unreadable`。`reap` は `kept <N> not-child` を出さなくなり、片付けた子と `gone` の子の記録を消す
  - `launch` は子のワークツリーを作る前に記録を書き、作成の失敗で消す。作ったあとの失敗は `launch_failed` に段（`create`・`terminal`・`ready`・`send`）を書く。エピックと別リポジトリの子は `failed <child> other-repo`。#1120 の同時に枠を使う子の数え方を記録に置き換えた（上限の値と `deferred` の出し方は変えていない）
  - 新しいサブコマンド `adopt <epic> <child>...`（記録の無い Orca の子を Orca の印から記録に取り込む）と `clear <epic>`（エピックの状態ディレクトリを消す。番号の検査・`/` と `..`・空の置き場・`/` と `$HOME` そのもの・シンボリックリンクでは消さない）
  - 子の引数に `<owner>/<repo>#<N>` も受ける（エピックと同じリポジトリなら番号と同じ扱い）
- `skills/develop/SKILL.md`: 回し方の手順 7 で `reap` の前に `adopt` を呼び、手順 3・4・7 で `wait` を呼ばずに待ちを終える前に `clear` を呼ぶ。手順 3 から `not-child` を外し `state-unreadable` を足した。手順 6 の「`wait` が stdout 空で exit 1 なら親ワークツリーで開き直す」を `launch` と `adopt` の exit 1 の報告に書き直した。子の状態の正本が記録で Orca の印は写しであること、完了条件で状態ディレクトリが消えていることの確認を足した
- `skills/develop/references/reply-after-idle.md`: 主の返事待ちの子を記録の `stop` が `stopped-seen` で見分ける
- `tests/epic-dispatch.bats`・`tests/develop-skill.bats`: Orca の一覧の `workspaceStatus` / `comment` を置いていたテストを記録を置く形に直し、記録の書式・排他・`adopt`・`clear`・`launch` の記録・枠の数え方・手順書の照合のテストを足した。記録は `EPIC_STATE_ROOT` を一時ディレクトリに向けて書く
- `openspec/changes/epic-state-files`: 要件の差分（capability `dev-workflow-epic-state` の新設と、`dev-workflow-develop` の読み替え。archive で `openspec/specs` に反映する）
- 変えていないもの: 各サブコマンドの出力の行と exit code（`reap` の `not-child` を除く）、`--resolve` の判断と送り方、`reap` の安全確認の中身、`gh pr list`・`git ls-remote` の呼び出しの形、上限の値の決め方
- 受け入れること: この変更の前に起動した子は記録を持たないので、親の見張りは記録が無い子として扱う（`reap` は `gone`、`wait --watch-done` は印を見ない）。再開時に手順 7 の `adopt` で取り込めば今までどおり見張れる。オーナーが Orca の画面で印を手で変えても親には効かない
- 戻し方: この PR の差分を戻す。戻したあとは `~/.claude/epic-state/` の下の記録は誰も読まないので、ディレクトリごと消してよい
