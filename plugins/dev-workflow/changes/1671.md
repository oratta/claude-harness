# 主への依頼の書き方を、項目を 4 つのまとまりに分けた形と使う場所の表に直す（#1671）

主に頼みごとをするときの正本（`output-styles/readable.md` の節 3）は、質問に「OK すると何が起きるか」を埋め込み Yes か No で答える形で、目的・緊急度・答えを待って止まっている作業の欄が無く、どこで出しても同じ長さだった。2026-11-18 にオーナーと決めた形（https://github.com/oratta/claude-harness/issues/1671 ）を正本にした。

- `output-styles/readable.md` の節 3: 6 段の順（質問 → 主に聞く理由 → いま困っていること → 推奨と根拠 → 受け入れるリスク → 答え方）を、項目（題名・アクション／目的・詳細・論点・推奨と根拠・リスク／緊急度・ブロック／アクションに付けるリンク）を 4 つのまとまりに分けた表と、使う場所 5 つ（対話のセッション・チャットで 1 件ずつ出す依頼・チャットで何件かまとめて出す一覧・依頼を並べる画面の行と詳細）の表に置き換えた。主に聞く理由の 3 つと論点の定義は表の前に残し、論点の有無は論点の項目に書く。1 行目は題名（依頼の形。質問にしない）、2 行目は `アクション:` の行にした。論点なしの依頼を短く省くのは対話のセッションだけ（4 行、目的を足せば 5 行）で、チャットの 1 件ずつの依頼と画面の詳細では論点なしでも全部の項目を書く。例 3 つを新しい形に書き直した
- `rules/communication-style.md` の 3: 正本と食い違わない要点に書き直した（使う場所の表と例は正本にあると案内する）
- pr-review-gate の `declarations.md`・`stages/hold.md`・`stages/pass.md`: 旧い型の語（`答え方`・`3〜4 行`・`OK すると何が起きるかを中身で書いた質問`）を消し、論点なしの依頼の行数は正本の節 3 を指す形にした
- 聖域に触れる: 常時注入の予算（`tests/injection-budget.txt`）を、main の 43034 → 44032 に上げた（この PR の増分は 998 バイト）。節 3 に 2 つの表（まとまりの表と使う場所の表）を足した分で増え、旧い 6 段の説明を消した分と前置き・例を詰めた分では収まらなかったため。最初は合流元の 42300 → 43300 で承認を受けたが、#1655 が先に main に入って main の予算が 43034 になり、合流後の実測が 44032 になったので取り直した。主の承認: https://github.com/oratta/claude-harness/issues/1671#issuecomment-6967017151 （最初の承認） と https://github.com/oratta/claude-harness/pull/1676#issuecomment-6968231417 （取り直し）
- 予算を詰めるため、正本の節 3 の「ほかの決まり」から「この文書だけを読んで答えられる状態にする」を外した（同じ趣旨が readable.md の冒頭の段落にある。戻すと予算を超える）。短い版の「他の資料を見に行かないと判断できない書き方はしない」と「読み手の側にしかない情報」は、常時注入に残す指示の目印（`tests/always-on-injection-scope.bats`）なので残した
- develop の `references/epic.md`・`channel.md`・`handover.md`: 親と channel の発言の書き分けを「1 行目を質問、最後の行を答え方」から「1 行目を題名、2 行目を `アクション:` の行」に直した。手順 8 の子の停止の記録の項目は新しい項目に置き直した（`止まった理由:` は題名と詳細、`主に聞く理由:` は論点、`前提:` は詳細、`推奨:`・`推奨の根拠:` は推奨と根拠、`受け入れるリスク:` はリスク。アクションの行は親が書く）。使う項目と長さは正本の使う場所の表に従い、論点なしの行数は手順 8 に写さず正本を指す。状態表の規定は依頼の有無で分け、依頼が無い報告は 2 行目に `アクション:` の行を書かない。状態表の列名 `答え方` と子の側の記録の項目名は変えていない
- 番号検査の hook（`scripts/owner-message-number-check.sh`）: 並びの 2 番目の行（前後の空白と `*` を除く）が `アクション` で始まり `:` か `：` が続く発言も、番号の検査の対象にした。旧い 2 つの条件（1 行目が質問・区切りより上の最後の行に答え方の語）は残し、拾い方を狭めていない
- 実機の取り直し（2026-11-18、`claude -p --plugin-dir <worktree>/plugins/dev-workflow --model sonnet`）: 親の手順 8 の立場に、rm の許可・CI が落ちた 2 件・初版の記録を配布の前提から外す件の 3 つの停止の記録（7 項目）を渡した。主に上げた報告（rm の許可）は 1 行目が題名（質問でない）、2 行目が `アクション: 親のタブで、この報告の直後に別の発言を挟まずに「OK」と打つ` で、論点・推奨と根拠・条件と確認の有無を書いたリスクを持ち、記録の項目名を見出しにせず、記録の URL を区切りの下に添えた。CI の件は主に上げず、`reply --as parent` の返事と `親の判断: 子 #9102 通した — …` の 1 行を出した。初版の記録の件は「1 通 1 件」で次の報告に回した
- 受け入れること: 論点なしの依頼で、実機の報告は区切りより上に論点・推奨に加えてリスクの行を書いた（正本の短い形の 4 行を 1 行超える）。spec の実機の Scenario がリスクの項目を求めているので直していない
- main との合流（2026-11-18、origin/main の 3df00df0 を merge。#1655 の主の手の操作を絞る変更と衝突した）: #1655 が旧い節 3 の「主に聞く理由」に入れた 2 つの差し替え（主の手でしかできない操作の例をパスワード・MFA・CAPTCHA と人が押すと決まっているマージにし、ログイン済みのブラウザで押せる操作は入らないと書く／決まりで主の承認が要る操作に、主の名義で外へ公開・送信する・課金する・外部のアプリやサービスに権限を渡す（OAuth の認可を含む）操作を足す）を、新しい節 3 の表の前に残した主に聞く理由の 3 つの箇条にそのまま取り込んだ。`openspec/specs/owner-question-style/spec.md` も同じ 2 つの箇条を差し替え、節 3 の Scenario の THEN に #1655 が足した文（主の手の操作の例とログイン済みのブラウザの扱い）を新しい形の文のうしろに足した。`references/epic.md` 手順 8 は、この PR の題名とアクションの行の形に、#1655 の実機操作の例（パスワード・MFA・CAPTCHA のように、エージェントの手では通せない操作）を入れた
