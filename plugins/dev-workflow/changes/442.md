# usage-probe の古いロックの取り直しで 2 本が同時に走らないようにする（#442 の 1 つ目）

古いロック（120 秒超）が残っているところへ probe が 2 本ほぼ同時に来ると、後の 1 本が先の 1 本の取り直した新しいロックを `rm -rf` で消し、2 本が同時に API を叩いていた（先の 1 本の終了時の `rmdir` が後の 1 本のロックも外す）。

- `usage-probe.sh`: 古いロックの取り直しは、別の排他ディレクトリ `${LOCK}.takeover` を `mkdir` で取れた 1 本だけが行う。排他の中でロックの mtime を測り直し、新しければ（別の probe が取り直した）何もせず引く。古いままなら消して `mkdir` に進む。新しいロックは移しも消しもしない（初版の `mv` で退避する案は、退避中に正規のパスが空いて別の probe が `mkdir` に成功する穴があり、レビューで指摘されて採らなかった）。排他が 120 秒を超えて残っていたら外して今回は引く
- テスト 2 件: 古さの判定（stat）の直後に待たせる足場で、(1) 4 本を同時に起動、(2) 0.3 秒ずらして起動し 2 本目が「古い」の判定を持ったまま取り直し済みのロックに行き当たる、のどちらも curl の呼び出しが 1 回だけで、ロックと排他が残らないことを固定する。どちらも修正前のコードでは落ちることを確認した
- 戻すときは古いロックの取り直しのブロックを `rm -rf "$LOCK"` に戻す
