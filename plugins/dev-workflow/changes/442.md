# usage-probe の古いロックの取り直しで 2 本が同時に走らないようにする（#442 の 1 つ目）

古いロック（120 秒超）が残っているところへ probe が 2 本ほぼ同時に来ると、後の 1 本が先の 1 本の取り直した新しいロックを `rm -rf` で消し、2 本が同時に API を叩いていた（先の 1 本の終了時の `rmdir` が後の 1 本のロックも外す）。

- `usage-probe.sh`: 古いロックは消さずに `mv "$LOCK" "$LOCK.$$"` で自分の名前へ移す（成功するのは 1 本だけ）。移したものの mtime を測り直し、120 秒以内なら（別の probe が取り直した新しいロックなので）元に戻して終わる。超えていれば `rmdir` してから `mkdir` に進む
- テスト `lock: concurrent takeover of one stale lock ...`: 古さの判定（stat）の直後に待たせる足場で 4 本を同時に起動し、curl の呼び出しが 1 回だけであることを固定する。修正前のコードでは 3 回とも落ちることを確認した
- 戻すときは該当ブロックを `rm -rf "$LOCK"` に戻す
