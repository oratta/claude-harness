# review-hit-set.py の順 3 違反を蓄積して報告する（#406）

`review-hit-set.py --head` は、順 3 の主表の扱い欄チェックと補助表（`### 書き換えた該当しない行`）の 3 条件のどれか 1 件に違反すると、そこで即座に `raise` して exit 1 になっていた。G が W に差し戻すたびに 1 件しか分からず、修正→再実行→次の違反、を違反件数ぶん繰り返す往復が発生していた。

- 主表の扱い欄チェックと補助表の 3 条件（対応先が扱い「該当しない」の行をちょうど 1 つ指さない・重複・書き換え無し）を、即時 `raise` から `report` への蓄積に変えた。表の全行を検査し終えてからまとめて `contract: <理由>: <path>:<line>` の形で標準出力に出し、exit 1 を返す
- 違反した行は後続の照合に混ぜない。対応先不正・書き換え無しの行は書き換えマップに採用せず、重複は最初に見つかった行の値だけを候補として残す
- 違反が 1 件でもあれば `second_stage`（`unmatched:` / `not-removed:` の計算）を呼ばない。前提の表が信頼できない状態で差分を計算しても意味が無いため。出力は第 1 段（`missing:` / `extra:`）と `contract:` 行だけになる
- 表の構造そのものが以降の行の検査を続けられなくする違反（見出し欠落・列数不一致・必須フィールド欠落・SHA/検索コマンドの形式不正・`--repo`/`git grep` の失敗）は、従来どおり即時 `raise`・stderr 出力・exit 1 のまま変えていない
