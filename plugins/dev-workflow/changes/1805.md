# epic-dispatch: 作業待ちの行と tool_use が同じ発言にあるとき、親の会話ログ判定で送信候補にしない（#1805）

PR #1801 の一周目指摘（P4-F1）。子の同じ assistant 発言に `作業待ち:` の行と状態行（作業待ちの記録）と tool_use の両方があると、`scripts/epic-dispatch.sh` の `keepalive_background_log` は、tool_use で立てた「記録のあとに動きがあった」印を、続く作業待ちの記録の判定で消していた。そのため親のログ判定では、実際には作業が続いている子が作業待ち向けの声かけの送信候補になりえた。

- `keepalive_background_log`: 発言に tool_use があるときは、作業待ちの行と状態行が揃っていても作業待ちの記録として数えない。それまでの記録があればその後に動きがあったもの（`answered`）になり、無ければ記録なし（`no-transcript`）になる
- 変えていないもの: 作業待ちの行と状態行だけの発言の正常経路、記録のあとに別の発言で tool_use が来たときの拒否、画面側の検査、`skipped` の理由の語
- 追加したテスト: `tests/epic-dispatch.bats` の「a marker and a tool use in the same assistant utterance is not a send candidate」
- 戻し方: この PR の差分を戻す。記録の形は変えていないので移行は要らない
