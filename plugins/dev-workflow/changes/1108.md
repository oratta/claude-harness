# git-destructive-guard: サブエージェントから呼ばれた破壊的 git 操作は確認画面を出さずに拒否し、子を親に返す（#1108）

対話セッションでサブエージェント（子）が破壊的 git 操作を打つと、`git-destructive-guard.sh` は主の呼び出しと同じく `ask` を返して主の確認画面を出していた。親はその画面に応答できず、子が止まっていることも分からないので、主が画面を見るまでワークフロー全体が止まっていた（reviewer が scratchpad の検証用 clone を `git checkout --` で戻そうとして止まった）。

- `scripts/git-destructive-guard.sh`: payload の `agent_id` が空でない文字列なら、`permission_mode` にも `DEV_WORKFLOW_GIT_GUARD_FORCE` にもよらず `deny` を返す。`agent_id` が無い・空・文字列でない呼び出しは今までどおり（主の呼び出し）。`DEV_WORKFLOW_GIT_GUARD=off` は子でも全許可のまま
- 子への拒否理由は子向けの文面にした: 実行されない／打ち直さず、別の書き方も試さない／scratchpad の検証用 repo なら git で戻さず作り直す／それ以外は作業を止め、何を・なぜ実行したかったかを報告に書いて親に返す。確認画面と `!` の案内は書かない
- 子への拒否の回数を `${TMPDIR:-/tmp}/dev-workflow-git-guard/<sha256(session_id + NUL + agent_id)>` に数える。2 回目以降は理由文に「直ちに作業を終えて親に返す」を足し、出力のトップレベルに `"continue": false` と `stopReason` を付けて子を打ち切る（実機で、子だけが終わり親は続けると確かめた。openspec/changes/archive/2026-10-19-subagent-git-guard-deny/design.md「実機確認の結果」）。数えられないときは 1 回目として扱い、拒否は必ず返す
- `agents/reviewer.md`・`worker.md`・`gate-runner.md`: 「scratchpad の検証用 repo は git の破壊的操作で戻さず、作り直す。」を足した
- `rules/destructive-git-guard.md` の「hook との分担」節と `rules/README.md` の該当行に、サブエージェントは確認画面を出さずに拒否され、子は打ち直さず親に返ることを足した
- 受け入れること: 主が子に破壊的操作を任せた場合も子では実行できず、親か主が打つ。SendMessage で再開された子は同じ `agent_id` なので回数が再開をまたいで続く。`continue: false` で打ち切られた子の return は空になり、親には拒否理由が届かない（#1117 で扱う）
- 戻し方: この PR の差分を戻す。回数のファイルは一時ディレクトリにあり、消さなくてよい
