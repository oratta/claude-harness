# Orca 経路のエピックで、子が「用が済んだ」の印を付けたワークツリーを親が片付ける（#805）

`/develop <エピック番号>` を Orca 経路で回すと、マージされ issue が閉じた子のワークツリーが Claude のタブごと残り続け、オーナーが手で消していた。子 issue のクローズも Orca の完了通知も、「用が済んだ子」と「マージ後の動作確認を待っている子」を見分けられないので、子が自分で Orca のボードの列を決め、それを片付けの合図にした。同じ箇所を触る #459・#526・#472・#473 も合わせて直した。

- `scripts/epic-dispatch.sh` に `mark <done|waiting> <issue>` を足した。今のワークスペースの `linkedIssue` が `<issue>` のときだけ、ボードの列を `completed`（done）か `in-review`（waiting）にする。Orca 管理外と `orca` が無い環境では何もしない（`skipped`）
- `wait` に `--watch-done <N>` を足した。付けたときだけ、ポーリングごとに `orca worktree list --json` を 1 回呼び、`completed` になった子を `done <N>...` で知らせる（issue が open のままでも終わる）。位置引数の子が 0 件でもよい。一覧を読めないポーリングが 3 回続くと `error workspaces`。付けない呼び出しは今までどおりで `orca` を呼ばない。位置引数が 0 件の `timeout` は `timeout` だけを出す
- `reap <child>...` を足した。`completed`・親の `launch` が作ったワークツリー（`parentWorktreeId` が今のワークツリー）・作業ツリーがきれい・`LLM/` が無い・マージ済み PR の `headRefOid` と HEAD が一致、のすべてを通った子だけ `orca terminal close --all` → `orca worktree rm`（`--force` なし）を呼び、残ったローカルブランチは先端が HEAD と同じときだけ `git branch -D` する。外れた子は何も消さずに `kept <N> <理由>`
- develop の SKILL.md に「ループの終わり」の節を足した。worktree の片付けを提案も質問もせず（#459）、記録先が issue で PR がマージ済みなら最後のツール呼び出しとして `mark` を呼ぶ。「エピックの扱い」の Orca 経路には、`wait --watch-done`・`done` で起こされたら `reap`・`kept` の子はエピックにコメントしてオーナーに残す・開いている子が無くなったあとの待ち方・再開時の `reap` を足した。手順書から `orca terminal read` を除き、`orca` のコマンドを呼ぶのは `epic-dispatch.sh` だけにした
- `tests/epic-dispatch.bats` に `mark`・`wait --watch-done`・`reap`・SKILL.md の記述のテストを足した。「gh の stderr はエラー行の直前に出る」テストに、3 回目のポーリングの stderr だけが出ることの確認を足し（#526）、gh のスタブが本当の呼び出し回数を `(poll <回数>)` に出すようにした
- README（ルートと dev-workflow）のエピックの行で unmanned がサブエージェント方式であることを明記し（#472）、ルート README の `epic-dispatch.sh` のパスを直した（#473）。片付けの動きも 1 文足した
- 受け入れたリスク: 子が印を付けたあとに文章を書き続けると、末尾が画面に出ないまま端末が閉じることがある（会話ログは残る）。`.gitignore` の対象のうち `LLM/` 以外はワークツリーと一緒に消える
