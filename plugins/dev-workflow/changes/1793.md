# 作業待ちの子が声かけの予約文を受けたとき、一行だけ返して待ちを続ける手順を足す（#1793）

作業待ち（agent・自分の PR の CI・Monitor・Codex コマンドを 60 分以上待つ子の本体）が、親からのキャッシュ維持の声かけ（予約文）を受けたときの手順を、子の手順書に接続した。受信基盤（共通定義・ログ読取・状態フック）は #1792 で入っており、ここでは変えていない。

- `skills/develop/references/epic-keepalive.md`: 停止前に加えて作業待ちの開始前・延長前にも `references/child-cache-keepalive.json` を読む。停止中はトップレベル、作業待ちは `background` の定義を使う。固定文と完全一致する入力を通常の返事より先に分類し、受信ターンではツールを呼ばず一行だけ返す。旧停止中の受信規則（調査・作業・停止コメントを行わず待つ、非一致の返事は `epic-child-stop.md` で再開）は残した。固定文の全文は複写せず、共有定義から作る
- `skills/develop/references/child-background-wait.md`: 待ちの開始前・延長前に `epic-keepalive.md` と `background` を読む。節 3 の先頭で、完全一致する予約文を通常入力時のタイマー取消より先に分類し、元作業 ID・実行 ID・自己タイマーとその ID・初回設置時刻を保って待ちを続ける。取消・再設置や 12 時間の基点・上限の延長、作業完了・自己通知成功と扱うことはしない。非一致の入力と元作業・自己タイマーの通知は既存の手順に渡す
- `tests/child-background-wait.bats`: 両手順書の接続・先頭分類・保持対象・ツール禁止を確かめる検査を足した
- 場面予算（`tests/injection-budget.txt`・場面集合）は変えていない。`epic-keepalive.md` は重複表現を削って 1799 バイトに収めた

検証の範囲: 手順書とその契約テストまで。親の送信有効化・自己タイマーの撤去・実会話での検証は #1777 に残る。

戻し方: この PR の差分を戻す。状態ファイルや共有定義の形は変えていないので移行は要らない。
