# #1582 別セッションの git ガードを確認待ちにしない

## 変更

起動側が `DEV_WORKFLOW_GIT_GUARD_NO_ASK` を付けたセッションでは、主の破壊的 git 操作を permission mode・FORCE によらず拒否する。前後の空白を除いた空文字と `0` は印なし、それ以外は印ありとする。
拒否理由はコマンドの全文・対象・なぜ要るか・止まった理由を書いてオーナーに承認を求め、ターンを終えるよう案内する。承認後もオーナーが自分で実行し、確認画面・入力欄の `!`・チャンネルへの案内は出さない。UNATTENDED と併用した主にもこの理由を優先する。

印を付ける責務は flatmate 側の起動設定に置く。harness の `epic-dispatch.sh launch` や develop の実行モード判定は変更しない。子の一度限りの許可・拒否記録・2 回目の打ち切りは維持する。版は上げない。

`epic.md` 手順 5 には、印のある別セッションの子が拒否後に承認を求めてターンを終え、親が会話ログを読める場合に検知できることを追記した。印のない確認画面の止まりや、会話ログを読めない子の止まりは検知できない。

## 検証

bats で対象 9 種・モード・FORCE・印の値・理由文・子の拒否と一度限りの許可・手順 5 の案内を確認する。常時注入の rules と予算は変更しない。
