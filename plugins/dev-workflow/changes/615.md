# 実行役の格の上限を、Claude と Codex で同じ対応表から強制する（#615）

実行役（spec-write・implement）に最上位の格を付けない規則は、Claude 側では `agent-model-guard.sh` の Fable の文字列判定、Codex 側では規則の文書だけにあり、同じ表から来ていなかった。上限を `references/model-tier-map.json` に置き、両方の強制層がそこから判定するようにした（親エピック #616）。

- `references/model-tier-map.json`: `"role_caps": {"spec-write": "上位", "implement": "上位"}` を足した（`version` は 1 のまま）。`codex-develop.py` の `load_tier_map` は、キーが `version`・`tiers`・`executors`・`role_caps` ちょうどで、`role_caps` が spec-write と implement の 2 役ちょうど・値が 4 格のどれかのときだけ受け、それ以外は表ごと拒否する
- `scripts/tier_caps.py`（新規・標準ライブラリだけ・Python 3.9 で動く）: model 名から格を引く規則（小文字・前後の空白を除いた名前か、`-` で区切った断片が列のモデル名と一致する格のうち、いちばん低い格）と、拒否の文面の前半（役・要求された格・上限の格）を置き、`codex-develop.py` と guard の両方が使う
- `scripts/codex-develop.py request`: profile 形式・自動選択では、実際に動く entry の役が実行役のとき `executed_tier` を上限と比べ、超えたら依頼ファイルを書く前に `RuntimeError` で止める（上限まで下げない）。旧形式（`--model`）では、phase の役が実行役のときだけ表を読み、`--model` を codex の列で格に戻して判定する。表が読めなければ実行役の旧形式も止まる。実行役以外の旧形式は今までどおり表を読まない
- `scripts/agent-model-guard.sh`: `dev-workflow:worker`（spec-write・implement）と `dev-workflow:gate-runner`（implement）で `model` があるとき、guard の場所から表を読み、claude の列で格に戻して上限を超えたら拒否する。拒否理由は共有の前半に `dev-workflow:decider`・`sonnet` / `opus`・規範を足す。格に戻せない名前と `model` の省略は通す。表が読めない・壊れているときは上限の判定を飛ばし、今の Fable 判定（決める役以外の Fable を拒否）に任せる
- 挙動の変化: 旧形式で `--phase implement` / `spec` に `astra` / `gpt-6-astra` を渡す依頼は拒否されるようになった。今の表では Claude 側の拒否される組み合わせは今までの Fable 判定と同じ（`fable` / `claude-fable-*`）で、文面に役と格が入る
- `references/model-tiers.md`: 上限の置き場所と、guard と `request` が同じ表から判定することを足した
- 戻し方: この PR の差分を戻す。状態ファイルは触っていないので移行は要らない
