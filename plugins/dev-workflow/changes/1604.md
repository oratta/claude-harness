# CI 用引き継ぎの入口を接続する

通常経路の CI 見張りの開始手順から、7 冒頭の CI 用引き継ぎを参照するようにした（F1）。develop の failed 後の W 起動／再開手順と handover.md を読む場面から、最新 CI 用引き継ぎが可なら「起動／再開前の無効化と再許可」に従って不可を投稿し、投稿成功後だけ指示する手順へ接続した（F3）。

handover.md の「修正後の待ちへ戻る前」には、今回の W が無関係と判断して push せず工程完了を返した後の next --unrelated 前も含め、今回の工程完了に基づく新しい可を投稿すると明記した（F4）。以前の完了／停止確認、push・idle、オーナーの続行指示だけで可へ戻さない規則を維持する。

関係 Bats は各入口を切り出して接続を検査する。実エージェントの起動や記録内容の真正性・読解ミスの保証は範囲外。軽い経路の関係確認・複数チェックの無関係判定・新しい停止確認許可経路は扱わない。起動時予算は入口への追記で増えたバイト数だけ増やし、既存文の圧縮や重複整理は行っていない。
