# model-switch-recache-notice.sh: 本体の読み込みに失敗しても標準エラーを出さず、検査を足す（#867）

通知を出す・出さないの定義は変えていない。#869（PR #914）で本体の渡し方を `-c` に変えたあとに残っていた取りこぼしを塞いだ。

- `scripts/model-switch-recache-notice.sh`: ファイルサイズ上限が小さい環境（`ulimit -f 0` など）では、ヒアドキュメントの一時ファイルに書く時点で SIGXFSZ が飛び、シェルごと exit 153 で終わっていた。SIGXFSZ を無視して書き込みの失敗に落とし、本体が空なら何も出さず exit 0 で終わる（標準エラーも空。spec の「標準エラーに何も書いてはならない」に沿う）
- `tests/model-switch-recache-notice.bats` に 4 件足した
  - スクリプトが `environ`・`getenv`・`sys.argv` を使わない（コメント行を除く grep が exit 1）
  - python3 に渡る引数と環境変数に payload の中身が載らない
  - `PATH=/usr/bin:/bin`（macOS 標準の python3 3.9.6）で通知が出る。`/usr/bin/python3` が無い環境では skip せず、理由を出して既定の python3 で確かめる
  - `ulimit -f 0` で本体を読めなくても、無出力・exit 0・標準エラー空

確かめたこと（macOS、`/usr/bin/python3` は 3.9.6）: bats 30 件がすべて通る。`trap` を外すと `ulimit -f 0` の件は落ちる。

戻し方: この PR を revert する。
