# エピックの途中で足された子は、親が起動する前に主に聞く（#1647。エピック #1474 の子）

flatmate のエピックで、親は子が見つけた範囲外の問題から起票した子を、主に聞かずに並行で起動した。主が一度出した「全部やってよい」も、後から足された子に使われた。この変更で、主に頼まれていない子に主の知らないうちにトークンが使われないようにした。

## 足したもの

- `skills/develop/references/epic.md`「別セッション方式とサブエージェント方式に共通」に項目を 1 つ足した。親が起動してよいのは回し始めの子と主が承認した子だけで、回している途中で足された子は起票と依存の紐付けまでで止め、起動前に主へ 1 問で聞く。承認はその発言の時点で挙がっていた子にだけ効く
- `skills/develop/references/epic-loop.md` の状態表の段落に、起動を主に聞いている子のステータス `未起動（主の判断待ち）` を足した
- `tests/develop-skill.bats` に文書の検査を 1 つ足した
- `openspec/changes/archive/2026-11-23-ask-owner-before-launching-added-children/`（仕様化成果。要件 3 つを足す）
- `tests/develop-epic-scene-budget.txt` の 11 場面の予算を実測値に上げた。`epic.md` に足した項目を 739 バイトから 525 バイトに、`epic-loop.md` に足した括弧書きを 114 バイトから 87 バイトに縮めたが、足した分を丸ごと消しても main の時点で `nested-stop`・`nested-delegated` が 6 バイト超えていた（#1782）ので、縮めるだけでは収まらない。新しい値は各場面の実測値そのもの（1.1 倍の余白の検査にも収まる）。これで #1782 も直る
