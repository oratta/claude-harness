# #1857 G001: Claude 役セッションへの hook 強制層

- 環境の `DEVELOP_ROLE` が空でなく、有効な `agent_id` がない役は、自身の `transcript_path` で途中計測する。既存の計測式・モデル別閾値・通知と強制停止を再利用し、実在する subagent のログ選択を優先する。
- 印なし・空の主と既存 subagent の動作を維持する。主へ実際に印が誤継承された場合は役として扱う。

- マーカー付き役の SessionStart は既存の subagent-budget 本文を JSON で配送し、probe・メモリ検知・親向け昇格節を省く。明示 scope の本文形式と既存 SubagentStart 配線は維持する。

- Stop に既存の停止ガードを追加する。役の自身ログにある背景起動と running 台帳の積集合だけを拒否し、回数を `role-sessions/<session_id>.count` へ分離する。既存の拒否上限・削除・見送り規則を維持する。

- 役の破壊的 git と既知の自己許可経路を、FORCE・NO_ASK・UNATTENDED・明示 off より先に deny する。役は子の permit・拒否回数・記録を扱わず、コマンド全文・対象・理由を本体に返し、承認後は主が実行する。Write / Edit / NotebookEdit の許可置き場保護も同じ役へ拡張する。

G001 は hook fixture の検証範囲。起動スクリプト・PR トークン集計・実機の `claude -p` 記録は後続 G002 で扱う。


## G002: 独立役の起動・集計とテスト境界

- 前景 launcher は担当 / profile role / 解決済み model を照合し、検証済み CLI・plugin で有限 turn の独立 Claude 役を起動する。session と自身の外部ログを登録し、再開前に `subagent-context.sh --file` を測る。終了理由・役の宣言・所有 group の回収を分離する。
- PR 計測へ外部 `--session-records` を追加した。独立役は `claude_sessions` に出し、従来の `agent_count` を保つ。既存ログとの重複、Codex 本体の進行中 rollout と古い数値コメントの重複を除き、欠測を診断する。measure wrapper も同じ登録を渡す。
- runner の Bats 子環境でのみ `DEVELOP_ROLE` を解除し、外側の役の hook を維持する。三つの起動分岐と既存 shard / 残留検査を回帰確認する。
- 実機確認用の `claude-role-live-check.py` と専用 reference を追加した。作業ツリー版を `--plugin-dir` で読み、一時 repo・会話ログ・証跡をリポジトリ外へ置く。
- 実装 worker は実機 Claude を起動していない。tasks 5.1–5.3 の実効ツール / 孫禁止・turn 上限 / 回収・実ログ集計・G001 git deny は本体が確認し、[issue #1857](https://github.com/oratta/claude-harness/issues/1857) にコマンド・観測値・外部証跡を記録する。未確認を合格と扱わない。

## G002: 本体の実機確認結果

- [初回記録](https://github.com/oratta/claude-harness/issues/1857#issuecomment-7238471692): Claude Code 2.1.332、作業ツリーの plugin を `--plugin-dir` で使用。capability は verification approved。normal は工程完了・cleanup ok。resume-cap は同じログの超過で context_cap・exit 2・CLI 不起動となった。
- 同記録の git-deny は、役の `git reset --hard HEAD` を G001 の PreToolUse が実行前に拒否した。一時 repo の HEAD・status・対象内容は前後一致（unchanged true）。役は打ち直さず工程中断で返した。
- [取り直し記録](https://github.com/oratta/claude-harness/issues/1857#issuecomment-7238538538): 背景の子を作った turn 上限ケースは max_turns で工程中断し、cleanup ok・残留なし・外側の対照は生存。通常の lifecycle ケースは背景の子ありで timeout 終了し、同じく回収できた。
- SIGKILL・INT・TERM は cleanup ok・残留なし・外側の対照生存だが、signal が背景起動より前に届いた。強制停止時の背景の子は偽 CLI のテストで確認、実機は未作成。確認スクリプトの lifecycle 全体は exit 1 であり、実機の全面合格とは扱わず後続ゲートの判断へ引き継ぐ。
- PR 集計の手計算・追記・重複排除は fixture で検証済み。上記実機記録には実 rollout / 実 Claude ログの集計照合結果はなく、実機で照合済みとは扱わない。tasks 5.1–5.3 のチェックは本体の finish 指示による記録整理で、これらの未確認点を解消した宣言ではない。
