# 文面検査の bats がロケール未設定で空振りするのを直す（#662）

main で落ちていた文面検査の bats は、スキル文書の文言が退行したのでもテストが古いのでもなく、**ロケール依存**が原因だった。`[^。]*` のような正規表現は、`LANG` 未設定（C ロケール）の環境では日本語の 1 文字を 1 文字として扱えず、「、」「の」などを含む区間に一致しない。UTF-8 ロケール（`LC_ALL=en_US.UTF-8`）では 4 件とも通る（無人サイクルの Bash は `LANG` 未設定）。

- `plugins/dev-workflow/tests/develop-skill.bats` の `setup()` に `export LC_ALL=C.UTF-8` を足した（develop の loop 1 件）
- `plugins/worktree/tests/skill-safety.bats` も同様（wt-clean 1 件。変更記録は `plugins/worktree/changes/662.md`）
- `plugins/dev-workflow/tests/pr-review-gate-skill.bats` の draft 2 件は、オーナーのマージ待ちの PR（#637 が同じ bats と `stages/pass.md` を、#174 が同じ bats を変更中）と変更ファイルが重なるため、この PR では直さない。同じ `setup()` への 1 行追加で直る（issue #662 に記載）
