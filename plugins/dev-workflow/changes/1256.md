# usage-probe: 429 の待ちを残して鮮度と間隔だけを外す --refresh を足す（#1256）

使用量を手で取り直すとき（genetta-inc/flatmate#1717 の「使用量を取り直す」ボタンなど）は、これまで `USAGE_PROBE_STALE=0 USAGE_PROBE_INTERVAL=0` を付けて `usage-probe.sh` を叩くしかなかった。`USAGE_PROBE_INTERVAL` は 429 の待ち（間隔 × 2^(連続回数-1)、上限 1 日）の基準でもあるので、0 にすると待ちも 0 になり、待ち中のアカウントまで叩いてしまう。そのため flatmate 側は、待ち中のスロットが 1 つでもあると取り直しを諦めていた（親のエピックは genetta-inc/flatmate#1656）。

- `scripts/usage-probe.sh`: 引数 `--refresh` を足した。付けたときは、スロットごとの実行条件のうち鮮度（セッション記録の `observed_at` と snapshot の `fetched_at` が `USAGE_PROBE_STALE` より古いこと）と前回の試行からの間隔（`USAGE_PROBE_INTERVAL`）を外す。429 の待ちとオフ（`enabled: false`）は残す
- 429 の待ちの長さは `--refresh` の有無で変わらない（同じ `USAGE_PROBE_INTERVAL` を基準に倍々、上限 86400 秒）。待ち中のスロットは叩かず、試行状態ファイルのそのスロットの試行時刻と連続 429 回数も変わらない。待ちが明けたスロットは鮮度にかかわらず叩く
- 指定は環境変数ではなく引数にした。環境変数は子プロセスに引き継がれ、hook など別の probe 呼び出しにまで漏れて毎回取り直すことになるため。`--refresh` はその 1 回の実行にだけ効く
- 引数なしの呼び出し（SessionStart の hook など）の振る舞い、ロック、試行の記録、スロット単位の fail-open、snapshot の形は変えていない。別の probe が走っている最中に `--refresh` で呼ぶと、今までどおり何もせず exit 0 で終わる。`--refresh` と `--print-slots` 以外の引数は今までどおり無視する
- flatmate #1717 の呼び出しを `--refresh` に切り替えるのは flatmate 側の別 issue
- 戻し方: この PR の差分を戻す。試行状態ファイルと snapshot の形は変えていないので移行は要らない
