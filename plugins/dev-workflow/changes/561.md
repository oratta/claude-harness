# SubagentStop hook: 停止を通した時点でカウンタファイルを削除する（#561）

PR #560（issue #264）のゲートレビューで見つかった non-blocking 指摘の切り出し。`subagent-stop-guard.sh` は拒否回数のカウンタファイルを、上限到達で通した分岐でしか削除していなかった。`running` が空で通す分岐と `pending` が空で通す分岐（＝理由文どおりに正しく待ってから停止した場合）ではファイルが残るため、次のターンで再び未完了の背景タスクを残して停止しようとすると、前回までの拒否回数の続きから数え始めてしまい、正しく従うサブエージェントほど後詰め（`MAX_BLOCKS` 回までの猶予）を早く使い切っていた。

- `counter_dir` / `counter` の算出を `running = {...}` の直前に移し、`running` が空になって通す分岐と `pending` が空になって通す分岐の両方で、`sys.exit(0)` の前に `try: os.remove(counter)` / `except OSError: pass` を追加した。`counter_dir` が未作成のままの早期リターンでは `os.remove` が `FileNotFoundError`（`OSError` のサブクラス）を投げるだけで、既存の `except OSError` でそのまま無視される
- 上限到達で通す分岐の既存の削除処理は変更していない。3 分岐とも「停止を通す時点でカウンタを消す」という同じ形に揃えた
- `openspec/specs/dev-workflow-subagent-waiting/spec.md` の要件「停止の拒否は上限回数までの後詰めにする」を、「上限に達して通した時点で削除する」から「停止を通した時点（上限到達・未完了なしのいずれでも）で削除する」に直した
- `openspec/changes/archive/2026-09-27-subagent-wait-stop-guard/specs/dev-workflow-subagent-waiting/spec.md`（PR #560 の archive 記録）と `plugins/dev-workflow/changes/264.md` の同趣旨の記述も揃えた
- `tests/subagent-stop-guard.bats` に、`running` が空になる分岐・`pending` が空になる分岐それぞれについて、1 回拒否させてから正しい入力で通し、カウンタファイルが削除されたことと、その後もう一度未完了のまま停止させると拒否理由が `1/3` から数え直すことを確認するケースを追加した（2 件、計 36 件）
