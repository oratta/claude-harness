# 主への確認を論点の有無で書き分け、論点の無い確認を短く即答できる形にする（#1209）

主への確認が決まった型の項目を全部埋めた形で届き、何を決めればよいかが読み取れなかった。決まりで聞いているだけで主が考える点の無い確認でも、ゲートの宣言の書式がリスク内容の作文を求め、問いが「リスクを許容するか」になっていた。論点（主が持っていて自分が持っていない観点を足すと結論がよくなる点）を定義し、論点あり／論点なし（決まりで聞いている）で書き分けるようにした。

- 正本 `~/.claude/output-styles/readable.md` の節 3 と短い版 `rules/communication-style.md` の 3 番目: 論点の定義と書き分けを足した。1 行目は OK すると何が起きるかを中身で書いた質問にする、番号で物を指さず番号は末尾の URL にだけ置く（主語かどうかを問わない）、困りごとが無いときは書かない、受け入れるリスクは推奨を選ぶことで新たに生じるものだけを書く、論点なしの確認は 3〜4 行に収める。例を論点ありの 1 つと、2026-10-22 の実例 2 つを論点なしで書き直したもの（各 4 行）にした
- pr-review-gate `declarations.md` の手順 3: 「主のリスク許容が必要」の雛形の、`主のリスク許容が必要。` のあとの空行に続く行を「論点なし — 分類に当たったので決まりで主の OK が要る」と「論点あり — 新たに生じるリスク」の 2 つの形にし、分類に当たっただけのときにリスク内容を作文しない。「この形式以外で主にリスク承認を求めない」と「これを許容するか」を外し、主への依頼文は正本の型で書くとした。宣言の行頭の `リスクなし` / `主のリスク許容が必要`、`対象 HEAD:` 行、`- 該当する観点:` などの項目、`主の回答: 許容` の照合は変えていない
- pr-review-gate `stages/hold.md`: 宣言が論点なしのときは、依頼も論点なしの 3〜4 行で書き、宣言を写さない
- develop `references/epic-child-stop.md`: 子の停止の記録の `主に聞く理由:` に論点の有無を添え、決まりで聞いているだけなら `論点なし（決まりで聞いている）` と書く。`受け入れるリスク:` は推奨を選ぶことで新たに生じるものだけにした。7 項目の名前と並びは変えていない
- develop `references/epic.md` の手順 8: 「親経由のリスク許容の依頼」を、子の記録の推奨を主に OK してもらう報告として正本の型で書く形にした（手続きの言葉で問わない）。答え方の行に、親のタブでこの報告の直後に打つことを書く点は残した（子のゲートの照合に使うため）
- `references/ci-watch.md` の、マージ待ちの子の記録の例: `主に聞く理由:` に論点なしを、`受け入れるリスク:` に新たに生じるものだけを書く形にした
- 仕様: 既存の 3 capability（owner-question-style・casting-catalog・dev-workflow-develop）と pr-review-gate の要件に触れるので、当初の「仕様化しない」を「仕様化する」に切り替え、openspec の change `owner-question-ronten` に仕様の差分を書いた
