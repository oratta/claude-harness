# reread_pct が Bash の読みも数えるようにする（#651）

`subagent-context-audit.sh --by-role` の `reread_pct` は Read ツールの `file_path` だけを数えていた。W はファイルをほぼ Bash（`sed -n` / `cat` / `head` / `tail`）で読むので、値が常に 0.0 になっていた。Bash の `command` からこれらの引数のファイルを取り出し、前任・後任の両方の「読んだファイル」に加える。照合はこれまでどおりベースネーム一致。

- `scan_full` が `Bash` の `command` を `|` `;` `&&` `||` 改行で区間に分け、先頭語が `sed`（単独の `-n` があるものだけ）・`cat`・`head`・`tail` の区間の引数を数える。スクリプト・オプション値・リダイレクト（`>` `<` を含む語）・グロブ・`$` を含む語は数えない
- 近似であり、`sed -ne`・`xargs cat`・`grep` / `awk` / `less`・heredoc 本文などは数え漏れ／誤計上を許容する。取りこぼしを塞ぎ切ることは完了条件にしない
- Read だけのトランスクリプトの値は変わらない
- 測り直すときは `--refresh` を付ける（TTL 内のキャッシュは変更前の算出を返すため）。`docs/usage-audit.md` にも書いた
- openspec change `bash-read-reread-pct` で `dev-workflow-execution-strategy` の Requirement「`reread_pct`」を更新
