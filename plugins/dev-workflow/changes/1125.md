# owner-reply-check: チャンネル経由の主の発言を、許可された送信者に限って数える（#1125）

住人の環境では、主が Discord で「許容する」と答えても会話ログの行が `origin.kind: "channel"`（しかも `isMeta: true`）で残るため、`owner-reply-check.sh` が主の発言として数えず、pr-review-gate の「会話で受領」が通らなかった。チャンネルにはオーナー以外も書ける（実物の会話ログに別のユーザーの発言があった）ので、送信者が許可された ID のときだけ数える。

- `scripts/owner-reply-check.sh`: `origin.kind` が `"channel"` の行は、本文の先頭の開きタグ（Claude Code がチャンネルプラグインの通知の meta から組み立てる `<channel source=… user_id=…>`）の `user_id` と `origin.server` の組が、新しい環境変数 `OWNER_REPLY_CHANNEL_SENDERS`（`<server>=<ID>` を空白かカンマで並べる）にあるときだけ数える。これらの行は isMeta を見ず（実物が `isMeta: true` のため）、タグを外した中身を本文として比べ、`MATCH:` にも中身を出す。開きタグの形が崩れている・属性名の重複・`source` と `origin.server` の食い違い・閉じタグで終わらない行と、1 行にチャンネルの塊が 2 つ以上ある行（中身に `<channel …>`・`</channel>` のタグがある、または content が 2 つ以上の text 要素の配列）と、`meta` の値の `"` と改行で開きタグを早く閉じて `user_id` を偽った行（中身に `user_id="` があるか、中身のどこかの行が `">` で終わる）は数えない。設定の値の形が崩れていたら exit 2
- `tests/owner-reply-check.bats`: チャンネルの行の入力を 2026-10-20 時点の実物の形で足した（通す・送信者違い・別のチャンネルの同じ ID・設定なし・送信者を読めない 9 つの形・中身の偽タグ・1 行に塊が 2 つ以上・要素 2 つ以上の配列・開きタグを早く閉じる偽装・queue-operation の行・origin の無い isMeta の行・3 つの使い方・設定の誤り）
- `openspec/changes/archive/2026-10-20-owner-reply-check-channel-sender`: 要件の差分（archive して `openspec/specs` に反映した）
- 変えていないもの: `origin.kind: "human"` の行と `origin` の無い行の判定、呼び出し側（pr-review-gate・develop）の手順と出力の形
- 受け入れること: `OWNER_REPLY_CHANNEL_SENDERS` を設定しない環境では、今までどおりチャンネルの発言は数えない。住人の環境で Discord の返事を通すには設定が要り、その決まり（置き場・主の ID の確かめ方）は #1126 で決める（design.md の「#1126 への引き継ぎ」）
- 戻し方: この PR の差分を戻す。状態や形式は変えていない
