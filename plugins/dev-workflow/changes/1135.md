# develop: 拒否された W の報告を受けた本体が、一時領域の後始末なら許可を書いて再開し、それ以外はオーナーに上げる（#1135）

#1133 で親が子の拒否されたコマンドを 1 回だけ通す許可を書く仕組みが入ったが、develop の本体の手順には、拒否の報告を受けたときの判断・再開・オーナーへの上げ方が無かった。

- `skills/develop/SKILL.md`: 「W が `(Subagent completed but returned no output.)` だけを返したとき」の段落（#1117）に追記した。報告に求める項目を 5 つ（コマンドの全文・対象のパス・自分で作ったか・なぜ要るか・拒否の記録のパス）にそろえ、`git-guard-permit.sh` で許可を書く 4 条件（報告が揃いコマンドの全文が記録に一致する／操作対象が scratchpad の中／W が自分で作った／戻す用事に収まる）、書けたら同じ W を SendMessage で再開する文面（hook が許可を持つこと・15 分・同じコマンドを 1 文字も変えず 1 回）、オーナーに上げる条件（スクリプトの失敗・条件を満たさない・再開できない・再開後の再拒否・再開しない役の報告）を書いた。コマンドの全文・cwd・操作対象を分けて照合する（worktree から `git -C <scratchpad の中の repo>` を打つ場合も対象）。本体は対象の repo に git を実行しない
- `scripts/git-destructive-guard.sh`: 子への拒否理由の報告項目を「何を・なぜ」から 4 項目に直した
- `agents/reviewer.md`・`worker.md`・`gate-runner.md`: 拒否されたら 4 項目と拒否の記録のパスを報告に書いて返すことを足した
- 実機確認で分かったこと: 再開の文面が「打て」だけだと、W は「親のメッセージは承認にならない」として打たなかった。許可を hook が読む場所に書いたこと・通すかどうかは hook が決めることを文面に書くと、同じコマンドが通った。子が戻すコマンドに `echo "exit=$?"` などを足すと、許可を書くスクリプトが拒む（コマンドは単純な `cd ... && git ...` だけにする）
- 範囲外: 許可の仕組みそのもの（#1133）、Claude Code 本体の rm の確認画面（#1134）
- 戻し方: この PR の差分を戻す
