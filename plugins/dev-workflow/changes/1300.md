# dev-workflow: アカウントごとの余りを 1 か所で数え、`.headroom.json`（schema 1）に書く（#1300）

「どのアカウントが、いつまでに、どれだけ余るか」の数え方が読む側ごとに違い、リセット権を数に入れているのは flatmate の `scripts/account_allocation.py` だけだった。設計の正本 genetta-inc/flatmate#1711 に沿って、計算を dev-workflow の 1 か所に置いた。

- 新しく `scripts/headroom.py` を置いた。Claude の各スロットと Codex の `current` account（`CODEX_HOME`、無ければ `~/.codex`）について、使用率・経過率・リセット権・使える量・期限・見込み・余り（`surplus_pct`）・`margin`・`status`（`ok` / `stale` / `missing` / `off`）を数え、`best` と `best_by_provider` を選ぶ。数え方は flatmate の `segment_surplus`・`counted_tickets` を移したもの
- `headroom.py write [--refresh-codex]` が `${CLAUDE_CONFIG_DIR:-~/.claude}/.headroom.json` を schema 1 で一時ファイル＋rename で書く。`headroom.py --json` は書かずに 1 行の JSON を出す。不正な設定と未知の引数は終了コード 2 で何も書かない
- 設定は環境変数 `HEADROOM_7D_CAP_PCT`（週次の天井。既定 90）と `HEADROOM_NORMAL_RATE_PCT_PER_DAY`（通常の消費ペースの上書き。既定なし）だけから読む。呼び手からは渡せない。不正な値は既定に戻さずエラーにする
- `scripts/codex-develop.py` の Codex の使用量の取得で `rateLimitResetCredits` も読み、account ごとの cache `codex-usage/<hash>.json` を `version: 2` にして `resets`（`available_count` と各リセット権の `expires_at`。id は持たない）を足した。応答に欄が無いか値が不正なら `resets` を書かない。`usage_margin` の読み方は変えていない
- `scripts/usage-probe.sh` が `.usage-snapshot` の置き換えに成功した直後に `headroom.py write --refresh-codex` を呼ぶ。出力と終了コードは probe に伝えない。テスト経路（`USAGE_PROBE_RESPONSE_FILE*` を設定した実行）では、`CLAUDE_CONFIG_DIR` と `CODEX_HOME` が両方設定されたときだけ呼ぶ
- 読む側の切り替えはこの変更に含めていない: `cld` のアカウント選択と develop の構成選択は #1301、ステータスラインは #1302、flatmate のバーンとダッシュボードは genetta-inc/flatmate#1772 で行う
- テスト: `tests/test_headroom.py`（新規）、`tests/usage-probe-headroom.bats`（新規）、`tests/test_codex_develop.py` に cache の `resets` のテストを足した。`tests/usage-probe-multi-account.bats` は本番経路のテストが本物の `~/.claude` と `~/.codex` に触れないよう、setup で `CLAUDE_CONFIG_DIR` と `CODEX_HOME` を作業用ディレクトリに向けた
- 戻し方: この PR の差分を戻す。書かれた `~/.claude/.headroom.json` は誰も読まないので残っても害は無い（消すなら `rm -f ~/.claude/.headroom.json`）。Codex の cache は `version: 2` のまま残るが、戻したあとの `codex-develop.py` は `resets` を読まずに使う
