# develop: コンパクト直後に SKILL.md を読み直させ、待っている間のコンパクトの下限を読み直しの費用込みで計算し直す（#1217）

コンパクトのあとに Claude Code が貼り直すのは、入口の `commands/develop.md` と小さい最近読んだファイルだけで、`skills/develop/SKILL.md` の本体は要約に置き換わる。要約の上では読んだことになっているので、エピックの親や子が手順を忘れたまま進んでいた。

- `scripts/develop-compact-reread.sh`（新規）と `hooks/hooks.json`: SessionStart（matcher `compact`）で、その会話で develop を呼んでいたときだけ「`SKILL.md` を offset と limit で 2 回に分けて読み直し、自分がエピックの親か子かを記録先の issue から確かめ直してから続ける」を `additionalContext` に差し込む。差し込む文には `SKILL.md` の絶対パスを書く
- develop を呼んだかの判定は、会話記録の jsonl で行う。数えるのは次の 3 つ: assistant の Skill 呼び出し（`dev-workflow:develop`）、user の発言（文字列か、一覧の text のブロック）にある `<command-name>/dev-workflow:develop</command-name>`、前のコンパクトのあとの `invoked_skills` の記録。名前空間の無い `develop` は数えない（プラグインのコマンドは `/develop` と打っても `/dev-workflow:develop` と記録されるので、名前空間の無い名前で拾えるのは利用者の別のスキルやコマンドだけ）。形の違う行は 1 行ずつ飛ばし、走査は続ける。SessionStart(compact) の時点では、今回のコンパクトの `compact_boundary` と `invoked_skills` はまだ書かれていない（`claude -p` で確認）。そのため `invoked_skills` だけでは 1 回目のコンパクトを拾えない。文中で名前に触れただけのものや、`codex-develop` のように名前に develop を含む別のスキルは数えない
- 判定できないとき（stdin が JSON でない・会話記録が無い・`CLAUDE_PLUGIN_ROOT` が空・python3 が無い）は何も出さない。常に exit 0
- 待っている間のコンパクトの下限（`CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS`、子・親とも 120,000）は変えていない。読み直しは 1 回約 39k トークンで、#1039・#1046 の集計の控えめの想定で R に足した 40k（issue やコメントの読み直しの分）とは別にかかる。両方を足した想定は計算し直しておらず、#1264 で計算する。控えめの想定でも 120,000 は最良と差が小さく、既定の 200,000 より安い。`references/reply-after-idle.md` の根拠の節に 1 行足した。計算は https://github.com/oratta/claude-harness/issues/1217#issuecomment-6359110216
- 受け入れること: 読み直しを差し込んだ会話は、再開のたびに約 39k トークンを読み直す。満タン側のコンパクト（直前の会話が 45 万以上）のあとにも差し込む
- 戻し方: この PR の差分を戻す。状態ファイルは作らないので、移行は要らない
