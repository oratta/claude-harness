# アカウント登録簿の一覧・追加・オン・オフをコマンドにする（#977）

アカウントを足す・止める・戻す操作を、`accounts.json` の手編集ではなくコマンド 1 つで行えるようにした。新しいスクリプト `scripts/accounts.sh` を足した。`schema` は `1` のまま。

- `accounts.sh list`: `<id>` `<label>` `on|off` `<securestorage>`（`null` は `-`）をタブ区切りで宣言順に出す。登録簿は変えない
- `accounts.sh add <id> [--label <label>]`: 認証情報の置き場所 `<CLAUDE_ACCOUNTS_HOME>/<id>`（既定 `$HOME/.claude-accounts`）を作って末尾に登録し、stdout にログインするコマンドを 1 行出す（パスは単一引用符で囲む）。同じ id は exit 2。`CLAUDE_ACCOUNTS_HOME` が絶対パスでなければ exit 2
- `accounts.sh off <id>` / `on <id>`: `enabled` を `false` / `true` に書く（`on` はキーを消さず `true` を書く）。`label`・`securestorage`・順序・未知のキーは変えず、認証情報の置き場所も消さない。登録簿に無い id は exit 2
- 書き換える前に登録簿を `<登録簿>.bak` へ 1 世代だけ控える。続けて実行すると最初の状態の控えは残らない
- 登録簿が JSON として読めない、または `accounts` が配列でないときは、何も書かず exit 1
- README の手編集の案内（`plugins/dev-workflow/README.md`、`plugins/statusline/README.md`）を、このコマンドの手順に改めた

## なぜ別スクリプトにしたか

`accounts-init.sh` は「居るシェルの `CLAUDE_SECURESTORAGE_CONFIG_DIR` の実値を登録し、同じ id は上書きする」手段で、`add`（置き場所を新しく作り、同じ id は拒否する）とは既存 id の扱いが正反対になる。同じスクリプトに入れると引数の有無で意味が切り替わるため、拡張せず別にした。`accounts-init.sh` とその既存テストは変えていない（design D1）。引数は `--id` ではなく位置引数の id にした。`on` / `off` / `add` は対象 id が必須の 1 操作だから（D2）。

## `accounts-init.sh` との差

`accounts` が配列でない登録簿の扱いが違う。`accounts-init.sh` は JSON として読めないときだけ exit 1 で、読めても `accounts` が配列でなければ空の登録簿として扱い、そのまま上書きする。`accounts.sh` は既存のスロットを黙って失わないよう、トップレベルがオブジェクトでない・`accounts` が配列でないときも何も書かず exit 1 にする（D5）。

## 戻し方

利用者側は、オフにしたアカウントを `accounts.sh on <id>` で戻す。直前の状態に戻したいときは `<登録簿>.bak` を `accounts.json` へ戻す。コードはこの PR の差分を戻す（`accounts.sh` を消しても、書かれた `enabled` は #976 の読み手がそのまま読む）。
