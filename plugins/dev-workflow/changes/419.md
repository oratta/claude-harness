# Codex 消費コメントの取得失敗を「計測できない」に合流させる（#419）

PR トークン上限の計測で、記録先の `Codex 消費:` コメントを集める `gh api` が通信障害や認証エラーで失敗すると、空か途中までの記録ファイルがそのまま集計され、Codex 分が抜けた合計が exit 0（上限以内）として返っていた。仕様が定める「計測できない（exit 1）なら記録先に通知する」経路にも入らなかった。

- 収集を `scripts/codex-records.sh --repo <owner>/<repo> --out <file> <番号>...` に切り出した。番号ごとに取得（`gh api --paginate --slurp`）と抽出（`jq`）の終了コードを検査し、全番号で成功したときだけ `<file>` を書いて exit 0 を返す。1 つでも失敗したら exit 1 を返し、途中までの記録も前回の計測で作った同名のファイルも残さない
- `skills/develop/SKILL.md` の計測手順は、`codex-records.sh` が exit 0 のときだけ `pr-token-budget.sh` を呼ぶ形にした。失敗したら集計を呼ばず、exit 1（計測できない。理由「Codex 消費コメントを取得できなかった」）として記録先に 1 サイクル 1 回だけ通知する
- `pr-token-budget.sh` は GitHub を読まないまま変えていない
