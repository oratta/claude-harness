# pr-review-gate: 段 C の親の取得を別リポジトリの親と取得の失敗で扱い分ける（#1011）

PR #1002 が足した段 C は、記録先 issue の親を `--jq .number` で番号だけ取り、取れなければエピックに属さない PR として飛ばしていた。親が別リポジトリにあると無関係な issue をエピックとして候補探しに渡し、レート制限・5xx・通信断の失敗でも段 C が飛ばされて、エピックの完了条件に効く指摘が参考コメントか「捨てる」に流れた。

- `skills/pr-review-gate/stages/triage.md`: 段 C の親の取得を、番号とリポジトリ（`repository_url`）の両方を取る形にし、候補探しの前に済ませるとした。「エピックに属さない」と読むのは出力に `HTTP 404` を含むときだけで、それ以外の失敗は 1 回だけやり直し、だめなら仕分けの PR コメントに書く。その場合は段 C を飛ばし、候補探しは `--epic` を付けず、「範囲で成り立つ」に当たった指摘は段 D・段 E を通さずエピックの外の新しい issue にする。親が別リポジトリのときは、エピックの本文と `## 条件の答え` を親のリポジトリで読み書きし、候補探しは `--epic` なしで全候補を `other` と読み、子に足す操作は親の `sub_issues` に対して行う。これに合わせて、候補探しの `--epic` の箇条、表の段 D・段 E の行、段 E の段落に例外を 1 句ずつ足した。ほかの段の言い回しは変えていない
- `openspec/specs/dev-workflow-pr-review-gate/spec.md`: 同じ文を、change `pr-review-gate-stage-c-parent-fetch` の delta（4 要件の MODIFIED）で直した。archive で main の spec に入る
- `tests/pr-review-gate-skill.bats`: 段 C の検査に新しい語句を足し、triage.md と spec（change の delta があればそれ、なければ main の spec）の文が同じ語句を持つことを確かめる項目を足した
- 触らなかった所: `reviewer-brief.md`・`gate-runner.md`・develop の `SKILL.md`（受け入れ条件 1 が「段 C に書く」で、段 C が親の取得の正本になるため）。すでに親の子である issue を子に足す確かめもしていない
- `skills/pr-review-gate/stages/triage.md` と `openspec/specs/dev-workflow-pr-review-gate/spec.md`（同じ語句）: 候補探しの親番号の `--exclude <エピック番号>` と、打ち切り時の `--epic <エピック番号> --children-only` の再実行を、親の取得に成功し親が `$R` にあるときに限った。親が別リポジトリのとき・親の取得が失敗し続けたときは再実行せず、初回の候補をすべて `other` と読む（検索語が `$R` の同じ番号の issue の子を探してしまうため）。`tests/pr-review-gate-skill.bats` に両方が同じ語句を持つ検査を足した（PR レビューの指摘）
