# develop: unmanned の W の質問を本体が Discord へ代理送信する（#594）

worker の tools に Discord の道具が無いのに、仕様の発明や曖昧な分割判定で W に直接送信を求めていたため、質問できず停止したり、判断を補って進めたりする余地があった。

- W は質問文・理由と `needs-approval` を return に含め、記録先にラベルと経緯コメントを残して作業を止める。仕様の発明では埋めた決定を列挙し、割り方が曖昧な場合は子 issue を作らない。MCP・CLI とも W の直接送信は禁止する。
- 本体（憲法のメイン自身）が return の質問を Discord へ代理送信し、`needs-approval` のままサイクルを終了する。実行モード表・worker 指示書・分割判定の正本をこの責務分担に揃えた。
- `tests/develop-worker-question-proxy.bats` で直接送信禁止・質問 return 契約・本体の送信手順・tools 不変を固定した。否定文脈の許容例と直接送信指示の拒否例も検査する。実際の Discord 配送は検査しない。
- 起動時予算は SKILL.md のみ 80987 → 81319 バイト（+332）。既存の工程・モード説明を削る案を確認したが、この変更とは別の契約を削らず、質問の受け取り・代理送信・終了を明示するため実測に合わせた。常時注入の予算とバージョンは変更しない。
