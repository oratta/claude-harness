# develop: 待っている間の自動コンパクトの閾値を親も 120,000 にそろえる（#1116）

親（エピックを回すセッション）の閾値は 100,000 としていたが、子の 120,000 とそろえた。差は小さく、開いたまま放置されるセッションでは最悪の想定で損の小さい 120,000 が合う。値が 1 つになるので、主の起動コマンド 1 か所で入れられる。

- `skills/develop/references/reply-after-idle.md`: 閾値の表の親を 120,000 にし、付ける場所を「主が起動するセッションは、主の起動コマンド（例: `cld`）が未設定のときだけ `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS=120000` を入れる」に直した。根拠の節に、親の 120k の費用の増減（−24.7M・−10.4M。#1039 の集計の値）とそろえた理由を足した
- `tests/epic-dispatch.bats`: 規則のファイルの検査を、親も 120,000・「未設定のときだけ」の記述あり・`=100000` と 100,000 が残っていない（冒頭の Claude Code の下限は「10 万」と書く）、に置き換えた
- `openspec/changes/idle-compact-parent-120k`: 要件の差分（archive で `openspec/specs` に反映する）
- 変えていないもの: 子の閾値（120,000）、`launch` の動き、分ける条件
- 受け入れること: 主の起動コマンドが値を入れていない親は、これまでどおり既定の 200,000 で動く。このリポジトリは主の起動コマンドを持たない
- 戻し方: この PR の差分を戻す。状態や形式は変えていない
