# 親が通す基準の「戻せる」に CI の再実行を含め、通る例を広げる（#1244）

エピックの親が、無関係なテストの時間切れやランナーの混雑で CI をやり直すだけの止まりを、毎回同じように通せるようにした。flatmate の同じ種類の 4 件の止まりで、親の判断が分かれていた（1 件は通し、1 件は「戻せるを満たさない」で主に上げた）。原因は「戻せる」の文言が commit の取り消しや設定の戻しだけを書いていて、commit も設定も変えない CI の再実行が当たるか読み手で揺れたこと。マージ待ちの経路は原因ではなかった（4 件の停止の記録の読み方は #1244 のコメントにある）。

- `references/parent-pass-criteria.md`: 条件表の「戻せる」の行に、同じ操作をやり直しても何も残らない操作（CI の再実行・ジョブの打ち直し）も戻せるに含める、を足した。通る例の「Mac が空いてからの CI の再実行」を「CI の再実行（無関係なテストの時間切れ・ランナーの混雑・待って打ち直すだけで済むもの）」に広げ、失敗が PR と無関係と言い切れなくても原因の切り分けを通す条件にしない、と添えた。例の節の前置きに、この例を #1244 で 2026-10-19〜20 の 4 件をもとに広げたことを足した。「主の側の情報が要らない」の行は、再実行が当たらないと今の文言で読めるので変えていない
- `openspec/specs/dev-workflow-develop/spec.md`: 要件「親が通してよい範囲の基準を 1 つのファイルに置く」の通す条件・例の文と、シナリオ 1 件を同じ内容に合わせた。仕様化判断は「する」（通し方: 文言合わせ）で、change `parent-pass-ci-rerun`（`## MODIFIED Requirements` だけ）を archive して入れた
- テスト: `tests/epic-dispatch.bats` の基準ファイルのテストで、旧い例の文言が残っていないこと、「戻せる」の行に CI の再実行とジョブの打ち直しが書かれていること、CI の再実行の例に原因の切り分けを通す条件にしないと書かれていること、例の節の前置きに #1244 の出どころがあることを確かめるようにした
- 変えなかったもの: `references/epic.md`（マージ待ちの子の段落は原因ではない）、`scripts/stop-judge.sh`。常時注入の固定分は変えていない
- 入れなかったもの: 見張りの道具の再実行回数の上限と基準の関係（#1252）、推奨が「ランナーの状態を確かめてから再実行」のときの読み方（#1253）
- 戻し方: この PR の差分を戻す（文書とテストだけ）
