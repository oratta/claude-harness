# epic-dispatch のテスト: orca と tmux を既定で「必ず失敗するスタブ」にする（#1508）

`tests/epic-dispatch.bats` の `setup` は `gh`・`git`・`sleep`・`sysctl` だけをスタブにしていて、`orca` はテストごとに `make_stub orca` を呼んだときだけ PATH に置かれていた。`make_stub orca` を呼び忘れたテスト（例: `dispatch` を通して `launch` を足したとき）は、PATH の `/usr/bin:/bin` 側に実物の `orca` や `tmux` があれば、本物のワークツリーやセッションを作りうる状態だった。

- `tests/epic-dispatch.bats`: ヘルパー `guard_stub` を足し、`setup` で `orca` と `tmux` を、テスト自身の PATH の先頭（`$BATS_TEST_TMPDIR/guard-bin`）に置く。呼ばれたら呼び出しを `$STUB_LOG` に残し、stderr に印を出して exit 99 で終わる。`dispatch` は PATH を `$STUB_BIN:/usr/bin:/bin` に作り直すので、この守りは `dispatch` を通した呼び出しには見えず、「PATH に orca が無い」テストと `make_stub orca` / `make_stub tmux` を呼ぶテストの動きは変わらない（守りは `dispatch` を通さず `$SCRIPT` を直接呼んだときに効く）
- `tests/epic-launch-tmux.bats` は確認済みで変更なし。`setup` で `tmux`・`git`・`orca`・`sleep` をすべてスタブにしていて、`orca` は既に `exit 99`（呼び出しをログに残す）で同じ形
- 製品コード（`scripts/`）・仕様は変えていない。version は上げていない
- 戻し方: この PR の差分を戻す
