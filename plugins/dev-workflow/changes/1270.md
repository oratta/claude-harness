# parent-pass-criteria: 上限で止まった子へのやり直しの返事に、needs-approval を外すことと見張りの開始コメントを足す（#1270）

CI の見張りのやり直しの上限で止まった子に、親が追加のやり直しを許したあと、子が見張りに正しく戻れなかった（PR #1268 のレビュー指摘 F1）。

- `skills/develop/references/parent-pass-criteria.md` の節「CI の見張りのやり直しの上限で止まった子」の「返事」の段落に、見張りに戻るまでの順序を書いた。`ci-watch.md` 2 の重複の確認（別のセッションが見張り中なら何もせず主に伝える）→ `gh run rerun --failed` → `needs-approval` を外す → `CI 見張り開始:` の投稿 → 再開手順。`needs-approval` を外すのは手順 7 の経路で止まった子で、付けたままだと、やり直しが通ったあと見張りは待たずにオーナーへマージを頼んで終わり、auto-merge も止まる（`ci-watch.md` 6 の表の `escalate` の行と「`ready` を受けたあと」の 1）。ただし外す前に PR の events で、最後の `needs-approval` の labeled が止まる前の最新の `CI 見張り開始:` のコメントより前なら、オーナーが付けたものなので外さず主に上げる。開始の記録なしに戻ると別のセッションが見張りを重ねうる（同じ「`ready` を受けたあと」の、親の返事が届いたときの段落）
- `tests/epic-dispatch.bats` の該当の @test に、返事の段落に「`needs-approval` を外す」「重複の確認」「`CI 見張り開始:` の投稿」「外さず」の 4 つの記述があることの検査を足した
- `ci-watch.md` と `scripts/` は変えていない
