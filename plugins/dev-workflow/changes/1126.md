# develop: 画面を見ている人のいないセッション向けの実行モード channel を足す（#1126）

flatmate の住人は tmux に常駐する対話のセッションで、オーナーは Discord だけを見ている。住人がオーナーから開発を頼まれて develop を回すと、interactive モードの「AskUserQuestion で聞く」と「新しいセッションで `/develop <記録先>` と一緒に返事を渡す」案内に流れ、誰も見ていない画面で止まっていた（住人は AskUserQuestion を禁止されている。2026-08-07 に約 12 時間止まった）。主とチャンネルだけで会話する 3 つ目の実行モード channel を足す。

- `skills/develop/SKILL.md`: 「実行モード」の表に channel の行（工程は interactive と同じ (0)〜(4)）を足し、モードの決め方（`--unmanned` → 印 `DEV_WORKFLOW_UNATTENDED` かチャンネルのメッセージでの依頼なら channel → interactive。開始コメントに `実行モード: <モード>（<理由>）`）・channel の聞き方（依頼の届いたチャンネルに送ってターンを終える）と読み替えの規則（develop から読む 8 文書の「interactive は AskUserQuestion」を channel ではこの聞き方に読む）・リスク許容（`OWNER_REPLY_CHANNEL_SENDERS` の有無で `チャンネルの返事の確認: 可 / 不可` を開始コメントと G の起動指示に書き、不可なら PR のコメントを案内する）・主への発言（すべてチャンネルに送り、1 行目は `主がすること:` の 3 つの形）を書いた。保留の案内・新しいセッションでの再開・レビューの周を主に聞くとき・(4) の保留・エピックの回し方（channel は `route` を呼ばずサブエージェント方式で、別の Claude Code セッションを起こさない）に channel の扱いを足した
- `commands/develop.md`: モードは SKILL.md の決め方で決める（既定は interactive）に直し、引数の分岐 ②⑤ と issueify フォールバックのヒアリング・承認は channel ではチャンネルに送ってターンを終えることを書いた
- `skills/pr-review-gate/stages/hold.md`: 手順 6-3 の依頼文を実行モードで分けた。interactive は今までどおり、channel は「このチャンネルで記録先の番号を添えて返事をすれば続ける」を案内し、`チャンネルの返事の確認:` が `可` でないときだけリスク許容を PR のコメントで受ける
- `tests/develop-channel-mode.bats`: 上の文面の確かめ（AskUserQuestion に触れるファイルが読み替えの列挙から漏れていないことを含む）
- `openspec/changes/develop-channel-mode`: 要件の差分
- 変えていないもの: interactive と unmanned の振る舞い、develop の description（常時注入の予算）、W・R1・G の指示書（`references/roles/gate-runner.md` を含む）

## flatmate 側で要る設定

住人の環境で使うには、flatmate 側で次を置く（harness 側では入れない）。

- 住人を起動する `boot.sh` に印 `DEV_WORKFLOW_UNATTENDED=1` を付ける（genetta-inc/flatmate#1663）。印が無くても、オーナーが Discord で頼んだ開発はチャンネルの依頼として channel になる
- 住人のセッションの環境（`settings.json` の `env` など）に `OWNER_REPLY_CHANNEL_SENDERS=<origin.server>=<オーナーの ID>` を置く（#1125）。無いとリスク許容のたびにオーナーが PR にコメントすることになり、開始コメントに `チャンネルの返事の確認: 不可（OWNER_REPLY_CHANNEL_SENDERS が無い）` が出る
- 住人の CLAUDE.md に「`#<番号>` を添えたチャンネルの返事を受け、その記録先に `引き継ぎ: 主の返事待ち` があれば、develop を記録先 `<番号>` で起動して続ける」案内を置く。住人のセッションが再起動で入れ替わったとき、返事を受けたセッションが develop を読み込むきっかけになる

## 確かめ方

受け入れ条件 3 つ目（住人で、オーナーの依頼 → develop → 質問をチャンネルで受けて回答 → PR → ゲート合格まで 1 回通した記録）は、住人がインストール済みの main のプラグインを読むのでマージ後にしか取れない。マージ後に flatmate #1638 のリハーサルで確かめ、記録を付けてから #1126 を閉じる。
