# CI 見張りの修正担当を引き継ぐ

通常経路の CI 見張りで、本体が前任 W を把握しなくても、PR に残した成果・対象・手渡し許可の根拠から implement 担当へ手渡せるようにした。情報不足や対象不一致、手渡し不可なら修正せず、共有の escalate と同じ停止先（エピックの子は親）へ報告する。

既存 W の再開と新しい W の起動の前に古い許可を無効にし、今回の工程完了または停止確認後だけ再許可する。HEAD や差分が変わる前に本体が交代しても、古い許可で二人目を起こさない。軽い通し方の新規 spec 起動と、同じ PR・状態ファイルによる継続は維持する。

CI 用引き継ぎが可である間は、ゲート failed 後のレビュー修正で W を起動・再開する場合も事前に不可へ更新する。CI fix 後の古い可から二人目を起こす経路を防ぐ。
