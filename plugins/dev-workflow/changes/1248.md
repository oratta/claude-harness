# develop: エピックの親が見張りをやめてよい条件を 1 か所に集め、やめる前に主の返事待ちの子を確かめる（#1248）

エピック #1038 の親が「6 時間の待ちが 3 回変化なし」という手順書に無い理由で見張りをやめ、主の返事待ちの子を残したまま止まった。親が待ちをやめる条件が手順 2・3・4・7 と手順 4 の `timeout` に散っていて、「それ以外ではやめない」が書かれていなかった。

- `skills/develop/references/epic.md`「回し方」に **待ちをやめてよい条件** の段落を足した。やめてよいのは、完了（`clear` まで）・後回しの子だけが残る報告・`error`/`failed` の報告・片付け待ちの子だけを待つ `wait` の `timeout`・主の指示の 5 つだけで、`timeout` が続いた、変化が無い、主に上げた、主の返事待ちの子が残っている、は理由にならないと書いた
- やめる直前の確認を書いた。開いた子で `wait --interval 0 --timeout 0 --watch-stopped`（受けていない止まりを拾う）と `pending-owner`（受けたまま再開していない子）を呼び、`needs-approval` の子も見る。止まった子が見つかれば、やめずに手順 4・8 で処理して待ちに戻る。`error`・`failed` で止まるときは確かめるだけで待ちに戻らず、見つかった子を止まる報告に書く。開いた子が 0 件（全子が閉じたとき・片付け待ちの子だけを待つ `wait` の `timeout`）なら、子を渡さずに呼ぶと使い方を出して exit 1 で終わるので呼ばず、報告に「確かめる子が無かった」と書く。止まった子なしとみなすのは、`wait` が `timeout`（exit 2）で、stderr に `unreadable state record` が無いときだけで、それ以外は確かめられなかった子と stderr を報告に書く
- 手順 4 の `timeout` でやめる箇所は、この確認を通してからやめる形にした。手順 5 と手順 8 には、`timeout` が続いても・主に上げたあとも待ちをやめない旨の参照を足した（手順は 8 本のまま）
- スクリプトは変えていない。既存の `wait --timeout 0 --watch-stopped` と `pending-owner` で確かめられる
- `tests/develop-skill.bats` に文面のテストを 5 件足した
- 見送ったもの: 親を起動し直す仕組み。主が見送ると決め、記録した（https://github.com/oratta/claude-harness/issues/1248#issuecomment-6359084052 ）。直したあとも親が見張りをやめる事例が出たら決め直す
- 残したもの: openspec の develop の spec に「`timeout` で報告して待ちをやめる」とだけ書かれ、この条件と食い違う箇所がある。spec はこの PR では直さず、別の issue で合わせる（https://github.com/oratta/claude-harness/issues/1263 ）
