# session-tripwires: SessionStart の注入を hookSpecificOutput の形で出し、開始時の文脈に実際に入れる（#1673）

`scripts/session-tripwires.sh`（SessionStart hook）は、昇格トリップワイヤー・Fable 残量モード・メモリの見直しの `[memory]` の 1 行を `{"additionalContext": …}` のトップレベルで出していた。Claude Code（v2.1.327 で確認）が SessionStart の JSON 出力から文脈に足すのは `{"hookSpecificOutput": {"hookEventName": "SessionStart", "additionalContext": …}}` の形だけで、トップレベルの形は会話ログの hook の記録に残るだけだった。このため、どのセッションの開始時（startup / clear / compact）にもこの 3 つはエージェントに届いておらず、#1654 で足した「`patches:` の issue が閉じたら知らせる」も見えていなかった。

- `scripts/session-tripwires.sh`: 通常の出力（`TRIPWIRES_SCOPE` が `subagent-budget` 以外）を `hookSpecificOutput` の形にした。`hookEventName` は常に `SessionStart`（登録先が SessionStart だけなので固定値。stdin を読んで切り替えない）。本文の中身・並び・fail-soft の条件と、`subagent-budget` の本文テキストの出力は変えていない
- `scripts/prompt-tripwires-refresh.sh`（UserPromptSubmit。プラグインが途中で更新されたときの再注入）: `session-tripwires.sh` の出力から本文を取り出す箇所を `hookSpecificOutput.additionalContext` に変えた。出力側だけ直すと本文が取り出せず、再注入が何も言わずに止まるため。トップレベルの形は読まない（同じ `CLAUDE_PLUGIN_ROOT` の 2 本を組で呼ぶので版が食い違わず、両方読むと古い形への退行をテストが見逃す）
- 仕様: `dev-workflow-escalation-tripwires` の要件「SessionStart hook がトリップワイヤーを常駐注入する」の出力の形と、要件「SubagentStart hook が dev-workflow の役に運用情報を注入する」の「`subagent-budget` 以外のときの出力は従来と変えない」を、新しい形に合わせて直した（change session-start-hook-output-shape）
- テスト: `tripwire-hook.bats`・`memory-tripwire.bats`・`usage-probe.bats`・`subagent-start-context.bats` の本文の取り出しを新しい形にし、`hookEventName == "SessionStart"` とトップレベルに `additionalContext` が無いことを確かめる検査を足した

影響: これまで届いていなかった本文が、全セッションの開始時に実際に文脈へ入る。文面は最初から載る前提のもので、量は変えていない。`tests/injection-budget.bats` の測定対象（rules / CLAUDE.md / output-styles / description）に hook の出力は入らないので、予算値は変わらない。

確かめ方: `claude --plugin-dir <worktree>/plugins/dev-workflow` で新しいセッションを起動し、会話ログ（`~/.claude/projects/<プロジェクト>/<セッション>.jsonl`）の `SessionStart:startup` の hook に、文脈に入った印の attachment があること、セッションに聞くと `## 昇格トリップワイヤー` の節が文脈にあると答えることを見る。

戻し方: この PR の差分を戻す。控えや状態のファイルは増やしていない。
