# モデル別の文脈上限・強制停止を計測経路へ接続する（#1800、3 分割の 2 本目）

PR #1804 で追加した共通処理を、文脈計測 CLI と途中計測 hook へ接続した。#1800 の change 2（`model-context-threshold-wiring`）に当たる。

- `scripts/subagent-context.sh`: 採用した usage と同じ assistant レコードの `message.model` で文脈上限を解決する。`--cap` の優先、環境変数の共通解釈、0 の許容、未知・不明モデルの fallback と再検証診断を扱う。解決失敗は stderr の理由と stdout のエラー JSON・exit 1 で知らせる。
- `scripts/context-tripwire.sh`: 同じ計測レコードのモデルから文脈上限・強制停止値を解決する。両値の正数条件、既存の通知・拒否と Bash 全件拒否、理由付き fail-open を保つ。診断は stderr に出し、同梱の再検証手順を絶対パスで案内する。
- 両スクリプトの Bats に、モデル・上書き・境界・不正な設定や同梱部品・別 cwd と配布先の回帰ケースを追加した。
- `skills/develop/references/decision-criteria.md` の文脈2経路を接続済みの説明へ直した。OpenSpec の主仕様を同期し、change を archive した。

change 3 には累計上限の接続（`pr-token-budget.sh`・そのテスト・`pr-token-budget.md`・`decision-criteria.md` の累計部分）と、利用手順 `token-thresholds.md` の文脈・累計両方の未配線注記の更新を残す。change 3 のマージまで利用手順の文脈上限の注記だけが古い状態になる点は、#1800 の文書分担の補正で合意済み。

共通処理・表の数値と版は変えない。戻す場合はこの PR の差分を revert する。状態ファイルやデータの移行は無い。

## ゲート一周目の差し戻しでの修正（change `fix-context-threshold-notification`）

ゲート一周目で、再検証の通知が stderr だけでは再開されないサブエージェント本人に届かない（exit 0 の hook の stderr は Claude に届かない）と指摘された。あわせて、共通処理のロードに成功したあとで解決 API が欠けると出力契約が壊れる実装漏れも見つかった。

- 通知経路を変更した。`context-tripwire.sh` は、利用する文脈指標に再検証が要るとき、stderr の診断に加えて `hookSpecificOutput.additionalContext` に再検証通知を出す（要求モデル・根拠モデル・対象指標・手順の絶対パス。本人は作業を止めず、自分で再検証も始めず、次の return に再検証が要る旨を書く）。診断だけでは締め・拒否をしない。閾値内は通知だけの JSON、cap 超の PostToolUse は既存の締め通知の本文に別段落で追記、hard 超の PreToolUse は既存の拒否の本文を変えず同じ出力へ追加する。再検証が要らない閾値内は従来どおり stdout 空。CLI は stderr と測定 JSON のまま。通知の到達は Bats の出力検査と公式の配送規則を根拠とし、実機では観測していない。
- 共通処理が欠けたときの扱いを変更した。API の欠損・非 callable・呼出し時の通常例外・必須キー欠損は `resolver_unavailable` として、CLI は error 文字列の 1 行 JSON と exit 1、hook は stdout 空・exit 0（traceback なし）にする。`invalid_table` / `invalid_override` の分類は変えない。
- 両 Bats に通知 JSON の解析検査と API 欠損 4 種の検査を足した。`decision-criteria.md` の文脈計測の説明も同期した。主仕様は 2 capability とも同期済みで、change は `openspec/changes/archive/2026-11-24-fix-context-threshold-notification/` に archive した。
