# モデル別の文脈上限・強制停止を計測経路へ接続する（#1800、3 分割の 2 本目）

PR #1804 で追加した共通処理を、文脈計測 CLI と途中計測 hook へ接続した。#1800 の change 2（`model-context-threshold-wiring`）に当たる。

- `scripts/subagent-context.sh`: 採用した usage と同じ assistant レコードの `message.model` で文脈上限を解決する。`--cap` の優先、環境変数の共通解釈、0 の許容、未知・不明モデルの fallback と再検証診断を扱う。解決失敗は stderr の理由と stdout のエラー JSON・exit 1 で知らせる。
- `scripts/context-tripwire.sh`: 同じ計測レコードのモデルから文脈上限・強制停止値を解決する。両値の正数条件、既存の通知・拒否と Bash 全件拒否、理由付き fail-open を保つ。診断は stderr に出し、同梱の再検証手順を絶対パスで案内する。
- 両スクリプトの Bats に、モデル・上書き・境界・不正な設定や同梱部品・別 cwd と配布先の回帰ケースを追加した。
- `skills/develop/references/decision-criteria.md` の文脈2経路を接続済みの説明へ直した。OpenSpec の主仕様を同期し、change を archive した。

change 3 には累計上限の接続（`pr-token-budget.sh`・そのテスト・`pr-token-budget.md`・`decision-criteria.md` の累計部分）と、利用手順 `token-thresholds.md` の文脈・累計両方の未配線注記の更新を残す。change 3 のマージまで利用手順の文脈上限の注記だけが古い状態になる点は、#1800 の文書分担の補正で合意済み。

共通処理・表の数値と版は変えない。戻す場合はこの PR の差分を revert する。状態ファイルやデータの移行は無い。
