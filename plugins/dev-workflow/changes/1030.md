# 自動マージの処理が親の判断の印を受け取り、聖域接触だけで付いた human-merge を外す（#1030）

エピックの子の PR のうち聖域に触れて `human-merge` が付いたものは、主が手でマージするまで止まっていた。主は 2026-10-15 に「マージ条件そのものに触れるものを除き、親が合理性と危険の低さを見てマージしてよい」と決めた。親が直接マージすると CI green・SHA ピン・緊急停止・マージ直前の取り直しを素通りするので、親は印を残し、マージするかは今までどおり自動マージの処理が決める形にした。

- `auto-merge.yml`（展開先と原本）に `MERGE_CONDITION`（マーカー `merge-condition-paths`。`SACRED` の部分集合）と、判定の関数 `parent_merge_judgment`（マーカー `parent-merge-judgment`）を足した。印は `parent-merge-approved` ラベルと、1 行目 `親のマージ判断: 可`・`親が見た HEAD: <今の HEAD>` の行を持つ OWNER・MEMBER・COLLABORATOR のコメント。`human-merge` を外すのは、印があり、ほかの見送りラベルが無く、聖域に触れていて、マージ条件そのもののパスに触れていないときだけ。取得の失敗はマージしない側に倒す
- claude-harness の `MERGE_CONDITION` は `.github/workflows/`・`plugins/dev-workflow/skills/pr-review-gate/`・`plugins/dev-workflow/templates/auto-merge/`。原本の既定は `.github/workflows/` だけで、README では任意の差し替えとして書いた（必ず差し替える 3 点は変えていない）
- ジョブの `if:` が `parent-merge-approved` の付与でも走る。イベント種は labeled のまま
- マージ直前の取り直しで同じ判定をやり直す。マージ後のコメントに親の判断で外したことと印のコメントの URL を書く
- `docs/auto-merge.md`（展開先と原本）に条件・印の書式・調べ方と、親の判断からも外したいときは `human-only` か `needs-approval` を付けることを書いた
- この PR は `.github/workflows/` に触れるので、親の判断でも外れず主がマージする
- 原本を使う他のリポ（flatmate など）は、原本を展開し直すまでこの経路を持たない（印を付けても見送られたまま）
- 戻し方: この PR を revert する。戻したあとは印が無視され、`human-merge` 付きの PR は今までどおり見送られる
