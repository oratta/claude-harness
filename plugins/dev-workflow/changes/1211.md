# 作業者・レビュアー・ゲートの担当が全体のテストを手元で回さず CI に任せる（#1211）

作業者の指示書は、対象リポジトリの CI の検査コマンドをすべて手元で実行するよう求めていた。claude-harness ではこれが `scripts/test.sh`（直列で 1 回約 40 分）の全体実行になり、#1177（PR #1208）では開始から CI の決着まで約 2 時間 20 分のうち約 2 時間が全体のテストの待ちだった（作業者が 3 回、レビュアー・ゲートの担当・本体が各 1 回）。同じ中身を CI は 4 つの組に分けて 5 分ほどで回し、ゲート合格後に本体が CI を見張って落ちたら直しに回す仕組み（`references/ci-watch.md`）も既にあるので、全体は CI に任せる。

- `skills/develop/references/roles/worker/implement.md`「全経路共通の大原則」: CI の定義から拾った検査を種類ごとに扱う形にした。lint・型検査などの静的検査は手元で実行する（変えたファイルに当てられるなら当てる）。テストの全体実行とビルドは手元で実行せず CI に任せ、代わりに変えたファイルに関係するテスト（足した・変えたテスト、変えたファイルのパスかファイル名を含むテストを `git grep -l` で探したもの、テストランナーの選ぶ機能の結果）だけを回す。PR・push で全体のテストを回すジョブが無いリポジトリでは、今までどおり手元で全体を回す。守備範囲の段落の「最後の防波堤は G による CI 結果の確認」は、合格後の CI の見張りに直した
- 同じファイルの (3a) の return に、関係するテストを探したコマンドと、CI に任せた検査とその CI のジョブ名を足した
- `skills/pr-review-gate/stages/reviewer-brief.md` 手順 2-1: レビュアーは報告を信用せず再実行する姿勢を保ったまま、再実行を関係するテストと lint に限る。全体のテストは作業者の結果か CI の結果を証拠にし、どちらも無ければ証拠が無いことを要約に書く
- `skills/pr-review-gate/stages/pass.md` 手順 4: ゲートの担当は全体のテストを手元で回さず、対象 HEAD の CI の結果を証拠にする。結論がまだ無いときや既に落ちているときは、その状態（run の URL）と合格後の CI の見張りで確かめる・直しに回すことを書いて進み、成功とは書かない。auto-merge 未配備のリポで残す「マージは人間の操作待ち」の 1 行には、CI が失敗か未決着ならその状態と、見張りが結論を出すまでマージしない旨を添える
- `scripts/test.sh` の並列化は範囲に入れなかった。作業者・レビュアー・ゲートの担当のいずれも手元で全体を回さなくなり、並列化で縮む待ちが残らないため。手元で全体を回したい人は、今のままでも `TEST_SHARD=k/N` を別々の端末で起動すれば同じことができる
- 受け入れること: 変えたファイルを別のスクリプト経由で間接的に読むテストは関係するテストとして拾えず、CI で初めて落ちることがある（合格後の CI の見張りが直しに回す）。auto-merge 未配備のリポでは、CI が落ちたまま passed が付いている時間がある
