# develop 手順書の版を入口で確認する

- 記録先確定直後・仕様化判断と編集前に、実際の読込元を取得した main と内容で比較する。第一親履歴に一致する古い版だけ停止し、未知の内容は理由を記録して続行する。
- commit 済みの候補には元 worktree・読込元・HEAD・指紋・記録先に拘束したマージ前の印を発行できる。印はテスト成功の証明ではない。
- 比較元不在・取得失敗・履歴不足は記録先へ投稿して続行する。投稿失敗は本文を結果に保持し、本体が次の記録機会に代理投稿する。
- guard も呼出規定も無い導入前キャッシュを、本変更だけで強制検査することはできない。同期機構の追加は含まない。

- SKILL 導入前・削除中の履歴は照合から外して第一親探索を続ける。印の発行先が共有 git-common-dir になる clone 本体は拒否する。
- Draft PR 経路の W 起動時に実際の読込元 root を渡し、投稿失敗時は本文全文と記録未完了を既存 return で本体へ返す。
