# 公開側のリポジトリ向けの禁止語検査を共有スクリプトとして足す（#1207）

公開側のリポジトリにオーナー固有の名前が混ざっていないかを調べる検査を、dev-workflow の共有スクリプトとして足した。これまでは flatmate の `scripts/ship-check.sh` の中にだけあり、Harness 側が同じ検査を作り直すと辞書の書式と判定がずれて片方だけで漏れるため。エピック genetta-inc/flatmate#1722 の子。

- `scripts/forbidden-words-check.sh`（新規）: ファイルの一覧を標準入力、`--root`・`--dict`（複数可）・`--allow`（複数可）・`--name`・`--count-file` を引数、`FORBIDDEN_WORDS_NO_GH` を環境変数で受ける。本文とパス名を固定文字列・大文字小文字無視で照合し、違反を 1 件 1 行で標準エラーに出す（終了コード 0 / 1 / 2）。違反の文面と出す順序は `ship-check.sh` の現行のまま
- allow は 2 種類の行を持つ。`<path>:<語>:#<issue番号>`（OPEN の間だけ有効。flatmate の既存の書式のまま）と、`<path>:<語>:=<行に含まれる固定の文字列>`（期限なし。その文字列を含む行の当たりだけ許し、パス名の当たりは許さない。後続の change が #1168 の許可リストを載せるため）
- `docs/forbidden-words-check.md`（新規）: 呼び出しの形・辞書の書式・allow の 2 種類と使い分け・検査の保証の範囲
- `tests/forbidden-words-check.bats`（新規）: 38 件。gh は PATH 先頭のスタブで差し替える
- 常時注入の固定分は増えない（スクリプトと文書だけ）。`.github/workflows/` は触っていない

確かめたこと: flatmate の親ワークツリーの実際の辞書・allow・出荷ファイル 201 本を渡すと、`ship-check.sh` と同じく違反 0 件・終了コード 0。違反を仕込んだ fixture（本文・パス名・期限付き allow・書式違反・未使用・CLOSED の gh スタブ）では、標準エラーの違反 13 行が `ship-check.sh` と文面・順序とも一致し、`--count-file` の 13 は `ship-check.sh` の集計行の 13 と一致した。
