# pr-review-gate: 切り出すと答えた止める指摘の置き場所と、保留の解除の G が読むファイルをそろえる（#1016）

PR #1002 の follow-up。主が「切り出す」と答えた止める指摘の置き場所で、「必ず follow-up issue にする」と「段 C の表のとおり（既存の子の受け入れ条件に足す）」のどちらに従うかが割れ、保留の解除の G は `gate-runner.md` の表に無い `stages/triage.md` を読めなかった。

- `stages/triage.md`: 追跡の義務を「必ず issue で追跡する（新しい issue を作るか、段 C の表のとおり既存 issue の受け入れ条件に足す）」に直した。「follow-up issue に切る」は新しい issue を作る場合と既存 issue で受ける場合の両方を指すと定め、既存 issue で受けたときも PR コメントには「follow-up issue に切った」と書いて URL を添えることにした（合格処理の G が数えるため）
- `references/roles/gate-runner.md`: 時点ごとに読むファイルの表の保留の解除の行に、切り出しの確認に「切り出す」と答えられたときは加えて `stages/triage.md` の置き場所の段落・候補探し・段 C の節を読む、と足した
- spec（`dev-workflow-pr-review-gate`・`dev-workflow-develop`）とテスト（`pr-review-gate-skill.bats`・`develop-roles.bats`）を同じ PR で揃えた
- 戻し方: この PR の差分を戻す。`stages/hold.md` と `stages/pass.md` は変えていない
