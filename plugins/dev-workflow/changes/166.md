# pr-review-gate: 実装とドキュメント文字列の整合確認を合格の必須条件にする（#166）

テストの成功と受け入れ条件の実行の証拠があれば合格していたので、実装と説明文（JSDoc・`--help` の usage・README・エラーメッセージ）が食い違ったまま `agent-review:passed` が付き、auto-merge を配備したリポではそのままマージされていた。

- `stages/pass.md` の手順 4 を `4-1. 振る舞いの確認`（それまでの本文）と `4-2. ドキュメント文字列の整合確認` に分けた。4-2 はすべての PR（通し方とレビュー重量によらない）で行い、`git grep -n` の結果を HEAD SHA 付きの PR コメント `## ドキュメント文字列の整合確認` に残す
- 手順 5 の合格前の実測の見出しを 3 つから 4 つにした。通過の必須点は 4 点のままで、整合確認は③動作確認の証拠に含まれる
- この PR が変えた振る舞いの説明が食い違っていれば、G は `agent-review:failed` と行 `取り直し: 説明の整合（周に数えない）` を返す。この取り直しはレビューの周に数えず、原因分類は `段 A だけ（昇格なし）`
- レビューの指摘のうち説明の食い違いは、止めない指摘の振り分け表の段 A（この PR で直す）に当たる。2 周目の終わりに残っても別の issue にせず、手順 4-2 で確かめる
- 前からある食い違い（この PR が変えていない振る舞いの説明）は不合格にしない。言い換えの説明と対象リポの外の文書は拾えない
- ゲートの手順が増えた分、`tests/gate-reading-budget.txt` の読む量の予算を実測値に上げた
- 戻し方: この PR の差分を戻す
