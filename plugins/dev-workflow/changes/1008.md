# accounts-command.bats: add の既存スロット保持・認証情報の保持・初期値のテストを足す（#1008）

`accounts.sh` が将来変わったとき、仕様の SHALL を破る変更（既存スロットを消す・認証情報の置き場所を消す・既定の label や `schema` を書かない）をテストが落として検出できるようにした。PR #1001（#977）のレビュー指摘 P3-F1・P3-F2・P3-F3 への対応。テストだけの変更で、`accounts.sh` の振る舞いは変えていない。

- 足した: 空でない登録簿への `add` のテスト。`.bak` が実行前の登録簿とバイト一致し、`accounts[:-1]` が元と同じで、末尾が `{id, label, securestorage}` であることを見る
- 足した: 登録簿が無い状態から `--label` なしで `add` したとき、label が id になり `schema` が 1 で書かれることを見るテスト
- 替えた: `off`/`on` が認証情報を消さないテスト。`accounts.sh add b` で作ったスロット自身の置き場所（`${CLAUDE_ACCOUNTS_HOME}/b`）が `off` → `on` のあとも残り、中のファイルも残ることを見る（以前は `write_registry` の `/x/b` ではなく別の場所を見ていた）
- 確かめたこと: `accounts.sh` の複製に次の改変を入れると、新しいテストが落ちる。先頭挿入、既存スロットを全部消して足す、`off`/`on` でスロットの置き場所を `rmtree`、同じく `rmdir`（例外を握りつぶす形を含む。空の置き場所を消す改変は、空のままの `off`/`on` の段で落とす）、label 既定値を書かない、`schema` を書かない
- 戻し方: この PR の差分を戻す。実行時の挙動は変わらない
