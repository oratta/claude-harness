# develop の候補探しに `--exclude <エピック番号>` と打ち切り時の子だけの再実行を足す（#1516）

PR #1507 が pr-review-gate の候補探し（`stages/triage.md`）に足した 2 つを、develop の本体が範囲外の問題を振り分ける候補探しにも足した（#1507 の独立レビューの指摘 F-8）。

- `skills/develop/SKILL.md` と `openspec/specs/dev-workflow-develop/spec.md` の候補探しの項: 記録先がエピックに属するときは `--exclude` にエピックの番号も渡す（エピックの本文にファイル名が書かれていると、エピック自身が `other` の候補に返るため）
- 同じ項: 出力に `(15 件で打ち切り。ほかにも一致あり)` が出たパスがあり、エピックに属するときは、そのパスだけ `--epic <エピック番号> --children-only` で再実行して子の候補を足す。「1 回だけ」の規則の例外で、打ち切られたパスごとに 1 回を超えない。再実行が失敗したときの扱いは `triage.md` の候補探しの段落に従う（文面は重ねて書かない）
- spec に 2 つのシナリオを足した
- SKILL.md の例外の括弧は「（打ち切られたパスの再実行だけ例外）」とした（指す先の無い「下の 2 つ目」を使わない）。`tests/develop-skill.bats` に、この項の文言を検査するテストを 1 件足した
- change は `openspec/changes/archive/2026-10-31-develop-candidate-search-epic-exclude/`。spec 本文は先に直接変更したので、archive は `--skip-specs` で行った
- `triage.md` と `review-issue-candidates.sh` は変えていない。`--epic` を親が `$R` にあるときだけ付ける件（PR #1513 のレビュー指摘）はこの変更の範囲外
- 戻し方: この PR の差分を戻す。移行は要らない
- `tests/develop-startup-budget.txt` の `skills/develop/SKILL.md` の予算を 81962 から 82426 に上げた（候補探しの項が 464 バイト増えたため。理由書きは詰め、受け入れ条件の 2 点と `triage.md` への参照だけを残した）
