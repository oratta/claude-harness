# develop の W の指示書を索引・共通・段のファイルに分ける（#556）

W（develop の作業担当）は 1 回の起動で仕様づくり・実装と検証・仕上げのどれか 1 つしかしないのに、どの段でも `skills/develop/references/roles/worker.md`（13,416 字）を全部読んでいた。pr-review-gate を段のファイルに分けた #553 と同じ形で、W が 1 回に読む指示書を共通の部分とその段のファイルだけにした。

- `skills/develop/references/roles/worker.md` を索引にした。段の表（`spec` / `implement` / `finish` と読むファイル）と旧節から移し先への対応表だけを持ち、手順の本文とコードブロックを持たない
- 手順の本文を `skills/develop/references/roles/worker/` の 4 本に移した。全段で読む `common.md`（本体が渡すもの・W がしないこと・昇格トリップワイヤー・コンテキスト上限と手渡し）、`spec.md`（記録先の用意・仕様化判断と記録・分割判定・仕様化する場合）、`implement.md`（(3a) 実装＋verify）、`finish.md`（(3b) archive＋PR＋仕様宣言）
- 本体は W の起動指示・再開指示・手渡しの起動指示に `段: spec|implement|finish` の 1 行を書く（develop の `SKILL.md`）。`agents/worker.md` の本文は `worker/common.md` と `段:` が指す段のファイルを読み、`段:` が無いか値が不正なら読まずに聞き返す、に変えた（description は変えていない）
- `scripts/codex-develop.py` が Codex の W の phase に渡す正本を、spec / implement / finish は `worker/common.md`＋段のファイル、explore / summarize は `worker/common.md` に付け替えた
- 事前分類の参照元（develop の `SKILL.md`・`spec-reviewer.md`・`decision-criteria.md`・`gate-runner.md`・pr-review-gate の `stages/triage.md`・`references/model-tiers.md`・README・`plugin.json` の description）と、worker.md の節を指す他の参照を移し先に直した
- worker.md の文言を検査していた bats の各アサーションを、文言が移ったファイルに 1 つずつ付け替えた。否定の検査は索引・`worker/` の 4 本・`pre-classification.md` を連結して見る。`develop-skill.bats` の (3a)/(3b) の切り出しは、字下げした `(3)` の注記行でも区切るようにした（SKILL.md に移した「(3) をこれより細かく切らない」の箇条が (3a) の作業として拾われていたため）
- 「仕様化判断を記録する前に実装へ進まない」「仕様化した場合は R1 の APPROVE のコメントを確認してから実装に入る」と仕様レビュー結果の書式を、`spec.md` から `common.md` の「実装に入る前の確認」に移した。分割前はどの段の W も読んでいた規則で、`spec.md` にだけ置くと、手渡しや Codex の新しい phase で実装の段から起こした W に届かないため（`spec.md` はそこへの参照にし、REQUEST_CHANGES を受けた artifact の直し方は残した）
- main に入った #515（保留で止まるときの引き継ぎと新しいセッションでの再開）と合わせた。新しいセッションの本体は自分が指示した工程を覚えていないので、W を起こすときの `段:` の値を引き継ぎの「次に起こす役割」に書いておき、再開ではその値を使う（develop の `SKILL.md` の引き継ぎの項目表と再開手順 4、`dev-workflow-develop` の「本体は W の起動指示と再開指示に段を書く」）
- 構造の検査 `tests/develop-worker-stages.bats` を足した。段ごとの字数（`common.md`＋段のファイル）を出すが、字数の大きさでは落とさない

## issue の当たりから変えた置き場所

- **事前分類表は共通に置かず、W が読まない `skills/develop/references/pre-classification.md` に移した。** 表を使うのは W を起こす本体と R1・G・pr-review-gate で、W は自分のモデルを選ばない。W が毎回読む指示書に置くと自分への指示と取り違えるうえ読む量だけが増える。`roles/worker/` の下に置くと「W が読むもの」と誤読されるので develop の `references/` 直下にした
- **昇格トリップワイヤーは実装の段ではなく共通（`common.md`）に置いた。** 規模超過・失敗ループ・仕様の発明の 3 条件は仕様づくりの段（R1 の差し戻しの修正を含む）でも起こりうる。W は hook 注入を受けないので、指示書が条件を持たない段では条件が効かなくなり、分割前より適用範囲が狭まる

## 中身を変えていないこと

規則・書式・コマンドは変えていない。移すときに変えた文言は、`common.md` 冒頭に `段:` の行を足したこと、「このファイルだけを読んで動く」を「このファイルと `段:` が指す段のファイルを読んで動く」に、「この worker.md には書かない」を「W の指示書（`worker/` のファイル）には書かない」にしたこと、`spec.md` の仕様化しない場合の段落に「本体が (3a) へ進むよう指示したら `worker/implement.md` を読んでから進む」を足したこと、別ファイルに分かれた位置の参照（「下の」「上の」）をファイル名と節名に直したことだけ。「(3) をこれより細かく切らない」の箇条は develop の `SKILL.md` の (3) に移した。
