# epic-dispatch launch が子に最初の指示を届けてから launched を出す（#458）

`epic-dispatch.sh launch` で Orca の子を起動すると、Claude Code は立ち上がるが最初の指示（`/develop #<子>`）が入力欄に届かず、空のまま止まることがあった（2026-09-24 に 6 件）。スクリプトは `orca worktree create` の終了コードだけで `launched` を出していたので、親は何もしない子を最長 6 時間待ち続けた。

- `orca worktree create` に `--prompt` を渡さず、create の JSON から端末のハンドル（`result.agentTerminalHandle`、無ければ `result.startupTerminal.handle`）を取り、`orca terminal wait --for tui-idle` で起動の完了を待ってから `orca terminal send --text <指示> --enter --wait-submit <秒>` で送る
- `launched` は送信結果の `stages` に `turn_started` があるときだけ出す。ハンドルが取れない・起動完了待ちの失敗・送信の失敗・`turn_started` 無しは `failed`。ハンドルがあれば、`orca terminal read` で確かめる案内と送り直しのコマンド（送り直し用の ID があれば `--retry-request` 付き）を stderr に出す
- 起動完了待ちの上限（既定 60000 ミリ秒）は `EPIC_DISPATCH_READY_TIMEOUT_MS`、送信の観測時間（既定 30 秒）は `EPIC_DISPATCH_SUBMIT_WAIT` で変えられる。非負の整数でなければ子を作らずに exit 1
- develop の SKILL.md（Orca 経路）に、`launched` の意味と、`failed` の子は送り直して動き出したのを確かめてから再開することを書き足した
