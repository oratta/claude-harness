# dev-workflow: 停止中の子のキャッシュ維持（#1383）

停止中の子への声かけの基盤として、固定文・返事専用の接頭辞・順序付きの欄・区切りを `references/child-cache-keepalive.json` に集約した。子は停止前に定義を読み、予約の固定文と完全一致する入力にはツール・作業・mark resumed/stopped・停止コメントの投稿をせず、定義どおりの一行だけ返して待ち続ける。

`child-log` は生成した固定文と、それに対応する型どおりの一行の返事を除外し、元の主の発言・子の質問と時刻を保つ。主が予約文そのものを入力した場合も除外する（送信元の識別は追加しない）。型違い・複数行の返事、一般の「了解」、途中に実際の回答が届いたあとの発言は表示する。質問の保持は正常な往復に限り、ログや停止状態の記録は書き換えない。

既存の `wait --watch-stopped` の通常ポーリングから、Orca/tmux の `keepalive <worktree> <text>` で既存・一意・前景の入力待ち・空欄のセッションだけへ送る。送信直前にも再観測し、端末の作成・終了・再起動・入力消去・再送はしない。両起動部品の start/deliver の起動時に `--prompt-suggestions false` を渡す。Orca の非空 draft は提案文でも送らず、tmux の薄字の提案文だけは空欄とみなす。実行中のスピナー・質問/許可/信頼の画面を除外し、バックグラウンドシェルだけなら送信できる。送信後はターン開始または画面の再観測（Orca）、会話ログへの到達（tmux）で確認する。provider の警告だけでは成否を決めず、確認できなければ failed send とし再送しない。

声かけは、最後のリクエストから 3000 秒以上 3600 秒未満、同じ停止から 86400 秒未満、TTL 1h の子に限る。最後のリクエストは cache-hit も含め、TTL の書き込み時刻とは分ける。未回答の信頼された停止コメントを基点にし、実際の回答あり・前の声かけの返事未着・done・未起動・起動失敗・会話量超過・計測不能・複数セッションは除外する。型違い・複数行の返事だけでは status/stop=stopped-seen・停止コメント・24 時間の基点を変えず、wait を終了させない。TTL 5m/不明は送らず、overage 等の切替はキャッシュ書き込みを観測するまで検知できない。親の追加 LLM 呼び出しは作らず、既存の timeout と一回の掛け直しの費用を維持する。一回確認（interval/timeout 0）と片付け待ちは送らず、通常の closed/done/stopped/error/timeout を優先する。送信の失敗は stderr の診断だけで通常の待ちを続ける。並行入力は送信直前の観測でも原子的には防げない。実セッション送受信（task 4.1）と親子の実エピック費用比較（task 4.2）は未確認で、削減成功とは扱わない。

#1374 の欄の意味・失敗検出と #1385 のコンパクト制御は追加していない。版は上げない。戻す場合は #1383 の実装差分を戻す。
