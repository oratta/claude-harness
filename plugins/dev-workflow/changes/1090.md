# 親経由の返事の合否を、偽 2 件・本物 1 件の混在ログでコマンド 1 つで固定する（#1090）

#1059 の受け入れ条件「偽の文では通らない、本物の文では通る」は、実機の Orca を主の手で動かして確かめていた。判定の実体である `owner-reply-check.sh --relayed` の合否を、テスト用の会話ログ（`OWNER_REPLY_PROJECTS_DIR`）で GitHub も Orca も使わずに固定した。

- `plugins/dev-workflow/tests/owner-reply-relayed-scenario.bats`（新規）: 親の会話ログ 1 本に、偽 1（親の発言・ツールの結果・本物のあとの親の発言とツールの結果）、偽 2（停止の記録より前の主の発言）、本物（親の報告のあとの主の「許容」）を並べ、同じ停止の記録で `--relayed` を当てる。偽 1 は `REASON=not-owner`、偽 2 は `REASON=not-after`（いずれも exit 1）、本物は exit 0 と `MATCH:` 行。`scripts/test.sh owner-reply-relayed-scenario` の 1 コマンドで主の入力なしに合否が出る。`OWNER_REPLY_SCRIPT` で対象のスクリプトを差し替えられる
- 仕様 `dev-workflow-owner-reply-check` に、この回帰の要件と範囲を足した（change `relayed-reply-scenario-check`）
- 固定しないもの: 宣言コメントへの追記と `needs-approval` の付け外し（ゲートの LLM 動作）。実機 Orca の確認は、親・子・ゲートの継ぎ目を変えたときのために残す
- 確認: スクリプトの写しで `not-after` と `not-owner` の判定を無効にすると、この bats が落ちる。`owner-reply-check.sh` 自体は変えていない
