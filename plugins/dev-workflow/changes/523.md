# ゲートを通っていない PR の CI を見張る入口 /ci-watch を足す（#523）

CI の見張りはゲート合格後にしか始まらず、オーナーがゲート未通過の PR について「CI が通ったらマージして」と頼んでも、CI の失敗からやり直し・直しへ進む入口が無かった。#522 の見張りの手順をそのまま使う入口を足した。

- `/ci-watch <PR の URL | PR番号> [--merge]`（`plugins/dev-workflow/commands/ci-watch.md`）を足した。見張るのはメインセッションで、待ち方・`--unrelated` の基準・一手ごとの動き・直し方は `references/ci-watch.md` に従い、入口は独自の規則を持たない
- `ci-watch.sh target <PR の URL | PR番号> [--merge]` を足した。番号は今のリポジトリ、URL は URL のリポジトリの PR として `gh pr view` で確かめ、`{"repo","number","url","merge"}` を 1 行出す。PR の形でない入力・解決できない PR・`--merge` 以外の引数では何も出さずに非 0 で止まる
- マージ依頼の有無は `--merge` の有無だけで決め、会話の文面から推定しない。このリポジトリでは `agent-review:passed` が付くと auto-merge.yml がマージするため、見張りだけを頼まれた PR でゲートを回すと承認の無いマージが起きうる
- `--merge` が無い見張りは、`ready` でゲートを回さず、ラベルも付け外しせずに `CI 見張り終了:` を投稿し、CI が通ったことを PR の URL を添えてオーナーに伝えて終える。`--merge` 付きは `pr-review-gate` の合格後だけ reference の「`ready` を受けたあと」に進む。`--merge` はゲート省略・別 PR・別 HEAD・main への直接 push・rebase・force-push・LLM によるマージの承認にはならない
- `fix` の直しは、メインセッションが起こす実装者のサブエージェント（model は sonnet）が担う。実装者が関係ない失敗と返したら `next --unrelated <チェック名> --after-fix` を 1 回だけ実行する
- 受け入れたリスク: オーナーが自由文でマージを頼んで `--merge` を付け忘れると、見張りは `ready` で終わり、マージが 1 往復遅れる。PR に最初から `agent-review:passed` が付いていれば、見張りと関係なく自動マージが進む（入口は止めない）

## 実機確認の手順（未実施）

ゲートを通っていない PR で CI を落とし、入口から `rerun` か `fix` に進むことを確かめる。確認は使い捨ての PR で行い、マージしない。

1. 開発用 clone（`CLAUDE_HARNESS_DEV_DIR`）の main から使い捨てのブランチを切り、CI が必ず落ちる変更（例: `tests/` に `@test "ci-watch entry check" { false; }` だけの bats を足す）を commit して push し、Draft で PR を作る。auto-merge.yml は Draft を skip する。確認中は `agent-review:passed` を付けない（付けると自動マージが走る）
2. メインセッションで `claude --plugin-dir <この PR の worktree>/plugins/dev-workflow` を起動し、`/ci-watch <使い捨て PR の URL>` を `--merge` なしで実行する
3. `CI 見張り開始:` の投稿、`wait` の `settled`、`next` の一手（`fix`。失敗の原因が PR の差分なので `--unrelated` は渡らない）、実装者サブエージェントの起動までを確かめる。やり直しを見るときは、関係ない失敗として実装者が返す形を作り、`next --unrelated <チェック名> --after-fix` の `rerun` と `gh run rerun` を確かめる
4. 直しの push のあと `ready` になったら、ゲートを回さずに `CI 見張り終了:` が投稿され、ラベルが変わらないことを確かめる
5. 実行した一手・結果・証拠（コメントの URL・`next` の出力）を使い捨て PR にコメントし、PR をマージせずに閉じる。ブランチの削除はオーナーに確認してから行う
