# usage-probe: 期限切れの平文 credentials を Keychain より優先しない（#1396）

`slot_token` は平文の `.credentials.json` からトークンが取れると Keychain を見なかった。macOS で古い平文が残ると、Claude Code 本体が更新した Keychain ではなく切れたトークンで API を叩き、401 で snapshot が更新されなくなっていた（oratta/mac-mini-migration#42）。

- `plugins/dev-workflow/scripts/usage-probe.sh` の `slot_token`: 平文の `claudeAiOauth.expiresAt` が 現在時刻 `NOW`（秒。テストでは `USAGE_PROBE_NOW` で固定）より過去なら、その平文のトークンは控えに残し、Keychain からトークンが取れたときだけ Keychain のトークンを使う。Keychain を引けない（`security` が無い・サービス名が空）か、取れなかったときは、控えの平文のトークンを返す（従来と同じ動き）
- `expiresAt` の単位は、1e11 以上ならミリ秒、未満なら秒とみなす。数値でない・欠損・負のときは切れていない扱いで、従来どおり平文を使う
- `expiresAt` が未来の平文、`expiresAt` の無い平文の動きは変えていない
- 401 を受けたスロットを試行状態に残す案は作っていない（issue が任意とした部品）
- テスト: `tests/usage-probe-multi-account.bats` に 8 件を足した（切れた平文の秒・ミリ秒と Keychain、未来の平文、`expiresAt` なし・数値でない・負・真偽値、既定スロット、`security` が無い環境、Keychain が空、Keychain の `accessToken` が null）
- 戻し方: この PR の差分を戻す。状態ファイルの形は変えていない
