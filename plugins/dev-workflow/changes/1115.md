# usage-probe の取得先にクエリを付け、snapshot にリセット権（reset_grants）を書く（#1115）

Claude のアカウントごとのリセット権（残数と有効期限）をステータスラインに出すため、`usage-probe.sh` を次のとおり変えた。仕様は `openspec/changes/statusline-reset-grants/`。

- `ENDPOINT` の既定を `https://api.anthropic.com/api/oauth/usage?cedar_ember=1&skip_spend=1` にした。非公開の呼び方で、予告なく変わりうる。使用率（`five_hour` / `seven_day` / `limits`）が従来の URL と同じ値を保つかは、実機で主が確かめる（保てなければ取得方式を作り直す）
- 応答の `cedar_ember` が dict で `eligible` が `true`、`grants` が配列のときだけ、`accounts.<id>.reset_grants` に `resets_left`・`ends_at`・`paused` を元の値のまま写す。`FIELDS` には入れない
- 寿命: 取得できたら作り直す。試みて失敗したスロットは欄を出さない（前回の値を写し直さない）。試みなかったスロットは前回の値を保つ。全スロットが失敗したときは、除く欄があれば、その欄だけを除いた前回の snapshot を書く
- 他の欄の引き継ぎと既存のテストは変えていない。新しいテストは `tests/usage-probe-reset-grants.bats`
- 戻し方: この PR の差分を戻す。`reset_grants` は読まれなくなるだけで、snapshot の他の欄は影響を受けない
- PR のゲートの指摘で直したこと: `skills/develop/references/decision-criteria.md` の snapshot の fail-open の説明を、試行して失敗したスロットの `reset_grants` は引き継がずに除き、全スロット失敗でも除く欄があれば書き直す、という現行の挙動に合わせた
- 本番経路の既定の User-Agent を `claude-code/<版>` から Claude Code 本体と同じ `claude-cli/<版> (external, cli)` に変えた（版が取れないときの固定値も `claude-cli/2.1.0 (external, cli)`）。`claude-code/<版>` だと usage API がリセット権を `eligible: false`（`ineligible_reason: "surface"`）で返すため（主の Mac で実測。使用率も同じ呼び出しで 200）。`USAGE_PROBE_USER_AGENT` による上書きは変えていない
