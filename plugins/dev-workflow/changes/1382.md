# develop: エピックの子の止まりに、親が子の会話ログで気づく（1 本目 epic-wait-detect-stop-from-log。#1382）

子が記録（`子の停止: 主の返事待ち`）も印も残さずに主へ質問して止まると、親は気づけず、見張りの `timeout` を繰り返すだけだった（oratta/mac-mini-migration#33 の子 4 件のうち 2 件）。#1382 は 2 本の change に分けていて、この 1 本目は親の見張りが子の会話ログから止まりに気づくところまでを入れる。子の `mark` と `references/epic-child-stop.md` の義務はまだ残す。

- `scripts/child-log-read.py`（新規）: `wait`・`pending-owner`・`child-log` が子の会話ログを読む 1 本の部品。LLM を呼ばず、会話ログを書き換えない。発言の uuid の入口でもあり、`[0-9a-f-]` 以外を含む値は空として読む。ローカルコマンド（`/mcp` など、直後に出力の行が来るもの）と `!` の行は入力にも主の発言にも数えない
- `epic-dispatch.sh wait --watch-stopped`: 記録も印も無い子でも、ターンが終わっているか未回答の質問ツールがあり、最後の発言が子の発言で、そのあとに入力が無く、背景のタスクが無ければ `EPIC_DISPATCH_STOP_IDLE_SEC` 秒（既定 120）、あれば `EPIC_DISPATCH_STOP_BG_IDLE_SEC` 秒（既定 1800）を過ぎた時点で止まった子として返す。記録の新しい任意項目 `stop_uuid`・`stop_at` に発言の uuid と時刻を書き、同じ発言を二度判断しない
- `wait --resolve`: `stop-judge.sh` に止まりの JSON を渡す。判断は `問いではない` も返せて、その止まりは再開に戻す
- `epic-dispatch.sh child-log --last <子>`: 最後の発言の全文・uuid・時刻・最後の入力の時刻（`last_input_at`）・未回答の問い・記録の `stop_uuid` を子ごとに JSON 1 行で出す
- `epic-dispatch.sh dismiss <子>`（新規）: 親が読んで問いでなかった止まりを再開に戻す
- `親の判断:` の書式が変わった: 子 issue の行は 2 行目が `止まりの発言: <uuid か 不明>`、3 行目が `停止の記録:`。エピックの行は `親の判断: 子 #N 通した — <理由> 発言 <uuid か 不明>`（記録があれば末尾に URL）。`notify-closed` と PR トークン上限の行は、uuid が分かるときだけ URL の前に `発言 <uuid> ` が入る。親は URL ではなく uuid で照合し、uuid が空の止まりだけ URL で照合する。子の発言の本文は公開のコメントに載せない
- `pending-owner`: 記録に `stop_uuid` があれば `pending <N> <uuid>` を出し、会話ログがその発言より進んだ子は出さない。手順書の出力の読み方も変わった
- 声かけ（`keepalive`）: 24 時間の基点を `stop_at`（空なら記録の作成時刻）にし、停止のコメントを必須にしない
- `references/epic.md`（手順 2・5・7・8）と `references/reply-after-idle.md`: 上の照合、記録の無い止まりを `child-log --last` の全文から組み立てて主に上げること、問いでない止まりを `dismiss` してから待ちに戻すことを書いた。`委任で送る` は記録のある止まりに限る。マージ待ち・PR トークン上限・二重送信の防止も、最新の記録ではなく今回の停止の記録で見る
- 受け入れること: 権限確認の画面で止まった子と、記録も印も無く会話ログも読めない子は検知できない（手順 2 の最初の通知で主に子のタブも見るよう伝える文は残す）。通知のあとに子が同じ問いを言い直すと別の発言として主に二度上がる
- 変えていないもの: 子の `mark stopped` / `mark resumed` の義務、`references/epic-child-stop.md`、`stages/pass.md` の親経由の受領
- 戻し方: この PR の差分を戻す。`stop_uuid`・`stop_at` は任意項目で、古い版は読み飛ばすので移行は要らない。戻すと `親の判断:` の行の照合が URL に戻るので、uuid だけが書かれた行（記録の無い止まりの行）は照合に当たらず、子が止まっていれば主に出し直される
