# リスク許容の引き継ぎで、PR の修正が根拠ファイルの行を動かしただけのときに main 由来と取り違えない（#1303）

`risk-carryover-check.sh` の判定 4 は、根拠ファイルの PR 自身の差分を `-U0` の削除・追加の行の並びだけで前後比較し、行の位置を見ない。そのため PR の修正が根拠ファイルの中で自分の変えた行を同じ本文のまま別の位置へ動かすと、`EVIDENCE_MAIN_ONLY=`（main から来た変更だけ）と判定され、判定役を通らずに主の許容が次の HEAD へ引き継がれていた（#1270 の作業中に push 時の自動セキュリティレビューが指摘）。

- `scripts/risk-carryover-check.sh`
  - 判定 2 のループで、merge commit でない commit（PR 自身の commit）ごとに `git diff --no-renames --name-only <親> <commit>` で触れたパスを集める
  - 判定 4: 前後の diff が空でない根拠ファイルに PR 自身の commit が触れていれば、PR 自身の差分が同じでも `EVIDENCE_MAIN_ONLY=` にせず `EVIDENCE_PR_CHANGED=` に出す（終了コード 4。`EVIDENCE_DIFF_LINES=` にも数える）。前後の diff が空の根拠ファイル・バイナリ・merge-base の `NG:` の扱いと順序は変えていない
  - 終了コード 4 の意味を「根拠ファイルの PR 自身の差分が前後で違うか、PR 自身の commit が根拠ファイルに触れた」に広げた。出力の行の形と終了コードの集合は変えていない
- `skills/pr-review-gate/stages/hold.md` 3-c: 呼び方のブロックの `EVIDENCE_MAIN_ONLY=` / `EVIDENCE_PR_CHANGED=` / 終了コード 4 の説明、引き継ぎの根拠の行の終了コード 4 の欄、引き継げないときに添える `EVIDENCE_PR_CHANGED=` の説明、「終了コード 4 の判定役」の冒頭の文を新しい意味に合わせた。4 行の構造・行頭・判定役への入力は変えていない
- issue の 2 案のうち「PR 自身の commit が根拠ファイルに触れたら終了コード 4」を採った。「位置を含めて文脈行つきで比べる」案は、main が PR の変えた行の近く（文脈の 3 行）を変えただけで終了コード 4 になり、「main の取り込みだけなら引き継げる」受け入れ条件を壊すうえ、前の HEAD の差分を新しい merge-base に載せ直す処理が要るため採らなかった
- merge commit は触れた commit に数えない（数えると main が根拠ファイルを変えた取り込みがすべて終了コード 4 になる）。merge commit の衝突解消が根拠ファイルの行を動かしただけのものは、許可リストに無い根拠ファイルなら今までどおり終了コード 3（PR 全体を見た取り直しのレビューが要る）で受ける
- 新たに起きる誤検出: PR 自身の commit が根拠ファイルを変えて同じ中身に戻した上に、main が同じファイルを変えたときは終了コード 4 になる（判定役に回るか主に聞く側に倒れるだけ）
- **読み方の変更**: 今まで終了コード 0 / 3 で `EVIDENCE_MAIN_ONLY=` に出ていたもののうち、PR 自身の commit が触れた根拠ファイルは終了コード 4 で `EVIDENCE_PR_CHANGED=` に出る。古い 3-c の文面と組み合わせても、判定役か主に聞く側に倒れるだけ
- openspec change `risk-carryover-pr-commit-touch` で `dev-workflow-pr-review-gate` の Requirement「前の HEAD の許容を新しい HEAD に引き継いでよい条件」と「risk-carryover-check.sh が差分の範囲と根拠ファイルの PR 自身の差分を判定する」を更新
