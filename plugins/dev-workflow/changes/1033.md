# エピックの子が主の返事を待って止まったとき、親が気づいて報告する（#1033）

Orca 経路で起動されたエピックの子が自分のタブで主に質問して止まると、ラベルもコメントも残らず、親の `wait` は最長 6 時間の `timeout` まで気づけなかった。子が止まる前に記録と印を残し、親の `wait` がその印で起きるようにした。

- `scripts/epic-dispatch.sh` の `mark` に `stopped` と `resumed` を足した。どちらもボードの列（`workspaceStatus`）には触れず、Orca のワークツリーのコメント欄を `orca worktree set --worktree current --comment <値>` で書き換える。`stopped` は `epic-stopped`、`resumed` は今のコメント欄が `epic-stopped` か `epic-stopped-seen` のときだけ `epic-resumed` にする（それ以外は `skipped <issue> not-stopped`）。linkedIssue の確認・`no-workspace`・`failed` は `done` / `waiting` と同じ
- `wait` に `--watch-stopped`（値なし）を足した。位置引数の子のうち、そのポーリングで閉じていない子の、同じ repoId・archive されていない・コメント欄が `epic-stopped` のワークツリーを全部 `epic-stopped-seen` に書き換え、書き換えられた子を `stopped <N>...` で返す。一覧は `--watch-done` と共用で 1 ポーリング 1 回。出力は `closed`・`done`・`stopped` の該当するものだけをこの順に 1〜3 行。書き換えに失敗したポーリングは失敗したポーリングに数え、3 回続けば `error workspaces`。一度受けた止まりは `epic-stopped-seen` になっているので、親の `wait` は同じ止まりで起き続けず、子が `mark stopped` を付け直せばまた起きる。`--watch-stopped` が無い呼び出しは今までどおりコメント欄を見ない
- develop の SKILL.md に「エピックの子が主の返事を待って止まるとき」の節を足した。`route` が `nested` を返すセッションだけが、1 行目 `子の停止: 主の返事待ち` の記録を投稿してから `mark stopped` を呼ぶ。本文で質問してターンを終えるときは `mark stopped` をそのターンの最後のツール呼び出しにし、返事を受けたターンの最初に `mark resumed`。質問ツールで待つときは記録 → `mark stopped` → 質問ツールの順に呼び、回答のあとに `mark resumed`。引き継ぎを書く場面では引き継ぎを先に投稿する。記録の 2 行目以降の項目名と形は #1036 で決める
- Orca 経路の手順 2 の `wait` に `--watch-stopped` を付け、出力の説明を 1〜3 行にした。手順 8 として、`stopped` で起こされたら最新の `子の停止:` の記録を読んでユーザーに報告し、止まった子を外さずに再び待つ手順を足した。止まった子への返事の仕方は #1034 で決める。手順 5 の「子のタブで質問して止まった子は検知できない」は、記録を残さずに止まった子に限る文にした
- `tests/epic-dispatch.bats` に `mark stopped` / `resumed`、`wait --watch-stopped`（受けた止まりで起き直さず、付け直した止まりでまた起きる通しの確認を含む）と SKILL.md の記述のテストを足した。orca のスタブは `--comment` で書いた値を以後の一覧と current に返す
- 入れなかったもの: 端末の入力待ちが続いたことから止まりを推定する案。Orca のワークスペースの直近 14 日の会話ログ 1,289 件で、ターンを終えたあとの次の入力の 91% が背景のタスクの終了通知で、30 分以上空いた止まりでも 8 割（440 / 548）は人を待っていなかった。誤検知が多いので入れず、記録を残さずに止まった子は今までどおり `timeout` の確認とユーザーが子のタブを見ることで拾う（根拠の正本は change `epic-child-stop-signal` の design.md）
- 受け入れること: 主がエピックの子のワークツリーのコメント欄に書いたメモは、`mark stopped` が上書きする（エピックの子のワークツリーでメモを使う運用は今のところ無い）
- 戻し方: この PR を revert する。残ったコメント欄の値（`epic-stopped` など）は `--watch-stopped` を付けない `wait` からは見えないので、戻したあとに消す必要はない
