# Codex 単独の develop で Claude 固定の例外役を起動しない（#1859）

## 変更したもの

- 一時ディレクトリへの書き込みが要るテストの再実行・画面確認役・引き継ぎの判定役・論点なしの確認役を、共通の `codex-develop.py request` で選ぶようにした。`codex-standard` では実行可能な依頼を作らず、Claude/Codex のどちらも起動しない。起動しなかった役・理由・不足する確認を記録し、未完了／実行不能／判断できない場合の既存経路へ戻す。
- CLI が必要な本体では、通常の自動選択表より先に `claude` が PATH にあるかを評価する専用分岐を加えた。不在なら Codex が有効かつ代表 margin が 0 以上の場合だけ `codex-standard` を選び、それ以外は理由付きの blocked JSON・exit 2 で役の起動前に止める。Claude 本体の自動選択と明示 profile の扱いを維持する。
- 一時書き込みが必要な独立レビューは、主に固定 HEAD・関連テストの正確なコマンドと範囲・環境と一時領域・期待結果を渡して再実行を依頼する。HEAD・コマンド・環境と一時領域・日時・出力・終了コード・回答の出典を PR に残す。証拠不足は保留、失敗は修正へ戻し、同じ HEAD・範囲の有効な証拠を受領済みなら再依頼しない。
- 主の証拠を受け取った後は、W と別 thread の読み取り専用 Codex レビュアーが残るコード／三表レビュー・可能な再実行・主の結果評価を完了する。その結果と証拠 URL を fresh G に渡して復帰する。主の証拠だけで合格へ進めず、CI/W の結果で主の再実行を代用しない。

## 受け入れ条件の確かめ方

- `PYTHONDONTWRITEBYTECODE=1 python3 plugins/dev-workflow/tests/test_codex_develop.py`: 4 例外の request が `codex-standard` で実行可能な依頼を作らず、起動呼び出しが 0 であること、通常の書き込み不要レビューが継続することを確認する。呼び出し元と復帰手順の文書契約も検査する。
- 同じ Python テストで、PATH に Claude が無く記録上の Claude margin が正でも Claude を選ばないこと、Codex にも余裕が無い場合は依頼ファイルも起動も無く停止すること、Claude 本体の従来選択と明示 profile を維持することを確認する。
- 関連 bats と `tests/plugin-release-convention.bats` で、手順書の整合・予算・変更記録の形式を検査する。`openspec validate avoid-claude-in-codex-only-develop --type change --strict` で仕様差分を検証する。各コマンドの実測結果は実装＋verify の返却に記録する。
- 静的検査に使う `scripts/lint.sh dev-workflow` は、役の起動とは別に CLI の検証コマンド `claude plugin validate` を呼ぶ。前の実装 thread でもこの経路を実行した。

実測: Python テスト 148 件と上記 OpenSpec strict 検証はともに exit 0。`scripts/lint.sh dev-workflow`（`claude plugin validate` を含む）と `scripts/test-auto-merge-workflow.sh` も exit 0。`gate-result.md|codex-develop.md|reviewer-brief.md|hold-resume.md|skills/develop/SKILL.md` を参照する関連 bats 29 本と変更記録形式の検査は、書き込める `TMPDIR`・`BATS_TMPDIR` を使って一括実行し、1,929 件すべて成功・exit 0。

## 後で直す候補

全工程 Codex の構成ではテストを含む PR ごとに主の再実行が要る。読み取り専用の役に書き込み先を与えない決まりはエピックの別の子の範囲であり、今回の変更ではこの負担を残す。
