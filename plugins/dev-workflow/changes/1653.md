# develop: 主に上げる止まりを、主に聞く理由を根拠つきで示せたものに絞る（#1653）

親と子が主に聞く理由の無い止まりを主に上げ、主が「論点は？」「なんで俺に聞くの」と聞き返す件が続いた（2026-11-12・11-13・11-16 の flatmate のエピック）。主に上げる側に倒す文を外し、論点なしの止まりを主の委任で親が進められるようにした。

- `owner-reply-check.sh --delegated`: 問いと確認のあいだに主の別の発言が挟まっても `not-direct` で落とさない（設計 D4 の案 A。判定を緩めた）。残す判定は、確認の行が主の発言・委任の記録より後・その前に記録の URL を書いた親の発言がある（`not-asked`）・停止の記録より前（`not-before`）。`--relayed` は変えていない
- pr-review-gate: リスク宣言に `論点なし — ` / `論点あり — ` の行を足し、論点なしの宣言は主に聞く前に決める役が確かめる（`hold.md` 6-0、`needs-no-point-check`）。`論点なしの確認: 通す` の記録が残る
- `parent-pass-criteria.md`: 「迷ったとき」を「主に上げるとき」に置き換え、主に聞く理由の 3 つのどれかと根拠を `理由:` に示せたときだけ主に上げる。「主の側にしか答えが無い」とする前の (a)〜(c) の確かめと、通らない例 3 件（11/16・11/12・11/13）を足した。委任の無いセッションでは、聖域の変更・破壊的な git 操作・マージを今どおり通さない
- `epic.md`: 委任の記録に 2 種目 `主の委任: 論点なしの止まり` を足した。委任の受け方（挟まった発言だけでは問い直さない）、委任が効く止まりを種類ごとに（リスク許容は ⑤ 論点なしを足して両方の種類で、聖域の変更・破壊的な git 操作・論点なしの確認で通ったマージ待ちは `論点なしの止まり` だけで、実機操作はどちらも効かない）、`進める（主の委任による。…）` の返事、判例を `.claude/casting/precedents.md` に残す契機、報告の「親の判断で通した PR・止まり」の節を書いた。手順 8 の「迷うときは主に上げる」を消した
- `parent-merge-criteria.md`: 委任があるときだけ論点なしの確認でマージ待ちに印を付ける手順（**委任で印を付ける**）を足した。マージの基準の「迷ったら主に上げる」は残した
- `epic-child-stop.md`: 聖域の変更・破壊的な git 操作の承認待ちでも停止の記録を残し、委任の返事で進めるときは記録した操作だけを行って `委任で進めた:` を残す
- `pr-review-gate/stages/pass.md`: 委任の真正性確認を `epic.md` と同じ文にそろえた（種類ごとの定型の行数と ⑤）
- `output-styles/readable.md` の節 3 と `rules/communication-style.md` の 3: 設計の分かれ目は主の指摘が効く観点だが主に聞く理由に数えず、決めた内容と他の案を報告に載せる
- 聖域に触れる: `rules/communication-style.md` と `output-styles/readable.md`（常時注入）。`tests/develop-startup-budget.txt` を 93433 から 94392 に上げた（SKILL.md を縮めたうえで増えた分）
- 常時注入の予算（`tests/injection-budget.txt`、聖域）を 41887 → 42300 に上げた。論点の定義を `readable.md` の節 3 と `communication-style.md` に足す受け入れ条件のため。足す前の余りは約 9 バイトで、既存の文は別のテストが見ているので削れない
