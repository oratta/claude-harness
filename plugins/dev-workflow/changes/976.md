# accounts.json の enabled でアカウントをオフにできるようにする（#976）

使っていないアカウント（解約済みなど）が `cld` の自動選択で選ばれることがあった。自動選択は取得からの経過時間でスロットを外さないので、使用率が増えないスロットは週の経過とともに余裕が大きく見える。登録を消さずに外せるよう、`accounts.json` の各スロットに `enabled`（真偽値、省略時はオン）を足した。`schema` は `1` のまま。

- オフになるのは `enabled` が JSON の `false` のときだけ。省略・`true`・`"false"`・`0`・`null` はオンとして読み、スロットは捨てない。オフのスロットも一覧には残る（宣言順・8 個の上限・`id` の一意性・active の判定に数える）
- `scripts/usage_view.py`: オンかオフかを含めて読む `read_slots(path)`（`[(id, securestorage, enabled)]`）を足した。`read_registry(path)` の戻り値（`[(id, securestorage)]`）と `build_view` の出力は変えていない
- `scripts/select-account.sh`: オフのスロットは自動選択の候補にせず、理由行の `margins` に `<id>:off` と出す。`select-account.sh <id>` でオフのスロットを指定すると、stdout は空・exit 2 で、stderr に `account <id> is off: set "enabled" to true or remove it for this slot in <登録簿のパス>` の 1 行を出す。全スロットがオフのときは既定アカウントへ縮退し、理由は新しい値 `default-due-to-all-off`（`selected` の決め方と exit 0 は従来の縮退と同じ）
- `scripts/usage-probe.sh`: オフのスロットは叩く対象から外す。Keychain・平文の credentials ファイルの読み出しも API 呼び出しもせず、試行状態にも記録しない。snapshot の同スロットの項目は前回値（`fetched_at` 込み）のまま引き継ぐ。`--print-slots` は 4 列のまま
- `scripts/accounts-init.sh`: 同じ id を上書きするとき、既存スロットに `enabled` があれば同じ値のまま残す。無いスロットと新しい id には書かない
- `enabled` を書いていない登録簿では、選択・取得・snapshot のいずれも変わらない
- 切り替えは当面 `accounts.json` を手で書き換える（切り替えのコマンドは #977、Codex 側のオフは #978）
- 戻し方: 利用者側は `enabled` の行を消す。コードはこの PR の差分を戻す（`enabled` を書いたままの登録簿は、古い読み手では未知のキーとして読み飛ばされ、全スロットがオンに戻る）
