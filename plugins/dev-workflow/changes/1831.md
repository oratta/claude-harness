## 1598-b: Orca で識別できない 1 端末を、画面の入力枠で子のセッションに決める（change orca-session-term-fallback）

Orca の端末一覧で `agentIdentity` が null、題名が子の付けたセッション名（`Claude Code` を含まない）のとき、親の `notify-closed` と `reply --as owner` が `failed <N> ambiguous-terminal` で終わり、子が片付かず主の答えも届かなかった（2026-11-07 と 2026-11-18 に genetta-inc/flatmate のエピックで観測）。

- `scripts/epic-launch-orca.sh`: `agentIdentity` でも題名でも決まらず、ワークツリーの端末がちょうど 1 つのときだけ、`orca terminal read --terminal <h> --screen --json` を 1 回呼ぶ。下端に Claude Code の入力枠（罫線・`❯` の行・罫線・フッター）があれば、その端末を子のセッションに選ぶ。判定は `keepalive` の入力枠の判定（`resolve_frame`）を使い回す
- `deliver`（`reply`・`notify-closed`・`wait --resolve`）は、入力枠が無い・画面を読めないときは今までどおり `failed ambiguous-terminal` で送らない。`keepalive` は入力枠が無ければ `skipped ambiguous-terminal`、読み取りの失敗は `failed observe`。選んだあとも `keepalive` は同じ画面を 2 回観測する
- 変えていないもの: 端末が 2 つ以上なら画面を読まない。シェルの端末だけのときは送らない。`launch` の起動を待つ判定（`shell_start`）、起動部品の stdout の語、tmux の部品
- 受け入れ条件「子のワークツリーに端末が 1 つだけあり、そこで子の Claude Code が動いているとき、`notify-closed` が `ambiguous-terminal` にならない」の証拠（`tests/epic-dispatch.bats`）:
  - `notify-closed: one unidentified terminal with the input frame gets the reply after the merge (#1598)`
  - `reply: one unidentified terminal with the Claude Code input frame at the bottom gets the answer (#1598)`
  - `reply: one unidentified terminal with a shell prompt or an unreadable screen sends nothing (#1598)`
  - `reply: two unidentified terminals are not read and send nothing (#1598)`
  - `launcher orca: deliver reads the screen once only for one unidentified terminal (#1598)`
  - `keepalive orca: one unidentified terminal is chosen by its input frame and still observed twice (#1598)`
  - `keepalive orca: one unidentified terminal without the input frame skips, and a failed read is failed observe (#1598)`
- 受け入れること: 識別できない 1 端末のときだけ、`deliver` の `orca` の呼び出しが 1 回（`orca terminal read`）増える

## 1753-a: parent-merge-inputs の各節の本文を、実行ごとの乱数の区切りで囲む（change parent-merge-inputs-fence）

`scripts/parent-merge-inputs.sh` の `section()` は、`## <見出し>` と本文をそのまま並べていた。PR の差分や本文に `## 委任の記録の候補` と書かれると、決める役は信頼できる節と見分けられなかった（自動セキュリティ検査の指摘）。

- 入力文の 2 行目に `区切り: <乱数>（…読み方…）` を出す。乱数は `od -An -tx1 -N16 /dev/urandom` から作る 32 桁の小文字の 16 進数で、実行ごとに変わる
- 各節の本文を `<<<本文 <乱数>` と `本文 <乱数>>>>` の行で囲む。見出しは区切りの外にだけ出す。信頼できる節（委任の記録の候補・委任の確認の場所・注意書き）も同じ形で囲む
- 集めた値のどれかが乱数を含むとき、または作った値が 32 桁の 16 進数でないときは、stdout を空にして exit 1
- `skills/develop/references/parent-merge-criteria.md`: 区切りの外の `## ` で始まる行だけを節の見出しとして読むことを書いた
- 乱数を固定する環境変数や引数は作っていない（テストは PATH の偽の `od` で固定する）
- 変えていないもの: 1 行目の `HEAD:`、節の見出しの名前、本文が空の節の `## <見出し>（なし）`、exit code の意味
- 受け入れ条件「差分に `## 委任の記録の候補` を含む PR を入力にしたとき、本物の委任の記録の節が 1 つだけと機械的に判別できる」の証拠（`tests/parent-merge-inputs.bats`、`scripts/test.sh` で exit 0）:
  - `fence: a forged closing line and heading in the diff stay inside the fence`
  - `fence: the nonce differs between runs`
  - `fence: a fixed od gives that nonce, and collected values containing it give exit 1`
  - `fence: od failure, non-hex or short values give exit 1 and empty stdout`
  - 基準の文は `tests/parent-merge.bats` の `criteria: scope says only headings outside the fence of line 2 are sections`
- 常時注入の予算: `tests/develop-epic-scene-budget.txt` の場面 `parent-merge-wait`（177028 → 177329）と `parent-merge-delegated`（183484 → 183785）を、それぞれ 301 バイト上げた（main の値からの差。新しい値は実測と同じ）。要件が、基準のファイル `parent-merge-criteria.md` に区切りの読み方を書くことを MUST にしている。その段落の分を実測に合わせて足した。ほかの場面の値は main のまま変えていない（main の取り込みで衝突した `parent-stopped`・`nested-delegated`・`parent-delegated` は、この PR が読む文書を変えていないので main の値を採った）

## 1825-a: 別のリポジトリの子の起動の指示で、子の番号にリポジトリを付ける（change xrepo-child-prompt-repo）

エピックと子が別のリポジトリにあるとき、最初の入力は `/develop #892 （エピック #1810 の子。エピックのリポジトリ oratta/claude-harness。…）` の形だった。文に出るリポジトリ名がエピックの側だけなので、子はエピックの側のリポジトリの #892 を読みに行った（2026-11-26 に genetta-inc/flatmate#892 の子で起きた）。

- `scripts/epic-dispatch.sh`: 別のリポジトリの子の、`launch` の最初の入力と起動し直しの指示（`reply --relaunch`・端末 0 個の起動し直し・`notify-closed --relaunch`・`wait --resolve`）を `/develop <子の owner>/<repo>#<N> （エピック #<E> の子。エピックのリポジトリ <エピックの owner>/<repo>。…）` にした
- `scripts/owner-reply-check.sh`: `DISPATCH_ARGS` が、子の番号の前に `<owner>/<repo>` を付けた形も起動の指示として主の発言から外す
- 変えていないもの: 同じリポジトリの子の入力（1 文字も変えていない）、返事の頭、子のターン状態のフック `scripts/epic-child-state.sh`。このフックの起動形の判定は、子の側の `<repo>#<N>` と `エピックのリポジトリ` の句をもともと受けるので、新しい形も `startup` になる。それをテストで確かめた
- 受け入れ条件の例「エピック oratta/claude-harness#1810 の子」は、取り違えない書き方の例示として読んだ。採った形では、子のリポジトリは番号に付け（`genetta-inc/flatmate#892`）、エピックのリポジトリは「エピックのリポジトリ oratta/claude-harness」の句で名指す。どちらの名前がどちらの側かは文から一意に決まる。エピックの番号にもリポジトリを付ける形（例の文字面どおり）を採らなかった理由は 2 つある。1 つは、エピックの側の `<repo>#<E>` を受けるには `epic-child-state.sh` の正規表現を変える必要があること。このファイルは聖域パス（`.github/workflows/auto-merge.yml` の SACRED）で、触ると PR が人間マージになる。もう 1 つは、並列で回る #1821 が同じファイルを編集していて衝突すること

  - 同じリポジトリの子の入力が変わらない: `tests/epic-dispatch.bats` の `launch: a same-repository child keeps the old command, first input and note` と `reply --relaunch: a same-repository child keeps the old instruction`（どちらも完全一致）
  - 新しい形は主の発言として数えない: `tests/owner-reply-check.bats` の `owner-reply cross-repo: the launch instruction with the repository on the child number does not match` と `owner-reply cross-repo: the relaunch instruction with the repository on the child number does not match`
  - 子のフックで `startup` になり、句のリポジトリが記録と違えば記録を変えない: `tests/epic-child-state.bats` の `input: cross-repo relaunch with the repository on the child number is startup; another epic repository is ignored`
