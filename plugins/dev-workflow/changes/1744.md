# エピックの親が子の状態記録だけで止まりを判断する（#1744）

エピック #1732 の子。親の `wait --watch-stopped` は、子が記録した `turn_input` / `turn_state` の型・世代・セッションが有効で、送り手が parent / startup、状態が `主の返事待ち` の場合だけ停止として扱う。会話ログ・アイドル時間・古い停止印だけからの推測を廃止する。

- owner のターンは `主の返事待ち`・`作業報告` のどちらでも、自動判断・返事・端末終了・再起動・声かけの対象にしない。状態記録の欠落・null・不正・不一致、作業報告・完了も対象外とする。
- 同じ世代・セッションの停止は二度新規判断せず、入力の更新で再開を記録する。停止の受領、長い待ちの再判断、自動送信・再起動の直前にも状態を照合し、主の新しい入力を古い判断で上書きしない。
- 親の有効な返事待ちと依存待ちの既存動作、公開コメントに発言本文を載せない契約を保つ。150,001 トークンの owner のターン、ログだけの停止、判断中の入力更新、「通す」以外の判断を回帰テストで確認した。
- OpenSpec change `epic-wait-recorded-turn-state-1744` を archive し、現行仕様へ反映した。

## 依存待ちの停止の受領と再開（change `epic-parent-dependency-wait-resume-1744`）

#1775 で子が成功した依存待ちの作業報告に `turn_state.dependency_wait: true` を保存するようになったので、親はそれを状態記録だけで受領し、既存の依存照合と `reply --relaunch --as parent` の再起動につなぐ（P3-F1 の再現テストを復旧テストに変えた）。

- 停止対象は「主の返事待ち」と「`dependency_wait: true` の作業報告」の 2 種類。`dependency_wait` が存在して boolean でない記録は、主の返事待ちでも停止対象にしない（記録全体の読取は拒まない）。欠落と `false` の返事待ちは従来どおり。
- 依存待ちの停止は会話ログが読めなくても受領し、判断役・長い待ちの判断し直し・声かけ・自動の戻しには渡さない。`pending-owner` は受領した組が今も有効な依存待ちならログの進みによらず既存の行で出す。
- `reply --as parent` は記録に `stop_turn` があるとき、受領した組が今も有効な停止かを送信前に 2 回確かめ、主の新しい入力があれば `skipped <N> not-stopped` で送らない。`--as owner` と `stop_turn` の無い記録は変えない。
- 移行条件: `dependency_wait` の無い古い作業報告は、ログやコメントに依存待ちの形があっても依存待ちに補わない。

フックが入っていない古い子は、ログや停止印があっても自動検知しない。手順書 `epic-stop.md` / `reply-after-idle.md` の書き換えは #1760 に分離した。子側の状態記録は #1670、時間による知らせは #1745 の範囲。戻すときは本 PR を revert する。version は上げない。
