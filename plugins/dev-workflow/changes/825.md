# epic-dispatch.sh reap: ブランチの削除を期待 OID つきにする（#825）

`reap` は、ブランチの先端が HEAD と同じことを確かめたあとで `git branch -D` を呼んでいた。確かめてから消すまでの間に別プロセスが同じ ref を進めると、進んだあとのブランチを消してしまう。削除時の期待 OID を Git に渡していなかったため。

- `scripts/epic-dispatch.sh` の `reap` は、`git branch -D <ブランチ>` をやめて `git update-ref -d refs/heads/<ブランチ> <HEAD>` を呼ぶ。ref が HEAD 以外へ進んでいれば Git が失敗し、`reaped <N> branch-kept` になる。「先端が HEAD と同じときだけ」「`git worktree list` から外れるのを上限つきで待つ」「別の worktree で使われているブランチは消さない」の既存の条件は変えない
- `openspec/specs/dev-workflow-develop/spec.md`・`dev-workflow-epic-state/spec.md` の reap の記述と Scenario を `git update-ref -d` に揃えた。「確認から削除までの間に子が積んだコミットは残る」ことを許容する文面は、期待 OID つきの削除で Git 側が担保する形になった
- `tests/epic-dispatch.bats` のスタブに `update-ref -d`（期待 OID が違えば exit 1）を足し、確認の後・削除の前に ref が進んだ場合に消されない回帰テストを足した。`git branch -D` を前提にしていた既存の検査は `update-ref -d` に置き換えた
- `git-destructive-guard.sh` の止める範囲は変えない。ただし `git update-ref -d` はコマンド文字列では止まらない破壊的操作なので、マージ時に破壊的操作の扱いとして人間の承認を取る
