# develop: エピックの子は mark stopped が skipped を返したときも、親に止まりが伝わっていないと主に添える（#1247）

エピックの子が主の返事を待って止まるとき、`epic-dispatch.sh mark stopped` が `skipped <N> no-workspace`（自分のワークツリーを持つ状態の記録が無い）を返しても、手順書は「何もしない」と定めていた。親の `wait --watch-stopped` は状態の記録の印だけを見るので、子は止まりが親に伝わっていないことに気づかず、親は待ちの打ち切りまで気づかなかった（実例: エピック #1122 の子 #1123、エピック #1137 の子 #1165。どちらも親と子のプラグインの版がずれ、子の状態の記録が作られていなかった）。

- `skills/develop/references/epic-child-stop.md`: `mark stopped` の出力が `marked` なら何もしない。`skipped` で始まる（`skipped <N> no-workspace`・`skipped <N> not-linked`）か `failed` なら、主への質問に「親に止まったことが伝わっていない」と 1 行添える。`not-linked`（記録が別の子のもの）も、親が見張る記録に印が付かない点で同じなので含めた
- 要件「エピックの子は止まる前に記録と印を残し、親は stopped を受けて報告する」の同じ 1 文は、change `epic-child-stop-skipped-not-conveyed` の spec の差分（MODIFIED）で同じ内容に直した。`openspec/specs/dev-workflow-develop/spec.md` 本体には、archive で反映される
- `scripts/epic-dispatch.sh` は変えていない。親の `wait --watch-stopped` が、状態の記録の無い子について issue の `子の停止:` コメントを見る変更は入れなかった（実例の 2 件は親が古い版のまま見張っていて防げず、今は `launch` と `adopt` が記録を作るので記録の無い子はまれで、受けた止まりの印を書く置き場の設計が要るため）
