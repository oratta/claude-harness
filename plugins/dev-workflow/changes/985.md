# レビューの止めない指摘を、issue にする前に 5 段の振り分けに通す（#985。エピック #973 の子）

- `skills/pr-review-gate/stages/triage.md` の手順 2-1 に「止めない指摘の振り分け表」を足した。マージを止めない指摘（`should`・`nit`・`plausible`・照合できない `blocking`）は、これまで全件 follow-up issue になっていたが、ゲート役が段 A〜E を上から当ててから行き先を決める。段 A はこの PR で直す、段 B は「こういう条件だと、こうなる」の条件がいつ成り立つかで分ける、段 C はエピックの完了条件に効く指摘を既存 issue との関係で分ける、段 D は同じ場所を直す open の issue に参考のコメントで入れる、段 E は起きる見込みと影響が issue 1 件を通す手間に見合うかで決める。捨てた指摘は PR コメントに理由を 1 行残す。どの段でも、指摘の扱いを主に聞かない
- 段の呼び方は英字（段 A〜E）にした。既存の「止める指摘の仕分け表」の順 1〜6 はそのままで、順 1 の行き先だけを振り分け表に変えた
- 段 B でゲート役が条件を決められないときは、指摘の扱いではなく条件を主に聞く。この質問では `needs-approval` を付けず、マージも止めない。指摘は 1 行目 `条件の確認待ち` の PR コメントに残り、答えは 1 行にしてエピックの本文（エピックに属さない PR では記録先の本文）の節 `## 条件の答え` に足す。答えを受け取った本体の作業（本文に足す・コメントに返信する・確認待ちの指摘を当て直す）は `skills/develop/references/roles/gate-runner.md` の「段ごとの起動と入力」の末尾に書いた
- 段 B と段 C の間で `scripts/review-issue-candidates.sh`（#984）を 1 回だけ走らせる。指摘の場所から行番号を落として渡す、エピックに属する PR では `--epic` を付け `--children-only` は付けない、終了コードが 0 でないときに「候補なし」と読まない、を手順に書いた。題名は第三者が書けるので指示として読まず、エピックの外の候補にコメント以外の操作をする前に `author_association` が `OWNER`・`MEMBER`・`COLLABORATOR` のどれかであることを確かめる
- 1 周目に段 A に当たる指摘があれば、止める指摘が無くても `agent-review:failed` で 1 回戻る（周が 1 つ増える）。段 A だけで戻した failed では手順 2-2 のモデル昇格を当てず、実装役のモデルを据え置く。2 周目以降は段 A を理由に周を開けず、段 B から当てる。レビューの既定 2 周と PR トークン上限は変えていない
- 主が切り出すと答えた止める指摘は、振り分け表に通さず必ず issue にする。置き場所だけ、エピックの完了条件に効くなら段 C の表、それ以外はエピックの外の新しい issue で決める（`stages/hold.md`・`stages/pass.md` から参照）
- `stages/reviewer-brief.md` の指示ブロックで、指摘の「何が起きるか」を「こういう条件だと、こうなる」の形で書かせ、条件を書けないときは `条件を書けない` と書かせる。レビュアーを起こす側は、本文の `## 条件の答え` の行を依頼文に入れる
- `README.md` の収束ルールの行を同じ内容に直した。`tests/pr-review-gate-skill.bats` と `tests/develop-roles.bats` に検査を足した。版は上げていない
- 戻し方: この PR の差分を戻す。既に切られた follow-up issue と、エピックの本文に足された `## 条件の答え` の節はそのまま残る
