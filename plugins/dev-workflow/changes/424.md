# develop: 失敗ループの昇格を格と `--failure` の値で書き、昇格で profile と実装役の設定を差し替えない（#424）

失敗ループのラダーは Claude のモデル名（`sonnet` → `opus` → `fable`）で段を書いていたので、Codex の profile では段の読み方が決まらず、本体が昇格のために profile を作り直したり model を独自に指定したりする余地があった。#614 で格を決める場所が `codex-develop.py request` の 1 か所になったので、ラダーを格と `--failure` の値で書き直し、本体は `request` が返した model だけを使う規則にした。

- `templates/escalation-tripwires.md`: 失敗ループの表を「段階・`--failure`・決める役の要求の格・実行役の要求の格」の 4 列にした。表の格は上限を適用する前の要求の格で、実際の model は `request` の返り値で決まる（例: `SHARED_BUDGET_MODE=depleted` では決める役も中位）。モデル名は `references/model-tier-map.json` で引く値で、Claude の値は括弧書きの例だけにした。「本体が opus 以上ならその場で」「本体が fable ならその場で」を消し、Opus・Fable の名前で書いていた但し書きを格の言葉（上位・最上位）にした。本体は昇格の手段として profile を作り直さず、`request` が返した model と違う model を指定しない、の一文を足した
- `references/codex-develop.md`「本体が行う操作」: 失敗ループの手順を実行側（W の phase に `--failure executor`）と判断側（`request --phase decider --failure judgment`）に分けて書いた。profile の作り直し・`--profile` / `--profile-file` の差し替え・返った model と違う model の独自指定や上書き・effort の変更をしない。返った model を Agent の `model` に渡すのは既存の契約どおりで、これに当たらない。Codex の実装役の model が変わらないのは対応表で引いた結果
- `references/codex-develop.md`「起動と role 解決」: develop 開始時の profile の指定（`--profile`・`--profile-file`・旧形式・無指定）を工程の途中で変えない。変えるときは主の承認を求め、記録先に `profile 変更: <変更前の指定> → <変更後の指定>` の行と主の承認の発言を引いたコメントを残す
- 再開の条件（`references/codex-develop.md` と `skills/develop/SKILL.md`「Role profile の選択」）: 呼び直しは今回の格の入力（失敗ループの段なら `--failure` の値を含む）で行い、`tier` と `model` だけを読む。返った `tier` が thread の格より低くなく、かつ返った `model` が thread の applied model と同じときだけ SendMessage で再開する。それ以外（降格と、model が変わる昇格）は fresh thread に手渡す。SendMessage の再開では model を変えられず、昇格が起きないまま再開されるため
- `skills/develop/SKILL.md`「モデル」節と `skills/develop/references/roles/worker/common.md`: 「W を `opus` で再開」と「decider の `model` の段は `templates/escalation-tripwires.md` を Read して従う」を消し、`--failure first` / `executor` / `judgment` と失敗の段の対応、`request` が返した model を使うこと、model が変われば新しい thread（W）に手渡すことを書いた。W の上限が上位（`opus`）であることは変えていない
- #615 に寄せたもの: 上位格のモデルを実装役に付けた依頼の機械的な拒否と、profile の差し替えの機械的な拒否（`request` での拒否とそのテスト）。この変更は文書の規則だけ
- 変えていないもの: `codex-develop.py` の挙動、`agent-model-guard.sh`、`session-tripwires.sh`、`references/model-tier-map.json`
- 戻し方: この PR の差分を戻す
