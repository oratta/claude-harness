# プロンプトから経緯の記述を外し、今のルールと理由だけにする（#506）

`/claude-api prompt-audit` の監査で、参照文書に「以前はこうだった」「○月○日に事故があった」という経緯の記述が残っていることが分かった。モデルは指示を文字どおりに読むので、廃止した旧ルールをまだ選択肢の一つとして想像したり、日付付きの出来事から損の大きさを推し量ろうとしたりする。今のルールとその理由・破ったときに何が起きるかだけを書く形に直した。

- `references/model-tiers.md` / `references/workflow-execution.md`: 由来だけを示す issue 番号への言及を削除し、引き継いだ経緯を書かずに今の対応表・集約先だけを説明する文にした
- `skills/develop/references/decision-criteria.md`: 境界を決めた issue 番号への言及を削除。境界値の `300` 秒はそのまま残す
- `skills/develop/references/roles/worker.md`: 特定時期の監査結果への言及を、Fable にすると枠の大半をこの行だけで使うという仕組みの説明に、事故発生の経緯への言及を、同じ規則を複数の面に書くと片方が漏れ食い違った規則で事故が起きるという仕組みの説明に書き換え
- `skills/develop/references/roles/gate-runner.md`: 特定日のレビュー実例への言及を、手順の食い違いが引き起こす結果の説明に書き換え
- `skills/pr-review-gate/SKILL.md`: 2 箇所の日付付き理由を、主が避けたい消費・止まったサブエージェントは再起動されないという仕組みの説明に書き換え。Codex の呼び出し規約・出力形式という変わりやすい外部仕様に付いた確認日の 2 件は残す判断済み
- `references/subagent-waiting.md` / `tests/subagent-waiting.bats`: 上記と同じ言い換えの重複箇所を揃えて直す
- `tests/test_codex_develop.py`: `decision-criteria.md` から由来番号への依存を削除したことに伴い、そのアサーションを削除。境界値 `<= 300` / `> 300` の検査は保持

`plugins/capability-registry/skills/capability-registry/SKILL.md:38` の PR 番号と `.claude/casting/precedents.md` は実装例・判例台帳として意図的に残す対象なので触っていない。
