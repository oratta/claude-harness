# rm-permission-guard: 権限確認を省くモードの子の、rm の判定に当たらない確認画面を拒否する（#1610）

flatmate #2061 の子の作業者が `gh issue comment 2061 --body "$(printf '...')"`（rm を含まない。本文に `$(printf ...)` と逆引用符が多い）を打ったところ、Claude Code 本体の確認画面「Dangerous rm operation not ruled out — the shell may read this command differently than it was parsed」が出て、誰も見ていない子が約 30 分止まった。`--dangerously-skip-permissions` でもこの確認は出る。`rm-permission-guard.sh`（#1134）は先頭の語が rm のときだけ答えるので、この確認には何も返していなかった。

- `scripts/rm-permission-guard.sh`: `agent_id` が空でない文字列で、コマンドが rm の入口の形（共通ファイルの `is_rm_command`、読めないときは同じ形の簡易判定）に当たらず、`permission_mode` がちょうど `bypassPermissions` のときは `decision.behavior: deny` を返す。message は `[dev-workflow rm-permission-guard]` で始め、rm の判定に当たらないコマンドで本体が確認を求めたので実行していないこと・原因が本文の引用や置換（`$(...)`・逆引用符）なら本文をファイルに書いて `--body-file` で渡すなどの形で打ち直せること・打ち直せなければコマンドの全文を報告に書いて親に返ることを書く。許可（`permits/`）は探さず、拒否の記録（`denied/`）と `permit-log.jsonl` も書かない。rm の答え方は変えていない。`is_rm_command` と `hooks/hooks.json` は変えていない
- bypassPermissions に絞った理由: 入力に確認の種類が無く、default などでは同じ hook が普通の権限確認（作業ディレクトリへの書き込みなど）でも呼ばれるので、見分けずに拒否すると画面で主が承認する流れが壊れる。bypassPermissions で確認画面が出るのは規則で許可できない安全確認だけなので、普通の確認を巻き込まない。`permission_suggestions` が空かどうかは公式に約束された性質ではないので使わない
- `tests/rm-permission-guard.bats`: `call` に `permission_mode` を渡せるようにし（既定は `default` のまま）、bypassPermissions の子の rm でない確認の deny と message・記録を作らないこと・共通ファイルが無いときも deny・default / acceptEdits / plan / 無い / 文字列でないの子と bypassPermissions の主には何も返さないこと・bypassPermissions の子の rm は今までどおり許可で答えることのテストを足した
- 実機確認（Claude Code 2.1.321、tmux の対話セッションで `claude --dangerously-skip-permissions --plugin-dir <worktree>/plugins/dev-workflow`）: 子が flatmate #2061 の本文と同じ形のコマンド（先頭を `true` に替えたもの）を打つと、変更前は子の確認画面「Dangerous rm operation not ruled out」で止まり、変更後は確認画面が出ずに deny され、子が message をそのまま報告に引いて返った。子の PermissionRequest の入力の `permission_mode` は `bypassPermissions` だった。`claude -p` では 2.1.321 の子は確認の対象になるコマンドでも PermissionRequest が呼ばれずに実行されたので、`-p` では確かめられない。結果は PR に載せる
- 範囲外: default などで動く子の、rm でない安全確認（画面を見る人がいる前提のモードとして本体の確認画面に任せる）。無人の印（`DEV_WORKFLOW_UNATTENDED`）での切り替え。`/bin/rm` などを rm の入口に入れること
- 受け入れること: bypassPermissions の子が、rm の判定に当たらない別種の安全確認（`/bin/rm`・critical path への書き込みなど）で、主の画面に上がらずに拒否されること（子が親に返り、主には報告で届く）
- 戻し方: この PR の差分を戻す
