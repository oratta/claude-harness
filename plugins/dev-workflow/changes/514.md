# 一周目のレビュアー差分を区画に分ける（#514）

差分が 600 行を超える PR では、Claude の一周目レビュアーがコンテキスト上限に達しやすかった。区画を計算する `scripts/review-partitions.sh` と、その区画を渡す pr-review-gate・develop の手順、G の三表照合と補足の規則を追加した。Codex のレビュアーは差分全体を 1 体で見る。

- `review-partitions.sh`: PR files API の追加＋削除の合計を使い、600 行を超えたときだけパス順に 400 行までファイル単位で詰める。400 行超のファイルは単独の区画にし、0 行のファイルは直前の区画に入れる。形式が崩れた入力は標準出力を空にして exit 2、空入力は `合計: 0 行` と `区画: なし` を出す
- `stages/prepare.md`: 計算結果を `レビュー重量:` コメントと `needs-reviewer` payload に残す。従来経路の Task サブエージェントにも同じ区画計算を使う
- `stages/reviewer-brief.md`・`stages/review-run.md`: Claude の区画ごとの起動・読む範囲・`P<k>-` ID・対象外の受け入れ条件・文字どおり `<rev>`・区画 1 だけのテストと lint 再実行を定める
- `develop/SKILL.md`: 区画ごとの並列起動後、全区画の要約を 1 体の G に渡す。補足では一周目の区画構成を保ち、executor が変わっても残差だけを補う
- `gate-runner.md`: 区画数を先に照合し、受け入れ条件とハンクは全区画の和集合、照合表は区画ごとに検査する。残差の補足先を決め、補足済み回数は PR で 1 つに保つ
- `tests/`: 区画計算の境界・0 行・不正入力・空入力と、各指示書の契約を検査する

## 決めたこと（design の決定 1〜8）

1. ファイル単位の区画をスクリプトで決定的に計算する。0 行ファイルは直前に付ける
2. Claude だけを区画化し、Codex は差分全体を渡す
3. 区画 k の変更点・finding ID は `P<k>-` で始める
4. 受け入れ条件・ハンクは区画の和集合で、照合表は区画ごとに検査する
5. 検索コマンドには SHA の代わりに文字どおり `<rev>` を書く
6. テスト・lint の再実行は区画 1 だけが行う
7. G が区画を計算し、`レビュー重量:` コメントと payload に残す
8. 区画レビュアーを並列に起こして 1 体の G に集め、補足は残差のある区画だけにする

## 受け入れたリスク

- 区画をまたぐ暗黙の食い違いは、変更点の検索語に出ない限り三表では見つからない
- 区画の数だけ起動の固定分が増える。上限超過による交代が減る見込みだが、事後計測で確かめる
- G は全区画の三表を読むため、大きい PR では G 自身が上限に近づく可能性が残る
- files API と既存の light / full 判定の行数は数行ずれる場合がある
- Codex が大きい差分で三表を欠く場合は G が fail-closed で止める
- 被覆の残差が区画 1 に集まる可能性がある

受け入れ条件 5 の事後計測はマージ後の develop PR 5 本が対象なので、(3b) でエピック #511 の子 issue に移す。この工程では起票せず、合否にも使わない。
