# 手渡し規則の本文が 1 箇所にあることの機械検査（逐語一致だけ・#265）

PR #253 で手渡し規則の本文を `skills/develop/references/decision-criteria.md` の「コンテキスト上限（サブエージェントの手渡し）」節に畳んだが、「1 箇所にしかない」ことの機械検査は無かった。言い換えの検出は原理的に完全にはできない（#253 で 7 周続けて fail-open で落ちた）ので、**作る**と決め、検査は逐語一致に絞った。

- 追加: `plugins/dev-workflow/tests/handoff-single-source.bats` と `tests/lib/handoff-verbatim.py`。正本の節の 40 文字以上の一文が、正本以外の追跡ファイルに逐語で現れたら落ちる。除外は正本自身だけ（履歴・テストも対象）
- 緑が保証しないこと（言い換え・語順違い・一文を割った写し・短い句）はテストのコメントと新 spec `dev-workflow-handoff-single-source` に明記した。「言い換えは検出しない」を固定するテストもある
- 何も見ていない緑を避けるため、節から 20 文以上読めていること、節が読めなければ失敗すること、実際に貼ると落ちることを別のテストにした
- 変異の確認: `plugins/dev-workflow/README.md` に正本の一文を貼ると `COPY plugins/dev-workflow/README.md` を出して落ち、戻すと通る
- 既存の `dev-workflow-develop` spec と `decision-criteria.md` は触っていない（オーナーのマージ待ちの #661 が同じファイルを変更中のため。新しい spec ファイルに分けた）
