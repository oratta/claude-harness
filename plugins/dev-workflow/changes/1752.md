# dev-workflow: Orca keepalive の履歴解除と到達確認を分離（#1752）

送信前二度の観測では古い背景待機の解除条件を維持し、送信後だけ履歴解除結果を到達条件から外す。古い待機→既知完了→送信文エコーが残っても、新しい前景スピナーまたは `esc to interrupt`、一意な既知入力枠全体・任意 draft の空欄、既知フッター、dialog 不在を確認できれば `sent` とする。エコーだけ・背景待機だけ・入力済み・未知枠・未知フッター・不正な観測では `failed send` とし、再送・入力消去・端末作成/終了・待機は行わない。

回帰 fixture は実機 send / 返事 / cache 利用の証拠ではなく、これらは未確認。親向け `epic-keepalive-watch.md` に、背景待機の `skipped busy` は正しい非送信であること、別の会話15万トークン未満・前景の入力待ち・通常の声かけ条件を満たす子を選ぶこと、候補が無ければ実機確認を未完了にする手順を追記した。実機の識別子・会話量・入力待ちの根拠・send 結果・予約文への返事・その後の request の `cache_read_input_tokens` と会話量の比較は #1728 / #1732 に残す。生ログを repo に置かず、保存先は `LLM_LOG_DIR`、未設定なら確認する。

P2-F2 の非bypass未知フッターは実画面未確認・未対応のまま認識を拡張しない。仕様段の 2026-11-23 / Orca 1.4.269 の読み取り（`orca terminal list --limit 100 --json` と `orca terminal read --terminal <handle> --screen --json`）では、対象repoのClaude端末10件すべてがsource=screen・bypass、非bypass候補0件、一覧truncated=falseだった。実装段の追加実画面観測は無い。未知フッターの合成回帰を実測と称さず、将来の対応には版・取得方法・匿名化した構造の記録と別途レビューが必要。
