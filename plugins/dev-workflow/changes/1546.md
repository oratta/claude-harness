# develop: エピックの子の止まりの手順から mark をなくし、定型の止まりを発言の行で渡す（2 本目 epic-child-stop-drop-mark。#1382）

1 本目（`changes/1382.md`）で親の見張りが子の会話ログから止まりに気づくようになったので、子が親に止まりを気づかせるための手順は要らなくなった。この 2 本目で、子の手順から `mark stopped` / `mark resumed` をなくし、`子の停止: 主の返事待ち` の記録を PR のリスク許容で止まるときだけにする。

- `references/epic-child-stop.md`: `mark` と「記録と印」の語をなくした。止まり方を、記録を残す止まり（PR のリスク許容）、定型の止まり（PR のマージ待ち・PR トークン上限・CI の見張りの上限で、最後の発言の末尾に `止まった理由:` の行を書く）、そのほかの止まり（最後の発言で質問・推奨・根拠を書く）に分けた。`--relayed` / `--delegated` と委任の条件の文は変えていない
- `references/epic.md`: 手順 8 に「今回の止まった理由」の定義を 1 か所置いた（今回の停止の記録があればその値、無ければ `child-log --last` の `.text` のうち行頭が `止まった理由: ` の最後の行の値）。分岐の文、マージ待ちの子、PR トークン上限の子はこの語で読む。手順 7・8 の `dismiss` の条件に `止まった理由:` の行が無いことを足した。行は子の発言なので、この行だけでは何も承認しない
- `references/parent-pass-criteria.md` / `parent-merge-criteria.md`: 記録を前提にした文を、記録か最後の発言を読む文に直した。記録の無い止まりでは、条件表の「子の記録」は最後の発言を指す
- `references/ci-watch.md`: `escalate` と `none` と `human-merge` の止まりを、`mark stopped` ではなく最後の発言の行で止まる形に直した。見張りの終了のコメントは今までどおり投稿して終える
- `skills/develop/SKILL.md`: 別セッション方式の子は、PR トークン上限の見込みを `止まった理由:` の行に続けて書く
- `scripts/stop-judge.sh`: 止まりの `.text` に行頭 `止まった理由: ` の行があるのに `判断: 問いではない` を出した出力を形の崩れにする
- `scripts/epic-dispatch.sh`: `mark stopped` / `mark resumed` は更新前の版の子のために受け続ける。動作は変えていない（コメントだけ）
- 移行: 更新前の版の子は定型の止まりでも記録を残すので、親は記録を先に読み、読めば今までどおり分岐する。子の `mark` もそのまま受ける。手での移行は要らない
- 受け入れること: 子が `止まった理由:` の行を書き誤ると、親は定型の分岐に入らず、ほかの止まりとして主に上げる
- 戻し方: この PR の差分を戻す。記録の形も状態ファイルも変えていないので、データの移行は要らない
