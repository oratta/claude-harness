# parent-pass-criteria: CI の見張りのやり直しの上限の節の対象を、前提欄と job-timeout の escalate まで広げる（#1280）

PR #1268 が足した節「CI の見張りのやり直しの上限で止まった子」は、対象を「`止まった理由:` が、同じ HEAD のやり直しを使い切ったことを挙げている止まり」に限っていた。`epic-child-stop.md` は `止まった理由:` を「主にしてほしいこと」と定めているので、使い切った事実は `前提:` に書かれやすく、その止まりが対象から漏れていた。

- `skills/develop/references/parent-pass-criteria.md`: 節の「対象」を、使い切った事実が `止まった理由:` と `前提:` のどちらに書かれていても対象とするよう直した。`job-timeout` の `escalate` は、記録にそう書かれていなくても常に対象とする（`pr-state.sh` の `decide` は同じ HEAD のやり直しを使い切ったあとにだけ `job-timeout` の `escalate` を返すため）。通す場合・主に上げる場合・返事は変えていない
- `openspec/specs/dev-workflow-develop/spec.md`: 同じ要件の対象の場面を合わせた（文言合わせ。差分は 1 行）
- `tests/epic-dispatch.bats`: 該当テストに、`前提:` も対象であること、`job-timeout` の `escalate` が常に対象であることの検査を足した
- 戻し方: この PR の差分を戻す。状態や仕組みは変えていない
