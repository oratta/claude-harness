# pr-review-gate: needs-reviewer の payload に full（Codex オフ）の判定値と証拠欄の値を足す（#1019）

従来経路の G が full かつ Codex オフで `needs-reviewer` を返すときの書式に、オフの判定値と証拠欄の値が無かった。雛形どおりの G は `判定: full（Codex 不可）` と書き、次の G が「（full・実測した Codex 不可: …）」を投稿しうるので、spec の「light・実測した Codex 不可・設定によるオフの 3 つを PR コメントから判別できる」が読み替え次第になっていた（PR #1003 のゲートの指摘）。

- `skills/pr-review-gate/stages/prepare.md`: payload の `判定:` に `full（Codex オフ）` を足した。`根拠:` に `Codex オフ（設定）`、`選んだ経路`・`終了コード`・`実待ち時間` に `未実行（Codex オフ）`、`実行コマンド` に `python3 <plugin>/scripts/usage_view.py --codex-enabled → off`、`出力の要点` に `Codex オフの設定により Codex を試していない` を足した。値は `stages/review-run.md` の雛形に揃えている。基本 payload を使う場合の列挙にも Codex オフを足した
- `tests/pr-review-gate-skill.bats`: 「オフの判定は review-run.md だけに書く」検査から、prepare.md の `- 実行コマンド:` で始まる行だけを除いた。この行は証拠の値で、手順ではない。prepare.md の他の行に `--codex-enabled` が増えれば引き続き落ちる
- `tests/develop-adapter-review-routing.bats`: 判定の行の期待文字列を合わせ、オフの根拠と証拠欄の値を確かめるテストを足した
- 要件は変えていない。`openspec/specs/dev-workflow-pr-review-gate/spec.md` の既存の要件に payload を揃えただけ
- オフの判定の手順、`review-run.md`、adapter 経路の値は変えていない
- 戻し方: この PR の差分を戻す。状態やファイルの移行は要らない
