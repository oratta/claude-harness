# pr-review-gate: レビュアー向け指示の「ハンク被覆」に、正確なハンクヘッダーが要ることと省略形で代用しないことを足す（#1774）

PR #1772 の一周目レビューで、レビュアーがハンクヘッダーを省略した形で返し、G の正確なハンク照合で未被覆になる例があった。レビュアー側の指示にも、G が受理する形を書いた。

- `skills/pr-review-gate/stages/reviewer-brief.md` の指示ブロック 3.（`ハンク被覆`）: ハンクの行は `git diff` の正確なハンクヘッダー（新規ファイルは `@@ -0,0 +1,N @@`）で書く。旧行範囲だけ・閉じる `@@` のない形・「新規」だけ・他区画への言及だけは被覆に数えない。G 側の受理形式（`stages/gate-triage.md` 手順 3）と同じ内容で、G の動きは変えていない
- 区画レビュアーの読む範囲とトークン消費（#1692）は変えていない
- 読み込み予算（`tests/gate-reading-budget.txt`）は聖域なので動かさず、同じファイルの次の 3 か所を縮めて収めた。どれも「誰が何をするか」を変えない、理由・例・記録先の言い回しだけの短縮
  - 冒頭の `## 条件の答え` の括弧から理由の文（「主が既に答えた条件を、レビュアーと G がもう一度聞かないため。」）を削除。起こす側が行を依頼文に入れる手順は同じ
  - Codex 読み替え表の `confidence_score` の行から、括弧の ``（`confirmed` は実行・テストで裏取りしたことを指す）`` を削除。同じファイルの指示ブロックの `検証` の欄に `confirmed` の定義（実行・テストで裏取り済み）があり、その再掲を消しただけで、読み替えの扱いは同じ
  - Codex 読み替え節の `（2026-09-21 に実測。#349 の PR コメントに記録）` を `（実測済み）` に短縮。実測の日付と記録先の案内が消えるだけで、読み替えの表と手順は同じ。理由の文の削除と上の再掲の削除だけでは足した文の分を収められず、この短縮も予算に使っている
- `#1401` の段落の例示の括弧（`bats のほか、`…）は `plugins/dev-workflow/tests/develop-adapter-review-routing.bats` が文言を固定し、`references/codex-develop.md` の同じ規則とも揃えてあるので縮めていない
- 契約テストの原文照合用データ `tests/fixtures/gate-contracts/blocks.json`（指示ブロック）と `prose.json`（上の 3 か所）を、変えた文に合わせた
- 範囲外: `tests/develop-epic-scene-budget.bats` は HEAD（dcfb6301）でも `nested-stop` / `nested-delegated` の予算超過で落ちる。この変更では直さない
- 戻し方: この PR の差分を戻す
