## 主の手でしかできない操作の例（change owner-hands-only-ops）

主の手でしかできない操作の例を、OAuth・ログイン・ダッシュボードの操作から、パスワード・MFA・CAPTCHA（エージェントの手では通せないもの）に替えた。ログイン済みのブラウザで押せる操作（OAuth の認可ボタン・チャットの板の作成など）は主の手の操作に入らない。主の名義で外へ公開・送信する・課金する・取り消せない操作は、手が要るからではなく規則が主の承認を求める操作として聞く。文面だけの変更で、スクリプトと hook は変えていない。

- `skills/develop/SKILL.md` の節「主に聞かずに決めること」: 例を替え、ログイン済みのブラウザで押せる操作を外す文と、主の名義で外へ出る操作を承認の側で聞く文を足した
- `skills/develop/references/parent-pass-criteria.md`: 条件「実機操作でない」の中身と通らない例の「実機操作」を同じように替えた（条件の数と名前は変えていない）
- `skills/develop/references/epic.md` 手順 8: 待ちに入る通知に書く「実機操作」の例を同じように替えた
- `output-styles/readable.md` の節 3: 主に聞く理由「主の手でしかできない操作」の例を、パスワード・MFA・CAPTCHA と人が押すと決まっているマージに替え、ログイン済みのブラウザで押せる操作は入らないと書いた（製品名は書いていない）

直さなかった箇所: `rules/communication-style.md`（例を持たない）、issueify の `human-only`（無人ループで完結できるかの基準で、主の操作の定義とは別）、parent-pass-criteria の「ランナーの機械での操作（ログイン…）」（別の機械の操作の話）、capability-registry の「OAuth アプリ承認」（CLI でできないことの一覧）。

## メモリの `patches:` の issue が閉じたら知らせる（change memory-patches-tripwire）

ハーネスの動きへの指摘をメモリにその場しのぎで書くと、ハーネスが直ったあともメモリが新しい規則を上書きし続ける。メモリと直し先の issue を結び付け、issue が閉じたら気づけるようにした。

- `rules/plugin-editing.md`: プラグインの動きへの指摘をメモリに書くときは、同じターンで直し先の issue を立て、frontmatter に `patches: <issue の URL>` を書く 1 行を足した（全プロジェクトのセッションに常時読み込まれる）。`rules/README.md` の行も合わせた
- `scripts/memory-tripwire.sh`: frontmatter の `patches:`（`metadata:` の下とトップレベル。値は GitHub の issue の URL 1 本）を読み、URL ごとに 1 日 1 回 `gh issue view` で状態を確かめる。閉じていれば既存の `[memory]` の 1 行に「ファイル名 ← URL」で足す（閉じ方は分けない）。初めてネットワーク（`gh`）を使い、メモリディレクトリの外に控えを書く
  - 控えの場所: `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/.memory-patches-cache.tsv`（`DEV_WORKFLOW_MEMORY_PATCHES_CACHE` で変えられる）。1 行が URL・確かめた日・状態（`OPEN` / `CLOSED` / 確かめられなかった `UNKNOWN`）・閉じ方。別のファイルに書いてから置き換える
  - 待ち時間: `patches:` が無いか、その日の控えがあるときは 0.5 秒未満。その日の最初のセッションで控えの無い URL があるときだけ、最大 `DEV_WORKFLOW_MEMORY_PATCHES_TIMEOUT` 秒（既定 3）待つ。時間切れの `gh` は自分が起こした PID だけを止める
  - 止め方: `DEV_WORKFLOW_MEMORY_PATCHES_TIMEOUT=0` で `gh` を呼ばない。`gh` が無い・認証切れ・オフラインのときは何も表示せず、セッションの開始を止めない（`gh` が無いとき以外は、その日は `UNKNOWN` と控えて確かめ直さない）
- `skills/memory-refresh/SKILL.md`: `patches:` の書き方の正本を置き、分類の削除に「`patches:` の issue が完了（`COMPLETED`）で閉じた」を足した。完了以外で閉じたものは、動きが直ったかを確かめてから分類する
- `tests/injection-budget.txt`: 常時注入の予算を、readable.md の例の差し替えと plugin-editing.md の 1 行を足した後の実測 42,471 バイトに合わせた（足す前の余裕は 0 バイトだった。他の文は削っていない）

戻し方: この PR の差分を戻し、控えのファイル（`${CLAUDE_CONFIG_DIR:-$HOME/.claude}/.memory-patches-cache.tsv`）を消す（残っても読まれないだけで害は無い）。
