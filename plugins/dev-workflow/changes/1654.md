## 主の手でしかできない操作の例（change owner-hands-only-ops）

主の手でしかできない操作の例を、OAuth・ログイン・ダッシュボードの操作から、パスワード・MFA・CAPTCHA（エージェントの手では通せないもの）に替えた。ログイン済みのブラウザで押せる操作（OAuth の認可ボタン・チャットの板の作成など）は主の手の操作に入らない。主の名義で外へ公開・送信する・課金する・外部のアプリやサービスに権限を渡す（OAuth の認可を含む）・取り消せない操作は、手が要るからではなく規則が主の承認を求める操作として聞く（OAuth の認可は取り消せるうえ公開・送信・課金のどれでもないので、名指ししないと承認の側から抜ける）。文面だけの変更で、スクリプトと hook は変えていない。

- `skills/develop/SKILL.md` の節「主に聞かずに決めること」: 例を替え、ログイン済みのブラウザで押せる操作を外す文と、主の名義で外へ出る操作を承認の側で聞く文を足した
- `skills/develop/references/parent-pass-criteria.md`: 条件「実機操作でない」の中身と通らない例の「実機操作」を同じように替えた（条件の数と名前は変えていない）。条件「聖域でない」に外部のアプリやサービスへの権限の付与（OAuth の認可を含む）を足した
- `skills/develop/references/epic.md` 手順 8: 待ちに入る通知に書く「実機操作」の例を同じように替えた
- `output-styles/readable.md` の節 3: 主に聞く理由「主の手でしかできない操作」の例を、パスワード・MFA・CAPTCHA と人が押すと決まっているマージに替え、ログイン済みのブラウザで押せる操作は入らないと書いた（製品名は書いていない）。主に聞く理由「決まりで主の承認が要る」に、主の名義で外へ公開・送信する・課金する・外部のアプリやサービスに権限を渡す操作を足した（develop を使わないメインセッションにも効かせるため）

直さなかった箇所: `rules/communication-style.md`（例を持たない）、issueify の `human-only`（無人ループで完結できるかの基準で、主の操作の定義とは別）、parent-pass-criteria の「ランナーの機械での操作（ログイン…）」（別の機械の操作の話）、capability-registry の「OAuth アプリ承認」（CLI でできないことの一覧）。

## メモリの `patches:` の issue が閉じたら知らせる（change memory-patches-tripwire）

ハーネスの動きへの指摘をメモリにその場しのぎで書くと、ハーネスが直ったあともメモリが新しい規則を上書きし続ける。メモリと直し先の issue を結び付け、issue が閉じたら気づけるようにした。

- `rules/plugin-editing.md`: プラグインの動きへの指摘をメモリに書くときは、同じターンで直し先の issue を立て、frontmatter に `patches: <issue の URL>` を書く 1 行を足した（全プロジェクトのセッションに常時読み込まれる）。`rules/README.md` の行も合わせた
- `scripts/memory-tripwire.sh`: frontmatter の `patches:`（`metadata:` の下とトップレベル。値は GitHub の issue の URL 1 本）を読み、セッションの開始時に URL ごとの状態を裏のプロセスで `gh issue view` に確かめて控えに書く。開始の処理は控えだけを読み、閉じていれば既存の `[memory]` の 1 行に「ファイル名 ← URL」で足す（閉じ方は分けない）。知らせは確かめた次のセッションに出る（閉じたあと 2 回目のセッションになることがある）。初めてネットワーク（`gh`）を使い、メモリディレクトリの外に控えを書く
  - 控えの場所: `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/.memory-patches-cache.tsv`（`DEV_WORKFLOW_MEMORY_PATCHES_CACHE` で変えられる）。1 行が URL・確かめた日・状態（`OPEN` / `CLOSED` / 確かめられなかった `UNKNOWN`）・閉じ方。別のファイルに書いてから置き換える。裏の確認が走っている間は、控えのパスに `.lock` を付けた目印のディレクトリを置き、同時に 2 つ走らせない（古い目印は取り直す）
  - 待ち時間: 照会は裏で走るので、開始はいつも 0.5 秒未満（GitHub への照会は 1 回 0.37〜0.73 秒かかり、開始で待つと 0.5 秒に収まらないため、主の決定でこの形にした）。裏の確認は標準入出力を閉じて起こし、hook を待たせない。当日に閉じたと控えた URL のほかを確かめ直し、最大 `DEV_WORKFLOW_MEMORY_PATCHES_TIMEOUT` 秒（既定 3）で打ち切る。時間切れの `gh` は自分が起こした PID だけを止める。上限は `TIMEOUT` 秒の `sleep` を時計にして秒で決め、待ちの刻みの数に頼らない（負荷で刻みが遅れても延びない）
  - 止め方: `DEV_WORKFLOW_MEMORY_PATCHES_TIMEOUT=0` で `gh` を呼ばない。`gh` が無い・認証切れ・オフラインのときは何も表示せず、セッションの開始を止めない（`gh` が無いとき以外は `UNKNOWN` と控え、閉じたとして扱わず、次のセッションで確かめ直す）
- `skills/memory-refresh/SKILL.md`: `patches:` の書き方の正本を置き、分類の削除に「`patches:` の issue が完了（`COMPLETED`）で閉じた」を足した。完了以外で閉じたものは、動きが直ったかを確かめてから分類する
- `tests/injection-budget.txt`: 常時注入の予算を、main の 42300 から 43034 バイトへ 734 バイト上げた（今の実測は 43032 バイトで、予算との差は 2 バイト）。readable.md の例の差し替え、plugin-editing.md の 1 行、readable.md の承認の項目へ権限を渡す操作などを足した分で、他の文は削っていない。実測に合わせて緩めるのではなく、主が上限の引き上げを許容した（リスク宣言への追記 https://github.com/oratta/claude-harness/pull/1655#issuecomment-6965464418 ）うえでの値
- `tests/develop-startup-budget.txt`: `skills/develop/SKILL.md` の起動時の予算を、main の 94392 から 94916 バイトへ 524 バイト上げた（今の実測も 94916 バイトで、予算と同じ）。節「主に聞かずに決めること」の例の差し替えと 2 文、承認の側に権限を渡す操作を足した分で、足した文は仕様が必須とする内容、他の文は削っていない。主が上限の引き上げを許容した（リスク宣言への追記 https://github.com/oratta/claude-harness/pull/1655#issuecomment-6965464418 ）うえでの値
