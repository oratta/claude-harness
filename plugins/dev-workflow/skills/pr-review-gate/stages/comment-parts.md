# comment-parts — pr-review-gate

## コメント長の上限を超えるとき（三表と順 3 の一覧）

`レビュー三表:` のコメントと `## 一覧（順 3）` のコメントが GitHub のコメント長の上限（65,536 字）を超えるときの規則。本文を行の境界で切って部分のコメントに置き、見出しの行と部分の URL だけを持つ親のコメントで結ぶ。読む側は部分を連結するだけで元の本文に戻るので、表の形式も照合の経路も変わらない。

**測り方**: 長さは `wc -c` のバイト数で測る。バイト数は字数より小さくならないので、GitHub がどちらで数えていても上限を超えない。コメント全体が 65,536 バイト以下なら分けずにこれまでどおり 1 件に置き、`部分 k/n:` の行は書かない。字数で収まってもバイト数で超えれば分ける。

**親と部分の形**: 親のコメントは下の表の見出しの行だけを持ち、本文（表）を置かず、続けて `部分 k/n: <コメントの URL>` の行を k の順に n 行置く。部分のコメントは 1 行目と 2 行目を下の表のとおりにし、3 行目を空行にして、4 行目以降に元の本文を置く。部分のコメントはそれぞれ、先頭の 3 行を含めて 65,536 バイト以下にする。

| 種類 | 親の 1 行目と見出しの行 | 部分の 1 行目 | 部分の 2 行目 | 部分に置く本文 |
|---|---|---|---|---|
| 三表 | `レビュー三表:`、`固定 HEAD: <40 桁>`、`一周目の区画: <なし \| n>`、`補足済み回数: <0 \| 1>` | `レビュー三表の部分 k/n` | `固定 HEAD: <40 桁>` | 元の三表の全部 |
| 順 3 の一覧（順 6 の裁定「全部列挙してから直す」の一覧を含む） | `## 一覧（順 3）`、`修正前 SHA: <40 桁>`、`検索コマンド: <コマンド>` | `一覧（順 3）の部分 k/n` | `修正前 SHA: <40 桁>` | 主表と補助表の全行。全ヒット要約に置き換えない |

**切り方**: 本文を行の境界で切る。部分を k の順に連結すると元の本文の行の並びに戻るようにし、表の見出しを部分ごとに繰り返さない。部分を空行で終えない（読むときに末尾の改行といっしょに落ちるので、空行は次の部分の先頭に送る）。切ったら各部分のコメントを `wc -c` で測り、65,536 バイト以下であることを確かめる。

**投稿の順**: 部分を k の順に `gh pr comment <PR> --body-file <file>` で投稿し、標準出力の URL を受け取る。全部の部分を投稿してから、親を最後に投稿する。三表は照合と振り分けの G が補足の `needs-reviewer` を返す前に、順 3 の一覧は W が push の前に、部分と親の投稿を終える。親を最後にするのは、途中で止まっても読み手が不完全な組を見ないようにするため。親のない部分は読まない。

**読み方**: 最新の親を探すときは、1 行目が `レビュー三表:` または `## 一覧（順 3）` のコメントだけを親として扱う（`レビュー三表の部分 k/n` と `一覧（順 3）の部分 k/n` は親ではない）。親に `部分 k/n:` の行が無ければ、これまでどおり親の本文を読む。行があれば、次の手順で表ファイルを作る。

1. 親に `部分 k/n:` の行が n 行そろっていることを確かめる
2. `<table-file>` に、親の見出しの行と空行をこの順に書く（`部分 k/n:` の行を入れない）
3. k の順に、親の行の URL の末尾 `#issuecomment-<コメント ID>` から ID を取り、次の 2 行で部分の本文を足す。`$R` は `<owner>/<repo>`。本文を会話に出さない

```bash
body="$(gh api repos/$R/issues/comments/<コメント ID> --jq .body)"
printf '%s\n' "$body" | tail -n +4 >> <table-file>
```

`$(...)` が各部分の末尾の改行を落とし、`printf '%s\n'` が行区切りを 1 個戻すので、部分の間には行区切りが 1 個だけ残る（行同士がつながらず、表の途中に空行も入らない）。`tail -n +4` は部分の先頭の 3 行を除く（残すと 2 行目の SHA の行が 2 回現れ、`review-hit-set.py` が contract エラーを出す）。

足す前に部分ごとに次を確かめる。`gh api repos/$R/issues/comments/<コメント ID> --jq .issue_url` の末尾の番号が同じ PR であること（別の PR のコメントなら連結しない）、部分の 1 行目の k/n が親の行と一致すること、部分の 2 行目が親の SHA の行（三表は `固定 HEAD:`、順 3 は `修正前 SHA:`）と一致すること、n 件すべて取得できたこと。部分の中の行の欠落は、ここでは確かめず、既存の照合が差分として拾う。

**読めないときの扱い**:

- 三表: 部分が読めない、または親と対応しないときは、元の三表の欠落として残差に記録し、Status `review-incomplete` で return する。合格処理へ進まず、2 回目の `needs-reviewer` を返さない
- 順 3 の一覧: `部分 k/n:` の行が n 行そろわない、部分が n 件取得できない、または部分が親と対応しないときは、照合を行わず W に表の出し直しを求める。順 3 の差し戻し 1 回に数える。W は親と部分を投稿し直し、G は最新の親を読む

**復元のあとの照合**: 分けないときの経路のまま。三表は、親の `一周目の区画:` と `補足済み回数:` を読み、連結した元の三表で同じ機械照合を行う。順 3 の grep の語は表ファイルを `review-hit-set.py` に渡す。順 3 の場合分けの軸はスクリプトへ渡さず、表の行の集合と軸の全域との集合一致だけを見る。

**1 行で部分に収まらないとき**: 1 行だけで部分に収まらない行（ミニファイされたファイルのヒットなど）があれば、そのコメントを投稿しない。W は投稿も push もせず、return で本体に報告する。G は補足の `needs-reviewer` を返さず、Status `review-incomplete` で return する（回数の記録が残らないまま補足を頼むと、補足済み回数が 0 に戻るため）。
