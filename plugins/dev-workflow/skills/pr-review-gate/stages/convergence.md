# 収束ルール — pr-review-gate

W の修正後の再レビューで、前提確認と重さ判定の G（develop 以外は本体）が周回と範囲を決めるときに読む。周の終わりの仕分けは `stages/triage.md`。

**収束ルール（レビュー周回のキャップ）**:

- レビューは**既定2周**（初回レビュー＋再レビュー1回）で確定する。3周目以降の周を開けるのは次の 3 つのときだけ（G も本体もこれ以外で開けない）: 直し方の判定（決める役）が「決まっている」で PR トークン上限の内側のとき（主に聞かずに開き、本体が記録先に事後報告を残す）、主が順 5 に「この PR で直す」と答えたとき、決める役が順 6 で「全部列挙してから直す」と裁定したとき（PR ごとに 1 回まで）。判定の記録と事後報告の書式の正本は develop の `references/fix-check.md` の節「レビューの周を主に聞かずに続ける（直し方の判定）」。
- **再レビューは差分限定**: 前回指摘が閉じたかの確認に限る。再レビューでの新規探索はしない。再レビュー中の新規の気づきは止めない指摘の振り分け表に通す。ただし例外 3 種（安全機構の穴・データ破壊・無言の機能不全）に当たる新規の指摘は差分限定の周でも受け取り、仕分け表に当てる。
- **例外: 方式の書き換えの後は全体レビューにする。** G は再レビューの前に、W の修正差分の行数と前周の指摘の対象行数を比べ、修正差分が大きく超えていれば（方式の書き換え）次の再レビューを PR 全体のレビューにする。2 つの行数を PR コメントに記録する。**周回は数え続ける**（1周目に戻さない。全体レビューになった2周目の結果にも `stages/triage.md` の仕分けをそのまま適用する）。
- **blocking の定義を限定する**: マージ後に issue で直せるものは blocking にしない。止めるかどうかは全周で「マージを止めるかの判定（全周共通）」で決める。
