# gate-triage — pr-review-gate

入口: 周の数に関係なく、レビュー要約または補足の結果を受け取ったときに読む。

## 一周目の三表を機械照合する

一周目のレビュー要約を受け取ったら、指摘の仕分け前に次を機械照合する。Gate Result に取り直し行がある周は周回 1 でも三表・区画の照合をせず再レビューの仕分けへ進み、過去の `レビュー三表:` の補足済み回数で `review-incomplete` にしない。G はここで変更点の意味や `一致` / `食い違い` の正しさを再レビューしない。

1. 記録先の各受け入れ条件が `変更点の一覧` の変更点 ID に 1 回以上対応しているかを集合比較する。
2. 各 `照合表` を `plugins/dev-workflow/scripts/review-hit-set.py --repo <repo> <table-file>`（`<repo>` はリポジトリルートのパスで、GitHub のリポジトリ名 `<owner>/<repo>` ではない） に渡し、固定 HEAD で再実行した repository-wide な grep の全ヒット集合と一致するかを確認する。`全ヒット要約:` の行を持つ表も同じコマンドに渡す（スクリプトが行数とハッシュで照合するので、全行の本文が無いことを表の欠落として扱わない。一致しなければ `summary:` / `extra:` の出力を残差にし、`contract:`（標準エラー出力）も残差にして、補足ではレビュアーが検索コマンドを実行し直して要約を出し直す。10 行以下の語は全行の表で出し直す）。場合分けの軸はこのスクリプトへ渡さず、軸の全域と表の行だけを比較する。
3. 固定した PR diff の全ハンク（新規ファイルの `@@ -0,0 +1,N @@` も含む）をファイルと正確なハンクヘッダーで列挙し、全区画の実際の被覆行の和集合と集合比較する。元の表と受領済みの補足を使い、「他区画で被覆済み」という文章だけやヘッダーが「新規」だけの行は被覆に数えない。補足を依頼する前に、未被覆の全ハンクをファイルと正確なハンクヘッダーの一覧にして補足要求へ含める。補足先と回数は既存規則に従う。

一周目の要約に区画の見出しがあるときだけ、区画数・ID と補足先の照合として `stages/gate-triage-partitions.md` を読む。

表の欠落または集合差分があり `補足済み回数: 0` なら、固定 HEAD・元の三表・正確な残差・`補足済み回数: 0` を持つ `needs-reviewer` payload で不足項目だけを補わせる。補足はレビューのやり直しではない。補足の `needs-reviewer` を返す前に、元の三表・`固定 HEAD: <40 桁>`・`一周目の区画: <なし | n>`・`補足済み回数: 1`（補足を頼んだ時点で 1 と数える。payload は 0 のまま）の行を持つ `レビュー三表:` のコメントを PR に投稿する（下の「段ごとの起動と入力」）。補足済み回数は最新の `レビュー三表:` のコメントから読み、fresh reviewer または fresh G へ交代してもリセットしない。

## 補足レビュー結果の受領

最新の `レビュー三表:` のコメントから元の三表・`一周目の区画:`・補足済み回数を読み、補足結果を加えて同じ機械照合を再実行する。一周目の区画の構成で和集合を再照合し、区画を計算し直さない。`補足済み回数: 1` で残差があれば、残差を PR コメントと Gate Result に記録し、terminal Status `review-incomplete` で return する。2 回目の `needs-reviewer` を返さない。手順 3 以降の合格処理へ進まない。差分が解消した場合だけ通常の指摘仕分けへ進む。


## 段ごとの起動と入力

- **レビュアーの要約受領**: `stages/triage.md` の「G として動くとき（develop）」節にある「レビュー実行者:」コメントを投稿してから、前の周の仕分けコメントに順 3 の指摘があれば、三表の照合より先に、その一覧表のコメント（`## 一覧（順 3）`）を `stages/triage-row3.md` の順 3 の 2 段で照合する（不一致の差し戻しは `stages/triage-row3.md` の順 3 の規則に従い、ここに新しい規則は足さない）。そのあと、一周目は最初に `変更点の一覧`・`照合表`・`ハンク被覆` を上の同名節どおり機械照合する。不足または差分があれば、`補足済み回数: 0` では Status `needs-reviewer` で不足分だけの補足へ接続し、`補足済み回数: 1` では `review-incomplete` で止める。三表の照合が完了したあとだけ要約に指摘が残っているかで分岐し、指摘が無ければ手順 3 以降（この G は宣言をせず、Status `次の段へ`・`次の段: 合格処理` で返す）。指摘が残っていれば、周の数に関係なく pr-review-gate 手順 2-1 の仕分け表（`stages/triage.md`）に上から当てる（順 1 は全周共通の判定）。止める指摘が無く順 1 だけなら、止めない指摘の振り分け表（`stages/triage-nonblocking.md`）に通す。1 周目に段 A に当たる指摘があれば `agent-review:failed` に付け替えて failed で返し、無ければ段 B 以降の結果を仕分けに記録してから（振り分けで issue にすると決まった指摘だけが follow-up issue になる）同じく `次の段へ`・`次の段: 合格処理` で返す。順 2〜4 は `agent-review:failed` に付け替えて failed で返し（止めない指摘は failed の PR コメントに一覧で残す）、順 5 は保留、順 6 は `needs-decider` で返す。ただし 2 周目以降の周の終わりには順 2〜4 をそのまま使わない。`stages/triage-convergence.md` の周の終わりの段落どおり、同じ型の再発は順 6、それ以外は判定に回す条件に当たれば `needs-fix-check`（直し方の判定。指摘ごとの仮の順を仕分けに記録する）、当たらなければ順 5 で返す。順 5 と順 2〜4、または順 5 と順 6 が混ざれば保留だけを先に返す。保留と `needs-decider` を同じ return で指示しない。判定に回す指摘と未裁定の順 6 が混ざれば `needs-fix-check` だけを先に返し、`needs-fix-check` と `needs-decider` を同じ return で指示しない（処理順は `stages/triage-convergence.md` の混在の段落）。仕分けは PR コメントに記録する
- **補足レビュー結果の受領**: 上の同名節どおり `補足済み回数: 1` を維持して三表を再照合する。残差があれば `review-incomplete`、無ければ同じ一周目の指摘仕分けへ進む

補足の needs-reviewer payload を組むときは `stages/prepare-reviewer.md` を読む。

三表のコメントが上限を超える、または部分コメントを復元するときは `stages/comment-parts.md` を読む。

出口: 照合が済んだら `stages/triage.md` の仕分けへ戻る。足りなければ本文の return で返す。
