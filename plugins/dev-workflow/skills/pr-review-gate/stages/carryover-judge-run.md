# 引き継ぎの終了コード 4 の判定役: 起こす側の手順 — pr-review-gate

判定役を起こす側（develop の本体・develop の外のメインセッション）だけが読む。回す条件と記録の選び方は `stages/carryover-judge.md`。develop の G は読まない。

##### 終了コード 4 の判定役（起こす側）

- **判定役**: `subagent_type: dev-workflow:decider`・`model: opus` で起こす（残量モードで上げも下げもしない）
- `SHARED_BUDGET_MODE=depleted` のときは判定役を起こさず、判定役を起こす側（develop の外のメインセッションではゲート自身、develop では本体）が `引き継ぎ判定: 判断できない`・`理由: 判定役を起こさなかった（共有枠 depleted）` の記録を投稿し、手順6で主に聞く側に倒す。develop の合格処理の G はこの記録を自分で投稿しない（二重投稿を避ける）
- **渡すもの**: `git diff --no-color --no-ext-diff --no-textconv <前 HEAD> <新しい HEAD> -- <EVIDENCE_PR_CHANGED のファイル>...` の出力と、前の宣言の本文（末尾の `主の回答:` 以降の追記行を除いた部分）の 2 つだけ。記録先の本文・レビューの指摘・W の return・作業の会話は渡さない
- **依頼文**: `agents/decider.md` の通常の 3 点（原因の分類・直し方・次のモデル）ではなく、次を求める。渡した 2 つだけから判定し、リポジトリを読み足さず、足りなければ「判断できない」と返す。返答の 1 行目は `引き継ぎ判定: 同じ`・`引き継ぎ判定: 変わった`・`引き継ぎ判定: 判断できない` のどれかちょうどにし、2 行目以降に理由（何が同じか・何が変わったか・何が足りないか）を書く。`agents/decider.md` の入力契約の 4 点はこの依頼には当てはまらず、渡した 2 つだけが入力であることも依頼文に書き、不足を理由に `不足:` で返さず 1 行目を必ず上の 3 形のどれかにするよう求める（`不足:` で返されると毎回「判断できない」に倒れるため）
- 「同じ」は、差分によって前の宣言のリスク内容・該当する観点・発生条件・影響範囲と戻し方のどれも変わらないことを指す
- 返答の 1 行目が 3 形のどれにも一致しなければ「判断できない」として記録し、依頼し直さない（主に聞く側に倒れるだけで、補える入力も無いため）
- **判定の記録**: 判定役を起こしたセッション（develop では本体）が、返答を次の書式で PR にコメントする（判定役は投稿できないので代理投稿する）。1 行目は正規表現 `^引き継ぎ判定: (同じ|変わった|判断できない)$` に完全一致させる。`根拠ファイル:` は `EVIDENCE_PR_CHANGED=` のファイルを 1 行にカンマ区切りで並べる。`対象 HEAD:` の文字列は使わない（auto-merge の workflow が宣言の照合に使うため）

```text
引き継ぎ判定: <同じ|変わった|判断できない>
前 HEAD: <40 桁フル SHA>
新しい HEAD: <40 桁フル SHA>
前の宣言: <前の宣言コメントのリンク>
根拠ファイル: <EVIDENCE_PR_CHANGED のファイル>, <ファイル>
差分の行数: <EVIDENCE_DIFF_LINES の値>
判定役: dev-workflow:decider / <モデル。起こさなかったときは「起こさず」> / 代理投稿 <投稿したセッションか本体の名前>
理由: <判定役の返答の 2 行目以降。起こさなかったときはその理由>
```
