# 照合と指摘の振り分け — pr-review-gate

以下 `$R` = `<owner>/<repo>`、`$N` = PR 番号。

パスは pr-review-gate 直下から。他の手順: `stages/prepare.md`（手順 1・2・2-0）、`declarations.md`（手順 3・3-b）、`stages/hold.md`（手順 3-c・6）。

## 入口

レビュー結果に指摘が残っているとき（develop の G は `skills/develop/references/roles/gate-runner-triage.md` の三表の機械照合を済ませたあと）、W の修正後の再レビュー、決める役の裁定または直し方の判定を受け取ったときに読む。

## 条件で読むファイル

このファイルは常に読む。次のファイルは、条件に当たるときだけ加えて読む。

| 条件 | 加えて読むファイル |
|---|---|
| レビュアーの要約か補足レビューの結果を受け取った | `stages/triage-summary.md`（develop の G は、一周目の要約と補足の結果なら `skills/develop/references/roles/gate-runner-triage.md` も） |
| W の `## 一覧（順 3）` のコメントを照合する | `stages/triage-row3.md`（戻した指摘が順 3 だけの修正のあとは `stages/prepare-step1.md` も） |

| 順 5・順 6・`needs-fix-check` に当たる、それらが混ざる、裁定か判定を受け取った | `stages/triage-escalation.md` |

## 手順

#### 2-1. レビューの実行（止める判定と仕分け）

**マージを止めるかの判定（全周共通）**: `blocking` かつ `confirmed` で、根拠の引用を G が記録先（issue または Draft PR 本文）の受け入れ条件、またはこの PR が触れる openspec の spec（change の delta spec を含む）の原文と照合できた指摘だけ止める。原文と照合できなくても、根拠が例外 3 種＝安全機構の穴・データ破壊・無言の機能不全に当たり `blocking` かつ `confirmed` なら止める。それ以外（`should`・`nit`・`plausible`・照合できない `blocking`）は止めない指摘の振り分け表へ。レビュアーの深刻度ラベルは参考にとどめる。

1周目で failed にするとき、止めない指摘も PR コメントに一覧で残し、段 A には「段 A・この PR で直す」と印を付け、follow-up issue はまだ切らない。止める指摘も1周目の段 A も無ければ failed にせず、手順3へ進むときに未解決の止めない指摘に段 B 以降を当て、段と行き先を PR コメントに記録する。

止める指摘が残ったら「マージを止めるかの判定（全周共通）」で判定し、下の仕分け表へ。

**止める指摘の仕分け表**（全周、指摘が届くたび上から当てる。正本はこの表だけ）:

| 順 | 当てる条件 | 動き | 主に聞くか |
|---|---|---|---|
| 1 | 止める判定に達しない（上の全周共通の判定で止まらない） | `stages/triage-nonblocking.md` の「止めない指摘の振り分け表」に回す（1周目は上の段落どおり failed の一覧に残す） | 聞かない |
| 2 | 受け入れ条件の中（根拠の引用元が記録先の受け入れ条件、またはこの PR の change の delta spec） | W が直す。`agent-review:failed` で W に戻す | 聞かない |
| 3 | 一覧の一致で閉じられる型（検索コマンドや軸の全域を W が書けない指摘は当てない） | W に一覧を作らせ（書式は `stages/row3-list-format.md`）、G は検索結果の集合一致で閉じる。`agent-review:failed` で W に戻す | 聞かない |
| 4 | 今直す 3 条件を満たす | W がその場で直し、仕分け欄に記録する。`agent-review:failed` で W に戻す | 聞かない |
| 5 | 順 1〜4 に当たらず、順 6 の条件にも当たらない | 主に「この欠陥を残して切り出すか」を聞く。`needs-approval` を付けて保留で return | 聞く |
| 6 | 同じ型の再発、または順 3・順 4 からの落とし込み | 決める役が方式を裁定する。Status `needs-decider` で本体に return | 聞かない（裁定が「切り出す」なら順 5 と同じ経路） |

2 周目以降の周の終わり（直し方の判定・主の回答・決める役の裁定で開いた周も同じ）には順 2〜4 をそのまま使わない。同じ型の再発は順 6。それ以外は、順 6 を除いた全件が 1 周目なら順 2〜4 に当たる場合だけ、各指摘の仮の順と根拠を記録して `needs-fix-check` を return。1 件でも順 5 相当なら全件を順 5 に当て、0 件なら判定に回さない。直し方の判定の正本は develop の `references/fix-check.md`「レビューの周を主に聞かずに続ける（直し方の判定）」。本体が判定役を起こし記録を投稿する。判定が「決まっている」なら仮の順 2〜4 で W に戻し、「選び直しが要る」なら順 5。指摘ごとの順と根拠を PR コメントに記録する。

再レビューで出た新規の指摘は止めない指摘として扱い、例外 3 種に当たるものだけ仕分け表に当てる（収束ルールの正本は `stages/convergence.md`）。

**段 A（この PR で直す）**: 直す場所がこの PR の diff が触れたファイルの中に収まる指摘は、1周目なら `agent-review:failed` で W に戻し「段 A・この PR で直す」と記録。止める指摘と 1 回の failed にまとめ、順 5・6 混在では順 2〜4 の指摘と同じに扱う。2周目以降は次の周を開けず、段 B から当てる。

**2周目の終わりにやること（G が、2周目の結果を受け取った直後に）**:

1. **残った指摘ごとに、違反する文を引用する。** 引用元は記録先の受け入れ条件と、この PR が触れる openspec の spec（delta spec を含む）だけ。引用元が無いときは全件「引用なし」。指摘ごとの引用・例外 3 種、または「引用なし」を PR コメントに記録する。止める判定は全周共通で、レビュアーの深刻度ラベルは参考にとどめる（高深刻度でも同じ）。
2. **止めない指摘（引用できない指摘を含む）は止めない指摘の振り分け表に通して `passed` の判定へ進む。** 段 B から当て、段と行き先を PR コメントに記録して手順3以降へ。段 A に戻さず、止めない指摘では3周目を開けない。
3. **止める指摘が残れば、順 2〜4 をそのまま使わない。** 引用できる指摘も全周共通の判定で止めるものだけを対象に、仕分け表直後の「2 周目以降の周の終わり」を適用する。直し方の判定・主の回答・決める役の裁定で開いた周の終了時にも同じ仕分けを適用し、また止める。無人運用（loop-dev-agent）も同じ。

#### 2-2. 修正サイクルのモデル昇格（failed → 修正実装）

`stages/triage-failed.md` にある。failed で戻す前に読む。

## G として動くとき（develop）

develop の G 専用。

### return の書式（failed / needs-decider / needs-fix-check / review-incomplete と仕分け）

`gate-runner.md`「return の書式」の共通欄（`## Gate Result` から `周回:` まで）のうしろに続ける。

```markdown
- 仕分け（指摘を受け取ったすべての周の return で必須。Status によらず書く）: pr-review-gate 手順 2-1 の仕分け表で指摘ごとに当てた順とその根拠（順 1・2 は違反文の引用・例外 3 種のどれか（安全機構の穴・データ破壊・無言の機能不全）。順 1 の指摘は、止めない指摘の振り分け表で当てた段と行き先も書く: 段 A は「この PR で直す」、捨てたなら理由の 1 行、issue にした・コメントで入れたなら follow-up issue またはコメントの URL、条件の確認待ちなら質問文。順 3 は集合一致で閉じた PR コメント URL。順 4 は W の記録「受け入れ条件の外・その場で直した・直し方 N 行」。順 6 の裁定を受けたら `決める役の裁定:` の内容）と、その PR コメント URL。止める指摘が無く、全件を振り分け表に通して `次の段へ` で返すときもここに書く。全周共通の判定で止める指摘が残り、順 5 に当たる場合は failed ではなく保留で返す（下）
- 効果測定（二周目以降に新しく出た、または未解決で残った各指摘に必須）: `同じ文が複数か所` / `場合分けの漏れ` / `直したつもりで直っていない` / `直しで新しく入った` のいずれか 1 つ。同じ指摘 ID と分類を仕分けの PR コメントにも記録し、その PR コメント URL を return に添える。この分類は記録だけに使い、全周共通の停止判定と仕分け順を変えない
### review-incomplete のとき
- 固定 HEAD・元の三表・補足後の三表・残差・`補足済み回数: 1` と、それらを記録した PR コメント URL。terminal なので reviewer の再起動・合格処理を提案しない
```

`failed` の欄は `stages/triage-failed.md`、`needs-decider`・`needs-fix-check` の欄は `stages/triage-escalation.md` にある。

### この段で起こされたときの入力

照合と振り分けの G は、起動指示の前の段の `## Gate Result` ブロックと、段に固有の入力（レビュアーの要約・補足レビューの結果・決める役の裁定・直し方の判定とその記録の URL・W の修正内容の要約）を受け取る。前の段の会話は持たず、固定した HEAD は最新の `レビュー重量:` コメントの `固定 HEAD:` の行から、三表と補足済み回数は最新の `レビュー三表:` のコメントから、前の周の振り分けは仕分けコメントから読む。起動指示と PR コメントが食い違ったら PR コメントを正とする。

- **レビュアーの要約受領**: `stages/triage-summary.md` に従う。
- **止める指摘が残らなかったとき**: 止めない指摘（順 1）を止めない指摘の振り分け表に通す。1周目に段 A に当たる指摘があれば `agent-review:failed` で返す。無ければ段 B 以降の結果を PR コメントに記録してから、Status `次の段へ`・`次の段: 合格処理` で返す。宣言（手順 3）は合格処理の G が行う

## 出口

- 止める指摘が残らなければ（段 A の failed を除き）`declarations.md`（手順 3・3-b）へ進む。
- 順 2〜4 と 1周目の段 A は `agent-review:failed` で修正サイクルへ戻す。修正後の再レビューは `stages/prepare.md` の手順 1 から始める。
- 順 5（主に切り出すかを聞く）は `stages/hold.md`（手順 6）へ進む。
- 順 6 は決める役の裁定を待ち、裁定を受け取ったらこの段に戻る。
