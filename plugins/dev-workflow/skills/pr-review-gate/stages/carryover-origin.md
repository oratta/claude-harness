# 前の HEAD の許容の引き継ぎ: 元の回答が会話・親経由のとき — pr-review-gate

`stages/carryover.md` の条件 3 と 4 行の追記で、元の直接の回答が `会話で受領`・`親経由で受領`・`親経由で受領（委任）` の記録のときだけ読む。引き継ぎが 2 回以上続いても元の直接の回答のままにする。どれかを満たさないときは引き継がず手順6で主に聞く。

## 条件 3 の確かめ直し

「最初の宣言」は `引き継ぎ元:` をたどった、元の記録を最初に追記した宣言のこと。形は行の頭で見分ける（`親経由で受領（委任）（親セッション ` は委任の形、`親経由で受領（親セッション ` は従来の形）。

- **`親経由で受領`**: `stages/authenticity-relayed.md` の「引き継ぎのとき」に従う
- **`親経由で受領（委任）`**: `stages/authenticity-delegated.md` の「引き継ぎのとき」に従う
- **`会話で受領`**: 元の記録のセッション ID と原文で `bash <plugin>/scripts/owner-reply-check.sh <セッション ID> <原文>` を回し直す。終了コード 0 で、記録の日時と同じ timestamp の `MATCH:` があり、その全文から許容の意思が読め、その timestamp が最初の宣言の作成日時より後で、全文が別の PR・別のリスクを名指ししていないときだけ引き継ぐ（終了コード 0 でも同じ timestamp の `MATCH:` が無い、全文が `許容しない` への部分一致だった、などは引き継がない。終了コードが 0 でなければ（この PC に会話ログが無い exit 2 を含む）引き継がない）
