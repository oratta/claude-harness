# 引き継ぎの終了コード 4 の判定役: 回す条件と G の返し方 — pr-review-gate

`stages/carryover.md` 3-c で終了コード 4 のときに読む。判定役を起こす側（develop の本体・develop の外のメインセッション）は加えて `stages/carryover-judge-run.md` を読む。develop の G は読まない。

##### 終了コード 4 の判定役

リスク宣言の中身が前と同じかは、作業の文脈を持たない判定役に比べさせる。

- **回す条件**: スクリプトが終了コード 4 を返し、条件 2〜4 を満たし、`RESOLVED_OUTSIDE_ALLOWLIST=` の行があるときは条件 1 の終了コード 3 と同じ確認（新しい HEAD で取り直したレビューが PR 全体を見た周である）も満たし、`EVIDENCE_DIFF_LINES=` が 100 以下（100 ちょうどは判定させる）で、下の記録の選び方で使える記録が無いときだけ回す。どれかを満たさなければ判定役を起こさず手順6で主に聞く（使える記録があるときは、その記録で条件 1 を決める）
- **起こすセッションの区別**: develop の外のメインセッションでは、ゲート自身が Agent ツールで判定役を起こし、判定の記録を PR に投稿して 3-c を続ける。develop の合格処理の G は判定役を起こせないので、回す条件を満たしたら宣言を投稿せず `needs-approval` も付けずに、Status `needs-carryover-judge`・`次の段: 合格処理` で返す（`SHARED_BUDGET_MODE=depleted` でも同じ）。従来経路の一括の G（`段: 一括（従来経路）`）は判定役を起こさず手順6で主に聞く
- **記録の選び方**: 同じ PR の 1 行目が `引き継ぎ判定:` のコメントのうち、`前 HEAD:` と `新しい HEAD:` が今回の 40 桁と一致し、`根拠ファイル:`（カンマ区切り）のファイルがスクリプトの `EVIDENCE_PR_CHANGED=` のファイルと（各要素の前後の空白を除いたうえで）順序を問わず同じ集合のものの最新 1 件だけを使う。一致しない記録は使わない。一致する記録があれば、同じ組で判定役を起こし直さない（develop の G は `needs-carryover-judge` を返し直さない）。1 行目が `^引き継ぎ判定: (同じ|変わった|判断できない)$` に一致しない記録は「判断できない」と同じに扱う。記録が `引き継ぎ判定: 同じ` なら条件 1 を満たし、引き継ぎの根拠の行にその記録のリンクを書く。判定を受けて起こされた合格処理の G（前の Gate Result が `段: 合格処理`・Status `needs-carryover-judge`）が一致する記録を見つけられないときは、`needs-carryover-judge` を返し直さず「判断できない」と同じに扱い、本体が投稿した記録のリンク（見つからなければその旨）と、HEAD か根拠ファイルが今回の組と一致しないことを理由に添えて手順6で主に聞く
- 守備範囲: 判定役の読み違い、小さい引き継ぎの積み重ね、記録の真偽、理由の妥当性はこの手順では止めない。条件 4 の本文の一致と新しい HEAD のレビューは引き継いでも残る

## G として動くとき（develop）

`gate-runner.md`「return の書式」の共通欄のうしろに続ける。

- **許容済みの PR で HEAD が動いたとき**: 取り直しの手順 3 で再び「主のリスク許容が必要」になったら、主に聞く前に手順 3-c を試す。終了コード 4 で回す条件を満たし、使える判定の記録が無いときは、Status `needs-carryover-judge` で返す

```markdown
### needs-carryover-judge のとき
（手順 3-c の「終了コード 4 の判定役」の回す条件を満たし、使える判定の記録が無い。宣言は投稿せず、`needs-approval` も付けない。`次の段: 合格処理`）
- 前 HEAD: <40 桁フル SHA> / 新しい HEAD: <40 桁フル SHA>
- 前の宣言のコメントのリンク: <URL>
- EVIDENCE_PR_CHANGED=: <ファイル>, <ファイル>
- EVIDENCE_DIFF_LINES=: <値>
```
