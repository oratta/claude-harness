# 前の HEAD の許容の引き継ぎ（手順 3-c）— pr-review-gate

## 入口

手順 3 が再び「主のリスク許容が必要」と判定し、同じ PR の前の HEAD の宣言に主の許容が記録済みのときに読む。引き継げなければ `stages/hold.md` の手順 6。

## 手順

#### 3-c. 前の HEAD の許容の引き継ぎ

手順 3 で「主のリスク許容が必要」と判定し前の HEAD に許容があるときは、手順6で主に聞く前に新しい HEAD へ引き継げるかを確かめる。main の取り込みや PR 自身の修正で HEAD が動いても、基準はリスクの中身が同じかである。前の HEAD のあとが main を取り込む merge commit だけのとき（終了コード 0 と `PR_COMMITS=0`）は、衝突解消・根拠ファイルの差分・取り直しのレビューの範囲・判定役・新しい HEAD の宣言本文によらず引き継ぐ（主の判断、#1329。条件 2 の根拠ファイルの行と条件 3 の真正性確認のやり直しは残る）。

前の宣言の選び方: 同じ PR の `## リスク宣言` コメントのうち、`主の回答: 許容` で始まる行（`主の回答: 許容（引き継ぎ）` を含む）と `真正性確認: 済` の行の両方を持つ最新 1 件。その `対象 HEAD:` の SHA が前 HEAD。

issue で承認済みの宣言（`stages/issue-approved.md` の 3 行を追記したもの）は引き継ぎの元にしない。HEAD が動いたら新しい HEAD で判定し直す。

```bash
bash <plugin>/scripts/risk-carryover-check.sh <前 HEAD> <新しい HEAD> <前の宣言の根拠ファイル>...   # --base の既定は origin/main。手順 1 の fetch と main の取り込みの後に回す
# 出力: CARRYOVER=yes|if-rereviewed|if-judged|no / MAIN_MERGES=<件数> / PR_COMMITS=<PR 自身の commit の件数>
#       / RESOLVED_FILES=<衝突解消したファイル。無ければ none>
#       / RESOLVED_OUTSIDE_ALLOWLIST=<許可リスト外の衝突解消のファイル>
#       / EVIDENCE_MAIN_ONLY=<main からの変更だけの根拠ファイル>
#       / EVIDENCE_PR_CHANGED=<PR 自身の差分が違うか PR 自身の commit が触れた根拠ファイル>
#       / EVIDENCE_DIFF_LINES=<その diff の追加と削除の合計> / NG: <引き継げない理由>
# 終了コード: 0 = 無条件で引き継げる（PR_COMMITS=0 なら許可リスト外の衝突解消があっても 0）
#             / 3 = PR 全体を見た取り直しのレビューを経ていれば引き継げる（条件 1）
#             / 4 = 根拠ファイルの PR 自身の差分が前後で違うか、PR 自身の commit が触れた（下の「終了コード 4 の判定役」に比べさせる）
#             / 1 = 引き継げない / 2 = 引数・環境の不備（引き継げない側に倒す）
# PR 自身の差分 = 各 HEAD と base の merge-base からのそのファイルの差分
```

引き継げるのは次のすべてを満たすときだけ:

1. スクリプトが終了コード 0 を返す（`PR_COMMITS` が 1 以上なら、merge commit が main の取り込みと版の行・CHANGELOG の並べ直しの衝突解消だけで、根拠ファイルの PR 自身の差分が前後で同じ。`PR_COMMITS=0` なら衝突解消の中身と根拠ファイルの差分は見ない）。または終了コード 3 を返し、新しい HEAD で取り直したレビューが PR 全体を見た周である。確かめ方は次の 2 つ:
   - 最新の `レビュー重量:` コメントの `固定 HEAD:` が新しい HEAD の 40 桁 SHA と一致する
   - 前の段の Gate Result の `周回:` が `1` か、`（全体レビュー: …）` が添えられている。`周回:` が 2 以上で注記が無い周は差分限定の再レビューと見分けられないので、PR 全体を見た周として扱わない。HEAD の一致・`レビュー重量: full`・仕分けコメントが無いことだけから推定しない
   終了コード 4 の条件 1 は `stages/carryover-judge.md`。
   終了コード 0 で `PR_COMMITS=0` なら、`RESOLVED_OUTSIDE_ALLOWLIST=` の行があっても PR 全体を見た取り直しのレビューを求めない。判定役も起こさない
2. 前の宣言に `- 根拠ファイル:` の行がある（無い宣言からは引き継げない）
3. 引き継ぎの元が主の直接の回答で、捏造でない。前の宣言に `主の回答: 許容` 系の行と `真正性確認: 済` の行がある。回答リンクは主が許容を述べた元の直接の回答を指し、引き継ぎの記録（宣言コメント）を指さない（2 回以上続いても同じ）。引き継ぐたびに、元の回答リンクに対して手順5の真正性確認（リンク先を開く・許容の意思を読む・GitHub コメントなら author を実測する）をやり直す。元の回答が会話で受領・親経由で受領・親経由で受領（委任）の記録のときは `stages/carryover-origin.md` に従って確かめ直す。確かめ直しのどれかを満たさない・終了コードが 0 でないときは引き継がず手順6で主に聞く
4. 新しい HEAD のレビュー結果から組み立てたリスク宣言の本文が、`対象 HEAD:` 行を除いて前の宣言の本文（末尾の `主の回答:` 以降の追記行を除いた部分）と同一である。比較は新しい HEAD の宣言を投稿する前に組み立てた本文で、文の一致で確かめる。終了コード 0 で `PR_COMMITS=0` ならこの条件は求めない

引き継げるなら、前の宣言と同じ本文を新しい `対象 HEAD:` で投稿し、末尾に次の 4 行を追記する（`needs-approval` は付けずに手順4・5へ）。終了コード 0 で `PR_COMMITS=0` のときも、本文は前の宣言の本文のままにし、新しい HEAD のレビューから組み立てた本文に置き換えない:

```
主の回答: 許容（引き継ぎ） — <元の直接の回答リンク>（<元の回答の日時>）
引き継ぎ元: <前の HEAD の 40 桁フル SHA> の宣言 <前の宣言コメントのリンク>
引き継ぎの根拠: risk-carryover-check.sh 終了コード <0・3・4 のどれか> — main の取り込み <件数> 件、PR 自身の commit <PR_COMMITS の値> 件、衝突解消 <none またはファイル>、許可リスト外 <none またはファイル>、根拠ファイル <diff は空のファイル / main からの変更だけ: EVIDENCE_MAIN_ONLY のファイル / 終了コード 4 のとき: PR 自身の差分が変わったか PR 自身の commit が触れた EVIDENCE_PR_CHANGED のファイル、差分 <EVIDENCE_DIFF_LINES の値> 行、判定 同じ <判定の記録のリンク> / PR_COMMITS=0 のとき: 比べず（PR 自身の commit 0 件）。該当するものを並べて書く>、取り直しのレビュー <終了コード 3 のとき・終了コード 4 で許可リスト外があるとき: 固定 HEAD <40 桁フル SHA>（周回 <値と注記>） <その レビュー重量 コメントのリンク>。終了コード 0 のとき: 不要。終了コード 4 で許可リスト外が none のときも不要>
真正性確認: 済 — 確認者 <エージェント名> / <日時>（元の回答を再確認）
```

元の回答が会話・親経由なら、1 行目の `<元の直接の回答リンク>（<元の回答の日時>）` を `stages/carryover-origin.md` のとおり置き換える。追記はどの形でも 4 行のまま。

1 つでも満たさなければ引き継がず、手順 3 の issue で承認済みを試し（`declarations.md` の出口の順）、それも当たらなければ手順6で主に聞く。質問には、スクリプトの `NG:` 行を理由として添える。終了コード 3 で取り直しのレビューを確かめられなかったときは、`RESOLVED_OUTSIDE_ALLOWLIST=` の行と `周回:` の値を添える。

省けるのは主への質問だけで、手順 2 のレビュー・手順 4 の証拠・手順 3-b の仕様宣言は新しい HEAD で出し直し、手順5の実測も省かない。これが手順1の「前回の合格部分を流用しない」の唯一の例外。

終了コード 4 の判定役の条件・記録の選び方と、develop の G が `needs-carryover-judge` で返す欄は `stages/carryover-judge.md`。

## 出口

- 引き継げたら宣言を投稿して合格処理の G に渡す（Status `次の段へ`・`次の段: 合格処理`）。引き継げなければ `stages/hold.md` の手順 6 へ進む。
