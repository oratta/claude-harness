# レビュー要約の受領 — pr-review-gate

レビュアーの要約か補足レビューの結果を受け取った照合と振り分けの G が読む。

レビュー要約を受け取った G は、「レビュー実行者:」の PR コメント（`レビュー実行者: Task サブエージェント（light 判定のため）` / `（full・実測した Codex 不可: <条件>）` / `（full・Codex オフ）`。adapter 経路では `レビュー実行者: <executor>/<model>（adapter 経路・<light|full>・dispatch 記録: <URL>）` とし、本体から渡された executor / model と dispatch 記録のコメント URL を写し、`<light|full>` には手順 2-0 の判定を書く。Codex の `<model>` は worker 結果の `execution.model_resolution.requested` と `execution.model_resolution.resolved` による `<requested>→<resolved>` として書く。resolved が null なら未観測と明示し、要求値や dispatch 時の model から補完しない。Claude の `<model>` は従来の値を使う。モデルと根拠を添え、full では対象 HEAD と上の同じ証拠を記録する。終了コードは取得できた場合のみ記し、架空の終了コードを書かない。light は事前判定として記録する）を **G が投稿**する。

- **レビュアーの要約受領**: 上の「レビュー実行者:」コメントを投稿してから、一周目は最初に `変更点の一覧`・`照合表`・`ハンク被覆` を `skills/develop/references/roles/gate-runner-triage.md` の「一周目の三表を機械照合する」どおり機械照合する。不足または差分があれば、`補足済み回数: 0` では Status `needs-reviewer` で不足分だけの補足へ接続し（補足を頼む前に元の三表・`補足済み回数: 1` を持つ `レビュー三表:` コメントを投稿する。payload は 0）、`補足済み回数: 1` では `review-incomplete` で止める。三表の照合が完了したあとだけ要約に指摘が残っているかで分岐し、指摘が無ければ手順 3 以降（この G は宣言をせず、Status `次の段へ`・`次の段: 合格処理` で返す）。指摘が残っていれば、周の数に関係なく pr-review-gate 手順 2-1 の仕分け表（`stages/triage.md`）に上から当てる（順 1 は全周共通の判定）。止める指摘が無く順 1 だけなら、止めない指摘の振り分け表（`stages/triage-nonblocking.md`）に通す。1 周目に段 A に当たる指摘があれば `agent-review:failed` に付け替えて failed で返し、無ければ段 B 以降の結果を仕分けに記録してから（振り分けで issue にすると決まった指摘だけが follow-up issue になる）同じく `次の段へ`・`次の段: 合格処理` で返す。順 2〜4 は `agent-review:failed` に付け替えて failed で返し（止めない指摘は failed の PR コメントに一覧で残す）、順 5 は保留、順 6 は `needs-decider` で返す。ただし 2 周目以降の周の終わりには順 2〜4 をそのまま使わない。pr-review-gate 手順 2-1 の周の終わりの段落どおり、同じ型の再発は順 6、それ以外は判定に回す条件に当たれば `needs-fix-check`（直し方の判定。指摘ごとの仮の順を仕分けに記録する）、当たらなければ順 5 で返す。順 5 と順 2〜4、または順 5 と順 6 が混ざれば保留だけを先に返す。保留と `needs-decider` を同じ return で指示しない。判定に回す指摘と未裁定の順 6 が混ざれば `needs-fix-check` だけを先に返し、`needs-fix-check` と `needs-decider` を同じ return で指示しない（処理順は pr-review-gate 手順 2-1 の混在の段落）。仕分けは PR コメントに記録する
- **補足レビュー結果の受領**: `skills/develop/references/roles/gate-runner-triage.md` の同名節どおり `補足済み回数: 1` を維持して三表を再照合する。残差があれば `review-incomplete`、無ければ同じ一周目の指摘仕分けへ進む
