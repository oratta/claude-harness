# 親が通してよい範囲の基準（案）

Orca 経路のエピックで、子が主の返事を待って止まったとき（子 issue に 1 行目 `子の停止: 主の返事待ち` の記録がある）、親の側で「通す」（子に返事を送って進めさせる）か「主に上げる」かを決める基準。判断は `scripts/stop-judge.sh` が呼ぶモデルがこのファイルを読んで行い、`scripts/epic-dispatch.sh wait --resolve` が結果に従って返事を送るか親を起こす。

この基準は案で、中身の最終決定は主が PR で行う。#1030（子の PR のマージ）の「合理性があり危険が低い」は、この基準を参照する。

## 通す条件

次の 9 つを**すべて**満たすときだけ通す。

| 条件 | 中身 |
|---|---|
| 既存の規則が主に聞く止まりでない | PR トークン上限の計測が exit 2 のときの続けるか止めるか、レビューの周の終わりの直し方の判定が「選び直しが要る」とき、PR のマージのように、既存の規則が主に聞くと定めている止まりでない（既存の規則を変えるのはこの基準の範囲外） |
| 推奨がある | 子の記録に推奨とその根拠がある（推奨の無い止まりは、主の好みや事業判断を聞いている） |
| 範囲の内側 | 推奨が、エピックの目的と子 issue の受け入れ条件の範囲を広げず、逆向きにもしない |
| 聖域でない | 自己統治物件（`CLAUDE.md`・hooks・権限設定・`rules/`・常時注入の予算ファイル）、破壊的な git 操作（`rules/destructive-git-guard.md` の一覧）、秘密情報の値、外部への公開・送信・課金、PR のマージに触れない |
| 戻せる | 推奨どおり進めて誤りだったとき、そのブランチの中の commit の取り消しや設定の戻しで戻せる。戻すのにかかる手間が判断できなければ戻せない側に倒す |
| 主の側の情報が要らない | 好み・事業判断・主しか知らない事実・リスクの許容が要らない。記録の「受け入れるリスク」は、エピックや子 issue に既に許容と書かれているか、その子のブランチの中に閉じるものに限る |
| 実機操作でない | MFA・OAuth・ログイン・ダッシュボードの操作など、主の手が要る操作を含まない |
| 配役表で主の観点が無い | 配役表（`.claude/casting/project.md`・`.claude/casting/local.md`）が渡されたとき、その止まりに要る観点の担い手が主でない |
| 繰り返していない | このエピックで同じ子の同じ件を既に一度通していて（渡された過去の `親の判断: 子 #N 通した` の行で分かる）、子がまた同じ件で止まっているのでない |

**迷ったとき**: 1 つでも満たさないか、満たすか判断できなければ「主に上げる」。通してよい止まりを主に上げても主の手間が増えるだけで危険は無いが、通してはいけない止まりを通すと主の承認なしに進む。

PR のマージの可否は、この基準で通さない（#1030 の手順に任せる）。既存の規則が主に聞くと定めている止まりも、この基準で通さない。

## 例

2026-10-01〜10-14 の止まり 35 件から。

通る例:

- hook が止めたファイルの読み取り（リポジトリの中のソースで、ファイル名が理由で止められたもの）
- 手順外の判断を推奨どおり受け入れること（推奨と根拠があり、子のブランチの中で戻せるもの）
- 自分の実行の配下で暴走したプロセスの停止（他のプロジェクトのプロセスは含まない）

通らない例:

- PR のトークン上限の引き上げ。既存の規則（dev-workflow-develop「レビューの 2 周目以降の周の終わりは直し方の判定を通して続ける」と develop の SKILL.md の上限変更の手順）は、計測が exit 2 のとき主に聞くことを求め、新しい上限の算出と `PR トークン上限:` の記録を主の「続ける」の返事を受けた本体が行う作りになっている。親の返事だけではこの記録が作られない
- レビューの周の終わりで、直し方の判定が「選び直しが要る」ときの続行（既存の規則が主に聞く止まり）
- マージの承認（#1030 の手順に任せる）
- 聖域のファイルの変更（`CLAUDE.md`・hooks・権限設定・`rules/`・常時注入の予算ファイル）
- 実機操作（MFA・OAuth・ログイン・ダッシュボードの操作）
- 主しか知らない設計意図を聞いている止まり

## 出力の形

判断は次の 3 行だけを出す。前置き・説明・コードブロックを付けない。

```
判断: 通す
理由: <1 行。どの条件をどう満たしたか、または満たさなかったか>
返事: <1 行。通すときに子へ送る文。主に上げるときは空でよい>
```

1 行目は `判断: 通す` か `判断: 主に上げる` のどちらか。`stop-judge.sh` がこのうしろに 4 行目 `記録: <停止の記録のコメントの URL>` を付ける。形が崩れた出力は通さず、親を起こす側に倒れる。

## 守備範囲

判断に渡すのは、`stop-judge.sh` が集めるものだけ（エピックの本文、子 issue の本文と投稿者が OWNER・MEMBER・COLLABORATOR の `親エピックからの注意書き:`、子の最新の停止の記録、同じ子への過去の `親の判断:`、このファイル、あれば配役表）。親や子の会話は入らない。

拾いたい誤りは、主の承認が要る止まり（聖域・破壊的操作・既存の規則が主に聞くと定めたもの・マージ）を通すこと、推奨の無い止まりや主の側の情報が要る止まりを通すこと、戻せない操作を通すこと、同じ件を通し続けることの 4 つ。子の記録の 2 行目以降の項目名や並びの違い（形は #1036）、通してよい止まりを主に上げること、通した判断があとで主に止められることは、この基準では止めない。基準をすり抜ける止まりが見つかるたびに条件を足して塞ぎ切ることは目的にしない（主が PR と 2 週間後の再集計で見直す）。
