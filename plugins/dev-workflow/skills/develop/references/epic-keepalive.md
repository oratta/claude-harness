# 停止中の子への声かけ（共有正本）

子は停止前、親は停止済み子の声かけを扱う前に読む。

**キャッシュ維持の声かけの例外**: 子は停止前に `references/child-cache-keepalive.json`（プラグイン直下の references）を読み、`separator` で `reply_prefix` と順序付きの `fields`（各欄名の後ろに空白と `<値>`）を連結した型を `request_template` の `{reply_format}` に入れた固定文を覚える。固定文と完全一致する入力を、通常の主の返事や親の判断より先に声かけとして扱う。主が同じ文を入力しても予約文として扱い、送信元の識別はしない。受信ターンではツールを呼ばない（定義の読み直しも含む）。会話だけから各欄の短い値を選び、専用の接頭辞と順序付きの欄を定義の区切りでつないだ一行だけ返す。値に改行や区切り文字を入れない。調査・作業・停止コメントの投稿は行わず、元の質問・停止状態・停止記録を保って待ち続ける。欄の意味の確定や失敗の検出は #1374 に残す。完全一致しない実際の返事は以下の通常の再開手順に従う。

### 停止中の子へのキャッシュ維持（#1383）

親の通常の `wait --watch-stopped` が、止まった発言の uuid（`stop_uuid`）か主の返事待ちの停止記録があり未回答、stop=stopped-seen、TTL 1h の子だけに固定の声かけを送る。最後の成功した CLI リクエスト（cache-hit を含む）から 3000 秒以上 3600 秒未満、止まった時刻（`stop_at`。空なら記録の作成時刻）から `EPIC_DISPATCH_OWNER_WAIT_SEC` 秒（既定 43200 秒。`wait` の長い待ちの上限と同じ値）未満のときに限る。TTL は最後の書き込みから読み、リクエスト時刻とは分ける。既存の会話量による再起動条件、計測不能・複数セッション、前の声かけの返事未着、実際の回答ありも対象外。

起動部品は既存の一意な前景の入力待ち・空欄にだけ送り、声かけのために起動し直さない。声かけも異常な返事も停止の印や停止コメント、声かけの期限の基点を延ばさない。3600 秒以上たったスリープ復帰後と期限（`EPIC_DISPATCH_OWNER_WAIT_SEC` 秒）の後は送らず、実際の返事が来たときに上の通常の再開判定へ渡す。

TTL 5m/unknown には送らない。overage 等で 5m に変わっても、キャッシュ書き込みによる切替を観測するまで検知できないため、切替直後の一回の書き直し費用を防げない場合がある。五分ごとの声かけはしない。


声かけの固定文と対応する型どおりの返事は `child-log` が除外する。元の質問と時刻を保つ保証は正常な一行の往復だけ。固定文は予約文なので、主が直接その文を入力した場合も型どおりの返事と共に除外する（送信元は識別しない）。通常の「了解」や型違い・複数行の返事は表示され、最後の子の発言になる。その逸脱だけでは status/stop=stopped-seen・停止コメント・声かけの期限の基点を変えず、wait は継続し親を起こさない。

送信失敗は stderr に残して次回の通常のポーリングに任せる。子の発言の内容を判定したり、声かけの返事から作業を進めたりしない。
