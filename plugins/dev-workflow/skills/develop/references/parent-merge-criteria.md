# 親がマージに回してよい子の PR の基準（案）

別セッション方式（起動部品は Orca か tmux）のエピックで、子が `human-merge` の付いた PR のマージ待ちで止まったとき（子 issue の最新の `子の停止: 主の返事待ち` の記録の `止まった理由:` が `PR のマージ待ち（` で始まる）、親の側で「マージに回す」（PR に判断の印を付ける）か「主に上げる」かを決める基準。判断は、親が起こした決める役（`subagent_type: dev-workflow:decider`）がこのファイルを読んで行う。親の手順は develop の `references/epic.md`「回し方」の **マージ待ちの子**。

マージを実行するのは自動マージの処理（`.github/workflows/auto-merge.yml`）で、この基準は親が判断の印（`parent-merge-approved` ラベルと `親のマージ判断: 可` のコメント）を付けてよいかだけを決める。マージ条件そのもののパス（`MERGE_CONDITION`）に触れる PR と、判断のあとに push されたコミットは、印があっても処理の側が止める（条件の正本は対象リポの `docs/auto-merge.md`）。

この基準は案で、中身の最終決定は主が PR で行う。条件名と「迷ったら主に上げる」は、止まった子を通す基準 `parent-pass-criteria.md` とそろえてある。マージの条件を `parent-pass-criteria.md` に足さない（`stop-judge.sh` がそのまま読むプロンプトで、マージはその基準で通さないと定めているため）。

## 可の条件

次の 6 つを**すべて**満たすときだけ `裁定: 可` にする。

| 条件 | 中身 | `parent-pass-criteria.md` の条件との対応 |
|---|---|---|
| 見送りが聖域接触だけ | 見送りラベル（`human-merge`・`needs-human-merge`・`human-only`・`needs-approval`）のうち付いているのが、自動マージの処理が付けた `human-merge` だけ（`🔒 **auto-merge 対象外（聖域パス接触）**` の投稿がある）。変更ファイル（rename 元を含む）が、渡された `auto-merge.yml` の聖域のパス（`SACRED`）に当たり、マージ条件そのもののパス（`MERGE_CONDITION`）に 1 つも当たらない | 「聖域でない」をマージ用に置き換えたもの（聖域のファイルに触れること自体は主の決定で親に任された） |
| ゲートが今の HEAD で済んでいる | `agent-review:passed` が付き、今の HEAD の SHA を書いたゲートの合格・リスク宣言・動作確認のコメントがあり、CI が green | 「既存の規則が主に聞く止まりでない」（ゲートが主の確認を求めている状態を通さない） |
| 主の側の情報が要らない | リスク宣言が「リスクなし」か、宣言したリスクへの主の許容が今の HEAD について記録されている。好み・事業判断・主しか知らない事実が要らない | 同名 |
| 範囲の内側 | 差分が、子 issue の受け入れ条件とエピックの目的を広げず、逆向きにもしない | 同名 |
| 戻せる | revert PR で元に戻り、マージから戻すまでの間にリポジトリの外へ戻せない作用（外部への公開・送信・課金・データの削除・秘密情報の値）が出ない。戻すのにかかる手間が判断できなければ戻せない側に倒す | 同名 |
| 配役表で主の観点が無い | 配役表（`.claude/casting/project.md`・`.claude/casting/local.md`）が渡されたとき、この変更に要る観点の担い手が主でない | 同名 |

**迷ったとき**: 1 つでも満たさないか、満たすか判断できなければ「主に上げる」（`裁定: 否`、入力が足りなければ `不足:`）。マージに回してよい PR を主に上げても主の手間が増えるだけで危険は無いが、回してはいけない PR に印を付けると主の承認なしにマージされる。

`parent-pass-criteria.md` の条件のうち「推奨がある」「実機操作でない」「繰り返していない」は、ここでは条件にしない。マージ待ちの止まりは推奨が「マージする」に決まっていて、実機操作を含まず、同じ HEAD への印の付け直しは親の手順の前提（今の HEAD の判断のコメントがまだ無い）が止めるため。

## 出力の形

判断は次の 2 行だけを出す。前置き・説明・コードブロックを付けない。

```
裁定: 可
理由: <1 行。どの条件をどう満たしたか>
```

1 行目は `裁定: 可`・`裁定: 否`・`不足: <足りないもの>` のどれか。2 行目は `理由: <1 行>`（`不足:` のときも何が無いと判断できないかを書く）。形が崩れた出力は可として扱わず、親は主に上げる。

## 守備範囲

判断に渡すのは、親が入力文に貼るものだけ（エピックの本文、子 issue の本文と投稿者が OWNER・MEMBER・COLLABORATOR の `親エピックからの注意書き:`、子の停止の記録、PR の本文とラベルと今の HEAD の SHA、変更ファイルの一覧と差分、PR のリスク宣言・動作確認・ゲートのコメント、CI の結果、PR の base ブランチの `auto-merge.yml` の `# >>> sacred-paths` 〜 `# <<< merge-condition-paths` の行、`human-merge` を付けた自動マージの処理の投稿、このファイル、あれば配役表）。親や子の会話は入らない。

拾いたい誤りは、主のリスクの許容が要る PR を可とすること、範囲を広げる差分を可とすること、外へ戻せない作用を持つ PR を可とすること、ゲートや CI が今の HEAD で済んでいない PR を可とすることの 4 つ。可としてよい PR を否とすること、可とした判断があとで主に止められること（revert PR で戻す）は、この基準では止めない。基準をすり抜ける PR が見つかるたびに条件を足して塞ぎ切ることは目的にしない（主が PR で見直す）。
