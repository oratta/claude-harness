# 主の委任の共有正本（develop）

親が委任を受ける・取り消すとき、親子が委任を適用する前に読む。親の投稿・確認場所の記録・送信操作は `references/epic-stop.md`。子は親の操作本文を読まず、このファイルで定型と有効性・種類別条件を確かめる。ゲートの記録と真正性確認は pr-review-gate の stages/pass.md 手順 5。

## 記録の定型

`主の委任: リスク許容` は 1〜4 行目、`主の委任: 論点なしの止まり` は 1〜5 行目が次の文字列ちょうど。<E> はエピックの番号。

  ```
  主の委任: リスク許容
  エピック: #<E>
  範囲: このエピックの子が pr-review-gate で求めるリスク許容のうち、子の停止の記録の推奨が「許容する」のもの。聖域の変更・破壊的な操作・マージの承認・不許容は含まない
  期間: この記録への主の確認の発言から、このエピックに `主の委任:` で始まる次のコメントが付くか、エピックが閉じるまで
  きっかけ: <主が任せる旨を述べた発言の全文。無ければ なし>
  ```

  ```
  主の委任: 論点なしの止まり
  エピック: #<E>
  範囲: このエピックの子の止まりのうち、子の停止の記録の `主に聞く理由:` が論点なしと書き、推奨と根拠があるリスク許容・聖域の変更・破壊的な git 操作と、同じ HEAD の論点なしの確認で通ったマージ待ち。論点ありの止まり・不許容・実機操作は含まない
  期間: この記録への主の確認の発言から、このエピックに `主の委任:` で始まる次のコメントが付くか、エピックが閉じるまで
  根拠: 主の決定（2026-11-01。線は論点の有無で引き、種類による例外は置かない） https://github.com/genetta-inc/flatmate/issues/1796#issuecomment-6551902839

  きっかけ: <主が任せる旨を述べた発言の全文。無ければ なし>
  ```

## 確認・期間・失効

問いの後の、全文から任せる意思が読める最初の主の発言が確認となる。確認より前の止まりには効かず、確認後から定型の `期間:` が定める終わりまでに限る。発言が挟まっただけでは失効しないが、取り消しや範囲変更なら使わない。親の問い・記録と確認場所の保存は `references/epic-stop.md`。

取り消しは主本人の再確認を求めず、投稿者が `OWNER`・`MEMBER`・`COLLABORATOR` のどれかなら効く。それ以外の投稿者の `主の委任:` で始まるコメントは、取り消しとしても新しい記録としても数えない。

- **委任が有効か**（親・子・G が同じ文で確かめる）: 委任の記録が、①エピック #<E> の issue のコメントで、1 行目が `主の委任: リスク許容` なら 1〜4 行目が、`主の委任: 論点なしの止まり` なら 1〜5 行目が定型の文ちょうど、2 行目の番号が <E> ②投稿者が `OWNER`・`MEMBER`・`COLLABORATOR` のどれか ③エピックの、投稿者が同じ 3 種の `主の委任:` で始まるコメントのうち最新 ④`lastEditedAt` が null ⑤エピックが開いている ⑥子 issue がエピックの子（sub-issue か本文の子の表にある）。子と G では、<E> は返事の頭 `主の返事（親エピック #<E> 経由）` の番号で、記録の URL の issue 番号と同じでなければ有効でない。`lastEditedAt` は GraphQL で読む（`gh api graphql -f query='query($id: ID!) { node(id: $id) { ... on IssueComment { lastEditedAt } } }' -f id=<コメントの node_id>`）
- **委任が効く止まり**（親・子・G が同じ文で確かめる。止まりの種類ごとに分ける）: **リスク許容の止まり**（委任の種類が `リスク許容` でも `論点なしの止まり` でも効く）: ①子 issue の番号を、本文で最初に現れる `Closes #N`・`Fixes #N`・`Refs #N` の `N` に持つ開いた PR に `needs-approval` が付いている ②その PR の、投稿者が `OWNER`・`MEMBER`・`COLLABORATOR` で `## リスク宣言` で始まる最新のコメントが `主のリスク許容が必要。` の行を持ち、`対象 HEAD:` が PR の今の HEAD と同じで、`主の回答:` で始まる行をまだ持たない（G では、今確かめている委任の形の記録の行だけは除く） ③停止の記録の作成日時が、そのコメントの作成日時と委任の確認の timestamp の両方より後 ④停止の記録の `推奨:` の値（先頭の空白を除く）が `許容する` で始まる ⑤②の宣言が `論点なし — ` の行を持ち、停止の記録の `主に聞く理由:` が論点なしと書く。**聖域の変更・破壊的な git 操作の止まり**（委任の種類が `論点なしの止まり` のときだけ効く）: 停止の記録の `止まった理由:` が `聖域の変更の承認: ` か `破壊的な git 操作の承認: ` で始まり、`推奨:` の値（先頭の空白を除く）が `進める` で始まり、`主に聞く理由:` が論点なしと書き、停止の記録の作成日時が委任の確認の timestamp より後。**マージ待ち**（委任の種類が `論点なしの止まり` のときだけ効く）: 停止の記録は残らないので、子の最後の発言とその時刻を入力にし、`parent-merge-criteria.md` の **委任で印を付ける** の手順に渡す（委任が有効・最後の発言の時刻が委任の確認の timestamp より後・今の HEAD の宣言が `論点なし — ` の行を持ち同じ HEAD の `論点なしの確認: 通す` の記録がある・可の条件）。印を付けたらエピックに `委任で送った: 子 #<N> <最後の発言の uuid> 委任の記録: <委任の記録の URL>` を残す。**実機操作の止まり**: どの種類の委任も効かない。論点ありの止まり（`主に聞く理由:` が論点ありと書くか、最新の `## リスク宣言` が `論点あり — ` の行を持つ）、方針の選び直しの止まり、委任の確認より前の止まり、推奨が `許容しない` の止まり、`needs-approval` か必要な宣言の無いリスク許容の止まりには、どちらの種類の委任も効かない
