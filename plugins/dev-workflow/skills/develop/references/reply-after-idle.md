# 時間がたった子・親への返事

エピックの子（Orca 経路の子セッション）と親（エピックを回すセッション）に、止まってから時間がたって返事を送るときの規則。会話のキャッシュは 1 時間で切れるので、そのまま送ると会話全体 N を書き込み直す（入力換算で 2N）。Claude Code の待っている間の自動コンパクトは、最後のリクエストから約 54 分で、会話が `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS`（既定 200,000、下限 100,000）以上なら会話を要約に置き換え、この費用を減らす。54 分は変えられず、PC が寝ている間は走らない。

送り方と起動し直し方の手順本体はここに書かない。止まった子を親が解決する手順（#1034。develop の SKILL.md「回し方」の Orca 経路の手順 8 と `scripts/epic-dispatch.sh reply`）が書き、ここを参照する。

## 閾値

| セッション | 値 | 付ける場所 |
|---|---|---|
| 子 | 120,000 | `epic-dispatch.sh launch` が子の起動コマンドの先頭に `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS=120000` を付ける。`EPIC_DISPATCH_IDLE_COMPACT_MIN_TOKENS` で変えられる（空か数字でなければ `launch` は使い方を出して exit 1） |
| 親 | 100,000 | 親は主が起動するセッションなので harness からは付けられない。主が親を起動するコマンドの先頭に `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS=100000` を付ける |

どちらの値も `~/.claude/settings.json` の `env` には置かない（主の手元の全セッションに効くため）。この変更より前に起動された子と、値を付けずに起動した親は既定の 200,000 のまま動く。

## そのまま送るか、起動し直すか

子に返事を送る前に、上から順に当てはめて決める。

| 子の状態 | 扱い | 理由（入力換算の費用） |
|---|---|---|
| 子の端末が無い | 起動し直す | ほかに手がない |
| 子の最後のリクエストから 60 分未満 | そのまま送る | キャッシュが生きている（0.1N） |
| 60 分以上で、その間に待っている間の自動コンパクトが走った | そのまま送る | 要約後の会話の書き込みで約 140k。起動し直し（平均約 258k）より安く、子の判断も残る |
| 60 分以上で、コンパクトが走っておらず、会話量 N が 150,000 以上 | 起動し直す | 2N が 300k 以上になり、起動し直しの平均を超える |
| 60 分以上で、コンパクトが走っておらず、会話量 N が 150,000 未満 | そのまま送る | 2N が起動し直しより安い |

判定に使う事実:

- **子の端末の有無**: 子のワークスペースに端末が残っているか（確かめるのは `scripts/epic-dispatch.sh reply` で、端末が無ければ起動し直して返事を付ける。#1034）
- **最後のリクエストの時刻とコンパクトの有無**: 子のワークツリーのセッションのトランスクリプト（`~/.claude/projects/` 配下の jsonl）の最後のリクエストの時刻と、そのあとに `compact_boundary` の行があるか
- **会話量 N**: 同じトランスクリプトを `plugins/dev-workflow/scripts/subagent-context.sh --file <トランスクリプト>` で測る

60 分前後や 150,000 前後で扱いが揺れる子、トランスクリプトが複数あってどれが子のものか分からない子は、そのまま送ってよい。

## 親への適用

親自身が長く待ったあと（背景の `wait` の終わりで起こされたときを含む）も、同じ表で、そのまま続けるか起動し直すかを決める。親の端末は主が持っているので、端末が無い行は当たらない。

親を起動し直したら、状態はエピックのコメントと依存グラフから復元する。

| 状態 | 復元元 |
|---|---|
| 回し方 | エピックの `回し方:` のコメント |
| 終わった子 | `子 #N マージ → 残り k 件` / `子 #N 見送り` のコメント |
| 外した子エピック | `後で別に起動するエピック:` のコメント |
| 残したワークツリー | `子 #N のワークツリーを残した` のコメント |
| 親が通した判断 | `親の判断: 子 #N 通した` のコメント |
| 残りの子 | 依存グラフと子 issue の状態から求め直す |

## 根拠と、この数字の限り

値と条件は、手元のログ（子 1,592 本・親 37 本、2026-09-16〜10-15）の集計から決めた。集計の全体:
https://github.com/oratta/claude-harness/issues/1039#issuecomment-6182988861

- 1 時間以上たってから返事が来た割合（会話 100k 以上の止まった点）: 子 3.2%、親 40.6%
- 返事の直前の会話の中央値: 子 159k、親 152k。既定の 200,000 ではほとんどがコンパクトの対象外
- 起動し直しの費用（起動時の読み込みの書き込みと作業の組み立て直し）: 子で中央値 197k・平均 258k
- 閾値ごとの費用の増減（期間合計、入力換算）: 子は 120k で −41.3M（基本の想定）・−12.4M（控えめの想定）、親は 100k で −26.8M・−9.5M。既定の 200k は子 −16.1M・親 −3.6M
- 返事が来ないまま端末が開いていると、コンパクトの費用が無駄になる。返事なしで終わった子の端末が全部開いたままの最悪の想定では、子の 120k は既定より損（+10.5M）。Orca 経路の子は `reap` で端末が閉じるので当たりにくい
- 待っている間の自動コンパクトの実績は 14 回だけで、要約の大きさと読み直しの量はその少ない例から出した。PC が寝ていたかはログから分からず、寝ていると効果は小さくなる
