develop の SKILL.md から移した節。読むのは本体で、SKILL.md の 1 ループの (2) で R1 が 2 周目以降の周の終わりに `REQUEST_CHANGES` を返したときと、(4) で G が `needs-fix-check` を返したとき（その分岐の手順に入る前に Read する）。指摘が返らなかったサイクルでは読まない。パスの書き方は SKILL.md と同じ（`skills/develop/` から見た相対パス）。

## レビューの周を主に聞かずに続ける（直し方の判定）

仕様レビュー（R1）と PR のレビュー（G）の両方で、2 周目以降の周の終わりに止める指摘が残ったときの本体の手順（#722）。この節が正本で、`references/roles/spec-reviewer.md` と `skills/pr-review-gate/stages/triage.md` は規則を短く書いてここを指す。判定の記録と事後報告の書式はこの節にだけ置く。

**規則**: 2 周目以降の周の終わりに残った止める指摘（仕様レビューは R1 の `REQUEST_CHANGES` の BLOCKER、PR のレビューは G が `needs-fix-check` で渡した指摘）がすべて直し方が決まっているもので、PR トークン上限の計測が exit 2 でなければ、本体は主に聞かず次の周を回し、記録先に事後報告を残す。主に聞くのは、方針の選び直しが要るとき（直し方の判定が「選び直しが要る」。入力不足で判定が出なかったときを含む）と、PR トークン上限を超えたとき（`pr-token-budget.sh` が exit 2）の 2 つだけ。interactive と unmanned で同じに扱う。主に聞かずに回す周の回数に上限は置かない（止めるのは PR トークン上限・直し方の判定・PR 側の順 6 の「PR ごとに 1 回まで」）。

**判定役**: 本体が決める役を `subagent_type: dev-workflow:decider` で起こす。モデルは仕分け表の順 6 の決める役と同じく残量モードどおりにし、`model` を明示する。description には記録先番号 `#N` を入れる（PR トークン上限の計測に含めるため）。起こす前にSKILL.md の「PR トークン上限」の節の計測を行い、exit 2 なら起こさず exit 2 の手順で止まる。G・本体・レビュアーの申告を判定の代わりにしない（レビュアーの申告は決める役への入力として渡す）。

**依頼の契約**: 依頼は、順 6 の裁定とマージ可否を問うときと同じ `agents/decider.md` の「可否と根拠」の出力契約で出し、問いを「残った指摘はすべて直し方が決まっているか（可）、1 件でも選び直しが要るか（否）」の 1 つにする。決める役が通常の 3 点（原因の分類・直す箇所と方法・次の実行役のモデル）で返す取り違えを防ぐため、依頼文に「3 点ではなく可否と根拠で返す」と書く。`agents/decider.md` は変えない。

**「直し方が決まっている」の定義**: 指摘ごとに次の 3 つをすべて満たすとき「決まっている」とする。1 件でも満たさなければ、その周の判定は「選び直しが要る」。

1. 直し方が 1 つに決まる。選択肢が残っていても、どれを選んでも受け入れ条件と利用者に見える振る舞いが変わらず、選ぶのに主の側にしか無い情報（好み・事業判断・許容度）が要らないなら、決める役が記録先と指摘から 1 つを選び、選んだ直し方とその理由を返答の指摘ごとの直し方に書いたうえで「決まっている」に数える
2. 記録先の範囲（受け入れ条件・issue の範囲）を変えない
3. 前の周で「決まっている」と判定した直し方を当てたのに閉じなかった指摘ではない

**入力**: 決める役は `Bash` を持たないので、本体が次を入力文に貼る。

- 記録先の本文と関連コメント（受け入れ条件・`仕様化判断:` の記録・それまでの `直し方の判定:` の記録）
- 残った指摘の原文（仕様レビューは最新の `仕様レビュー: REQUEST_CHANGES` のコメント、PR のレビューは G の仕分けの PR コメントとレビュアーの要約）
- 前の周の指摘の原文
- 対象ファイルのパス（change の artifact、または PR の変更ファイル）
- W の直近の return

**返答の 1 行目**: 依頼文で 1 行目を `裁定: 可`（すべて決まっている）・`裁定: 否`（1 件でも選び直しが要る）・`不足: <足りないもの>` のどれかちょうどに指定し、2 行目以降に指摘ごとの直し方（1 行）か、選び直しが要る理由（選択肢、または変わる範囲）を書かせる。本体は 1 行目だけで分岐する（本文の読み取りで分岐しない）。1 行目が `不足:` か 3 形のどれにも一致しなければ、足りないものを補って同じ問いで 1 回だけ依頼し直し、2 回目も同じなら「選び直しが要る」として扱う（3 回目の依頼はしない）。

**判定の記録**: 返答を受け取ったら、本体が記録先に判定の記録のコメントを投稿する（決める役は投稿できないので代理投稿する。PR のレビューでも G ではなく本体が投稿する）。1 行目は正規表現 `^直し方の判定: (決まっている|選び直しが要る)$` に完全一致させ（太字・全角コロン・末尾句点を付けない）、2 行目以降に次を `項目名: 値` で書く。

| 項目 | 中身 |
|---|---|
| 対象 | `仕様レビュー` または `PR レビュー（PR #N）` |
| 周 | 何周目の終わりか |
| 判定役 | `dev-workflow:decider`・モデル・本体が代理投稿 |
| 指摘ごとの判定 | 続く行に 1 行 1 件で、指摘の要約と原文の URL、直し方か選び直しの理由 |
| 入力不足 | `なし`、または 2 回目も不足で「選び直しが要る」とした場合の足りなかったもの |

**続行と事後報告**: 判定が「決まっている」なら、仕様レビューでは W を `段: spec` で再開して artifact を直させ、R1 に次の周の差分再レビューをさせる。PR のレビューでは判定と判定の記録の URL を渡して照合と振り分けの G を新しく起こす（G が仮の順どおりに W に戻す）。各 spawn・再開の前の PR トークン上限の計測は省かない。主に聞かずに回した周の結果を受け取ったら（仕様レビューは R1 の結果、PR のレビューはその周の照合と振り分けの G の return）、記録先に事後報告のコメントを投稿する。1 行目は正規表現 `^主に聞かずに回した周: [0-9]+ 周目$` に完全一致させ、2 行目以降に次を `項目名: 値` で書く。

| 項目 | 中身 |
|---|---|
| 対象 | 判定の記録の `対象` と同じ |
| 残っていた指摘 | 前の周の終わりに残った指摘の要約を 1 行 1 件、またはそれを載せたコメントの URL |
| 判定の根拠 | 判定の記録のコメント URL |
| 使ったトークン | 周の前の合計 → 周のあとの合計、その差、上限 |
| 周の結果 | その周のレビュー結果 |

`使ったトークン` の 2 つの値は、本体が spawn・再開の前に毎回とる PR トークン上限の計測の値を使う（周の前は直し方の判定の決める役を起こす前の計測、周のあとは周の結果を受け取ったあと最初の計測）。新しい計測の仕組みは足さない。

**主に聞くとき**: 判定が「選び直しが要る」なら、仕様レビューでは記録先に `needs-approval` を付けて経緯をコメントし、interactive は AskUserQuestion で判断を仰ぎ、channel はそのコメントのフル URL を添えてチャンネルで聞き（`references/channel.md` の「channel の聞き方」）、unmanned はそのサイクルを終える。そのときの引き継ぎは `references/handover.md` の場面「レビューの 2 周キャップ超え」として書き、待ち理由は `2 周キャップ超え` とする。PR のレビューでは判定と判定の記録の URL を渡して照合と振り分けの G を新しく起こし、G がその指摘を順 5 に当てて主に聞く。PR トークン上限が exit 2 ならSKILL.md の「PR トークン上限」の節の exit 2 の手順に従う。

この判定の守備範囲は、2 周目以降の周の終わりに残った指摘について、主の判断が要る指摘を主に聞かずに進めてしまうことを防ぐことである。拾いたいのは、選ぶのに主の側にしか無い情報が要る、または選択肢によって受け入れ条件や利用者に見える振る舞いが変わる設計の選択肢から選ぶ必要がある指摘・記録先の範囲を変える指摘・前の周で決まっているとした直し方で閉じなかった指摘で、これらは主に上げる。直し方が 1 つに決まる指摘（例: 受け入れ条件の文と artifact の 1 文が食い違い、artifact 側を受け入れ条件に合わせれば閉じる BLOCKER。同じ文言が別の場所に残っている指摘）と、選択肢の違いが受け入れ条件と利用者に見える振る舞いを変えない指摘（例: BLOCKER を閉じるテストを、外から親を一時停止して書くか、本体にテスト用の待ちを入れて書くか。どちらでも実装の振る舞いは同じ）は主に聞かずに通す。判定が「決まっている」とした直し方が外れることは防がない（次の周の終わりの判定の 3 つ目の条件で拾う）ので、判定の誤りが 1 件も無いことをこの手順の完了条件にしない。
