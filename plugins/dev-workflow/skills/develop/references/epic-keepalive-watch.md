# 停止中の子への声かけの見張り（親専用）

親が停止済み子の声かけを扱う前に読む。予約文・受信契約と child-log の保証は `references/epic-keepalive.md`、固定文字列と返事の型は `references/child-cache-keepalive.json`（プラグイン直下）を読む。

### 停止中の子へのキャッシュ維持（#1383）

親の通常の `wait --watch-stopped` が、止まった発言の uuid（`stop_uuid`）か主の返事待ちの停止記録があり未回答、stop=stopped-seen、TTL 1h の子だけに固定の声かけを送る。最後の成功した CLI リクエスト（cache-hit を含む）から 3000 秒以上 3600 秒未満、止まった時刻（`stop_at`。空なら記録の作成時刻）から `EPIC_DISPATCH_OWNER_WAIT_SEC` 秒（既定 43200 秒。`wait` の長い待ちの上限と同じ値）未満のときに限る。TTL は最後の書き込みから読み、リクエスト時刻とは分ける。既存の会話量による再起動条件、計測不能・複数セッション、前の声かけの返事未着、実際の回答ありも対象外。

起動部品は既存の一意な前景の入力待ち・空欄にだけ送り、声かけのために起動し直さない。声かけも異常な返事も停止の印や停止コメント、声かけの期限の基点を延ばさない。3600 秒以上たったスリープ復帰後と期限（`EPIC_DISPATCH_OWNER_WAIT_SEC` 秒）の後は送らず、実際の返事は `reply-after-idle.md`「そのまま送るか、起動し直すか（子）」へ渡す。

TTL 5m/unknown には送らない。overage 等で 5m に変わっても、キャッシュ書き込みによる切替を観測するまで検知できないため、切替直後の一回の書き直し費用を防げない場合がある。五分ごとの声かけはしない。


送信失敗は stderr に残して次回の通常のポーリングに任せる。子の発言の内容を判定したり、声かけの返事から作業を進めたりしない。

一回確認（`--interval 0 --timeout 0`）と片付け待ちだけの wait では送らない。入力を消去しない。親の timeout 後の同じ wait の一回の掛け直しは、`references/epic-loop.md` 手順５に従う。
