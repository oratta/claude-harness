# 停止中の子への声かけの見張り（親専用）

親は停止済み子の声かけ前に読む。予約文・受信契約・child-log の保証は `references/epic-keepalive.md`、固定文・返事の型はプラグイン直下 `references/child-cache-keepalive.json` を読む。

### キャッシュ維持（#1383）

通常の `wait --watch-stopped` は、`stop_uuid` または主の返事待ちの停止記録があり未回答、stop=stopped-seen、TTL 1h の子だけへ送る。最後の成功 CLI リクエスト（cache-hit 含む）から3000秒以上3600秒未満、停止時刻 `stop_at`（無ければ記録作成時刻）から `EPIC_DISPATCH_OWNER_WAIT_SEC` 秒（既定43200秒、wait上限と同値）未満に限る。TTLは最後の書き込みから読み、リクエスト時刻とは分ける。既存の会話量による再起動条件、計測不能・複数セッション、前の声かけ未回答、実際の回答ありは対象外。

既存の一意な前景の入力待ち・空欄にだけ送り、再起動・入力消去はしない。声かけや異常な返事で停止印・停止コメント・期限基点を延ばさない。3600秒以上のスリープ復帰後と期限後は送らず、実際の返事は `reply-after-idle.md`「そのまま送るか、起動し直すか（子）」へ。TTL 5m/unknown には送らない。overage等で5mになっても書き込み観測まで検知できず、切替直後一回の書き直し費用は防げない場合がある。五分ごとには送らない。

送信失敗はstderrに残し次の通常ポーリングへ。子の発言を判定せず、声かけの返事で作業を進めない。一回確認（`--interval 0 --timeout 0`）と片付け待ちだけのwaitでは送らない。親timeout後の同じwaitの一回の掛け直しは `references/epic-loop.md` 手順５へ。
