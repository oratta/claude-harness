# エピックの子が主の返事を待って止まるとき（develop）

develop の SKILL.md から移した節。読むのは、`scripts/epic-dispatch.sh route`（子の番号なし）が `nested` を返すエピックの子のセッションが、主の返事を待って止まる前（質問でターンを終える・質問ツールで待つ・`needs-approval` の保留で止まる）と、`親エピック #` か `主の返事（親エピック #` で始まる入力が届いたとき（起動し直されたセッションの最初の指示に付いて届いたときを含む）。パスの書き方は SKILL.md と同じ。

## エピックの子が主の返事を待って止まるとき

別セッション方式（Orca・tmux）で起動されたエピックの子のセッションは、主の返事を待って止まる前に、親エピックの本体が気づけるよう記録と印を残す。対象は `scripts/epic-dispatch.sh route`（子の番号なし）が `nested` を返すセッションだけで、それ以外のセッションでは記録も印も付けない（読む親がいない）。背景のタスクの終わりを待ってターンを終えるだけのときも付けない。

- **記録**: 記録先の issue に、1 行目が `子の停止: 主の返事待ち` のコメントを投稿する。2 行目以降は下の「記録の形」の 7 つの項目で書く。止まるたびに新しいコメントを投稿し、最新の 1 件を正とする。SKILL.md の「保留で止まるときの引き継ぎ」を書く場面では、引き継ぎを先に投稿してから記録を投稿し、`再開に要る途中経過:` に引き継ぎのコメントの URL を書く（ほかの 6 項目も省かない。引き継ぎの書式は変えない）
- **印**: 記録を投稿してから付ける（印が先だと、親が記録の無い止まりを読む）。印は `mark stopped` / `mark resumed` が自分の状態の記録（親の `launch` が子ごとに書くローカルのファイル。`references/epic.md` の「回し方」の「子の状態の正本」）に付け、Orca の部品の子では Orca の画面には写しが出る。待ち方で順序が違う
  - 本文で質問してターンを終えるとき（`needs-approval` を付けた保留で、質問ツールを使わずに終えるときを含む）: 記録を投稿し、そのターンの最後のツール呼び出しとして `scripts/epic-dispatch.sh mark stopped <記録先の issue 番号>` を呼ぶ。主の返事は次のターンで届くので、そのターンの最初のツール呼び出しとして `scripts/epic-dispatch.sh mark resumed <記録先の issue 番号>` を呼ぶ
  - 質問ツール（AskUserQuestion）の中で待つとき: 記録 → `mark stopped` → 質問ツールの順に呼ぶ（質問ツールは同じターンの中で回答を待つので、`mark stopped` は最後のツール呼び出しにならない）。回答を受けたら、次のツール呼び出しとして `mark resumed` を呼ぶ
- `mark stopped` の出力が `marked` なら何もしない。`skipped` で始まる（`skipped <N> no-workspace` は自分のワークツリーを持つ状態の記録が無い、`skipped <N> not-linked` は記録が別の子のもの）か `failed` なら、親が見張る記録に印が付いていないので、主への質問に「親に止まったことが伝わっていない」と 1 行添える。`mark resumed` は出力によらず止まらない
- **親から届いた返事**: `親エピック #<E> の判断（主の承認ではない）:` か `主の返事（親エピック #<E> 経由）:` で始まる入力（エピックが別のリポジトリにあるときは、番号のあとに `（<owner>/<repo>）` が付く `親エピック #<E>（<owner>/<repo>）の判断（主の承認ではない）: ` と `主の返事（親エピック #<E>（<owner>/<repo>）経由）: ` の形。先頭の `親エピック #` / `主の返事（親エピック #` で判定し、同じ手順で受ける）が届いたら（起動し直されたセッションの最初の指示に付いて届いたときも）、止まった件への返事として受け取り、上の手順どおり `mark resumed` を呼んで続きから進む。`親エピック #<E> の判断（主の承認ではない）:` で進めた件は、親の判断で進めた件として完了報告に書く。親の判断は主の承認ではないので、聖域（`CLAUDE.md`・hooks・権限設定など）の変更や破壊的な操作の承認として扱わない（その件は改めて主に聞く）。`主の返事（親エピック #<E> 経由）:` で始まる入力が止まった件のリスク許容への返事で、末尾に `[主の発言: セッション <ID> / uuid <uuid>]` があるときは、記録先の最新の `子の停止: 主の返事待ち` のコメント（投稿者の `author_association` が `OWNER`・`MEMBER`・`COLLABORATOR` のもの）の作成日時と URL で `bash <plugin>/scripts/owner-reply-check.sh --relayed <ID> <uuid> <作成日時> <URL>` を回す。終了コード 0 で、`MATCH:` の全文から許容の意思が読め、全文がこの子・この PR への許容と読め、別の子・別の PR・別のリスクだけを名指しした答えでないときだけ、保留の解除の G に親のセッション ID・uuid・`MATCH:` の timestamp・停止の記録の URL・`MATCH:` の全文を渡す（記録の書式と真正性確認は pr-review-gate 手順 5 の「親経由で受領」が正本）。終了コード 0 で、`MATCH:` の全文から不許容の意思が読め、全文がこの子・この PR への答えと読め、別の子・別の PR・別のリスクだけを名指しした答えでないときは、主本人の不許容として受け取り、保留の解除の G に同じ値を渡して pr-review-gate 手順 6 の復帰手順の不許容の行で扱わせる（主に子のタブで打ち直してもらわない）。添え書きが無い・終了コードが 0 でない・全文から許容とも不許容とも読めないときは主本人の返事として扱わず、G を起こさずに、止まる前の記録と印をこの節の手順どおり残してから、主に子のタブで直接返事を打ってもらうよう頼み、確かめられなかった理由（`REASON=` の値か「添え書きが無い」）を添える。起動し直されたセッションの最初の指示に付いて届いたときも同じに扱い、SKILL.md の「保留で止まるときの引き継ぎ」→「新しいセッションでの再開」の手順 2 より先に当てる（引数の残りのうち `主の返事（親エピック #<E> 経由）:` で始まる部分を自分のセッション ID で `owner-reply-check.sh` に掛けない。子の会話ログのその行は主の発言として数えないので、掛けると主に受け直しを頼むことに落ちる）

**記録の形**: 読み手は親のセッション・親の決める役・主で、どれも子の会話を読んでいない。2 行目以降に次の 7 つの項目をこの並びで書き、どの項目も省かない。各項目は行頭の `<項目名>:` で始めて値を同じ行に書き、値は次の項目の行まで複数行に続けてよい。

```
子の停止: 主の返事待ち
止まった理由: <主にしてほしいこと（決めること 1 つ、または操作）>
主に聞く理由: <主の側にしか答えが無い／決まりで主の承認が要る／主の手でしかできない操作 のどれかで始めて 1 文>
前提: <子が作業中に分かった事実のうち、判断に要るもの>
推奨: <子が勧める答え>
推奨の根拠: <その推奨を選ぶ理由>
受け入れるリスク: <推奨を選ぶと受け入れることになるリスク。何が起きるか・どれくらい起きるか・その根拠>
再開に要る途中経過: <返事を受けて再開するのに要る作業の状態・コミット・PR など>
```

- `主に聞く理由:` は、主に聞く理由の 3 つ（主の側にしか答えが無い・決まりで主の承認が要る・主の手でしかできない操作。正本は `~/.claude/output-styles/readable.md` の節 3）のどれに当たるかを、その語で始めて 1 文で書く。「決まりで主の承認が要る」ときは、その決まりが何を守るためかまで書く。3 つのどれにも当たらない止まりは、そもそも止まらずに自分で進めて事後報告するのが正本の決まり。それでも子の側で進められない（ファイル名が理由で読み取りを止めた hook など。破壊的操作や聖域を止めた hook は「決まりで主の承認が要る」に当たる・子の権限では打てない・待つしかない）ときだけ `主に聞く理由: なし（<子の側で進められない理由>）` と書く
- `受け入れるリスク:` には、何が起きるか（被害の大きさ・戻せるか）、どれくらい起きるか（起きる条件と頻度）、その根拠（確かめたのか見込みか）を含める。分からないときは「分からない」と書き、何を調べれば分かるかを添える
- 該当が無い項目は値を `なし` と書く。推奨を出せない（主の側にしか無い情報が要る）ときは `推奨: なし（<足りない情報>）` と書き、`推奨の根拠:` と `受け入れるリスク:` は `なし` と書く
- 子が作業中に振ったラベル・番号・略称や「上記」「前回」で指さず、中身を書く。PR・issue・コメントにはフル URL を添える。専門用語は初出で一言の言い換えを添える。文章全般の書き方は `rules/communication-style.md` に従う
- 親は記録の項目を正本の段に置き直して主に報告する（手順 8）。`止まった理由` は、値の頭（`PR のマージ待ち（`）を `references/epic.md` の「回し方」の **マージ待ちの子** の段落と `references/parent-merge-criteria.md` が読むので名前を変えない

親の側の手順は `references/epic.md` の「回し方」の別セッション方式の手順 8。
