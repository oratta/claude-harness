# G の照合と振り分け — レビュー要約の受領

照合と振り分けの G と、一括（従来経路）の G だけが読む。共通欄は `gate-runner.md`、仕分けの正本は `skills/pr-review-gate/stages/triage.md`。

## 一周目の三表を機械照合する

一周目のレビュー要約を受け取ったら、指摘の仕分け前に次を機械照合する。G はここで変更点の意味や `一致` / `食い違い` の正しさを再レビューしない。

1. 記録先の各受け入れ条件が `変更点の一覧` の変更点 ID に 1 回以上対応しているかを集合比較する。
2. 各 `照合表` を `plugins/dev-workflow/scripts/review-hit-set.py --repo <repo> <table-file>` に渡し、固定 HEAD で再実行した repository-wide な grep の全ヒット集合と一致するかを確認する。場合分けの軸はこのスクリプトへ渡さず、軸の全域と表の行だけを比較する。
3. 固定した PR diff の全ハンクをファイルとハンクヘッダーで列挙し、`ハンク被覆` が全ハンクを 1 回以上含むかを集合比較する。

一周目の要約に `区画 <k>/<n>` の見出しがある場合、先に最新の `レビュー重量:` コメントにある区画の数と受け取った三表の区画の数を比べ、足りない区画を残差にする。受け入れ条件の被覆は全区画の `変更点の一覧` の和集合、ハンク被覆は全区画の `ハンク被覆` の和集合を PR 全体と集合比較する。各区画の `照合表` はそれぞれ `review-hit-set.py` に渡す。区画 k の変更点 ID と finding ID が `P<k>-` で始まることも確かめ、外れた ID はその区画の残差にする。区画に分けなかった一周目（`区画 <k>/<n>` の見出しが無い）は区画の数を比べず 1 組の三表で照合する。

残差の補足先は、足りない区画ならその区画、ハンク被覆ならそのハンクのファイルが属する区画、照合表と ID の接頭辞ならその表や ID を出した区画、受け入れ条件の被覆なら区画 1 とする。区画 1 は受け入れ条件の被覆の残差について、受け入れ条件の全文・全区画のファイル一覧とそのハンクを読んでよく、`P1-` の変更点 ID で補う。対応が無ければ `P1-` の finding を返す。補足要求には残差のある区画ごとに元の三表と残差を分けて載せる。補足済み回数は区画ごとではなく PR で 1 つだけ数える。

表の欠落または集合差分があり `補足済み回数: 0` なら、固定 HEAD・元の三表・正確な残差・`補足済み回数: 0` を持つ `needs-reviewer` payload で不足項目だけを補わせる。補足はレビューのやり直しではない。補足の `needs-reviewer` を返す前に、元の三表・`一周目の区画: <なし | n>`・`補足済み回数: 1`（補足を頼んだ時点で 1 と数える。payload は 0 のまま）の行を持つ `レビュー三表:` のコメントを PR に投稿する（共通 role の「段ごとの入力」）。補足済み回数は最新の `レビュー三表:` のコメントから読み、fresh reviewer または fresh G へ交代してもリセットしない。

## 補足レビュー結果の受領

最新の `レビュー三表:` のコメントから元の三表・`一周目の区画:`・補足済み回数を読み、補足結果を加えて同じ機械照合を再実行する。一周目の区画の構成で和集合を再照合し、区画を計算し直さない。`補足済み回数: 1` で残差があれば、残差を PR コメントと Gate Result に記録し、terminal Status `review-incomplete` で return する。2 回目の `needs-reviewer` を返さない。手順 3 以降の合格処理へ進まない。差分が解消した場合だけ通常の指摘仕分けへ進む。

## レビュー要約の入力

- **レビュアーの要約受領**: `stages/triage.md` の「G として動くとき（develop）」節にある「レビュー実行者:」コメントを投稿してから、一周目は最初に `変更点の一覧`・`照合表`・`ハンク被覆` を上の同名節どおり機械照合する。不足または差分があれば、`補足済み回数: 0` では Status `needs-reviewer` で不足分だけの補足へ接続し、`補足済み回数: 1` では `review-incomplete` で止める。三表の照合が完了したあとだけ要約に指摘が残っているかで分岐し、指摘が無ければ手順 3 以降（この G は宣言をせず、Status `次の段へ`・`次の段: 合格処理` で返す）。指摘が残っていれば、周の数に関係なく pr-review-gate 手順 2-1 の仕分け表（`stages/triage.md`）に上から当てる（順 1 は全周共通の判定）。止める指摘が無く順 1 だけなら、止めない指摘の振り分け表（`stages/triage.md`）に通す。1 周目に段 A に当たる指摘があれば `agent-review:failed` に付け替えて failed で返し、無ければ段 B 以降の結果を仕分けに記録してから（振り分けで issue にすると決まった指摘だけが follow-up issue になる）同じく `次の段へ`・`次の段: 合格処理` で返す。順 2〜4 は `agent-review:failed` に付け替えて failed で返し（止めない指摘は failed の PR コメントに一覧で残す）、順 5 は保留、順 6 は `needs-decider` で返す。ただし 2 周目以降の周の終わりには順 2〜4 をそのまま使わない。pr-review-gate 手順 2-1 の周の終わりの段落どおり、同じ型の再発は順 6、それ以外は判定に回す条件に当たれば `needs-fix-check`（直し方の判定。指摘ごとの仮の順を仕分けに記録する）、当たらなければ順 5 で返す。順 5 と順 2〜4、または順 5 と順 6 が混ざれば保留だけを先に返す。保留と `needs-decider` を同じ return で指示しない。判定に回す指摘と未裁定の順 6 が混ざれば `needs-fix-check` だけを先に返し、`needs-fix-check` と `needs-decider` を同じ return で指示しない（処理順は pr-review-gate 手順 2-1 の混在の段落）。仕分けは PR コメントに記録する
- **補足レビュー結果の受領**: 上の同名節どおり `補足済み回数: 1` を維持して三表を再照合する。残差があれば `review-incomplete`、無ければ同じ一周目の指摘仕分けへ進む
