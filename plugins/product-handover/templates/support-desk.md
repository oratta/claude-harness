# サポート窓口の設定（雛形）

プロダクトの問い合わせ窓口を1つ用意し、集約先の受信箱に流す。ここで決めた
アドレスは利用規約・プライバシーポリシー・返金ポリシー・特定商取引法表記の
すべてから参照されるので、法務ドラフトを書く前に決める。

## 命名規則

```
support-<slug>@<domain>
```

`<slug>` はプロダクト名から機械的に導出する（小文字・ハイフン区切り）。

**`+` サフィックスではなくハイフンを使う。** Cloudflare Email Routing は `+` 付きアドレスを
完全一致で解決しないため届かない（2026-07-13 に実際に届かず判明）。加えて `+` を含む
アドレスは Web フォームのメールバリデーションで弾かれることがある。ハイフンなら
どのメールシステムでも安全に扱える。

## ルーティング（catch-all は使わない）

ドメインの catch-all を有効にすると、そのドメイン宛のランダム送信とスパムを全部受けることに
なる。プロダクトごとに**個別のルーティングルールを1件だけ**作る。

| 項目 | 値 |
|---|---|
| 送信先アドレス | `support-<slug>@<domain>` |
| 転送先 | 集約先の受信箱 |
| catch-all | 無効のまま |

Cloudflare Email Routing ならダッシュボードか API でルールを1件作る。ドメインの
DNS を Cloudflare 以外で管理しているなら、その事業者の転送機能で同じ形を作る。

## 受信側の仕分け

集約先の受信箱に `to:support-<slug>@<domain>` のフィルタを作り、ラベル付けと
優先度設定をしておく。プロダクトが増えるとフィルタなしでは埋もれる。

## 一次対応の範囲

エージェントに一次対応させる場合、どこまでを自走させ、どこから人間に上げるかを決めて書く。

| 種別 | 一次対応 | 人間へのエスカレーション基準 |
|---|---|---|
| 使い方の質問 | エージェント | |
| 不具合報告 | エージェント（再現と issue 化まで） | |
| 返金・課金 | | 金銭が動く判断は人間 |
| 個人情報インシデント | | 常に人間。法定の報告期限があるため即時 |
| 法的な請求・通知 | | 常に人間 |

## 人間にしかできない作業

- ルーティングルールの作成（ダッシュボード操作または API トークンの発行）
- 集約先受信箱のフィルタ作成
- 特定商取引法表記の事業者情報（住所・連絡先）の穴埋め
