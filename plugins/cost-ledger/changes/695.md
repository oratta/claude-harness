# 695: 1 回の応答が複数行に分かれても、後続行の issue と投稿の印を拾う

会話ログでは 1 回の応答（同じ `requestId`）が複数の行に分かれることがある。これまでは先頭の行だけを事実にしていたため、2 行目以降にだけある `gh issue view <番号>` や投稿（`gh pr comment` など）が帰属と区間に反映されなかった。

- `cost_ledger.py` が、2 行目以降の行から issue と投稿の印を拾い、補足の事実（`continuation: true`、トークン 0、鍵は `<requestId>#<行の uuid>`）として出す。トークン数と金額は先頭の行の 1 回分のまま変えない。実行されていない文字列（`Edit` の本文など）は拾わない
- 補足の事実は元の会話ログ内の行頭バイト位置 `source_offset` も持つ。同じ `timestamp` の後続行を、`uuid` の辞書順でなく元の会話ログの順で並べ、投稿の印の前後が入れ替わらないようにするため。`split_intervals` は timestamp → 元の requestId → 通常の事実が先 → 補足は `source_offset` 順で並べる。`source_offset` の無い補足（この変更の前の版が書いたもの）が混ざる同時刻・同一 requestId のグループは、従来の `request_id` 順に戻す。読み取りは行をバイト列のまま読み、デコードの前に位置を数える
- 補足の事実はメッセージ数（`branch` の `メッセージ`・`intervals` の `messages`・`report` の件数）に数えない
- 通常の事実が `uuid` の欄を持つようになった。複製された履歴（resume・fork）の先頭の行を補足と取り違えないため。`uuid` の無い古い台帳の行も読める
- `ledger-sync --rescan` を足した。控えの読み終え位置を使わず、今ある会話ログを先頭から読み直し、索引に無い補足の行だけを追記する。既存の行は 1 バイトも変えない。通常の `ledger-sync` と Stop hook は `--rescan` を暗黙に行わない
- LLM のトークンは使わず、`gh` の呼び出しも増やさない。スラッシュコマンド・スキルの本文は変えていない
- 仕様: `openspec/specs/cost-ledger-attribution/spec.md`・`openspec/specs/cost-ledger-persistence/spec.md`（archive 後）
- テスト: `plugins/cost-ledger/tests/multiline.bats`（24 件。同時刻の後続行の並び・位置の一致・位置の無い補足の互換・トークン 5 種のゼロ化・通常の同期が既読ログを開き直さないことを含む）。`facts.bats` の事実の欄の一覧に `uuid` を足した
- 利用者がやること: 補足を足す前に書いた台帳を直すなら、**1 回だけ** `python3 scripts/cost_ledger.py ledger-sync --rescan` を流す（実行前に台帳を `cp` で控える。会話ログが既に消えた期間の補足は補えない）。流さなくても、これから先の応答は通常の同期で補足の行が付く

### 位置（`source_offset`）を足した後の測り直し（2026-10-07、同じ Mac）

読み取りを、行をバイト列のまま読んで位置を数える形に変えたので、全履歴 1 パス・Stop hook・`--rescan` を測り直した。計測中の load average は 55〜120 で、絶対値は上の表より大きくばらつく。位置を足す前の版（このブランチの前の HEAD `abf75986` のスクリプト）と今の版を交互に同じ条件で流した。

| 項目 | 位置を足す前の版 | 位置を足した今の版 |
|---|---|---|
| 全履歴 1 パス（`facts`、台帳なし、3 回） | 47.9 / 30.1 / 38.9 秒（中央値 38.9 秒） | 27.2 / 22.2 / 26.9 秒（中央値 26.9 秒） |
| Stop hook 1 回相当（`ledger-sync --quiet` を交互に 5 回、台帳の写しは約 16 万行） | 0.32〜0.40 秒 | 0.31〜0.38 秒 |
| `ledger-sync --rescan`（実環境の台帳の写し、控えなし） | - | 25.9 秒で 7,340 行を追記（うち 7,332 行が補足の行で全部 `source_offset` あり。残り 8 行は計測中に増えた応答） |

- 全履歴 1 パスが遅くならなかった（今の版のほうが速い値が出た）のは、行をテキストとして読み替える処理を、バイト列の行を直接デコードする形に変えたため、と見ている。負荷のばらつきが大きいので、速くなったことは主張せず「遅くなっていない」だけを記録する
- `--rescan` は、追記前のバイト数ぶんの先頭が元の台帳と `cmp` で一致した。続けて 2 回目を流したときの追記は 0 行（`multiline.bats` でも確認）
- hook の値が上の表（0.10〜0.11 秒）より大きいのは、計測中の負荷が高いため。位置を足す前の版も同じ条件で 0.32〜0.40 秒で、差は無い
