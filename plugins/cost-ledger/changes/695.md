# 695: 1 回の応答が複数行に分かれても、後続行の issue と投稿の印を拾う

会話ログでは 1 回の応答（同じ `requestId`）が複数の行に分かれることがある。これまでは先頭の行だけを事実にしていたため、2 行目以降にだけある `gh issue view <番号>` や投稿（`gh pr comment` など）が帰属と区間に反映されなかった。

- `cost_ledger.py` が、2 行目以降の行から issue と投稿の印を拾い、補足の事実（`continuation: true`、トークン 0、鍵は `<requestId>#<行の uuid>`）として出す。トークン数と金額は先頭の行の 1 回分のまま変えない。実行されていない文字列（`Edit` の本文など）は拾わない
- 補足の事実はメッセージ数（`branch` の `メッセージ`・`intervals` の `messages`・`report` の件数）に数えない
- 通常の事実が `uuid` の欄を持つようになった。複製された履歴（resume・fork）の先頭の行を補足と取り違えないため。`uuid` の無い古い台帳の行も読める
- `ledger-sync --rescan` を足した。控えの読み終え位置を使わず、今ある会話ログを先頭から読み直し、索引に無い補足の行だけを追記する。既存の行は 1 バイトも変えない。通常の `ledger-sync` と Stop hook は `--rescan` を暗黙に行わない
- LLM のトークンは使わず、`gh` の呼び出しも増やさない。スラッシュコマンド・スキルの本文は変えていない
- 仕様: `openspec/specs/cost-ledger-attribution/spec.md`・`openspec/specs/cost-ledger-persistence/spec.md`（archive 後）
- テスト: `plugins/cost-ledger/tests/multiline.bats`（15 件）。`facts.bats` の事実の欄の一覧に `uuid` を足した
- 利用者がやること: 補足を足す前に書いた台帳を直すなら、**1 回だけ** `python3 scripts/cost_ledger.py ledger-sync --rescan` を流す（実行前に台帳を `cp` で控える。会話ログが既に消えた期間の補足は補えない）。流さなくても、これから先の応答は通常の同期で補足の行が付く

## 実測（2026-10-07、開発に使っている Mac）

会話ログは実環境のもの（読み取りのみ）。台帳は実環境の台帳を一時ディレクトリへ写したもの（約 69 MB・160,420 行）に流した。足す前のスクリプトは `git show f26fbecf` の内容を一時ディレクトリに取り出して使った。計測中のマシンの負荷が高く（load average 65〜80）、全履歴 1 パスの値はばらつく。

| 項目 | 足す前 | 足した後 |
|---|---|---|
| 全履歴 1 パス（`facts`、台帳なし、6 回の中央値） | 約 41.5 秒 | 約 46.5 秒 |
| Stop hook 1 回（応答 1 行を足して 5 回） | 0.09〜0.12 秒 | 0.10〜0.11 秒 |
| `gh` の呼び出し（`cost 695`、PR 経路 / issue 経路） | 1 回 / 2 回 | 1 回 / 2 回 |
| 回収率（main / master 上のコストのうち issue 番号に帰属した割合）flatmate | 68.6%（$176.70 / $257.71） | 61.1%（$157.48 / $257.71） |
| 回収率 claude-harness | 13.4%（$10.85 / $80.76） | 44.2%（$35.67 / $80.76） |

- 全履歴の事実は 160,216 件から 167,435 件に増えた。増えた分は補足の事実 7,216 件（`issues` を持つもの 5,829 件、投稿の印を持つもの 3,732 件）と、計測の間に増えた応答
- 回収率は、main / master の事実だけを区間に切って、issue に帰属した区間の金額の割合を出した（金額の合計は前後で同じ）。flatmate が下がったのは、後続行の投稿の印で区間が正しく閉じるようになり、閉じた後ろの区間が issue に帰属しなくなったため。50% は下回らない
- `ledger-sync --rescan`（実環境の台帳の写し）: 57.5 秒で 7,335 行を追記。追記前のバイト数ぶんの先頭は元と一致。2 回目は計測中に増えた応答だけ（実環境のログは更新され続けているため 0 行にならない。会話ログが動かない fixture では 0 行であることを `multiline.bats` で確かめている）
