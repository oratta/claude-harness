# backfill.sh / gate-report.sh が dirname 不在の PATH でカレントディレクトリを引かないようにする（#854）

- **振る舞いの変更**: `scripts/backfill.sh` と `scripts/gate-report.sh` は、自分の場所を `$(dirname "$0")` ではなく `${0%/*}` から求める。`PATH` に `dirname` が無いと、今までは `cd ""` が成功してカレントディレクトリを `scripts_dir` に使い、そこに `backfill.py`・`gate_report.py`・`write_allow.py` があれば読んでいた。今は場所を求められなければ（`$0` にスラッシュが無い・`cd` が失敗）何もせず `exit 0` する
- 直さないもの: `PATH` に `bash` が無いときの `env: bash: No such file or directory`。`#!/usr/bin/env bash` の解決はスクリプトが始まる前で、スクリプトの中から消せない。`hooks.json` の呼び出し方を変えると `PATH` が正常な環境の起動経路が変わりうるため、前提（利用者の `PATH` が壊れている）が攻撃側から作れないこともあり、直さずに閉じる
- テスト: `tests/backfill.bats` と `tests/gate-report.bats` に、`dirname` が無い `PATH` でカレントディレクトリのダミーが読まれない（マーカーが残らない）ことを 1 本ずつ足した。変更前のスクリプトでは落ちる
- 戻し方: 2 つのスクリプトの `scripts_dir` の 4 行を元の `$(cd "$(dirname "$0")" ...)` の 1 行に戻し、足したテストを消す
