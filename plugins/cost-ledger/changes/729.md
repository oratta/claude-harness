# 729: /cost がプラグイン設定（userConfig）の台帳パスを使うようにする

#713 で userConfig の `LEDGER_PATH`（`/config` で設定）を足したが、`/cost` のコマンド本文の Bash 実行にその値が届くかは未確認だった。実機（Claude Code 2.1.292、`claude -p --plugin-dir`）で、**Bash 実行には `CLAUDE_PLUGIN_OPTION_LEDGER_PATH` が渡らない**（`CLAUDE_PLUGIN_ROOT` も渡らない）ことを確かめた。コマンド本文の中のプラグイン設定の置換は効き、未設定のときは置換されず文字列のまま残る。観測は issue #729 のコメントにある。

- `commands/cost.md` の集計呼び出しが、本文の置換値を `CLAUDE_PLUGIN_OPTION_LEDGER_PATH` として `cost_ledger.py` に渡す
- `cost_ledger.py` の `ledger_path()` は、`${user_config.` で始まる値（未設定のとき置換されずに渡る文字列）を未設定として扱い、`COST_LEDGER_PATH` に落とす
- `commands/cost.md` の未設定時の案内は `/config` を先に、従来の `COST_LEDGER_PATH`（settings.json の `env`）を次に案内する
- README の既知の制限の 1 行を、渡し方の説明に置き換えた
- `COST_LEDGER_PATH` だけの利用者は何も変えずに動く。plugin.json の `description` は変えていない。`version` は上げていない
- 受け入れた制約: パスにシングルクォート `'` を含むと `/cost` の呼び出しが壊れる（案内文と README に明記）
- 戻し方: `cost.md` の呼び出しと案内、`ledger_path()` の分岐、追加した bats 4 件を戻す
- LLM のトークンは使わない（実機確認の `claude -p` を除く）
- テスト: `tests/userconfig.bats` に 2 件、`tests/cost-command.bats` に 2 件を追加
