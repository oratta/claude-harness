# 737: issue クローズで閉じた PR の問い合わせが失敗したことを、行のきっかけの欄の印で見分けられるようにする

`gh issue close`（PR でない issue）で、閉じた PR の問い合わせ（GraphQL）が失敗したときだけ、`issue クローズ` の行のきっかけの欄の最後に `+PR 照会失敗` を足すようにした。これまでは、閉じた PR が 0 件の回も失敗した回も `issue クローズ` の行だけが積まれ、コメントを読んでも見分けが付かなかった。

- 印が付く失敗: `gh` の失敗・応答が JSON でない・応答の形の崩れ（1 件でも）・閉じた PR が 100 件を超える。成功して 0 件の回・別のリポジトリや fork の PR だけが返った回には付かない
- 例: `issue クローズ+PR 照会失敗`、`issue コメント+issue クローズ+PR 照会失敗`。失敗した回の行にだけ 8 文字（`+PR 照会失敗`）増える。成功した回の行は 1 文字も変わらない
- 合計の行は、失敗した回も今までどおり付かない。失敗した回の合計は後追い（#691）でも補われない（後追いは `issue クローズ` の要素を持つ行がある issue を候補から外す。印付きの行も外れる）。手動で合計を確認するには `/cost <issue番号>`（合計を表示するだけで、コメントの行は補わない）
- `gh` の呼び出しは、成功・0 件・失敗のどの回も PR でない issue の `gh issue close` で 4 回のまま（変更の前後で同じ）。LLM のトークンは使わない。変更は `gate_report.py` の `closing_prs()`（失敗で `None`）と `stack()`（`None` のときだけ名前を足す）。`cost_ledger.py` は変えていない
- 反映に `/reload-plugins` は要らない（`hooks.json` と `gate-report.sh` を変えていない）
- 仕様: `openspec/specs/cost-ledger-timeline/spec.md`（「`issue クローズ` では、閉じた PR を合わせた合計の行を積む」）
- テスト: `plugins/cost-ledger/tests/gate-report.bats`、`plugins/cost-ledger/tests/backfill.bats`
