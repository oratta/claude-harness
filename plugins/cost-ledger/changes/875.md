# gate_report.py の lock() と gh api のリポジトリ名まわりの検査を固める（#875・#876・#929）

`tests/gate-report.bats` のテストの補強が中心で、`openspec/` は変えていない。

- **#875**: 「ロックファイルは検査した置き場の fd を基準に開く」テストが、置き場を開いて返った実際の fd を記録するようにした。その fd が `fstat` された fd・ロックファイル作成の `dir_fd` と同じであることと、`lock()` のあとにその fd へ `fstat` すると `EBADF` になることを見る。今までは「ロックの fd の番号 − 1 が検査用の fd」と仮定していて、番号が隣り合わないと fd が漏れていても通った。`gate_report.py` は変えていない
- **#876**: `gh api` のリテラルの endpoint（`repos/<owner>/<repo>/...`）から取り出した owner と repo にも、`-R` / `--repo` / `GH_REPO` と同じ `valid_parts()` を掛けた（`api_targets()`）。どちらかが `.` か `..` の endpoint は解決できない対象として飛ばし、`gh` を呼ばない。今までは `repos/a/../issues/1/comments` が `a/..` の #1 として取り出され、許可の一覧にその名前（`a/..`）があるときだけ、対象の確認の `gh` まで進んでいた（`gate_report.py` は、一覧に無い名前の対象を解決の前に落とす。行は積まれていなかった）。`my.org/my.repo`・`acme/.github` のように名前の中に `.` を含むだけの endpoint は今までどおり通る
- **#929**: `lock()` の再試行のテスト 3 本が、`time.sleep` を差し替えて渡された間隔を記録し、20 ms（`0.02`）が 4 回であることを見る（回数だけでなく間隔も固定。実際には待たないので時間に依存しない）。「置き場が消えた直後に別の inode をロックしない」テストは、置き場を `shutil.rmtree` でなく `os.listdir` + `os.unlink` + `os.rmdir` で消す。`rmtree` が内部で呼ぶ `os.open` のフラグ（`O_DIRECTORY` の有無）は Python の版で変わりうるので、置き場を開いた回数の数え方がそれに依存していた。`gate_report.py` は変えていない
- `gh` の呼び出し回数は、`.` / `..` の endpoint で（許可の一覧にその名前があるときだけ出ていた）1 回から 0 回に減る以外は変わらない
- 戻し方: `api_targets()` の `valid_parts()` の 2 行と、上記テストの追加・変更を戻す
