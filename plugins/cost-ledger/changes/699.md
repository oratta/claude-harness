# 699: 固定パス検査が __pycache__ の .pyc に当たって手元で落ちるのを直す（#702 も同じ原因）

`plugins/cost-ledger/tests/facts.bats` の「the log root comes from CLAUDE_CONFIG_DIR with no hardcoded path」は `scripts/` と `commands/` を再帰的に grep して `/Users/...` と `/home/...` が無いことを確かめる。`cost_ledger.py` を import したりテストを流したりすると、gitignore 済みの `scripts/__pycache__/*.pyc` にソースの絶対パスが入り、手元でだけこのテストが落ちていた。

- `facts.bats` の grep に `--exclude-dir=__pycache__ --exclude='*.pyc'` を足した。追跡の有無や拡張子では絞らないので、未追跡の新規ファイルや `.json` などに書いた絶対パスも今までどおり検出する（`git ls-files` と `--include` は、それを見落とすので採らなかった）
- `scripts/test.sh` に `export PYTHONDONTWRITEBYTECODE=1` を足し、テストが起動する Python（hook 経由を含む）が `.pyc` を作らないようにした。bats を直接起動した場合は効かないが、その場合は上の grep の除外が守る
- 戻し方: 足した 2 箇所（grep の 2 オプションと `export` の 1 行）を消す
- LLM のトークンは使わず、`gh` の呼び出しも増やさない。スキル本文・hook・`cost_ledger.py` は変えていない
- テスト: 既存の `facts.bats` の 1 件を直した（新しいテストは足していない）
