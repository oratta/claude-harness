# 697: `gh api` の直叩きと `gh pr create` / `gh pr reopen` でも「ここまでのコスト」の行を積む

節目ごとの自動投稿（PostToolUse の hook `gate-report.sh`）のきっかけを広げた。これまでは `gh pr comment` などの `gh` のサブコマンドだけを見ていて、`gh api` の REST で行った投稿・状態変更と、`gh pr create`・`gh pr reopen` では行が積まれなかった。このリポジトリは `gh issue view` などが GraphQL エラーになり、コメントの投稿や状態の変更を `gh api` で行うことが多いので、節目の多くが抜けていた。

- 新しく積むきっかけと行の「きっかけ」の列:

  | コマンド | きっかけ |
  |---|---|
  | `gh pr create`（`--dry-run`・`-w` / `--web` を除く） | `PR 作成` |
  | `gh pr reopen <番号か URL>` | `PR 再オープン` |
  | `gh api repos/<owner>/<repo>/issues/<番号>/comments` への POST | `issue コメント`（番号が PR なら `PR コメント`） |
  | `gh api -X PATCH repos/<owner>/<repo>/pulls/<番号>` でフィールドが `state=closed` / `state=open` | `PR クローズ` / `PR 再オープン` |
  | `gh api -X PATCH repos/<owner>/<repo>/issues/<番号>` でフィールドが `state=closed` / `state=open` | `issue クローズ` / `issue 再オープン`（番号が PR なら `PR クローズ` / `PR 再オープン`） |
  | `gh api -X PUT repos/<owner>/<repo>/pulls/<番号>/merge` | `マージ` |

- `gh issue reopen <PR の番号>` も `PR 再オープン` として積むようになった（これまでは PR の再オープンが表に無いので捨てていた）
- `gh pr create` の対象は、コマンドを実行したディレクトリのブランチ（`-H` / `--head` があればそのブランチ）をヘッドに持つ PR。open で、`created_at` がコマンドの実行時刻の前後 300 秒以内のときだけ積む。「このブランチの PR は既にある」で失敗したときに、作っていない PR へ `PR 作成` の行を積まないため。同じコマンドに番号なしの `gh pr comment` があれば、1 行にまとめて `PR 作成+PR コメント` になる
- `gh api` の引数を endpoint・メソッド・フィールドに分けて読むようにした。メソッドは `gh` と同じ規則（`-X` / `--method`、無ければフィールドか `--input` があれば POST、どちらも無ければ GET）。`repos/{owner}/{repo}/...` は前置きの `GH_REPO`、無ければコマンドを実行したディレクトリのリポジトリとして読む
- 合格ラベルの付与（`gh api .../issues/<番号>/labels`）の判定も同じ読み方にそろえた。直ったこと: `--input` や `--jq` の値がラベルのパスの形をしていても、その番号を対象にしない／`--jq 'labels[]=agent-review:passed'` を付与と見ない／`repos/{owner}/{repo}/issues/<番号>/labels` への付与を積む
- 積まないもの: `gh api graphql` の mutation／`--input` で JSON を渡した PATCH（`state` を変えたか分からない）／`state` を変えない PATCH／コメントの編集（`issues/comments/<id>` への PATCH。hook 自身の書き換えと同じ形）／完全な URL・問い合わせ文字列付き・`:owner/:repo` で書いた endpoint／メソッドや `state` の値がコマンドから 1 つに決まらないもの／`gh pr create --head owner:branch`／`--hostname` や `GH_HOST` で github.com 以外を指したもの
- 直していないこと: **PR でない issue への `gh api` のコメント投稿・クローズ・再オープンは、行は積まれるが、累計が 0 か実際より小さく出ることがある。** issue への帰属は `cost_ledger.py` の `ISSUE_RE`（`gh issue view|comment|edit|close|develop <番号>` の文字列）で決まり、`gh api .../issues/<番号>/...` は帰属の鍵にならないため。PR の行はブランチで帰属するので影響しない。帰属の側（`cost_ledger.py`）はこの変更では触っていない
- `gh pr reopen` を既に open の PR に実行しても `PR 再オープン` の行が積まれる（既に Ready の PR への `gh pr ready` と同じ）。PR を作ってから 300 秒以内に `gh pr create` をもう一度実行して失敗すると `PR 作成` の行がもう 1 行積まれる。どちらも数字は正しい
- 変えていないもの: 行の書式・コメントの形・ロック・裏のプロセスで動かす作り（`gate_report.py` の `stack()`）、`cost_ledger.py`、`hooks.json`。緊急停止は今までどおり `COST_LEDGER_GATE_REPORT=off`
- 反映に `/reload-plugins` は要らない（`hooks.json` を変えていない。スクリプトは実行のたびに読まれる）

## 実測

hook 1 回の同期部分（セッションが待つ部分）の壁時計時間。`gh` を何もせず成功を返す stub に差し替え、`COST_LEDGER_HOOK_FOREGROUND` を付けずに `gate-report.sh` へ hook の JSON を渡して、起動から終了までを 20 回測った中央値（かっこ内は最小〜最大。macOS、bash 3.2、python3）。

| 場合 | 変更前 | 変更後 |
|---|---|---|
| `ls -la`（きっかけに無関係） | 7.5 ms（6.9〜9.4） | 7.2 ms（6.7〜7.8） |
| `gh api repos/o/r/issues/300/comments`（読み取り） | 7.6 ms（6.5〜14.7） | 7.6 ms（7.0〜13.6） |
| `gh api repos/o/r/issues/300/comments -f body=x` | 7.3 ms（6.8〜8.0） | 54.6 ms（50.5〜59.5） |
| `gh pr create --title x --body y` | 7.5 ms（6.9〜8.0） | 52.5 ms（49.0〜66.4） |
| `gh pr comment 300 --body x`（前からあるきっかけ。比較用） | 52.4 ms（47.5〜60.8） | 53.0 ms（50.3〜60.8） |

読み取りの `gh api` は `python3` を起動しないので、無関係のコマンドと同じ時間で抜ける。新しいきっかけは `python3` を 1 回起動する分（前からあるきっかけと同じ 50〜55 ms）が同期部分にかかる。どの場合も 1 秒未満。比較用の `gh pr comment` は前後で変わらない。

`gh` の呼び出し回数（`COST_LEDGER_HOOK_FOREGROUND=1` で裏の処理をその場で実行し、stub の `gh` の呼び出しを数えた）。同期部分は `gh` を呼ばない（0 回）。下の回数はすべて裏のプロセスの分。

| コマンド | 変更前 | 変更後 | 内訳 |
|---|---|---|---|
| `gh pr create --title x --body y` | 0 | 3 | 対象の確認 1・既存コメントの取得 1・書き込み 1 |
| `gh pr reopen 300` | 0 | 3 | 同上 |
| `gh api repos/o/r/issues/300/comments -f body=x`（#300 は PR） | 0 | 4 | 対象の確認 2（issue として確かめてから PR として取り直す）・既存コメントの取得 1・書き込み 1 |
| `gh api -X PATCH repos/o/r/pulls/300 -f state=closed` | 0 | 3 | 対象の確認 1・既存コメントの取得 1・書き込み 1 |
| `gh api -X PUT repos/o/r/pulls/300/merge` | 0 | 3 | 同上 |
| `gh api repos/o/r/issues/300/comments`（読み取り） | 0 | 0 | `python3` も起動しない |

- テスト: `plugins/cost-ledger/tests/gate-report.bats`（83 件から 121 件）
