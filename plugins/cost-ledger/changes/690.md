# 690: 子 issue を持つ issue の `/cost` で、子 issue ごとの内訳と合計を出す

GitHub の子 issue を持つ issue（エピック）に `/cost <番号>` を打つと、エピック自身と子孫の issue ごとの額と、その合計を出すようにした。これまではエピックの番号を触った区間だけの額（ほぼ 0）が出ていた。合計は、エピック自身と子孫の issue がそれぞれ数える行（#689 の issue の合計の行: 閉じた PR のブランチの行と、その issue に帰属した区間の行）を、行ごとに 1 回だけ足した額。

- 子を持つ issue の `/cost` は、1 行目の帰属の種別が `子 issue 込み` になり、金額が子 issue の分を含む合計になる。2 行目以降に `  子 issue の合計:`・`  issue #<番号> 自身:` の行と、issue ごとの入れ子の内訳が出る。1 行目の合計は「子 issue の合計」にエピック自身の額を足した値
- 複数の issue を閉じた PR（同じヘッドブランチの PR を含む）の分は、番号がいちばん小さい issue に全額が入る。ほかの issue の行には `（単独 $3.00、PR #300 は #11 に計上）` が付く。`--json` の `issues[].own_usd` の和が `total_usd` と一致する
- 子を持つ issue の `/cost` だけ、`gh` が「番号の判別の 2 回 + 子を持つ issue の数」になる（`gh api graphql` を子を持つ issue 1 件につき 1 回。孫が無ければ 2 回から 3 回）。判定は番号の判別で呼んでいる issue の問い合わせの `sub_issues_summary.total` で行うので、子を持たない issue（2 回）と PR（1 回）の回数と出力は変わらない
- 台帳への差分の追記は 1 回で、台帳を読み通す回数は子 issue の数にも PR の数にも比例しない（区間は対象の issue の番号の集合で、PR の分は全ヘッドブランチをまとめて読む）
- GraphQL の失敗・応答の形の崩れ・100 件超・8 段より深い入れ子では、合計を出さずに終了コード 2 で終わる（標準エラーにどの issue で何が読めなかったかを出す）
- 数えないもの: GitHub の子 issue として登録されていない issue・別のリポジトリの子 issue（別立ての行に出す）・fork からの PR・`Closes` で結び付いていない PR
- 変えていないもの: `/cost <子の番号>`（区間だけの額のまま。内訳のその子の額とは一致しない）、`cost_ledger.py issue`・`timeline`、hook がエピックのコメントに積む行（エピックの番号を触った区間だけの累計）
- 反映に `/reload-plugins` は要らない（`hooks.json` と `commands/cost.md` の `description` を変えていない。スクリプトは実行のたびに読まれる）
- 仕様: `openspec/specs/cost-ledger-cost-command/spec.md`（子 issue ごとの内訳と合計、`gh` の回数）、`openspec/specs/cost-ledger-attribution/spec.md`（エピックの合計の定義）、`openspec/specs/cost-ledger-timeline/spec.md`（エピックに積む行は区間だけの累計）
- テスト: `plugins/cost-ledger/tests/epic.bats`（新規）
