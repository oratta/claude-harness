# 303: 投稿やステータス変更のたびに「ここまでのコスト」を 1 行積む

PR / issue へのコメント（`gh pr comment`・`gh issue comment`）、状態の変更（`gh pr ready`・`gh pr close`・`gh pr merge`・`gh issue close`・`gh issue reopen`）、ゲート通過（合格ラベル `agent-review:passed` の付与）のたびに、その PR / issue の 1 本のコメントへ「ここまでのコスト」を 1 行積むようにした。1 行は時刻・きっかけと、金額・入出力トークン・キャッシュトークンの `累計 (前の行からの増分)`。これまではゲート通過時に 1 行目だけのコメントを 1 本貼っていた。

- コメントの形が変わる。1 行目（`/cost <番号>` の 1 行目と同じ形）・節目ごとの表・最終行の記録 `<!-- cost-ledger:timeline v1 ... -->` の 3 部になる。増分は最終行の記録（丸める前の値）から計算し、手元のファイルには何も保存しない
- hook `scripts/gate-report.sh` はコマンド文字列の判定だけをして終わり、GitHub への問い合わせ・集計・書き込みは裏のプロセス `scripts/gate_report.py`（新規）が行う。行が付くまで数秒かかる。数字と書式は `cost_ledger.py timeline`（新規のサブコマンド）が作る。issue の集計は関係するセッションの行だけを台帳から読む
- 状態を変えるきっかけは、積む前に GitHub に問い合わせて、その状態になっていることを確かめる（`gh pr merge --auto` は、実行した時点でマージされていなければ積まない）
- ゲート通過の対象は PR だけになった。PR でない issue に合格ラベルを付けても積まない（これまでは issue にも貼っていた）
- 対象の PR / issue が作業中（hook の `cwd`）のリポジトリのものでなければ積まない（手元のコストを別のリポジトリへ書き出さないため。`cwd` のリポジトリが判別できないときも積まない）。そのため、fork の clone から upstream の PR にコメントしても行は付かず、別のディレクトリから `-R` で自分のリポジトリの PR を指したときも行は付かない。これまでのゲート通過の投稿は、`-R` で指した別リポジトリの PR にも貼っていた
- 通知（2026-10-07 に別アカウントを購読者にして実測）: コメントの編集では購読者の未読の通知は増えず、新規コメントでは増える。行を積む形で増える通知は、初回の節目で作るコメント 1 本と、きっかけのコメント自体の分だけ。測り方と表は PR #704 のコメント https://github.com/oratta/claude-harness/pull/704#issuecomment-6020155419
- 古い形のコメント（目印 `<!-- cost-ledger:gate-report -->`）は書き換えも削除もしない。切り替えの時点でゲート通過済みかつ未マージの PR には、次の節目で新しいコメントが作られ、古い形のコメントと 2 本並ぶ
- 1 行目は最終行の記録の値（小数 6 桁に丸めた金額）から作る。そのため `/cost` の 1 行目と 1 セントずれる場合がある
- 裏の処理が失敗した節目（`gh` の失敗・タイムアウト・ロックが取れない）には行が付かない。次に積まれる行の増分がその分を含む
- 同じ対象への同時の書き込みは、`${TMPDIR:-/tmp}/cost-ledger-timeline/` の下のロックファイルで直列にする。この置き場がシンボリックリンク・他人の持ち物・他人が書ける、のどれかなら使わず、その節目には行が付かない
- 緊急停止 `COST_LEDGER_GATE_REPORT=off` は、ゲート通過を含む全部のきっかけを止める
- 仕様: `openspec/specs/cost-ledger-timeline/spec.md`（新設）、`openspec/specs/cost-ledger-gate-report/spec.md`（付与の判定だけを残して改定）
- テスト: `plugins/cost-ledger/tests/timeline.bats`（新規）、`plugins/cost-ledger/tests/gate-report.bats`
- 反映: `hooks.json` は変えていないので、`/reload-plugins` は要らない（hook は起動のたびにスクリプトを読む）

## 実測（2026-10-06。台帳は実際のもの 約 15.7 万行、各 5 回の中央値）

`gh` は PATH の先頭に置いた記録用のラッパーで受け、読み取りだけを本物に流した（書き込みは記録して成功を返した）。対象は PR #665（マージ済み・合格ラベルあり）と issue #303。変更前は a8bf4ca8 の `gate-report.sh`・`cost_ledger.py`・`pricing.json`。

hook 1 回の所要時間:

| 場合 | 変更前 | 変更後 |
|---|---|---|
| 対象外の Bash（`ls -la`） | 0.007 秒 | 0.007 秒 |
| 対象のコマンドの同期部分（セッションが待つ時間）: ゲート通過 | 3.300 秒（全部が同期） | 0.055 秒 |

| 同: `gh issue comment` | 対象外 | 0.051 秒 |

| 同: PR（ゲート通過） | 3.300 秒 | 1.625 秒 |
| 同: issue（`gh issue comment 303`） | — | 1.776 秒 |

`gh` の呼び出し回数（対象 1 件、コメント 100 件未満）:

| 場合 | 変更前 | 変更後 |
|---|---|---|

変更後の 3 回は、対象の確認・既存コメントの取得・書き込み。4 回目はヘッドブランチを取るための `pulls/<番号>`。
