# 701: 突き合わせの読み直しが上限を超えて読み終えたときの扱いを決め、テストで固定する

単価表のずれの突き合わせ（#692）の読み直しは、ファイルを開く前と 5,000 行ごとにだけ上限（既定 1 秒）を確かめる。最後に確かめてから読み終えるまでの間に上限を超えると、その後に確かめる箇所が無く、`未確認` にならず通常の比較結果が出る。issue はループ終了後に確認を足す案を挙げ、読み終えた結果を捨てる挙動が望ましいかを先に決めるよう求めていた。

**決定: 読み終えた結果は、上限を超えていても使う。捨てて `未確認` にはしない。** 処理は変えない。

- 打ち切りの目的は `/cost` を 1 秒以上余計に止めないこと。読み終えた時点で時間は使われており、結果を捨てても待ち時間は戻らない
- 結果を捨てる理由は「読み切っていない行の合計で比べると、単価表が正しくても差が出る」こと。全行を読み終えた結果には当てはまらない
- ループ後に確認を足すと、最終ファイルが短いかどうかだけで、同じ内容・同じ所要時間でも `未確認` になったりならなかったりする
- 受け入れるリスク: 最後の読み込みが上限を大きく超えて長引いても打ち切られない（仕様の守備範囲にもともと書かれた性質）

## 変えたもの

- 仕様: `openspec/specs/cost-ledger-pricing/spec.md` の要件「突き合わせのための読み直しは上限の時間で打ち切り…」。冒頭を「まだ読んでいない行が残っていて、確かめた時点で上限に達していたら打ち切る」に限定し、読み終えた結果は使うことと Scenario 1 件を足した（archive で反映）
- テスト: `plugins/cost-ledger/tests/drift.bats` に 4 件。`time.monotonic` を呼び出し回数で差し替え（開始とファイルを開く前の確認は 0 秒、以降は 2 秒）、台帳の経路と会話ログの経路で、短い最終ファイルでは `cut_off` が立たず `drifted` が 1 になること、確認の間隔を 1 行にすると `cut_off` が立つことを見る。ループ後に確認を足すと前者が落ちることを確かめた（確かめたあと元に戻した）。テストは `sys.dont_write_bytecode` を立て、`scripts/__pycache__` を残さない
- コード: `cost_ledger.py` の `_drift_lines()` と `session_facts()` の docstring に理由を足しただけ（処理は変えない）
- LLM のトークンは使わない。スラッシュコマンドの本文は変えていない
