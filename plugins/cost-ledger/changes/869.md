# hook の 2 本が python3 を -E -s で起動する（#847）

`scripts/backfill.sh`・`scripts/gate-report.sh` の python3 に `-E -s` を付けた。`PYTHONPATH` などの `PYTHON*` の環境変数とユーザー site を検索先に使わない。

- `ledger-hook.sh` はこの PR では変えていない（PR #909 が同じファイルを変えたため。`-E -s` の付与は follow-up）
- `-I` は付けていない。2 本は隣の `.py` を直接実行し、`backfill.py` と `gate_report.py` は同じディレクトリの `write_allow.py`・`cost_ledger.py` を import する。`-I` はスクリプトのディレクトリも検索先から外すので、import できなくなる（`python3 -I` で `backfill.py` を読むと `write_allow` が見つからないことを bats で固定した）
- `.py` を直接実行する形はカレントディレクトリを検索先に入れないので、作業リポジトリに置いた `json.py` は直す前から読まれない。`-E -s` で塞いだのは `PYTHONPATH` とユーザー site の経路
- 2 本を実際に通し、カレントディレクトリと `PYTHONPATH` に置いた偽の `json.py` が読まれないこと（`-E -s` を外すと読まれること）を bats で固定した
- 検索先の先頭はスクリプトの隣（プラグインの `scripts/`）のまま。そこに書き込める相手への対策はこの PR の範囲外
- `scripts/cost_ledger.py` は触っていない。hook が何を記録するかは変えていない
- 検査は `tests/hook-python-isolation.bats`
- 戻し方: 2 か所の `-E -s` を外す
