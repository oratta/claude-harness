# zsh で `~/.claude/plugins/installed` が無いと `/cost` の探索ループが止まる不具合を直す（#913）

`plugins/cost-ledger/commands/cost.md` の探索ループは、`~/.claude/plugins/marketplaces/*/…` と `~/.claude/plugins/installed/*/…` の glob を `for` の単語に直接並べていた。zsh は glob が 1 件も当たらないと `no matches found` でコマンドごと失敗する（`zsh -f` でも同じ。実測は PR 本文）。bash は一致なしを文字列のまま残すので止まらない。

- 探索をループの直前に、zsh で `nullglob` が未設定のときだけ（判定は `[[ ! -o nullglob ]]`。zsh の `[ ]` は 3 引数が OR と評価され常に真になるため `[[ ]]` を使う）`setopt nullglob` し、ループの直後に `unsetopt nullglob` で戻す（利用者が元から設定していれば触らない。zsh で off→off・on→on を実測）。`[[ ]]` は sh・dash では単なる語として構文上通り、`[ -n "${ZSH_VERSION:-}" ]` の短絡で評価されない。bash では何も変えない。ループの形（行頭の `for dir in`）は変えない（既存の検査が形に依存する）
- 探索の順番（作業中のプラグインのルート → marketplaces → installed）と、見つかったときの結果は変えない
- 検査は新規 `plugins/cost-ledger/tests/cost-command-zsh.bats`（`plugins/installed` が無い・空・当たりがある、の 3 通りを zsh と bash で。加えて zsh で、元から nullglob 有効なら有効のまま・置換済みの先頭候補が選ばれる経路。zsh が無い環境では skip。CI（ubuntu）には zsh が無いので zsh の経路は CI で検査されない）
- 同じ形の glob が `casting`・`dev-workflow`・`infra`・`statusline`・`worktree` の各コマンド文書とエージェント定義（計 9 か所。infra は `plugins/infra/agents/infra-phase-4-github-actions.md:51`）にもある。この変更では直していない（follow-up: https://github.com/oratta/claude-harness/issues/938 ）
- 戻し方: `cost.md` の探索を元の `for` に戻し、新しい bats を消す
