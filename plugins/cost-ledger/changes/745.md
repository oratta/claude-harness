# 745: 子 issue を持つ issue に積む行に、子 issue と子 PR の分を入れる

hook が GitHub の子 issue を持つ issue（エピック）のコメントに積む行は、これまでエピックの番号を触った区間だけの累計で、実際の作業が起きる子 issue と子 PR の分を含まなかった。エピックの履歴の額がほぼ 0 に見え、`/cost <エピック番号>`（子 issue 込み。#690）の合計と食い違っていた。子を持つ issue に積む行は、毎回（節目の行も合計の行も）`/cost <番号>` の 1 行目と同じ「子 issue 込み」の累計になる。

- 子を持つ issue のコメントの 1 行目の帰属の種別は `子 issue 込み`。閉じたときの合計の行のきっかけの欄は、件数だけの書式 `合計（子 issue <n> 件込み: PR <m> 件 $<額> + PR 外 $<額>）`（PR ごとの額は書かない）
- `cost_ledger.py timeline` に `--child-issue <番号>`（子孫の issue。複数）と `--child-pr <PR番号>:<ヘッドブランチ>`（エピックと子孫を閉じた PR。複数）を足した。`--pr` と一緒に渡す・値が崩れているときは終了コード 2。`--child-issue` が無ければ従来どおり区間だけ（`--child-pr` だけでは何も変わらない）。`timeline` は `gh` を呼ばない
- 子を持つかの判定は、対象の確認で既に取っている応答の `sub_issues_summary.total`（1 以上）で行うので、`gh` は増えない。後追い（`backfill.py`）は一覧の応答の `children` で同じ判定をする
- `gh` の回数は、子を持つ issue だけ「子を持つ issue（対象を含む）1 件につき `gh api graphql` 1 回」が加わる（1 行につき 5 回まで）。子孫の問い合わせが閉じた PR の問い合わせを兼ねるので、コメントは 3 回から 3 + その回数、`issue クローズ` は 3 + その回数（孫が無ければどちらも 4 回）。子を持たない issue（コメント 3 回・クローズ 4 回）と PR（3 回）の回数と、`timeline` に渡る引数は変わらない
- 子孫の問い合わせの失敗・応答の形の崩れ・100 件超・8 段超・6 回目の問い合わせが要るときは、従来の区間だけの行を積み、節目の行のきっかけの欄の最後に `子 issue 照会失敗` を足す（`PR 照会失敗` と同じ扱い）
- 数えないもの: GitHub の子 issue として登録されていない issue・別のリポジトリの子 issue・fork からの PR（`/cost <番号>` と同じ）
- 反映に `/reload-plugins` は要らない（`hooks.json` と `commands/cost.md` の `description` を変えていない。スクリプトは実行のたびに読まれる）。LLM のトークンは使わず、hook は何も出力しない
- 仕様: `openspec/specs/cost-ledger-timeline/spec.md`（子 issue を持つ issue に積む行、`gh` の呼び出し回数）、`openspec/specs/cost-ledger-cost-command/spec.md`（hook の行の守備範囲）
- テスト: `plugins/cost-ledger/tests/epic-timeline.bats`（新規）。`timeline.bats` の子 issue を持つ issue の Scenario は「`--child-issue` を渡さなければ区間だけ」の形に直した
