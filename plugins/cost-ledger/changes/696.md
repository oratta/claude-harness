# 696: サブエージェントの出力トークンを、応答の確定行の値で数える

会話ログでは、1 回の応答が書き始めたブロックごとに別の行になり、各行の `usage.output_tokens` はその行を書いた時点の値になる。`stop_reason`（`tool_use` / `end_turn` など）が付いた最後の行だけが応答の確定値で、サブエージェントのログでは先頭の行が途中の値（2〜8 など）のままだった。cost-ledger は先頭の行だけを事実にしていたので、サブエージェントの出力トークンを少なく数えていた。

- `cost_ledger.py` が、後続行の `message.stop_reason` が空でない文字列で、`output_tokens` がその応答についてすでに数えた出力（先頭の事実の出力 + 補足の事実の出力の合計）を上回るとき、**差分**を `output_tokens` に持つ補足の事実（`continuation: true`、入力・キャッシュは 0、鍵は `<requestId>#<行の uuid>`）を出す。同じ行が issue 番号か投稿の印も持つときは同じ 1 つの補足の事実に載せる。差分が 0 以下で issue も印も無い行は何も出さない（メイン側の応答・複製された会話ログ・同じログの再読み込みでは増えない）
- 先頭の事実と台帳の既存の行は書き換えない（append-only のまま）。応答単位の出力の合計が確定値になる
- 確定値が会話ログに無い応答（どの行にも `stop_reason` が付かない）は、先頭の行の値のまま。推定で埋めない。規模と原因は README に書いた
- 控え（`<台帳>.state.sqlite`）に `counted` 表（requestId → 数えた出力）を足した。`catch_up` が台帳の各行の出力を元の `requestId` に足し込む。古い形の控えは初回の同期で台帳から作り直す（1 回だけ）。台帳が正で、控えは消しても同じ結果になる
- 補足の事実は引き続きメッセージ数に数えず、出力トークンと金額の合計には足される。LLM のトークンは使わず、`gh` の呼び出しも増やしていない
- 仕様: `openspec/specs/cost-ledger-attribution/spec.md`・`openspec/specs/cost-ledger-persistence/spec.md`（archive 後）
- レビューゲート 1 周目の修正: 台帳を設定していない経路（`issue --closing-pr` の PR の分を読む `load_branches_facts` と、本体値との突き合わせで読み直す `session_facts`）が、数えた出力を覚えない素の `set` を渡していて、確定行の値がそのまま足され出力を二重に数えていた。`SeenSet` を渡すようにした。あわせて、モデル別の内訳（`/cost` の `out=` と金額）に補足の事実の出力の差分と金額を足し、1 行目の額と内訳が合うようにした
- テスト: `plugins/cost-ledger/tests/finaloutput.bats`（16 件）
- 利用者がやること: 途中の値で書いた過去の台帳を直すなら、**1 回だけ** `python3 scripts/cost_ledger.py ledger-sync --rescan` を流す（実行前に台帳を `cp` で控える。会話ログが既に消えた期間は補えない。既存の行は 1 バイトも変わらず、差分の補足の行が追記される）。流さなくても、これから先の応答は通常の同期で差分が付く
