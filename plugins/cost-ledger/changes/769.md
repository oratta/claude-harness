# 769: cost-ledger: 変更前の版と混ざって動く期間の、確定行の差分と控えの整合を直す

#757 のレビューで見つかった 2 件を直した。

- 変更前の版が出力 0 の補足の行（`r1#u2`）を書いた確定行が `--rescan` で直らなかった。`key in seen` でも確定行なら出力の差分を計算し、正のときは鍵 `<requestId>#<uuid>#out`・`issues` 空・`post_marker` なしの補足の事実を出す。元の requestId は末尾の `#<uuid>`（`#out` の行は `#<uuid>#out`）だけを除いて求める
- 控え（`<台帳>.state.sqlite`）の `meta` に `counted_covered` を足した。`catch_up` は `ids` / `heads` を `covered` から、`counted` を `counted_covered` から別々に読み足す。変更前の版の hook が `covered` だけを進めても、`counted` に入っていない先頭の行が次の同期で足される。`counted_covered` が台帳より大きい、または無い（古い形、`counted` を作った直後で落ちた形）ときは `counted` を捨てて台帳の先頭から作り直す
- 台帳の既存の行は書き換えない。利用者がやることは無い（控えは自動で作り直される）
- PR #1197 のレビューで見つかった 3 件も直した
  - 直前の配布版（`counted` と `covered` を進めるが `counted_covered` を持たない版）が先頭の行を足したあと、`counted_covered` から読み直して同じ出力を二重に足していた。`counted_covered` が `covered` と違うときも `counted` を捨てて台帳の先頭から数え直す
  - `--rescan` で足す `<鍵>#out` の行が、投稿の印を持つ `<鍵>` の行の後に並び、投稿で閉じる区間の外に出ていた。区間分割の並べ替えで `<鍵>#out` を `<鍵>` の直前に置く（台帳は変えない）
  - 元の requestId を最初の `#` で切っていたので、`#` を含む requestId の控えの `counted` と並べ替えが崩れていた。補足の事実の `uuid` の欄を使って末尾だけを除く
