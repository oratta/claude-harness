# finaloutput.bats の 2 件のテストに、前提が効いたことの検査を足す（#895・#894）

- 「a null or missing stop_reason on a larger line with Bash is not a final line」に、`sed` で `"stop_reason":null,` を消したあと、`"stop_reason"` を含む行が 2 行で全体が 3 行であることの検査を足した（#895）。`sed` のパターンが当たらなくなると 3 になって落ちる
- 「a plain ledger-sync does not reopen a log it has already read to the end」に、控えを戻す 2 文（DELETE と UPDATE）の rowcount がどちらも 1 であることの検査と、対照の `ledger-sync --rescan --quiet` で台帳が 3 行になる検査を足した。途中の行の失敗は `|| return 1` で止める（#894）。実装が毎回開き直す場合、`--rescan` でも開き直さない場合、DELETE が 0 行に当たる場合のそれぞれで落ちることを、複製で壊して確かめた
- 実行コードは変えていない（テストだけ）。戻し方: 足した検査の行を消す
