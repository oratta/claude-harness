# 882: エピックの履歴で変更のない子木への問い合わせを省く

孫を持つエピックの hook は、ルートを毎回取得し、子の `updatedAt`・`subIssuesSummary.total/completed`・閉じた PR の一覧が同じなら保存済み部分木を使う。PR 一覧の順番だけの違いでは再取得しない。金額は保存せず、手元のログから毎回計算する。`/cost <番号>` は従来どおり全件取得する。

- 偽 `gh` による別プロセスの連続 hook の実測: 初回は GraphQL 3 回（`gh` 合計 6 回）、未変更の 2 回目は GraphQL 1 回（合計 4 回）、子 1 件の変更時は GraphQL 2 回（合計 5 回）。実問い合わせだけを 5 回上限に数える。
- 保存は対象別にロック用ディレクトリへ置き、検査済みディレクトリ fd とロックを読み取りから正常取得後の置換まで保持する。通常 hook と後追いの両方で解放する。リンクや不安全なファイルは使わない。保存が無い・壊れている・形式や対象が違う場合は全件取得し、保存の書き込みだけの失敗では正常な結果を使う。
- GitHub の取得失敗時は正常な保存があっても `子 issue 照会失敗` を表示し、部分結果を使わず合計行も積まない。前回の正常な保存は残す。深さ制限・重複排除・別リポジトリと fork の除外は維持する。
- 子より深い変更が子の信号に現れない場合は、関連や額が古くなりうる。保存を使わない `/cost <番号>` で現在の額を確認できる。既存の行は補正しない。
- `cost_ledger.py` と `attribution.bats` は変更していない。反映に `/reload-plugins` は不要（hook の配線と description は変更なし）。
