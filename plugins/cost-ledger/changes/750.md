# #750: 削除済みの作業ディレクトリの行のリポジトリを、パスから推定する

エピックの `/cost` で「リポジトリ不明」の額が合計から外れていた。原因は、作業ツリーを消したあとに台帳へ取り込んだ行の `cwd` に `git rev-parse` が効かず、リポジトリ識別子が「不明」になることだった。

## 変えたこと

- `cwd` がディレクトリとして存在しないとき、パスからリポジトリを推定する（`RepoResolver`）。`/.claude/worktrees/` を含むならその手前のリポジトリ、それ以外は現存する最も近い祖先（置き場）の直下に残るリンクされた作業ツリーが 1 リポジトリで、置き場の名前がそのリポジトリのディレクトリ名か origin のリポジトリ名と一致するときだけ決める。推定で決めた事実には `repo_inferred: true` を付ける
- 置き場の子の識別子は git を起動せず `.git` ファイル（`gitdir:` と `commondir`）から読む。子の数だけ `git rev-parse` を起動する形は、実機の置き場（子 29 件）の推定だけで 0.640 秒かかった（ファイルから読む形で 0.024 秒）。指す先の無い残骸の子は除いて残りの子で判定する
- `ledger-sync --rescan` が、台帳の「不明」の行の組（セッションとブランチ）のうち、全 `cwd` が同じ 1 リポジトリに決まる組に補正行（`"repo_fix": true`）を追記する。hook と通常の `ledger-sync` は書かない
- 台帳を読むとき（`load_facts` の 2 経路）、補正行を取り除き、同じ組の「不明」の行に当てる。同じ組に別のリポジトリの補正行があれば不明に戻る（取り消しの手順は README）
- `cost <issue番号>`・エピック・番号なしの `cost` に「推定で数えた行」の件数と額を出す（`--json` は `inferred_repo_usd`・`inferred_repo_messages`）

## マージ後に実機で行う手順

1. 台帳を写す: `cp -p "$COST_LEDGER_PATH" <写しの置き場>`
2. `python3 plugins/cost-ledger/scripts/cost_ledger.py ledger-sync --rescan` を 1 回流す
3. `cost 272` で、リポジトリ不明が 0 件になり、推定で数えた行が出ることを確かめる

## 残る誤り

- 別のリポジトリの行を数える恐れ: 置き場の名前のリポジトリと違うリポジトリの作業ツリーが過去にそこへ置かれていた場合、その行は置き場の名前のリポジトリに寄る。指す先の無い残骸の子を除いて判定するので、残骸が別のリポジトリのものでも残りの 1 種類に決まる
- 補正行は消せない: 台帳は追記だけ。取り消しは同じ組に別のリポジトリの補正行を足す
- 直らない分が残る: 置き場の名前がリポジトリ名と違う行、置き場ごと消えた行、会話ログが消えた期間の行は「リポジトリ不明」のまま
