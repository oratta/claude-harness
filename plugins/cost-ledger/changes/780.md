# /cost が置換された値を引用した here-document で読む（#780・#796）

#729 / PR #774 のレビュー指摘 2 件を、同じコードブロックなので 1 本で直した。コマンドの外から見た挙動（どの台帳を読むか・出力・未設定時の扱い）は変えていない。

- #780: 台帳パスの置換値を `'...'` で包むのをやめ、`IFS= read -r LEDGER_OPTION <<'LEDGER_PATH_EOF'` で読んで `CLAUDE_PLUGIN_OPTION_LEDGER_PATH="$LEDGER_OPTION"` として渡す。`'` を偶数個含むパスで別のパスの台帳ができる問題と、奇数個で構文エラーになる問題が消えた。#729 で受け入れた「`'` を含めない」制約と、案内文・README の注意書きを外した
- #796: 探索の先頭候補に使うプラグインのルートを、二重引用符の中に直接置くのをやめ、`IFS= read -r PLUGIN_ROOT <<'COST_LEDGER_PLUGIN_ROOT'` で読む。`$(...)`・バッククォート・`"` を含むルートが実行されて探索先が変わる問題が消えた。置換されないとき（値が `$` で始まる文字列のまま残る）は `PLUGIN_ROOT` を空にして、#808 の「先頭候補を飛ばして後続へ進む」挙動を保つ
- spec `cost-ledger-cost-command` の「`/cost` はプラグイン設定の台帳パスを使う」を直した。「値を環境変数として渡す」「探索の先頭は置換された絶対パス」の規範は変えず、「置換値をシェルの構文として解釈しない」ことと、「コマンド本文が値を渡している」シナリオの文面、特殊文字の 2 シナリオを足した。経緯は `openspec/changes/archive/2026-10-10-cost-command-heredoc-values/`
- テスト: `tests/cost-command.bats` に、cost.md の bash ブロックを置換して実行する 5 件（`'` が偶数個・特殊文字・未置換の台帳・特殊文字を含むルート・未置換のルート）と構文の検査 1 件を追加。`tests/command-plugin-root.bats` の抽出が here-document の形を含むようにした
- 既知の限界: 値が改行を含むと文字どおりには扱えない。改行入りの値は先頭の 1 行だけが台帳パスとして渡る。値が区切り語と同じ行を含むと here-document がそこで終わり、その行より後ろの行がシェルのコマンドとして実行される（exit 0 のまま）。値が区切り語 1 行だけだと台帳パスは空で渡る。直す前は `'` 1 文字で同じこと（値の中のコマンドの実行）が起きた。今回は改行と区切り語の完全一致が要る分だけ狭くなった。値を書けるのは利用者自身の設定だけ
- 戻し方: cost.md の呼び出しを #808 の形に戻す。version は上げていない。LLM のトークンは使わない
