# zsh 向け nullglob 退避が、ZSH_VERSION を export した bash で `setopt: command not found` を出さないようにする（#955）

- nullglob を立てる行の条件に `command -v setopt >/dev/null 2>&1` を足した（`[ -n "${ZSH_VERSION:-}" ] && command -v setopt >/dev/null 2>&1 && [[ ! -o nullglob ]]`）。`ZSH_VERSION` を環境変数として export した bash では、これまで `[[ ! -o nullglob ]]` と `setopt` が bash で評価されて標準エラーに `command not found` が出ていた。今は `setopt` が無い bash では退避を行わず、何も出さない
- 戻す側の `unsetopt` 行（`if [ -n "$X_NG" ]; then unsetopt nullglob; fi`）の条件は変えていない。issue の受け入れ条件には「`unsetopt` 側もそろえる」とあるが、`X_NG` は setopt 側の条件が偽なら空のままで、`unsetopt` は評価されない。実物で `ZSH_VERSION=5.9 bash` に 10 か所のブロック（ZSH_VERSION 行から `unsetopt` 行まで）を実行し、標準エラー出力なし・exit 0 を確かめた。旧形では bash が `setopt` の失敗後も `X_NG=1` を立てるため `unsetopt` まで評価されて警告が 2 行出ていた。回帰テストは `tests/zsh-nullglob-guard.bats`
- zsh での挙動は変えていない（nullglob が未設定のときだけ立て、後で戻す）。探索結果も変わらない
- 同じ形に 10 か所をそろえた（statusline・worktree の 2 か所・casting・dev-workflow の 4 か所・infra・cost-ledger）。戻し方: 足した `&& command -v setopt >/dev/null 2>&1` を消す
