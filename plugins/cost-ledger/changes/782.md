# 782: Stop hook でも置換されなかったプレースホルダを未設定として扱う

#729 で `cost_ledger.py` の `ledger_path()` は `${user_config.` で始まる値を未設定として扱うようにしたが、Stop hook の `scripts/ledger-hook.sh` は `CLAUDE_PLUGIN_OPTION_LEDGER_PATH` をそのまま `COST_LEDGER_PATH` に写していた。プレースホルダが hook の環境に渡ると、作業ディレクトリに `${user_config.LEDGER_PATH}` という名前の台帳と .lock・.state.sqlite ができた（spec cost-ledger-persistence の台帳の場所の要件に反する）。

- `ledger-hook.sh` は、`CLAUDE_PLUGIN_OPTION_LEDGER_PATH` が `${user_config.` で始まるとき空にしてから従来の解決に進む。プレースホルダだけなら python を起動せず exit 0、`COST_LEDGER_PATH` もあればそちらに追記する
- 終了コード・無出力の方針は変えない。`version` は上げていない
- `scripts/backfill.sh` は変えていない（spec cost-ledger-backfill が、SessionStart の補完では除外は要らないと定めている）。このため `backfill.sh` は `${user_config.` で始まる値も今は台帳のパスとして採り、`ledger-hook.sh` と扱いが分かれる。そろえるなら `backfill.sh` に同じ `case` を足し、spec cost-ledger-backfill の該当の文も直す（spec の変更を伴うので別に判断する）
- `tests/userconfig.bats` に hook 版のテストを 2 件足した
- 戻し方: スクリプトの `case` 1 行（とコメント）とテスト 2 件を戻す
