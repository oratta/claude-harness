# 689: issue を閉じたときに、閉じた PR の分も重複なしで合わせた合計を載せる

`gh issue close`（PR でない issue）で、`issue クローズ` の行に続けて「issue の合計」の行を積むようにした。issue の合計は「その issue を閉じた PR のブランチの分」+「issue に帰属した区間のうち、どの PR のブランチ上にも無い分」で、両方に帰属する行は区間の側から除く（二重に数えない）。これまでは区間だけの累計しか出ず、PR の分と足すと重なる行を二重に数えていた。

- `gh issue close` で積まれる行が 2 行になる場合がある。2 行目のきっかけの欄は `合計（#300 $3.00 + PR 外 $2.00）` で、閉じた PR が何件でも PR ごとに額を書く（PR が多いと行が長くなる）。額は別々に丸めるので、内訳の和が合計と 1 セントずれることがある
- 合計の行の増分は、同じ節目の `issue クローズ` の行（区間だけの累計）との差。ほかの行の増分は合計の行を飛ばして計算し、合計の行を入れても既存の行は書き直さない
- コメントの 1 行目は、最後の行が合計の行のときだけ合計になり、帰属が `区間+閉じた PR` になる
- 閉じた PR は裏のプロセス `scripts/gate_report.py` が `gh api graphql`（`closedByPullRequestsReferences(first: 100)`）で 1 回問い合わせる。`gh` の呼び出しは、PR でない issue の `gh issue close` だけ 3 回から 4 回になる（閉じた PR の数では変わらない）。`gh issue comment`・`gh pr comment`・`gh pr close` などは 3 回のまま。問い合わせはロックを持ったあとに行う
- 数える PR は、ベースが対象のリポジトリで、ヘッドブランチも同じリポジトリにある PR だけ。fork からの PR・別のリポジトリの PR・クローズ済みで未マージの PR・`Closes` などで結び付いていない PR は数えない
- 合計の行が付かない場合: 閉じた PR が 0 件・問い合わせの失敗・100 件を超える・応答の形が 1 件でも崩れている。どれも `issue クローズ` の行だけを積む（0 件と失敗は見分けが付かない）
- `cost_ledger.py` の `timeline` と `issue` に `--closing-pr <番号>:<ヘッドブランチ>`（繰り返し可）を足した。`issue` は 1 行目の下に `  合計（閉じた PR 込み）: …` を出し、`--json` に `closing_prs`・`outside_pr_usd`・`combined_total_usd` を足す。付けなければ今までと同じ出力（JSON の 3 つの鍵は、空の配列と `total_usd` と同じ値）。形が崩れた値と、`timeline --pr` と一緒に渡した場合は終了コード 2
- PR の分は手元の台帳のそのブランチの全部の行なので、ブランチ名を使い回していると大きく出て、別の PC での作業は `$0.00` になる。1 本の PR が複数の issue を閉じると、それぞれの issue の合計に全額が入る
- auto-merge や PR の `Closes` による issue の自動クローズでは付かない（手元でコマンドが走らないので hook から見えない。`issue クローズ` の行と同じ）
- 反映に `/reload-plugins` は要らない（`hooks.json` と `gate-report.sh` を変えていない。スクリプトは hook のたびに読まれる）
- 仕様: `openspec/specs/cost-ledger-attribution/spec.md`（issue の合計の定義）、`openspec/specs/cost-ledger-timeline/spec.md`（合計の行）
- テスト: `plugins/cost-ledger/tests/issue-total.bats`（新規）、`plugins/cost-ledger/tests/gate-report.bats`
