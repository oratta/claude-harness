# レシピ: goal-acceptance-pass

> 初期シードレシピ（change-3 goal-time-recipes）。規約は `plugins/loops/references/recipe-format.md` を参照。

## ループ型

**ゴールベース**（4 分類: ターンベース / ゴールベース / タイムベース / プロアクティブ のうち）。
longrun の `plan.md` に列挙された受け入れ条件（機械検証コマンド群）が全て PASS するまで自律反復させる完了ゲート。
選定基準は `references/loop-types.md` の「停止条件を手放す」に従う。

## 目的

longrun の完了判定を人間の目視ではなく機械検証で回す。`plan.md` の「受け入れ条件」に並ぶ検証コマンドを
全て期待値で PASS させるまで、不足の実装・修正 → 再検証を自律反復させる。longrun 完了ゲート用。

## 起動コマンド

コピペ可能な `/goal` 文字列（`<plan.md path>` を対象 longrun の plan.md 実パスに置換して使う）:

```
/goal read the "受け入れ条件" section of <plan.md path>, run every listed verification command, and don't stop until all of them PASS with their expected values, stop after 6 tries
```

- 起動コマンドはネイティブプリミティブ `/goal` のみ。**独自 CLI やラッパースクリプトは作らない**。
- 受け入れ条件の各項目は「コマンド + 期待値」の組。エバリュエータが各コマンドの結果を期待値と突き合わせる。

## 停止基準

- **成功基準（定量・機械検証可能）**: **対象 longrun の plan.md の受け入れ条件に列挙された機械検証コマンドが全て PASS すること**。
  - **受け入れ条件をコマンド + 期待値として読み取る手順**:
    1. `plan.md` の「## 受け入れ条件」節を開く。
    2. 各チェック項目 `[ ]` から、実行すべき**コマンド**（例: `find plugins -name '*.bats' -print0 | xargs -0 bats`）と**期待値**（例: exit 0 / 全 PASS、grep ヒット件数、JSON parse 成功）を抽出する。
    3. コマンドが明記されていない項目は、記述から機械検証可能なコマンド + 期待値に翻訳する（曖昧なら人間へエスカレーション）。
    4. 全項目を実行し、1 つでも期待値と不一致なら未達として次の試行へ。
- **打ち切り条件（必須）**: 最大試行数のデフォルトは **6 回**（`stop after 6 tries`）。
  - **変更方法**: 起動コマンド文字列末尾の `stop after 6 tries` の数値 `6` を書き換える。時間上限にしたい場合は `stop after 45 minutes` 等へ書き換える。

## 前提

- 対象 longrun の `plan.md` が存在し、「受け入れ条件」節に機械検証可能な項目が列挙されていること。
- 各検証コマンドが実行できる環境（このリポジトリでは `bats-core`・`node`・`git`・`gh` など）。
- 参照: `plugins/loops/references/recipe-format.md`、`plugins/loops/references/self-verification.md`（evidence 提示の原則）。

## コスト注意

公式トークン管理の該当項目:
- **実行頻度を必要最小限にする**: 完了ゲートは longrun の節目で手動起動する。常時ループにしない。
- **決定論的作業のスクリプト化**: 受け入れ条件の検証コマンド群は決定論的なので 1 本のスクリプト/リストに固定し、LLM には未達項目の修正のみを任せる。
- **大規模実行前のパイロット実行**: 受け入れ条件が多い plan では、まず `stop after 2 tries` で 1 巡させ、検証コマンドの読み取りが正しいか確認する。
- ループはチャットの約 4 倍のトークンを消費する点に留意する。

## エスカレーション

- **同一の受け入れ条件が 2 連続で同じ失敗**をしたら、無限リトライに入る前に人間へエスカレーションする。
- 受け入れ条件を弱める・スキップする・テストを削る等の報酬ハッキングは禁止。必要ならエスカレーション。
- `passes:true` 相当の完了宣言は、検証コマンドの exit 0 / 期待値一致の **evidence がある場合のみ**。自己申告での完了は禁止。
- 機械検証に翻訳できない主観的な受け入れ条件が残った場合は、その項目を人間の確認に回す。
