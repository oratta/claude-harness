# レシピ: loop-pr-babysit

> 初期シードレシピ（change-3 goal-time-recipes）。公式例 `/loop 5m check my PR, address review comments, and fix failing CI` を
> このリポジトリの Draft PR 運用（CLAUDE.md）向けに調整した版。規約は `plugins/loops/references/recipe-format.md` を参照。

## ループ型

**タイムベース**（4 分類: ターンベース / ゴールベース / タイムベース / プロアクティブ のうち）。
一定間隔で PR の状態をチェックし、レビューコメント対応と CI 修正を回す。起動タイミングを手放したいので `/loop` を使う。
選定基準は `references/loop-types.md` の「トリガー（起動タイミング）を手放す」に従う。

## 目的

自分の Draft PR を面倒見する。レビューコメントへの対応と失敗した CI の修正を、人間が張り付かずに一定間隔で自動反復させる。
公式のタイムベース代表例をこのリポジトリの非破壊 Draft PR 運用に合わせて調整したもの。

## 起動コマンド

コピペ可能な `/loop` 文字列（公式例準拠、`<PR番号>` は対象 PR に置換）:

```
/loop 5m check PR #<PR番号>: address new review comments and fix failing CI, push to the feature branch and update the Draft PR only
```

- 起動コマンドはネイティブプリミティブ `/loop`（ローカル）のみ。**独自 CLI やラッパースクリプトは作らない**。
- **実行間隔のデフォルトは 5〜10 分**（保守的）。上記は `5m`。
  - **間隔の変更方法**: コマンド文字列先頭の `5m` を書き換える（例: `10m`）。5 分より短くしない（頻度最小化）。

## 停止基準

- **PR 終了検知（必須）**: 対象 PR が **マージ**または**クローズ**されたことを検知したら、`/loop` をキャンセルしてループを終了する。
- **最大継続期間**: 目安として稼働は 1 営業日以内。放置されている PR は手動キャンセル（`/loop` の停止操作）で解除する。
- **無進捗検出**: 同一のレビューコメント/CI 失敗が続いて進展しない場合は停止してエスカレーション。
- 上記のいずれか（PR のマージ/クローズ・期間超過・手動キャンセル）で必ず終了する。

## 前提

- `gh` CLI が使え、対象 PR にアクセスできること。
- このリポジトリの **Draft PR 運用**（CLAUDE.md）: worktree 上の feature branch から Draft PR を作って逐次更新する運用。
- CI の実行結果が `gh pr checks` で取得できること。
- 参照: `plugins/loops/references/recipe-format.md`、リポジトリ `CLAUDE.md`（PR 運用ルール）。

## コスト注意

公式トークン管理の該当項目:
- **実行頻度を必要最小限にする**: 間隔は 5〜10 分の保守的デフォルト。5 分より短くしない。PR が動いていない時間帯は停止する。
- **決定論的作業のスクリプト化**: CI 状態の取得（`gh pr checks`）やコメント取得は決定論的なので、LLM には差分の修正のみを任せる。
- **大規模実行前のパイロット実行**: 初回は 1〜2 サイクル手動で回し、暴走しないことを確認してから常用する。
- ループはチャットの約 4 倍のトークンを消費する点に留意する。

## エスカレーション

**外向きアクションは非破壊デフォルト（feature branch への push と Draft PR の更新まで）**。以下は行わず、必要になったら人間へエスカレーションする:

- **マージしない**（`gh pr merge` 禁止）。
- **Ready for Review へ切り替えない**（Draft のまま）。
- **main への直接 push をしない**（feature branch のみ）。
- force push・PR クローズ・ブランチ削除などの不可逆操作もエスカレーション。
- レビューコメントの意図が不明・設計判断が必要・2 連続で同じ CI 失敗が直らない場合も人間へ引き渡す。
