# レシピ: goal-tests-green

> 初期シードレシピ（change-3 goal-time-recipes）。規約は `plugins/loops/references/recipe-format.md` を参照。

## ループ型

**ゴールベース**（4 分類: ターンベース / ゴールベース / タイムベース / プロアクティブ のうち）。
検証可能な終了基準（全 bats PASS）があり、達成まで自律反復させたいので `/goal` を使う。
選定基準は `references/loop-types.md` の「何を手放すか＝停止条件を手放す」に従う。

## 目的

このリポジトリの bats テストスイートが全て PASS するまで、失敗の修正 → 再実行を自律反復させる。
「テストを直す → 走らせる → また直す」の手動往復を人間が回さずに済ませるためのレシピ。

## 起動コマンド

コピペ可能な `/goal` 文字列（成功基準のコマンド + 期待値 + 最大試行数を埋め込む）:

```
/goal make `find plugins -name '*.bats' -print0 | xargs -0 bats` exit 0 with all tests passing, stop after 5 tries
```

- 起動コマンドはネイティブプリミティブ `/goal` のみ。**独自 CLI やラッパースクリプトは作らない**。
- 反復・停止判定は `/goal` のエバリュエータと `stop after N tries` に委ねる。

## 停止基準

- **成功基準（定量・機械検証可能）**: 検証コマンド `find plugins -name '*.bats' -print0 | xargs -0 bats` が **exit 0**（全 PASS）を返すこと。エバリュエータはこの exit code と PASS 件数で判定する。
- **打ち切り条件（必須）**: 最大試行数のデフォルトは **5 回**（`stop after 5 tries`）。
  - **変更方法**: 起動コマンド文字列末尾の `stop after 5 tries` の数値 `5` を書き換える（例: `stop after 8 tries`）。時間上限に切り替えたい場合は `stop after 30 minutes` 等に書き換える。
- 成功基準の達成（exit 0）または最大試行数の到達のいずれかで必ず停止する。打ち切り条件無しでは起動しない。

## 前提

- このリポジトリ直下で実行できること（`plugins/` 配下に `*.bats` が存在する）。
- `bats-core` がインストール済み。
- 参照: `plugins/loops/references/recipe-format.md`（規約）、`plugins/longrun/references/model-tiers.md`（モデル指定はティア名で。ID 直書き禁止）。

## コスト注意

公式トークン管理の該当項目:
- **実行頻度を必要最小限にする**: このレシピは手動起動の開発用。CI で回る決定論的検証をループにしない。
- **決定論的作業のスクリプト化**: テスト実行自体は決定論的なので `find ... | xargs -0 bats` のスクリプトに固定し、LLM には失敗原因の修正のみを任せる。
- **大規模実行前のパイロット実行**: 初回は `stop after 2 tries` 程度で挙動を確認してから本数を上げる。
- ループはチャットの約 4 倍のトークンを消費する点に留意する。

## エスカレーション

- 同一テストが **2 連続で同じ失敗**をした場合は、報酬ハッキング（テスト自体の削除・スキップ化）に倒れる前に人間へエスカレーションする。
- テストファイルの削除・`skip` 追加などテストを弱める変更は禁止。必要ならエスカレーション。
- 最大試行数に達しても全 PASS しない場合は、残った失敗一覧を提示して人間に引き渡す（成功と偽って完了宣言しない）。
