# /loops:goalify — brain dump から goal ブリーフを一発生成

ユーザーの頻出ワークフロー「やりたいことを書き出す → /goal に読ませるファイルを作らせる → 不足情報はヒアリングさせる」を
1 コマンドに畳む。生成物は**使い捨ての goal ブリーフ**（ゴールベースループ）であり、反復利用が見えたらレシピへの昇格を促す。

ヒアリング方法論は `plugins/longrun/references/plan-interview-methodology.md` を参照流用する
（既に書かれている項目は聞かない。不足だけを最小限の質問で埋める）。

## 入力

`/loops:goalify <テキスト|ファイルパス>` として起動する。

- 引数が**インラインテキスト**なら、そのテキストを brain dump（やりたいことの書き出し）として解析を開始する。
- 引数が**ファイルパス**なら、そのファイルの内容を読み込み brain dump として解析を開始する。

## フロー

### Step 1: 4 観点で充足分析する

brain dump を以下の **4 観点**で分析し、それぞれが「書かれているか / 不足しているか」を判定する:

1. **成功基準の機械検証可能化** — 何を達成したら成功か。**実行コマンド + 期待値**（exit code・出力・ファイル実在等）に変換できるか
2. **停止条件** — 最大試行数 / 時間などの上限
3. **スコープ境界** — 触ってよい範囲 / やらないこと
4. **前提** — 参照パス・環境・依存

### Step 2: 不足しているものだけヒアリングする

**不足している観点だけ**を AskUserQuestion で質問する（MUST）。**brain dump に既に書かれている項目については質問しない（MUST NOT）**。

- 例: 成功基準と前提は書かれているが停止条件とスコープ境界が無い → 停止条件とスコープ境界だけを質問する。
- **4 観点すべてが揃っている brain dump なら、質問は 0 問**でそのまま Step 3 の生成に進む。

### Step 3: goal ブリーフと /goal 起動コマンドを生成する

`goals/<name>.goal.md` を生成する。以下の **5 見出し**をすべて持つ:

1. **目的**
2. **成功基準** — 各項目は**機械検証可能な形式（実行コマンド + 期待値）**で書く。
   「良くなったら」等の**主観的基準を含めてはならない（MUST NOT）**。例: `find plugins -name '*.bats' | xargs bats` → 全 PASS（exit 0）
3. **制約**
4. **参照パス**
5. **エスカレーション条件**

続いて、この goal ブリーフを参照する **/goal 起動コマンドを 1 行**で出力に含める。コピペ可能な形式で:

```
/goal follow goals/<name>.goal.md until all success criteria pass, stop after <N> tries
```

### Step 4: レシピ昇格を促す（出力に 1 行）

生成物は使い捨ての goal ブリーフである前提で、出力に次の案内を **1 行**含める:

> このワークフローを**反復利用するなら `recipes/<name>.md` へ昇格**を検討（`/loops:design` で規約準拠のレシピ化）。

## 完了時の自己検証

- 生成した `goals/<name>.goal.md` を Grep し、5 見出しがすべて存在すること、「成功基準」の各項目がコマンド + 期待値で
  書かれ主観語（「良くなったら」等）を含まないことを確認してから完了を報告する。
- /goal 起動コマンド 1 行とレシピ昇格の案内が出力に含まれることを確認する。
