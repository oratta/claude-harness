# report-calls.py が `]` と `=` を行継続で分けた配列代入を取りこぼす件を直す（#244）

`plugins/casting/tests/lib/report-calls.py` の `_opens_subscript` は、対応する `]` の直後の文字だけで代入語かを判定していた。`a[1<<2]\` の次の行が `=3` の形では `]` の直後が行継続 `\` なので添字として開かず、`<<` がヒアドキュメント開始と誤認されて以降の `report` 呼び出しが全消滅していた（検出カテゴリが黙って減る無言経路）。

- `]` の直後が `\` だけで行が終わるあいだは次の物理行へ進み、`=` か `+=` で始まるかを見るようにした（bash は継続を除いてから読むため）
- `plugins/casting/tests/casting-structure.bats` に `=` 分割・`+=` 分割のフィクスチャを足した（修正前は fail、修正後 pass）
- 行継続の先読みで、コマンドの引数の `foo[bar` を代入の添字と読む誤認の範囲が広がった（PR #635 レビュー指摘。`: foo[bar <<EOF ]=3` は main でも壊れていた）。代入語として添字を開くのは、コマンド位置（`if` `{` `!` などの予約語の直後を含む）か前置き代入の連なり（`x=1 a[…]=3 cmd`）か複合代入 `=( … )` の中だけにした。リダイレクトの後ろは bash も代入語として読まないので開かない。単語を読み始める位置は、いま居る `$(` `` ` `` `((` がその論理行の中で開いていればその直後（`echo "$(a[…]=3)"` の中はコマンド位置）で、`function name {` の本体の先頭もコマンド位置として扱う
- その形（1 行の形と行継続で分けた形、どちらもヒアドキュメント本文に偽の `report` を置く）と、前置き代入・予約語の直後・二重引用の中の `$(`・`function name {` の本体の代入が引き続き添字として開くことを確かめるフィクスチャを足した（修正前は fail、修正後 pass）
- 追跡下のシェルスクリプト全件で、修正前後のスキャナ出力に差は出ない（`*.sh` `*.bash` `*.bats` 全件でコード領域の判定も行単位で一致）
- version は上げない
