# 委任の定義 — 許可ツール × 任された観点（delegation）

エージェントへの「委任」を何で定義するかの唯一の正本（oratta/claude-harness#207、2026-08-28 主整理）。観点の語彙は `catalog.md`、観点の注入の配線は `injection.md` が正本で、ここには複製しない。このファイルが持つのは**委任の定義・宣言の書式・正本の優先順**だけ。

## 定義

委任はプリミティブ 2 つの積で決まる。

| プリミティブ | 意味 | 正本（ここが真） | 確認のしかた |
|---|---|---|---|
| **許可ツール** | エージェントが主に聞かずに使ってよいツール・コマンドの集合 | Claude Code の permission 設定（`settings.json` / `settings.local.json` の allow / deny、`/permissions`） | 設定ファイルを読む。宣言ファイルの表はその要約 |
| **任された観点** | エージェントが主に聞かずに判断してよい観点の集合 | 配役表の 3 層解決（`catalog.md` → `project.md` → `local.md` → セッション宣言。`casting-check.sh resolve` の出力） | resolve を実行する。宣言ファイルの表はその要約 |

エージェントは主に問いかける前にこの 2 つのホワイトリストを見て、「このツールは使ってよい」「この観点は自分が判断する」と理解して進める。返信前チェック（`rules/perspective-casting.md`）の手順③「担い手は主か」は、観点側とツール側の両方をこの定義で確認する手順である。

**論点**とは、別の観点を入れると結論が変わるもの。LLM 側が情報を持っているもの（セキュリティのデファクト、言語のイディオム、ライブラリの使い方など）は論点ではなく、観点の担い手に関係なく自分で決める。任された観点の論点は自分で判断し（迷ったら論点相談）、任されていない観点の論点だけを主に上げる。

## ロール（プリセット）は組み合わせ名

「委任レベル 0/1/2」「開発担当」「マーケ担当」のようなロールは、許可ツール集合と任された観点集合の**特定の組み合わせに付けた名前**であり、プリミティブではない。ロールを増やしても定義は変わらず、2 表の中身が変わるだけ。ロールの一覧表や正本はこのプラグインには置かない（住人ごとの組み合わせは導入先——flatmate の住人定義や各 repo の宣言ファイル——が持つ）。

例（説明用。正本ではない）:

| ロール名 | 許可ツール | 任された観点 |
|---|---|---|
| 読むだけの調査係 | Read / Grep / Glob と読み取り系 Bash | 報告の正確性・技術設計・品質 |
| 開発担当 | 上に加えて Edit / Write / テスト・lint・git commit・push | 上に加えて 資産・回復可能性（可逆）・運用工数・維持（見積） |

## 委任宣言の書式（2 表を 1 か所に）

宣言は `## 委任` 見出しの下に 2 表を並べる。**この書式は repo ファイルとセッション宣言で共通**。

```markdown
## 委任

### 許可ツール

| ツール/パターン | 許可 | 出どころ |
|---|---|---|
| Bash(npm test:*) | 許可 | .claude/settings.json allow |
| Bash(git push:*) | 要承認 | 主の口頭指示（2026-08-28） |

### 任された観点

| 観点 | 担い手 | 根拠 |
|---|---|---|
| 財務・コスト | エージェント | project.md（予算方針文 policies/budget.md） |
| 信用・レピュテーション | 主 | カタログ既定 |
```

列の意味:

- 許可ツール表 — `ツール/パターン` は permission の記法（`Bash(npm test:*)` 等）か自然文、`許可` は「許可／要承認／禁止」の 3 語、`出どころ` はその許可がどこで決まっているか（settings のパス・主の指示・ロール名）
- 任された観点表 — `観点` は `catalog.md` の語彙、`担い手` は「エージェント／主」（カタログの担い手表記をそのまま写してもよい）、`根拠` はどの層の行から来ているか（カタログ既定／project.md／local.md／セッション宣言）と、移譲文書があればそのファイル名

### 置き場

| 置き場 | 用途 |
|---|---|
| `<repo>/.claude/casting/delegation.md`（git 追跡） | その repo で働く住人が共通で受ける委任。`/casting:init` が雛形（`templates/delegation.md`）から生成する |
| 起動プロンプト中のセッション宣言 | そのセッションだけの委任。書式は同じ |

## 宣言は要約であり、正本ではない

宣言ファイル・セッション宣言の 2 表は、両正本（permission 設定と配役表 3 層）の**要約を 1 枚で読めるようにしたもの**で、正本ではない。宣言と正本が食い違ったら**正本が勝つ**。立ち上げ時にはこの 1 枚を読み、迷ったら正本（permission 設定・`casting-check.sh resolve`）を見る。

宣言ファイルは `casting-check.sh` の検査対象に入れない（列構成が配役表と違うため 5 列検査に巻き込まない。front matter の `catalog_version` も検査しない）。整合の機械検査は持たないので、配役表や permission を変えたときは宣言ファイルの該当行も同じ変更で直す。

**任された観点表は第 3 層の上書きではない。** セッション宣言で観点の担い手を変えたいときは、従来どおり 5 列の上書き表（`skills/casting/SKILL.md` の「セッション宣言の書式」）を書く。`## 委任` 配下の 3 列表だけ書いても resolve の結果は変わらない。

## 観点の判断基準を作る入口

任された観点の判断基準（`.claude/casting/policies/<slug>.md`）は `/casting:policy-interview <観点>` で主と 1 問ずつやり取りして作る（`commands/policy-interview.md`）。policy が整った観点は配役表の該当行を「エージェント」に変え、宣言ファイルの観点表にも同じ変更を写す。
