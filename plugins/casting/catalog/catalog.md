# 観点カタログ — 「観点の配役」フレームワーク正本

意思決定移譲のフレームワーク「観点の配役」が使う観点語彙・既定の担い手・変更手続きの唯一の正本。
配役表（`project.md` / `local.md`）と判例台帳（`precedents.md`）はこのカタログの観点名だけを使う。
フレームワーク自体の背景・運用の考え方は `skills/casting/SKILL.md` を参照。

## 列定義

配役表・判例台帳・このカタログで共通に使う5列の意味。

| 列 | 意味 |
|---|---|
| 観点 | 「コンテキスト＋判断基準」の束に付けた名前。配役表と判例台帳はこの語彙で書く |
| この観点が要る論点の条件 | 目の前の論点をこの問いに当てはめ、Yes ならこの観点の担い手を議論に入れる、という判定条件 |
| 判断基準の出どころ | 内蔵＝モデルの学習済み知識だけで判断できる／注入＝主が選んだ方針を文書で渡さないと判断できない／混合＝判断力は内蔵で足りるが、閾値や許容量だけ注入が要る |
| 移譲に必要な文書 | これを書いてエージェントに渡した時点で移譲が成立する文書。「—」は文書なしで移譲できるという意味 |
| 既定の担い手 | 3層デフォルトの最上層（プロジェクト既定表）に入れる初期値。2026-08-17 主承認済み |

| 報告の正確性 | 主に見せる数字・状態は検証済みか | 内蔵（検証手順の強制） | — | エージェント |

## 横断軸（観点ではない）

観点そのものではなく、各観点の判定に掛け合わせる2つの軸。

1. **可逆性・影響範囲＝乗数** — 各観点の深刻度を増幅する。判定不能なら回復不能側に倒す
2. **能力・権限の借用＝手の借用** — 判断ではなく「手の借用」（権限追加・アカウント操作・実機確認）。観点判定を通さず正当にエスカレーションできるが、プリフライト（自力で片付かないことの確認）は必須

## 変更手続き

観点の配役への変更は2ルートに分かれる。

**軽量ルート（配役の変更＝担い手・移譲に必要な文書の中身）**: 判例台帳の「還元」欄が入口。
エージェント→主へ戻す方向は即時反映してよい。主→エージェントへ移す方向は、移譲に必要な文書の整備と主承認が必要。

**重量ルート（構造の変更＝観点の追加・削除・統合・分割・列定義変更）**: 次の3条件をすべて満たすこと — ① `version` を1つ上げる ②下の変更記録に追記する ③主承認必須。
