# casting — 「観点の配役」フレームワーク運用ガイド

意思決定移譲のフレームワーク「観点の配役」の実務手順。主に上げてよい論点は「主の視線が加わると結論が変わるもの」だけ、
かつその観点が未移譲のとき、という判定を運用する。カタログ本文（14観点・列定義・横断軸）は `../../catalog/catalog.md` が唯一の正本で、ここには複製しない。

## 3層の置き場と上書き順

配役表は `<repo>/.claude/casting/` 配下に置く。番号の大きい層が小さい層を上書きする。

| 層 | 置き場 | 扱い |
|---|---|---|
| 第1層 プロジェクト既定 | `.claude/casting/project.md` | git 追跡。`/casting:init` が catalog.md の既定値をコピーして生成する |
| 第2層 エージェント/マシン別上書き | `.claude/casting/local.md` | gitignore（`/casting:init` が `.gitignore` に追記する）。作るのは各エージェントの任意 |
| 第3層 セッション宣言 | 起動プロンプト中の宣言 | ファイルなし。下記の書式でそのセッションだけの上書きを宣言する |

判例台帳 `.claude/casting/precedents.md` はこの3層とは別枠（git 追跡・追記型）。

### セッション宣言の書式

第3層は起動プロンプト内に、project.md / local.md と同じ5列の Markdown 表で書く。上書きしたい観点の行だけを書けばよい（全14行を書き直す必要はない）。

```
## casting 上書き（このセッション限り）

| 観点 | この観点が要る論点の条件 | 判断基準の出どころ | 移譲に必要な文書 | 既定の担い手 |
|---|---|---|---|---|
| 財務・コスト | 支出・API 消費・収益に影響するか | 混合 | 予算方針文 | エージェント（今回は方針文を渡したので移譲） |
```

## 配役表の作り方

1. 対象 repo で `/casting:init` を実行する（`plugins/casting/commands/init.md`）。`project.md` と `precedents.md` が雛形から生成され、`local.md` が `.gitignore` に追記される
2. `project.md` の「既定の担い手」列を、そのプロジェクトの実情に合わせて編集する。観点名・列構成そのものは変えない（変えたくなったら下記「カタログの変更手続き」の重量ルート）
3. 主→エージェントへ移譲する行は、「移譲に必要な文書」列に書かれた文書を先に用意してから書き換える。文書なし（「—」）の行はそのまま書き換えてよい

## 論点が来たときの判定（返信前チェックの中身）

毎ターンの薄い版は `rules/perspective-casting.md`（5手順・正本）。ここではその②〜④の具体手順を書く。

1. 目の前の論点を catalog.md の「この観点が要る論点の条件」に順に当て、Yes になる観点をすべて拾う（複数観点にまたがってよい）
2. 拾った観点それぞれについて、project.md → local.md → セッション宣言の順で上書きを辿り、最終的な担い手を確定する
3. 担い手が主の観点が1つでもあれば、その論点は主に上げる。全観点の担い手がエージェントなら、方針文・判断基準に従って自走する
4. 横断軸（可逆性・影響範囲／能力・権限の借用）を確認する。不可逆・判定不能なら聖域として無条件で人間承認に倒す。権限の借用は観点判定を経ずに正当にエスカレーションできるが、プリフライト（自力で片付かないことの確認）は必須

## 判例の書き方

`precedents.md` に1判例1ブロックで追記する（既存の判例は書き換えない）。書式・記入例は `templates/precedents.md` と同一。

- **観点**: catalog.md の語彙（複数の観点が絡む判例は「、」区切り）、当てはまらなければ「カタログ外」
- **経路**: 「主に上げた」／「自走した」
- **帰結**: 「論点だった」／「論点じゃなかった」＋一言の理由（主の視線で結論が変わったかどうかが判定基準）
- **還元**: project.md / local.md のどこを変えたか。変えなければ「なし」

判例が積み上がるほど、`scripts/casting-check.sh` が「同一観点で論点じゃなかったが2件以上」を検出し、その観点の移譲仕組み化（方針文整備）を促す。

## カタログの変更手続き

- **軽量ルート**（配役の変更＝担い手・移譲文書の中身）: 判例の「還元」欄が入口。エージェント→主へ戻す方向は即時。主→エージェントへ移す方向は移譲文書の整備＋主承認
- **重量ルート**（構造の変更＝観点の追加・削除・統合・分割・列定義変更）: catalog.md の `version` を1つ上げ、「変更記録」節に追記し、主承認を得る

## casting-check.sh

`scripts/casting-check.sh [--catalog <path>] [<repo-root>]` は対象 repo の `.claude/casting/` に対して、未知の観点語彙・「カタログ外」判例・同一観点の「論点じゃなかった」2件以上・`catalog_version` 不一致の4項目を検査する。検出なしで exit 0、検出ありなら一覧を出力して exit 1。CI やコミット前フックに組み込んでよい。
