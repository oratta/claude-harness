# session-proc-reaper の comm 一覧が空のとき、原因がログに残るようにする（#496）

`srp_select_targets` の awk は `FNR == NR` で 1 つ目のファイル（comm 一覧）を判定していた。`ps -o pid=,comm=` が失敗して一覧が空になると、2 つ目のファイル（env 一覧）の全行でもこの条件が真になり、env 一覧が comm として読まれて対象が 0 件になっていた。止めない側に倒れるので事故ではないが、ログが `none` だけで原因が分からなかった。

- `FNR == NR` を `FILENAME == ARGV[1]` に置換
- awk の前に comm 一覧が空なら `none mark=… trigger=- reason=ps-comm-empty` をログに出して return 1
- comm 一覧が空でないときの挙動は変えない。検査は `session-proc-cleanup.bats` に 1 件追加
- 戻し方: 上記 2 箇所と追加した bats を元に戻す
