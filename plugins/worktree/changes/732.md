# wt-setup の context: fork / background: false が効くかを実機で確かめ、残す理由を書く（#732）

Claude Code 2.1.292 の `claude -p --plugin-dir` で、同名の `commands/foo.md` と `skills/foo/SKILL.md`（`context: fork` / `background: false`）を持つ probe プラグインを作って比べた。`/probe:foo` も Skill ツールの `probe:foo` も commands 側の本文が実行され、fork の表示は出なかった。同名の commands が無い `probe:bar` では Skill ツール経由で `completed (forked execution)` と出た。つまり `/wt-setup` と `worktree:wt-setup` は `commands/wt-setup.md`（インライン実行のラッパー）に解決され、SKILL.md の frontmatter は現行経路では効かない。公式ドキュメントは「skill と `.claude/commands/` のファイルでは skill が勝つ」と書くが、プラグインの同名の組み合わせでは実機で commands が勝った。

frontmatter の `context: fork` / `background: false` は残した。既存の要件（`skill-execution-isolation`）が fork を求めていること、ラッパーを外したときに最初から効くこと、残すコストが数行であることが理由。frontmatter に短い YAML コメントを足し、SKILL.md 本文に節「frontmatter の fork 指定について」を足して観測と理由を書いた。`plugins/worktree/tests/skill-safety.bats` に、先頭 12 行のコメントと本文の節を検査するテストを足した。

版（`version: 1.7.1`）は上げていない。
