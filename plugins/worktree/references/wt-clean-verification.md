# wt-clean 自己検証の詳細手順

`wt-clean` スキルの `## 自己検証` 節から参照される検証詳細。共通原則は `plugins/loops/references/self-verification.md`。

wt-clean は worktree を診断（🟢🟡🔴）して Pass 1（自動処理）/ Pass 2（判断バッチ）で処理する破壊的操作を含むため、完了宣言の前に「削除・退避が意図どおりに行われた evidence」を必ず確認する。

## 診断・処理後に確認する evidence

- **削除された worktree が登録から消えている**: `git worktree list` の出力に、削除対象として選んだパスが現れないことを確認する。
- **自動削除（🟢/🟡）の直前に診断根拠を表示している**: マージ済み判定の根拠（branch --merged / squash 検証結果）を表示せずに削除していないこと（無音削除の禁止）。
- **🟡（LLM あり）の退避検証が削除に先行している**: 退避先ファイル（LLM 退避物）が実在し空でないことを**検証してから** worktree を削除したことを確認する。検証失敗のまま削除していないこと。
- **🔴 / dirty の破壊操作が Pass 2 の回答後に実行されている**: マージ / スキップ / 破棄 / dirty 破棄のいずれを選んだかと、その結果（マージ commit の有無・ブランチの残存）が一致し、AskUserQuestion の回答を受け取った後の別ターンで実行されていることを確認する。
- **孤児の整理**: パスが既に存在しない worktree は `git worktree prune` で整理し、`git worktree list` がクリーンになったことを確認する。
- **Step 0 の同期**: `origin/<main>` の同期を行った場合、`--no-sync` でない限り同期が成功した exit code を確認する。
- **稼働シグナルのある worktree を自動処理していない**: 削除対象パス配下に非シェルプロセス（`claude` / `node` / `next` 等）が稼働していた、または `~/.claude/projects/<worktree-path-slug>/` に 24 時間以内更新の `.jsonl` があった worktree について、Pass 1 の自動削除・自動再利用化に入れず Pass 2 の判断バッチへ回したことを確認する。Pass 2 の提示に検出内容（PID・コマンド名／セッションログの更新時刻）が含まれていたことも確認する（絶対禁則 3・issue #77: git がクリーンな壁打ちセッションの worktree を 🟢 Safe と誤判定して削除した事故）。
- **削除対象 worktree 配下のプロセス残留なし**: `git worktree remove` を実行する全ての箇所で、その直前に `kill_devserver_under` によるプロセス検出・停止（SIGTERM→SIGKILLフォールバック）を行い、停止した PID・コマンド名または「プロセスなし」がログに表示されていることを確認する。停止対象は削除対象パス配下に限定され、メインリポや他 worktree のプロセスを誤って止めていないことも確認する。

## PASS 条件

上記の各確認が期待どおり（対象パスが消えている / 退避物が実在する / 選択と結果が一致する / 稼働シグナルのある worktree を自動処理していない / プロセス残留がない）であることを evidence として提示できたときのみ、クリーンアップ完了を宣言する。
