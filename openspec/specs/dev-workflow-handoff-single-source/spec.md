# dev-workflow-handoff-single-source Specification

## Purpose
手渡し規則（コンテキスト上限に達したサブエージェントの手渡し）の本文が正本 1 箇所にあることを、どこまで機械で守り、どこから先を仕様レビューに任せるかの契約。言い換えの検出は原理的に完全にはできないので、機械検査は逐語一致に絞る。

## Requirements

### Requirement: 正本の一文が他のファイルに逐語で貼られていないことを機械検査する

`plugins/dev-workflow/tests/handoff-single-source.bats` は、手渡し規則の正本 2 か所——`skills/develop/references/decision-criteria.md` の「コンテキスト上限（サブエージェントの手渡し）」節（次の `##` / `###` 見出しの直前まで）と、`skills/develop/references/return-declaration.md` の全文——から、表とコードブロックを除いた一文のうち 40 文字以上のものを集め、その文の出どころの正本以外のすべての追跡ファイル（もう片方の正本を含む）に対して逐語で探し、1 件でも見つかれば失敗しなければならない（MUST）。除外するファイルは、その文の出どころの正本自身だけとし、履歴の記録（`openspec/changes/archive/`・`plugins/*/changes/`・CHANGELOG）やテストも除外してはならない（MUST NOT）。除外を足すと、そこが穴になるため。2 つの正本のあいだも除外しないのは、本体向けの規則と W・G 向けの宣言を同じ文で両方に置くと、直すときに片方が取り残されるためである。

この検査は、2 つの正本から読めた文の合計が 20 件未満のとき、およびどちらかの正本（節またはファイル）が読めないときに緑になってはならない（MUST NOT）。見出しの改名やファイルの移動で何も見ていない緑になることを防ぐため。また、どちらの正本の一文についても、実際に別ファイルへ貼ったときに落ちることを負例のテストで固定しなければならない（MUST）。

**守備範囲**: 入力の出どころは、この repo の git 追跡ファイル（プラグイン・スキル・ルール・docs・履歴・テスト）と、2 つの正本の本文である。拾いたい誤りは、正本の 40 文字以上の一文を、読み手が手で（または別の担当が機械的に）別ファイルへ逐語でコピーしてしまうことだけである。通ってよい入力は、正本のパスを指す参照、40 文字未満の短い句、言い換えた文、一文を割って貼った写し、正本以外の語彙で書いた別の説明である。これらを検出する穴が見つかるたびに検査を拡張して塞ぎ切ることを、この検査の完了条件にしない（MUST NOT）。

#### Scenario: 正本の一文を別の面にコピーする

- **WHEN** `README.md` など正本以外のファイルに、どちらかの正本の 40 文字以上の一文をそのまま貼る
- **THEN** `handoff-single-source.bats` が、写しのあるファイルのパスを出して失敗する

#### Scenario: 一方の正本の一文をもう一方の正本に貼る

- **WHEN** `return-declaration.md` の 40 文字以上の一文を `decision-criteria.md` の「コンテキスト上限（サブエージェントの手渡し）」節にそのまま貼る
- **THEN** `handoff-single-source.bats` が、`decision-criteria.md` のパスを出して失敗する

#### Scenario: 正本の節が読めない

- **WHEN** `decision-criteria.md` の節の見出しが改名されて節が見つからない、または `return-declaration.md` が無い
- **THEN** 検査は「0 件で緑」ではなく失敗する

### Requirement: 逐語一致検査が保証しないことを明記する

テスト（`handoff-single-source.bats`）のコメントと本 spec の両方に、緑が保証するのは「正本の一文が逐語では他に存在しない」ことだけだと書かなければならない（MUST）。任意の言い換え・語順を変えた写し・一文を割って貼った写し・40 文字未満の短い句は検出しないことを明記しなければならない（MUST）。言い換えの再掲を捕まえるのは、規則の本文を正本に置くという既存の要件（dev-workflow-develop「コンテキスト上限の規則の本文は、本体向けを decision-criteria.md に、W と G の宣言を return-declaration.md に置く」）の MUST NOT と、仕様レビューである。言い換えを検出する語彙リストや除外リストを足して網羅を目指してはならない（MUST NOT。PR #253 でゲート 7 周・仕様レビュー 4 周を使って収束しなかった）。

#### Scenario: 言い換えて再掲する

- **WHEN** 正本の規則を別の言い回しで他のファイルに書く
- **THEN** 機械検査は通る（検出しないことがテストで固定されている）。捕まえるのは仕様レビューである
