## Requirements
### Requirement: 共有の禁止語検査スクリプトを dev-workflow の scripts に置く

`plugins/dev-workflow/scripts/forbidden-words-check.sh` を置かなければならない（MUST）。実行権限を持ち、先頭行は `#!/bin/bash` でなければならない（MUST）。bash 3.2 で動き、依存は bash・grep・sed・tr・sort と任意の `gh` だけでなければならない（MUST）。`CLAUDE_PLUGIN_ROOT` など plugin として install されていることに依存してはならない（MUST NOT）。新しい plugin を足してはならない（MUST NOT）。

#### Scenario: スクリプトが実行できる
- **WHEN** `plugins/dev-workflow/scripts/forbidden-words-check.sh` の権限と先頭行を調べる
- **THEN** 実行権限が付き、先頭行は `#!/bin/bash` である

#### Scenario: plugin の外のパスから呼べる
- **WHEN** スクリプトを別のディレクトリにコピーして、`CLAUDE_PLUGIN_ROOT` を未設定のまま `--root` を一時ディレクトリにして呼ぶ
- **THEN** 使い方のエラーにならず、そのディレクトリのファイルを検査して終了する

### Requirement: 引数と終了コードの契約

スクリプトは検査するファイルの一覧を標準入力から 1 行 1 パス（`--root` からの相対）で読み、引数は次のとおりでなければならない（MUST）。`--root <dir>`（必須。検査の cwd）、`--dict <file>`（1 回以上。複数回指定できる）、`--allow <file>`（0 回以上。複数回指定できる）、`--name <名前>`（任意。既定 `forbidden-words-check`。`gh` が引けないときの通知の先頭に使う）、`--count-file <file>`（任意。違反の件数を 10 進数 1 行で書き込む）。空行は無視する。パスの相対の基準は `--root` で、`--dict`・`--allow`・`--count-file` の相対パスも `--root` から解く。

終了コードは、違反が 0 件なら 0、1 件以上なら 1、引数の誤り（必須の引数が無い・知らない引数・`--root` に移れない）なら 2 でなければならない（MUST）。違反は 1 件 1 行で標準エラーに出し、標準出力には何も出してはならない（MUST NOT）。`--count-file` を指定したときは、違反が 0 件でも `0` を書く。

環境変数 `FORBIDDEN_WORDS_NO_GH` が空でなければ `gh` を呼んではならない（MUST NOT）。`gh` は呼び出し元の PATH から探し、`--root` を cwd にして呼ばなければならない（MUST）。

#### Scenario: 違反が無ければ exit 0 で何も出さない
- **WHEN** 辞書の語を含まないファイルの一覧を標準入力に渡して呼ぶ
- **THEN** 終了コード 0、標準出力も標準エラーも空で、`--count-file` には `0` が書かれる

#### Scenario: 違反があれば exit 1 で件数を渡す
- **WHEN** 辞書の語を含むファイルの一覧を渡して呼ぶ
- **THEN** 終了コード 1、標準エラーに違反が 1 件 1 行で出て、標準出力は空で、`--count-file` に違反の件数が書かれる

#### Scenario: 引数の誤りは exit 2
- **WHEN** `--root` を付けずに呼ぶ、または知らない引数を付けて呼ぶ
- **THEN** 終了コード 2 で、標準エラーに使い方が出る

### Requirement: 辞書の書式と照合の規則

辞書は 1 行 1 語の固定文字列で、空行と `#` で始まる行は無視しなければならない（MUST）。照合は大文字小文字を区別しない部分一致で、一覧の各ファイルの本文とパス名の両方に当てる。バイナリのファイルの本文は見ない（`grep -I`）。複数の `--dict` の語は、引数の順・各ファイルの行の順に連結して 1 つの辞書として扱い、重複する語も取り除かず保持する（移植元の単一の辞書で同じ語が 2 行ある挙動と同じ）。したがって同じ語が複数の辞書や行にあれば、当たりは語の出現ごとに 1 件ずつ出て（件数は重複の数だけ増える）、表示する綴りはそれぞれの出現が書かれたとおりの大文字小文字で、出す順は連結した辞書の順になる。辞書のファイルが無ければ `<辞書のパス>: 無い`、読めなければ `<辞書のパス>: 読めない` を違反として出さなければならない（MUST）。語の数が 0 なら照合を行わない。

違反の文面: 本文の当たりは `<パス>:<行番号>:<辞書の語>`（語は辞書に書かれたとおりの大文字小文字）、パス名の当たりは `<パス>:path:<辞書の語>`、読めないファイルは `<パス>: 読めない`、読めるのに `grep` が 0・1 以外の終了コード N で終わったファイルは `<パス>: 読めない（grep の終了コード N）` でなければならない（MUST）。同じ行が複数の語に当たれば語ごとに 1 件、同じ語が複数の行に当たれば行ごとに 1 件を出す。

#### Scenario: 辞書の語を足すと落ちる
- **WHEN** 辞書に 1 語を足し、その語を含む行を一覧のファイルに書いて呼ぶ
- **THEN** 終了コード 1 で、標準エラーに `<パス>:<行番号>:<語>` が出る

#### Scenario: 大文字小文字を区別しない
- **WHEN** 辞書の語が `moko` で、ファイルの本文に `MOKO` がある
- **THEN** 当たりとして違反になる

#### Scenario: パス名の当たり
- **WHEN** 辞書の語を名前に含むファイルが一覧にある
- **THEN** 標準エラーに `<パス>:path:<語>` が出る

#### Scenario: コメントと空行は語にならない
- **WHEN** 辞書に `#` で始まる行と空行だけがある
- **THEN** 違反は 0 件で exit 0 になる

#### Scenario: 辞書が無い
- **WHEN** `--dict` に存在しないパスを渡す
- **THEN** 標準エラーに `<パス>: 無い` が出て exit 1 になる

#### Scenario: 複数の辞書に同じ語がある
- **WHEN** `--dict` を 2 回指定し、両方に語 `foo` があり（片方は `Foo`）、ファイルの 1 行に `foo` がある
- **THEN** 当たりは辞書の連結順に 2 件出て、それぞれ辞書に書かれた綴りの `foo`・`Foo` で表示され、`--count-file` の件数は 2 になる

#### Scenario: 読めないファイル
- **WHEN** 一覧にあるファイルが読み取り権限を持たない
- **THEN** `<パス>: 読めない` が違反として出る

#### Scenario: 複数の辞書を合わせる
- **WHEN** `--dict` を 2 回指定し、2 つ目の辞書の語だけを含むファイルがある
- **THEN** その語の当たりが違反になる

### Requirement: allow は期限付きと恒久の 2 種類の行を持つ

allow のファイルは 1 行 1 件で、空行と `#` で始まる行は無視しなければならない（MUST）。行は `<path>:<語>:<第 3 欄>` で、`<path>` は最初の `:` まで、`<語>` は次の `:` まで（どちらも `:` を含まない）、第 3 欄は 2 つ目の `:` から行末までとする。第 3 欄で種類を決めなければならない（MUST）。

- 期限付き: 第 3 欄が `#` と 1 桁以上の数字だけ（`#<issue番号>`）。そのファイルの中のその語の当たり（本文の全行とパス名）をすべて許す。issue が OPEN の間だけ有効
- 恒久: 第 3 欄が `=` で始まり 2 文字以上。`=` のうしろが「行に含まれる固定の文字列」で、`:` や `#` を含んでよい。そのファイルで、その語に当たった本文の行のうち、行がその固定の文字列を含む行だけを許す。パス名の当たりは許さない。期限は無く、issue を引かない
- どちらでもない行は書式違反

語の比較は大文字小文字を区別せず、`<path>` は一覧のパスと完全一致で比べる。allow のファイルが無いときは何もしない（違反にしない）。

#### Scenario: 期限付きの許可は語の当たりをファイル全体で許す
- **WHEN** `a.txt:Foo:#10` があり、`a.txt` の 2 行と 5 行に `foo` があり、issue #10 は OPEN
- **THEN** `a.txt` の当たりは違反にならない

#### Scenario: 恒久の許可は固定の文字列を含む行だけを許す
- **WHEN** `a.txt:flatmate:=経緯（flatmate#599）` があり、`a.txt` の 3 行目が `経緯（flatmate#599）を参照` で 7 行目が `flatmate を使う` である
- **THEN** 7 行目だけが違反になり、3 行目は違反にならない

#### Scenario: 恒久の許可はパス名の当たりを許さない
- **WHEN** 語 `flatmate` を名前に含むファイル `flatmate-notes.md` に対し `flatmate-notes.md:flatmate:=x` がある
- **THEN** `flatmate-notes.md:path:flatmate` は違反として残る

#### Scenario: 恒久の許可は期限で切れない
- **WHEN** 恒久の行があり、`gh` が使える環境でどの issue も CLOSED である
- **THEN** 恒久の行は issue を引かれず、違反にならない

#### Scenario: flatmate の既存の書式は変わらない
- **WHEN** `scripts/test-ship-check.sh` が使う形の allow（`<path>:<語>:#<issue番号>` の行、書式違反の行 `a:b:c` や `a:b`）を渡す
- **THEN** 期限付きの行は従来どおり通り、書式違反の行は `<allow のパス>:<行番号>: 書式が <path>:<語>:#<issue番号> でない: <行>` の文面で違反になる

### Requirement: allow の未使用と issue の状態を検査する

どの当たりも打ち消していない allow の行（期限付きも恒久も）は、`<allow のパス>:<行番号>: 何も打ち消していない（出荷集合に無い・語がもう無い）: <行>` の文面で違反にしなければならない（MUST）。期限付きの行があり `FORBIDDEN_WORDS_NO_GH` が空で `gh` が使えるとき、行に書かれた issue 番号（重複は 1 回だけ）を `gh issue view <番号> --json state -q .state` で引き、`OPEN` 以外なら、その issue を指す期限付きの行ごとに `<allow のパス>:<行番号>: issue #<番号> が OPEN でない（<状態>）: <行>` を違反にしなければならない（MUST）。`gh` が状態を返せなかったら、`<--name の値>: gh で issue #<番号> の状態を引けないため、allow は書式だけ検査する` を標準エラーに出して以降の issue の検査をやめ、これを違反に数えてはならない（MUST NOT）。

#### Scenario: 打ち消さない許可は違反
- **WHEN** 一覧のファイルにその語がもう無い期限付きの行、または固定の文字列を含む当たりが無い恒久の行がある
- **THEN** 「何も打ち消していない」の違反になる

#### Scenario: 閉じた issue の許可は違反
- **WHEN** 期限付きの行が引く issue が CLOSED（`gh` のスタブで返す）
- **THEN** 「OPEN でない（CLOSED）」の違反になる

#### Scenario: gh が引けなければ書式だけ検査する
- **WHEN** `gh` が失敗する
- **THEN** 通知の行が出るが違反に数えず、他に違反が無ければ exit 0 になる

### Requirement: 違反を出す順序は flatmate の ship-check の現行に合わせる

違反は、辞書の読み込みの違反、allow の書式の違反、ファイルごとの当たり（一覧の順に、各ファイルで辞書の語の順に、パス名の当たり、本文の当たりの行番号の昇順）、未使用の allow、issue の状態の違反の順に出さなければならない（MUST）。

#### Scenario: 順序が固定されている
- **WHEN** 辞書が無く、allow に書式違反の行があり、未使用の行もある状態で呼ぶ
- **THEN** 辞書の違反、書式の違反、未使用の違反の順に標準エラーに出る

### Requirement: flatmate の呼び出しの契約

flatmate の `scripts/ship-check.sh` が次の形で呼んで、置き換え前と同じ違反一覧（同じ文面・同じ順序・同じ件数・同じ終了コードの意味）を得られなければならない（MUST）。呼び出し: 出荷ファイルの一覧を標準入力に渡し、`bash <スクリプトのパス> --root <検査 root> --dict ship/forbidden.txt --allow ship/allow.txt --name ship-check --count-file <一時ファイル>`。`SHIP_CHECK_NO_GH` が非空のときは呼び出し側が `FORBIDDEN_WORDS_NO_GH` に写す。スクリプトの取得方法（flatmate の CI は固定した commit の `oratta/claude-harness` の checkout、手元は環境変数で名指した clone）の決定は genetta-inc/flatmate#1732 が受け持ち、このスクリプトは「リポジトリのファイルとしてパスで直接呼べる」ことだけを約束する。

#### Scenario: flatmate と同じ入力で同じ違反一覧になる
- **WHEN** flatmate の `scripts/test-ship-check.sh` の fixture と同じ内容（禁止語を含む出荷ファイル・パス名に禁止語を含むファイル・期限付きの allow・書式違反の allow・CLOSED を返す `gh` のスタブ）を上の呼び出しの形で検査する
- **THEN** 標準エラーの行の文面と順序が、置き換え前の `ship-check.sh` の同じ検査と一致し、`--count-file` の件数は標準エラーの違反の行数と一致する

### Requirement: 辞書の書式と allow の期限の規則を文書にする

`plugins/dev-workflow/docs/forbidden-words-check.md` に、少なくとも次を書かなければならない（MUST）。スクリプトの呼び出しの形（引数・標準入力・環境変数・終了コード）、辞書の書式と照合の規則、allow の 2 種類の書式（期限付きは issue が OPEN の間だけ有効、恒久は固定の文字列を含む行だけを許し期限なし）と使い分け、基準をコメント行に書くこと、検査の保証が「辞書に登録した語の混入を止める」までで辞書の網羅はリポジトリ側の責務であること、公開リポジトリの辞書には新たに固有名を足さず個人版の辞書は引数で足すこと。

#### Scenario: 文書に規則がある
- **WHEN** `plugins/dev-workflow/docs/forbidden-words-check.md` を読む
- **THEN** 上の項目がすべて書かれていて、`--dict`・`--allow`・`--count-file`・`#<issue番号>`・`=<行に含まれる固定の文字列>`・「OPEN の間だけ有効」・「辞書の網羅」の語を含む

### Requirement: この検査の守備範囲

この要件は、辞書・allow・照合・allow の期限の検査を含むこの capability のすべての要件に共通の守備範囲を定め、各要件の検査はこの範囲を超える保証をしてはならない（MUST NOT）。

- 想定する入力の出どころ: 各リポジトリの管理者が用意する辞書と allow、および呼び出し側が選定したファイル一覧。ファイル一覧の集合の選定（何を公開側の部品とするか）と、ルートの外を指す symlink などの排除は呼び出し側が担い、このスクリプトは渡された一覧のファイルを検査するだけである。敵対的な入力（辞書や一覧を悪意で作る者）は想定しない
- 拾う誤り: 辞書に登録した語が一覧のファイルの本文とパス名に混入していること、allow の書式の違反・未使用・issue が OPEN でないこと
- 通してよい具体例: 辞書にない固有名・文の良し悪し・一覧の範囲の正しさ・辞書の網羅・基準（出典・互換）が許可の根拠として足りるか。人のレビューと辞書の整備が見る
- 完了条件にしないこと: 上の「通してよい具体例」を見つけること、見つかる穴をすべて塞ぐこと（MUST NOT）
- 範囲外: Harness の CI への接続、公開版の辞書、#1168 の検索のテストの置き換え（後続の change）、flatmate 側の置き換え（genetta-inc/flatmate#1732）

#### Scenario: 辞書にない語は通る
- **WHEN** 辞書にない固有名を含むファイルを検査する
- **THEN** 違反は出ず、その誤りは辞書の整備とレビューが見る

#### Scenario: 一覧にないファイルは検査されない
- **WHEN** 辞書の語を含むファイルが標準入力の一覧に含まれていない
- **THEN** 違反は出ない。集合の選定は呼び出し側の責務である
