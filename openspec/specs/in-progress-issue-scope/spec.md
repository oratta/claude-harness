# in-progress-issue-scope Specification

## Purpose
作業中の issue に受け入れ条件が足されて範囲が広がるのを防ぐため、足す前に作業中かを確かめ、作業中なら新しい issue に切り出すか、作業中と書いて主に聞く。

## Requirements

### Requirement: 既存 issue の受け入れ条件を足す前に作業中かを確かめる

エージェントは、既存の issue の受け入れ条件を足す前に、その issue が作業中かを確かめなければならない（MUST）。足してよいかを主に聞く場合は、聞く前に確かめなければならない（MUST）。issue の本文だけを読んで作業中でないと判断してはならない（MUST NOT）。別のリポジトリのセッションから足すときも同じである。

この決まりは常時注入の `rules/*.md` に置かなければならない（MUST）。足そうとする瞬間に手順書を読む判断はできないためである。

G がレビュー指摘の振り分け（`dev-workflow:pr-review-gate` の手順）で受け入れ条件に足す場合だけは、この要件の対象外とする。本体が範囲外の問題の起票で同じ手順の段 C の問いを借りる場合は対象外に入らず、この決まりを優先する。

#### Scenario: 本文だけでは作業中かが分からない

- **WHEN** エージェントが open の issue に受け入れ条件を足そうとし、本文には作業中である旨が書かれていない
- **THEN** エージェントは編集の前に、その issue のコメントと、開いた紐づく PR を確かめる

#### Scenario: 足してよいかを主に聞く

- **WHEN** エージェントが、受け入れ条件を足してよいかを主に聞こうとしている
- **THEN** エージェントは問いを書く前に作業中かを確かめ、作業中なら問いにその旨を書くか、聞かずに新しい issue に切り出す

#### Scenario: 別のリポジトリのセッションから足す

- **WHEN** 別のリポジトリのエピックを回すセッションが、harness の issue に受け入れ条件を足そうとする
- **THEN** そのセッションにも `rules/*.md` の決まりが載っていて、対象のリポジトリを指定して同じ確認をする

#### Scenario: レビュー指摘の振り分けは対象外

- **WHEN** G が `dev-workflow:pr-review-gate` の振り分けの手順で、指摘を別の子 issue の受け入れ条件に足す
- **THEN** G はこの要件ではなく、その手順の決まりに従う

#### Scenario: 本体が段 C の問いを借りる

- **WHEN** 本体が、作業中に見つけた範囲外の問題の起票で段 C の問いを借り、同じエピックの子 issue の受け入れ条件に足す扱いに当たった
- **THEN** 本体はその子 issue が作業中かを確かめ、作業中ならこの決まりに従う

### Requirement: 作業中かを 2 つの材料で判定する

エージェントは、issue が作業中かを `develop 開始` か `実行モード:` の行があるコメントと、開いた紐づく PR の 2 つで判定しなければならない（MUST）。どちらかがあれば作業中である。開いた紐づく PR とは、本文に `Closes` / `Fixes` / `Refs #<番号>`（大文字小文字不問）のいずれかがある open の PR である。番号が PR の本文に現れるだけで、この 3 つの参照の形でないものは含まない。マージ済みの PR は開いた紐づく PR に数えない。したがって、マージ済みの PR だけが残る open の issue は、`develop 開始` か `実行モード:` の行があるコメントがあれば作業中、無ければ作業中でない。

**守備範囲**: 入力の出どころは、`gh` が返す issue のコメントと open の PR の本文である。拾いたい誤りは、issue の本文だけを見て作業中の issue に足すことである。通してよい例は、番号が本文に現れない PR で進む作業、PR も開始のコメントも無い作業、放置された issue を作業中と読むことである。穴が見つかるたびに塞ぎ切ることは、この要件の完了条件にしない。

#### Scenario: Refs で参照する PR だけで進む作業

- **WHEN** open の PR の本文に `Refs #<番号>` があり、issue に `develop 開始` か `実行モード:` の行があるコメントが無い
- **THEN** エージェントは、その issue を作業中と読む

#### Scenario: 番号が PR の本文に現れるだけ

- **WHEN** open の PR の本文に番号が現れるが、`Closes` / `Fixes` / `Refs` の参照の形ではない
- **THEN** エージェントは、その PR を開いた紐づく PR に数えない

#### Scenario: マージ済みの PR だけが残る

- **WHEN** open の issue に、紐づくマージ済みの PR だけがあり、開いた紐づく PR が無い
- **THEN** エージェントは `develop 開始` か `実行モード:` の行があるコメントがあれば作業中と読み、無ければ作業中でないと読む

### Requirement: 作業中なら新しい issue に切り出すのを既定にする

確かめた結果、issue が作業中なら、エージェントは足そうとした内容を新しい issue に切り出さなければならない（MUST）。例外は、次の要件のとおり主の OK を得て同じ issue に足す場合だけである。切り出すことを主に聞いてはならない（MUST NOT）。

#### Scenario: 作業中の issue に足す内容が見つかった

- **WHEN** issue に `develop 開始` か `実行モード:` の行があるコメントか、開いた紐づく PR がある
- **THEN** エージェントは元の issue の本文を編集せず、内容を新しい issue に起票し、URL を事後報告する

#### Scenario: 作業中でない

- **WHEN** issue に `develop 開始` か `実行モード:` の行があるコメントも、開いた紐づく PR も無い
- **THEN** この要件は何も求めない。受け入れ条件を足すかどうかは、これまでの判断のとおりに決める

### Requirement: 作業中の issue に足すときは作業中と書いて主に聞く

作業中の issue にどうしても受け入れ条件を足すときは、エージェントは、作業中であること（PR があればその URL）を問いに書いて主の OK を得てから足さなければならない（MUST）。作業中であることを問いに書かずに得た OK で足してはならない（MUST NOT）。

主が作業中と知っていることが主の発言から分かるときは、聞き直さなくてよい（MAY）。

#### Scenario: 同じ issue に足したい

- **WHEN** エージェントが、切り出すより同じ issue に足すほうがよいと判断した
- **THEN** 主への問いに、その issue が作業中であることと PR の URL が書かれていて、主の OK の後に足す

#### Scenario: 主が作業中と知らずに足す指示を出した

- **WHEN** 主が issue に足すよう指示し、その issue が作業中で、主がそれを知っていると発言から分からない
- **THEN** エージェントは足す前に、作業中であることと PR の URL を書いて主に聞く
