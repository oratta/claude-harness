# cost-ledger-pricing Specification

## Purpose
API 換算コストの単価表と円換算レートの置き場所と引き方。単価はモデル名の最長一致の前方一致で引き、換算は固定レートで環境変数から上書きできる。未知モデルを黙って 0 円にしない。
## Requirements
### Requirement: 料金表と換算レートの単一の置き場所
システムは API 換算に用いる単価表（$/MTok の 入力・出力・キャッシュ書込 5m・キャッシュ書込 1h・キャッシュ読出）と、USD から円への換算レートを、リポジトリ内の**同じ 1 ファイル**にのみ SHALL 置く。集計の実装やコマンドが個別に単価やレートを持ってはなら MUST NOT ない。このファイルはコードではなくデータ形式と SHALL する（実装言語に依存せず読めるようにするため）。

#### Scenario: 単価とレートが 1 か所にしかない
- **WHEN** リポジトリ内で単価と換算レートの数値を検索する
- **THEN** cost-ledger の実装のうちそれらを定義している箇所は 1 ファイルだけである

#### Scenario: 単価を直すと全経路に効く
- **WHEN** 料金表のあるモデルの単価を書き換える
- **THEN** `/cost` の出力がその単価で計算し直される

### Requirement: 単価の引き方は最長一致の前方一致
会話ログのモデル名は `claude-haiku-4-5-20251001` のように日付が付くため、システムは料金表の鍵をモデル名の**前方一致**で引 MUST く。複数の鍵が前方一致するときは**最も長い鍵**を採 MUST る。単純な順次走査で最初に一致した鍵を採ってはなら MUST NOT ない（`claude-fable-5` と `claude-fable-5-1` のように一方が他方の接頭辞になる鍵があり、表の並び順に結果が依存する）。

#### Scenario: 日付付きのモデル名を引く
- **WHEN** モデル名が `claude-haiku-4-5-20251001` で、料金表に `claude-haiku-4-5` がある
- **THEN** `claude-haiku-4-5` の単価が使われる

#### Scenario: 接頭辞が重なる鍵がある
- **WHEN** モデル名が `claude-fable-5-1` で、料金表に `claude-fable-5` と `claude-fable-5-1` の両方がある
- **THEN** 表の並び順にかかわらず `claude-fable-5-1` の単価が使われる

### Requirement: トークン内訳からのコスト算出
システムは `message.model` で単価を選び、トークン 5 種（入力・出力・キャッシュ書込 5m・キャッシュ書込 1h・キャッシュ読出）にそれぞれの単価を掛けて合計 MUST する。

#### Scenario: キャッシュ読出が正しく安く計算される
- **WHEN** ある行のトークンの大半がキャッシュ読出である
- **THEN** その行のコストは同じトークン数を入力単価で計算した場合より小さい

#### Scenario: 手計算と同じ値になる
- **WHEN** トークン 5 種の数が分かっている行のコストを求める
- **THEN** 出力の金額は、5 種それぞれのトークン数に料金表の単価を掛けて足した値と一致する（丸め誤差を除く）

### Requirement: 未知モデルの扱い
料金表のどの鍵にも前方一致しないモデル名を**未知モデル**と SHALL する。システムは未知モデルのぶんを黙って 0 円として落としてはなら MUST NOT ない。未知モデルが存在したことを利用者に分かる形で示 SHALL す。

#### Scenario: 料金表に無いモデルが混ざる
- **WHEN** 会話ログに料金表のどの鍵にも前方一致しないモデル名の行が含まれている
- **THEN** 集計は中断せず、未知モデルの名前とその行数が出力に示される

### Requirement: 円換算は固定レート
システムは USD から円への換算に**固定レート**を用 MUST いる。実行のたびに外部から取得してはなら MUST NOT ない。日によって円の値が変わると、テストがネットワークに依存し、後続の台帳と PR への投稿が同じ数字を再現できなくなる。

レートは環境変数で上書きでき SHALL る。システムは出力に用いたレートを必ず添え MUST る。

#### Scenario: 同じログなら何度実行しても同じ円が出る
- **WHEN** 同じ会話ログに対して `/cost` を日を変えて 2 回実行する
- **THEN** 円の金額が両方で同じになる

#### Scenario: レートを環境変数で上書きする
- **WHEN** 換算レートの環境変数を設定して `/cost` を実行する
- **THEN** その値で円が計算され、出力に添えられるレートもその値になる

#### Scenario: 出力にレートが添えられる
- **WHEN** `/cost` が値を返す
- **THEN** 出力には用いた換算レートが示されている

### Requirement: 本体のコスト値と自前の計算をセッションの区間ごとに突き合わせる
システムは、コストを答えるとき（`cost_ledger.py` の `cost`・`branch`・`issue`）、答えに行が含まれるセッションのうち、`session-cost-record` の記録（`${CLAUDE_CONFIG_DIR:-$HOME/.claude}/.session-cost/<セッション ID>`）があるものについて、Claude Code 本体の値と自前の計算を突き合わせ SHALL る。

突き合わせる 2 つの値は次のとおりと MUST する。記録の 4 項目を、区間の最初の観測時刻 `t0`・最初の観測値 `v0`・最後に値が変わった観測時刻 `t1`・最後の観測値 `v1` と呼ぶ。

- 本体の値: `v1 − v0`（その区間で、観測を始めてから増えた分）
- 自前の計算: そのセッション ID を持つ行のうち、時刻が `t0 + 1` 秒以上 `t1 + 1` 秒未満のものを、料金表の単価で計算した合計

自前の計算には、そのセッション ID を持つ行を**ブランチやリポジトリで絞らずに**すべて含め MUST る。本体の値はセッション全体の値で、1 つのセッションがサブエージェントの worktree など別のブランチの行を持つためである。行の重複は `requestId` で排除 SHALL する。

`t1` が `t0` と同じ記録（観測が 1 回だけ）、形が `session-cost-record` の形式でない記録、読めない記録は、突き合わせの対象から外 SHALL す。そのために集計を中断したり、終了コードを変えたりしてはなら MUST NOT ない。

突き合わせは LLM を使わず、`gh` を呼ばず、ネットワークに出てはなら MUST NOT ない。

守備範囲: この要件が記録を対象に入れるか外すかを決めるときに受け取る入力は、同じ設定ディレクトリの下に statusline のスクリプトが書いた記録ファイルと、Claude Code 本体が書いた会話ログ（台帳を使うときは cost-ledger 自身がそこから写した台帳）の 2 つに限る。どちらも同じ利用者の同じマシンのファイルで、悪意のある第三者が作った入力は想定しない。拾いたい誤りは、書きかけ・別の形・読めない記録や、観測が 1 回だけで増分を持たない記録のせいで、コストの出力が止まる・変わる・誤った警告が出ることである。次の入力は誤ったまま通ることを許す: 5 項目の形は満たすが statusline が書かない組み合わせの記録（`t1` が `t0` より前、`v1` が `v0` より小さい、手で書き換えた値）は検査せずにそのまま計算し、誤った警告が出る、または出るべき警告が出ないことがある／時刻を読めない会話ログの行は区間の外として扱い、その分だけ自前の計算が小さくなる／記録が無いセッション（statusline を入れていない、入れ直していない、別のマシンで動いた）は比べず、そのセッションのずれには気づかない／描画と同じ秒に書かれた行は区間の内か外のどちらかに倒れ、応答 1 回分の差が出る。これらの穴を見つかるたびに塞ぎ切ることは、この要件の完了条件にしない。

#### Scenario: 別ブランチの行も自前の計算に入る
- **WHEN** あるセッションがブランチ `feat` の行 $1.00 と、別のブランチ `wt` の行 $2.00 を持ち、本体の値の増分が $3.00 の記録がある状態で、ブランチ `feat` のコストを求める
- **THEN** 1 行目の金額は `feat` の $1.00 のままで、ずれの警告は出ない

#### Scenario: 区間の外の行は比べない
- **WHEN** あるセッションに時刻 `t0` より前の行 $5.00 と、`t0 + 1` 秒以上 `t1 + 1` 秒未満の行 $2.00 があり、本体の値の増分が $2.00 である
- **THEN** ずれの警告は出ない

#### Scenario: 記録が無いセッションは比べない
- **WHEN** 答えに含まれるどのセッションにも記録が無い
- **THEN** ずれの警告は出ず、出力は記録の仕組みが無いときと同じである

#### Scenario: 壊れた記録で止まらない
- **WHEN** 答えに含まれるセッションの記録ファイルの中身が 5 項目の形でない
- **THEN** 終了コードは 0 で、コストの出力は記録が無いときと同じである

#### Scenario: 台帳から読むときも同じ結果になる
- **WHEN** 同じ会話ログと同じ記録に対して、`COST_LEDGER_PATH` を設定した場合と設定しない場合でコストを求める
- **THEN** ずれの警告の有無と中身が両方で同じである

### Requirement: ずれが閾値を超えたら警告する
システムは、突き合わせたセッションについて、本体の値と自前の計算の差の絶対値が次の**両方**を超えたとき、そのセッションを「ずれあり」と SHALL する。

- 差額: $0.50
- 割合: 本体の値と自前の計算のうち大きい方の 10%

「ずれあり」のセッションが 1 つ以上あるとき、システムは出力の 2 行目以降に警告を 1 行だけ出 MUST す。警告は `単価表のずれ:` という語を含み、突き合わせたセッションの数、「ずれあり」のセッションの数、差額が最大のセッションの ID・本体の値・自前の計算・差額・割合、閾値を示 SHALL す。「ずれあり」のセッションが複数あっても行を増やしてはなら MUST NOT ない（出力を読む側の量を増やさないため）。

「ずれあり」のセッションが無いとき、この警告を出してはなら MUST NOT ない。

閾値は実装の 1 か所にだけ置き、警告の文面はその値から作 SHALL る。

守備範囲: この判定が受け取る入力は、前の要件で対象に入ったセッションの本体の値の増分と自前の計算の 2 つの額に限る。拾いたい誤りは、料金表の単価が実際の単価から大きく離れていること（改定に追随していない単価、別のモデルの単価が前方一致で当たっている場合）である。次の入力は誤ったまま通ることを許す: 差額が $0.50 以下、または割合が 10% 以下のずれ（小さな改定、短いセッション）は「ずれあり」にならない／高すぎる単価と安すぎる単価が 1 つのセッションの中で打ち消し合うと「ずれあり」にならない／料金表が正しくても、料金表が表現していない課金（200K を超えるコンテキストの割増など）や会話ログに行が残らない呼び出しの額が閾値を超えると「ずれあり」になる／本体の値そのものが誤っていても、本体の値を正として比べる。これらの穴を見つかるたびに塞ぎ切ることは、この要件の完了条件にしない。

#### Scenario: 差が両方の閾値を超える
- **WHEN** あるセッションの本体の値の増分が $10.00、自前の計算が $6.00 である
- **THEN** 出力の 2 行目以降に `単価表のずれ:` を含む行が 1 行あり、そのセッションの ID、`$10.00`、`$6.00` が示される

#### Scenario: 差が閾値以内
- **WHEN** あるセッションの本体の値の増分が $10.00、自前の計算が $9.50 である（差額 $0.50、割合 5%）
- **THEN** `単価表のずれ:` を含む行は出ない

#### Scenario: 割合は超えるが差額が小さい
- **WHEN** あるセッションの本体の値の増分が $0.60、自前の計算が $0.30 である（割合 50%、差額 $0.30）
- **THEN** `単価表のずれ:` を含む行は出ない

#### Scenario: 差額は超えるが割合が小さい
- **WHEN** あるセッションの本体の値の増分が $100.00、自前の計算が $95.00 である（差額 $5.00、割合 5%）
- **THEN** `単価表のずれ:` を含む行は出ない

#### Scenario: 自前の計算の方が大きい
- **WHEN** あるセッションの本体の値の増分が $6.00、自前の計算が $10.00 である
- **THEN** `単価表のずれ:` を含む行が出る

#### Scenario: ずれありが複数でも 1 行
- **WHEN** 「ずれあり」のセッションが 3 つある
- **THEN** `単価表のずれ:` を含む行は 1 行で、「ずれあり」の数として 3 が示され、差額が最大のセッションの値が示される

### Requirement: 単価の無いモデルを含むセッションは差の大きさにかかわらず警告する
システムは、突き合わせたセッションの区間の中に、未知モデル（料金表のどの鍵にも前方一致しないモデル名）の行で、トークン 5 種のいずれかが 1 以上のものがあるとき、差が閾値以内でも警告を 1 行出 MUST す。警告は `単価表のずれ:` という語を含み、該当する未知モデルの名前、該当するセッションの数、それらのセッションの本体の値の合計と自前の計算の合計を示 SHALL す。

トークン 5 種がすべて 0 の未知モデルの行（会話ログに現れる `<synthetic>` のように API 呼び出しを伴わない行）だけでは、この警告を出してはなら MUST NOT ない。

この警告は、既存の「未知モデル: 名前 行数」の表示を置き換えるものではない。既存の表示はそのまま出 SHALL す。

守備範囲: この分類が受け取る入力は、対象に入ったセッションの区間の中にある会話ログの行のモデル名とトークン 5 種の数に限る。拾いたい誤りは、料金表に単価の無いモデルが使われ、その分が 0 円として落ちているのに、セッション全体の差が閾値以内に収まって気づけないことである。次の入力は誤ったまま通ることを許す: 料金表のどれかの鍵に前方一致する新しいモデルは、単価が違っていても未知モデルにならず、閾値の判定だけで拾う／トークンの数が実際と違う行（数が 0 と書かれているが課金された行、数が 1 以上と書かれているが課金されなかった行）は、書かれた数のとおりに分類する／記録が無いセッションや区間の外にある未知モデルの行は、この警告の対象にならない（既存の「未知モデル: 名前 行数」の表示には出る）。これらの穴を見つかるたびに塞ぎ切ることは、この要件の完了条件にしない。

#### Scenario: 単価の無いモデルの行が区間にある
- **WHEN** あるセッションの区間に、料金表に無いモデル `claude-future-9` のトークンを持つ行があり、本体の値の増分が $0.20、自前の計算が $0.05 である（差は閾値以内）
- **THEN** `単価表のずれ:` と `claude-future-9` を含む行が出る

#### Scenario: トークンの無い未知モデルの行だけでは警告しない
- **WHEN** あるセッションの区間に、モデル名が `<synthetic>` でトークンがすべて 0 の行があり、それ以外の行の自前の計算が本体の値の増分と一致する
- **THEN** `単価表のずれ:` を含む行は出ない

### Requirement: 突き合わせのための読み直しは上限の時間で打ち切り、打ち切ったことを知らせる
突き合わせのためだけに会話ログまたは台帳をもう一度読む処理（以下「読み直し」。答えをブランチで絞って読んだ経路で、対象のセッションの行をブランチで絞らずに集めるために行う）は、始めてからの経過時間が上限に達したら打ち切 MUST る。上限の既定は 1 秒とする（エピック #272 の「セッションを 1 秒以上止める処理」に当たらないようにするため）。

経過時間は、読み直しを始めた時点から、時計の修正に左右されない時計で測 SHALL る。上限に達したかどうかは、少なくとも、ファイルを 1 つ開く前ごとと、1 つのファイルの中で一定の行数を読むごとに確かめ SHALL る（台帳は 1 つの大きなファイルなので、ファイルの切れ目だけでは打ち切れない）。

打ち切ったとき、システムは次のとおりに振る舞 MUST う。

- どのセッションも「ずれあり」と判定せず、閾値超えの警告も、単価の無いモデルの警告も出さない（読み切っていない行の合計で比べると、単価表が正しくても差が出るため）
- 出力の 2 行目以降に、`単価表のずれ:` と `未確認` という語を含む行を 1 行だけ出す。この行は、突き合わせを途中で打ち切ったこと、対象だったセッションの数、上限の秒数、最後まで突き合わせる方法（下の環境変数）を示す
- 出力の 1 行目と終了コードは変えない

打ち切ったことを示さずに、ずれが無いときと同じ出力にしてはなら MUST NOT ない。

上限は環境変数 `COST_LEDGER_DRIFT_BUDGET_SECONDS` で変えられ SHALL る。値は 0 以上の秒数、または打ち切らないことを表す `inf` とする。`0` は、読み直しが要るときに 1 行も読まずに打ち切ることを表す。未設定、または数として読めない値・負の値のときは既定の 1 秒を使 SHALL う。

読み直しが要らないとき（対象のセッションが 1 つも無い、または `issue` の経路のように最初から全行を読んでいてその行を使う）は、上限は働かず、`未確認` の行も出してはなら MUST NOT ない。

守備範囲: この要件が受け取る入力は、利用者が自分で設定する環境変数 `COST_LEDGER_DRIFT_BUDGET_SECONDS` の値と、読み直しの経過時間の 2 つに限る。拾いたい誤りは、会話ログの多い環境で読み直しが `/cost` を 1 秒以上余計に止めることと、打ち切った結果が「ずれなし」に見えることである。次の入力は誤ったまま通ることを許す: 上限を確かめる間隔より長くかかる 1 回の読み込み（遅いディスクの 1 ファイル、1 行が極端に長いファイル）は、上限を超えてから打ち切る／利用者が大きな値や `inf` を設定したときは、設定どおり 1 秒以上止める／会話ログの多い環境で既定のまま使うと毎回打ち切られ、環境変数を設定して実行し直すまでずれに気づかない／読み直しの前に行う、答えそのもののための読み（この変更より前からある処理）の時間は上限に数えない。これらの穴を見つかるたびに塞ぎ切ることは、この要件の完了条件にしない。

#### Scenario: 上限に達したら未確認の行を出す
- **WHEN** 「ずれあり」になるはずのセッションがある状態で、`COST_LEDGER_DRIFT_BUDGET_SECONDS=0` を設定してブランチのコストを求める
- **THEN** 出力の 2 行目以降に `単価表のずれ:` と `未確認` を含む行が 1 行あり、それ以外に `単価表のずれ:` を含む行は無く、1 行目は記録を消した状態で求めたときと同じで、終了コードは 0 である

#### Scenario: 打ち切らない設定では最後まで突き合わせる
- **WHEN** 同じ状態で、`COST_LEDGER_DRIFT_BUDGET_SECONDS=inf` を設定してブランチのコストを求める
- **THEN** 閾値超えの警告の行が出て、`未確認` を含む行は出ない

#### Scenario: 台帳から読むときも打ち切る
- **WHEN** 同じ状態で、`COST_LEDGER_PATH` と `COST_LEDGER_DRIFT_BUDGET_SECONDS=0` を設定してブランチのコストを求める
- **THEN** 出力の 2 行目以降に `単価表のずれ:` と `未確認` を含む行が 1 行ある

#### Scenario: 読み直しが要らなければ未確認の行は出ない
- **WHEN** 答えに含まれるどのセッションにも記録が無い状態で、`COST_LEDGER_DRIFT_BUDGET_SECONDS=0` を設定してブランチのコストを求める
- **THEN** `単価表のずれ:` を含む行は出ない

#### Scenario: 読めない上限の値では既定を使う
- **WHEN** 「ずれあり」になるはずのセッションがある小さなテスト用データで、`COST_LEDGER_DRIFT_BUDGET_SECONDS=abc` を設定してブランチのコストを求める
- **THEN** 閾値超えの警告の行が出て、終了コードは 0 である

### Requirement: 警告は 1 行目と終了コードを変えず、省くこともできる
ずれの警告は、出力の 1 行目（帰属先ごとの固定書式の行）を変えてはなら MUST NOT ない。警告の有無で終了コードを変えてはなら MUST NOT ない。

`issue` の経路を JSON で出すとき、システムは突き合わせの結果を `price_drift` という鍵に入 SHALL れる。警告が無ければ値は `null` とする。

`cost` サブコマンドは、突き合わせそのものを行わない引数 `--no-drift-check` を受け付け SHALL る。pr-review-gate 通過時に PR へコストを貼る hook は、この引数を付けて `cost` を呼ば MUST なければならない（hook は 1 行目しか使わず、突き合わせのための読み直しは所要時間を増やすだけなので）。

#### Scenario: 警告があっても 1 行目は同じ
- **WHEN** 「ずれあり」のセッションがある状態と、同じ会話ログで記録を消した状態でコストを求める
- **THEN** 両方の出力の 1 行目は同じで、終了コードはどちらも 0 である

#### Scenario: 突き合わせを省く
- **WHEN** 「ずれあり」のセッションがある状態で、`cost` を `--no-drift-check` 付きで実行する
- **THEN** `単価表のずれ:` を含む行は出ず、1 行目は引数を付けないときと同じである

#### Scenario: ゲート連携の hook は突き合わせを省いて呼ぶ
- **WHEN** 合格ラベルの付与を捕まえた hook が `cost_ledger.py` を呼ぶ
- **THEN** その呼び出しの引数に `--no-drift-check` が含まれている

#### Scenario: JSON の出力に結果が入る
- **WHEN** 「ずれあり」のセッションがある状態で、`issue` の経路を JSON で出す
- **THEN** 出力は有効な JSON で、`price_drift` に突き合わせたセッションの数と「ずれあり」のセッションの数が入っている
