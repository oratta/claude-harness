## ADDED Requirements

### Requirement: 親は主の答えに発言の場所を添えて送り、子は親の会話ログで確かめてからリスク許容として受け取る

develop の SKILL.md は、Orca 経路のエピックで主が親のセッションに書いたリスク許容を、子のゲートが主本人の返事として受け取れるよう、次の 3 か所を規定しなければならない（MUST）。この要件のために、3 か所以外の SKILL.md の節と `scripts/epic-dispatch.sh` を変えてはならない（MUST NOT。エピック #1038 の並行する子の範囲）。

**Orca 経路の手順 8（親の送り方）**: 親は主の答えを `scripts/epic-dispatch.sh reply --as owner` で送る前に、`owner-reply-check.sh --locate "$CLAUDE_CODE_SESSION_ID" <主の答え>` を回し、`MATCH:` のうち全文が主の答えと同じで timestamp がいちばん新しい行の uuid を取り、主の答えの末尾に ` [主の発言: セッション <親のセッション ID> / uuid <uuid>]` を添えて渡さなければならない（MUST）。主の答えそのものは書き換えない（MUST NOT）。終了コードが 0 でない、または該当する行が無いときは添え書きを付けずに送り、主に「子のゲートは親経由の許容を確かめられないので、リスク許容なら子のタブで打ってほしい」と伝えなければならない（MUST）。

**「エピックの子が主の返事を待って止まるとき」の「親から届いた返事」（子の受け取り方）**: 子は、`主の返事（親エピック #<E> 経由）:` で始まる入力が止まった件のリスク許容への返事で、末尾に `[主の発言: セッション <ID> / uuid <uuid>]` があるとき、記録先の最新の `子の停止: 主の返事待ち` のコメント（投稿者の `author_association` が `OWNER`・`MEMBER`・`COLLABORATOR` のもの）の作成日時と URL で `owner-reply-check.sh --relayed <ID> <uuid> <作成日時> <URL>` を回さなければならない（MUST）。exit 0 で、`MATCH:` の全文から許容の意思が読め、全文が別の子・別の PR・別のリスクを名指ししていないときだけ、保留の解除の G に、親のセッション ID・uuid・`MATCH:` の timestamp・停止の記録の URL・`MATCH:` の全文を渡さなければならない（MUST。記録の書式と真正性確認は pr-review-gate 手順 5 の「親経由で受領」が正本で、SKILL.md に書式を再掲しない）。添え書きが無い・`--relayed` が exit 0 でない・全文から許容と読めないときは、主本人の返事として扱ってはならず（MUST NOT）、G を起こさずに、主に子のタブで直接返事を打ってもらうよう頼み（止まる前の記録と印は同じ節の手順どおり）、頼む文に確かめられなかった理由（`REASON=` の値か「添え書きが無い」）を添えなければならない（MUST）。リスク許容以外の返事（動作確認の結果・切り出しの確認への回答など）の受け取り方は変えない。

**保留の行の「リスク許容を会話で受けたら」の文**: エピックの子が親経由で許容を受けたときは、自分のセッション ID ではなく、上の「親から届いた返事」の手順で確かめてから G に渡すことを、参照で書かなければならない（MUST）。

この要件の守備範囲で入力として扱うのは、親の会話の主の答え、子に届いた入力の頭と末尾の添え書き、子の記録先の停止の記録のコメント、同じ PC の親の会話ログである。拾いたい誤りは、親の打ち込みや確かめられない親経由の返事を主のリスク許容として G に渡すこと、別の止まり・別の子への主の答えを流用すること、親が場所を添えずに送ったときに主に子のタブでの返事を頼まないこと、の 3 つである。次は通ってよく、この要件では止めない: 親が報告した 2 件の止まりにまとめて答えた名指しの無い「許容」（両方の子で受け取る）、親の報告と主の答えのあいだに親の会話の圧縮が挟まったもの。会話ログの改変と、頭の無い自由な文での親の打ち込みを見破ること、偽造の経路を見つけるたびに塞ぎ切ることは、この要件の完了条件としない。

#### Scenario: 親の送り方が手順 8 に書かれている

- **WHEN** SKILL.md の Orca 経路の手順 8 を読む
- **THEN** `owner-reply-check.sh --locate` で主の発言の uuid を引くこと、`[主の発言: セッション <親のセッション ID> / uuid <uuid>]` を主の答えの末尾に添えて `reply --as owner` に渡すこと、引けないときは添え書きを付けずに送り主に子のタブでの返事を頼むことが書かれている

#### Scenario: 子の受け取り方が「親から届いた返事」に書かれている

- **WHEN** SKILL.md の「エピックの子が主の返事を待って止まるとき」の「親から届いた返事」を読む
- **THEN** 添え書きのある親経由のリスク許容を、最新の停止の記録の作成日時と URL で `owner-reply-check.sh --relayed` に掛け、exit 0 で全文から許容と読めるときだけ G に渡すこと、そうでなければ主に子のタブでの返事を理由付きで頼むこと、書式の正本が pr-review-gate 手順 5 の「親経由で受領」であることが書かれている

#### Scenario: 確かめられない親経由の許容では G を起こさない

- **WHEN** 子に `主の返事（親エピック #1038 経由）: 許容 [主の発言: セッション <ID> / uuid <uuid>]` が届き、`--relayed` が `REASON=not-after` で exit 1 を返す
- **THEN** 子は保留の解除の G を起こさず、主に子のタブでの返事を、止まる前の記録と印を残してから頼む

#### Scenario: 保留の行が親経由の受け取り方を指している

- **WHEN** SKILL.md の保留の行の「リスク許容を会話で受けたら」の文を読む
- **THEN** エピックの子が親経由で受けたときは「親から届いた返事」の手順に従うことが書かれている
