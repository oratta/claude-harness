## ADDED Requirements

### Requirement: 合格条件はエピックの親経由で受けた許容を、親の会話ログで確かめて受け付ける

`skills/pr-review-gate/stages/pass.md` の手順 5 は、主の許容の回答の形として、回答リンクと `会話で受領` に加えて、エピックの親経由で受けた回答（`親経由で受領`）を持たなければならない（SHALL）。この形は、develop の本体（エピックの子）が `owner-reply-check.sh --relayed` の exit 0 を確かめてから渡した値で、手順 3 の宣言コメントに次の 1 行で追記しなければならない（MUST）:

```
主の回答: 許容 — 親経由で受領（親セッション <セッション ID> / 発言 <uuid> / <日時>）停止の記録: <URL> 原文: <原文>
```

`<日時>` は `--relayed` の `MATCH:` 行の timestamp、`<原文>` はその行の全文とする（MUST）。

真正性確認で G は次をすべて確かめなければならない（MUST）。①停止の記録の URL のコメントを `gh api` で読み、1 行目が `子の停止: 主の返事待ち`、投稿者の `author_association` が `OWNER`・`MEMBER`・`COLLABORATOR` のどれか、コメントの issue がこの PR の記録先であること。②記録のセッション ID・uuid と、①で読んだ作成日時・URL で `owner-reply-check.sh --relayed` を回し、exit 0 で、`MATCH:` の timestamp が記録の日時と同じであること。③`MATCH:` の全文から許容の意思が読め、全文が別の PR・別の記録先・別の子・別のリスクを名指ししていないこと（記録の原文だけで読まない）。④その timestamp が記録を追記する宣言コメントの作成日時より後であること。通したら `真正性確認: 済 — 確認者 <エージェント名> / <日時>（owner-reply-check.sh --relayed 終了コード 0）` を追記しなければならない（SHALL）。どれかを満たさないときは合格させてはならず（MUST NOT）、手順 6 に戻して、主に子のタブで直接返事を打ってもらうよう頼まなければならない（MUST）。

手順 5 の合格条件の表はこの形を許容済みとして扱わなければならない（SHALL）。`stages/hold.md` の手順 6 の復帰手順（リスク許容待ちの行）は、親経由で受けた回答のときにこの記録を追記してから手順 5 の真正性確認に進むことを書かなければならない（MUST）。手順 3-c の引き継ぎは、元の直接の回答が `親経由で受領` の記録でもよく、そのときは元の記録の値で①〜③を確かめ直し、引き継ぎの 1 行目の回答の部分を元の記録の `親経由で受領（…）停止の記録: <URL> 原文: <原文>` に置き換えなければならない（MUST）。行頭は `主の回答: 許容` のままにする（MUST。3-c の「前の宣言の選び方」がこの記録を主の直接の回答として拾うため）。

手順 5 の「会話で受領」の守備範囲の文は、Orca の親セッションが決まった頭（`主の返事（親エピック #` / `親エピック #`）を付けて子のターミナルに打ち込んだ文は `owner-reply-check.sh` が主の発言として数えないこと、頭の無い自由な文は今までどおり区別できないことに書き直さなければならない（MUST）。

守備範囲: ①入力の出どころは、develop の本体（エピックの子）が渡した値と、G が `gh api` で読む停止の記録のコメントと、ゲートが動いている PC の親のセッションの会話ログである。本体と G は協力的だが、写し間違い・別の止まりの記録との取り違えをする前提で扱う ②拾いたい誤りは、主の入力でない行を指した記録、止まる前の主の発言を指した記録、親がこの止まりを主に報告していないのに送られた記録、別の子・別の PR を名指しした主の答えを流用した記録、他人が投稿した停止の記録や別の記録先の停止の記録を根拠にした記録で合格させること ③通ることを許す入力は、名指しの無い「許容」（親がこの止まりを報告したあとの答えなら、まとめて報告された別の子と区別しない）、親の報告と主の答えのあいだに会話の圧縮が挟まったもの。会話ログの改変・追記は検知しない。親の会話ログを読めない PC では exit 2 で合格させず、主に子のタブで打ってもらう ④ここに挙げた以外の偽造の経路を見つけるたびに検査を足し、穴を塞ぎ切ることをこの要件の完了条件にしない（MUST NOT）。

#### Scenario: 記録の書式と確かめ方が書かれている

- **WHEN** `grep -n "親経由で受領" plugins/dev-workflow/skills/pr-review-gate/stages/pass.md` を実行する
- **THEN** 1 行以上が出て、手順 5 に記録の書式（親セッション・発言の uuid・日時・停止の記録・原文）と、停止の記録のコメントの確かめ方と、`owner-reply-check.sh --relayed` の終了コード 0 を真正性確認とする旨がある

#### Scenario: 合格条件の表と復帰手順と引き継ぎに入っている

- **WHEN** 手順 5 の合格条件の表、`stages/hold.md` の手順 6 の復帰手順のリスク許容待ちの行、手順 3-c を読む
- **THEN** どれにも `親経由で受領` の形の扱いが書かれている

#### Scenario: スクリプトが通さなければ合格させない

- **WHEN** `owner-reply-check.sh --relayed` が exit 1（`not-found`・`not-owner`・`not-after`・`not-asked`）か exit 2 を返す
- **THEN** G は合格処理をせず、手順 6 で主に子のタブでの返事を頼む

#### Scenario: 別の子を名指しした答えでは合格させない

- **WHEN** `--relayed` は exit 0 だが、`MATCH:` の全文が `1034は許容` で、この PR の記録先が #1030
- **THEN** G は合格処理をせず、主に再確認する

#### Scenario: 他人の停止の記録や別の記録先の停止の記録では合格させない

- **WHEN** 記録の停止の記録の URL が、`author_association` が `OWNER`・`MEMBER`・`COLLABORATOR` のどれでもない投稿者のコメント、またはこの PR の記録先でない issue のコメントを指す
- **THEN** G は合格処理をしない
