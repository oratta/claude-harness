## Context

`plugins/dev-workflow/scripts/git-destructive-guard.sh` は PreToolUse（Bash）で破壊的 git 操作を見つけると、`permission_mode` が `default` / `acceptEdits` / `plan` / `bypassPermissions` なら `ask`、それ以外は `deny` を返す（`DEV_WORKFLOW_GIT_GUARD_FORCE=ask|deny` で上書きできる）。子（サブエージェント）から呼ばれたときも同じ規則で `ask` になり、主の確認画面が出る。親はその画面に応答できず、子が止まっていることも分からない（issue #1108 の発端）。

hook の payload には、子から呼ばれたとき `agent_id` が入る。`plugins/dev-workflow/scripts/context-tripwire.sh` がすでにこれを使い、空でない文字列かどうかで子を見分けている。

## Goals / Non-Goals

**Goals:**

- 子が破壊的 git 操作を打ったとき、確認画面で止まらず、その場で拒否されて親に返る
- 拒否された子が打ち直しや言い換えを繰り返さない（2 回目以降は打ち切るか、より強く返すよう指示する）
- 子が scratchpad の検証用 repo を戻したいだけのときは、git の破壊的操作を使わず作り直すよう、拒否理由とエージェント定義の両方で案内する

**Non-Goals:**

- 主の対話（`agent_id` が無い呼び出し）の振る舞いを変えること
- scratchpad 内の repo への破壊的操作を許可すること（下の「採らない案」）
- 子が親に返ったあと、親がどう主に上げるかを決めること（親の指示書と既存の規則に任せる）

## Decisions

### 子の判定は `agent_id` が空でない文字列かどうかで行い、`permission_mode` と `DEV_WORKFLOW_GIT_GUARD_FORCE` より先に見る

`context-tripwire.sh` と同じく `payload.get("agent_id")` が空でない文字列なら子とする。子と判定したら、`permission_mode` も `DEV_WORKFLOW_GIT_GUARD_FORCE` も見ずに `deny` にする。

- `FORCE` より先に置く理由: `FORCE=ask` は実機確認のための上書きで、それが残ったセッションで子が起きると、今回と同じく子が確認画面で止まる。子には `ask` を返す場面が無いので、上書きを効かせる必要が無い
- `DEV_WORKFLOW_GIT_GUARD=off` は子でも全許可のまま（無人運用の逃げ道。シェル側で python3 より前に抜ける今の形を変えない）
- `agent_id` が無い・文字列でない・空のときは主の呼び出しとして今までどおり扱う。Claude Code の版によって子の payload に `agent_id` が入らない場合は今の振る舞い（`ask`）に戻るだけで、今より悪くならない

### 拒否した回数は一時ディレクトリに `agent_id` ごとのファイルで数える

置き場所は環境変数 `TMPDIR`（未設定か空なら `/tmp`）の下の `dev-workflow-git-guard/` で、ファイル名は `session_id` と `agent_id` を NUL でつないだ文字列の sha256 の 16 進。中身は拒否した回数の整数。子の拒否を返すたびに、読んで 1 足して書く。

- `tempfile.gettempdir()` を使わない理由: 書き込めない `TMPDIR` を黙って飛ばして別の候補（`/tmp` など）に書くので、bats で「数えられないときも拒否する」を確かめられず、テストの隔離も崩れる
- ハッシュにする理由: `agent_id` や `session_id` をそのままパスに使うと、区切り文字や `..` の検査が要る。ハッシュなら常に 1 段のファイル名になる
- `session_id` を混ぜる理由: 別のセッションで `agent_id` が重なっても数が混ざらない（`session_id` が無ければ空文字として扱う）
- 新しい環境変数は足さない。bats は `TMPDIR` をテストごとの一時ディレクトリに向ければ隔離できる
- ディレクトリやファイルを作れない・読めない・中身が整数でないときは、その呼び出しを 1 回目として扱う（拒否は必ず返す。数えられないことで通してはならない）
- 消さない。ファイルは数バイトで、一時ディレクトリは OS が片付ける
- SendMessage で再開された子は同じ `agent_id` を持つので、回数は再開をまたいで続く。一度拒否された子は、再開後の最初の破壊的操作で 2 回目として扱われる。拒否されたら親に返す指示を受けたうえで再び打っているので、繰り返しとして扱ってよいと判断した

### 2 回目以降の拒否: 強い理由文は常に足し、`continue: false` は実機確認の結果で決める

2 回目以降の拒否では、どちらの場合も理由文に「直ちに作業を終えて親に返す」を足す。そのうえで:

- 実機で、子の中で `continue: false` を返すと**子だけが終わり、親は子の結果を受け取って続ける**と確かめた場合: 出力のトップレベルに `"continue": false` と `stopReason`（理由文と同じ趣旨の短い文）を足す
- 実機で**親まで止まる**と分かった場合、または確かめられなかった場合: `continue: false` を返さない（強い理由文だけ）。親まで止まると、今回直したい「ワークフロー全体が止まる」がそのまま起きるため、分からないときも返さない側に倒す

実機確認の方法（実装段で行い、結果をこの design.md の末尾と PR に記録する）: `claude -p --plugin-dir <worktree>` で親を起こし、親に `general-purpose` の子を 1 つ起こさせる。子には scratchpad に作った使い捨て repo で `git checkout -- <file>` を打たせ、拒否されても実験のため別のファイルでもう一度打つよう指示する。親には、子が返ったあとに決まった目印の行（例 `PARENT-CONTINUED`）を出力させる。`continue: false` を返す版の hook で、出力に目印が出れば「子だけが終わる」、出なければ「親まで止まる」とする。1 回目の拒否で子が確認画面で止まらず、打ち直さずに親に返ることも同じ方法で確かめる（このときは打ち直しを指示しない）。

### 子への理由文は主向けの文面と分ける

子への `permissionDecisionReason` は、主向けと同じ前半（当たった操作の種類と `rules/destructive-git-guard.md`）に、子向けの後半を続ける: 実行されない／打ち直さず、別の書き方も試さない／scratchpad の検証用 repo なら git で戻さず作り直す／それ以外は作業を止め、何を・なぜ実行したかったかを報告に書いて親に返す。主向けの後半（確認画面を出している、`!` を付けて主が打つ）は子には書かない。子は主に直接は聞けず、主に上げるのは親の役目なので、子に主への承認の取り方を案内すると、子が自分で主に聞こうとして止まる余地が残る。判定しきれなかった入れ子（`kinds is None`）の場合も、前半はその文面のまま、後半は子向けにする。

### エージェント定義と規則に検証用 repo の戻し方を書く

reviewer / worker / gate-runner の定義の本文に「scratchpad の検証用 repo は git の破壊的操作で戻さず、作り直す」を 1 文足す。拒否されてから知るより、打つ前に知っているほうが拒否の回数が減る。decider は `Bash` を持たないので足さない。`rules/destructive-git-guard.md` の「hook との分担」節には、子から呼ばれたときは確認画面を出さずに拒否され、子は作業を止めて親に返ることを足す（常時注入なので 1 文に収める）。

### 採らない案: scratchpad 内の repo なら許可する

コマンドの中で `S=...` と変数を作ってから `git -C $S/h ...` と使う形が普通にあり、hook は変数を展開できないので、行き先が scratchpad かを判定できない。判定できない入力を通すと、主の作業ツリーへの破壊的操作も同じ書き方で通ってしまう。

## Risks / Trade-offs

- 子が本当に破壊的操作を必要とする場面（主が子に `git branch -D` を任せた、など）でも子では実行できず、親か主が打つことになる。今も確認画面で止まって進まないので、実行できないこと自体は変わらず、止まらずに返る分だけ良くなる
- 同じ子が並列の Bash 呼び出しで同時に拒否されると、回数の読み書きが重なって 2 回とも 1 回目と数えることがある。起きても打ち切りが 1 回遅れるだけで、拒否は返る
- 再開をまたいで回数が続くので、前の工程で 1 回拒否された子は、次の工程で 1 回目の破壊的操作から打ち切られる（上の判断）。打ち切られても子は親に返るだけで、作業は親が引き継げる
