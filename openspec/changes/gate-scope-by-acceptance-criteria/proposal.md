# Proposal

## Why

pr-review-gate の振り分けは「今回触ったファイルの中で直せるなら直す」（段 A）と「受け入れ条件の外でも 30 行以内なら直す」（順 4）で動いていて、issue の完了に要るかを問うていない。そのため提案程度の指摘でも小さければ PR に取り込まれ、小さな issue が膨らんで時間とトークンを余計に使っている（#1389）。

## What Changes

- 止めない指摘の振り分け表の段 A を「直さないと受け入れ条件を満たせないか、または例外 3 種（安全機構の穴・データ破壊・無言の機能不全）に当たるか」に変える。どちらでもない指摘は、触ったファイルの中でも、行数が小さくても今の PR で直さず、段 B 以降に回す
- 受け入れ条件が求めていない新しい部品・機能を足す提案は、行数によらず範囲外とする
- 止める指摘の仕分け表の順 4 に当てられるのを、根拠が例外 3 種の指摘に限る。例外 3 種でない止める指摘は小さくても順 4 に当てない
- レビュアーへの依頼に受け入れ条件の全文を入れ、指摘ごとに `受け入れ条件の要否` の印（`要る: <ID>` / `要らない`）を付けさせる。印は参考で、判定の根拠は G の照合のままにする
- 段 A と順 4 に当てた指摘の記録に、要る受け入れ条件の ID か、当たる例外 3 種のどれかを足す

変えないもの: レビュアーが見る範囲、マージを止めるかの判定（全周共通）、段 B 以降の流れ、周の歯止め。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `dev-workflow-pr-review-gate`: 段 A の定義、順 4 の当て先、レビュアーの固定書式と依頼文の中身、振り分けの記録を変える
