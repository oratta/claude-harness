## Context

cost-ledger は会話ログのトークン数に `plugins/cost-ledger/pricing.json` の単価を掛けてコストを出す。単価は手で書いているので、新しいモデルが出てから追記するまでそのモデルの分は 0 円になり、単価の改定にも追随しない。エピック #272 はこれを「主が飲んだリスク」として記録している。この change は、そのずれに気づけるようにする（issue #692、エピック #272 の子）。

比べる相手は Claude Code 本体が計算したセッションのコストで、statusline の入力の `cost.total_cost_usd` に入っている。`plugins/statusline/scripts/statusline.sh` は既にこの値を読んで表示している（42 行目で取り出し、861〜878 行目で表示）が、どこにも残していない。

守る制約（エピック #272 の「全体の制約」）:

- LLM のトークンを使わない。書き残す・数える・比べるのはスクリプトで行い、スキル本文やコマンド本文に LLM に実行させる手順を足さない。hook は会話の文脈に何も入れない
- 待ち時間を増やさない。statusline は描画のたびに走るので、足す前後の描画時間を測って PR に書く
- `gh` の呼び出し回数を測って PR に書く
- 常時注入される文面（`rules/`・`CLAUDE.md`・各種 `description`）を増やさない

仕様づくりの時点で実物から確かめたこと（2026-10-06、この worktree を置いている Mac）:

| 確かめたこと | 結果 |
|---|---|
| 台帳を使わない `cost_ledger.py branch <ブランチ>` の所要時間 | 23.6 秒（会話ログのディレクトリ 581 個。1 回の実測） |
| 台帳ファイルの大きさ | 約 67 MB |
| 同じ `requestId` を持つ複数行のトークン数 | 1 つの会話ログ（94 リクエスト、うち 47 が複数行）で、同じリクエストの行はすべて同じ値。最初の行を採る既存の重複排除で出力トークンが欠けることはない |
| statusline の利用者への届き方 | `/statusline:setup` が `scripts/statusline.sh` を `~/.claude/` にコピーする。プラグインを更新しただけでは新しいスクリプトは動かない |
| pr-review-gate 通過時の hook が呼ぶもの | `gate-report.sh` の 401 行目が `cost_ledger.py cost <番号>` を呼び、1 行目だけを使う。hook の timeout は 60 秒 |

## Goals / Non-Goals

**Goals:**

- 本体のコスト値を、statusline がセッションごとに書き残す
- `/cost` が、答えに含まれるセッションについて本体の値と自前の計算を比べ、ずれていれば警告行を出す
- 単価の無いモデルを含むセッションは、差が小さくても警告する
- ずれが無いときの追加コストを 0 に近づける（描画時間・`/cost` の所要時間・出力の行数）

**Non-Goals:**

- 単価表を自動で直すこと。警告を見て `pricing.json` を直すのは人
- ずれの原因を診断すること（どのモデルのどの単価が違うか）。警告は 2 つの値と差を示すだけ
- statusline の表示に印を出すこと（下の「知らせ方」の決定を参照）
- pr-review-gate 通過時に PR へ貼るコメントに警告を載せること（貼るのは 1 行目だけ、という子 #276 の決定を変えない）
- `report` と `intervals` のサブコマンドでの突き合わせ（`/cost` から届く `cost`・`branch`・`issue` だけ）
- 200K を超えるコンテキストの割増など、単価表の表現力を上げること（エピックが飲んだリスクのまま）
- 他の子 issue の範囲: 台帳を動かし始める設定（#688）、節目ごとの行（#303）、issue を閉じたときの合計（#689）、エピックの内訳（#690）、auto-merge 後の後追いの行（#691）

## Decisions

### 記録は 1 セッション 1 ファイル・1 行で、区間の最初と最後の観測だけを持つ

記録の形は `1 <t0> <v0> <t1> <v1>`（版、区間の最初の観測時刻と観測値、最後に値が変わった観測時刻と観測値）。statusline は値が増えたら `t1`・`v1` だけを差し替え、値が下がったら 4 項目とも今の値で始め直す。

読み手は**増分** `v1 − v0` を、時刻が `[t0 + 1, t1 + 1)` の行の自前の計算と比べる。増分で比べる理由は 2 つある。

- `/clear` で本体の値が 0 に戻る場合も、セッションの途中から記録が始まる場合（statusline のスクリプトを入れ替えた直後）も、同じ規則で扱える。「観測を始めた時点の値」を引くので、観測より前の行を数える必要が無い
- `/clear` のときにセッション ID が変わるかどうかに依存しない。変われば別のファイルになり、変わらなければ「値が下がった」で区間が始め直される。`--resume` で本体の値が戻るかどうかも同じ理由で問わない

区間の端を 1 秒ずらす（`t0 + 1` 以上、`t1 + 1` 未満）のは、記録の時刻が秒に切り捨てた整数で、会話ログの時刻がミリ秒まであるため。本体の値に入った行は描画より前に書かれているので、描画と同じ秒の行は「最後の観測に入っている」側に倒す。区間の最初も同じ向きに倒す。

**検討した別案**:

- 値が変わるたびに 1 行ずつ追記する（観測の時系列を残す）: 値が下がった位置を読み手が見つけられるが、長いセッションでは数千行になり、要るのは最後の区間の両端だけ。採らない
- セッションごとではなく全セッションを 1 ファイルに追記する: 複数セッションが同時に書くので排他が要る。statusline に排他を持ち込まない
- 閉じた区間（`/clear` より前）も残して比べる: 単価表が古いかどうかは最後の区間だけで分かる。記録を 1 行に保つ方を採る

### 記録の場所は設定ディレクトリの下で、ファイル名はセッション ID そのもの

場所は `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/.session-cost/<session_id>`。会話ログのルート（`cost_ledger.py` の `log_root()`）と同じ設定ディレクトリから決まるので、アカウントごとに設定ディレクトリを分けていても、読み手は自分が読む会話ログと同じアカウントの記録を見る。テストは既に `CLAUDE_CONFIG_DIR` を一時ディレクトリに向けているので、場所を上書きする環境変数は足さない。

ファイル名をセッション ID そのものにするのは、読み手が「このセッションに記録があるか」をファイルの有無だけで判定できるようにするため（既存のセッション記録の覚えのように sha256 を取ると、statusline 側で `shasum` の起動が、読み手側で同じ導出の再実装が要る）。セッション ID をパスに使うので、半角英数字・`_`・`-` の 1〜128 文字に限り、それ以外は書かない。

### statusline の書き込みは「値が変わった描画」でだけ外部コマンドを起動する

描画のたびに行うのは、記録ファイルを bash の組み込みの `read` で 1 回読み、最後の観測値と今の値を**文字列で**比べることだけ。同じなら何も起動せず抜ける。違うときだけ、数値の大小比較（bash は小数を比べられないので `awk` を 1 回）と、一時ファイルへの書き込み＋`mv`（既存のセッション記録と同じ形）を行う。値が変わるのはアシスタントの応答 1 回につき 1 度なので、モード切り替えなど応答を伴わない描き直しでは外部コマンドが増えない。

時刻は既にスクリプトが持っている `now`（356 行目の `date +%s`）を使い、`date` の起動を増やさない。そのため書き込みの処理は 356 行目より後ろ、セッションコストの表示の近く（861 行目以降）に置く。

400 日より古い記録の削除（`find -mtime +400 -delete`）は、新しい記録ファイルを作る描画（1 セッションに 1 回）でだけ走らせる。400 日は、会話ログの保持期間を 365 日にする運用（#688）より長く残すための値。記録は 1 ファイル 100 バイト未満。

**検討した別案**: 一時ファイルを使わず `printf > ファイル` で直接上書きする（外部コマンド 0 個）。書きかけを読み手が読む可能性が残り、既存のセッション記録の書き方（一時ファイル＋`mv`）とも揃わない。値が変わった描画でだけ走る処理なので、`mktemp` と `mv` の起動は受け入れる。前後の描画時間は実測して PR に書く。

### 突き合わせの対象は「その答えに含まれるセッション」で、そのセッションの行は読み直して集める

`/cost` がブランチで絞って読んだ行には、同じセッションの別ブランチの行（サブエージェントが別の worktree で動いた分）が入っていない。本体の値はセッション全体なので、突き合わせには絞らない行が要る。そこで、対象のセッション（答えに含まれ、かつ記録ファイルがあるもの）が 1 つでもあるときだけ、そのセッション ID の行を読み直す。

読み直しを軽くする工夫:

- 台帳を使うとき: 台帳 1 ファイルを、JSON にパースする前の生の行にセッション ID が含まれるかで絞って読む。`ledger_sync` はやり直さない（最初の読みで済んでいる）
- 台帳を使わないとき: 更新時刻が、対象の記録の `t0` のうち最も古いものより前の会話ログは開かない（そのセッションの区間の行は `t0` より後に書かれるので、それより前に更新が止まったファイルには無い）。開いたファイルは同じく生の行で絞る
- 記録が 1 つも無ければ読み直さない。statusline を入れていない利用者の `/cost` は今と同じ速さのまま

`issue` の経路は最初から全行を読んでいるので、読み直さずにその行を使ってよい。

**検討した別案**:

- 最初の 1 回の読みで、記録のある全セッションの行も一緒に集める: 記録は増え続けるので、いずれほぼ全行をパースすることになり、ブランチ名で先に弾く既存の速さを失う
- 突き合わせ専用のサブコマンドを足し、`/cost` には出さない: 手で叩かないと気づけないので「知らせる」にならない
- 応答の終わりごとに `Stop` hook で今のセッションを突き合わせ、結果をファイルに置く: 応答のたびに計算が走り、結果を見せる先（statusline の印）も別に要る。下の「知らせ方」で採らなかった

### 閾値は「差額 $0.50 超 かつ 大きい方の額の 10% 超」

閾値は `cost_ledger.py` の定数 2 つに置く（`pricing.json` は単価と換算レートの置き場所で、閾値はどちらでもないので入れない）。

10% にした根拠は、単価表が古いときに起きるずれが 10% よりずっと大きいこと。

| 単価表が古い例 | そのモデルの分のずれ |
|---|---|
| 単価の無いモデル（0 円として落ちる） | 100% |
| `pricing.json` の `claude-opus-5` → `claude-opus-5-5` 相当の改定（入力 $5 → $4） | 20% |
| 同じ 2 モデルのキャッシュ読出（$0.5 → $0.2） | 60% |
| `claude-sonnet-4-6` → `claude-sonnet-5` 相当の改定（入力 $3 → $2） | 33% |

一方、単価表が正しくても起きる差は小さい: 描画と同じ秒に書かれた行が 1 つ区間の内か外に倒れること、会話ログに行が残らない補助的な呼び出し（タイトル生成など）があること。これらを 10% で吸収する。

差額 $0.50 を併せて求めるのは、短いセッションでは応答 1 回分のずれが割合では大きくなるため。$0.50 未満の差は直しても額に効かない。単価の無いモデルは別の規則で必ず警告するので、短いセッションでも見落とさない。

割合の分母を「大きい方の額」にするのは、本体の値が 0 に近いときに割り算が壊れないようにするためと、自前の計算が大きい向き（値下げに追随していない）も同じ基準で拾うため。

**この閾値が実機で通用するかは、この change の中で確かめる**（tasks の実機の測定）。単価表が正しいはずのセッションで差が閾値を超えたら、閾値を手元で動かさずに、測った値と考えられる原因を添えて止める（閾値は仕様の決定なので）。

**検討した別案**:

- 割合だけ（10%）: $0.10 のセッションで応答 1 回分がずれただけで警告が出る
- 差額だけ（$0.50）: $200 のセッションの 0.3% のずれで警告が出る
- 5%: 単価表が正しくても起きる差の大きさをまだ実測していないので、狭い側に倒す根拠が無い

### 知らせ方は `/cost` の出力の 2 行目以降に警告行を出す。statusline に印は出さない

ずれがあるときだけ、`/cost` の出力の内訳のうしろに `単価表のずれ:` で始まる行を出す（閾値超えで 1 行、単価の無いモデルで 1 行）。ずれが無ければ何も出さない。1 行目は `headline()` が作る行のままで、pr-review-gate 通過時に PR へ貼るコメントには載らない。

理由:

- ずれた数字を見ているその場で知らせられる。警告は「いま見ているこの金額がずれているかもしれない」という意味を持つ
- ずれが無いときの追加は 0 行。ずれがあるときも最大 2 行で、`/cost` を叩いたときにしか文脈に入らない
- 追加する仕組みが「記録を書く」と「比べて出す」の 2 つで済む

**検討した別案**: statusline に印を出す。常に目に入るが、statusline は単価表も会話ログも読まないので、誰かが裏で計算して結果をファイルに置き、statusline がそれを描画のたびに読む必要がある。計算を走らせる場所（応答ごとの `Stop` hook）と、逆向きの受け渡しがもう 1 つ増える。まず `/cost` の警告で始め、足りなければ別の issue で足す。

**この決定で受け入れること**: 手で `/cost` を叩くまで、ずれに気づかない。PR に自動で貼られる行だけを見ている間は警告が目に入らない。

### pr-review-gate 通過時の hook は突き合わせを省いて呼ぶ

`gate-report.sh` は `cost_ledger.py cost <番号>` の 1 行目しか使わない。突き合わせの読み直しは hook の所要時間を増やすだけなので、`cost` に `--no-drift-check` を足し、hook はそれを付けて呼ぶ。`gate-report.sh` の変更は引数 1 つで、`hooks/hooks.json` は変えない。

`openspec/specs/cost-ledger-gate-report/spec.md` は「貼る数字を `cost_ledger.py cost <番号>` の 1 行目から取る」と定めていて、引数を足してもこの要件は変わらない（1 行目は引数の有無で同じ）。そのため gate-report 側の仕様には手を入れず、「hook は突き合わせを省いて呼ぶ」は `cost-ledger-pricing` の要件に置く。

## Risks / Trade-offs

- [単価表が正しくても、実機では差が 10% を超えるかもしれない] 会話ログに残らない補助的な呼び出しの額や、200K を超えるコンテキストの割増（単価表が表現していない）の大きさは、仕様づくりの時点では測れていない。→ tasks の実機の測定で確かめ、超えたら閾値を手元で動かさずに止めて報告する
- [描画と同じ秒に書かれた行が区間の内か外に 1 つ倒れる] サブエージェントが裏で動いているときに起きうる。応答 1 回分で、差額 $0.50 と 10% の両方を超えることはまれ。→ 閾値で吸収する。対策は足さない
- [長い応答の途中で別のセッションから `/cost` を叩くと、会話ログには行があるのに本体の値にはまだ入っていない] 一時的な差で、応答が終われば消える。→ 対策は足さない
- [`--resume` で新しいセッション ID に前の会話ログの行が写される場合] 写された行は元の時刻を持つので、新しい記録の `t0` より前になり、区間の外として比べない。→ 増分で比べる決定で吸収済み
- [statusline を `/statusline:setup` で入れ直すまで記録が始まらない] プラグインの更新だけでは `~/.claude/statusline.sh` は古いまま。→ `plugins/statusline/changes/692.md` と README に「入れ直すと記録が始まる」と書く。入れ直すまでは警告が出ないだけで、`/cost` の値は今と同じ
- [読み直しで `/cost` が遅くなる] 台帳を使わないと現状で 23.6 秒かかっている環境がある。→ 更新時刻で開くファイルを絞る。前後の所要時間を測って PR に書く。hook は `--no-drift-check` で影響を受けない
- [`${CLAUDE_CONFIG_DIR:-$HOME/.claude}/.session-cost/` にファイルが溜まる] 1 セッション 1 ファイル。→ 400 日より古いものを、新しい記録を作る描画のついでに消す

## Migration Plan

- マージ後、利用者が `/statusline:setup` を再実行すると記録が始まる。再実行しなくても既存の動作は変わらない
- 戻すときは、この change の commit を revert する。残った `.session-cost/` は読まれなくなるだけで害は無い（消すなら `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/.session-cost/` をディレクトリごと消す）
