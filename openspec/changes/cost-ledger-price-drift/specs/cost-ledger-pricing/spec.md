## ADDED Requirements

### Requirement: 本体のコスト値と自前の計算をセッションの区間ごとに突き合わせる
システムは、コストを答えるとき（`cost_ledger.py` の `cost`・`branch`・`issue`）、答えに行が含まれるセッションのうち、`session-cost-record` の記録（`${CLAUDE_CONFIG_DIR:-$HOME/.claude}/.session-cost/<セッション ID>`）があるものについて、Claude Code 本体の値と自前の計算を突き合わせ SHALL る。

突き合わせる 2 つの値は次のとおりと MUST する。記録の 4 項目を、区間の最初の観測時刻 `t0`・最初の観測値 `v0`・最後に値が変わった観測時刻 `t1`・最後の観測値 `v1` と呼ぶ。

- 本体の値: `v1 − v0`（その区間で、観測を始めてから増えた分）
- 自前の計算: そのセッション ID を持つ行のうち、時刻が `t0 + 1` 秒以上 `t1 + 1` 秒未満のものを、料金表の単価で計算した合計

自前の計算には、そのセッション ID を持つ行を**ブランチやリポジトリで絞らずに**すべて含め MUST る。本体の値はセッション全体の値で、1 つのセッションがサブエージェントの worktree など別のブランチの行を持つためである。行の重複は `requestId` で排除 SHALL する。

`t1` が `t0` と同じ記録（観測が 1 回だけ）、形が `session-cost-record` の形式でない記録、読めない記録は、突き合わせの対象から外 SHALL す。そのために集計を中断したり、終了コードを変えたりしてはなら MUST NOT ない。

突き合わせは LLM を使わず、`gh` を呼ばず、ネットワークに出てはなら MUST NOT ない。

#### Scenario: 別ブランチの行も自前の計算に入る
- **WHEN** あるセッションがブランチ `feat` の行 $1.00 と、別のブランチ `wt` の行 $2.00 を持ち、本体の値の増分が $3.00 の記録がある状態で、ブランチ `feat` のコストを求める
- **THEN** 1 行目の金額は `feat` の $1.00 のままで、ずれの警告は出ない

#### Scenario: 区間の外の行は比べない
- **WHEN** あるセッションに時刻 `t0` より前の行 $5.00 と、`t0 + 1` 秒以上 `t1 + 1` 秒未満の行 $2.00 があり、本体の値の増分が $2.00 である
- **THEN** ずれの警告は出ない

#### Scenario: 記録が無いセッションは比べない
- **WHEN** 答えに含まれるどのセッションにも記録が無い
- **THEN** ずれの警告は出ず、出力は記録の仕組みが無いときと同じである

#### Scenario: 壊れた記録で止まらない
- **WHEN** 答えに含まれるセッションの記録ファイルの中身が 5 項目の形でない
- **THEN** 終了コードは 0 で、コストの出力は記録が無いときと同じである

#### Scenario: 台帳から読むときも同じ結果になる
- **WHEN** 同じ会話ログと同じ記録に対して、`COST_LEDGER_PATH` を設定した場合と設定しない場合でコストを求める
- **THEN** ずれの警告の有無と中身が両方で同じである

### Requirement: ずれが閾値を超えたら警告する
システムは、突き合わせたセッションについて、本体の値と自前の計算の差の絶対値が次の**両方**を超えたとき、そのセッションを「ずれあり」と SHALL する。

- 差額: $0.50
- 割合: 本体の値と自前の計算のうち大きい方の 10%

「ずれあり」のセッションが 1 つ以上あるとき、システムは出力の 2 行目以降に警告を 1 行だけ出 MUST す。警告は `単価表のずれ:` という語を含み、突き合わせたセッションの数、「ずれあり」のセッションの数、差額が最大のセッションの ID・本体の値・自前の計算・差額・割合、閾値を示 SHALL す。「ずれあり」のセッションが複数あっても行を増やしてはなら MUST NOT ない（出力を読む側の量を増やさないため）。

「ずれあり」のセッションが無いとき、この警告を出してはなら MUST NOT ない。

閾値は実装の 1 か所にだけ置き、警告の文面はその値から作 SHALL る。

#### Scenario: 差が両方の閾値を超える
- **WHEN** あるセッションの本体の値の増分が $10.00、自前の計算が $6.00 である
- **THEN** 出力の 2 行目以降に `単価表のずれ:` を含む行が 1 行あり、そのセッションの ID、`$10.00`、`$6.00` が示される

#### Scenario: 差が閾値以内
- **WHEN** あるセッションの本体の値の増分が $10.00、自前の計算が $9.50 である（差額 $0.50、割合 5%）
- **THEN** `単価表のずれ:` を含む行は出ない

#### Scenario: 割合は超えるが差額が小さい
- **WHEN** あるセッションの本体の値の増分が $0.60、自前の計算が $0.30 である（割合 50%、差額 $0.30）
- **THEN** `単価表のずれ:` を含む行は出ない

#### Scenario: 差額は超えるが割合が小さい
- **WHEN** あるセッションの本体の値の増分が $100.00、自前の計算が $95.00 である（差額 $5.00、割合 5%）
- **THEN** `単価表のずれ:` を含む行は出ない

#### Scenario: 自前の計算の方が大きい
- **WHEN** あるセッションの本体の値の増分が $6.00、自前の計算が $10.00 である
- **THEN** `単価表のずれ:` を含む行が出る

#### Scenario: ずれありが複数でも 1 行
- **WHEN** 「ずれあり」のセッションが 3 つある
- **THEN** `単価表のずれ:` を含む行は 1 行で、「ずれあり」の数として 3 が示され、差額が最大のセッションの値が示される

### Requirement: 単価の無いモデルを含むセッションは差の大きさにかかわらず警告する
システムは、突き合わせたセッションの区間の中に、未知モデル（料金表のどの鍵にも前方一致しないモデル名）の行で、トークン 5 種のいずれかが 1 以上のものがあるとき、差が閾値以内でも警告を 1 行出 MUST す。警告は `単価表のずれ:` という語を含み、該当する未知モデルの名前、該当するセッションの数、それらのセッションの本体の値の合計と自前の計算の合計を示 SHALL す。

トークン 5 種がすべて 0 の未知モデルの行（会話ログに現れる `<synthetic>` のように API 呼び出しを伴わない行）だけでは、この警告を出してはなら MUST NOT ない。

この警告は、既存の「未知モデル: 名前 行数」の表示を置き換えるものではない。既存の表示はそのまま出 SHALL す。

#### Scenario: 単価の無いモデルの行が区間にある
- **WHEN** あるセッションの区間に、料金表に無いモデル `claude-future-9` のトークンを持つ行があり、本体の値の増分が $0.20、自前の計算が $0.05 である（差は閾値以内）
- **THEN** `単価表のずれ:` と `claude-future-9` を含む行が出る

#### Scenario: トークンの無い未知モデルの行だけでは警告しない
- **WHEN** あるセッションの区間に、モデル名が `<synthetic>` でトークンがすべて 0 の行があり、それ以外の行の自前の計算が本体の値の増分と一致する
- **THEN** `単価表のずれ:` を含む行は出ない

### Requirement: 警告は 1 行目と終了コードを変えず、省くこともできる
ずれの警告は、出力の 1 行目（帰属先ごとの固定書式の行）を変えてはなら MUST NOT ない。警告の有無で終了コードを変えてはなら MUST NOT ない。

`issue` の経路を JSON で出すとき、システムは突き合わせの結果を `price_drift` という鍵に入 SHALL れる。警告が無ければ値は `null` とする。

`cost` サブコマンドは、突き合わせそのものを行わない引数 `--no-drift-check` を受け付け SHALL る。pr-review-gate 通過時に PR へコストを貼る hook は、この引数を付けて `cost` を呼ば MUST なければならない（hook は 1 行目しか使わず、突き合わせのための読み直しは所要時間を増やすだけなので）。

#### Scenario: 警告があっても 1 行目は同じ
- **WHEN** 「ずれあり」のセッションがある状態と、同じ会話ログで記録を消した状態でコストを求める
- **THEN** 両方の出力の 1 行目は同じで、終了コードはどちらも 0 である

#### Scenario: 突き合わせを省く
- **WHEN** 「ずれあり」のセッションがある状態で、`cost` を `--no-drift-check` 付きで実行する
- **THEN** `単価表のずれ:` を含む行は出ず、1 行目は引数を付けないときと同じである

#### Scenario: ゲート連携の hook は突き合わせを省いて呼ぶ
- **WHEN** 合格ラベルの付与を捕まえた hook が `cost_ledger.py` を呼ぶ
- **THEN** その呼び出しの引数に `--no-drift-check` が含まれている

#### Scenario: JSON の出力に結果が入る
- **WHEN** 「ずれあり」のセッションがある状態で、`issue` の経路を JSON で出す
- **THEN** 出力は有効な JSON で、`price_drift` に突き合わせたセッションの数と「ずれあり」のセッションの数が入っている
