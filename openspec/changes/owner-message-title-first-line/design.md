# Design

## Context

正本の新しい書き分けと、題名・アクションの項目の定義は change `owner-request-eight-items` の design で決めた。この change はそれに揃えるだけで、新しい決まりを足さない。

## Goals / Non-Goals

**Goals:** develop の文書と spec に残る旧い書き分け（1 行目を質問、最後の行を答え方）を、正本の新しい書き分けに置き換える

**Non-Goals:** 状態表の列の作り替え／hook の見分け方（change `owner-number-check-title-form`）／親が主に上げるかの判定（主に聞く理由の 3 つは変わらない）

## Decisions

### 「答え方の行」は「アクションの行」に置き換え、位置は 2 行目にする

旧い文書で「最後の答え方の行」「区切りより上の本文の最後の行」と書いている箇所は、どれも「どこで何を打つか」を書く行を指している。新しい正本ではそれがアクションの行で、2 行目に置く。中身（親のタブで打つ・報告の直後に別の発言を挟まない・チャンネルで返す・PR のフル URL を添える・チャンネル以外の画面を書かない）は変えない。

### 要件の見出しは変えない

spec の要件「channel モードの主への発言はすべてチャンネルに送り、チャンネルでする操作を答え方の行に書く」と、Scenario の見出し 2 つ（「…報告の答え方に場所と条件が入る」「区切りより上の最後の行と 1 行目は変わらない」）は、見出しを変えずに本文だけを直す。見出しを変えると RENAMED を挟むことになり、他の change やテストが見出しで要件を引いている箇所まで直す範囲が広がるため。本文では「アクションの行（見出しの『答え方の行』）」と 1 度だけ対応を書く。

他の案: RENAMED で見出しも直す。食い違いは見出しの語だけで振る舞いは同じなので、範囲を広げる価値が無いと判断した。

### 状態表の列名 `答え方` は変えない

列は「どの画面で何を打つか」を並べるもので、意味は変わらない。列名を変えるとテストと既存の報告の読み方が変わるだけで、主に得るものが無い。

### 止まった子の記録の項目は、正本の新しい項目に置き直す

要件「Orca 経路の親は止まった子を解決し、解決できないものを主に分かる形で上げる」は、子の停止の記録の 7 項目を旧い 6 段（質問・主に聞く理由・いま困っていること…）に置き直すと決めている。新しい項目への対応は次のとおりにする。

| 記録の項目 | 新しい項目 |
|---|---|
| `止まった理由:` | 題名（依頼の形に直す。質問にしない）と詳細 |
| `主に聞く理由:` | 論点（論点ありなら論点、論点なしなら推奨どおりでよい旨と決まりが守るもの） |
| `前提:` | 詳細 |
| `推奨:`・`推奨の根拠:` | 推奨と根拠 |
| `受け入れるリスク:` | リスク |
| `再開に要る途中経過:` | 書かない（記録の URL で足りる。今までどおり） |

アクションは記録に無いので親が書く。返事の場所と条件は、要件「エピックの親が主に出す発言は、正本の 1 行目の書き分けに従う」のとおり。`主に聞く理由:` を論点に置くのは、change A が主に聞く理由の 3 つを書く前の判定にし、判定の結果を論点の項目に書くと決めたため。

使う項目と長さは正本の使う場所の表に従う。親のタブで出す報告は対話のセッションの行、channel の親がチャンネルに送る報告はチャットで 1 件ずつ出す依頼の行に当たる。後者は緊急度とブロックも書き、ブロックには返事を待って止まっている子を書く。論点なしの止まりの行数は、epic.md の手順 8 に「3〜4 行」と写さず、正本の論点の無い依頼の決まりを指す（行数を二か所で決めると、change A のように正本を直したときに食い違うため）。エピックの目的と他の子との関係は、目的・詳細の項目に書くか区切りの下に置く。

子の側の記録の項目名（`止まった理由:` など）は変えない。親が「今回の止まった理由」として読む語で、子の手順と照合の仕組みが使っているため。

他の案: 記録の項目名を新しい項目名に揃える（`題名:` `論点:` など）。子の手順・`epic-dispatch.sh`・テストまで直す範囲が広がり、主に届く文面は親が置き直すので得るものが無い。

実機の Scenario（ログの 3 場面を子の停止の記録にして親に報告を書かせるもの）は、THEN を新しい形に直したので、実装の段で取り直す。

### 状態表の 1 行目と 2 行目は、依頼の有無で分ける

状態表の要件の「1 行目と 2 行目は題名とアクションの行のまま」は、依頼の無い報告にもアクションの行を求めると読める。依頼がある報告だけ 1 行目を題名・2 行目をアクションの行にし、依頼が無い報告は 1 行目を `主がすること: なし` にして 2 行目に `アクション:` の行を書かない、と分けて書く。依頼の無い報告にアクションの行があると、change C の hook がその報告を依頼として拾うため。

## Risks / Trade-offs

- [見出しの語と本文の語が違う] → 本文に対応を 1 度書く
- [change A だけが先に入ると食い違う] → 同じ PR に積む
- [実機の Scenario の取り直しに手間がかかる] → `claude -p --plugin-dir` で 3 場面を 1 回ずつ回すだけにする。取れなかったら実装の段で止めて返す
