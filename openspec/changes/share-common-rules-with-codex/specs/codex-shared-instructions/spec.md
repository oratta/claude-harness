# Spec Delta

## Purpose

Claude Code と Codex の指揮役・worker に同じ正本の共通ルールを届ける。配布の明示性、個人情報と既存ホーム指示の保持、UTF-8 指示容量の検査、実際に読めたことの内容による確認を契約にする。

## ADDED Requirements

### Requirement: 共通指示は許可された正本から全文生成する
生成処理は公開版と許可済み個人版の `rules/*.md` を README を除いて安定した順序で全文連結しなければならない（MUST）。readable の要点は正本の `rules/communication-style.md` を使い、別の手書き要約を持ってはならない（MUST NOT）。公開分の生成物は追跡し、個人版を含む生成物はローカル限定にしなければならない（MUST）。検査は正本と生成物の不一致を非0で知らせなければならない（MUST）。

守備範囲（生成物一致・overlay 選別）: 入力元は公開正本・追跡生成物と利用者が許可した overlay。一致検査は再生成したバイト列との差を拾う。overlay は既存 `harness-overlay-sync` の「overlay の印のファイルの検査の守備範囲」に従う。例えば形式が正しい許可済み overlay に意味的に矛盾する本文があっても選別を通り、正本と生成物が一致すれば一致検査も通る。読込成功は保証しない。穴をすべて塞ぐことは完了条件にせず、上記の一致と overlay 契約の検査を完了条件とする。

#### Scenario: 正本を一行変えて再生成していない
- **WHEN** 正本のルールを一行変更し、追跡された公開生成物を再生成せず一致検査する
- **THEN** 検査は非0になり、再生成すると変更行を含む全文が出力されて一致検査が0になる

#### Scenario: 許可済み overlay だけを含める
- **WHEN** 許可済み・許可外・許可取消済みの overlay が存在する状態で生成・再同期する
- **THEN** 既存の `harness-overlays` と `.harness-overlay` の許可・検証契約を満たすものだけを含み、許可外・取消済みの本文は新しい管理区画に残らない
- **AND** 許可ファイルの行順によらず同じ入力から同じバイト列を生成し、README は含まれない

#### Scenario: 個人版の本文を配布する
- **WHEN** 許可済みの個人版ルールを加えた生成物をホームに配布する
- **THEN** 本文はローカルの配布先にだけ置かれ、公開追跡生成物には入らない

### Requirement: harness の全文指示には適用範囲を付ける
生成する共通区画は harness の `AGENTS.md` 全文を含め、この節は harness 配布元リポジトリを変更するときだけ適用すると明記しなければならない（MUST）。相対参照の基準を供給元として示し、一般 repo や flatmate に harness の開発場所・PR 運用を広げてはならない（MUST NOT）。Claude 固有の hook や Agent を Codex で実行済みと扱ってはならない（MUST NOT）。

#### Scenario: harness 以外のリポジトリで読む
- **WHEN** flatmate または一般 repo の Codex セッションが生成された共通区画を読む
- **THEN** 共通 rules と harness 専用節の境界、および参照の供給元が明示され、harness 専用の開発場所・PR 運用はその repo の規約として適用されない

### Requirement: Codex ホームへの配布は明示実行する
`scripts/sync.sh` は `--codex` 指定時だけ Codex ホームを更新しなければならない（MUST）。対象は `~/.codex`、設定されている現在の `CODEX_HOME`、明示された登録ホームの和集合とし、実体パスで重複を除かなければならない（MUST）。登録先の受渡しは反復可能な `--account-home NAME=PATH` または `--account-home-file PATH` の平坦な JSON オブジェクトとし、別の台帳やホーム探索を追加してはならない（MUST NOT）。

守備範囲（登録先検証）: 入力元は呼出元の CLI 引数または登録先 JSON。両形式の併用、同名・JSON キー重複、非平坦な JSON、空・非文字列の名前や値、相対パス、存在しない登録先を拾う。例えば別名で同じ実在ディレクトリを指す絶対パスは通し、実体の重複を除く。有効な認証が無いディレクトリも通してよく、セッション開始成功は保証しない。穴をすべて塞ぐことは完了条件にせず、既存契約の誤りを拾い、有効な表から配布対象を決められることを完了条件とする。

#### Scenario: 従来の同期を実行する
- **WHEN** `--codex` を付けずに従来の同期コマンドを実行する
- **THEN** Codex ホームの AGENTS と config は書き換わらない

#### Scenario: 複数の登録ホームへ配布する
- **WHEN** `--codex` と有効な登録先を渡し、既定ホーム・現在のホーム・登録先に同じ実体を指すパスが含まれる
- **THEN** 和集合の各実体に一度ずつ同じ共通区画を配り、再同期しても同じ入力の AGENTS と config のバイト列は変わらない

#### Scenario: 登録先の入力が不正である
- **WHEN** 両形式を併用する、同名を重複指定する（JSON キー重複を含む）、非平坦な JSON・空または非文字列の名前や値・相対パス・存在しない登録先を渡す
- **THEN** `codex-develop.py` の登録先契約と同様に非0で拒否する

### Requirement: 管理区画は既存ホーム指示と共存する
配布は共通指示を開始・終了マーカー付き管理区画として `AGENTS.md` の先頭に置き、区画外の既存バイト列を保持しなければならない（MUST）。再同期は管理区画だけを置換しなければならない（MUST）。破損・重複マーカー、管理外のリンク、非空の `AGENTS.override.md` を検出した場合は上書きせず非0で知らせなければならない（MUST）。

入力検査の守備範囲（管理区画検証）: 入力元は配布対象ホームの既存 `AGENTS.md`、更新対象のリンク状態と `AGENTS.override.md` である。片側だけ・逆順・重複のマーカー、管理外のリンク、非空の override を拾う。例えば、マーカーの無い既存7行は初回配布の入力として通し、区画外に共通指示と意味的に矛盾する文があっても通して保持する。本文の意味的一貫性やモデルが指示に従うことは検査しない。穴をすべて塞ぐことは完了条件にせず、上記の置換を妨げる状態を検出し、正常な区画の置換と区画外バイト列の保持を確認できることを完了条件とする。

#### Scenario: 主の既存7行がある
- **WHEN** 管理区画の無い既存7行の `AGENTS.md` に初回配布し、続けて再同期する
- **THEN** 共通区画が先頭に入り、7行の順序・意味・バイト列は区画外に保持され、再同期で重複区画が生じない

#### Scenario: 安全に置換できないホームである
- **WHEN** マーカーが片側だけ・逆順・重複している、更新対象が管理外のリンクである、またはホームに非空の `AGENTS.override.md` がある
- **THEN** 問題の指示・設定を上書きせず非0になり、対象と原因を知らせる

### Requirement: ホーム設定は指示容量の最低値だけを更新する
配布は `project_doc_max_bytes` の共通最低値を131072にし、未設定・小さい値を引き上げ、既存の大きい値を維持しなければならない（MUST）。関係する容量キー以外の認証・MCP・他の設定を保持しなければならない（MUST）。profile 等に最低値を下回る有効値が残った状態を成功扱いにしてはならない（MUST NOT）。

入力検査の守備範囲（容量設定）: 入力元は配布対象ホームの `config.toml` にあるトップレベルと profile 等の容量設定である。容量キーの未設定・最低値未満と、更新後にも小さい有効値が残る状態を拾う。例えば、既存値が262144である設定は通して維持し、無関係な MCP 設定の接続先が利用不能でも容量設定の検査は通してよい。指示本文の総量、認証や MCP の動作、実機での読込成功はこの設定検査だけでは保証しない。穴をすべて塞ぐことは完了条件にせず、容量の最低値と既存の大きい値の維持、無関係な設定の保持を確認できることを完了条件とする。

#### Scenario: 既存設定を保持して容量を更新する
- **WHEN** 新規ホーム、最低値未満の設定、最低値より大きい設定に配布する
- **THEN** 新規・小さい値は131072になり、大きい値は維持され、関係しない設定は保持される

#### Scenario: profile に小さい容量値がある
- **WHEN** トップレベルとは別に profile 等に小さい有効値が設定されている
- **THEN** その容量値も最低値以上に更新するか非0で知らせ、容量不足のまま成功を返さない

### Requirement: 自動メモリを共通指示へ取り込まない
生成・配布・worker 起動は Claude の `~/.claude/projects/*/memory/` を探索・コピー・リンクしてはならない（MUST NOT）。docs は、別プロジェクトや住人の記憶の混入を防ぐためであることと、必要な知識を依頼で明示的に渡せることを説明しなければならない（MUST）。

#### Scenario: Claude の自動メモリが存在する
- **WHEN** 共通指示を生成・配布し worker を起動する
- **THEN** 自動メモリは取込元にならず、生成物・ホームの管理区画・worker の一時ホームに入らない

### Requirement: 指示全体の容量を UTF-8 で検査する
容量検査は共通区画、生成見出し・区切り、区画外のホーム指示、探索順で選ばれるリポジトリ規約と人格を UTF-8 バイト数で合算しなければならない（MUST）。合計が設定上限以下なら0、超過なら非0とし、同じディレクトリの AGENTS と CLAUDE を二重計上してはならない（MUST NOT）。固定入力とローカル実物の検査結果は区別しなければならない（MUST）。

入力検査の守備範囲（UTF-8 容量検査）: 入力元は実際の公開生成物とホーム指示、manifest の測定値を再現したダミー本文、または探索順で選ぶローカル実物と設定上限である。UTF-8 合計の上限超過、区切り・区画外本文の計上漏れ、同階層の二重計上を検査し、実物不在を明示する。例えば容量内なら意味的に矛盾する本文や原文と内容が異なる同サイズのダミー本文も通る。固定入力の成功は実物の更新への追従や読込成功を保証せず、実物の容量内判定も実機で読めた証拠にはしない。穴をすべて塞ぐことは完了条件にせず、指定入力のバイト数と上限境界を正しく判定し、固定入力と実物の結果を区別できることを完了条件とする。

#### Scenario: 日本語と上限境界を検査する
- **WHEN** 日本語を含む指示・区切り・区画外本文の合計が上限ちょうど、および1バイト超過する入力を検査する
- **THEN** 文字数でなく UTF-8 バイト数で判定し、前者は0、後者は非0になる

#### Scenario: ponta の固定入力で全体を検査する
- **WHEN** 公開生成物と、flatmate の ponta を含む固定入力を検査する
- **THEN** 非公開入力の相対ファイル名・実測バイト数・SHA-256・測定元を manifest から追跡でき、同サイズを再現する決定的な UTF-8 ダミー本文と末尾マーカーを使い、見出しを含む全体が131072バイト以内であると検査できる
- **AND** 公開ルール・harness AGENTS・生成見出しは実際の生成物を測り、個人ルール・人格本文を公開 repo に転載しない

#### Scenario: flatmate の実物を検査する
- **WHEN** ローカルの flatmate と ponta の指示を実物検査する
- **THEN** 実際の探索順で選ばれるファイルだけを合算し、AGENTS と CLAUDE の同居を二重計上せず、flatmate 側のファイルは変更しない
- **AND** 実物が不在なら不在を明示し、固定入力の成功を実物の成功と報告しない

### Requirement: 実機の読込は回答内容で確認する
実機検証は新規 Codex セッションによる破壊的 git・commit・主への聞き方の三規則の回答、flatmate の人格末尾の回答、worker による既存履歴に合う日本語 commit を別々に issue #1853 に記録しなければならない（MUST）。通信完走だけを品質合格としてはならない（MUST NOT）。実ホームへの適用は対象・具体差分・復旧方法を提示して権限を確認した主または本体が sync 経由で行わなければならない（MUST）。

#### Scenario: 三規則と人格末尾を読めた証拠を残す
- **WHEN** 配布後の新規セッションと ponta の作業ディレクトリのセッションを検証する
- **THEN** 各規則の中身と実際の人格の最後の節の中身を答えた出力を記録し、正本と照合して判定する

#### Scenario: worker の commit 規約を確認する
- **WHEN** 配布済み account home を選択した worker に検証用変更を commit させる
- **THEN** commit の SHA とメッセージ、既存の日本語履歴との照合結果を記録し、実行終了だけを合格理由にしない
