## 決定

1. **本体のログの選び方**: 記録の `session` は `orca terminal` のハンドルか tmux のペイン ID（`launch` の `started <handle>` を書いたもの）で、会話ログのファイル名と対応しない。Claude のセッション ID を記録に持たせるには起動の指示の変更（`--session-id` など）が要り、起動済みの子には効かないので範囲外。代わりに内容から選ぶ。置き場の直下の `*.jsonl` のうち、`entrypoint == "cli"` かつ sidechain でない assistant 行を持つファイルを候補にし、全行 `timestamp` 最大値が最新の 1 本を本体とする。`sdk-py`・`sdk-cli` のログは候補にならず、過去の cli のセッションは最終活動が古いので負ける。最新というだけでは本体との対応が保証されない（本体のログが欠けて過去の cli だけ残ると誤採用する）ので、記録の `stop_uuid` が選んだログに在ることを確かめる。無ければ、`stop_uuid` が空なら候補がちょうど 1 本のときだけ決める。最終活動が同時刻の候補は決めない。決められなければ送らない（推測しない考え方を保つ）。issue の受け入れ条件の「session と一致するログ」は「本体のログ」に読み替える。
   - 検討した別案: 最終更新時刻（mtime）だけで選ぶ案は、SDK の短いセッションが新しいと取り違えるので採らない。ログが 2 本以上の cli で最終活動が近いときに送らない案は、`/clear` や再開のあとに送れなくなる割合が大きいので採らない。
2. **共有化**: 選び方を `transcript_dir` の隣の 1 つの関数にし、`keepalive_candidate` の python と `decide_relaunch` が使う。`decide_relaunch` は同じ原因（本数が 1 でないと常に 0）で外れていたので同じ直し方にそろえる。`cache_ttl_of` は選んだログのファイルを任意の引数で受け取れるようにし、声かけの判定は選んだログだけから TTL を読む（本体以外のキャッシュの書き込みを採用しない）。`wait` の待ち時間の上限の既定が使う呼び出しは引数なしのままで、全ログを読む今の動きを変えない。`wait --resolve` の起動し直しの判定の要件（dev-workflow-develop）の「ちょうど 1 本」も同じ選び方に直す。
3. **結果の置き場**: 子の記録に任意の文字列 `keepalive`（`<UTC 時刻> <結果>`）。理由は、記録は子ごと 1 ファイルで親が書く先として既にあり、`pending-owner` や人が読める。別ファイルや GitHub コメントは書き込みが増えるので採らない。ポーリングごとに書かないよう、前回と結果が同じなら書き直さない。書けなくても判定は変えない。
4. **理由の取り方**: `keepalive_candidate` は、拒否した理由の語を stdout に出して exit 1 にする（今は無言の exit 1）。呼び元の `keepalive_child` が語を結果にして書く。早期 return の分岐にも語を付ける。語彙は spec に閉じて置く。
5. **#1545 との関係**: #1545 は未マージなので今の main に合わせる。同じ関数を触る箇所が競合したら、後から入るほうが合わせる。

`cache-live` は送信条件（最後のリクエストから 3000〜3599 秒）と矛盾するので `cache-future`（書き込み時刻が今より未来）に直した。

## リスク

- `/clear` や再開の直後は選んだログがまだ `stop_uuid` の行を持たず、その回は送らない（止まった子の声かけは送れなかった回があっても次の回に届く）。誤って過去のログで送るより安全側に倒す。
