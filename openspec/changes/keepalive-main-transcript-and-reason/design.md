## 決定

1. **本体のログの選び方**: 記録の `session` は `orca terminal` のハンドルか tmux のペイン ID（`launch` の `started <handle>` を書いたもの）で、会話ログのファイル名と対応しない。Claude のセッション ID を記録に持たせるには起動の指示の変更（`--session-id` など）が要り、起動済みの子には効かないので範囲外。代わりに内容から選ぶ。置き場の直下の `*.jsonl` のうち、`entrypoint == "cli"` かつ sidechain でない assistant 行を持つファイルを候補にし、全行 `timestamp` 最大値が最新の 1 本を本体とする。`sdk-py`・`sdk-cli` のログは候補にならず、過去の cli のセッションは最終活動が古いので負ける。最新というだけでは本体との対応が保証されない（本体のログが欠けて過去の cli だけ残ると誤採用する）ので、記録の `stop_uuid` が選んだログに在ることを確かめる。無ければ決めない。`stop_uuid` が空のときも決めない（主の決定。#1554 の記録先のコメント参照）。`stop_uuid` が空で残るのは、会話ログが読めない間や、読めた最後の発言の uuid が不正な形で空にされる（`child-log-read.py` の `safe_uuid`）ときで、読めて正しい形なら detect_stopped が次の見張り（既定 300 秒以内）で埋めるので、送らなくても失うものは小さい。最終活動が同時刻の候補は決めない。決められなければ送らない（推測しない考え方を保つ）。issue の受け入れ条件の「session と一致するログ」は「本体のログ」に読み替える。
   - 検討した別案: 最終更新時刻（mtime）だけで選ぶ案は、SDK の短いセッションが新しいと取り違えるので採らない。ログが 2 本以上の cli で最終活動が近いときに送らない案は、`/clear` や再開のあとに送れなくなる割合が大きいので採らない。
2. **共有化**: 選び方を `transcript_dir` の隣の 1 つの関数にし、`keepalive_candidate` の python と `decide_relaunch` が使う。`decide_relaunch` は同じ原因（本数が 1 でないと常に 0）で外れていたので同じ直し方にそろえる。`cache_ttl_of` は選んだログのファイルを任意の引数で受け取れるようにし、声かけの判定は選んだログだけから TTL を読む（本体以外のキャッシュの書き込みを採用しない）。`wait` の待ち時間の上限の既定が使う呼び出しは引数なしのままで、全ログを読む今の動きを変えない。`wait --resolve` の起動し直しの判定の要件（dev-workflow-develop）の「ちょうど 1 本」も同じ選び方に直す。
3. **結果の置き場**: 子の記録に任意の文字列 `keepalive`（`<UTC 時刻> <結果>`）。理由は、記録は子ごと 1 ファイルで親が書く先として既にあり、`pending-owner` や人が読める。別ファイルや GitHub コメントは書き込みが増えるので採らない。ポーリングごとに書かないよう、前回と結果が同じなら書き直さない。書けなくても判定は変えない。
4. **理由の取り方**: `keepalive_candidate` は、拒否した理由の語を stdout に出して exit 1 にする（今は無言の exit 1）。呼び元の `keepalive_child` が語を結果にして書く。早期 return の分岐にも語を付ける。語彙は spec に閉じて置く。
5. **#1545 との関係**: #1545 は未マージなので今の main に合わせる。同じ関数を触る箇所が競合したら、後から入るほうが合わせる。

`cache-live` は送信条件（最後のリクエストから 3000〜3599 秒）と矛盾するので `cache-future`（書き込み時刻が今より未来）に直した。

## リスク

- `/clear` や再開の直後は選んだログがまだ `stop_uuid` の行を持たず、その回は送らない（止まった子の声かけは送れなかった回があっても次の回に届く）。誤って過去のログで送るより安全側に倒す。

## 守備範囲（spec の要件が長すぎる警告を避けるため、spec から移した）

- 本体のログの選び方: 入力は子の会話ログの置き場の `*.jsonl` の中身（`entrypoint`・`isSidechain`・`type`・`uuid`・`timestamp`・`message.usage`）と、記録の `stop_uuid`。拾いたい誤りは、SDK が起こした短いセッションや過去のセッションのせいで声かけが送られないこと、本体のログが無いのに過去のログを本体として判定して送ること、判定に本体以外のログの値が混ざること。次は通してよく、止めない: 本体と過去のセッションの最終活動が同時刻のときに送らないこと／`stop_uuid` が空の記録には（候補が 1 本でも）送らないこと／`/clear` や再開の直後で選んだログがまだ `stop_uuid` の行を持たず、その回は送らないこと／ログの行の崩れ方をすべて塞ぐこと。取り違えの穴を見つけるたびに検査を足して塞ぎ切ることは完了条件にしない。
- 結果の記録: 入力は声かけの判定の各段の結果（記録、`gh` の読み取り、会話ログ、起動部品の出力）。拾いたい誤りは、送らなかったのに理由が読めず動いていないことに気づけないこと、理由の語が毎回書き換わって記録が荒れること、記録の書き込みの失敗で `wait` の出力が変わること。次は通してよく、止めない: 複数の理由に当たるときにどれを書くか（判定の順で最初に当たったもの）／`out-of-window` のような通常の待ちを理由として残すこと／時刻が秒の単位でずれること。理由の分類を細かくし続けることは完了条件にしない。
