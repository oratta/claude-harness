## Context

置き場所の規則は段 C の表が持つ（既存の子の受け入れ条件に足す場合を含む）。「必ず follow-up issue にする」はその表を持つ前の言い方で、割れが起きる。

## Decisions

- 追跡の義務は「issue で追跡する」とし、手段は段 C の表に任せる。義務（捨てない・参考のコメントで済ませない）は変えない。代替案（段 C の表を使わず常に新しい issue）は、同じ場所を直す子が並ぶ重複を生むため採らない
- gate-runner.md の表は dev-workflow-develop の要件が「段の表に揃える」と定めるため、保留の解除の行は両方に同じ追記をする。読む条件は、前提確認の行の「W の修正後の再レビューのときは加えて」と同じ書き方にする
- 受け入れ条件 1 の「同じ commit で」は、同じ PR で main の spec と揃う（change の archive で main の spec が更新される）と読む
- `stages/hold.md` と `stages/pass.md` の「follow-up issue に切る」の語は変えない。置き場所の要件と triage.md の同じ段落に、この語は新しい issue を作る場合と段 C の表のとおり既存 issue で受ける場合の両方を指す、と定義の 1 文を足して食い違いを防ぐ（hold.md は PR #1436 が触るため範囲外）。「既存 issue で受ける」は、段 C の表の外の issue をエピックの子に足す場合も含む
