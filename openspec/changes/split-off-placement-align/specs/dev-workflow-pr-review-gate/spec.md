## MODIFIED Requirements

### Requirement: 主が切り出すと答えた止める指摘は捨てずに置き場所だけ決める

切り出しの確認（順 5）で主が「切り出す」と答えた止める指摘、および決める役の裁定を経て主が切り出すと答えた指摘について、G はその指摘を必ず issue で追跡しなければならない（MUST。新しい issue を作るか、段 C の表のとおり既存 issue の受け入れ条件に足す）。段 B・段 E で捨ててはならず、段 D の参考のコメントで済ませてはならない（MUST NOT。主が残すと決めた確認済みの欠陥で、追跡が切れると直されないため）。

置き場所は次で決める（MUST）: エピックに属する PR で、その欠陥がエピックの完了条件に効くなら、候補探しのスクリプトを走らせて段 C の表のとおりに分ける。それ以外はエピックの外の新しい issue にする。

#### Scenario: 主が切り出すと答えた欠陥がエピックに効く

- **WHEN** エピックに属する PR で、主が切り出すと答えた止める指摘がエピックの完了条件に効き、当たる issue が無い
- **THEN** G は新しい子 issue を作り、URL を PR コメントに記録し、`needs-approval` を外す

#### Scenario: エピックに属さない PR で主が切り出すと答えた

- **WHEN** エピックに属さない PR で、主が切り出しの確認に「切り出す」と答える
- **THEN** G はその指摘を新しい issue にし、捨てることも既存 issue への参考のコメントで済ませることもしない


#### Scenario: 主が切り出すと答えた欠陥を直す子 issue が既にある

- **WHEN** エピックに属する PR で、主が切り出すと答えた止める指摘がエピックの完了条件に効き、同じ場所を直す子 issue が既にあり、段 C の表がその子の受け入れ条件に足すと示す
- **THEN** G は新しい子 issue を作らず、その子の受け入れ条件に足して URL を PR コメントに記録する（追跡は切れない）
