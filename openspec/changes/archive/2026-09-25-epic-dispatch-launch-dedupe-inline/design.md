## Context

`plugins/dev-workflow/scripts/epic-dispatch.sh` の `cmd_launch` は `orca worktree list --json` を起動前に 1 回だけ読み、その一覧に既にワークツリーがある子番号を `skipped` にする（`spec.md:462`）。この一覧は呼び出し開始時点のスナップショットなので、同じ呼び出しの引数リストに同じ番号が 2 回以上含まれていても、1 回目で作った子は一覧に反映されず、2 回目も `create` が呼ばれてしまう。issue #434（PR #428 レビュー指摘 F6 の follow-up）はこの穴を塞ぐ。並行する兄弟 issue #429 #431〜#433 が `route`・`wait`・エピック深さ制限を触るが、この変更はそれらに触れない。

## Goals / Non-Goals

**Goals:**
- 同じ `launch` 呼び出しの引数に同じ子番号が複数回渡されたとき、2 回目以降は `orca worktree create` を呼ばず `skipped <N>` を出す

**Non-Goals:**
- 呼び出しをまたいだ重複検知（既存の一覧チェックがカバー済み、変更しない）
- `route` の引数検査を変えること（重複番号を通す既存仕様はそのまま）
- 子の起動順序や `--base` 解決など、このループ以外の `cmd_launch` の挙動

## Decisions

- **実装方式**: ループ内で空白区切りの文字列 `seen` に処理済み番号を追記し、`case` のワイルドカードマッチで既出判定する（bash の連想配列より依存が少なく、既存コードのスタイル — シェル変数の文字列ベース管理 — に合わせる）。代替案（連想配列 `declare -A`）は bash 4 未満の互換性を捨てるため採らない
- **`skipped` の意味を 1 つに保つ**: 「一覧に既存ワークツリーがある」場合と「同じ呼び出し内で既に処理した」場合を同じ `skipped <N>` の 1 行で表す。呼び出し元（develop 本体）は理由を区別する必要がないため、出力フォーマットは変えない
- **stdout の行数**: 重複した番号 1 回ごとに `skipped <N>` を 1 行出す（1 回目の `launched`/`failed` に加え、2 回目以降は毎回 1 行）。exit code は他の `skipped` と同じく成功扱い（`failed` が 0 件なら exit 0）

## Risks / Trade-offs

- [引数の順序によって `seen` の初期化位置を間違えると全番号が誤って `skipped` になる] → テスト（重複あり・重複なしの両方）で `local ... seen=" "` がループ外で 1 回だけ初期化されることを確認する
- [空白区切り文字列のマッチが番号の部分一致を拾う懸念（例: `11` と `111`）] → `case "$seen" in *" $n "*)` は前後に半角スペースを含めて照合するため部分一致は起きない（`" 11 "` は `" 111 "` にマッチしない）
