## Context

`#284`（`bats-assertion-guard`）は、bats テスト本文の途中に置いた単独文の `[[ ... ]]` が bash 4.1 未満（macOS 標準の `/bin/bash` 3.2.57 など）でだけ素通りする穴を塞いだ。その際、行頭が `!` で始まる否定形 `! [[ ... ]]` は対象定義（行頭 `[[ `）に一致せず対象外とし、対応を本 issue（#283）に委ねた。

`! cmd` の穴は `[[ ]]` の穴と原因が異なる。POSIX/bash の `errexit`（`set -e`）は、`!` で反転したコマンドの非ゼロ終了を**常に**無視する（`if`/`while` の条件式・`&&`/`||` の非最終要素・パイプラインの非最終要素と並ぶ、バージョンに依存しない除外規則）。`[[ ]]`/`(( ))` は bash 4.1 でこの除外規則の対象から外れた（＝ `set -e` が効くようになった）が、`!` による反転はこの改修の対象外で、今も昔もどのバージョンでも除外され続ける。つまり `! grep -q ... "$FILE"` を本文途中に置く書き方は、CI（`ubuntu-latest` の bash 5 系）でも退行を検出できない。ローカルの `/bin/bash 3.2.57` で `set -e` 下の関数の中に非終端の `! true` を置いて実測し、以降の行まで到達することを確認した（bash 5 系は手元に無いが、この除外規則はバージョン非依存の POSIX/bash 仕様であり、実装後の CI 実行そのものが実証になる）。

実測（`git ls-files '*.bats' ':(exclude)_longruns/' | xargs grep -nE '^[[:space:]]*! '`）: 35 ファイル・179 行。うち `plugins/cost-ledger/tests/gate-report.bats` の 13 行は既に `! cmd || return 1` の形でガード済み。残り34ファイル・166行が未ガード。

## Goals / Non-Goals

**Goals:**
- 対象34ファイル・166行の、単独の文として置かれた `! cmd`（`! [[ ... ]]` を含む）すべて（本文中の位置を問わず、最後の文も含む）に `|| return 1` を付ける。
- ガードの有無を機械的に検査する常設テストを追加する。
- `! cmd` の非検査がバージョンに関わらず常に起きることを実演するテストを追加する（`#284` の bash バージョン分岐は不要）。

**Non-Goals:**
- `[[ ]]`（否定なし）の扱い（`#284` で対応済み）。
- ガードを付けた結果として露呈した実装側の不具合の修正方針の変更（この PR 内で直し、`bash scripts/test.sh` 全件 green を受け入れ条件に残す。別途 issue は切らない）。
- `if`/`while`/`elif`/`until` の条件式に使われる `! cmd`、パイプライン途中の `! cmd`（`cmd1 | ! cmd2` のような形。今回の対象166行には実在しない）の扱い（スコープ検査 grep が構造的に対象外とする。理由は「Decisions」）。
- 複数行にまたがる `! cmd \` やヒアドキュメント本体内の `! ` 行の扱い（これらはスコープ検査 grep に誤って拾われるため、対象外ではなく「そう書かない」規約とする。理由は「Decisions」）。

## Decisions

**採用1: `|| return 1` を付ける（`run` + 終了コード比較は採らない）**

issue 本文は次の形への書き換えを提案している:
```bash
run grep -q 'import shlex\|, shlex' "$SCRIPT"
[ "$status" -ne 0 ]
```
検討した案:
1. **`! cmd || return 1`**（採用） — `plugins/cost-ledger/tests/gate-report.bats` が #273 で既に採っている形（13箇所で実証済み）。1行の末尾にトークンを足すだけで、`! ` を残したまま意味も見た目も変えない機械的な差分になる。`#284` が `[[ ]]` に採った「既存の書き方を壊さず末尾にガードを足す」方針とも一貫する。
2. **`run` + `[ "$status" -ne 0 ]`**（issue 本文の提案・不採用） — 1文が2〜3行に展開され、対象166行では diff が3倍近くに膨らむ。加えて `! echo "$input" | grep -Eq '...'` のようなパイプライン形（今回複数実在）を `run` に置き換える際、`run` はパイプライン全体を1コマンドとして扱えず、`bash -c` で包むなど書き方が行ごとに分岐する。cost-ledger の先例が既に `! cmd || return 1` で統一されている以上、同じリポ内で否定検査の書き方を二重にする理由が無い。

規模（34ファイル・166行）と cost-ledger の実績を踏まえ、案1を採用する。

**採用2: ガード対象は「本文中の位置」ではなく「単独の文として置かれた `! cmd` かどうか」で定義する**

`#284` の「採用2」を踏襲する。最後の文かどうかを判定に使わず、行頭（空白のみ）から `!` に続く空白で始まる行はすべて対象とする。判定は grep 1本のパイプラインで機械照合する:
```bash
git ls-files '*.bats' ':(exclude)_longruns/' \
  | xargs grep -nE '^[[:space:]]*! ' \
  | grep -vE '\|\| return 1[[:space:]]*(#.*)?$'
```
1段目が対象行（行頭 `! `）を抽出し、2段目が末尾 `|| return 1`（末尾コメント可）で終わる行＝ガード済みを除外する。出力が0行になることが完了条件。

grep が構造的に対象外とする（行頭 `! ` に一致しない）もの:
- `if`/`while`/`elif`/`until` の条件式（`if !`/`while !` は行頭が `if`/`while` になるため対象外に自然に外れる。対象166行に実在なし）
- パイプライン途中の `! cmd2`（`cmd1 | ! cmd2` の形。行頭が `!` でないため対象外。対象166行に実在なし）
- 既に `! cmd || return 1` でガード済みの13行（`plugins/cost-ledger/tests/gate-report.bats`。除外リストは使わず、上記grepの2段目が自然に除外する）

grep が誤って拾う（対象外ではない）ため、そう書かない規約とするもの:
- 複数行にまたがる `! cmd \`（1行目が行頭 `! ` に一致するため拾われる。対象166行に実在なし。行末が `\` で終わる行が無いことを確認済み）
- ヒアドキュメント本体内の `! ` で始まる行（`tests/test-sh-residual-guard.bats` はヒアドキュメントを多用するが、対象166行はいずれもヒアドキュメント外の実際のテスト本文であることを確認済み。ヒアドキュメントの開始/終了トークンを追跡する検査で確認した。本体内に `! ` 行があれば拾われる）

対象166行には、単純な `! grep -q ... "$FILE"` 形に加え、パイプライン形（`! echo "$x" | grep -Eq '...'`、`! sed ... | sed ... | grep -qF '...'` など）、関数呼び出しの否定（`! skip_phase1 ...`、`! tracked_alive`）、否定形 `[[ ]]`（`plugins/statusline/tests/statusline-multi-account.bats:215,216,303`。`#284` が本 change の範囲と明記した3箇所）が含まれる。いずれも行末に ` || return 1` を追加するだけで対応できる（構文上の特別扱いは不要）。

**採用3: 実演テストはバージョン分岐しない**

`#284` の実演テストは bash 4.1 未満／以降で検証内容を分けたが（`[[ ]]` の穴がバージョン依存のため）、`! cmd` の穴はバージョンに依存しないため分岐は不要。ガード無しの fixture が常に素通りする（`ok`）こと、ガード付きの fixture は常に `not ok` になることを、バージョン判定・`skip` 無しで確認する。

**採用4（実装上の注意）: 新設テストの fixture はソース上に行頭 `! ` を出現させない**

`#284` の「採用3」と同じ理由。ガード対象の実演テストを追加するファイル（既存の `tests/bats-assertion-guard.bats` を拡張する）自体も `git ls-files '*.bats'` の対象であり、本 change の新設スコープ検査（上記grep）にも掛かる。ガード無し fixture の `! cmd` をソースに直接 `  ! true` のような単独行として書くと、その行が新設スコープ検査に恒久的にヒットする。`#284` と同じく `printf`/`echo` で組み立てて子プロセス用の一時ファイルへ書き出し、追加先のソース上に行頭 `! ` の行を出現させない。

## Risks / Trade-offs

- [Risk] 166行という規模の機械的編集は対象行の見落としの可能性がある → Mitigation: スコープ検査 grep を常設テストにし、`git ls-files` ベースで対象ファイルを動的に列挙するため新規ファイル追加時も自動で拾う。
- [Risk] ガードを付けた結果、これまで見逃されていた本物のバグに当たり、対象テストが赤くなる可能性がある → Mitigation: この PR 内で実装側の欠陥を直し、`bash scripts/test.sh` 全件 green を受け入れ条件に残す（先送りしない。理由は proposal.md「Impact」）。
- [Risk] スコープ検査 grep（2段パイプライン）が今後の書き方（パイプライン途中の `! cmd`、複数行にまたがる `! cmd` など）を正しく除外し続けられる保証はない → Mitigation: 対象166行では実測でいずれも0件であることを確認済み。将来これらの書き方が増えて grep の誤検知/見逃しが問題になったら、その時点で別途 issue を切ってスコープ検査を強化する（本 change のスコープ外）。
