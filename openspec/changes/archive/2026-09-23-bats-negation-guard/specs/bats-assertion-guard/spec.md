## ADDED Requirements

### Requirement: 単独文の否定検査 `! cmd` はすべてガードされている
`git ls-files '*.bats' ':(exclude)_longruns/'` で見つかる bats ファイルのうち、単独の文として置かれた否定検査 `! cmd`（`! [[ ... ]]` を含む）は、テスト本文中の位置を問わず（最後の文も含む）すべて `|| return 1` のガードを伴わなければならない（SHALL）。検査は行末が `|| return 1`（末尾コメント可）のものだけを通すため、`|| return 2` や `|| false` 等の代替表現は違反として扱う。

対象の定義: ①対象は git 追跡下の bats ファイル（`git ls-files '*.bats' ':(exclude)_longruns/'`）、②拾いたい誤りは単独文として置かれた否定検査 `! cmd` のガード漏れ、③この grep が通す（対象外として扱う）ことを許す入力は `if`/`while`/`elif`/`until` の条件式として使われる `! cmd`（行がそれらのキーワードで始まるため行頭 `! ` に一致しない）・パイプライン途中に置かれた否定（`cmd1 | ! cmd2` のように行頭が `!` でない形）・行頭が `||` 等で始まる行（前の文への継続として扱われ行頭 `! ` に一致しない）・既に `|| return 1`（末尾コメント可）で終わる行（ガード済み、2段目の grep が除外する）の4種、④この grep 1本で塞ぎ切ることを完了条件にはしない（design.md「Risks」）。

複数行にまたがる `! cmd \`（1行目が行頭 `! ` に一致するため拾われる）・複数行の `if`/`while`/`elif`/`until` 条件式の2行目以降が `! ` で始まる場合・ヒアドキュメント本体内の `! ` で始まる行は、上記の「対象外」ではなく、この grep に誤って拾われる。したがって bats テストではこれらの書き方をしない（1行にまとめる、または `printf`/`echo` で組み立てる）ことを規約とする。

対象を `git ls-files '*.bats' ':(exclude)_longruns/' | xargs grep -nE '^[[:space:]]*! '` で実測した結果、35ファイル・179行が該当し、うち `plugins/cost-ledger/tests/gate-report.bats` の13行は既に `! cmd || return 1` の形でガード済みだった。残り34ファイル・166行を対象とし、いずれも継続行（`\` で終わる行）・複数行の条件式の2行目以降・ヒアドキュメント本体内の行には該当しないことを実測で確認した。

対象166行には `plugins/statusline/tests/statusline-multi-account.bats:215,216,303` の否定形 `[[ ]]`（`! [[ "$line" =~ ... ]]`）を含む（`bats-assertion-guard` の既存要件「単独文の `[[ ]]` アサーションはすべてガードされている」は行頭が `[[ ` で始まる行だけを対象とし、否定形は対象外としていたため、この要件で別途カバーする）。

#### Scenario: ガード無しの対象行が 0 件である
- **WHEN** 次のコマンドを実行する
  ```
  git ls-files '*.bats' ':(exclude)_longruns/' \
    | xargs grep -nE '^[[:space:]]*! ' \
    | grep -vE '\|\| return 1[[:space:]]*(#.*)?$'
  ```
- **THEN** 出力が 0 行である（末尾に `|| return 1` を伴わない対象行が存在しない）

#### Scenario: ガード対象の判定に位置を使わない
- **WHEN** テスト本文の中に単独文の `! cmd` を追加する
- **THEN** それがテスト本文の最後の文であっても、途中の文であっても、ガードが必要である（同じ要件が適用される）

### Requirement: `! cmd` のガード付き／無しの実演テストが常設されている
ガード付き fixture が常に fail し、ガード無し fixture が常に素通りすることを確認する実演テストが常設されていなければならない（SHALL）。`!` によるコマンドの反転は POSIX/bash の `errexit`（`set -e`）除外規則のひとつであり、`[[ ]]`/`(( ))` の非ゼロ終了と異なりバージョン依存の修正対象になっていない。したがって、この実演テストは `#284`（`bats-assertion-guard` の `[[ ]]` 向け実演テスト）と異なり bash のバージョンによる分岐を必要としない。

#### Scenario: ガード付き fixture はどの bash バージョンでも fail する
- **WHEN** 途中に `! true`（または相当する、常に成功するコマンドを否定して「アサーション違反」を模する否定検査。`! false` は否定すると常に成功側に転ぶため、失敗を模擬できず不採用）を `|| return 1` 付きで置いた fixture テストを子プロセスの bats で実行する
- **THEN** 実行した bash のバージョンに関わらずそのテストは fail する（`not ok` として報告される）

#### Scenario: ガード無し fixture はどの bash バージョンでも素通りする
- **WHEN** 途中に `! true`（または相当する、常に成功するコマンドを否定して「アサーション違反」を模する否定検査）をガード無しで置いた fixture テストを子プロセスの bats で実行する
- **THEN** 実行した bash のバージョンに関わらずそのテストは `ok`（素通り）として報告される（`skip` は発生しない）
