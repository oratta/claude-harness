## Context

動機は proposal.md の Why を参照。今の `risk-carryover-check.sh` は次の 2 か所で、リスクの中身と関係なく引き継げない側に倒れる。

- 判定 2: `git rev-list <新> ^<前> ^<base>` に merge commit でない commit が 1 件でもあると `NG: non-main commit ...`
- 判定 4: 根拠ファイルの `git diff --quiet <前> <新>` が空でないと `NG: evidence file changed ...`

3-c は終了コード 0 / 3 以外を主に聞く。主の決定（issue #1238 のコメント、2026-10-23）は、判定の基準を「ファイルが変わったか」から「リスク宣言の中身（リスク内容・発生条件・影響範囲と戻し方）が前と同じか」に移すことで、main から入った変更だけなら PR 自身の差分（merge-base との差分）を前後で比べれば機械的に決まる、とした。PR 自身の差分が変わった場合は判定役（`dev-workflow:decider`、`model: opus`）に比べさせるが、それは後続の change `risk-carryover-decider-judge` の範囲で、この change では主に聞く。

リスク宣言の中身の同一性は、今も 3-c の条件 4（新しい HEAD のレビューから組み立てた宣言の本文が、`対象 HEAD:` 行を除いて前と同一）で見ている。スクリプトが担うのは、根拠ファイル（リスクの根拠として宣言に挙げたファイル）の中で PR の変更が動いていないことの機械的な確認である。

## Goals / Non-Goals

**Goals:**

- main の取り込みで根拠ファイルが動いても、PR 自身の差分が前後で同じなら終了コード 0（または 3）で引き継げる
- 根拠ファイルに触れない PR 自身の commit（W の修正・CI の直し）があっても引き継げる
- PR 自身の差分が変わった根拠ファイルを、ほかの引き継げない理由（`NG:`）と区別できる終了コード 4 で返し、後続の change が判定役に渡せる材料（ファイル名と行数）を出す

**Non-Goals:**

- 終了コード 4 を判定役に比べさせて引き継ぐこと（後続の change）。判定役に渡す行数の上限（後続の change で決める。案は 100 行）
- 履歴の書き換え（rebase・force-push）をまたぐ引き継ぎ。今どおり判定 1 で `NG:`
- 3-c の条件 2〜4（根拠ファイルの行・真正性・宣言の本文の一致）を変えること

## Decisions

### 決定 1: PR 自身の差分は、各 HEAD と base の merge-base からの差分にする

前は `git diff <merge-base(前, base)> <前> -- <f>`、新は `git diff <merge-base(新, base)> <新> -- <f>` を比べる（`git diff <base>...<HEAD>` と同じ範囲）。base は今どおり `--base`（既定 `origin/main`）で、手順 1 の fetch のあとの値を使う。前の HEAD の merge-base は、前の HEAD が最後に取り込んだ main の commit（取り込んでいなければ分岐点）になる。

- 代わりの案 A: `git diff <前> <新>` から main 側の変更を引く（main の commit ごとの差分を逆に当てる）。衝突解消が入ると引き算が定まらず、作りが重い
- 代わりの案 B: 根拠ファイルの中身そのもの（blob）を比べる。今の判定 4 と同じで、main が同じファイルを変えると必ず違いになり、#1245 型を救えない
- merge-base が 1 つに決まらないとき（criss-cross merge）は `NG:` にする。`git diff A...B` は複数あると 1 つを選ぶが、どれを選ぶかで比較が変わる。この運用（PR に main を merge する）では起きにくいので、主に聞く側に倒す

### 決定 2: 比べるのは `-U0` の削除・追加の行（と改行なしの印）を順序を保ったもの

`git diff -U0 --no-color --no-ext-diff --no-textconv <mb> <HEAD> -- <f>` の、mode の行（`old mode`・`new mode`・`new file mode`・`deleted file mode`。mode だけの変更を拾うため）と、最初の `@@` の行より後ろにある `-`・`+`・`\`（`\ No newline at end of file`）で始まる行だけを、出てくる順のまま取り出し、前後で文字列として比べる。ハンクの見出し（行番号）・`diff --git` / `index` / `---` / `+++` の頭の行・文脈の行は比べない。

- 理由: main がファイルの別の場所を変えると行番号がずれ、PR の変えた行の近くを変えると文脈の行が変わる。どちらも PR 自身の変更の中身ではないので、比べると #1245 型の多くが終了コード 4 に落ちる。PR が足した行・消した行の並びが同じなら、PR がそのファイルに入れた変更は同じと読める
- 頭の行を「最初の `@@` より後ろ」で切るのは、消した行の中身が `-- ` で始まると `--- ` の行と区別できないため（1 回の呼び出しは 1 ファイルなので、頭の行は最初の `@@` より前にしか無い）
- 代わりの案 C: 文脈つきの差分をそのまま比べる。main が PR の変えた行の 3 行以内を変えるたびに違いになる
- 代わりの案 D: `git patch-id --stable`。行番号は無視するが文脈の行を含むので案 C と同じ弱さがあり、出力が 1 つのハッシュで、違ったときに何が違うかを示せない
- 失うもの: 位置を見ないので、同じ行の並びをファイルの別の場所へ動かした変更は同じと判定される。衝突解消で PR の行を別の関数へ移すような変更で起きうる。条件 4（新しい HEAD のレビューから組み立てた宣言の本文の一致）が残るので、これだけで別のリスクが通るわけではない。逆に、main の変更で差分の切れ目（どの行を消して足したと見るか）が変わると、中身が同じでも違いになる。これは終了コード 4 で主に聞く側に倒れるだけ
- バイナリの根拠ファイルは `-U0` の差分に `@@` が出ず、取り出す行が前後とも空になって「同じ」と誤る。前後の diff が空でない根拠ファイルのうち、前後の HEAD の diff、または各 HEAD の PR 自身の差分（merge-base からその HEAD まで）のどちらかでバイナリとして扱われるものは比べずに `NG:` にする（`git diff --numstat` が `-	-` を返すことで見分ける。merge-base の版だけがバイナリで PR がテキストに置き換えた場合も、PR 自身の差分が前後とも空になって「同じ」と誤るため）

### 決定 3: merge commit でない commit を `NG:` から外す

判定 2 から「merge commit でない commit がある」を外し、件数を `PR_COMMITS=` で出す。merge commit については今の条件（2 親・第 2 親が base の祖先・第 1 親が PR の履歴の中）を残す。

- 理由: これを残すと、PR 自身の修正が入った HEAD は根拠ファイルに触れていなくても必ず `NG:` になり、主の決定（ファイルが変わっても、リスクの中身が同じなら聞き直さない）を PR 自身の修正の場合に当てられない。issue #1238 本文の実例（別リポジトリの PR。CI の直しの commit）もこの判定で止まる。本文の前提（根拠ファイルの変更だけが `NG:` の理由になる）との食い違いは記録先にコメント済み（issue #1238 の 2026-10-23 のコメント）
- 外しても安全側が残る理由: (1) 根拠ファイルの PR 自身の差分が変われば終了コード 4 になり、この change では主に聞く。(2) 根拠ファイル以外への修正でリスクの中身が変わったかは、3-c の条件 4 が、新しい HEAD のレビュー（W の修正を読んだ再レビュー）から組み立てた宣言の本文の一致で見る。ここは今の main の取り込みの場合と同じ守り方で、新しい仕組みではない
- 代わりの案 E: 判定 2 は残し、main の取り込みの場合（#1245 型）だけを救う。PR 自身の commit が入る型（issue #1238 本文の実例）は後続の change でも救えない（判定役を呼ぶ条件「根拠ファイルの変更だけが NG」に入らない）
- 代わりの案 F: merge commit でない commit のうち、根拠ファイルに触れたものだけを `NG:` にする。終了コード 4 と役割が重なり、後続の change で判定役に渡す経路に乗らない
- 履歴の書き換え（判定 1）は残す。前の HEAD が祖先でないと前の HEAD の SHA が手元から消えることがあり、何を許容したかを git で確かめられないため

### 決定 4: 終了コード 4（`CARRYOVER=if-judged`）と優先順 1 → 4 → 3 → 0

`NG:` が無く、`EVIDENCE_PR_CHANGED=` に当たる根拠ファイルが 1 つでもあれば終了コード 4 を返す。

- 別の終了コードにする理由: G は終了コードで分岐する（出力の行を読み違える前提で扱う）。`NG:` の一種にすると、後続の change で「判定役に渡してよい理由だけか」を G が `NG:` の文から読み分けることになる。issue #1238 の受け入れ条件「他の引き継げない理由と区別できる終了コード」にも当たる
- 1 を最優先にする理由: `NG:` がある時点で判定役に比べさせても引き継げない（履歴の書き換えなどは中身の比較で救えない）
- 4 を 3 より先にする理由: 4 は判定が要り、3 はレビューの確認が要る。重なったときに 3 を返すと判定が要ることが落ちる。4 のときも `RESOLVED_OUTSIDE_ALLOWLIST=` の行は出すので、後続の change で両方を確かめられる（この change では 4 は主に聞く）
- `EVIDENCE_DIFF_LINES=` は `EVIDENCE_PR_CHANGED=` のファイルについての `git diff --numstat <前> <新>` の追加と削除の合計にする。後続の change で判定役に渡す差分と同じ範囲（前後の HEAD の diff）で数えるため。無ければ 0 を出す（行が常にあるほうが読み違えにくい）
- 2 は今どおり（引数・環境の不備）。0〜3 の意味は変えない

### 決定 5: 3-c では終了コード 4 を主に聞き、理由に `EVIDENCE_PR_CHANGED=` の行を添える

後続の change が入るまでの扱い。主に聞く件数は今より増えない（今は同じ場合が終了コード 1 で主に聞いている）。引き継ぎの根拠の行には `PR_COMMITS=` の件数と、根拠ファイルが「diff は空」か「main からの変更だけ（`EVIDENCE_MAIN_ONLY=` のファイル）」かを書く欄を足す。4 行の構造と行頭（`引き継ぎの根拠: risk-carryover-check.sh 終了コード `）は変えない（`pass.md` の合格条件の表と既存の bats がこの行頭を見る）。

## Risks / Trade-offs

- [main 側の変更が PR のリスクの前提を変える（例: PR が頼る関数の振る舞いを兄弟の PR が変えた）] → 主の決定で受け入れる（main から入った変更だけなら聞き直さない）。main の変更はそれぞれのゲートを通っている。新しい HEAD のレビューで新しいリスクが見つかれば、条件 4 の本文の一致が外れて主に聞く
- [根拠ファイルの列挙が漏れていて、漏れたファイルへの PR 自身の修正がリスクを変える] → 今の守備範囲（「G が根拠ファイルを列挙し損ねた宣言」は通ることを許す入力）のまま。条件 4 が新しい HEAD のレビューから宣言を組み立て直すので、レビューが見つければ止まる
- [位置を見ない比較で、行の移動を同じと判定する] → 条件 4 が残る。起きる頻度は確かめていない（過去の引き継ぎで衝突解消が根拠ファイルに及んだ PR を数えれば分かる）
- [差分の切れ目が変わって中身が同じでも終了コード 4 になる] → 主に聞く側に倒れるだけ。後続の change で判定役が比べる対象になる

## Migration Plan

- スクリプトと 3-c の文面を同じ PR で直す（終了コード 4 を知らない古い 3-c は、4 を 0 / 3 以外として主に聞くので、片方だけが先に入っても引き継ぎすぎる側には倒れない）
- 既存の宣言・引き継ぎの記録は書き換えない。引き継ぎの根拠の行を機械で読むのは `pass.md` の表（行頭だけ）と bats だけ
- 戻すときは PR を revert する（データの移行は無い）
