## Context

#1519 の項目 1 は、親が private で G のトークンが読めない 404 を「親が無い」と読む問題について、「守備範囲の許す誤りに足すか、手順の文を直すか」の選択を残している。

## Decisions

- 項目 1: 守備範囲の許す誤りに足す（「親が見えず 404 になる場合」）。理由: `/parent` の 404 は `No parent issue found` と、親は有るが読めない場合で応答が同じで、G は区別できない。手順の文で区別させる手段が無く、既存の「記録先 issue 自体が見えない 404」の許容と同じ型なので、その行を広げる。受け入れ条件 3 の語句もこの選択を前提にしている。
- 項目 8: 守備範囲の許す誤りに足す。理由: 別リポジトリの親では全候補を `other` と読むため確かめない、という既存の手順のとおりで、手順の文は直さない。
- 項目 4 の 1 句は、`## 条件の答え` を読み書きする 3 箇所（gate-runner.md・reviewer-brief.md・spec の同じ文）で同じ語句にする: 「親が別リポジトリなら親のリポジトリの本文（`stages/triage.md` の段 C の段落）」。
- spec の文と triage.md の文は同じ語句で揃え、同じ commit で直す。

## Risks

- 文面だけの変更で、判定の骨格は変わらない。語句の食い違いは bats の grep で検出する。
