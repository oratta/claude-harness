# Design

## Context

#1752 / 親 #1732。PR #1749 の merge commit `b29859fa` は開始 HEAD `47ba8764` の祖先である。動機は proposal の Why を参照。

`keepalive_screen_reason` は一意な入力枠を解決後に `wait_state` を求め、最後の既知の完了行から上罫線までに空行・既知 recap 以外があれば `unknown` とする。送信後もこの値で早期終了するため、完了行の後ろに送信文エコーや新しいスピナーが現れると空欄検査へ進めない。現行関数を匿名の合成画面で再生し、送信前の待機→完了は `ready`、送信後の待機→完了→エコー→前景スピナーは `skipped unknown-state`、待機履歴なしの同じ前景スピナーは `busy-empty` と確認した。これは退行の再現で、修正後のテスト成功ではない。

前提環境は既存の bash / python3 / jq / Orca CLI、接続済みの子端末、実装検証用 bats。実機検証には通常の声かけ条件を満たす停止中の子と外部の会話ログが別途必要である。

## Goals / Non-Goals

**Goals:** 履歴の待機解除を送信許可の責務に限定し、送信後の到達確認は独立した証拠で行う。入力全体の空欄検査と一度だけの送信を保つ。

**Non-Goals:** 未観測フッターの認識拡張、送信文エコーの内容による成功判定、完了の返事だけによる到達判定、tmux / dispatch の変更、実機 send・cache 利用を fixture で代替すること。

## Decisions

### 一つの設計判断: 送信前の待機解除と送信後の到達確認の責務を分ける

既存の JSON / source / 枠・フッター解決と入力全体・任意 draft の検査を共通に保つ。初回と送信直前の二度の観測は、既存どおり `wait_state` を使い、未解除の待機を busy、完了後の余分な行を unknown-state とする。送信前の許可集合は広げない。

send exit 非ゼロは `failed send`、exit 0 で `turn_started` があれば既存どおり `sent`。それ以外は一度だけ同じ端末を read し、以下をすべて満たす場合だけ `sent` とする。

1. 正常な `result.terminal`、source=screen、一意な既知入力枠と既知フッターがある。
2. dialog が無く、入力領域全体が空で、draft があれば空文字である。
3. 送信前には無かった既存の前景実行表示（既知のスピナー、または `esc to interrupt`）がある。

送信後の分岐は `wait_state` の none / busy / released / unknown を成功にも失敗にも流用しない。背景待機行だけ・エコーだけ・完了行だけでは条件3を満たさない。入力枠に含まれる待機文・エコーは通常の入力として条件2で拒否する。未知の枠・フッターは条件1で拒否する。履歴判定の除外を、枠の曖昧さや入力検査の除外へ広げない。

`after-send` モードで履歴解除を到達条件にしないようにして、残りの共通検査を通した後だけ既存の `busy-empty` を返す小さな変更を想定する。内部関数の分割は必須でない。`cmd_keepalive` の二度の事前観測・一度の send・必要時一度の事後観測と結果語を変えない。

代案:

- 完了後に許す行へ送信文エコーやスピナーを足す: 送信前の許可範囲まで広がり、本文の表示形式に依存するので採らない。
- send exit 0 / エコーだけを成功にする: 受付だけで未到達でも成功になるので採らない。
- `turn_started` だけを認める: unsupported provider で画面上の到達証拠があっても失敗になるので採らない。

### 既存制約を具体化する検証の扱い

P2-F2（非bypass実行中に既知のフッター印が無い可能性）は未確認で、認識規則を追加しない。2026-11-23、Orca 1.4.269 で `orca terminal list --limit 100 --json` を実行し、対象リポジトリの agentIdentity=claude の10端末を `orca terminal read --terminal <handle> --screen --json` で読み取った。10件とも source=screen で bypass 表示があり、非bypass候補は0件、一覧 truncated=false。読み取り専用で、モード切替・送信・入力消去・端末作成は行っていない。観測はその時点の対象端末に限られ、非bypass画面が存在しないという証明ではない。

未知フッターの合成テストは「送信前は送らず、送信後は成功にしない」の回帰としてのみ使い、非bypassの実測 fixture と称しない。後に該当実画面を観測して対応するなら、版・取得コマンド・匿名化した構造を添えて別途レビューする。P2-F2の未確認は return と issue にも残す。

P1-F3と実機確認の手順は親専用 `epic-keepalive-watch.md` に置く。背景エージェント待機中の子の `skipped busy` は正しい非送信として扱い、到達失敗のサンプルにしない。別の会話15万トークン未満・入力待ちの子を選び、既存のTTL/時刻/停止/未回答などの条件を満たさなければ待つ。候補が無いことを成功に置き換えない。

## Risks / Trade-offs

- 送信前観測と送信の間に別の入力が入り、偶然前景ターンが始まる競合 → 二度の事前観測と事後の空欄検査を維持する。原子的な排他までは保証しない。
- 返事が速く事後観測で busy を見られない → `turn_started` も無ければ `failed send` を維持し、再送しない。
- P2-F2の未知フッターは到達しても確認不能 → 未確認・未対応として残し、推測で枠の認識範囲を広げない。
- 履歴に古い実行表示が残る可能性 → 同じ判定が送信前に一度でも busy なら send へ進めない。未知の画面形全てを塞ぎ切ることは完了条件にしない。

## Migration Plan

独立仕様レビューで案を確定した後に実装と回帰テスト、親向け手順、変更記録を作る。状態データ移行は不要。切り戻しは実装 commit の revert とする。仕様段では main spec や実行コードを編集しない。

マージ後の実機検証は tasks の別欄に残す。選んだ子の識別子・会話量・入力待ち/背景待機の区別・送信結果・予約文への返事・その後の request の `cache_read_input_tokens` と会話量の比較を #1728 と #1732 に記録する。生ログはリポジトリへ保存せず、保存が必要なら `LLM_LOG_DIR` を使い、未設定なら保存先を確認する。fixture 成功やCLI送信の exit 0 だけで実機 send / cache の成功を宣言しない。
