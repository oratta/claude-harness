## Context

主に問いを返す文章の書き方の正本は `output-styles/readable.md` の節 3（「判断を求めるときは、質問から書いて、推奨まで出す」）で、PR #1179 で 6 段の型に直した（capability `owner-question-style`）。正本は Output Style として、短い版の `rules/communication-style.md` はルールとして常時載っているが、主が「わからん」と返したその瞬間に、直前の説明を型で書き直すよう促す仕組みは無い。親エピック #1176 は、この促しを `UserPromptSubmit` hook（主が発言を送るたびに走る hook）で差し込むと決めた。

既存の hook の置き方（2026-10-21 時点）:

- hook を持つプラグインは capability-registry・cost-ledger・dev-workflow・statusline・worktree。`UserPromptSubmit` を使っているのは dev-workflow だけで、`prompt-tripwires-refresh.sh` を 1 件登録している
- `rules/` と `output-styles/` はプラグインではなく `scripts/sync.sh` が `~/.claude/` に symlink を張る置き場で、hook を持てない
- dev-workflow の hook のスクリプトは `plugins/dev-workflow/scripts/<名前>.sh` に置き、`hooks/hooks.json` から `"${CLAUDE_PLUGIN_ROOT}/scripts/<名前>.sh"` で呼ぶ。python3 を使うときは `python3 -I`（`tests/hook-python-isolation.bats` が hooks.json の配線先を列挙して検査する）
- 既存テスト `plugins/dev-workflow/tests/prompt-tripwires-refresh.bats` は `UserPromptSubmit` の 1 件目のエントリが `prompt-tripwires-refresh.sh` であることを確かめている

## Goals / Non-Goals

**Goals:**

- 主の発言に説明が伝わっていない合図の語があるときだけ、正本の型で言い直すよう促す文を差し込む
- 差し込む文は正本の場所を指し、型の中身を写さない（型を直すときに直す場所を正本 1 か所に保つ）
- 毎発言で走るので、語が無い発言ではほぼ時間を使わない。どんな入力でも発言の送信を止めない

**Non-Goals:**

- 言い直しの出来（型を守ったか）を検査すること。hook は促すだけで、出力は見ない
- 語の一覧で伝わらなかった場面をすべて拾うこと（取りこぼしは許す。下の「語の選び方」）
- 無効にする環境変数などの切り替え。差し込みは語に当たったときの 1 文だけで、邪魔になった実例が出てから考える
- 親エピック #1176 のもう一方の子 #1183 の範囲（子の停止の記録・手順 8・parent-pass-criteria.md）と issue #1181

## Decisions

### 置き場所: dev-workflow プラグインの hooks.json に、別スクリプト・別エントリで足す

- **dev-workflow を選ぶ理由**: `UserPromptSubmit` の hook を既に持つ唯一のプラグインで、言い直しが起きた 9 場面はどれも develop のエピックの親の発言だった。issue #1184 も dev-workflow を想定している。公開版と個人版の仕分け（`docs/public-private-split.md`）で、新しいスクリプトは行 `plugins/dev-workflow/` の「公開版」に入り、行を足す必要が無い
- **選ばなかった案 1 — 新しいプラグインを作る**: 正本は全セッションに効く書き方なので独立したプラグインにする筋はあるが、プラグイン 1 本ぶんの marketplace.json・plugin.json・README・仕分けの表の行・テストの置き場が増える。スクリプト 1 本のためには重い
- **選ばなかった案 2 — casting プラグインに置く**: 主に上げるかの判定を持つが、hooks を持っておらず、casting が入っていない環境では効かなくなる。正本の節 3 も casting を「入っていれば」の条件つきで扱っている
- **選ばなかった案 3 — `prompt-tripwires-refresh.sh` に書き足す**: あちらはプラグインの更新を見て再注入する別の責務で、状態ファイルを持つ。混ぜると片方を直すときにもう片方のテストが巻き込まれる
- **エントリの位置**: `UserPromptSubmit` の配列の 2 件目に足す（1 件目は `prompt-tripwires-refresh.sh` のまま）。既存テストが 1 件目を見ているのと、2 つの hook は互いに依存しないため。`UserPromptSubmit` は matcher を取らないので付けない。`timeout` も付けない（語が無い発言では python3 を起動せずに終わる）

### 語の選び方: 狭い語の一覧＋差し込む文を「新しい依頼ならそれに答える」で締める

語は発言の本文に部分一致で探す。一覧は次のとおり（ひらがな・漢字の両方の表記を並べる）。

| 合図 | 語 |
|---|---|
| 意味が取れないと言う | `意味わから`・`意味分から`・`意味がわから`・`意味が分から`・`意味不明` |
| 分からないと言う | `わからん`・`分からん`・`解らん`・`わかんない`・`分かんない` |
| 説明を求め直す | `説明して` |
| 読めないと言う | `読みにくい`・`読み難い` |
| 伝わっていないと言う | `伝わらない`・`伝わってない`・`何言って`・`なに言って` |

- **入れなかった語**: `わからない`・`分からない` だけの形は、「原因がわからない、調べて」のように調査の依頼で頻繁に出るので入れない（`意味がわからない` は `意味がわから` で拾う）。issue に例として挙がった `意味が` だけの形は、「やる意味がない」「意味が違う」で当たるので、`意味がわから`・`意味が分から` に絞る。`論点` は「論点もなしに意思決定できると思ってんの？」で使われたが、普通の議論でも頻繁に出るので入れない
- **誤検出の扱い**: `説明して`（「この関数を説明して」）や `わからん`（「なんで落ちるかわからん、調べて」）は、直前の説明とは関係のない新しい依頼でも当たる。語を狭めすぎると肝心の場面を取りこぼすので、語は残し、差し込む文の最後に「主の発言が新しい依頼なら、その依頼に答える」を置いて、誤って当たったときの害を「1 文読み流す」程度にする
- **見ない部分**: 3 つの逆引用符（```）で囲まれたブロックの中と、`>` で始まる引用の行は探さない。貼り付けたログや Claude の文の引用に語が入っていても当てないため。主が引用の外に「これ意味わからん」と書けば、そちらで当たる
  - ブロックの開きは、行頭の空白のあとが ``` で始まる行（```bash のように言語名が続いてもよい）。閉じは、次に同じ条件の行が来たところ（Markdown の閉じは言語名を持たないが、言語名つきの行で閉じたとみなしても、貼り付けの中でそうなる例は少なく、判定を単純に保つほうを取る）。閉じが来なければ発言の終わりまでをブロックとみなす（閉じ忘れた貼り付けの中の語で当てないため。閉じ忘れの後ろに主が書いた語は取りこぼすが、取りこぼしは hook が無い今と同じ状態）
- **複数の語に当たったとき**: 表の上から（spec の語の一覧の順で）最初に当たった語を 1 つ示す。「意味わからん」は `わからん` にも当たるので、長くて意味の分かる `意味…` の語を一覧の先頭に置いた
- **取りこぼしの扱い**: 一覧に無い言い方（「は？」「どういうこと」など）は拾わない。「どういうこと」は普通の質問でも多く出る。取りこぼした場面は今の状態（hook が無い）と同じなので、実際に取りこぼした発言が見つかったら一覧に足す

### 差し込む文: 正本の場所を指すだけ。型の中身を写さない

差し込む文は次の内容の固定文で、当たった語だけを差し替える。

> 主の発言に、直前の説明が伝わっていないことを示す語（「<当たった語>」）がある。直前の説明は伝わっていないものとして扱い、`~/.claude/output-styles/readable.md`（Output Style `readable`）の節 3 の型で、子の作業の言葉や仕組みの名前を使わずに言い直す。主の発言が新しい依頼なら、その依頼に答える。

- 正本のパスは `~/.claude/output-styles/readable.md` の形で書く。capability `owner-question-style` の要件が、プラグインから正本を指すときにこの形を求めている（プラグインは他のリポジトリから読まれるので、リポジトリ相対パスは辿れない）。公開版の制約（固有名とオーナーの PC のパスを書かない）にも当たらない
- 6 段の名前（「主に聞く理由」「受け入れるリスク」など）や理由の 3 つは書かない。書くと正本を直したときにこの文が古くなる。テストで、文にそれらの語が無いことを確かめる
- 出力は `{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":"…"}}` の JSON 1 つ。`decision` や `continue` は返さない（発言を止めない）

### 実装: 生の入力への grep で先に振り分け、当たったときだけ python3 で読む

- 毎発言で走るので、まず標準入力の生の JSON に `grep` で語の一覧を当てる。どれにも当たらなければ python3 を起動せずに exit 0（`prompt-tripwires-refresh.sh` と同じ考え方）
- Claude Code は日本語をそのまま UTF-8 で JSON に書く。念のため、`\u` の形の逃がし（`\u3042` など）が入力にあるときも python3 に回し、JSON として読んでから探す
- python3（`-I` 付き）で `prompt` を取り出し、逆引用符のブロックと引用の行を除いてから語を探し直す。当たれば JSON を出す
- JSON が壊れている・`prompt` が無い・文字列でない・python3 が無い、のどれでも何も出さず exit 0

### 常時注入の予算への影響: 増えない

`tests/injection-budget.bats` が測るのは `rules/`・`CLAUDE.md`・`output-styles/`・各種 `description` で、hook のスクリプトと hooks.json は測る対象ではない。この change は rules・output-styles・description を変えないので、予算ファイル `tests/injection-budget.txt` は動かさない。差し込みは語に当たった発言のときだけ 1 回約 500 バイト（日本語約 160 文字）載る。

## Risks / Trade-offs

- [誤検出: 新しい依頼の「説明して」「わからん」で当たる] → 差し込む文の最後で「新しい依頼ならその依頼に答える」と書く。起きたときの害は、文脈に 1 文（約 500 バイト）増え、Claude が直前の説明を言い直すか迷う程度。頻度は分からない。調べるなら、会話ログ（`~/.claude/projects/` の jsonl）の主の発言に語の一覧を当てて、当たった発言のうち新しい依頼だったものの割合を数える
- [取りこぼし: 一覧に無い言い方で伝わらなかったと言われる] → hook が無い今と同じ状態に留まるだけ。見つかったら語を足す
- [`claude -p` で起動した子のセッションでも走る] → 子に渡す指示文に語が入っていれば当たる。差し込む文が条件つきなので、子は新しい依頼（指示文）に答える。サブエージェントの起動では `UserPromptSubmit` は走らない
- [正本の節の番号が変わる] → 差し込む文は「節 3」と書くので、正本の節の並びを変えたらこの文も直す必要がある。テストで、正本に `## 3. 判断を求めるときは` の見出しがあることを確かめ、ずれたらテストが落ちるようにする

## Migration Plan

マージ後、各環境でプラグインが更新されると次の発言から効く。戻すときは hooks.json のエントリとスクリプトを消す PR を出す（状態ファイルは持たないので、後片付けは無い）。
