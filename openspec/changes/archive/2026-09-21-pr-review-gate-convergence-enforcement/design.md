## Context

pr-review-gate の収束ルールは「既定 2 周・再レビューは差分限定・3 周目は新規の高深刻度 blocking のみ・マージ後に直せるものは blocking にしない」の 4 行で、誰がいつ適用するかが書かれていない。PR #268 では G が Codex の深刻度ラベルをそのまま blocking と扱い、毎周新しい軸の指摘が出て 5 周続いた。途中で W が方式ごと書き換えたのに再レビューは差分限定のままで、書き換えた部分の新しい問題が「新規の高深刻度」として次の周を正当化し続けた。

方針は 2026-09-11 に主が承認済み（issue #281 のコメント「方針の確定」の PR-A）。この design はその方針を SKILL.md と gate-runner.md にどう落とすかだけを決める。

## Goals / Non-Goals

**Goals:**

- 2 周目の終わりに G がやることを、判定材料（受け入れ条件と spec の原文）込みで手順にする
- 3 周目を自動で開けない。開くのは主が「続ける」と答えたときだけにする
- 方式の書き換えの後でも差分限定のせいで見落とさない、かつ周回のリセットで無限に続かないようにする

**Non-Goals:**

- R1 の観点に守備範囲を足す（#287）
- PR 単位のトークン累計で止める（#288）
- 指摘 1 件の固定書式（#349。この change のマージ後にその上に載せる）
- 決める役の出力契約（`agents/decider.md`・`tests/decider-agent.bats`）の変更
- pr-review-gate 手順 2-2（原因分類とモデル昇格）の変更

## Decisions

**判定を「引用できるか」にする（深刻度ラベルを使わない）。** 深刻度はレビュアーが付けるもので、Codex は毎周新しい軸で「高」を付けられる。引用は記録先の受け入れ条件と spec という PR より前に決まった文に対して行うので、周を重ねても基準が動かない。代案の「高深刻度の定義を細かくする」はルール追加で、今回の原因（適用されなかった）を直さないので採らない。既存テストが固定する「高深刻度」の語は「深刻度ラベルは参考にとどめる」の文脈で残す。

**引用元は記録先の受け入れ条件と、この PR が触れる spec（delta spec を含む）に限る。** 「仕様の守備範囲」を広く取ると、無関係な spec の一文を引いて blocking にできてしまう。守備範囲の明記そのものは #287 で R1 側に足すので、この change では引用元の範囲だけを固定する。

**引用できる指摘が残ったら failed ではなく保留（`needs-approval`）で返す。** failed で返すと本体は W を再開して修正サイクル（実質の 3 周目）に入る既存の流れになる。保留なら本体は主に 1 アクションで依頼する既存の流れに乗る。主が「続ける」と答えたら 3 周目を開き、「範囲外として閉じる」なら指摘を follow-up issue に切って手順 3 へ進む。この復帰は SKILL.md 手順 6 の復帰表に保留種別「2 周目キャップ」の行として足し、どちらの回答でも `needs-approval` を外すことを明記する（既存の復帰表が「needs-approval を外す/残すを明示的に選ぶ」を義務にしているため）。

**決める役を挟まない。** 挟むと Fable のターンを使い、しかも「どう直すか」を答えさせることになり、PR #268 で 998 行の書き換えが起きた経路そのものになる。キャップの判定は引用の有無で機械的に決まるので、判断役は要らない。

**方式の書き換えの判定は G が再レビュー開始前に行い、2 つの行数を記録する。** 「大きく超える」の閾値は数値で固定しない（承認済み方針の文言のまま）。代わりに G が判定に使った 2 つの行数（修正の差分行数と前周の指摘の対象行数）を PR コメントに残し、後から判定の妥当性を確かめられるようにする。周回を数え続けるので、全体レビューにしても上限は 2 周のまま変わらない。

**gate-runner.md の `周回:` 欄は `<1|2|3以降（主の続行指示あり）>` の形にする。** 3 周目以降は主の続行指示があったときだけ存在するので、その条件を欄の書式に含める。全体レビューにした周は同じ行に「（全体レビュー: 差分 N 行 / 前周指摘 M 行）」を添える。

## Risks / Trade-offs

- [無人運用で自動で片付く PR が減る] → 主が承認済みのトレードオフ。止まった PR は `needs-approval` で一覧でき、主は 1 択に答えるだけでよい
- [G が引用を甘くして何でも引用できるとする] → 引用は原文そのままを PR コメントに残すので、主と後続のレビューで検証できる。引用の質の固定は #349（指摘の固定書式）で補う
- [「大きく超える」の判定が G ごとにぶれる] → 2 つの行数を必ず記録する。ぶれが実害になったら数値閾値を別 issue で決める
- [dev-workflow-develop の spec に「修正後は G を再開して差分再レビュー（2 周）」の文があり、全体レビューの例外と字面がずれる] → 周回数 2 は変わらず、再レビューの範囲は pr-review-gate の収束ルールが正本という読み方で整合する。この change では dev-workflow-develop の spec を変えない（承認済み方針の触るファイルに入っていないため）
