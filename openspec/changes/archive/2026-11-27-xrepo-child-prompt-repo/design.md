# Design

## Context

最初の入力の形に依存しているところは 3 つある（2 つ目の `epic-child-state.sh` は聖域パスで、この change では変えない）。

1. `owner-reply-check.sh` の `DISPATCH_ARGS`（`<command-args>\s*#\d+\s*（エピック #\d+ の子。`）。親が打った起動の指示を主の発言として数えないための判定
2. `epic-child-state.sh` の `startup()`。子のターン状態のフックが、起動の指示を `sender: startup` と分類する。子の側は `/develop (<repo>#|#)<N>` を既に受けるが、エピックの側は `（エピック #<E> の子。` しか受けない。エピックの repo は `エピックのリポジトリ X。` の句から読み、無ければ「子とエピックが同じ repo」と見なす
3. tmux の部品の届いたかの確かめ（送った文の引数の先頭 40 文字で会話ログを照合する）。文字列の比較なので、形が変わっても働く

## Goals / Non-Goals

Goals:
- 別のリポジトリの子の最初の入力と起動し直しの指示で、子の番号がリポジトリ付きで書かれ、エピックのリポジトリが「エピックのリポジトリ」の句で名指しされる
- 主の発言の判定と送り手の分類が、新しい形を起動の指示として扱う
- 同じリポジトリの子の入力は 1 文字も変わらない

Non-Goals:
- 同じリポジトリの子の表記を変えること
- 返事の頭（`親エピック #<E>（<repo>）の判断…`）を変えること
- 子のターン状態のフック（`epic-child-state.sh`）を変えること

## Decisions

### 子の番号だけにリポジトリを付け、エピックは今の句のまま（採用）

- launch: `prompt="/develop $crepo#$num （エピック #$epic の子。エピックのリポジトリ ${erepo}。親ワークツリー $parent から ${lname_label} で起動）"`
- 起動し直し: `prompt="/develop $(es_get "$rec" repo)#$(es_get "$rec" number) （エピック #$epic の子。エピックのリポジトリ ${xrepo_epic%%#*}。返事を受けて起動し直し） $msg"`

子が読み違える元（番号だけの子の表記）はこれで消える。`epic-child-state.sh` の `startup()` は、子の側の `<repo>#<N>` と `エピックのリポジトリ X。` の句を既に受けるので、このファイルを変えずに新しい形が `startup` になる。`tests/epic-child-state.bats` にその確認と、エピックの句の repo が記録と違えば登録・切替しない確認を足す。

受け入れ条件の例「エピック oratta/claude-harness#1810 の子」は、取り違えない書き方の例示として読む。満たすべきことは「文中のリポジトリ名が、エピックの側と子の側のどちらかを取り違えない」ことで、この形では子のリポジトリが番号に付き（`genetta-inc/flatmate#892`）、エピックのリポジトリが「エピックのリポジトリ oratta/claude-harness」と名指しされるので、どちらの名前がどちらの側かが文から一意に決まる。

### `DISPATCH_ARGS` を広げる

`<command-args>\s*(?:[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+)?#\d+\s*（エピック #\d+ の子。` にする。番号だけの形は今までどおり当たる。エピックの側は `#\d+` のままで、launcher が出す形だけに当てる。

### 退けた案: 子とエピックの両方の番号にリポジトリを付け、`エピックのリポジトリ` の句を外す

受け入れ条件の例の文字面にいちばん近いが、エピックの側の `<repo>#<E>` を受けるには `epic-child-state.sh` の `startup()` の正規表現を変える必要がある。このファイルは聖域パス（`.github/workflows/auto-merge.yml` の SACRED）で、触ると #1831 の PR が人間マージになる。エピック #1826 は #1831 を聖域に触らない子として組んでいる。さらに並列で回る #1821 が同じファイルを編集するので衝突する。採用案で受け入れ条件の中身（取り違えない書き方）を満たせるので、この案は採らない。

## Risks / Trade-offs

- 起動形を読むほかの部品が、この 3 つのほかにあると見落とす。`エピック #` と `/develop #` を grep して、`epic-child-state.sh`・`owner-reply-check.sh`・`child-log-read.py` のほかに無いことを確かめた。`child-log-read.py` は `/develop` で始まる行を丸ごと主の発言から外すので、形によらない
