## ADDED Requirements

### Requirement: レビュアーとゲートの担当は全体のテストを手元で回さない

`stages/reviewer-brief.md` の手順 2-1 のレビュアーへの姿勢は、テスト・lint を報告を信用せず自分で再実行することを保ったまま、再実行するのは変えたファイルに関係するテスト（この PR で足した・変えたテストのファイルと、テストのファイルのうち変えたファイルのパスかファイル名を含むもの）と lint に限り、テストの全体実行（テストランナーをファイルで絞らずに起動するもの）を手元で行わないことと、全体のテストの結果は作業者の結果か CI の結果を証拠にし、どちらも無いときは全体のテストの証拠が無いことを要約に書く（G が手順 4 で CI の結果を扱う）ことを書かなければならない（MUST）。区画に分けたレビューで再実行するのが区画 1 だけという既存の規則は変えない。

`stages/pass.md` の手順 4（動作確認）は、ゲートの担当がテストの全体実行を手元で行わないことを書かなければならない（MUST）。受け入れ条件が全体のテストの合格を求めるとき（例: 「`bash scripts/test.sh` が通る」）は、対象 HEAD に付いた CI の結果を証拠にし、次のとおり扱うことを書かなければならない（MUST）: 対象 HEAD の CI が成功していれば run の URL を結果の欄に書く。CI の結論がまだ無い（実行中、または Draft のため未実行）ときは、その状態と、合格後の CI の見張り（`references/ci-watch.md`）で結論を確かめることを結果の欄に書いて進めてよい。対象 HEAD の CI が既に失敗しているときは、結果の欄を成功の印にせず、失敗した run の URL と、合格後の CI の見張りで直しに回すことを書く。結論の無い CI や失敗した CI を成功として書いてはならない（MUST NOT）。関係するテストと lint の結果は、作業者が PR に載せた証拠を使ってよい（MAY）。auto-merge 未配備のリポジトリで、対象 HEAD の CI が失敗か未決着のときは、合格処理の後に残す「マージは人間の操作待ち」の 1 行に、CI の状態と、合格後の CI の見張りが結論を出すまでマージしない旨を添えなければならない（MUST）。

理由: 手元の全体実行は claude-harness で約 40 分かかり、#1208 ではレビュアーとゲートの担当もそれぞれ全体を回していた。CI は同じ中身を分けて短時間で回し、ゲートの合格後は本体が CI を見張って落ちたら直しに回す仕組みと、auto-merge の必須チェックが既にある。Draft では CI を走らせないリポジトリでも手順 4 が進めるよう、CI の結論を待たせない（#1211）。

この要件の守備範囲: 入力は、PR の変えたファイルの一覧、作業者が PR に載せた検査の証拠、`gh pr checks` で見える対象 HEAD の CI の状態である。拾いたい誤りは、レビュアーとゲートの担当が全体のテストを手元で回して待つことと、CI の状態を確かめずに全体のテストの受け入れ条件を成功と書くことである。CI の結論が出る前、または CI が落ちた HEAD で合格にした PR は、この要件では止めない（合格後の CI の見張りが、PR に関わる失敗なら直しに回して passed を外し、関わらない失敗ならやり直す。auto-merge を配備したリポジトリでは必須チェックが緑になるまでマージされない）。CI の結論を見ずに合格にした PR が落ちる場面を、ゲートの側で塞ぎ切ることは、この要件の完了条件にしない（見張りが拾う）。

#### Scenario: レビュアーへの姿勢が再実行の範囲を限っている

- **WHEN** `stages/reviewer-brief.md` の手順 2-1 の姿勢の文を読む
- **THEN** テスト・lint を報告を信用せず自分で再実行すること、再実行するのは変えたファイルに関係するテストと lint であること、全体のテストを手元で回さないこと、全体のテストの結果は作業者の結果か CI の結果を証拠にすること、どちらも無いときは全体のテストの証拠が無いことを要約に書くことが書かれている

#### Scenario: 動作確認で全体のテストを CI の結果で扱う

- **WHEN** `stages/pass.md` の手順 4 と手順 5 の末尾を読む
- **THEN** ゲートの担当がテストの全体実行を手元で行わないこと、全体のテストの合格を求める受け入れ条件は対象 HEAD の CI の結果を証拠にすること、CI の結論がまだ無いときは状態と合格後の CI の見張りで確かめることを書いて進めること、対象 HEAD の CI が既に失敗していれば失敗した run の URL と合格後の CI の見張りで直しに回すことを書くこと、結論の無い CI や失敗した CI を成功として書かないこと、auto-merge 未配備のリポジトリで CI が失敗か未決着のときは「マージは人間の操作待ち」の 1 行に CI の状態と見張りの結論が出るまでマージしない旨を添えることが書かれている

#### Scenario: CI が実行中のままゲートが進む

- **WHEN** 受け入れ条件に「`bash scripts/test.sh` が通る」がある PR で、ゲートの担当が手順 4 を行う時点で対象 HEAD の CI が実行中である
- **THEN** ゲートの担当は手元で `scripts/test.sh` を実行せず、動作確認の表のその受け入れ条件の結果の欄に CI が実行中であることと run の URL、合格後の CI の見張りで結論を確かめることを書き、手順 5 へ進む

#### Scenario: CI が落ちている HEAD では失敗を書いて見張りに渡す

- **WHEN** ゲートの担当が手順 4 を行う時点で、対象 HEAD の CI の全体のテストのチェックが失敗している
- **THEN** ゲートの担当は手元で全体のテストを実行せず、その受け入れ条件の結果の欄を成功の印にせず、失敗した run の URL と、合格後の CI の見張りで直しに回すことを書く

#### Scenario: auto-merge 未配備のリポジトリで CI が未決着のまま合格する

- **WHEN** auto-merge を配備していないリポジトリで、対象 HEAD の CI が実行中のままゲートの担当が合格処理を終える
- **THEN** ゲートの担当が PR に残す「マージは人間の操作待ち」の 1 行に、CI が実行中であることと、合格後の CI の見張りが結論を出すまでマージしない旨が書かれている

#### Scenario: 作業者の結果も CI の結果も無いときのレビュアーの要約

- **WHEN** Draft では CI を走らせないリポジトリで、作業者が全体のテストを CI に任せており、レビュアーが手順 2-1 を行う
- **THEN** レビュアーは全体のテストを手元で回さず、全体のテストの証拠が無いことを要約に書く
