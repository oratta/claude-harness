## Context

SKILL.md の手順 2-1 の表は companion 経路だけを列挙する一方、同ファイルの呼び出し規約と G の指示書は既に exec を許容している。この不整合により、companion 不在だけで Codex 全体を未導入と判定できてしまう。既存 Bats は Markdown の節の静的検査と、掲載 bash 断片を偽コマンドで実行する検査を併用している。

## Goals / Non-Goals

Goals: 従来モードで利用可能な Codex を取りこぼさず、不可判定の実測証拠を保存する。PC ごとの実測手順と記録欄を提供する。

Non-Goals: #707 の App Server モードの変更・共通導入判定の二重実装、companion 必須化、インストールやログインの自動実行、全 PC の実測、レビュー重量・合格条件・待ち時間の変更。

## Decisions

### 正本の表と実測条件を一つの互換修正として揃える

本体が確定した方針に従い、SKILL.md を正本として exec と companion を正式経路にする。companion / slash command が無ければ exec を試す。G は現行どおり Bash の exec または companion task を使い、Agent / slash command を要求しない。companion 必須化案はバイナリ単体でレビューできる既存運用を捨てるため採らない。

exec は既存の `codex exec -c approval_policy=never -c model_reasoning_effort=medium -` を用いる。レビュー指示はファイルから標準入力へ渡し、固定した HEAD・diff 範囲・受け入れ条件を含める。起動・完了シグナル・結果の読み方・有限ポーリングは subagent-waiting.md に委ね、数値や起動雛形を複製しない。

不可の証拠は、バイナリ探索コマンド（例: `command -v codex`）で確認した不在、実際の Codex 呼び出しが返した認証切れ、起動後の正本の総待ち上限到達に限る。auth.json の存在・バージョン表示・companion 不在だけでは可否を確定しない。引数誤り・権限拒否・通信障害などを三条件に読み替えて Claude へ暗黙に切り替えない。「サブスク切れ」という推測も認証切れの実測の代わりにはしない。

PR コメントに対象 HEAD・選んだ経路・実行コマンド・終了コード（取得できた場合）・出力の要点を残す。タイムアウトは実待ち時間と完了未確認を記し、架空の終了コードを書かない。G の full 不可時の needs-reviewer にも同じ証拠を含める。light の記録は事前判定として区別する。

### 本体の範囲決定を PC 確認手順に反映する

手順とテンプレートは SKILL.md の従来モードの節に置く。PC 識別子・日時・バイナリのパスとバージョン・companion 有無・対象 HEAD と範囲・実行コマンド・完了状態と結果・可否 / 未確認・残課題を記録する。認証情報そのものは転載しない。実際のレビュー完了を確認して初めてレビュー可能と記録する。

配布スキルはリポ非依存を維持し、記録先を「対象 issue」と表記する。本案件では #715 に実測結果を残す。PR は文書化完了と実測完了を区別し、実測前に #715 を自動 close する指定を使わない。

## Risks / Trade-offs

- 静的テストでは実環境の可用性を証明できない。各 PC の実測を別運用として残す。
- 二つのモードを混用すると #707 の制約が崩れる。従来モード限定と新モードへの非適用を検査する。
- 表だけ直すと G の説明・コメント例に古い不可判定が残る。表・説明・コメント例・return payload をまとめて照合する。

## Validation Strategy

実装前に Bats を追加し Red を確認する。単なるファイル内の exec の存在検査では現状でも通るため、手順 2-1 の表と不可判定・記録・G の payload の節を対象にする。bash 断片を追加する場合は既存の偽コマンド方式で分岐を検証し、実 Codex / ネットワークは呼ばない。Green 後に関連テスト、注入予算・配布整合、OpenSpec strict validation を実施する。

## Open Questions

仕様上の未決事項なし。PC 一覧と実測結果は別運用で記録する。
