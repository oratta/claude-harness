## Context

`plugins/dev-workflow/scripts/subagent-stop-guard.sh` は SubagentStop hook で、未完了の背景タスクを残したまま停止しようとするサブエージェントを拒否する。拒否回数は `${TMPDIR:-/tmp}/dev-workflow-stop-guard/<session_id>-<agent_id>.count` に数え、上限（`MAX_BLOCKS=3`）に達した停止だけを通す後詰めになっている。現状、カウンタファイルの削除は「上限到達で通す」分岐（`n >= MAX_BLOCKS`）にしか書かれておらず、`running` が空・`pending` が空の 2 つの正常終了分岐（151-155 行、175-177 行）では削除しない。この 2 分岐は「理由文どおりに正しく待ってから停止した」ケースであり、ここでファイルが残ると次回の拒否回数が前回の続きから始まる。

## Goals / Non-Goals

**Goals:**
- 3 つの「停止を通す」分岐（`running` 空／`pending` 空／上限到達）すべてで、通す直前にカウンタファイルを削除する
- 削除できない場合（`OSError`）でも停止自体は通す既存の fail-open 方針を維持する
- spec・archive・変更記録の文言をコードの挙動に合わせて揃える

**Non-Goals:**
- 未完了背景タスクの検出ロジック（所有判定・トランスクリプト探索）は変えない
- 拒否理由文の文面・上限回数（`MAX_BLOCKS=3`）は変えない
- `stop_hook_active` を使わない方針など、他の要件には触れない

## Decisions

**カウンタ計算をどこに移すか**: `counter_dir` / `counter` の算出（現行 180-181 行）を `running = {...}` の直前（現行 151 行の手前）に移す。3 つの分岐すべてがこの後に来るため、算出を 1 箇所に保ったまま全分岐から参照できる。算出自体は `session_id` / `agent_id` の文字列結合だけで副作用が無いため、早期化しても意味は変わらない。

**削除の書き方**: 各分岐の `sys.exit(0)` の直前に `try: os.remove(counter)\nexcept OSError: pass` を追加する。`counter_dir` が未作成のまま `running` 空・`pending` 空で早期リターンするケースでは `os.remove` が `FileNotFoundError`（`OSError` のサブクラス）を投げるので、既存の `except OSError` でそのまま無視できる（`os.makedirs` を先に呼ぶ必要はない）。

**上限到達分岐は書き換えない**: 既存の削除コード（`try: os.remove(counter)` / `except OSError: pass`）はそのまま残し、他の 2 分岐に同じパターンを追加するだけにする。3 箇所を同じ形に揃えることで、「停止を通す分岐は必ずカウンタを消す」という不変条件を読み取りやすくする。

**代替案として検討したが採らなかったもの**: 削除処理を関数化して 3 箇所から呼ぶ案は、差分が数行のみでヘルパー関数を新設するほどの重複ではないため見送った（3 箇所とも 2 行の定型処理）。

## Risks / Trade-offs

- [カウンタ削除を早期化したことで、削除のタイミングが「拒否回数を書き込む前」になる分岐がある（`running` 空・`pending` 空は書き込み自体をしない経路のため影響なし）] → 書き込みを伴う分岐（上限到達）は既存のまま変更しないため、書き込みと削除の順序は現行から変わらない
- [`os.remove` 呼び出しが増えることで、稀に競合する並行停止同士がカウンタファイルの有無を取り合う] → 既存の上限到達分岐も同じ `except OSError: pass` で無視しており、今回追加する 2 箇所も同じ扱いにするため新しいリスクではない
