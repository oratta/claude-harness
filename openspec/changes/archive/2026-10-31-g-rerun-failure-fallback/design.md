## 決定

- **再実行が失敗したときは、1 回目に出た候補だけで振り分ける。** 捨てた案: 今の「打ち切られたパスは相乗りせず新しい子 issue」（1 回目に子が見つかっていても重複する子 issue を作りうる。同じ打ち切りでも再実行が成功して打ち切られたときは出た候補で振り分けるのと釣り合わない）／走らせ直す（1 回の規則を崩す。失敗の原因が続くなら同じ結果）。理由: 再実行が打ち切られた場合と失敗した場合は、どちらも「15 件の外の子は見えていない」状態で同じ。同じ扱いにすると規則が 1 つになる。リスク: 15 件の外に同じ場所を直す子があると見落として新しい子 issue を作る。これは打ち切りの再実行でも許している見落としと同じで、頻度は低い。
- 失敗の記録は残す: 仕分けの PR コメントに「再実行に失敗した」と終了コードを書く（見落としの可能性を人が読み取れるように）。
- 1 回目の実行が失敗したときの扱い（相乗りせず段 C の「当たる issue が無い」へ）は変えない。1 回目は候補が 0 件で、使える結果が無いため。
- 1〜4（コマンド形・見出し・spec の箇条・再実行の引数保持）は文言の補完で、設計の選択は無い。再実行の引数は、1 回目と同じ `--repo` と `--exclude`（PR・記録先・エピックの番号）のまま、パスを絞って `--epic <エピック番号> --children-only` を付ける。
- archive 済みの change は書き換えない（過去の決定の記録。issue 本文の「変更の delta」はこの change の delta と main の spec を指すと読む）。
- 要件の本文に「守備範囲」の段落を足す（入力はスクリプトの出力と終了コード／拾いたい誤り／通ることを許す入力／塞ぎ切ることは完了条件にしない）。main の spec にも tasks.md の 2.1 で同じ段落を写す。
