## MODIFIED Requirements

### Requirement: コメント長の上限を超える本文は親と部分のコメントに分ける

`stages/triage.md` は、`レビュー三表:` のコメントと `## 一覧（順 3）` のコメントが GitHub のコメント長の上限（65,536 字）を超えるときの共通の規則を持たなければならない（MUST）。長さは `wc -c` のバイト数で測る。コメント全体が 65,536 バイト以下なら、分けずにこれまでどおり 1 件に置かなければならない（MUST）。超えるときは次の形にしなければならない（MUST）。

- 親のコメント: 1 行目は分けないときと同じにし、続けて要件「三表の親と部分」「順 3 の一覧の親と部分」が種類ごとに定める見出しの行を置く。そのあとに本文（表）を置かず、`部分 k/n: <コメントの URL>` の行を k の順に n 行置く
- 部分のコメント: 1 行目を `<種類>の部分 k/n`、2 行目を親と同じ SHA の行、3 行目を空行にし、4 行目以降に元の本文を置く。それぞれ 65,536 バイト以下にする

#### Scenario: 上限に収まるコメントは分けない

- **WHEN** 投稿する本文全体が 65,536 バイト以下である
- **THEN** コメントは 1 件で、`部分 k/n:` の行を持たず、読み手はこれまでどおり親の本文を読む

#### Scenario: 字数で収まってもバイト数で超えれば分ける

- **WHEN** 本文が 40,000 字で 120,000 バイトある
- **THEN** コメントは親と部分に分かれ、どの部分も 65,536 バイト以下である
