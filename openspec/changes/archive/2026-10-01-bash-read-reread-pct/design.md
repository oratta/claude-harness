## Context

`scan_full` は assistant の `tool_use` のうち `name == "Read"` の `input.file_path` のベースネームを `reads` に集める。Bash の `tool_use` は `input.command`（文字列）を持つので、そこからファイル引数を取り出して同じ `reads` に足せば、`reread_pct_for_w` は変更不要。

## Decisions

### D1: コマンド文字列の解析は shlex で字句分割し、正規表現で全文を探さない

`input.command` を `|` `;` `&&` `||` 改行で区間に割り、各区間を `shlex.split`（失敗した区間は読み飛ばす）して先頭語（`cd x &&` のような前置は区間分割で外れる）が `sed` / `cat` / `head` / `tail` の区間だけを対象にする。全文を正規表現で探すと、`echo` の引数や heredoc の本文中の語を誤って数えるため。代替案（正規表現で `sed -n '...' PATH` を直接抜く）は、クォート内の空白と `-n` の位置の揺れで取りこぼすので採らない。

### D2: 区間ごとのファイル引数の決め方

- 共通: `-` で始まる語（オプション）、`>` か `<` を含む語（`2>/dev/null` `2>&1` `>out.txt` のようにくっついた形を含む）とリダイレクト記号だけの語の直後の語、`-` 単独（標準入力）は数えない
- `cat`: 残りの語すべてがファイル
- `head` / `tail`: `-n` / `-c` の次の語（値）は数えない（`-n20` `-20` のように値がオプションに付く形は語ごと除外される）。残りの語がファイル
- `sed`: 単独の `-n` オプションがある区間だけ対象にする（`-ne` のまとめ書きは対象外。数え漏れ側に倒す）（置換などの書き換え用途を読みに数えない）。`-e` / `-f` が無ければ最初の非オプション語はスクリプトなので数えず、以降の語がファイル。`-e` / `-f` がある場合はその値の語を数えず、非オプション語はすべてファイル
- 数えた語は `os.path.basename` にして `reads` に足す。展開前のグロブ（`*` `?` `[` を含む語）とシェル変数（`$` を含む語）は実ファイルが分からないので数えない

### D3: 範囲

`grep` / `awk` / `less` など他の読み方は対象外（issue の範囲を超える）。`reads` を変えるだけで `docs_total` のホップ判定（`INSTR_RE` の指示書トリガー）は Read のままにする。Bash で指示書を読んだホップは今回 `docs_median` に入れない（別件）。

## Risks / Trade-offs

- 近似なので、取りこぼしが見つかるたびに塞ぎ切ることを完了条件にしない。守備範囲（入力の出どころ・拾いたい誤り・通してよい入力）は spec の Requirement に書いた
- 解析は近似であり、変数展開・グロブ・複雑なシェル構文の読みは数えない。数え漏れ側に倒れ、過大計上はしない方針（誤検出より漏れを選ぶ。目的が 0.0 の解消であり、手計算の 37.5% との近さで妥当性を見るため）
- ベースネーム一致のため、同名の別ファイル（`SKILL.md` など）を読み直しと数えうる。これは従来の仕様と同じ
