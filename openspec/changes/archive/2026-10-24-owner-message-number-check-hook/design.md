# Design

## Context

動機は proposal.md の Why。ここでは方針を決めるのに要る現状だけを書く。

- 正本は `output-styles/readable.md` の節 3（`## 3. 判断を求めるときは、質問から書いて、推奨まで出す`）。#1209 のあと、節 3 の「ほかの決まり」の段落に「issue・PR の番号で物を指さず中身で書き、番号は末尾の URL にだけ置く」「背景の詳しい説明と元の記録の URL は、区切って下に置く」があり、続く段落に 1 行目の書き分け（判断・確認・操作を求める発言は 1 行目を質問にし、区切りより上の本文の最後の行を答え方にする。何もしなくてよい報告は 1 行目を `主がすること: なし` にする。主の質問への答えは対象外）がある。短い版 `rules/communication-style.md` の 3 番目も同じ決まりを持つ
- #1184 の hook `plugins/dev-workflow/scripts/unclear-reply-rephrase.sh`（`UserPromptSubmit`）は、置き場所を dev-workflow の別スクリプト・別エントリにし、語の判定を「狭い一覧＋誤って当たったときの害を差し込む文で抑える」にし、差し込む文は正本の場所を指すだけで型の中身を写さない、と決めた（change `2026-10-21-unclear-reply-rephrase-hook` の design）。この change はその 3 つに揃える
- dev-workflow の `hooks.json` には `Stop` のキーがまだ無い。`Stop` を持つのは cost-ledger だけ（`ledger-hook.sh`。別プラグインなので互いに影響しない）
- `Stop` の payload のキーは、Claude Code 2.1.310 の `claude -p --plugin-dir` で 2026-10-24 に実測した: `background_tasks`・`cwd`・`effort`・`hook_event_name`・`last_assistant_message`（そのターンの最後の発言の本文。実測では返した文と一致）・`permission_mode`・`prompt_id`・`session_crons`・`session_id`・`stop_hook_active`（実測では `false`）・`transcript_path`。メインセッションの停止なので `agent_id` は無い
- dev-workflow の hook が python3 を起動するときは `python3 -I`（`tests/hook-python-isolation.bats` が hooks.json の配線先を列挙して検査する）

## Goals / Non-Goals

**Goals:**

- 主に判断・確認・操作を求める発言で、区切りより上に `#数字` が残っているか、番号を書いたのにリンクが無いときに、ターンを終える前に書き直させる
- 差し戻しの理由は、どの行のどの番号か（またはリンクが無いこと）という事実と、正本の場所だけを書く。正本の文言を写さない（正本を直すときに直す場所を 1 か所に保つ）
- 1 ターンに差し戻すのは 1 回まで。どんな入力でもセッションを止め続けない

**Non-Goals:**

- 書き直しの出来（中身で書けたか、6 段の型を守ったか）を検査すること。2 回目は見ない
- `#` の付かない番号の書き方（「PR 1712」「issue 1712」）を拾うこと
- Discord などのチャンネルに reply のツールで送る発言（ツールの引数に乗り、`last_assistant_message` には乗らない）。必要になったら別の issue で `PreToolUse` 側を考える
- サブエージェントの return（`SubagentStop`。読み手は主ではなく本体）
- 正本 `output-styles/readable.md` と `rules/communication-style.md` の文言を直すこと（エピック #1216 の注意書きによる。直す必要が見つかったらエピックに子 issue を切る）

## Decisions

### 置き場所: dev-workflow の hooks.json に `Stop` のキーを足し、別スクリプトにする

- #1184 と同じく dev-workflow に置く。番号で物を指した実例はどれも develop のエピックの親の発言で、`UserPromptSubmit` の言い直しの hook と同じ問題（主に伝わらない発言）の前後を受け持つ
- **選ばなかった案 1 — `unclear-reply-rephrase.sh` に書き足す**: 起きる時点（主の発言の前と、Claude の発言のあと）も、入力の形も、返し方（文を差し込む／停止を拒否する）も違う。混ぜると片方のテストがもう片方に巻き込まれる
- **選ばなかった案 2 — casting プラグインに置く**: hooks を持っておらず、casting が入っていない環境で効かなくなる
- **選ばなかった案 3 — 新しいプラグイン**: スクリプト 1 本のためには重い（#1184 の design と同じ理由）
- **エントリ**: `hooks.Stop` に 1 件だけ置く。`Stop` は matcher を取らないので付けない。`timeout` も付けない（`#数字` を含まない発言では python3 を起動せずに終わる）

### 読む本文: payload の `last_assistant_message` だけ。無ければ通す

- Claude Code が `Stop` の payload に渡す `last_assistant_message`（そのターンの最後の発言の本文）を読む。トランスクリプトの末尾を読む方法は、ファイルの大きさに比例して遅くなり、どの記録が「最後の発言」かを自分で決める必要があるので取らない
- `last_assistant_message` が無い・文字列でない版の Claude Code では、何もせず通す（取りこぼしは hook が無い今と同じ）
- payload に `agent_id` があるとき（サブエージェントの停止として渡されたとき）も通す

### 対象の見分け方: 1 行目が質問か、区切りより上の最後の行が答え方

正本の 1 行目の書き分けをそのまま判定に使う。本文は、逆引用符 3 つのブロック（開きと閉じの決め方は #1184 と同じ。閉じが無ければ最後まで）の行を除き、空でない行だけを並べたものとして見る。

- **引用の行**: `>` で始まる行は除かない。#1184 の hook は主が貼った他人の文で当てないために除いたが、この本文は全行を主が読むので、引用の中の番号も主が探しに行く手間になる。`~~~` や 4 字の字下げのブロックも除かない（逆引用符のブロックだけを除くのは #1184 と同じ判定に揃えるため）
- **1 行目の整え方**: 前後の空白と `*` を除いてから、報告かどうかと質問かどうかの両方を判定する（`**主がすること: なし**` や `**…ですか？**` の太字でも同じに扱う）。`主がすること` のあとのコロンと `なし` の間の空白は 0 個以上
- **区切り**: 前後の空白を除くと `-` だけが 3 つ以上並ぶ最初の行。無ければ本文全体が「区切りより上」
- **対象外**: 整えた 1 行目が `主がすること: なし`（コロンは半角・全角のどちらも可）で始まる発言は、番号があっても対象にしない。正本の番号の決まりは節 3（判断・確認・操作を求める文章）の中にあり、報告はその外だから
- **対象**: 次のどちらかに当たる発言
  - 整えた 1 行目の末尾が `？` か `?`
  - 区切りより上の最後の行が、答え方の語 `と打って`・`と打つ`・`を押して`・`と返して`・`と答えて` のどれかを含む（`と打つ` は「『OK』と打つ。」のような言い切りの答え方を拾うために足した）
- **`と書いて` を答え方の語に入れない**: 「…と書いてある」の報告で当たるため。「…と書いてください」で答えさせる依頼は 1 行目の質問で拾う
- **主の質問への答え**: 1 行目に答えを書くので、ふつうは質問で終わらず、答え方の行も無いので対象に入らない。答えの 1 行目が問い返しで終わると対象に入るが、差し戻しの理由の最後の文（下の「差し戻しの理由」）で害を抑える
- **選ばなかった案 — 主への依頼かをモデルに判定させる（`type: prompt` の hook）**: 毎ターン呼び出しの費用と待ち時間がかかり、判定がぶれてテストで固定できない

### 止める条件: 区切りより上の `#数字`、またはリンクの無い番号

番号は `#` に数字が続く並び（`#1712`、`oratta/claude-harness#1712` の `#1712`）。探す前に、本文から `http://`・`https://` で始まる URL（空白までの並び）を取り除く。URL の中の `#issuecomment-…` や `/pull/1712` は番号として数えない。

- **条件 1**: 区切りより上に番号がある。どの行（区切りより上の本文での行の順。1 から数える）のどの番号かを、行ごとにすべて示す
- **条件 2**: 本文のどこかに番号があるのに、issue・PR の URL（`http(s)://` で始まり、パスに `/issues/<数字>` か `/pull/<数字>` を含むもの）が本文に 1 本も無い。どの URL でもよいとしなかったのは、目的が「主が番号の指す物を開けること」で、ダッシュボードなど別の URL があっても番号の指す物は開けないから
- 両方に当たれば両方を示す
- **選ばなかった案 — 区切りより上のフル URL の行にある `#数字` を許す**: 正本は番号を「末尾の URL にだけ置く」と決めているので、URL の外に `#数字` があれば区切りより上ではすべて差し戻す。受け入れ条件の「番号がフル URL の行にだけある」は、番号が URL の中（`/pull/1712`）にある場合と読む

### 差し戻しの返し方: `decision: block` と、事実と正本の場所だけを書いた理由

- 出力は `{"decision":"block","reason":"…"}` の JSON 1 つ。Claude Code はターンを終えずに理由を Claude に渡し、Claude が書き直した発言を続けて出す
- 理由に書くもの: 差し戻しの印（`[dev-workflow 主への発言の差し戻し]`）、条件 1 なら行ごとの番号（例: `行 1: #1712`）、条件 2 なら固定の文字列 `issue・PR の URL が 1 本も無い`（条件 2 に当たらないときは書かない。テストがこの文字列で条件を見分ける）、書き直す先として `~/.claude/output-styles/readable.md`（Output Style `readable`）の節 3 の「ほかの決まり」の段落と 1 行目の書き分けの段落、発言全体を書き直して出し直すこと、この差し戻しはこのターンで 1 回だけであること、主に判断・確認・操作を求める発言でなければそのまま終えてよいこと
- 正本の文言（「中身で書き」「末尾の URL にだけ置く」など）は写さない。写すと正本を直したときにこの文が古くなる。テストで、理由にそれらの語が無いことと、正本の側にその決まりの文と見出しが残っていることを両方確かめ、正本が変わったらテストが落ちるようにする
- 正本のパスは `~/.claude/output-styles/readable.md` の形で書く（#1184 と同じ。プラグインは他のリポジトリから読まれるので、リポジトリ相対パスは辿れない）

### 1 ターンに 1 回: `stop_hook_active` で数える

- payload の `stop_hook_active` が真なら、何もせず通す。Claude Code は、Stop hook の差し戻しで続けたターンの次の停止でこの値を真にする。上限が 1 回なので、これで足りる
- **選ばなかった案 — 回数を状態ファイルに数える（`subagent-stop-guard.sh` の方式）**: あちらは 3 回まで拒否するので数が要る。1 回なら状態ファイルの作成・削除・壊れたときの扱いが要らない分だけ単純になる
- 弱点: 別の Stop hook（他のプラグイン）が先に差し戻したターンでは、この hook は 1 回も差し戻さずに通す。取りこぼしは hook が無い今と同じ状態

### 全解除と fail-soft

- `DEV_WORKFLOW_OWNER_NUMBER_CHECK=off` で何もしない。停止を拒否する hook なので、誤って当たり続けたときに主がすぐ切れるようにする（`subagent-stop-guard.sh` の `DEV_WORKFLOW_STOP_GUARD=off` と同じ考え方）
- どの入力でも終了コード 0。JSON が壊れている・python3 が無い・キーが無い・型が違うときは、標準出力にも標準エラーにも何も書かない
- 速い道: 生の入力に `#` と数字の並びが無ければ、python3 を起動せずに終わる（`#` と数字は JSON で逃がされない）

### 常時注入の予算への影響: 増えない

hook のスクリプトと hooks.json は `tests/injection-budget.bats` の測る対象ではなく、rules・output-styles・description を変えないので、予算ファイルは動かさない。差し戻しは当たったターンだけ理由の文（数百バイト）が載る。

## Risks / Trade-offs

- [画面ではもう表示されている] → Stop hook はターンの終わりに走るので、対話の画面では最初の発言が表示されたあとに書き直しが続けて出る。「送る前に止める」は「ターンを終える前に書き直させる」の意味になる。主は最後の発言を読めばよい。完全に隠すには、発言を出す前に走る仕組みが要り、今の Claude Code の hook には無い
- [誤って当たる: 主への依頼でない発言の 1 行目が `?` で終わり、番号がある] → 理由の最後の文「主に判断・確認・操作を求める発言でなければそのまま終えてよい」で、害を「1 回の追加の応答」に抑える。頻度は分からない。調べるなら、会話ログ（`~/.claude/projects/` の jsonl）の発言にこの判定を当てて、当たった発言のうち依頼でなかったものの割合を数える
- [`claude -p` で起動した子のセッションでも走る] → 子の最後の発言が質問で始まり番号を含むと、1 回書き直させる。エピックの子の return は 1 行目が宣言で、質問ではないので、ふつうは当たらない
- [取りこぼし: `#` の無い番号、チャンネルの reply、2 回目の書き直しでも番号が残る] → hook が無い今と同じ状態に留まる
- [正本の段落が変わる] → 理由は「節 3 の『ほかの決まり』の段落と 1 行目の書き分けの段落」を指す。テストで正本にその見出しと決まりの文があることを確かめ、正本を直す変更でテストが落ちるようにする

## Migration Plan

マージ後、各環境でプラグインが更新されると次のターンから効く。戻すときは hooks.json の `Stop` のキーとスクリプトを消す PR を出す（状態ファイルを持たないので後片付けは無い）。急いで止めたいときは `DEV_WORKFLOW_OWNER_NUMBER_CHECK=off` を設定する。
