## Context

PR トークン上限（#288）の計測は、本体が SKILL.md の手順どおりに `Codex 消費:` コメントを集めて記録ファイルを作り、`pr-token-budget.sh --codex-records` に渡す。現在の手順は `for n in ...; do gh api --paginate --slurp ... | jq ...; done > file` の 1 本のパイプラインで、`gh api` の失敗はループの終了コードにも記録ファイルにも現れない。`pipefail` を付けても、後段の `pr-token-budget.sh` の成功で終了コードが上書きされる。仕様は「計測できない」ときの exit 1 経路（止まらずに進み、記録先に 1 サイクル 1 回だけ通知する）を持っているが、取得失敗はそこに入らない。

## Goals / Non-Goals

**Goals:**
- コメントの取得・抽出・書き込みのどれかが失敗したら、集計を呼ばずに exit 1（計測できない）の経路に入る
- 途中まで取れた記録や、前回の計測で作った記録ファイルを、成功した記録として使わせない
- 失敗の検出を bats で再現できる形にする

**Non-Goals:**
- 取得失敗時に止まる（fail-closed）ようにすること。既存の方針どおり計測不能は止まらずに進む
- `pr-token-budget.sh` に GitHub の読み取りを持たせること
- `Codex 消費:` コメントの書式検査を強めること（書式に合わない行は従来どおり `pr-token-budget.sh` の `skipped_lines` で扱う）

## Decisions

### 収集を別スクリプト `scripts/codex-records.sh` に切り出す

`codex-records.sh --repo <owner>/<repo> --out <file> <番号>...` とし、番号ごとに `gh api --paginate --slurp` の出力を一時ファイルに受けて終了コードを見る。続けて `jq` で 1 行目が `^Codex 消費: ` のコメントを抽出し、これも終了コードを見る。全番号で成功したら一時ファイルを `--out` に移して exit 0、1 つでも失敗したら一時ファイルと既存の `--out` を消して exit 1 を返す。

検討した案:

| 案 | 採らなかった理由 / 採った理由 |
|---|---|
| SKILL.md の手順文を関数やサブシェルにして各番号で `|| return 1` を書く（issue の直し方 1 の例） | 手順文は本体が毎回書き写して実行するので、書き写しの誤りで検査が抜けても気づけない。テストも SKILL.md から文字列を抜き出して走らせる形になり壊れやすい |
| `pr-token-budget.sh` に `--fetch-codex-records <repo>` を足し、取得失敗をそのまま exit 1 にする | 呼び出しは 1 回で済むが、既存要件「スクリプトは GitHub を読んではならない」を破り、集計のテストすべてに `gh` のスタブが要るようになる |
| **別スクリプトに切り出す（採用）** | 失敗の検出をスクリプトの終了コード 1 つにまとめられ、`gh` を PATH のスタブに差し替えて bats で検証できる。`pr-token-budget.sh` は GitHub を読まない性質のまま残る |

`--out` を引数で受けるのは、本体の Bash ツールのシェル（zsh、noclobber 有効）で `> file` が既存ファイルに対して失敗するのを避けるためでもある。

### 失敗時は集計を呼ばない

収集が非 0 なら本体は `pr-token-budget.sh` を呼ばず、exit 1（計測できない）と同じ扱いにする。Claude 分だけで集計して exit 2 なら止まる、という案もあるが、Codex 分が抜けた合計を「合計」として記録先や問いに出すと誤読されるうえ、issue の受け入れ条件が「失敗時は集計を呼ばず計測不能に合流」なので採らない。

## Risks / Trade-offs

- [取得失敗が続くあいだは上限が効かない] → 既存の計測不能と同じ fail-open で、記録先への通知で人が気づける状態にする。通知は同じ理由について 1 サイクル 1 回
- [`gh api --paginate` が途中のページで失敗しても exit 0 を返す実装だった場合は検出できない] → `gh` は途中ページの失敗を非 0 で返す。出力が JSON 配列の配列でないときも `jq` の失敗として検出する
