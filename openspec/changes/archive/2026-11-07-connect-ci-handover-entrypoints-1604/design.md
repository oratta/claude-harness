# Design

## Context

動機は proposal.md の Why を参照する。handover.md 57–92 行には通常経路の CI 引き継ぎ、起動前の不可投稿、今回の工程完了／停止確認後だけの再許可がある。ci-watch.md は 7 冒頭からこの正本を参照しているが、開始手順には参照がない。develop/SKILL.md の failed 後の W 再開と handover.md を読む場面にも接続がない。無関係返却では push せず next へ進むため、「修正後の待ちへ戻る前」の適用時点が曖昧になる。

## Goals / Non-Goals

**Goals:** 通常経路の三つの入口から、既存の引き継ぎ・無効化・再許可の規則を辿れる状態にする。

**Non-Goals:** 新しい許可根拠、ロック、状態ファイル項目、無関係判断基準の導入。軽い経路の関係確認、複数チェック無関係判定、実エージェント起動による確認。#1596 / #1602 / #1549 の範囲は扱わない。

## Decisions

### 既存の正本へ参照で接続する

ci-watch.md の開始手順（2）から 7 冒頭へ参照を足す。develop/SKILL.md の failed 後の W 起動／再開と handover.md を読む場面には、最新が可なら「起動／再開前の無効化と再許可」に従い、不可の投稿成功後だけ指示することを記す。詳細な項目・投稿順序・停止先は handover.md を正本に保つ。無関係返却後も今回の工程完了を根拠として next 前に可を更新することを同ファイルの CI 節冒頭に明記する。

三箇所に独立した手順を複製する案は更新漏れを増やすため採らない。今回は既存規則への接続だけであり、許可条件の設計を選び直す必要はない。既存要件二つを全文保持して変更し、関連シナリオを追加する。共有 reference を編集するが、変更する契約は develop の通常経路に閉じるため、別の ci-watch capability への要件追加は不要。

## Risks / Trade-offs

- [全文のどこかに同じ語があるだけの検査では入口の欠落が通る] → 関係 Bats は開始節・failed 分岐・読む場面・CI 引き継ぎ節を切り出して、参照先と条件・順序を検査する。正本だけを確かめる既存テストを入口の検査で補う。
- [文書契約のテストではエージェントの読解や実際の投稿成功を保証できない] → #1604 の受け入れ条件どおり接続を検査範囲とし、既存の真正性・読解ミス等の守備範囲を維持する。実起動は不要。
- [SKILL.md の追加で起動時予算を超える] → baseline は実測・予算とも 86910 bytes。追記だけを行い、超えた場合は tests/develop-startup-budget.txt の当該行を今回の増加バイト数分だけ上げる。既存文の圧縮や重複整理はしない。PR 本文に理由と https://github.com/oratta/claude-harness/issues/1586 を書く。

## Migration Plan

R1 APPROVE 後に三つの文書の接続と関係 Bats・変更記録を実装する。仕様の同期／archive と PR 作成は finish 工程で行う。PR 本文には `Closes #1604` と、予算増加時の理由・#1586 リンクを含める。状態ファイルの移行は不要で、取り消す場合はこの接続差分を戻す。
