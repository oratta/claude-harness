## Context

実装は `stop-judge.sh` が停止の記録の `created_at >= 最後の入力の時刻` で今回の記録を選ぶ（GitHub の時刻が秒で切られるので小数を落として比べる）。止まりの対象は `epic-dispatch.sh` の `WAIT_TURN_DEFS` が記録の `turn_state`（`主の返事待ち`、または `作業報告` かつ `dependency_wait`）で決め、発言の `止まった理由:` の値は見ない。

## Goals / Non-Goals

- Goals: 文書を実装に揃える。#1714 の受け入れ条件を bats で固定する
- Non-Goals: 実装の変更。`主の返事待ち` の状態行で `止まった理由: なし` と書いた子を止まりから外すこと（新しい要件になるので入れない。判断は今までどおり judge に任せる）

## Decisions

- 比較の境界は実装に文書を合わせる（逆にしない）。実装は両方の時刻の小数秒を切り捨てて秒単位で `>=` に比べるので、spec にも「秒単位・同じ秒は含む」と書き、同じ秒の Scenario を足す。同じ秒の記録を今回の止まりに含める方が、記録の取りこぼしより安全なため
- #1714 は実装を変えず、既に満たしていることをテストで残す。通常の作業報告（`dependency_wait` が欠落か false）は止まりの対象外という既存の構造が理由。`dependency_wait: true` の作業報告は依存待ちの止まりとして `stopped` を返す（judge は呼ばない）ので、#1714 の対象は通常の作業報告に限り、依存待ちは境界として別のテストで固定する

## Risks / Trade-offs

- [#1543 の 14 件のうち、照合で「残っている」と分かる件が増える] → 実装の段で 1 件ずつ照合し、残る件は同じ PR で直すか、直さない理由を記録先に書く
