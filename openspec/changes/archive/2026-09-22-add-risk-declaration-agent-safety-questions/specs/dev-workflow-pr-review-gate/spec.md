## ADDED Requirements

### Requirement: リスク宣言は 7 観点で判定し、新 3 観点も主のリスク許容待ちに流す

pr-review-gate SKILL.md 手順 3 のリスク宣言は、プロダクトのユーザーへの影響・データ喪失・課金/法務・外部公開面の変化の 4 観点に、資格情報・安全ゲートの弱体化・エージェント権限の拡張の 3 観点を加えた 7 観点で判定しなければならない（SHALL）。新 3 観点それぞれについて、何が当たり何が当たらないかの線引きを手順 3 に書かなければならない（SHALL）。7 観点のどれか 1 つでも当たる PR は「主のリスク許容が必要」と宣言し、手順 6 で `needs-approval` を付けて主の許容を待たなければならない（MUST）。「リスクなし」の定型文は 7 観点すべてが無いことを述べる文でなければならない（SHALL）。宣言コメントの 1 行目 `## リスク宣言` と 2 行目 `対象 HEAD: <40 桁フル SHA>` の規約、および行頭 `リスクなし — ` / `主のリスク許容が必要。` の文言は変えてはならない（MUST NOT）。

#### Scenario: 「リスクなし」の定型文が 7 観点を述べる

- **WHEN** SKILL.md 手順 3 の「リスクなし」のコメント雛形を読む
- **THEN** `リスクなし — ` で始まる行に、プロダクトのユーザーに及ぶ影響・データ喪失・課金/法務・外部公開面の変化・資格情報・安全ゲートの弱体化・エージェント権限の拡張の 7 つがすべて現れ、それらが「いずれも無い」と述べている

#### Scenario: 新 3 観点のどれかに当たると needs-approval の経路に入る

- **WHEN** 資格情報・安全ゲートの弱体化・エージェント権限の拡張のどれかに当たる PR で手順 3 を回す
- **THEN** 手順 3 の表により「主のリスク許容が必要」となり、後続が手順 6（`agent-review:passed` を付けず `needs-approval` を付ける）であることが手順書に明記されている

#### Scenario: 新 3 観点の線引きが書かれている

- **WHEN** SKILL.md 手順 3 を読む
- **THEN** 資格情報（ID・パスワード・API の鍵・トークンの取得・保管・利用を変えるコード・設定・エージェントへの行動指示）、安全ゲートの弱体化（止め具を外す・緩める変更。厳しくする変更は当たらない）、エージェント権限の拡張（新しい権限・外部サービス・書き込み先）の定義が書かれている

#### Scenario: 許容が必要な場合の雛形が当たった観点を書かせる

- **WHEN** SKILL.md 手順 3 の「主のリスク許容が必要」の雛形を読む
- **THEN** 当たった観点を書く行（`該当する観点:`）がある

#### Scenario: 宣言の 1 行目・2 行目の規約が変わらない

- **WHEN** 変更後の SKILL.md 手順 3 の 2 つの雛形を読み、`plugins/dev-workflow/tests/pr-review-gate-skill.bats` を実行する
- **THEN** どちらの雛形も 1 行目が `## リスク宣言`、2 行目が `対象 HEAD: <$HEAD_SHA 40桁フル>` のままで、テストが exit 0 で終わる
