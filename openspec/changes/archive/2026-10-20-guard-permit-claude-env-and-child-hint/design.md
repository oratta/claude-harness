## Context

一部の起動環境（エピック #1137 の親のセッションなど）では、Claude Code のセッションの Bash に `GIT_CONFIG_COUNT=2`、`GIT_CONFIG_KEY_0=credential.interactive`、`GIT_CONFIG_KEY_1=credential.guiPrompt`（と対応する VALUE）を入れる。`git-guard-scratchpad.py` の `_redirect_env()` は名前が `GIT_CONFIG` で始まる変数を無条件で拒否の理由にするため、親の許可を書くスクリプトが毎回終了コード 1 で終わる。

実機確認（issue #1165 のコメント 6292542007）では、このセッションや素の `claude -p` にはこの変数が無く、親のプロセスにだけ入っていた。確認では親に同じ値を明示設定して再現した。

## Decisions

- **許可リストにする（`GIT_CONFIG*` を一律に外さない）**: git は `GIT_CONFIG_COUNT` / `KEY` / `VALUE` で任意の設定（`core.worktree`、`core.hooksPath`、`alias.*` など）を差し込める。無害と分かっているキーだけを一覧に持ち、それ以外は今までどおり落とす。一覧は `credential.interactive`・`credential.guiPrompt` の 2 つ。足すときは要件を直す
- **組として確かめる**: COUNT が 10 進の非負整数（上限なし。巨大な値でも、環境にある `GIT_CONFIG_KEY_*` の番号を先に集めて件数を比べ、COUNT 個が揃っていなければループを回さず落とす）、KEY_0..KEY_{COUNT-1} と VALUE_0..VALUE_{COUNT-1} がすべてあり、KEY がすべて一覧にあり、COUNT の範囲の外の番号が無いときだけ通す。1 つでも崩れたら `GIT_CONFIG*` を全部、今までどおり落とす。git が無視する範囲外の番号の変数も、読み違いを避けるため落とす（止めすぎる向き）
- **VALUE は見ない**: 一覧のキーは値によって行き先を変えない
- **拒否メッセージは打ち方を教える 1 文だけ足し、「打ち直さず」は変えない**: 子が変数や置換を含む形で打って拒否されると、親が許可を書けず主に上がる。メッセージは「親の許可を受けられる打ち方の例は、変数を使わず実パスで単独のコマンドとして打つこと」と例を示す。`;` や `&&` で繋いだ形（`cd ./tbl; rm -rf x/*` など）も判定を満たせば許可を受けられるので、「単独以外は許可を受けられない」とは断定しない（断定すると実際の許可条件と矛盾する）。打ち直しの許可にはしない（打ち直すかは親が再開指示で決める。促すと既存の「打ち直さず」と食い違い、拒否の回数の打ち切りも効かなくなる）。文に許可スクリプトの名前は書かない（子への理由に名前を書かない既存の規則のため）
- **rm の message にも同じ文**: rm の判定は `cd` + `rm` の形も通すが、その形（#1159）は範囲外なので、文は単独のコマンドだけを案内する

## Risks / Trade-offs

- Claude Code が将来、別のキーを `GIT_CONFIG_*` で入れると、また判定が落ちて親が許可を書けなくなる。止めすぎる向きの失敗で、一覧にキーを足して直す。今回は足さない
- 判定は、判定を動かすプロセス（親の Bash のスクリプト、または hook）の環境変数を見る。hook が使う時点でも同じ判定にかかるので、書く時と使う時で環境が違えば使う時に拒む
