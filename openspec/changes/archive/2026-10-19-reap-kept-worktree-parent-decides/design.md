## Context

`reap` は子のワークツリーを消せない理由があると `kept <N> <理由>` を返す。理由の中には、未コミットがある（`dirty`）・main に入っていない commit がある（`unmerged-commits`）のように親の確かめでも残る結果になるものと、`rm-failed`・`pr-lookup-failed` のように reap 側の都合で止まったものがある。後者は親が自分で確かめれば消せることがある。#1094 が同時に SKILL.md と `epic-dispatch.sh` の reap の端末を閉じる処理を触るので、この変更は SKILL.md の文言に限る。

## Decisions

- 確かめは親が行い、`reap` の理由の種類で分岐しない（`not-done` を除く）。理由ごとの分岐を持つと reap の理由が増えるたびに SKILL.md を直すことになるため、「残した理由の解消と未コミット・`LLM/` が無い」「HEAD が取り込み済み」の 2 条件だけに揃える。代替案は `epic-dispatch.sh` に確かめを移すことだが、#1094 との競合を避けるためやらない
- `not-done` は用が済んでいないので従来どおり待つ。
- HEAD の取り込み済みは、`launch` の起点ブランチ（`EPIC_DISPATCH_BASE` / `--base`、既定 main）のリモートの先端への包含、またはマージ済み PR の `headRefOid` との一致か tree の一致で見る。squash でマージされると main に HEAD の commit が入らないため、tree の一致を使う
- 消したときの行は `子 #N のワークツリーを確かめて消した（<理由>）`。片付け待ちの除外条件は `子 #N のワークツリーを残した` で始まる行なので、この行は除外にならない。代わりに本体が消した子はそのセッションの片付け待ちから外す。再開時は手順 7 の `reap` が `gone` を返して外れる
- 残したときの行は `子 #N のワークツリーを残した（<理由>）` で始め、末尾に ` — <満たさなかったこと>` を足す。除外条件と reply-after-idle の復元はこの前置きで動くので変わらない

- `llm-logs` の例外は置かない（issue の範囲は `not-done` を除く全部）。`reap` の `llm-logs` は `<path>/LLM` が在ることを指す。`LLM/` は gitignore 済みで `git status` に出ないので、例外を外すだけだと 2 条件を通って `rm` がログごと消す。そこで確認 (a) を「`reap` が残した理由が解消している」と定め、具体的に `git status` が空かつ `LLM/` が無いこととした。`LLM/` がある子は (a) を満たさず残る。範囲を変える例外ではなく、確認の中身で消してはいけないものを守る書き方である
- `reap` が `ambiguous`（候補が複数）か `not-child`（親の子ではない）を返したときは、単一の `<path>` を特定できないので確かめず消さず、残した行に理由を書く
- `rm` が失敗したときの残した行は、満たさなかった条件の代わりに `rm 失敗` を書く

## Risks

- 親が確かめを誤ってワークツリーを消す。`--force` を付けない `orca worktree rm` は未コミットの変更があれば止まる。HEAD が main か merged PR に入っていれば commit は失われない
