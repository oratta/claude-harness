## MODIFIED Requirements

### Requirement: 常時性を手放してはいけないルールを縮約対象から外す

**読むべき瞬間に、そのルールを読もうと判断できないルール**は、常時注入から外してはならない（MUST NOT）。判定条件は「そのルールが止めようとしている行動を思いついた時点で、先に skill や references を読む判断ができるか」であり、できないものは常時注入に残す。

この判定は、ファイル単位だけでなく**縮約する各文書の中の文・段落単位にも掛けなければならない**（MUST）。対象は、要件「常時注入の文書は発火条件と要点までに留める」と同じ `rules/*.md`・`CLAUDE.md`・skill / agent / command の `description` である。文書を縮約してよいと判定した場合でも、その中の一文が「読むべき瞬間に、読もうと判断できない」指示であれば、その文は短い形で常時注入に残さなければならない（MUST）。常時注入から外してよいのは、**読まれなくても挙動が変わらない部分**に限る（MUST）。具体的には次の 5 種類をいう。

- 経緯・事故の説明
- 理由の説明（何を守るかは残し、なぜそうするかの説明だけを外す）
- 同じ範囲で必ず載る文書との重複: 重複の相手は、外した文が載っていたのと同じ範囲（メインセッションとサブエージェントの両方、かつ全プロジェクト）で必ず載る文書に限る。`output-styles/*.md` はサブエージェントに載らず、`CLAUDE.md` は harness リポジトリのセッションにしか載らないため、`rules/*.md` の文の重複の相手にはならない（`rules/*.md` の文については、事実上ほかの `rules/*.md` だけが相手になる）
- `description` の手順説明
- 移設先へ誘導される手順・具体例: 常時注入に残した一文が、その手順や具体例が必要になる瞬間に移設先を読ませるもの。ファイル単位の判定条件「先に skill や references を読む判断ができるか」を文単位に当てはめたもので、残した一文がその判断のきっかけになっていることが条件である

外した文ごとに、上の 5 種類のどれに当たるかを PR 本文の移設表に載せなければならない（MUST）。分類は段落単位でまとめて示してよい（MAY。同じ段落の文が同じ分類に入るとき）。`rules/README.md` の一覧表はルールごとの移設先と常時注入に残した要点までを持ち、文ごとの分類は持たなくてよい。どの分類にも当たらない文は、次の列挙に無くても短い形で常時注入に残さなければならない（MUST）。

次の指示はこの条件に当たるため、縮約したルールの中でも短い形で常時注入に残さなければならない（MUST）。この列挙は 2026-09-11 の見直しで判定した結果で、判定に当たる文をすべて尽くしたものではない。禁じるのは縮約を理由に外すことであり、指示そのものが不要になった場合や、指示が前提とする仕組み（環境変数名・コマンド名・手順の構成）が変わった場合は、同じ変更の中でこの列挙も直す。プラグイン編集ルール（`rules/plugin-editing.md`）は #1129 で個人版のリポジトリ `oratta/claude-harness-oratta` に移したので、この列挙に載せない。移す前にこの列挙で残すとしていた指示（worktree を切る前に fetch する、別プロジェクトの worktree で `/wt-setup` を走らせるとそちらのリポジトリに Draft PR が作られる）は、写した個人版のルールの本文に残っている。

- 観点の配役（`rules/perspective-casting.md`）の返信前チェックの各手順の判定（担い手が主の観点が 1 つでもあれば主へ上げる、判断基準が無い・読めないときは主へ上げる、全観点を移譲済みなら独断せずスペシャリストに相談する）と、主からフィードバックを受けたらそのターンで配役表を更新する義務: 発火させる hook が無く、フィードバックは主の発言がきっかけでスキルを読む契機が無い
- 書き方ルール（`rules/communication-style.md`）の ✅/❌ 例、専門用語の初出の言い換え、読み手の側にしか無い情報が要るときは質問してよいという例外: サブエージェントには Output Style が効かず、PR 本文や issue コメントを書くのはサブエージェントである
- コミットポリシー（`rules/git-commit-policy.md`）の、PR 運用とローカル main 運用それぞれで自律実行してよい範囲の線引き: commit・push の瞬間に目に入らないと効かない
- 一回限りの操作ルール（`rules/one-off-no-script.md`）の「この実行では起きない入力への指摘を直し始めたら、汎用ツールを作ろうとしているサイン」: 手を止めるきっかけの一文である
- モデル選択ルール（`rules/subagent-model-selection.md`）の「最上位ティアを使う前に `FABLE_BUDGET_MODE` を確認する」: ワークフロー外で決める役を立てるときに確認されなくなる

この判定は path スコープの採否にも掛かる（MUST）。対象パスのファイルを読んで初めて載る形では、**そのファイルを読まないまま起きる事故**を防げない。読むべき瞬間にどのファイルも読んでいないルールに `paths:` を付けてはならない（MUST NOT）。

次のルールはこの条件に当たるため、常時注入に残さなければならない（MUST）。いずれも `paths:` を付けてはならない（MUST NOT）。

- 破壊的 git 操作の禁止（`rules/destructive-git-guard.md`）: 「戻すだけ」と思った瞬間が読むべき瞬間で、その時点で skill を呼ぶ判断ができない
- 他プロジェクトのプロセスを kill してポートを確保する禁止（`rules/dev-server.md`）: 同じ
- ダッシュボードで表示されたシークレットの即時保存（`rules/browser-infra-env-capture.md`）: 読むべき瞬間はシークレットが画面に表示された時で、そのときエディタではどのファイルも読んでいない。`.env*` を触って初めて載る形では「保存しようと思わなかった」事故を防げない

上の 2 つの列挙で残すとした指示とルールには、残すと決めた指示の退行を止めるテストを置かなければならない（MUST）。テストは指示ごとにその文にしか現れない語句（目印）を選んで該当ルールの本文にあることを検査し、目印は単語 1 つではなく文の一部を切り出した語句にする。指示の文言を変えるときは、同じ変更で目印も直す。

#### Scenario: 常時性を手放せないルールが常時注入に残っている

- **WHEN** `rules/` の一覧と各ファイルの frontmatter を見る
- **THEN** `destructive-git-guard.md`・`dev-server.md`・`browser-infra-env-capture.md` が実ファイルとして存在し、いずれも `paths:` を持たず、それぞれの禁止事項（承認なしに実行しない操作の一覧、他プロジェクトのプロセスを kill しない、表示された次のアクションで保存する）が本文に残っている

#### Scenario: 縮約で外した文がすべて読まれなくても挙動が変わらない分類に入っている

- **WHEN** 縮約した各文書（`rules/*.md`・`CLAUDE.md`・`description`）について、縮約前の本文と縮約後の本文を突き合わせ、外した文を PR 本文の移設表と照らす（段落単位でまとめた分類も可）
- **THEN** 外した文がすべて移設表に載っており、それぞれ「経緯・事故の説明」「理由の説明」「同じ範囲で必ず載る文書との重複」「`description` の手順説明」「移設先へ誘導される手順・具体例」のいずれかに分類されている。どれにも当たらない文が常時注入から外れたまま残っていない

#### Scenario: 瞬間に目に入らないと効かない指示が縮約後も常時注入に残っている

- **WHEN** 縮約後の `rules/perspective-casting.md`・`rules/communication-style.md`・`rules/git-commit-policy.md`・`rules/one-off-no-script.md`・`rules/subagent-model-selection.md` を読む
- **THEN** この要件で残すとした指示（返信前チェックの各手順の判定とフィードバック時の更新義務、✅/❌ 例・専門用語の初出の言い換え・質問してよい例外、運用ごとの自律実行の範囲、汎用ツール化のサイン、`FABLE_BUDGET_MODE` の確認）が、それぞれのルールの本文に短い形で残っている

#### Scenario: 残すと決めた指示はテストで検査される

- **WHEN** 上の列挙で残すとした指示のうち 1 つを `rules/*.md` から消した状態で `scripts/test.sh` を実行する
- **THEN** exit code が 0 以外になる（テストが、残すと決めた指示ごとの目印となる語句（`FABLE_BUDGET_MODE`・「汎用ツールを作ろうとしているサイン」・「例外なく事前承認」など）を該当ルールの本文から検査している）
