## MODIFIED Requirements

### Requirement: Third-party actions in workflow templates MUST be pinned to a commit SHA

`plugins/infra/templates/workflows/*.yml.template` の `uses:` のうち GitHub 公式（`actions/*`）以外のものは、40 桁のコミット SHA で参照し、その SHA が指すバージョンを同じ行のコメントに併記しなければならない。テンプレートの展開先では production のデプロイ／マイグレーションという secrets を持つジョブで動くため、可変タグ／ブランチ参照（例: `supabase/setup-cli@v2` は tag ではなくブランチ）は上流の push だけで別コードの実行につながる。この検査は「抽出」「公式判定」「コメント形」の 3 点で fail-closed でなければならない — 抽出は行のパターン照合ではなく YAML パーサ（`ruby -ryaml` の AST 走査）で行い、`---` 区切りの複数 document を含むファイル全体（stream）について任意の深さの mapping にある `uses` キー（コロン前の空白・行頭の `- `・キーの引用（`- "uses": ...` / `- 'uses': ...`）・flow mapping（`- { uses: ... }`）・`uses` の Scalar に付いた anchor を参照する alias キー（`- *u: ...`）を YAML の文法どおりに含む。alias キーは anchor の付け替えを追わず、一度でも `uses` に付いた anchor 名を参照するものはすべて `uses` キーとみなす）を全数列挙し、パースできないテンプレートは違反として扱い、公式判定は行全体の部分一致ではなくパーサが返した `uses` の値そのもので行い、コメントは同じ行の YAML 本文（パーサの位置情報でその行で終わる Scalar / Alias / flow collection）より後ろにあるバージョンらしい形（`v` 省略可の数値列。直後は空白か行末で終わる）でなければならない。This requirement MUST be satisfied.

守備範囲: この検査が受け取る入力は、`plugins/infra/templates/workflows/` 配下のファイルとシンボリックリンク（このリポジトリに commit された、テンプレートを書く人・PR の作成者が置いたもの）に限る。拾いたい誤りは、第三者 action を可変タグ／ブランチで参照したテンプレートが合格することと、走査から外れる置き方（読めないサブディレクトリ・シンボリックリンク・パースできないファイル・2 つ目以降の document・改行を含むファイル名）のせいで検査されないまま合格することの 2 つ。次の入力は通ることを許す: `actions/*` の行（タグ参照のままでよい）／形は正しいが SHA とコメントのバージョンが実際には対応していない行（対応はオフラインで検証しない）／名前が `*.yml.template` でない通常ファイル（例: `bad.yaml.template`。走査しない）／値の行で開いて次行で閉じる flow collection の内側の `#v1`。ハードリンクと、走査対象のディレクトリより上の階層にあるシンボリックリンクは扱わない。この検査は悪意のある commit を防ぎ切る境界ではないので、迂回の形が見つかるたびに塞ぎ切ることを完了条件にしない。

#### Scenario: Every third-party `uses:` in the templates carries a SHA and a version comment

- **WHEN** `plugins/infra/templates/workflows/` 配下の全 `*.yml.template` を YAML としてパースし（`ruby -ryaml` の AST 走査。`plugins/infra/tests/list-uses.rb`。`---` で区切った複数 document は最初の 1 つだけでなくすべて走査する）、任意の深さの mapping にある `uses` キー（引用の有無を問わない。`uses` の anchor を参照する alias キーを含む）を全数列挙し、パーサが返したその**値**（引用符・flow mapping の終端記号はパーサが扱うので値に含まれない。コメント中の `uses:` はパーサが無視する）が `actions/` で始まらないものを検査する
- **THEN** 値が `<owner>/<action>@<40 桁 16 進数>` の形（`<owner>` に `/` を含まず、`<action>` は `repo/subdir` のようなサブパスを許す）でなければならない
- **AND** 値が 1 行に収まっていなければならない（複数行に跨る block scalar や複合値は違反）
- **AND** 同じ行のうち、**パーサの位置情報でその行の YAML 本文（その行で終わる Scalar / Alias / flow collection）が終わった位置より後ろで最初に現れる `#` から始まる部分**（＝コメント部分。そこより後ろに残るのは flow の終端記号・空白・コメントだけなので、引用文字列の中の `#`（`"a\"# v1 "` のようにエスケープを含む形も）や flow context の plain scalar に含まれる `#`（`x#v1`）はコメントの境界にならない。値の行で始まって次行に続く Scalar がある行は、行末までが本文なのでコメント無しとして扱う）の先頭が、バージョンらしい形（`#` の直後に空白を挟んでよく、`v` は省略可、`1` / `v2.1.1` のような数値列で、直後は空白か行末）でなければならない。値より前に置かれた他のキーの値（例: `- { name: "a#b", uses: ... }`）、値より後ろに置かれた他のキーの値（例: `- { uses: ..., name: x#v1 } # TODO` / `- { uses: ..., name: "a\"# v1 " } # TODO`）、コメント部分の途中に現れる `#<数字>`（例: `# TODO #176 follow-up`）を判定材料にしてはならない。走査ツールが前置するファイルパス・行番号も判定材料にしてはならない（ファイルはパスをパーサの引数として渡し、行番号はパーサが返す位置情報で引く）
- **AND** 行の切り方はパーサ（libyaml）と同じ改行判定（CRLF・bare CR・NEL・LS・PS・LF）でなければならない。LF でしか切らないと bare CR を含むテンプレートで行番号がずれ、別の物理行のコメントをバージョンコメントに採用して合格したり、違反行の本文が空になったりする（#247）。本当のコメントが `# TODO` の行は、別の行に `# v9` があっても fail し、違反行の本文が出る
- **AND** `uses:` のキーと値が別行にあるとき、「同じ行のコメント」は**値のある行**のコメントを指す。`uses:` ↵ `<owner>/<action>@<40 桁 16 進数> # v2.1.1` は pass、`uses: # v2.1.1` ↵ `<owner>/<action>@<40 桁 16 進数>` は（キーの行のコメントは値に付かないので）fail する（#248）
- **AND** 値の行で開いて次行で閉じる flow collection（例: `- { uses: <40 桁 16 進数>, l: [ #v1` ↵ `1] } # TODO`）の内側に置いた `#` は、YAML の文法上その値の行に属するコメントなので、この要件のコメント境界の判定対象になる。つまり値の行の途中から始まる `#v1` は、次行で閉じる flow collection の内側にあってもバージョンコメントとして採用されうる。これは `origin/main` から変わらない既存の挙動で、実装では除外せず、仕様として書いて固定する（テンプレートの記述者が意図してこの形を書く理由が無く、除外の実装は行を跨ぐ本文の位置追跡を増やすだけで得るものが小さいと判断した。#248）
- **AND** テンプレートの列挙は NUL 区切り（`find -print0` と `read -d ''`）でなければならない。改行区切りにすると、ファイル名に改行を含むテンプレートのパスが途中で分断され、正しいファイルも違反行も報告できなくなる（旧 grep 実装では走査から落ちて無言で pass した。パーサ方式の現在は違反扱いで fail するが、原因の分からない報告になる）。だから NUL 区切りを維持する（テスト S16a-19、#197）
- **AND** テンプレートの列挙（`find`）が 0 以外で終了したら、検査は fail しなければならない（MUST）。読めないサブディレクトリなどで列挙が不完全なときは違反の有無を判定できないので、列挙できたファイルだけで pass させない（テスト S16a-25、#240）
- **AND** 走査対象のディレクトリ配下にあるシンボリックリンクは、名前（`*.yml.template` かどうか）とリンク先（ファイル・ディレクトリ・リンク切れ）を問わず、リンク先を追わずにリンク自体を違反として fail しなければならない（MUST）。`find` は既定でシンボリックリンクのディレクトリに降りないので、リンクを列挙から外すと、その下のテンプレートが走査されないまま pass する（テスト S16a-26・S16a-27・S16a-28、#240・#900）
- **AND** パースできないテンプレートは違反として fail しなければならない（パース失敗を「抽出 0 件」として無言で pass させない）
- **AND** 抽出された `uses` キーが 1 件以上存在しなければならない（テンプレートの改名・移動で走査対象が 0 件になり無言で pass するのを防ぐ）

#### Scenario: Known bypasses of the check are rejected

- **WHEN** 次の 15 形をテンプレートに置いて検査する — ① `uses: <owner>/<action>@<40 桁 16 進数> # TODO`（バージョンでないコメント）② `uses: evil/action@v1 # mimics uses: actions/cache@v4`（コメント中の `actions/` で公式を騙る）③ `uses : evil/action@v1`（コロン前に空白）④ `uses: evil@<40 桁 16 進数> # v1`（`<owner>/` が無い）⑤ `# v1evil` / `# 1.` / `# TODO (#176)` / `# 2026-08-22`（バージョンに見えるだけのコメント）⑥ ファイルパスに `# v9` を含む dir に置いた `# TODO` 行（走査ツールの前置がコメント判定を肩代わりする形）⑦ `uses: <owner>/<action>@<40 桁 16 進数> # TODO #176 follow-up`（コメント部分の途中にある `#<数字>` がバージョンに見える形）⑧ パスに `:` を含む dir（例: `a:4:b # v9 x`）に置いた `# TODO` 行（前置の剥がし方が壊れてパス片がコメント判定を肩代わりする形）⑨ `- "uses": evil/action@v1` / `- 'uses': evil/action@v1`（引用したキー）⑩ `- { uses: evil/action@v1 }` / `- {name: deploy, uses: evil/action@v1}`（flow mapping）⑪ `- { name: "uses: actions/cache@v4", uses: evil/action@v1 }`（flow mapping の前置キーの引用値が `uses: actions/` で公式を騙る）⑫ `- { name: "a#b", uses: evil/action@v1 }`（flow mapping の前置キーの引用値の `#` がコメント境界を騙る）⑬ YAML としてパースできないテンプレート ⑭ `---` で区切った 2 つ目の document に置いた `uses: evil/action@v1`（最初の document しか見ない走査が素通りさせる形）⑮ `- { uses: <owner>/<action>@<40 桁 16 進数>, name: x#v1 } # TODO` / `- { uses: <owner>/<action>@<40 桁 16 進数>, name: "a\"# v1 " } # TODO` / 値の行で始まって次行に続く引用値 `"multi #v1\n line"` を持つ `# TODO` 行（値より後ろの YAML 本文に含まれる `#` がコメント境界を騙る形）
- **THEN** 15 形すべてが検査に fail しなければならない
- **AND** 正しく固定された行（`uses: <owner>/<action>@<40 桁 16 進数> # v2.1.1`。引用符で囲んだ形・`owner/repo/subdir@<40 桁 16 進数>` のサブパス形・キーを引用した形・flow mapping 形（バージョンコメントは閉じ括弧の後。`- { name: "a#b", uses: <owner>/<action>@<40 桁 16 進数> } # v2.1.1` / `- { uses: <owner>/<action>@<40 桁 16 進数>, name: x#v9 } # v2.1.1` / `- { uses: <owner>/<action>@<40 桁 16 進数>, name: "a\"# TODO " } # v2.1.1` のように他のキーの値が `#` を含む形も）・`---` で区切った 2 つ目の document に置いた形を含む）と GitHub 公式（`actions/*`）の行は pass しなければならない
