# Design

## Context

動機と範囲は proposal.md を参照。現在の共通定義はトップレベルの `request_template`・`reply_prefix`・`fields`・`separator` だけを持つ。`child-log-read.py --keepalive-text` を親と状態フックが利用し、既存のテストもこの形を読む。

child-log は予約文への応答が定義の一行形式と一致するときだけ発言から除外する。状態フックは最新 user が予約文なら、応答の形式が逸脱していても元の記録を変えない。この違いは既存契約であり、新しい種類にもそのまま適用する。子の session / transcript 対象判定、状態更新の排他、通常入力による世代更新は維持する。

## Goals / Non-Goals

**Goals:** 共通定義を両読取経路で使い、作業待ち用の往復で元の入力・状態・作業待ちの記録を失わない。既存呼出しと旧予約文の生成結果を互換に保つ。

**Non-Goals:** 受信手順の読み込み・実行を子へ接続すること（#1793）、親から作業待ち用の送信を開始すること、自己タイマーの撤去（#1777）、元作業やタイマーの実行をこのフックで制御すること。記録に新しい状態や世代を追加しない。

## Decisions

### 新しい種類の表現は既存定義への追加で行う

issue で指定された新旧プロトコルの分離を、次の互換な形で具体化する。これが issue に無い値を埋める一つの決定である。

- トップレベルの旧 4 項目と値はそのまま残し、`background` オブジェクトに同じ 4 項目を持たせる。新形式の接頭辞は `[child-background-cache-keepalive]`、欄名は既存と同じ `待ち:`・`次:`、区切りは ` | ` とする。
- 新しい `request_template` は次の一つの固定文とする。`{reply_format}` は既存と同じ生成規則で展開する。

> 作業待ちのキャッシュ維持のための声かけです。主の返事や親の判断、作業の完了通知ではありません。ツール・調査・新しい作業・印の変更・記録の投稿をせず、元の作業とその実行 ID・自己タイマーを保ち、現在の会話だけから次の型の一行だけを返して元の作業待ちを続けてください: {reply_format}。各値は短くし、改行と区切り文字を含めないでください。

- `child-log-read.py --keepalive-text` は旧固定文を同じバイト列で出す。`--keepalive-text background` で新固定文を生成する。通常のログ読取呼出しと JSON 出力の形は変えない。

既存のルートを種類の配列へ置換する案は、親と既存テストの呼出し互換性を崩すため採らない。同じ応答接頭辞を共用する案は、別の種類の返事を誤って隠すため採らない。異なる欄名や新しい状態スキーマを増やす必要はない。

### 既存の除外規則を種類ごとに適用する

ここは issue の受け入れ条件と既存仕様の適用であり、新しい除外権限は加えない。

- ログ読取は共通定義から両固定文を生成し、現在対応中の種類を保持する。完全一致の request は通常入力に数えない。応答はその種類の形式に一致した場合だけ除外する。別の固定文が来たら対応する種類を切り替える。
- 通常の user 入力または型違い・複数行の assistant 応答で対応を終了する。既存どおり tool_result / meta / ローカルコマンドは対応を切らない。予約文だけで既存の背景タスクを完了扱いにしない。全イベントによる活動時刻の観測は既存どおり続ける。
- 状態フックは生成器で新旧固定文を取得し、予約文集合として Python の判定へ渡す。未登録通知の除外、input の更新除外、Stop の最新 user の照合の全箇所に同じ集合を使う。予約文の読取失敗は既存と同じエラー経路に置く。
- Stop は応答の prefix だけでは除外しない。同じ対象 session / transcript の最新 user がどちらかの固定文に完全一致する場合に限って元の記録を保持し、その後に通常 user が入れば通常の検査へ戻す。対象外 session と古い Stop を除外する既存規則も保つ。

## Risks / Trade-offs

- [主が固定文をそのまま入力すると通常入力にならない] → 既存と同じ完全一致予約の限界として受け入れる。送信元認証や衝突回避の仕組みは追加しない。似た文を通常入力として扱うテストを置く。
- [応答を広く除外して本当の発言を隠す] → 対応する種類・一行形式を照合し、交差した応答・単独の prefix・本当の入力割込み・複数行を表示する回帰テストを置く。
- [状態フックとログ読取で逸脱時の扱いが違う] → 状態保持と会話表示を分ける既存契約を保ち、逸脱応答では「記録は変えず、ログには表示」をそれぞれ確かめる。
- [受信基盤だけでは子が新しい型で返す保証は完成しない] → #1793 で手順を接続したあと #1777 で送信を有効化する。今回の変更だけで稼働済みや実機成功とは宣言しない。

## Migration Plan

既存記録の移行は不要。R1 承認後、5 ファイルを変更し、対応する 2 スイートを実行する。#1792 完了後に #1793 が共通定義を読み込む手順を接続する。問題があればこの change の実装を戻せる。親は旧経路のままなので、新形式の受信基盤だけを戻しても新しい送信は残らない。
