# Design

## Context

動機と分割判定は proposal.md を参照。判断記録は [#1765 のコメント](https://github.com/oratta/claude-harness/issues/1765#issuecomment-7088638343)。既存の review-hit-set.py は語ごとに 1 組の SHA・検索コマンド・表を受け取り、列名・本文・全ヒット集合を厳密に検査できる。一方 reviewer-brief.md の「自己点検」は、投稿前にスクリプトを実行するところまでは要求していない。

G の gate-triage.md は全ハンクとの集合比較と正確な残差を既に求めるが、新規ファイルや他区画で被覆済みという主張をどう扱うかは具体的でない。補足回数は PR 全体で 1 回であり、補足後の残差を隠して通す変更はしない。

## Goals / Non-Goals

**Goals:** 投稿される表の形式を既存の検査に合わせ、補足要求の時点で未被覆の全ハンクを具体的に示す。

**Non-Goals:** 表の意味・finding の判定の自動生成、スクリプトの入力形式の緩和、順 3 の第 2 段の変更、区画の再設計、レビュアーの読む範囲・トークン削減（#1692）、補足回数やゲート通過条件の緩和。

## Decisions

### 厳密な契約を維持し、投稿前に最終の表そのものを検査する

受け入れ条件 1 の選択は「載せる前の自己検出」。reviewer-brief.md の既存の自己点検の位置に、語ごとの最終の表を一時ファイルに保存し、`python3 plugins/dev-workflow/scripts/review-hit-set.py --repo <repo> <table-file>` を実行する手順を加える。`<repo>` はローカルのリポジトリルート。投稿用の表と検査用の表を別に作らない。一周目の検査に `--head`（順 3 の修正後照合）は付けない。出力と exit code を確認し、exit 0 になるまで修正・再実行する。実行できない場合は理由を報告し、検査済みと記さない。

- 10 行以下では正確な 4 列の列名と各行の本文全体を使う。抜粋から本文を推測せず、固定 SHA の検索結果で補う。
- 0 ヒットでは正確な列名と区切りだけの空の表を使い、`（ヒットなし）` のデータ行を置かない。
- パス列はバッククォートで囲まない。本文は既存の escape / fence 規則を使う。
- 10 行を超える語では既存の全ヒット要約を維持し、下に置く表には食い違いの行だけを完全な本文で書く。食い違いが無い場合は表を省く。
- `contract:` / `missing:` / `extra:` / `summary:` のある表は未完了として直す。結果の要約に検査した語数・コマンド・exit code を残す。

代案の許容・正規化は採らない。列名やパスの装飾は剥がせても、失われた本文は書式の正規化では復元できない。自動で本文を検索結果に差し替えると、照合すべき不一致を検査側が消す恐れがある。既存スクリプトをそのまま使えば順 3 の契約と #1410 の修正範囲も保てる。PR 本文にこの選択と理由を記載する。

### 被覆の残差を既存の G の照合で具体化する

受け入れ条件 2 で認められた「G が補足を頼む前に抜けたハンクを一覧で示す」を選ぶ。区画作成時に別の割当形式や新しいスクリプトを導入せず、gate-triage.md の全ハンク列挙・集合比較に、新規ファイルの `@@ -0,0 +1,N @@` も含むことを明記する。

比較キーは固定 PR diff のファイルと実際のハンクヘッダー。元の表と既に受け取った補足の被覆行を全区画で和集合にし、存在しない被覆を他区画への文章参照から補完しない。`新規` とだけ書かれた行も正確なヘッダーの代わりにはしない。未被覆の各キーを一覧にしてから、既存の区画への振分け規則で補足要求に載せる。補足後にも残れば同じ一覧を記録して review-incomplete で止める。

### #1703 の再照合は固定された資料で行う

対象 HEAD は `f5c801dc4985c664e99ac8cc7ff0b10367523964`。以下の PR コメントを原資料にし、後の HEAD の表に置き換えない。

- 元の三表: https://github.com/oratta/claude-harness/pull/1703#issuecomment-6995951632
- 補足 1/3: https://github.com/oratta/claude-harness/pull/1703#issuecomment-6996185665
- 補足 2/3: https://github.com/oratta/claude-harness/pull/1703#issuecomment-6996186174
- 補足 3/3: https://github.com/oratta/claude-harness/pull/1703#issuecomment-6996186643
- 当時の残差の照合用記録: https://github.com/oratta/claude-harness/pull/1703#issuecomment-6996272164

補足で語の表が出し直されたものはその表、それ以外は元の表を使う。原資料の取得物・抽出した表・修正版・実行ログはすべて $TMPDIR の mktemp ディレクトリに置く。元のコメントは編集しない。

未修正の語ごとの表で当時の違反を検出したあと、新しい自己検査手順に従って書式を直す。検索語・固定 SHA・扱い・finding ID を変えず、欠けた全文を固定 SHA から戻す。全ヒット要約の不要な一致行は既存契約どおり省く。全対象語の修正版を再検査して exit 0 を確かめ、原資料 URL・語・修正内容・修正前後の出力と終了コードを変更記録に残す。検索自体の誤りや意味上の欠陥を見つけたら、書式の解消と区別して未解消として報告する。

ハンクは当時記録された 175 個と元の表＋補足の和集合を比べ、少なくとも gate-result.md / pr-token-budget.md / worker-recovery.md の未被覆と changes/1685.md の不正確なヘッダーを補足要求前に列挙できることを記録する。表の書式を直しただけでハンク被覆まで完了したと記さない。

## Risks / Trade-offs

- [手動で再整形した投稿用の表が検査した表とずれる] → 最終の表を語ごとに検査してからそのまま投稿するよう指示し、要約に実行結果を残す。
- [歴史的コメントにネットワーク経由でしかアクセスできない] → 通常の回帰テストは合成 Git リポジトリで 4 種の不正形→検出→修正版の成功を確認する。実データの再照合は上記 URL と固定 SHA を明記した変更記録で満たし、取得できなければ未確認として報告する。
- [指示文だけの強化を実動作の保証と誤認する] → 既存の検査スクリプトの回帰テストと、レビュアー／G の指示の契約テストを両方追加する。新たな自動フックによる投稿ブロックまでは保証しない。
- [同一ファイルの open PR との競合] → #1410 が触る review-hit-set.py / triage.md のロジックには触れず、#1285 と重なる reviewer-brief.md は自己点検段落に絞る。取り込み時の再確認は実装担当が行う。

## Migration Plan

既存の strict checker をそのまま使うためデータ移行は不要。仕様レビュー後に指示と回帰テストを追加し、#1703 の再照合を記録する。通常の finish 段で仕様を同期・archive し、PR 本文に採用方式と理由を残す。差し戻しはこの指示とテストの変更を戻すだけで、照合スクリプトの契約は変わらない。
