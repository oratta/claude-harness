# Design

## Context

issue #564 の監査精度修正。既存の担当分類は完全一致の列挙、読み直し率のキーは description の最も左の #N のみである。全文走査と部分読みの差は実装コメントにはあるが、仕様は用途を限定しすぎている。

## Goals / Non-Goals

**Goals:** 手渡し後も担当を維持し、別プロジェクトの番号衝突を防ぎ、既存の fail-open と既定出力をテストで固定する。

**Non-Goals:** 実行制御、注入、閾値、version、キャッシュ形式の変更、読み取りコマンド解析の拡大。

## Decisions

- 接頭辞は `re.fullmatch(r"(W|R1|G|Reviewer)\d*", token)` のグループ1を返す。数字の単純削除では R1 が壊れるため採用しない。agentType の優先順位は維持する。
- 読み直し率のキーは固定深さのパスから取った slug と最も左の #N の組とする。セッションはキーに含めず、同じプロジェクト内の手渡しを横断集計する。リポジトリ名の外部照会は不要。
- 全文走査の既存実装は変更せず、全体・担当別の最終判定にも使うことを仕様に合わせて記録する。現行 spec の直接編集はせず、MODIFIED 要件全文を archive 時に反映する。
- python3 を隠すテストは必要なコマンドだけを symlink した PATH を使う。検証側の Python は PATH を戻した状態で JSON を読む。

## Risks / Trade-offs

- slug が異なる worktree は別プロジェクトとして扱う。issue 指定の識別子を使うため、同じリポジトリへの正規化は行わない。
- 担当別呼び出しと既定呼び出しは走査方式が異なり、最終 usage の探索窓によって値が僅かにずれうる。この制約を仕様に明記する。

## Migration Plan

既存インターフェースのまま適用できる。既存キャッシュは TTL 後または `--refresh` で更新する。archive は後工程で現行 spec に反映する。

## Open Questions

なし。実装担当の成果物は change として残し、archive は後工程へ引き継ぐ。
