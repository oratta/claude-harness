# Proposal

## Why

#1777（エピック #1732）の作業待ちでは、子が自己通知のたびにタイマーを置き直すため維持に複数のリクエストが要る。#1792 / #1793 で main に入った受信契約へ親の送信を接続し、Orca の子が自分の実行中作業を失わず、一回の応答で会話キャッシュを維持できるようにする。

## What Changes

- 子の通常の作業報告に、同じ作業待ちを識別する ID と初回開始時刻の明示記録を追加する。主の返事待ち・依存待ち・通常の作業報告から推測しない。
- 通常の `wait --watch-stopped` の既存ポーリング内で、Orca の有効な作業待ちにも共有定義の `background` を送る。送信直前に状態・現行会話・画面を再照合する。
- 作業待ちに限り、既知の背景エージェント待機行を送信拒否の根拠から外す。前景実行・入力済み・dialog・未知画面の拒否と一回だけの送信・到達確認は保つ。
- 作業待ちは会話量 150k の停止済み子向け除外を使わず、TTL 1h・最後の成功リクエストから 3000 秒以上 3600 秒未満・前回未応答なら非送信・初回開始から最大 12 時間を適用する。
- 外部起こしを選ぶ Orca の作業待ちには自己タイマーを置かない。tmux・外部起こしを使えない本体は #1743 の自己通知、委譲 worker は既存のサブエージェント待機契約を保つ。
- 主の返事待ちの送信・停止受領・wait の出力と終了規則は保つ。実エピックのログで「維持一回あたりリクエスト一回」を確認するタスクを残す（マージ後でよい）。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `dev-workflow-develop`: 既存の停止済み子向け送信を保ち、作業待ちの送信対象・期限・除外・画面条件を追加する。
- `dev-workflow-epic-state`: 作業待ちの明示情報、現行ログとの対応、Orca の限定した背景待機許可と判定記録を規定する。
- `dev-workflow-child-background-wait`: 外部起こしが可能な経路の自己タイマーを抑止し、初回開始からの維持期限を規定する。

## Impact

実装対象は `epic-child-state.sh`、`epic-dispatch.sh`、`epic-launch-orca.sh`、子と親の待機手順、既存 Bats 三本、変更記録。既存三 capability は同じ維持動作の記録・送信・待ち方を別々に規定しているため、整合して初めて受け入れ条件を満たす一つの PR とする。受信定義・一行応答・child-log の除外・予約文のフック除外は再実装しない。#1797 の異種予約文の扱いは対象外。

Orca の判定拡張で実作業中にも予約文が届く残余リスクがある。頻度は未計測であり、後続 PR のリスク宣言に具体的な影響と制限を記し、主の許容を取る。
