# loops-loop-types-reference Specification (Delta)

## ADDED Requirements

### Requirement: loop-types.md は公式 4 タイプの選択リファレンスを提供する

`plugins/loops/references/loop-types.md` は、公式記事「Getting started with loops」に基づく 4 ループタイプ — ターンベース / ゴールベース / タイムベース / プロアクティブ — の一覧表を含まなければならない (MUST)。各タイプについて「手放す対象」（ターンベース = 検証ステップ / ゴールベース = 停止条件 / タイムベース = トリガー / プロアクティブ = プロンプト自体）、対応するネイティブプリミティブ（skill の自己検証 / /goal / /loop・/schedule / 合成）、使い分けの基準、具体例を記載すること。

#### Scenario: 4 タイプの表が存在する

- **WHEN** `plugins/loops/references/loop-types.md` を grep する
- **THEN** ターンベース・ゴールベース・タイムベース・プロアクティブの 4 タイプがすべて記載され、各タイプに手放す対象と対応するネイティブプリミティブが対応付けられている

#### Scenario: 使い分けと具体例が記載されている

- **WHEN** 各タイプの説明を読む
- **THEN** どういう業務にどのタイプを選ぶかの基準と、具体例（例: PR 面倒見 = タイムベース、テスト全 PASS まで = ゴールベース）が記載されている

### Requirement: 実行機構との責務分離を 1 節で明記する

`plugins/loops/references/loop-types.md` は、実行機構との責務分離を説明する節を 1 つ含まなければならない (MUST)。この節では、レシピ側が宣言するのは「発火時に投入するプロンプト」「推奨頻度」「停止基準」「実行環境の制約」までであり、どう定期実行するか（スケジューラへの登録・セッション運用・課金選択）はレシピおよび loops プラグインのスコープ外＝呼び出し側の責務であることを明記すること。レシピは実行方法非依存に書く方針であることを含めること。

#### Scenario: 責務分離の節が存在する

- **WHEN** `plugins/loops/references/loop-types.md` の見出しを確認する
- **THEN** 実行機構との責務分離を扱う節が存在し、レシピの宣言範囲 4 項目（発火時プロンプト / 推奨頻度 / 停止基準 / 実行環境の制約）が記載されている

#### Scenario: 定期実行の配線がスコープ外であると明記されている

- **WHEN** 同じ節を読む
- **THEN** スケジューラへの登録・セッション運用・課金選択は呼び出し側の責務であり、レシピは実行方法非依存に書くことが明記されている
