## Context

親の止まりの検知は #1744（`epic-dispatch.sh` の `WAIT_TURN_DEFS`）で、状態の記録の `turn_input.sender` が `owner` でなく、`turn_state` が有効な `主の返事待ち`（または `dependency_wait: true` の作業報告）のものだけを対象にする形になった。手順書はこの前の形（会話ログの最後の発言から止まりを読む）のまま、止まりの出どころを書いていない。

## Decisions

- 手順書に書く止まりの出どころは、スクリプトの現在の動きと同じ 3 点にする: ① 主が子のタブで打った入力から始まったターン（`sender: owner`）は何もしない ② 親が送った入力（頭が `親エピック #`）か起動時の指示から始まったターンの `主の返事待ち` は、今までどおり親が主に知らせるか親が答えてよい件なら返す ③ 状態の記録が無いまま終わったターンは止まりにせず `--resolve` の判断にも回さない。依存待ちの作業報告は `epic-loop.md` の依存待ちの手順が先に扱うので、手順 8 には繰り返さず参照だけ置く
- 手順 8 の `child-log --last` の読みと `dismiss` の節は残す。これらは、すでに状態の記録で決まった止まりの説明を組み立てる・判断が崩れた止まりを戻すためのもので、止まりを推し量る使い方ではない。その旨を新しい一文で明示し、`dismiss` の節の前提を変えない（`dismiss` の要件は変えない）
- 返事の送り方は、`reply --as parent` / `--as owner` と `wait --resolve` が子の表で自動判定する現状（#1742）に合わせ、親が表で分類する書き方を `reply` の 2 か所（手順 8 の主の答え・委任で送る段落）から外す。`notify-closed` には自動判定が無いので、`reply-after-idle.md` の「本体が表で分類し」はそのまま残す（#1768 の指摘の整理）
- 表の読み順は、表の前置きに「上から順に読み、最初に当たった行で決める」を足して明示する。現表の行の順序と内容は変えない

## Risks

- 手順書の文言を検査する bats（`develop-skill.bats` の `reply-after-idle` の表の行）が、行の文言変更で落ちる。表の行は変えず前置きだけ足すので、落ちるのは前置きの検査のみ（実装で確かめる）
- 要件の文と手順書の文を同じ PR で直すので、片方だけ戻すと食い違う。戻すときは手順書・spec を同時に revert する
