## Context

`plugins/dev-workflow/scripts/git-destructive-guard.sh` の判定部（埋め込みの python3）は、コマンド文字列を次の順で読んでいる（行番号は main ba8f9838 時点）。

1. `substitutions`（77-115）: `$(...)` とバッククォートの中身を取り出す。単一引用符だけを見て、置換の中の引用は追わずに括弧の数だけで終わりを決める（F4）
2. `normalize`（118-156）: 引用符の外の改行を ` ; ` に置き換え、ヒアドキュメントの本文を取り除く。区切り語を `[A-Za-z_][A-Za-z0-9_]*` の正規表現で取るので `END-TAG` は `END` までしか読まず、`<<<` もヒアドキュメントとして扱う（F9）。コメントを知らないので `#` の後ろの `'` で引用状態に入る（F5）。バックスラッシュと改行の組をそのまま残す（F7）
3. `tokenize`（159-167）: `shlex`（`punctuation_chars=True`）で字句に分ける。返る字句は文字列だけで、引用された `;` と演算子の `;` の区別が消える（F8）
4. `simple_commands`（170-190）: 演算子の字句で単純コマンドを区切る。リダイレクトも区切りとして扱うので `git reset >/dev/null --hard` が `git reset` と `--hard` に割れる（F6）。改行を含む字句は捨てる（F1。複数行の `-m` を読まないための処置だったが、`bash -c` の引数や `-c` の設定値まで捨てる）
5. `judge`（201-211）: 置換の中身を先に再帰で判定し、そのあと 2〜4 の結果を単純コマンドごとに判定する。置換の取り出しがヒアドキュメントの除去より前なので、引用されたヒアドキュメントの本文の `$(...)` まで判定する（F10）

F1・F4〜F10 の 8 件は、すべてこの「字句の読み」の段で起きている。git のサブコマンドとオプションの解釈（`judge_simple` 以降、`parse_opts` / `judge_git` / `judge_push`）には原因が無い。

同じファイルを #821（git と wrapper のオプション解釈）と #822（Unicode エスケープのテスト）が並行して直している。#821 は `judge_simple` の wrapper の読み飛ばし（214-226）と `parse_opts` 以降、#822 は bats の Unicode の検査とその周辺を触る見込み。

## Goals / Non-Goals

**Goals:**

- F1・F4〜F10 の 8 件の入力で、hook の結果をシェルの実際の動きに合わせる（実行される git は止め、実行されない文字列は通す）
- 既存の bats（判定 9 種・対象外・メッセージ本文・オプションの値・ヒアドキュメントの後ろ・モード・拒否理由・fail-open・閉じていない引用符・hooks.json）をすべてそのまま通す
- #821・#822 と衝突しにくい形で入れる（触る範囲を字句の読みに限り、bats は 1 か所のまとまりに足す）

**Non-Goals:**

- bash の文法の完全な実装（`case` の `)`、算術式 `$((...))` の中身、`${...}` のパラメータ展開の中の置換、プロセス置換 `<(...)` の中身の判定、`function` 定義、zsh 固有の構文）。今回の 8 件と同種の形を直すのが目的で、守備範囲の「塞ぎ切ることは完了条件にしない」は変えない
- git と wrapper のオプション解釈（#821）、Unicode エスケープ（#822）、F2・F11・F12（修正済み）・F13・F14
- 判定 9 種・ask / deny・逃げ道・fail-open の変更

## Decisions

### 字句の読みを、引用状態と種別を保つ 1 回の走査に置き換える

`substitutions` / `normalize` / `tokenize` / `simple_commands` の 4 段を、1 つの字句解析（以下「字句読み」）に置き換える。字句読みはコマンド文字列を先頭から 1 文字ずつ読み、次の状態を持つ: 引用なし／単一引用符の中／二重引用符の中、語の途中か語の境目か、読み残しのヒアドキュメント（区切り語・`<<-` か・区切り語が引用されていたか）。出力は「単純コマンドの並び（各コマンドは語の並び）」と「中を判定すべき置換の中身の並び」の 2 つ。各語は引用除去後の文字列とする（現状の `shlex` の出力と同じ値なので、`judge_simple` 以降はそのまま使える）。

字句読みが守る規則:

- **演算子は引用の外でだけ演算子になる**（F8）: `;` `&&` `||` `|` `&` `(` `)` と引用の外の改行で単純コマンドを区切る。引用符の中やバックスラッシュの後ろの同じ文字は語の一部
- **行継続**（F7）: 引用の外と二重引用符の中のバックスラッシュ＋改行は、何も無かったものとして読み飛ばす。単一引用符の中では文字どおり残す
- **コメント**（F5）: 引用の外で、語の境目にある `#` から改行の手前までを読み飛ばす。引用符の中の `#` と、語の途中の `#`（`a#b`）はそのまま語の一部
- **リダイレクト**（F6）: `<` `>` `>>` `<>` `>|` `>&` `<&` `&>` `&>>` と、直前に数字だけの語が接していればその fd（`2>`、`2>&1`）を 1 つのリダイレクトとして読み、次の語をその対象として取り除く。単純コマンドは区切らない（`git reset >/dev/null --hard` は `git reset --hard` として判定する）
- **ヒアドキュメント**（F9・F10）: 引用の外の `<<` と `<<-` の次の語を区切り語とする。区切り語は引用除去後の語全体（`END-TAG`、`'EOF'` → `EOF`）で、区切り語のどこかに引用符かバックスラッシュがあれば「引用された」とする。本文は、その行の改行の次から、`<<` なら行全体が区切り語と一致する行、`<<-` なら先頭のタブを除いて一致する行までで、本文の行はコマンドとして読まない。引用されたヒアドキュメントの本文からは置換も取り出さない（F10）。引用されていない本文の `$(...)` とバッククォートは、シェルが実行するので置換として取り出して判定する
- **here-string**（F9）: `<<<` は here-string として読み、次の語を通常の語として扱う（ヒアドキュメントの読み残しを作らない）
- **置換**（F4）: 引用の外と二重引用符の中の `$(` は、中身を同じ字句読みで読み進めて、引用の外にある対応する `)` で閉じる（中身の中の引用符・入れ子の置換・コメント・ヒアドキュメントを追う）。バッククォートはエスケープされていない次のバッククォートで閉じる。取り出した中身は現状どおり `judge` に再帰で渡し、置換を含む語は語としてそのまま残す。単一引用符の中は置換にしない
- **改行を含む語は捨てない**（F1）: 引用符の中の改行を含む語も 1 つの語として残す。`bash -c` / `sh -c` / `zsh -c` の引数と `eval` の引数は現状どおり `judge` に再帰で渡すので、その中の改行は連結として判定される。それ以外の位置の語（`git commit -m` の値、`echo` の引数、`git -c` の設定値）は、`judge_simple` 以降の既存の規則でコマンドとして読まれない
- **引用符が閉じていないとき**: 現状どおり、空白と改行で割った字句に同じ判定をかける（既存要件「逃げ道と fail-open」の振る舞いを変えない。文面の扱いは下の「要件は ADDED で足し、既存要件の文面は変えない」）

代替案: 現在の 4 段を残し、穴ごとに継ぎ当てる（`normalize` にコメントと行継続と区切り語を足し、`substitutions` に引用の追跡を足し、`simple_commands` にリダイレクトの例外を足す）。F8 は `shlex` が引用された `;` と演算子の `;` を同じ文字列で返す以上、`shlex` を使う限り直せない。F10 は置換の取り出しとヒアドキュメントの除去が別の走査なので、片方の結果をもう片方に渡す仕組みを足すことになり、同じ引用の追跡が 3 か所に重複する。8 件のうち 6 件が「引用状態を別々の走査で数え直している」ことに由来するので、1 回の走査にまとめる方を採る。

### 改行を含む語の扱いと、既存の MUST NOT の書き分け

既存要件「破壊的 git 操作を Bash の実行前に検出する」は「ヒアドキュメントの本文と、引用符の中の改行より後ろの行（commit メッセージや issue コメントの本文に書いた git の行）もコマンドとして読んではならない（MUST NOT）」と書いている。F1 の `bash -c '<改行>git reset --hard'` は、引用符の中の改行より後ろの行を、シェルが実際にコマンドとして実行する形である。この MUST NOT の意図は括弧書きのとおりメッセージ本文の誤読を防ぐことで、`-c` / `eval` の引数を除外する意図ではない（同じ要件が `bash -c` と `eval` の引数を判定する MUST を持つ）。そこで新しい要件の中で「`bash` / `sh` / `zsh` の `-c` と `eval` の引数として渡された文字列は、引用符の中の改行を含んでいてもコマンドとして判定する。既存の MUST NOT は、それ以外の位置の引用文字列に適用する」と書き分ける。

同じ MUST NOT の「ヒアドキュメントの本文」の側も書き分ける。この MUST NOT は本文の行を単純コマンドとして読まないことを指す。引用されていない本文の `$(...)` とバッククォートはシェルが実行する（本文を書き出す前に展開される）ので、この MUST NOT に当たらず、置換として中を判定する。引用された本文の置換はシェルが展開しないので判定しない（F10）。

### 要件は ADDED で足し、既存要件の文面は変えない

既存要件の MUST NOT の位置を直接書き換える（MODIFIED）方が読みやすい。しかし MODIFIED は要件ブロック全体を書き写して置き換えるので、#821 が同じ要件（オプション解釈の規則が同じブロックにある）を MODIFIED で直してどちらかが先に archive されると、後から archive した側の書き写しが先の変更を黙って消す。衝突を避けるため、この change は要件「コマンド文字列をシェルと同じ単位で読む」を ADDED で足し、既存要件との関係（上の書き分け）はその中に書く。両方が main に入ったあとで要件を 1 つにまとめたくなったら、別の change で行う。

要件「逃げ道と fail-open」も、「`shlex` が引用符の不整合で字句に分けられないときは、空白で割った字句に同じ判定をかけなければならない（MUST）」と `shlex` を名指ししていて、この change で `shlex` を使わなくなると文面と実装がずれる。振る舞い（閉じていない引用符は空白と改行で割って判定する）は変えないので、要件を MODIFIED で書き直さず、新しい要件の 9 項目めに「`shlex` が…分けられないとき」は字句読みが引用符の閉じていない入力を受けたときと読む、と読み替えを書く。MODIFIED にしない理由は 2 つ。1 つ目は、この要件には `\u00` を見る早期 exit の規則があり、Unicode エスケープを扱う #822 が同じ要件を MODIFIED で直す可能性が残る（#821 が MODIFIED にするのは「破壊的 git 操作を Bash の実行前に検出する」だけだと R1 が確認したが、#822 はまだ change が無い）。2 つ目は、振る舞いを変えない文面の読み替えのためだけに要件のまとまりを丸ごと書き写すと、archive の順によって相手の変更を消す危険を負うことになり、得るものに見合わない。

守備範囲は、新しい要件の中に独立した段落として書く（入力の出どころ、拾いたい誤り、通してよい入力、誤検知の側に倒れる形の扱い）。既存要件の守備範囲を参照するだけでは、PR レビューで「この形はまだ通る」「まだ止まる」と言われたときに範囲外と判定する根拠が新しい要件の側に無いため。予約語や記号が単純コマンドの先頭に来る形（`do` / `then` / `{` / `!`）は変更の前も後も取りこぼすので、通してよい入力の例として明記する。

### テストの置き場所

bats は `out of scope: message bodies are not read as commands`（156-163）の直後、`# --- 引数を取るオプションの値` の見出し（165）の前に、見出しコメント `# --- シェル構文の読み（#820 F1・F4〜F10） ---` 付きのまとまりとして足す。#821 はオプションの値のまとまり（165-207）、#822 は Unicode の検査（312 付近）を触る見込みで、行が重ならない。各 F について「止まる入力」と、同じ構文で「通す入力」（引用された `;`・`|`・`&`、引用ヒアドキュメント本文の置換、単一引用符の中の `\`＋改行、引用符の中の `#`、複数行の `-m`）を対にする。

## Risks / Trade-offs

- [字句読みの書き換えで、既存の検出が落ちる] → 既存の bats を 1 件も変えずに通すことを実装の完了条件にする。加えて、書き換え前のスクリプトと書き換え後のスクリプトに同じ入力（既存 bats の全入力と #820 の入力）を流し、結果が変わったのが #820 の入力だけであることを確かめる
- [自前の字句読みは、`shlex` が扱えていた形を取りこぼしうる（例: `$'...'` の ANSI-C 引用、`${...}` の中の `}`）] → 現状の `shlex` も `$'...'` の中のエスケープを解釈しない。`$'...'` は単一引用符と同じく中を語として読み、置換を取り出さない。`${...}` の中の置換は Non-Goals に置き、取りこぼしは守備範囲どおり「通ることを許す入力」の側に倒れる
- [誤読で「止める」側に倒れる新しい誤検知] → 起きても ask / deny が出るだけで、確認画面で主が通せる（PR #794 のゲートの仕分けと同じ扱い）。bats の「通す入力」の対で主要な形を固定する
- [#821 / #822 との衝突] → 触る範囲を `substitutions`〜`judge`（77-211）と bats の 1 か所に限る。`judge_simple` の wrapper の読み飛ばし（214-226）と `parse_opts` 以降は触らない。先に main に入った側があれば、実装の最初に origin/main を取り込んでから着手する
