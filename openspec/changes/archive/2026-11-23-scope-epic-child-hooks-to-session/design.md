# Design

## Context

動機は proposal.md を参照。`epic-child-state.sh` は worktree と `agent_id` で候補を決め、入力ごとに payload の ID で `turn_input` を置き換える。Stop には既に ID とログパスの照合があるが、入力側の誤更新を防げない。`epic-state.sh` の `session` は端末ハンドルであり、Claude セッション ID ではない。

既存の `startup` 判定は、入力先頭の `/develop #<子> （エピック #<親> の子。…）` と記録の子番号・親番号を照合する。別 repo 表記がある場合はエピックの repo を照合し、省略時は子とエピックが同じ repo のときだけ一致とする。Orca と tmux の起動・再起動指示はこの形を既に使う。排他は `epic-state.sh` の記録単位のロックを共用している。

## Goals / Non-Goals

**Goals:** 別セッションの入力・Stop によって本来の子のターン情報が変わらず、本来の子の次の Stop が保存できること。初回と正規の起動し直しを同じ規則で登録し、親が読む任意拡張の形を維持すること。

**Non-Goals:** 親の wait / reply / resolve、送信先の端末選択、launcher の API、フック配線、既存の番号・URL 検査、別セッションによる意図的な起動指示の偽装を変更・解決しない。`route` や `mark` の worktree 検索も変更しない。

## Decisions

### 既存 ID と一致する起動指示で登録・切替を管理する

設計上の選択は対象 ID の決め方1件にまとめる。`turn_input.session_id` を使い、別のトップレベル ID や状態ファイルは足さない。`turn_input` / `turn_state` が共に無い旧記録だけを未登録とする。既に拡張があって型不正なら、未登録として上書きしない。

| 記録とイベント | UserPromptSubmit | Stop |
|---|---|---|
| payload の ID が空・未設定・文字列でない | 対象外 | 対象外 |
| 未登録、親子・repo が一致する起動指示 | generation=1、sender=startup で登録 | 起動形のテキストがあっても登録しない |
| 未登録、それ以外 | 対象外 | 対象外 |
| 記録の ID と同じ | 既存の分類・世代更新・予約文除外 | 既存の状態検査・世代照合 |
| 異なる ID、一致する起動指示 | 既存世代+1、sender=startup で切替 | 切替しない |
| 異なる ID、それ以外 | 対象外 | 対象外 |

同一 ID で起動指示を再び送っても登録し直しではなく通常入力（既存どおり owner）。異なる ID の `親エピック #` / `主の返事（親エピック #` は一致する起動指示ではなく対象外。別 repo の番号だけが一致しても登録・切替しない。先頭以外の引用は起動指示にしない。予約文は未登録時にも登録を作らず、登録済みの元の状態も保つ。

採らない案:

- launcher が `--session-id` 用 ID を先に発行・保存する: 強く対象を固定できるが、起動・再起動・起動失敗・取り込みの契約と両 launcher を変更する。今回の誤更新は既存拡張で防げるため採らない。
- 異なる ID を常に拒む: 正規の再起動が新しい ID になるので採らない。
- 未登録の最初の任意入力で ID を確定する: 別セッションが先着すると同じ問題になるので採らない。

### 対象の識別を副作用とターンの詳細検査より前に置く

通常入力で対象外と分かれば stdout / stderr 空の exit 0 で返す。`turn_input` / `turn_state` に加え `updated_at` と未知項目を含む記録全体を一切変えない。対象外 Stop では既存ガードを同じ payload で1回だけ実行した出力と終了コードを返し、状態行を要求しない。既存ガードの block はそのまま返すが、本来の子の `turn_state` を null にしない。

順序は worktree 候補検索 → ID と起動指示による対象の識別 → 対象の拡張・payload・ログの詳細検査とする。異なる有効 ID が記録から読めるなら、拡張の別項目が壊れている、別セッションの prompt が文字列でない、ログパスが無い・読めない、ロックが残っている、保存の設定が不正、という場合も対象外にできること。対象外と分かる入力のために状態ロックを待たない。

対象 ID が一致する、または一致する起動指示で登録・切替する場合には、既存の拡張検査・ログ境界・状態行・保存失敗の契約を保つ。記録に拡張はあるが ID 自体が読めない型不正では他セッションと確定できないので、従来の拡張不正のエラーとし、未登録扱いにはしない。worktree の候補が複数の場合も既存のエラーを維持する。

入力の事前識別後、既存の入力ロック内で再読した記録に対して同じ対象判定を繰り返す。S1 の通常入力が事前判定を通っても、ロック取得までに S2 の起動指示で切り替わっていれば S1 は書き込まない。Stop は現在のスナップショットのセッションとログを照合し、保存時には既存どおり `turn_input` 全体を同じロック内で再照合する。切替後の旧 Stop は公開も無効化もできない。

## Risks / Trade-offs

- 起動形は認証ではない → 別セッションから親子・repo の一致する起動指示を意図的に送ると切り替わる。古いセッションで同じ起動指示を再送した場合も同じ。通常の別セッション／`claude -p` の誤認防止が守備範囲で、強い所有権の証明は完了条件にしない。この動作を試験にも残す。
- 未登録の旧記録では任意の通常入力で自動登録しなくなる → 一致する起動指示を送り直す手順を子の文書に記す。未登録 Stop は新たに状態行を要求せず既存ガードへ戻す。
- 修正前に別セッションで上書き済みの ID は正規 ID と区別できない → 更新だけで復旧済みと扱わない。本来の子のセッションに一致する起動指示を送り直して再登録する。
- 初回起動と未登録セッションの Stop が競合する → Stop では登録せず、入力側の排他更新のみで登録する。切替と旧入力・旧 Stop の競合を Bats で再現する。

## Migration Plan

この工程では artifact のみを commit し、R1 APPROVE を待つ。実装後も schema=1 と既存項目の形を維持するため、正常な `turn_input` のある子は同じセッションの次の通常入力・Stop から利用できる。未登録または誤った ID が保存された記録は、既存 launcher が生成する記録に一致した起動指示を本来の子に送り直す。予約文や任意の主の入力で自動登録しない。

子の文書と `plugins/dev-workflow/changes/1756.md` にこの移行と限界を記す。版は上げない。archive と現行仕様への反映は後続 finish 工程。戻す場合は実装と仕様反映を revert し、任意拡張の削除・手動移行は不要。戻すと worktree の別セッションによる誤更新も戻る。
