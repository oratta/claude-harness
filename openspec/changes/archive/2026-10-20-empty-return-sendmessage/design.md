## Context

`continue: false` で打ち切られた子の結果は、親には `(Subagent completed but returned no output.)` だけで届く（#1108 の実機確認。`openspec/changes/archive/2026-10-19-subagent-git-guard-deny/design.md`「実機確認の結果」）。W は名前付きで起こして SendMessage で再開する設計なので、報告を求める経路が既にある。実機で SendMessage により報告を取り直せたのはバックグラウンドで起こした子である。ただし現行の SKILL.md の W 起動指示に `run_in_background: true` の指定は無く、W が確認済みの前提を満たす根拠は「名前付きで起こした Agent の子は SendMessage で再開でき、develop 本体の環境では既定でバックグラウンドで返る」という見立てに依る。この見立ては弱いので、実機確認（tasks 2.2）で `run_in_background: true` の子に加えて、指定しない既定の起こし方（W と同じ起こし方）の子でも報告を取り直せるかを確かめ、結果を design 末尾に記録する。既定の起こし方で取り直せなければ、SKILL.md の W 起動指示にバックグラウンド指定を足すかを、その結果を見て決める。R1・G など再開しない役は段ごとに新しく起こす。

この change の対象は W だけにする。issue の受け入れ条件も実機確認も W 相当の子を想定している。R1・G・レビュアーが空で返ったときは範囲外とし、既存の手渡しの許可条件（空の return は `工程中断:` 扱いで、停止確認などの条件を満たすまで新しい役を起こさない）に従う。

## Decisions

### 報告を求めるのは 1 回だけ

SendMessage で報告を求めるのは 1 回だけにする。再開後の子は破壊的操作を打たないので回数は増えず、1 回で足りる。1 回求めても空なら、子の中で何が起きたか分からないので、同じ指示で起こし直さず主に上げる。回数を決めずに待つと、止まった子を相手にワークフローが止まる。

### 作業ツリーは報告に頼らず確かめる

報告の有無によらず、`git -C <path> status --porcelain` で未コミット差分を確かめる。打ち切られた子は commit できていない可能性があり、差分が残っていれば本体が引き取る（既存の要件「強制停止で止まった作業ツリーは本体が引き取る」と同じ扱い）。

### 打ち切りと分かったら起こし直さない

報告に破壊的 git 操作で打ち切られたとあれば、同じ指示で子を起こし直さない。同じ指示では同じ操作に当たるため。主に、打ち切られた操作と、その子に任せる範囲の見直し（本体か主が操作を行う、指示を変える）を上げる。報告が打ち切り以外の理由を示すなら、通常の失敗の扱い（昇格トリップワイヤー）に従う。

### 再報告も空なら主に上げる

1 回求めても報告が空、または原因が読み取れないときは、同じ指示で起こし直さず、空だったことと作業ツリーの状態（`git status --porcelain` の結果）を主に上げる。

### 再開しない役は範囲外

R1・G・レビュアーのように再開しない役が空で返ったときは、この change では扱わない。既存の要件（手渡しの許可条件、G が工程中断で返したときの扱い）に従う。これらを同じ段で起こし直す方針は、空の return が `工程中断:` 扱いで停止確認などの条件を要するため、既存の spec と衝突する。

## Risks / Trade-offs

- 報告の書き直しは子のコンテキストを 1 往復分増やす。1 回に限るので上限は小さい
- SendMessage で再開した子の報告が、打ち切りの理由を正しく書く保証は無い。そのため、差分の確認は報告に頼らずに行う

## 実機確認の結果

2026-10-20、Claude Code 2.1.303 で確かめた。親は `claude -p --setting-sources project,local --plugin-dir <worktree>/plugins/dev-workflow --permission-mode bypassPermissions --model sonnet`、子は `general-purpose`（`model: haiku`、`name` 付き）。`TMPDIR` は実験ごとに scratchpad の空のディレクトリに向け、子には scratchpad の使い捨て repo で `checkout -- a.txt` と `checkout -- b.txt`（どちらも `-C <repo>` 付きの git）を打たせた。親には、子の結果が `(Subagent completed but returned no output.)` だけなら SendMessage で報告を求めるよう指示し、最後に目印の行 `PARENT-CONTINUED` を出力させた。

- 子に「拒否されたら打ち直せ」と指示する形では、haiku も sonnet も hook の文面に従って 2 回目を打たず、打ち切りに至らなかった。そこで 2 つの Bash 呼び出しを同じメッセージで並列に発行させ、2 回拒否させた
- **バックグラウンド指定あり（`run_in_background: true`）**: 回数のファイルは `2`。子は打ち切られ、親には結果本文のない完了通知だけが届いた。親が SendMessage で報告を求めると、子は何をしようとして何が拒否されたか、2 回の拒否で打ち切られたこと、repo が変わっていないことを報告に書き直した。親は `PARENT-CONTINUED` を出力した
- **既定の起こし方（`run_in_background` を指定しない）**: 回数のファイルは `2`。親には同じく結果本文のない完了通知だけが届き（完了通知が非同期に届いたので、既定でもバックグラウンドで返る）、SendMessage で同様の報告を取り直せた。親は `PARENT-CONTINUED` を出力した
- 使い捨て repo の作業ツリーは両方とも変わっていない（拒否されたため）

**決めた方**: 既定の起こし方でも報告を取り直せたので、SKILL.md の W 起動指示に `run_in_background` の指定は足さない。
