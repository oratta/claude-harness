## MODIFIED Requirements

### Requirement: 実作業の待ちは一時間キャッシュを確認して維持する

セッションを保持する子の本体は、自分の現行会話の TTL が 1h、最後の成功リクエストから 3600 秒未満と確認でき、既存の待ちが 45 分以内に本体へ返らない場合に、45 分の有限な自己通知を一つだけ用意しなければならない（MUST）。最初のタイマーを置いた時刻をその待ちの基点として保持し、同じ待ちの再設置で更新してはならない（MUST NOT）。維持の上限はこの基点から12時間とする。本体へ制御が戻らない前景呼び出しやツールが使えない環境で維持を保証してはならない（MUST NOT）。判定の守備範囲は「長い待ちの入力判定の守備範囲を共有する」に従う。

#### Scenario: 大きい会話の agent 待ち
- **WHEN** 会話 20 万トークン、TTL 1h の nested 本体が、60 分を超えうる実行中の agent を保持して待つ
- **THEN** 停止済み子の 150k の除外条件を流用せず、本体自身の有限な自己通知を使い、元の agent を終了・再起動しない

#### Scenario: 既存の期限通知を利用する
- **WHEN** Monitor の期限や有限の前景コマンドが 45 分以内に本体へ返り、次のモデルリクエストが発生する
- **THEN** その通知や返りを利用し、同じ待ちに追加のタイマーを重ねない

#### Scenario: 再設置で維持の基点を延ばさない
- **WHEN** 同じ元作業を待つ間に自己通知を受け、次のタイマーを置く
- **THEN** 最初のタイマーを置いた時刻を保持し、12時間の計測をその再設置時刻からやり直さない

### Requirement: 自己通知と元作業の決着を区別する

自己通知は起動時に保持した ID と成功した終了で識別しなければならない（MUST）。受信では元の作業が未完了で現在も維持対象、かつ最初のタイマーを置いた時刻から12時間未満の場合だけ次の一回を用意しなければならない（MUST）。12時間以上なら次のタイマーを置かず、元作業と実行IDを保持して完了通知を待ち続け、届いたときに一度の書き直しを受け入れなければならない（MUST）。上限到達を理由に元作業を捨てたり止めたりしてはならない（MUST NOT）。自己通知では通常の調査・実装・投稿・停止状態の変更を行ってはならない（MUST NOT）。通知だけで工程完了、CI 決着、Codex 委譲成功を宣言してはならない（MUST NOT）。判定の守備範囲は「長い待ちの入力判定の守備範囲を共有する」に従う。

#### Scenario: CI がまだ実行中の維持通知
- **WHEN** 本体の自己通知が成功し、元の CI wait は未完了で、最初のタイマーから12時間未満かつ現在も維持対象である
- **THEN** 本体は CI の途中出力を読まず、別の CI wait を起動せず、CI の timeout や settled と解釈せず、キャッシュ維持に必要な待ち直しだけを行う

#### Scenario: 通知の文字列が一致しても別作業
- **WHEN** 別タスクの出力や引用が自己通知と同じ文字列を含むが、保持した ID と一致しない
- **THEN** 自己通知とみなさず、元の作業の通知として従来の処理へ渡す

#### Scenario: 12時間に達した通知では再設置しない
- **WHEN** 自己通知を受け、元作業は未完了だが最初のタイマーから12時間に達している、または12時間を超えている
- **THEN** 現在の TTL が 1h でも次のタイマーを置かず、元作業と実行IDを保持し、元作業の完了通知を待ち続ける

#### Scenario: 上限後に元作業の完了通知が届く
- **WHEN** 12時間上限により維持を終えたあと、キャッシュが切れてから元作業の完了通知が届く
- **THEN** 一度の書き直しを受け入れて元作業の結果を回収し、キャッシュのために作業を停止・再起動せず、維持タイマーも再開しない

### Requirement: 費用の見積もりと実機確認を分けて記録する

実装前に、会話 20 万トークンの再書き込み・維持・停止と再起動の費用、単価の根拠、選択と理由を #1743 に記録しなければならない（MUST）。12時間上限を反映した比較を新しいコメントで追加し、手順書と変更記録の費用の結論を合わせなければならない（MUST）。TTL と API 定価換算の前提、維持の tool 往復と新規入力・出力の追加費用を示し、見積もりやテスト合格を実機の削減成功と扱ってはならない（MUST NOT）。

#### Scenario: 通知が無い一日待ちとも比べる
- **WHEN** 24 時間の維持と書き直しを比較する
- **THEN** 無上限で維持した旧会話部分の約 $2.52 と、12時間で維持を打ち切る新方針を区別する。毎時再開する場合と最後に一回だけ再開する場合を分け、キャッシュの失効だけでは課金されないことを明記する

#### Scenario: 12時間上限の費用比較を追記する
- **WHEN** 初回タイマーを基点とする12時間の維持費を見積もる
- **THEN** 記録済みの単価と会話20万トークンの前提で、維持16回と最後の再開を `(2 × 16 + 1) × 0.2 × $0.20 = $1.32` と概算し、一度の1h書き直し `0.2 × $8 = $1.60` を超えないと示す。これは旧会話部分の比較とし、追加の入出力・ツール往復や上限後の書き直しを含む総費用の保証にしない

#### Scenario: マージ前の契約テストが合格する
- **WHEN** 手順の参照・タイマーの雛形・例外のテストが通る
- **THEN** 合格は手順と雛形の検証として報告し、マージ後の実子の 60 分超の usage 観測は未実施として残す
