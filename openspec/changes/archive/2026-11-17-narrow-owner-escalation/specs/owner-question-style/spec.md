## ADDED Requirements

### Requirement: 設計の分かれ目は主の観点として、主を止めずに報告に載せる

`output-styles/readable.md` の節 3 と、その短い版の `rules/communication-style.md` の 3 は、運用の形・構造の分け方・将来の拡張に効く設計の分かれ目（複数の案があり、選び方で後の運用・構造・拡張のしやすさが変わるもの）を、主の指摘が効く観点として書かなければならない（MUST）。扱いは、主に聞く理由にせず（それだけを理由に主を止めない）、決めた内容と他の案（採らなかった案と採らなかった理由）を報告（完了報告、エピックの親の報告）に載せる、と書かなければならない（MUST）。主に聞く理由の 3 つ（主の側にしか答えが無い・決まりで主の承認が要る・主の手でしかできない操作）は増やしてはならない（MUST NOT）。

理由: 2026-11-17 の調査で、主の指摘で方針が変わった 23 件のうち 19 件が設計・運用・拡張性で、安全面は 0 件だった。論点の無い依頼を減らすと、これらの指摘の場面まで失われうるので、止めずに渡す経路を置く。

#### Scenario: 正本と短い版に主の観点と扱いが書かれている

- **WHEN** `output-styles/readable.md` の節 3 と `rules/communication-style.md` の 3 を読む
- **THEN** どちらにも「運用の形・構造の分け方・将来の拡張」の語と、主を止めずに決めた内容と他の案を報告に載せる扱いが書かれ、主に聞く理由は 3 つのまま

#### Scenario: テストが主の観点の記述を確かめる

- **WHEN** `bats tests/owner-question-style.bats` と `bats tests/injection-budget.bats` を実行する
- **THEN** どちらも exit 0 で、前者に正本と短い版の両方で主の観点の語と「報告に載せる」扱いを確かめるテストがある
