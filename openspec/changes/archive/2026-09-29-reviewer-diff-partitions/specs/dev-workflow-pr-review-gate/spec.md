## ADDED Requirements

### Requirement: 差分が 600 行を超えたら Claude のレビュアーを区画に分ける

pr-review-gate の手順 2-0（`stages/prepare.md`）は、一周目のレビューについて、PR の差分の行数（PR files API が返すファイルごとの追加＋削除の合計）が 600 行を超えたら差分を区画に分けることを書かなければならない（MUST）。600 行以下なら区画に分けてはならない（MUST NOT）。

区画はファイル単位とし、PR files API が返す順にファイルを 1 つずつ見て、次の規則を上から順に当てはめなければならない（MUST）:

1. 変更行 0 のファイル（バイナリ・改名のみ）は、直前のファイルと同じ区画に入れる。直前のファイルが 400 行を超えて単独の区画になっていても同じ区画に入れる（0 行のファイルは区画の行数を増やさないので、単独の区画の「他の変更行を持つファイルと同じ区画にしない」を崩さない）。先頭から 0 行のファイルが続くときは、最初に作られる区画（区画 1）に入れる
2. 1 ファイルで 400 行を超えるものは、新しい区画を始めてそれだけを入れ、その区画を閉じる（次の変更行を持つファイルは新しい区画を始める）
3. それ以外のファイルは、開いている区画に足して 400 行を超えないなら足し、超えるなら（または開いている区画が無ければ）新しい区画を始める

dev-workflow プラグインは、この計算を行うスクリプト `plugins/dev-workflow/scripts/review-partitions.sh` を含まなければならない（MUST）。スクリプトは標準入力から `<追加＋削除>\t<パス>` の行を受け取り、1 行目に `合計: <N> 行`、2 行目に `区画: なし` または `区画: <n>` を出し、区画があれば区画ごとに `区画 <k>/<n>（<M> 行）` の行と、その区画のファイルごとに `- <パス>（<L> 行）` の行を出さなければならない（MUST）。1 列目が 0 以上の整数でない行、またはタブを含まない行が 1 行でもあれば、標準出力に何も出さず、標準エラーにその行を示して終了コード 2 を返さなければならない（MUST）。空入力は `合計: 0 行` と `区画: なし` を出して終了コード 0 とする（MUST）。

区画を計算した側は、結果を `レビュー重量:` の PR コメントの 3 行目以降に載せなければならない（MUST）。develop の G は `needs-reviewer` の payload に `区画:` の欄を持ち、区画の一覧（区画が無ければ `なし`）を載せなければならない（MUST）。

区画ごとにレビュアーを起こすのは、Claude のレビュアー（従来モードの Task サブエージェント、`dev-workflow:decider` のレビュアー、adapter 経路で phase `review` の executor が claude のレビュアー）に限らなければならない（MUST）。Codex のレビュアー（従来モードの Codex CLI、adapter 経路で executor が codex）には区画に分けず差分全体を 1 体に渡さなければならない（MUST）。二周目以降の差分限定の再レビューと全体レビューの周は区画に分けない（SHALL）。

区画の判定（`review-partitions.sh` の入力解析と区画の計算）の守備範囲は次のとおりとする:

- 入力: G（または従来モードでレビュアーを起こす側）が `gh api repos/$R/pulls/$N/files --paginate --jq '.[] | "\(.additions + .deletions)\t\(.filename)"'` で作った行。人が手で書いた一覧や `gh pr diff` の出力ではない。作る側は協力的だが、jq の式やパイプの書き間違い、別の PR の出力を渡す誤りをする前提で扱う
- 拾いたい誤り: 行数の列が数でない行・タブの無い行（jq の式の誤り、`gh pr diff` など別の形式の出力を渡した誤り）を区画の計算に混ぜて黙って誤った区画を出すこと、同じ入力から人や段によって違う区画が出ること（計算を決定的にし、境界の優先順位を上の 3 規則で一意にする）
- 通ることを許す入力の例: パス順に並んでいない入力（入力の順をそのまま使う）、同じパスが 2 回出る入力（重複を検出しない）、別の PR や古い HEAD の files API の出力（形式が正しければ区画を出す）、`gh pr diff` の行数と数行ずれる合計、空白を含むパス
- 範囲外: files API が返すファイル数の上限（3,000 ファイル）を超える PR での欠け、区画の中身がレビューに適した関連のまとまりかどうか、400・600 の値の妥当性（受け入れ条件 5 の事後計測で見直す）。これらを塞ぐことは本要件の完了条件にしない

#### Scenario: 600 行以下は区画に分けない

- **WHEN** ファイルごとの追加＋削除の合計がちょうど 600 行の入力を `review-partitions.sh` に渡す
- **THEN** 出力は `合計: 600 行` と `区画: なし` で、区画の見出しを出さない

#### Scenario: 600 行を超えたらファイル単位で 400 行まで詰める

- **WHEN** 200 行・150 行・100 行・200 行の 4 ファイル（合計 650 行）を `review-partitions.sh` に渡す
- **THEN** 出力は `区画: 2` で、区画 1/2 は先頭 2 ファイル（350 行）、区画 2/2 は残り 2 ファイル（300 行）になる

#### Scenario: 400 行を超える 1 ファイルは単独の区画になる

- **WHEN** 100 行・500 行・100 行の 3 ファイルを `review-partitions.sh` に渡す
- **THEN** 500 行のファイルはそれだけで 1 区画になり、区画の数は 3 になる

#### Scenario: 400 行を超えるファイルの直後の 0 行のファイル

- **WHEN** 100 行・500 行・0 行・100 行の 4 ファイル（合計 700 行）を順に `review-partitions.sh` に渡す
- **THEN** 出力は `区画: 3` で、区画 1/3 は 100 行のファイル（100 行）、区画 2/3 は 500 行のファイルと 0 行のファイル（500 行）、区画 3/3 は最後の 100 行のファイル（100 行）になる

#### Scenario: 形式の崩れた入力は区画を出さない

- **WHEN** 1 列目が数でない行、またはタブを含まない行を含む入力を `review-partitions.sh` に渡す
- **THEN** 標準出力は空で、標準エラーにその行が出て、終了コードは 2 になる

#### Scenario: Codex のレビュアーは区画に分けない

- **WHEN** 差分が 600 行を超え、レビューの実行者が Codex である
- **THEN** レビューを起こす側は区画に分けず、差分全体を 1 体の Codex レビュアーに渡す

### Requirement: 区画を渡されたレビュアーの書き方

`stages/reviewer-brief.md` のレビュアー向け指示ブロックは、区画を渡されたときの書き方を含まなければならない（MUST）: 読む範囲は区画のファイルとし（照合表の grep はリポジトリ全体のまま）、変更点 ID と finding ID の頭に `P<k>-`（k は区画の番号）を付け、`変更点の一覧` はその区画のファイルに関わる受け入れ条件だけを被覆して関わらないものは `区画の対象外: <受け入れ条件 ID>` と書き、`ハンク被覆` は区画のファイルの全ハンクを被覆し、照合表の `検索コマンド:` には SHA を書かず文字どおり `<rev>` と書き、テスト・lint の再実行は区画 1 のレビュアーだけが行う（他の区画は再実行しなかったことを要約に書く）。

既存要件「レビュアーへの指示に全件列挙と再レビューの制限を含める」の「各受け入れ条件は 1 項目以上に対応させる」と「固定した PR diff の各ハンク」は、区画に分けたときは全区画の和集合で満たすものとしなければならない（MUST）。

レビュアーを起こす側（`stages/reviewer-brief.md` の入口と `stages/review-run.md`）は、区画ごとに 1 体を起こし、各レビュアーに固定 HEAD・受け入れ条件の全文・区画の番号と総数・区画のファイル一覧・レビュアー向け指示ブロックを渡さなければならない（MUST）。

#### Scenario: 区画の指示が揃っている

- **WHEN** `stages/reviewer-brief.md` のレビュアー向け指示ブロックを読む
- **THEN** 区画を渡されたときの書き方として、`P<k>-` の接頭辞、`区画の対象外:`、区画のファイルの全ハンク、文字どおり `<rev>`、テスト・lint の再実行は区画 1 だけ、が書かれている

#### Scenario: 従来モードの Task サブエージェントも区画に分ける

- **WHEN** `stages/review-run.md` の従来モードの優先順の表で、Task サブエージェントの行を読む
- **THEN** 差分が 600 行を超えたら区画ごとに起こすことが書かれ、Codex CLI の行には区画に分けないことが書かれている

### Requirement: G は区画ごとの三表を和集合で照合する

`gate-runner.md` の「一周目の三表を機械照合する」は、区画に分けたレビューについて次を書かなければならない（MUST）: 一周目のレビュアーが区画ごとに起こされたとき（本体から受け取った要約に `区画 <k>/<n>` の見出しが付いているとき）に限り、`レビュー重量:` コメントの区画の数と受け取った三表の区画の数が一致することを先に確かめ、足りない区画を残差とする。区画 k の三表の変更点 ID と finding ID が `P<k>-` で始まることを確かめ、外れた ID をその区画の残差とする。全区画の `変更点の一覧` の和集合で各受け入れ条件が 1 回以上対応すること、全区画の `ハンク被覆` の和集合が固定した PR diff の全ハンクを含むことを集合比較する。各区画の `照合表` はそれぞれ `review-hit-set.py` に渡す。一周目のレビュアーが区画に分けずに起こされたとき（Codex のレビュアー、または区画が `なし`）は、`レビュー重量:` の区画の数と比べず、今までどおり 1 組の三表として照合する。

残差は、次の規則でどの区画の補足に回すかを決めなければならない（MUST）: 足りない区画はその区画、ハンク被覆の残差はそのハンクのファイルが属する区画、照合表の残差と ID の接頭辞の残差はその表・ID を出した区画、受け入れ条件の被覆の残差（全区画が `区画の対象外:` とした、またはどの区画も触れなかった受け入れ条件）は区画 1 とする。区画 1 が受け入れ条件の被覆の残差を補うときに読んでよい範囲は、その受け入れ条件の全文、`レビュー重量:` コメントの全区画のファイル一覧、それらのファイルの PR diff のハンクとし、補った変更点 ID は `P1-` で始める。対応する変更が PR diff のどこにも無ければ、それを `P1-` の finding として返す。

補足要求では、残差のある区画ごとに元の三表と残差を分けて載せ、補足済み回数は区画ごとではなく PR で 1 つだけ数えなければならない（MUST）。補足の `needs-reviewer` を返す前に投稿する `レビュー三表:` のコメントには、一周目の区画の構成（`一周目の区画: なし` または `一周目の区画: <n>`）を書かなければならない（MUST）。補足レビュー結果の受領では、その行の構成で同じ和集合の照合をやり直さなければならない（MUST）。補足を受け取るときに区画を計算し直したり、一周目と違う区画の構成で照合したりしてはならない（MUST NOT）。

この照合と残差の振り分けの守備範囲は次のとおりとする:

- 入力: 本体から受け取った区画ごとのレビュー要約（三表と指摘）、G 自身が手順 2-0 で投稿した `レビュー重量:` コメントの区画の一覧、固定 HEAD の PR diff、記録先の受け入れ条件、最新の `レビュー三表:` のコメント。レビュアーは協力的だが、区画の外の書き漏れ・接頭辞の付け忘れ・`区画の対象外:` の付け過ぎをする前提で扱う
- 拾いたい誤り: 区画のレビュアーが返らない・三表を欠く区画、どの区画も被覆しない受け入れ条件（全区画が `区画の対象外:` にしたものを含む）、どの区画も被覆しないハンク、区画ごとの照合表とリポジトリ全体の grep のずれ、接頭辞の無い ID や他の区画の番号の接頭辞（区画をまたいだ ID の取り違え）、補足で残差の区画が特定できずに補足先が決まらないこと
- 通ることを許す入力の例: 自分の区画のファイルに関わる受け入れ条件を `区画の対象外:` にしたが他の区画が被覆したもの（和集合で満たす）、ファイルの属さない区画のレビュアーがそのハンクも被覆したもの、存在しない受け入れ条件 ID を挙げた `区画の対象外:` の行（照合に使わない）、弱い根拠で受け入れ条件に対応させた変更点、`一致` / `食い違い` の判定の誤り
- 範囲外: 区画をまたぐ変更どうしの食い違い（照合表の grep に出るものを除く）、変更点の意味の正しさ、区画の構成そのものの妥当性。これらを塞ぐことは本要件の完了条件にしない

#### Scenario: 区画の三表が足りない

- **WHEN** `レビュー重量:` コメントの区画が 3 つで、G が受け取った三表が 2 区画分しかない
- **THEN** G は足りない区画を残差として扱い、`補足済み回数: 0` なら不足した区画だけの補足を求める

#### Scenario: 受け入れ条件は区画の和で被覆される

- **WHEN** 受け入れ条件 1 は区画 1 の `変更点の一覧` にだけ、受け入れ条件 2 は区画 2 の `変更点の一覧` にだけ対応している
- **THEN** G は和集合で両方の受け入れ条件が被覆されているとして、受け入れ条件の被覆を残差にしない

#### Scenario: 全区画が対象外とした受け入れ条件は区画 1 が補う

- **WHEN** 区画が 3 つで、3 区画すべてが受け入れ条件 X を `区画の対象外: X` とし、他に残差が無く、`補足済み回数: 0` である
- **THEN** G は X を区画 1 の残差として補足を求め、補足先は区画 1 だけで、区画 1 の補足は全区画のファイル一覧とそのハンクを読んで `P1-` の変更点 ID で X を被覆する（対応する変更が無ければ `P1-` の finding を返す）

#### Scenario: 接頭辞の無い ID は出した区画の残差になる

- **WHEN** 区画 2 の `変更点の一覧` に `P2-` で始まらない変更点 ID がある
- **THEN** G はその ID を区画 2 の残差とし、補足先は区画 2 になる

#### Scenario: 区画に分けなかった一周目は 1 組で照合する

- **WHEN** `レビュー重量:` コメントの区画が 3 つで、一周目のレビュアーが Codex で差分全体を 1 体で見て、接頭辞の無い 1 組の三表を返した
- **THEN** G は区画の数を比べず 1 組の三表として照合し、`レビュー三表:` のコメントに `一周目の区画: なし` と書く
