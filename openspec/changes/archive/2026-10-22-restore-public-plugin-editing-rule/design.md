## Context

change `move-private-parts-to-private-repo`（archive 済み）は `rules/plugin-editing.md` をまるごと個人版へ移した。主の指摘で、全員に要る部分は公開版に残すことになった。公開版の元のルールは 2226 バイトで、1 つのファイルに両方の部分が混ざっていた。

## Decisions

### 1. 分け方: 公開版は 5 点だけ、残りは個人版

公開版に残すのは、プラグインを入れた誰の環境でも当てはまる注意に限る（proposal の 5 点）。`CLAUDE_HARNESS_DEV_DIR`・`/wt-setup`・`sync.sh`・版を上げない・`changes/` の記録・Draft PR は、Harness を開発する人（このリポジトリの管理者）だけに要るので個人版に置く。

- 選ばなかった案 公開版に元のルールを全文戻す: 個人版の運用（環境変数・Draft PR）が公開版の全利用者に常時注入される。主の決定とも違う
- 選ばなかった案 節（`## `）で分けて 1 つのファイルを公開版と個人版にまたがらせる: 1 つのファイルは 1 つのリポジトリにしか置けず、分けるにはファイルを 2 本にするしかない

### 2. 個人版のファイル名は `harness-dev.md`

公開版 `plugin-editing.md` と個人版を同名にすると、`~/.claude/rules/plugin-editing.md` の symlink 先が 1 つしか選べず、全員に要る部分か開発者向けの部分のどちらかが読まれなくなる。名前を分ければ、公開版の symlink（`sync.sh` が張る）はそのまま、開発する PC だけが個人版の symlink を足せる。

- 選ばなかった案 同名のまま、開発する PC の symlink を個人版へ張り替える: 張り替えた PC では全員向けの 5 点が読まれなくなる（個人版の側に 5 点を重ねて書くことになり、2 か所の重複を直し続ける）
- 名前の理由: ファイルの中身が「Harness を開発するときの手順」であることがそのまま読める。個人版の他のファイル名（`weekly-report` など）と並べて迷わない

### 3. 記録の仕方

仕分けの表は `rules/plugin-editing.md` を「公開版」で載せる。「個人版に移した部品」の表の部品は公開版に無いものの一覧（検査が `git ls-files` 0 件を確かめる）なので、公開版に残るこのルールは表に入れず、表のあとの段落に「移した部分と移した先 `rules/harness-dev.md` と写し元の commit SHA」を書く。

### 4. 常時注入の予算

戻すルールの実測バイト数だけ常時注入が増える。`tests/injection-budget.bats` の推奨（実測 + 約 5%）に従い `tests/injection-budget.txt` を動かす。値は実装時に実測して決め、PR 本文に「何を戻し、なぜその値か」を書く。#1218 で 43506 から 40023 に下げた分の一部を戻す形になる。

### 5. 聖域の変更

`CLAUDE.md`・`AGENTS.md`・`tests/injection-budget.txt` は聖域。変更は「個人版が入っていれば」の文言を元に戻す（関連ルールの参照）ことと予算の値だけで、PR 本文に理由を書き、マージは主の承認で行う。

## Risks / Trade-offs

- 個人版の PR は別リポジトリで、公開版のマージと順序が前後しうる。公開版のマージ前に個人版の `harness-dev.md` が main に無くても、公開版の利用者への影響は無い（個人版が要るのは開発する PC だけ）。主は個人版の Draft PR をマージする
- 公開版のルールが短くなる分、元の「開発用 clone は fetch してから worktree を切る」等は開発者向けでしか読まれない。これは主の決定どおり
