# Design

## Context

`ci.yml` の `test` ジョブは `runs-on: ubuntu-latest` で、bats を `sudo apt-get install -y --no-install-recommends bats=1.10.0-1` で入れている。Ubuntu の apt にある bats の版は、noble（24.04）が 1.10.0-1、resolute（26.04）が 1.13.0-1（packages.ubuntu.com で 2026-11-17 に確認）。`ubuntu-latest` が 26.04 を指すようになったので、固定した版が見つからなくなった。

bats の版には、このリポジトリで分かっている挙動の差がある。Bats 1.11 以降はテスト名の符号化が変わり、macOS の bash 3.2 で多バイト文字を含むテスト名が `unknown test name` になる件があった（`plugins/dev-workflow/changes/1340.md`・`plugins/cost-ledger/changes/1346.md`。どちらも CI は 1.10.0 固定のまま、テスト名の側を直した）。CI は Linux の bash 5 なのでこの件そのものは起きないが、版を上げれば別の差が出うる。

## Goals / Non-Goals

**Goals:**
- bats のジョブが bats を入れる手順で落ちず、テストの結果で緑か赤になる
- bats の版の固定を保ち、さらに「固定した版が apt にあるランナー」もそろえて固定する

**Non-Goals:**
- bats の版を上げること（上げるなら、版の差を確かめる別の変更にする）
- `lint`・`test-result` のジョブのランナーの固定（bats を使わず、今回の障害と関係しない）
- ランナーのイメージが外されるのを前もって検知する仕組み

## Decisions

### bats のジョブの `runs-on` を `ubuntu-24.04` に固定し、`bats=1.10.0-1` を保つ

比べた案は次の 3 つ。

| 案 | 中身 | 採らない／採る理由 |
|---|---|---|
| (a) ランナーを 24.04 に固定（採用） | `test` ジョブの `runs-on: ubuntu-24.04`。版は 1.10.0-1 のまま | bats の版が変わらないので、テストの落ち方が今日までと同じ。変える行が少ない。ランナーの版と bats の版の組が固定され、`ubuntu-latest` の切り替えで再発しない |
| (b) 26.04 の版に上げる | `bats=1.13.0-1`（再発を防ぐなら `runs-on: ubuntu-26.04` も固定） | 障害の修理に bats の版上げが混ざる。版上げで落ちるテストが出たとき、この PR の中で原因の切り分けとテストの直しまで要る。版上げをするなら別の変更で行うほうが「自分の変更か bats か」を切り分けやすい |
| (c) apt を使わずに入れる | 上流の `bats-core` の `v1.10.0` を git から取って `install.sh` を回す、など | ランナーの版から独立するが、入れ方の手順が増え、タグは上流が付け替えうるので固定の強さはコミット SHA を書くまで apt の版固定より弱い。今回の障害を直すのに必要な範囲を超える |

(a) の弱点は、GitHub が ubuntu-24.04 のランナーを外す日（Ubuntu の LTS は通常、次の次の LTS が出るころに外される）にジョブが走らなくなること。そのときは「ランナーが見つからない」で落ちるので、黙って版が変わることは起きない。そのときに (b) か (c) を選び直す。

### 固定した版を 3 か所で書き、テストでそろっていることを確かめる

固定の情報は `runs-on: ubuntu-24.04`・`bats=1.10.0-1`・ステップ名 `install bats (1.10.0-1)` の 3 か所にある。テストは次を確かめる。

- 分けたジョブ（`shard:` の行を持つジョブ）の `runs-on:` が `ubuntu-<数字>.<数字>` の形の 1 行で、`ubuntu-latest` や式（`${{ }}`）でない
- そのジョブの `apt-get install` の行が `bats=<版>` の形で版を書いている（`bats` だけで入れていない）
- ステップ名 `install bats (<版>)` の版が `bats=<版>` と同じ

ランナーの版と bats の版の組が apt で実在するかはテストでは確かめない（ネットワークが要り、確かめられるのは CI の実行だけ）。CI の `install bats` の手順が通ることで確かめる。

## Risks / Trade-offs

- [ubuntu-24.04 のランナーが外される] → その日に bats のジョブが走らなくなる。`ci.yml` のコメントに、そのときは `runs-on` と `bats=` とステップ名を一緒に直すことを書いておく
- [lint のジョブは `ubuntu-latest` のままなので、shellcheck の版はイメージ更新で変わりうる] → 今回の範囲外。変わって落ちたら落ちて気づく
- [テストは決めた形しか読めない] → `runs-on` を式や複数行で書くと「読めない」として落とす（既存の `check_shard_matrix` と同じく、読めないまま通さない側に倒す）
