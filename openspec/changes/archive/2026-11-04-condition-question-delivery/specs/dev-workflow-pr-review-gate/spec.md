## MODIFIED Requirements

### Requirement: 条件を主に聞くときは条件だけを聞き、マージを止めない

段 B で G が決められないとき、主に聞く文は条件についての問いでなければならない（MUST。例:「既存データのある環境に配ることは、今回あるか。今回は無くても後であるか」）。指摘を issue にしてよいか・直すかを聞いてはならない（MUST NOT）。

G はこの質問で `needs-approval` を付けてはならず、保留で return してはならない（MUST NOT）。G は、1 行目が `条件の確認待ち` の PR コメントに、その指摘と質問文を残し、ほかの指摘の振り分けと手順 3 以降をそのまま進める（MUST）。return の仕分け欄には質問文を写す（MUST）。

照合と振り分けの G の return の仕分け欄に `条件の確認待ち` の質問文があれば、G を起こした側（develop では本体）は、その質問文と `条件の確認待ち` の PR コメントの URL を主への次の報告にそのまま載せる（無人運用（loop-dev-agent）では記録先にコメントする）。この義務を果たすことは必須である（MUST）。冒頭のこの文は一字も変えず、`stages/triage.md` の段 B の節と、本体が読む `skills/develop/references/roles/gate-runner.md` の「条件の答えを受け取ったとき」の段落の前にも書かなければならない（MUST）。本体が必ず読む `skills/develop/SKILL.md` の (4) の `次の段へ` の行にも、`gate-runner.md` を指す短い 1 文を書かなければならない（MUST）。自分でゲートを回すセッションは、G を起こした側を兼ねる。この義務は、G の Status・次の段・マージを変えてはならない（MUST NOT）。

主の答えは 1 行にして、エピックの本文（エピックに属さない PR では記録先の本文）の節 `## 条件の答え` に足さなければならない（MUST。節が無ければ作る）。この節には聞かれた分だけを足し、先に書き出しておかない（MUST）。足した行は、同じエピック（記録先）の以後のレビューの依頼文に入れる（MUST。入れるのはレビュアーを起こす側で、規定は `stages/reviewer-brief.md` に置く）。

答えを受け取ったセッション（develop では本体）は、本文に行を足し、`条件の確認待ち` のコメントに答えを返信し、確認待ちの指摘を段 B の表から当て直す（MUST。PR がマージ済みでも行う。段 A には戻さない。ラベル・周・宣言には触れない）。当て直しはサブエージェントに任せてよい。この義務は `stages/triage.md` の段 B の節に加えて、本体が読む `skills/develop/references/roles/gate-runner.md` の「段ごとの起動と入力」の末尾にも書かなければならない（MUST。`stages/triage.md` は G だけが読み、本体は読まないため）。答えが出るまで、その指摘は `条件の確認待ち` のまま残す（MUST）。

#### Scenario: G が条件を決められない

- **WHEN** 止めない指摘の条件が「既存データのある環境で壊れる」で、エピックと記録先の本文・受け入れ条件・コード・`## 条件の答え` のどこにも、既存データのある環境に配るかが書かれていない
- **THEN** G は `条件の確認待ち` の PR コメントにその指摘と条件についての質問を残し、`needs-approval` を付けず、止める指摘が無ければ手順 3 以降へ進む

#### Scenario: 主が答えた

- **WHEN** 主が「MVP では配らない。MVP 後に配る」と答える
- **THEN** エピックの本文の `## 条件の答え` に 1 行が足され、確認待ちの指摘は段 B の表の「後で成り立つ」として段 D・段 E に当てられる

#### Scenario: 次のレビューの依頼

- **WHEN** 同じエピックの次の PR でレビュアーを起こす
- **THEN** 依頼文に、エピックの本文の `## 条件の答え` の行が入っている

#### Scenario: 質問文を主に届ける

- **WHEN** 照合と振り分けの G が止める指摘が無く、`条件の確認待ち` の PR コメントを残し、return の仕分け欄に質問文がある
- **THEN** G を起こした側は、その質問文と PR コメントの URL を主への次の報告に載せる。無人運用（loop-dev-agent）では記録先にコメントする。G の Status は `次の段へ` のまま、マージは止まらない
