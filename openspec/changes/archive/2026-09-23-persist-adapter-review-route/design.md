## Context

develop の G は、起動・再開指示の `レビュー経路:` 行から adapter 経路と従来経路を判別する。develop 本体はすべての G 指示に `レビュー経路: adapter` を書く責任を持つが、現在の `gate-runner.md` は行の無い指示を一律に従来経路と読めるため、同一 G の再開時に本体が一度行を書き落とすだけでレビュー実行者が切り替わり得る。

G の再開には二つの形がある。Claude の同一 G を SendMessage で再開する場合は初回の指示を同じコンテキストに保持する。一方、コンテキスト上限による手渡しや Codex の fresh phase で起こす後任 G は別の G であり、前任の初回指示を前提にできない。

## Goals / Non-Goals

**Goals:**

- adapter 経路で起動済みの同一 G が、行の無い再開指示だけを理由に従来経路へ切り替わらないようにする
- 行の無い新規 G 起動を従来経路にする後方互換の既定を保つ
- gate-runner、develop 本体、Codex adapter reference、OpenSpec の説明を同じ初回起動／再開の境界に揃える

**Non-Goals:**

- develop 本体が G の各起動・再開・手渡し指示へ常に `レビュー経路: adapter` を書く責任を緩めること
- 明示された `レビュー経路: adapter` / `レビュー経路: 従来` の意味や、各経路でのレビュー実行者を変えること
- 経路を環境変数、GitHub コメント、永続状態から復元する仕組みを追加すること

## Decisions

### 経路を同一 G のコンテキスト内で sticky にする

`レビュー経路: adapter` で起動された G は、後続の再開指示に `レビュー経路:` 行が無い場合、初回に選んだ adapter 経路を保持する。行の欠落を「従来経路を選び直す入力」とは扱わない。

- 採用理由: 同一 G は初回起動の指示を既に持っており、再開メッセージの省略だけでレビュー委譲の境界を変える合理性がない。書き忘れ 1 回で G が Codex を直接呼ぶ故障も防げる
- 代替案: develop 本体の「常に書く」責任だけに依存する。既にその責任は定義済みだが、欠落時に安全でないことが issue #391 の対象なので採用しない
- 代替案: GitHub コメントや環境変数から経路を復元する。既存の「それらから推測しない」契約を崩し、複数の状態源を作るため採用しない

### 行の無い従来経路は新しい G の起動時だけに適用する

`レビュー経路:` 行の無い指示を従来経路とする規則は、新しい G の起動指示にだけ適用する。手渡しで起こされた後任 G も新しい G なので、この起動指示に行が無ければ従来経路となる。したがって本体の「起動・再開・手渡しのすべてに常に書く」責任は維持する。

- 採用理由: 古い本体や develop 外の呼び出し元に対する後方互換を保ちながら、同一 G の再開だけを安全にできる
- 代替案: 行の無い新規起動も adapter 経路にする。従来経路の互換契約を破るため採用しない

### 文書契約を既存の bats で固定する

既存の `develop-adapter-review-routing.bats` に、gate-runner の sticky 規則と、対になる develop 本体・Codex adapter reference の記述を照合するテストを追加する。実行時の永続状態は追加せず、G が読む指示書の契約をテストする。

## Risks / Trade-offs

- [同一 G と後任 G の境界が文言だけでは曖昧になる] → `SendMessage` で再開される同一 G と、手渡し／fresh phase で起動される後任 G を例示し、テストで「手渡しで起こされた後任の起動指示」を固定する
- [sticky 規則が本体の行記載責任を不要に見せる] → `SKILL.md` と仕様の「常に書く」MUST は残し、sticky は欠落時の安全策であって正常系の省略許可ではないと明記する
- [関連文書の一部だけ更新される] → 既存の adapter review routing bats で gate-runner、develop SKILL、codex-develop reference の三面を同時に照合する
