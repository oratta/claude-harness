# Design

## Context

背景と範囲は proposal.md を参照。子側は #1670 で、入力を受けると新世代の `turn_input` と `turn_state: null` を同時保存し、Stop が終了状態を保存する。型・値・世代・セッション一致の読み取り契約は `dev-workflow-epic-state` に既にある。

現行の親は `detect_stopped` が会話ログと印から停止を推測する。`resume_moved` と `deliver_reply` にもログによる再開判定があり、長い待ちの `rejudge_changed` は検知を通さず判断役を再度呼ぶ。通常検知だけの変更では主の新入力の後に古い判断を送る経路が残る。

## Goals / Non-Goals

**Goals:** 一つの状態判定を通常の検知・再判断・自動送信の直前で共有し、主と対話中の子を自動操作しない。既存の排他更新と子側フックの原子的な無効化を利用する。

**Non-Goals:** 子側フック・状態値・権限検証の変更、owner の返事待ちの時間通知、手順書 2 ファイルの変更、手動の reply / 起動操作の新たな制限。状態の完了から status=done を自動生成することも含めない。

## Decisions

### 1. 状態記録を停止の正本にする（#1744 本文の決定）

`epic-dispatch.sh` 内に読み取り判定をまとめ、#1670 の型・値の検査を再利用できる形で同等に満たす。`parent` / `startup` と `主の返事待ち` の有効な組だけを対象にする。会話ログ・stop の印・依存待ちのマーカーによる代替検知は設けない。ログを使う方式を残す案は、主の作業報告の誤検知と古い状態の再利用を残すため採らない。

会話ログから受領の重複と再開を推測する部分も、入力の世代・セッションの照合へ置き換える。受領済みの組は親側の補助情報に保持し、既存の stop / stop_at と一緒に排他更新する。子が所有する turn_input / turn_state は親が書き換えない。同一世代の再受領をログの uuid や mark の付け直しだけで許可しない。長い待ちの材料更新による既存の再判断は別に維持する。

### 2. 検知と送信で同じ対象条件を確かめる（#1744 の非介入条件の適用）

検知の排他更新、resolve の入口、長い待ちの再判断、自動返事を launcher に渡す前に、対象の世代・セッションと状態を再確認する。判断待ちに主が入力していれば、その通す判断を破棄する。`decide_relaunch` を呼ぶのは、対象条件を満たす有効な「通す」だけにする。「主に上げる」「問いではない」、判断の失敗・不正・返事の欠落では送信・端末終了・再起動へ進まない。

自動送信の確認は wait の経路に適用し、明示的に呼ぶ reply や依存解消後の起動操作の契約まで広げない。キャッシュ維持の声かけも wait からの自動送信なので、owner や無効な終了状態には送らない。

### 3. 対象確定後の判断材料と再起動計測には既存のログ取得を残す

停止の可否・送り手・再開はログから決めない。一方、対象と確定した後に判断役へ渡す本文・uuid・質問、依存待ちの末尾マーカーの判定、通す判断後の既存の会話量・経過時間の計測には既存のログ読み取りを利用する。ログを読めなくても状態記録による停止の判定は成立し、既存の判断役の 2 引数の呼び出しを利用できる。stop_uuid は発言を取得できた場合の記録・照合用に残す。

これは #1744 の「今までどおり」の処理を維持しながら「状態の記録だけを読む」を停止判定の根拠に適用する具体化であり、記録先に明記されていない仕様上の補完として **1 件**に数える。ログ取得を全廃する案は判断の本文と既存の再起動条件まで変えるため採らない。

依存待ちマーカーの既存の構文と、対象の停止を自動判断せず親へ返す処理は維持する。ただし状態記録の無い旧形式や作業報告を停止対象に格上げする特例は残さない。これは #1744 の対象判定を適用した結果である。

## Risks / Trade-offs

- 古い子の停止を自動検知しなくなる → #1744 の明示された互換変更として扱い、記録なし・印ありの両方を回帰テストにする。
- 再判断や声かけが通常検知を迂回する → 対象判定を共有し、古い stopped-seen / told_uuid を持つ owner のターンも試す。
- 排他更新前や判断中に主の入力が入る → 読み取った組を更新時と自動送信の直前に再確認し、変化した古い判断は送らない。入力受理と外部端末操作全体を一つのトランザクションにする変更は含めない。
- 旧テストがログだけで停止を作る → 対象の振る舞いを試す fixture には有効な組を明示し、記録なしを対象にしないテストは独立して残す。ログ読取部品の単体契約は維持する。
- 手順書と実装の更新時期が分かれる → #1760 がこの change の後で手順書を整合させる。

## Migration Plan

R1 の承認後、指定されたスクリプト 1 ファイルとテスト 3 ファイルを同じ実装サイクルで変更し、対象 suite と strict validation を通す。新しい外部依存や子側フックの移行作業はない。戻す場合は実装とテストを一緒に revert し、会話ログから停止を推測する旧挙動に戻る点を記録する。
