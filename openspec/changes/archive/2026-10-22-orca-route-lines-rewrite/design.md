## Context

#1168 の仕様化判断で、Orca 経路の行は #1123 の change 3b と同じ箇所なので #1177 に切り出した。3b は PR #1178 でマージ済みで、develop `SKILL.md` の「エピックの扱い」は、起動部品が Orca か tmux かの 2 つになり、手順 1〜8 は部品によらず共通、部品で違う点は「部品ごとの欄」の表、という形に書き直されている。一覧の行番号は 3b の本文に合わせて直してあるが、3b の後の内容では、すでに「Orca と tmux を並べた書き方」になった行と、Orca だけを前提にした行が混ざっている。

## Decisions

### D1. 行ごとの選び方（直す／基準で外す）

一覧の 25 件は、それぞれ現在の本文を読んで次のどちらかにする。

- **基準で外す**: その行が Orca を、tmux など他の起動部品と並べた 1 つとして書いている（「Orca・tmux」「Orca か tmux」「Orca の部品の列」「`orca` と `tmux` の判定」）。読み手の環境に Orca が無くても、Orca の部品は使わない選択肢として読める。新しい基準「差し替え可能な起動部品の 1 つとして Orca を並べた行」に当たる
- **直す**: その行が Orca だけを前提にしている（「Orca 経路」と名乗る・Orca に登録済みのリポジトリを探す・Orca の親が子のターミナルに打ち込む・オーナーの起動コマンド `cld` を前提にする）。「Orca を使う場合」と条件をつけ、Orca が無い環境（tmux の部品・サブエージェント方式）の読み方が分かる書き方にする。`cld` は `EPIC_DISPATCH_CLAUDE_CMD`（未設定なら `epic-dispatch.sh` の既定）で差し替える起動コマンドと書き、`cld` の名は既定値として一度添えるに留める

迷ったら「直す」側にする。判定は `tasks.md` の判定の表に仮の判定を置き、実装の担い手が本文を読んで確かめ、実施欄に最終の判定を残す。

### D2. 「部品ごとの欄」の表（PR #1178 のオーナーの指摘）は一覧に足さず、基準で外す

選んだ案: 載せない行の基準に「差し替え可能な起動部品の 1 つとして Orca を並べた行」を足し、表の見出し（493 行）と Orca の部品の列の行（495〜502 行）をこれに当てる。いま一覧に載っている 493 行の見出しも、同じ理由で一覧から外す。

選ばなかった案:

- **495〜502 行と 493 行を一覧に足して直す**: この表は Orca・tmux・サブエージェント方式を比べるためのもので、Orca の列の中身は「Orca を使う場合」の書き方そのものである。直す先が自分自身なので、直し終えても行が残り、受け入れ条件「担い手が #1177 の行が 0 件」を満たせない。Orca の列を消すと tmux との比較が成り立たない
- **Orca の語の全件検索を足し、許可リストに基準で外した行を 1 件ずつ載せる**（`moko` などの検索と同じ形）: 受け入れ条件の外で、許可リストが 20 件を超える。基準の判定は人のレビューが見る（既存の「候補語で取りこぼしを確かめられる」と同じ守備範囲）

### D3. 検査

- 一覧の全体で「直す issue」が「担い手なし」の行が 0 件であることを確かめる（受け入れ条件 2）。既存のテスト「no dev-workflow row in the listing is left without an owner」は dev-workflow の行だけを見ていたので、一覧の全体に広げる
- `DEVWF_ORCA_ROWS`・`check_orca_owner` と、それを使う 4 つのテスト（「#1177 に付いている」「付け替えると落ちる」「行を落とすと落ちる」「全部落とすと落ちる」）は外す。行を直して一覧から消した時点で、検査する相手がない。`epic-launch-orca.sh` が保留の部品なので一覧の行が落ちるテスト（`epic-launch-orca.sh is a pending part…`）は、担い手の欄を `#1177` から別の値に変えて残す
- 一覧が空になりうる。`tests/public-private-split.bats` の埋め込み Python に「固有記述の一覧に行が無い」で落とす検査（`if not listing`）があるので、行が 0 件でも通すようにし、見出しの行（`LIST_HEADER`）が文書にあることだけを確かめる。他の一覧のテストは、テスト内で一時の文書に行を足して使う（既存の `edit_doc` のやり方）

## Risks / Trade-offs

- 基準で外した行は、`epic-launch-orca.sh` が公開版に残る前提に立つ。#1129 が個人版に決めると、外した行が個人版の部品を名指す行になる。外した行の場所を docs の節に残し、#1129 が戻す手順を基準の項目に書いて手がかりにする（レビュー R1 の指摘）

- 基準の判定は人の判断で、検査は拾わない。D2 で述べた守備範囲のとおり、Orca だけを前提にした行が基準で外されたままになる誤りは、仕様レビューと pr-review-gate が見る
- 一覧を全部消すと、将来 Orca の語が公開版に戻っても検査は落ちない。許可リストの検索を足さないのは D2 のとおり受け入れ条件の外で、必要になれば別の issue で足す
- `SKILL.md` の同じ節を別の PR が触っていれば衝突する。マージ前に `git fetch` して重なりを確かめる
