## Context

flatmate の `scripts/ship-check.sh` は、出荷ファイルの集合を manifest から作ったあと、①本文とパスの禁止語照合（`ship/forbidden.txt`）②allow（`ship/allow.txt`、`<path>:<語>:#<issue>`）の書式・未使用・issue の OPEN の検査、を同じ関数の中で行う。①②は集合の作り方に依存せず、ファイルの一覧だけで動く。Harness 側では #1168 が、公開版の部品に固有名が戻らないことを `tests/public-private-split.bats` の中の正規表現と許可リスト（`ファイル|行に含まれる固定の文字列|基準` の 3 つ組、期限なし）で守っている。2 つの検査は目的が同じで、辞書と判定が別々にある。この change は①②を共有スクリプトにする。#1168 の検索を共有スクリプトに移すのは後続の change `public-names-ci-check` で、その入力形式をこの change が先に決める。

## Decisions

### 1. 置き場: 既存の dev-workflow の `scripts/` に置く

新しい plugin は作らない。新 plugin は `marketplace.json`・常時注入の予算（`tests/injection-budget.bats`）・仕分けの表（`docs/public-private-split.md`）の行を増やす。dev-workflow は表で公開版で、`plugins/dev-workflow/` の行が新しいファイルを覆う。flatmate の CI と手元は、スクリプトをパスで直接呼ぶだけなので plugin として install される必要がない（`CLAUDE_PLUGIN_ROOT` にも依存しない）。

### 2. 呼び出しの形: ファイル一覧は標準入力、辞書と allow と root は引数

出荷集合・公開版の部品の集合の決め方はリポジトリごとに違う（flatmate は manifest か除外方式、Harness は仕分けの表と #1168 の範囲）。決め方を共有スクリプトに入れず、呼び出し側が 1 行 1 パス（root からの相対）で渡す。`--dict` と `--allow` は複数回指定できる（公開側の辞書に個人版の辞書を足せるようにする。個人版の辞書の語は公開リポジトリに書かない）。違反の件数は呼び出し側が自分の違反と合算して「違反 N 件」を出せるよう、`--count-file` で渡す。

### 3. allow の 2 種類の書式（期限付きと恒久）をどう両立させるか

決めたこと: 1 本の allow ファイルに 2 種類の行を置ける。第 3 欄（2 つ目の `:` より後ろ全部）で種類を決める。

| 種類 | 書式 | 許す範囲 | 有効期間 | 使う側 |
|---|---|---|---|---|
| 期限付き | `<path>:<語>:#<issue番号>` | そのファイルの中のその語の当たりすべて（パス名の当たりを含む） | issue が OPEN の間だけ。CLOSED なら違反 | flatmate の既存の行（そのまま動く） |
| 恒久 | `<path>:<語>:=<行に含まれる固定の文字列>` | そのファイルで、その語に当たった行のうち、行の本文がその固定の文字列を含む行だけ（パス名の当たりは許さない） | 期限なし | #1168 の許可リストの行（後続の change が移す） |

- 第 3 欄が `#` と数字だけなら期限付き、`=` で始まり 2 文字以上なら恒久、それ以外は書式違反。パスと語は `:` を含められない（flatmate と同じ）。恒久の固定の文字列は `:` や `#` を含んでよい（`flatmate#320: find -path` のような行を書けるように、第 3 欄は 2 つ目の `:` から行末まで全部とする）
- flatmate の既存の書式 `^[^:]+:[^:]+:#[0-9]+$` の行は、これまでと同じ意味で通る。それ以外で恒久の書式でもない行は、これまでと同じ文面の書式違反になる。したがって flatmate の `ship/allow.txt` と `scripts/test-ship-check.sh` は変更なしで同じ結果になる
- 未使用の検査は両方の種類に効く。恒久の行が 1 件の当たりも打ち消さなければ「何も打ち消していない」違反になる（#1168 の「許可リストの鮮度」の検査を包む）
- 基準（#1168 の「出典」「互換」）の置き場: 恒久の行の直前の `#` で始まるコメント行に書く。スクリプトは基準を検査しない。基準が許可の根拠として足りるかは人のレビューが見る（#1168 の守備範囲と同じ）。後続の change が #1168 の tasks の判定の表と許可リストの行を 1 対 1 に保つ
- 語の欄: #1168 の許可リストには語の欄がない。移すとき、後続の change が各行に「その行に当たる辞書の語」を足す。辞書の語は大文字小文字を区別せずに照合するので、許可の語の欄も小文字化して比較する（flatmate と同じ）

選ばなかった案:
- **恒久の許可を期限付きの形（`#issue`）に寄せる**: 出典・互換の行は issue の完了で意味を失わないので、issue を閉じるたびに違反になる。出典の行ごとに issue を持たせるのは過剰
- **ファイル単位の恒久の許可（`<path>:<語>:perm`）にする**: そのファイルに同じ語を書き足しても通ってしまい、#1168 の要件「同じファイルの別の行に書き足すと許可リストに無いので落ちる」の精度を落とす
- **#1168 の許可リストを共有スクリプトに移さず bats に残す**: 判定が bats とスクリプトの 2 本に分かれ、今回消したい重複が残る
- **行番号で許可を指す**: 行番号は編集でずれる

### 4. 辞書と照合の規則（flatmate の現行を引き継ぐ）

辞書は 1 行 1 語、空行と `#` で始まる行は無視、語は固定文字列、大文字小文字を区別しない部分一致で、ファイルの本文（バイナリは見ない）とパス名の両方に当てる。#1168 の検索は正規表現・大文字小文字を区別する検索だが、後続の change が語を固定文字列に直す（`moko` など。大文字小文字を区別しなくなることによる新しい当たりは、後続の change が範囲ごとに確かめる）。

### 5. 違反の文面と順序は flatmate の現行のまま

flatmate が呼び出し側を置き換えたあとの「同じ入力で同じ違反一覧」を満たすため、文面と出す順序（辞書の読み込みの違反 → allow の書式 → ファイルごとの当たり → 未使用の allow → issue の状態）を変えない。flatmate の ship-check は集合の展開の違反を先に出してから共有スクリプトを呼ぶので、全体の順序も同じになる。「出荷集合に無い」など flatmate 向けの語を含む文面もそのまま共有する（文面を呼び出し側で変えられるようにはしない。変えると同じ一覧の保証が崩れる）。`gh` が引けないときの通知だけは先頭の名前を `--name`（既定 `forbidden-words-check`）で差し替えられる（flatmate は `ship-check`）。

### 6. flatmate の呼び出しの契約（genetta-inc/flatmate#1732）

- 取得: スクリプトは bash（3.2 で動く）・grep・sed・tr・sort と任意で gh だけに依存し、リポジトリの clone か checkout のパスから直接呼べる。flatmate の CI は固定した commit の `oratta/claude-harness`（public）の checkout のパス、手元は環境変数で名指した clone のパスを使う。取得の仕組み（環境変数の名前・commit の固定の仕方）は #1732 が決めて flatmate の文書に書く。この change は「パスで直接呼べること」だけを約束する
- 呼び出し: `printf '%s\n' <出荷ファイルの一覧> | bash <スクリプト> --root <root> --dict ship/forbidden.txt --allow ship/allow.txt --name ship-check --count-file <一時ファイル>`
- 環境変数 `FORBIDDEN_WORDS_NO_GH` が空でなければ `gh` を呼ばない（flatmate は `SHIP_CHECK_NO_GH` をこれに写す）。`gh` はスクリプトを呼んだ側の PATH から探す（flatmate のテストのスタブがそのまま効く）。`gh` は検査 root を cwd にして呼ぶ

## Risks / Trade-offs

- 恒久の許可の書式は flatmate の書式の拡張で、flatmate 側の文書と整合を取る必要がある。flatmate はこの種類を使わない。第 3 欄の種類の判定を flatmate の既存の書式で変えないので、flatmate への影響は無い
- 違反の文面に flatmate 向けの語（出荷集合）が残る。Harness の違反一覧に出る文面が Harness の言葉と合わないのは受け入れる。起きるのは allow が未使用のときだけ
- スクリプトを flatmate が固定 commit で取得する方式なので、共有スクリプトの文面を変えたときは flatmate が固定を進めるまで反映されない。これは意図した動き（flatmate の出荷検査が Harness の更新で突然変わらない）
