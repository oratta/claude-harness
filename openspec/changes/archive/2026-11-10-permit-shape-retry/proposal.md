# Proposal

## Why

子（サブエージェント）が一時領域の後始末を準備のコマンドとまとめて打つと（`R=<一時領域>; git init ... && git checkout -- a.txt` のように変数や `&&` でつなぐと）、許可を書くスクリプトは行き先を確定できないとして断る。これは安全側で正しいが、develop の手順ではこのとき親がすぐオーナーに上げるので、実パスの単独のコマンドに打ち直せば親が許可を書ける操作でもオーナーの手が止まる（エピック #1137 の完了条件の実機確認の 3 回目の試行で実際に起きた: https://github.com/oratta/claude-harness/issues/1137#issuecomment-6301780070 ）。今は親が、スクリプトの断った理由が「コマンドの形」なのか「行き先が一時領域の外」なのかを機械的に見分けられない。

## What Changes

- 許可を書くスクリプト（`plugins/dev-workflow/scripts/git-guard-permit.sh`）は、一時領域の判定に落ちたとき、記録のコマンドが単独のコマンドの形（その種類の判定が許す文字だけでできていて、`;`・`&`・改行の区切りが無い）でなければ、終了コード 3 で終わる（今は 1）。stderr には今の理由の行に加えて、実パスの単独のコマンドに打ち直せば判定し直せる旨の 1 行を書く。単独のコマンドの形なのに落ちたもの・記録の置き場所や中身の確かめに落ちたものは、今までどおり 1 で終わる。許可を書くかどうかの判定（一時領域の判定）は変えない
- develop の本体は、許可を書くスクリプトが 3 で終わり、許可を書く 4 つの条件のうち場所の判定以外（報告の項目とコマンドの一致・子が自分で作った・戻す/片付けるのが目的、および報告の対象のパスがこのセッションの scratchpad の下の形）を満たすときは、オーナーに上げずに同じ子を再開し、準備は別の呼び出しで先に済ませたうえで、破壊的な操作だけを実パスの単独のコマンドとして 1 回だけ打ち直し、拒否されたら打ち直さず報告に戻るよう指示する。打ち直しで新しくできた拒否の記録で、許可の手順をやり直す。打ち直しの指示は同じ子の同じ操作（戻す・片付ける対象と目的が同じもの）について 1 回までで（打ち直しで新しい拒否の記録ができても回数は戻さない）、打ち直したあとにスクリプトがまた 0 以外で終わったら（3 でも）、今までどおりオーナーに上げる
- 打ち直しで子が hook に打ち切られて空の return で返ったときは、報告を 1 回だけ求め直してよい（打ち直しの指示は同じ指示での起こし直しに数えない）

## Capabilities

### New Capabilities

（なし）

### Modified Capabilities

- `destructive-git-hook`: 要件「許可を書くスクリプトは一時領域の中に収まるコマンドだけを許可する」の終了コードに、形の理由で断ったときの 3 を足す
- `dev-workflow-develop`: 要件「破壊的 git 操作の拒否の報告を受けたら、条件を満たすときだけ許可を書いて再開し、それ以外はオーナーに上げる」に、スクリプトが 3 で終わったときの打ち直しの指示と、その回数の上限を足す。要件「空の return を受けたら報告を 1 回だけ求め、同じ指示で起こし直さない」に、打ち直しを主に上げない例外・打ち直しの再開を起こし直しに数えないこと・打ち直しのあとの空の return には報告を改めて 1 回だけ求めてよいことを足す

## Impact

- `plugins/dev-workflow/scripts/git-guard-permit.sh`（判定に落ちたときの終了コードの振り分けと stderr の 1 行）
- `plugins/dev-workflow/skills/develop/SKILL.md`「1 ループ」の節の、`returned no output` を含む段落と、その直後に足す打ち直しの段落
- `plugins/dev-workflow/tests/git-destructive-guard.bats`（終了コード 3 と 1 の振り分け）、`plugins/dev-workflow/tests/develop-skill.bats`（段落の文言）
- 触らないもの: 判定の共通ファイル `git-guard-scratchpad.py`（#1159 が `check_rm` と `cd` の規則を直す）、hook の `git-destructive-guard.sh`（#1166・#1463 が触る）、`rm-permission-guard.sh`
- 終了コード 3 を返すようになっても、0 以外で失敗を見ている既存の呼び出し（SKILL.md と既存の bats）は失敗のまま読むので壊れない
