# Design

## Context

動機と範囲は proposal.md を参照する。観測項目の正本は `plugins/dev-workflow/changes/1385.md:23-31`、設定適用と機械確認の限界は `references/reply-after-idle.md:9-29` にある。初回実機確認の `/config` と、disk/起動引数の確認は同じ証拠ではない。`subagent-context.sh --file` は最後の有効な assistant usage の入力・cache creation・cache read の和を返し、exit 0 と 2 は計測成功、1 は計測不能である。

## Goals / Non-Goals

**Goals:** 観測に必要な事実、実行者による確認、機械計測値を区別して保存し、同じ入力から同じ観測結果を得る。親・子の待機試行、単発の設定確認、通常 compact/hook の別区間をそれぞれ追跡できる。

**Non-Goals:** Claude の起動、API リクエスト、待機の維持、スリープ制御、設定適用、hook の追加、主の承認の代行は行わない。スクリプトの成功や fixture テストから実機合格を推定しない。

## Decisions

### 手順書と受動的な収集 CLI に分け、既存部品を再利用する

自動起動・設定変更・監視まで統合する案は、主が決める起動本数と消費上限に踏み込むため採用しない。一つの観測契約を手順書で定め、収集 CLI は既存ログと実行者のメタデータだけを受け取る。以下はその契約の具体化であり、独立した機能を追加しない。

#### 実行手順と承認欄

新規 reference に、実行時に主が埋める欄（承認者・承認の記録、親/子/単発それぞれの上限本数、消費上限と単位、対象 worktree と設定適用範囲、停止条件）を置く。推奨は初回に親・子・単発を各 1 本、逐次実行、追加試行は 0 本として追加承認を得る形とする。消費上限の金額・token 数は主が実行時に記入し、空欄のまま起動しない。待機中の追加 API リクエストは 0 とする。これらの推奨値は承認ではない。

版・plugin commit、各セッションの実効 idleCompaction 値と `/config` 等の確認方法を記録する。子の起動引数は idleCompaction の指定だけを確認し、`ps` の全出力や settings 全体を保存しない。親は develop 前後の on/off と、live 反映か再起動かを記録する。通常の設定適用・戻し方は reply-after-idle.md を参照し、手順を複写しない。

親・子の idle 待機は、実際の idle 閾値とその出典（利用版の既定値なら版と確認元）を確認してから行う。閾値 120000 や子再起動の 150000 を流用しない。観測開始時点の対象 JSONL・完結した行数・時刻、最後の API リクエスト時刻とその確認元を外部のメタデータに記録し、終了時刻・終了行数を追記する。最後のリクエストの時刻が不明なら assistant の応答時刻や mtime で代用せず未検証にする。60 分以上の待機は収集対象セッションへ声かけせず、実行者が外側で測る。スリープと追加リクエストの有無は実行者が yes/no/unknown で記録する。

通常の自動 compact と hook は idle 待機に重ならない別の行区間で記録する。通常の上限付近での自動 compact か、手動 compact かを実行者が確認し、hook の案内とその後の SKILL 本体の Read による再読み込みを分けて記録する。hook が存在するだけでは作動の証拠としない。承認範囲内でこの区間を観測できなければ未実施とする。

#### 収集 CLI とデータ

`python3 <plugin>/scripts/idle-compaction-observation.py --transcript <jsonl> --metadata <json>` の単一 CLI とする。1 回の入力は一つのセッションの一つの区間とし、metadata に role（parent/child/standalone）、kind（idle/config/normal-compact）、版・commit、設定確認結果・方法、上記の時刻・行位置・閾値の値と出典、スリープ・追加リクエスト・compact 種別、hook 案内/再読み込みの確認状態を持たせる。存在しない観測は unknown/未実施として明示し、真偽に補完しない。手順書には秘密値を含まない入力例と全項目の意味を置く。

行位置は「開始時に完結していた行数 S、終了時に完結していた行数 E」とし、収集区間は S < 行番号 <= E。会話量は開始位置までの prefix を外部の一時領域に切り出して `subagent-context.sh --file` で測り、その結果から `context_tokens` だけを取り込む。終了時の会話量で開始時の不足を埋めない。計測部品の JSON や stderr をそのまま転送しない。

イベント件数は区間内の JSON object が `type=system` かつ `subtype=compact_boundary` のものだけを数える。文字列検索は使わない。読めない入力、区間の切り詰め、不正 JSON/未完の行などで区間が確定できないときは理由を残して未検証にする。未知の正常な type は無視してよい。ログの回転に追従する探索機能は持たせず、対象ファイルと位置は実行者が指定する。

出力 JSON には入力済みの必要な観測項目、開始時の会話量、経過秒、区間内の boundary 件数、区間の結果と理由コードを収める。idle の結果は、実効 off・閾値以上・最後のリクエストから 3600 秒以上・正しい開始/終了位置と時刻・スリープなし・追加リクエストなし・通常/手動 compact の混在なしが揃った場合だけ `observed`（0 件）または `unexpected-boundary`（1 件以上）とする。それ以外は `unverified`。normal-compact は別区間の自動 compact と hook 案内/Read の確認を記録し、idle の結果と合算しない。config は役割別の実効値確認だけを記録し、単発に 60 分待機を要求しない。

exit 0 は収集結果を保存できたことだけを表す。`unverified` や `unexpected-boundary` でも結果を保存し、呼び出し側は結果欄を読む。入力を解釈できない・保存できないなど収集自体の失敗は exit 1 とし、合格の代用にしない。

#### 保存先と出力の制限

入力メタデータ、prefix、一時データ、収集結果を repo 配下に置かない。保存先は `LLM_LOG_DIR` のみとし、未設定/空なら一切作成せず「主に保存先を確認し LLM_LOG_DIR を設定して再実行」と案内して exit 1 にする。実行 cwd の repo と、この plugin が置かれた repo への保存を、実パスに解決して拒否する（symlink による repo 内への保存も含む）。保存結果は同ディレクトリの新規ファイルに書き、元ログは変更しない。

入力値を丸ごと転記せず、定義済みの観測項目だけを型・列挙値等を確認して保存する。会話本文、tool 入出力、環境変数一覧、settings 全体、起動引数全体、入力の未知キー、エラー時の入力断片を stdout/stderr/結果ファイルに出さない。実行者の確認元は方法の列挙値・版・記録位置などの限定した項目で持ち、自由文のログ貼り付け欄を作らない。stdout は保存完了と結果区分、エラーは固定の原因だけを示す。

## Risks / Trade-offs

- 非公開 JSONL の形や実際の閾値が版ごとに変わる → 版と出典を必須の観測項目とし、不明・読めない場合は未検証にする。将来の全形式への対応は完了条件にしない。
- スリープ・追加リクエストなしを JSONL だけで証明できない → 機械計測と実行者の申告を分け、unknown を合格にしない。OS ログの自動収集は追加しない。
- 親が 60 分後に再起動する通常運用と実験が干渉する → 専用セッションを外側から受動的に観測し、収集のために対象へ返信しない。通常運用の規則は変更しない。
- fixture の成功が実機完了と混同される → 変更記録に #1385 の実機確認を完了扱いにしないことと、実機結果は主が別途記録することを明記する。

## Migration Plan

手順書・CLI・Bats・変更記録だけを追加する。既存入口への自動接続や設定移行は行わない。実装後は fixture で契約を確認し、主が承認欄と LLM_LOG_DIR を指定して初めて実機手順を実行する。取り消しは追加した 4 ファイルを戻すだけで、実設定の自動復元は不要である。
