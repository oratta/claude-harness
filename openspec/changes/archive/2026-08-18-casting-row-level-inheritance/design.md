## Context

#112/#113 の初期実装（コピー方式）に対する、主と確定済みの仕様変更（#114）。設計の再検討はせず、確定事項の実装に効く判断だけを記録する。

## Decisions

### 伝搬コピーではなく行単位参照

主の当初案は「カタログ書き込みスクリプトが全子へコピーを伝搬する」だったが、行単位の継承（未記載行はカタログ参照）にすれば伝搬そのものが不要になる。子が明示上書きした行に伝搬しないのは子の意思の尊重であり正しい。スクリプトの役割は伝搬ではなく「影響の可視化」（継承中／上書き中の一覧）に置き換えた。失われる「ファイル単体での全体視認性」は resolve サブコマンドで補う（主が許容済み）。

### 行を書くなら5列すべて（列の部分上書きをしない）

列単位の部分上書きを許すとマージ規則が3次元（層×行×列）になり、resolve と lint の複雑さが跳ね上がる。行単位なら「その観点はこの層の行が正」の1規則で済む。上書き行を書くコストは5列コピーして1列直すだけで小さい。

### registry は `~/.claude/casting/registry.txt`

影響一覧には導入済み repo の発見手段が要る。repo 側に持つと走査起点が無いため home 側に置く。1行1絶対パスの平文（jq 依存なし・手で直せる）。テスト容易性のため環境変数（`CASTING_REGISTRY`）でパスを差し替え可能にする。

### hooks による書き込み強制は次段

「スクリプト以外では書き込めない」の機械的強制は casting ファイルへの直接 Edit を deny する PreToolUse hook（シークレット露出ガードと同型）で実現できるが、hook の追加は自己統治物件で無条件人間承認の対象。今回は規約（catalog.md / SKILL.md への明記）までとし、hook は主の承認を得てから別 change で入れる。

### resolve は casting-check.sh のサブコマンドにする

パース部品（front matter・表の1列目抽出・語彙照合）を check と共有するため、別スクリプトにしない。引数なし実行は従来どおり検査、`resolve` は合成表示。
