# Design

## Context

背景は proposal.md。#1541・#1759・#1789 を main 7759b7f3 で確かめ、#1541 は文書・spec・テストだけ、#1759 は再現未確認で残る可能性が高い、#1789 は全部残っていると分かった。`check_children` は `<owner>/<repo>#N` を受けるのでコードの変更は要らない。

## Goals / Non-Goals

**Goals:** 親が主への問いを落とさない・未回答の止まりを `resumed` にしない・`owner-away` の文面とテストを実物に合わせる。

**Non-Goals:** PR と記録の結び付け方の揺れを塞ぎ切ること。`told` を `epic-multirepo.md` の列挙に足すこと（issue に無い。気づきとして残す）。

## Decisions

1. **pending-owner に `status != done` を足す。** `told` と揃える。`pending` を出す子は変わらない。`dismiss` は status を見ず、足さない（done の子を `resumed` に戻しても害がない）。
2. **#1759 は「問いではない」を形の崩れにする。** `stop-judge.sh` が `判断: 問いではない` を受けたときだけ、未回答の停止の記録（`子の停止: 主の返事待ち` の最新コメントが時刻不問であり、子の open の PR に `needs-approval`）を確かめ、該当すれば exit 1。`gh pr list` の失敗も exit 1。モデルの出力の経路（222 行以降）に加え、完了見出しでモデルを呼ばず `問いではない` を返す早期 return（131-137 行）にも同じ検査を入れる（片方だけでは完了見出しの止まりが抜ける）。他の判断では PR を調べず、費用を増やさない。
   - 却下案: 古い停止の記録を今回の記録に格上げする。既存の MUST NOT「最後の入力より前の記録を今回の止まりの根拠にしてはならない」と衝突する。
3. **`owner-away` の掛け直しは同じ出力のほかの行の処理のあと。** `closed`・`stopped` が並ぶのに先に掛け直すと取りこぼす。

## Risks / Trade-offs

- 再現未確認の #1759 に対する検査が空振りしうる → 変更は `問いではない` のときだけの追加確認で、通常経路を変えない。
- `gh pr list` 失敗で止まりが `stopped` に残る → 安全側（主に見える）に倒す。
