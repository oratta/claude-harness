## Context

動機は proposal.md の Why。今の形:

- 本体は spawn・再開・Codex 委譲の前に `pr-token-budget.sh` を呼ぶ。exit 2 なら `needs-approval` を付けて主に「続けるか、範囲外として閉じるか」を問う。「続ける」なら本体が `PR トークン上限: <合計 ＋ 直前の上限>` を投稿し、以後 `--cap` に渡す（SKILL.md「PR トークン上限」）
- 別セッション方式の子は、止まる前に `子の停止: 主の返事待ち` の記録（7 項目）を投稿し、印を付ける（`epic-child-stop.md`）。親の `wait --resolve` は `stop-judge.sh` でモデルに `parent-pass-criteria.md` を読ませ、通すものには返事を送る。通せないものは `stopped` で親を起こす。起こされた親は手順 8 で記録を読み、`止まった理由:` が `PR のマージ待ち（` で始まるものは専用の手順に進む。それ以外は基準に照らし直して、通すか主に上げる
- `stop-judge.sh` がモデルに渡すのは、エピックと子の本文・注意書き・停止の記録・過去の `親の判断:` の行・基準・配役表だけで、エピックのほかのコメントは渡さない

## Goals / Non-Goals

**Goals:**
- エピックの子の超過のうち、見込みが親の権限の内のものを、主の返事なしに続けられる
- 誰がどの記録を書けば次の計測の `--cap` が決まるかが、手順書から一通りに読める

**Non-Goals:**
- 既定の上限 3,000 万の変更と、最適値の探索（別の issue）
- エピックの子でない作業の上限の扱い
- `stop-judge.sh`・`epic-dispatch.sh` の変更

## Decisions

### 1. 権限はエピックの issue のコメントに置く

1 行目 `子の PR トークン権限: <値>`（数字だけ。既定 60000000）のコメントをエピックに置く。投稿者が OWNER・MEMBER・COLLABORATOR の最新の 1 件を正とする。主が広げたら、親が新しい値で投稿し直し、2 行目に `主の発言: <要旨>` を書く。

- 採った理由: 親のセッションが変わっても（再開・後任）同じ値が読める。既存の `回し方:` や `親の判断:` と同じく、エピックのコメントが親の状態の置き場になっている。投稿者の条件は、手順 8 が読む記録と同じにする
- 退けた案:
  - 環境変数にする案。親のセッションの起動時にしか効かず、主が夜に広げてもその場では反映されない
  - ローカルの状態の記録（epic-state）に置く案。スクリプトを変えることになり、主にも見えない
- 権限のコメントが無いエピック（この変更の前に起動したエピック）は、親が手順 7 で再開したとき、手順 8 で PR トークン上限の止まりを照らす前、またはサブエージェント方式の本体が子の記録先の exit 2 で照らす前に既定値で投稿し、主に伝えてから使う。主に上げるのは、投稿者の条件を満たす権限のコメントがあるのに値が数字として読めないときだけ

### 2. 親が通すのは起こされた親（手順 8）だけで、`wait --resolve` の判断のモデルには通させない

`parent-pass-criteria.md` の通す条件の 1 行目（既存の規則が主に聞く止まりでない）と通らない例は、PR トークン上限の止まりを判断のモデルに通させないまま残す。手順 8 の親は、`止まった理由:` が `PR トークン上限（` で始まる止まりを基準に照らし直さず、専用の手順に進む（`PR のマージ待ち（` の振り分けと同じ形）。

- 採った理由:
  - スクリプトもテストのスタブも変えずに済む
  - 判断のモデルは権限のコメントを受け取っていないので、照らせない
  - 費用の上限の比較を、記録の URL と数値を確かめられる親に寄せられる
  - 親が一度起こされる手間はかかるが、止まりの大半を占めていた主の待ち（数時間〜20 時間）に比べて小さい
- 退けた案: `stop-judge.sh` に権限のコメントを渡し、モデルに通させる案。入力を増やすとテストと偽の記録への対策も増える。また費用の判断が LLM の 3 行の出力だけで決まる
- 基準のファイルには、通らない例の理由を「判断のモデルは通さない。起こされた親が `epic.md` 手順 8 の専用の手順で、親の権限に照らす」に直す。今の理由（「親の返事だけでは記録が作られない」）は、子の本体が記録を書く作りにするので成り立たなくなる

### 3. 通す条件は 2 つ、新しい上限は権限そのもの

次の 2 つをどちらも満たすときだけ通す。

- (a) 子の記録の「合計の見込み」が権限以下
- (b) 今の上限（止まったときの計測の上限）が権限より小さい

通すときの新しい上限は権限の値にする。

- (b) があるので、権限まで上げてもまた止まった子は主に上がる
- 見込みが書かれていない・読めないときは主に上げる
- 同じ子を二度通すことは、新しい上限が権限になる以上 (b) で起きない。基準の「繰り返していない」は、この専用の手順では照らさない
- 主への承認は、主が権限を決めたこと（既定値を伝えたこと、または主が広げたこと）で済んでいる。だから基準の「聖域でない」（課金）にも照らさない
- 通さずに主に上げるときは、権限の値と権限を広げる選び方を添える。主が権限を広げて答えたら、親は新しい値で権限のコメントを投稿し直し、同じ止まりを (a)(b) に照らし直して、満たせば `reply --as parent` で新しい上限 ＝ 新しい権限を送る。主が広げずに「続ける」とだけ答えたら、今までどおり `reply --as owner` で届け、子の本体は今の式（合計 ＋ 直前の上限）で書く
- 退けた案: 「合計 ＋ 見込みの残り」のように、見込みぴったりに上げる案。見込みが少し外れるたびに止まり、権限の内なのに親が何度も起こされる

### 4. `PR トークン上限:` は子の本体が書く

親は `reply --as parent <E> <N> <返事>` で、次の返事を送る。

`続ける。新しい上限 <権限>（親の権限。<権限のコメントの URL>）`

子の本体は `親エピック #E の判断（主の承認ではない）:` で受け取り、記録先に次のコメントを投稿してから再開する。

```
PR トークン上限: <権限>
決めた人: 親エピック #<E> の判断（親の権限の内。主の承認ではない）
権限: <権限のコメントの URL>
停止の記録: <停止の記録の URL>
```

親はエピックに `親の判断: 子 #N 通した — PR トークン上限を親の権限 <権限> まで上げた（合計の見込み <Y>） <停止の記録の URL>` を残す。

- 採った理由:
  - 計測を回すのは子の本体で、`--cap` は記録先の最新の `PR トークン上限:` から読む。記録先を書くのも子の本体にすれば、今の「続ける」と同じ場所・同じ担い手になる
  - 親が子の記録先に直接書く案は、子の本体がまだ返事を受けていないのに上限だけが変わる時間を作る
- 親の返事は、主が権限のコメントで先に承認した範囲の執行である。子の本体は、要件「エピックの子は親から届いた返事を止まった件への返事として受け取る」の「聖域の承認として扱わない」と、基準の聖域の「課金」には当たらないものとして読み、主に聞き直さない。権限の URL を `権限:` の行に残すことで、どの主の承認の範囲かを後から辿れる
- 1 行目は今の書式のまま（`^PR トークン上限: <数>`）なので、後任の本体と引き継ぎの手順 6 はそのまま読める

### 5. サブエージェント方式では本体が同じ条件で照らす

サブエージェント方式（unmanned・channel を含む）では、本体がエピックの親を兼ね、子の記録先ごとに計測する。子の記録先の計測が exit 2 になったら、本体は自分の見込みを Decision 3 の条件で照らし、満たせば主に聞かずに 4 と同じ書式で `PR トークン上限:` を投稿する（`決めた人:` は `エピック #<E> の本体（親の権限の内）`、`停止の記録:` は `なし`）。満たさなければ今の exit 2 の手順で主に聞く。

- 見込みは、本体が主に出す問いの材料と同じ形で、記録先にコメントとして残す
- 採った理由: 主の決定は「エピックの親に権限を持たせる」で、回し方による違いを書いていない。方式で扱いが割れると、同じエピックを方式違いで再開したときに読み違える

### 6. 子の記録に書く見込みの形

`止まった理由:` は `PR トークン上限（合計 <合計> / 上限 <上限>）: 続けるか、範囲外として閉じるか` で始める。`前提:` の中に、次の 3 行を書く。

- `終わるまでの見込み: あと約 <X>（合計の見込み <Y>）`
- `続けるべきか: <続ける／閉じる と理由>`
- `次に絞る範囲: <残工程のうち何に絞るか>`

7 項目の形と項目名は変えない（値の中に書く）。親は LLM として読むので、行の名前が揃っていれば足り、機械の検査は足さない。

## Risks / Trade-offs

- [子の見込みが外れて、権限まで使っても終わらない] → (b) で主に上がる。主の確認なしに使えるのは、子 1 件あたり権限（既定 6,000 万）まで
- [子が見込みを小さく書いて通そうとする] → 上限は見込みではなく権限で切るので、外れても権限を超えては使わない。見込みを書かない記録は主に上がる
- [主が子のタブで直接「続ける」と答えた場合] → 今までどおり主の返事として扱い、本体が今の式で新しい上限を書く（この変更の外）
- [親が一度起こされる] → 別セッション方式では、親が起こされる手間は残る。止まりの時間は親のポーリング間隔の程度に縮む

## Migration Plan

手順書だけの変更で、スクリプトは変えない。この変更の前に起動したエピックは権限のコメントを持たないので、親が手順 7 で再開したとき、手順 8 で PR トークン上限の止まりを照らす前、またはサブエージェント方式の本体が子の記録先の exit 2 で照らす前に、既定値で投稿して主に伝える。戻すときは手順書の差分を戻すだけで、残った `子の PR トークン権限:` のコメントは読まれなくなるだけ。
