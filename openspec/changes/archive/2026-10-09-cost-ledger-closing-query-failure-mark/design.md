## Context

`gate_report.stack()` は `issue クローズ` を積むとき `closing_prs()` を 1 回呼び、返った PR を `--closing-pr` で `cost_ledger.py timeline` に渡す。`closing_prs()` は失敗・形の崩れ・100 件超で `[]` を返すので、成功して 0 件の回と区別が付かない（#689 の spec が「誤ったまま通ることを許す」と書いた穴）。後追い（#691）は `backfill.stack_one()` から同じ `stack()` を使い、候補は GitHub の閉じた issue の一覧、二重追記の判定は `timeline_has_trigger_near()`（きっかけの欄を `+` で分けた要素に呼び名があり、時刻が `--at` の 300 秒前以降なら足さない）。

制約（エピック #272）: 行を短く保つ・LLM のトークンを使わない・`gh` の呼び出し回数を増やさない。

## Goals / Non-Goals

**Goals**
- 失敗した回だけ、行に短い印が付く
- 成功した回の行と `gh` の回数は #689 のときのまま

**Non-Goals**
- 失敗した回の合計を自動で補うこと
- 失敗の理由（ネットワーク・形の崩れ・100 件超）の区別
- `cost_ledger.py` の変更（`cost`・`issue` サブコマンドは既に失敗を別の行で伝えている）

## Decisions

### 1. 印の置き場所と形: きっかけの欄の末尾の `+` 区切りの要素 `PR 照会失敗`

行は `| 時刻 | きっかけ | 金額 | 入出力 | キャッシュ |` で、きっかけの欄は既に `issue コメント+issue クローズ` のように `+` で要素をつなぐ。失敗のときだけ末尾に `PR 照会失敗` を足す（`issue クローズ+PR 照会失敗`）。

- 比較した案: (a) きっかけの欄の末尾要素（採用）、(b) 合計の行の代わりに「合計（取得失敗）」の行を積む、(c) 隠し行（記録）にだけ持つ、(d) 金額の欄に `(?)` を付ける
- (b) は成功時の行数と同じ 2 行になり、失敗の回だけ行が 1 本増える。1 行が短い代わりに行数が増え、読む側のトークンも増える。不採用
- (c) はコメントを読んでも見えない（隠し行は HTML コメント）。目的はコメント上で見分けること。不採用
- (d) は `(?)` が既に「増分が分からない」の意味で使われている（`TIMELINE_UNKNOWN`）。意味が重なる。不採用
- (a) は追加が 8 文字で、失敗した回の 1 行にだけ付く。`timeline_row()` を通る欄の中身が変わるだけで書式は変えない。`+` で分けた要素にするので `timeline_has_trigger_near()` は `issue クローズ` を今までどおり見つける（後追いが同じ出来事の行を重ねて積まない）。`_is_total_trigger()` は `合計（` で始まる欄だけを見るので影響しない
- 呼び名は `PR 照会失敗`。既存の呼び名（`PR コメント`・`PR クローズ`）と並べて、PR の合計を問い合わせて失敗したことが読める

### 2. 失敗と成功の区別は `closing_prs()` の戻り値で付ける

失敗は `None`、成功は `[]` か `[(番号, ブランチ)]`。`stack()` は `None` のときだけ名前を足す。`gh` の呼び出しは増えない（今ある 1 回の結果の読み方を分けるだけ）。失敗に含めるのは、`gh` の失敗・JSON でない・期待する形でない・1 件でも形が崩れている・`hasNextPage` が真。「数えない PR（別のリポジトリ・fork）だけが返った」は、読めているので失敗ではなく、印を付けない。

### 3. #691 の後追いとの関係: 失敗分は補わない

後追いの候補は「前回見た時刻以降に閉じられた issue」で、hook が既に `issue クローズ` を積んだ issue は `timeline_has_trigger_near()` で外れる。印付きの行も `issue クローズ` の要素を持つので外れる。これを変えて補うには、印付きの行を「未完了」と見て、後追いで 2 行目として `issue クローズ` と合計の行を積む（同じ出来事の行が 2 本並ぶ）か、既存の行を書き換える（`timeline_rewrite_increments` 以外に行の書き換えが増える）必要があり、問い合わせが失敗し続ける環境で毎回のセッション開始に `gh` の呼び出しも増える。エピックの制約（呼び出し回数と行の短さ）に反する割に、得るのは同じ合計で、`/cost <issue番号>` で手で取れる。補わないことにし、spec の守備範囲に許す穴として書く。

## Risks / Trade-offs

- 失敗した回の合計は、コメントに載らないまま。印で気づけるだけ。気づいたら `/cost <issue番号>` で合計を確かめられる（再表示するだけで、コメントの行は補わない。README に書く）
- 失敗の理由は区別しない。ネットワークの一時的な失敗でも、100 件超でも同じ印
- 失敗の印は、PR 合計を取れなかったという事実だけで、`issue クローズ` の行の数字（区間だけの累計）には影響しない
