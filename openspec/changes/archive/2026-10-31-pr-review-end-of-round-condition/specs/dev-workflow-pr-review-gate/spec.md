## ADDED Requirements

### Requirement: 周の終わりに残った止める指摘の条件を先に確かめる

`skills/pr-review-gate/stages/triage.md` は、周の終わりの段落の直後に段落「周の終わりの止める指摘の条件」を持たなければならない（MUST）。G は、2 周目以降の周の終わりに止める指摘が残ったとき、順 6・直し方の判定・順 5 の振り分けより先に、指摘ごとの「何が起きるか」に書かれた条件がいつ成り立つかを段 B の表の分け方で決める（MUST）。止めるかどうかの判定（全周共通）は変えてはならない（MUST NOT）。

「周の終わりに残った指摘を直し方の判定に回す」Requirement と手順 2-1 の周の終わりの扱いの「残った止める指摘」は、この段を通したあとの指摘を指す（MUST）。順 6 を除いた指摘の件数も、この段を通したあとの指摘で数える（MUST）。

**当てないところ**: 1 周目の指摘と、順 3・順 4 からの落とし込みで順 6 に当てる指摘には、この段を当ててはならない（MUST NOT）。

#### Scenario: 順 6 より先に閉じて裁定を使わない
- **WHEN** 周の終わりに前の周と同じ型の再発の指摘が残り、その条件が成り立つ予定が無く、閉じない指摘の 2 種のどちらにも当たらない
- **THEN** G は順 6 に当てる前に指摘を閉じ、`needs-decider` を返さない

#### Scenario: 一部を閉じて残りを既存の経路に進める
- **WHEN** 2 周目の終わりに止める指摘が 2 件残り、1 件は条件が成り立つ予定が無く閉じない指摘の 2 種のどちらにも当たらない、もう 1 件は受け入れ条件を引用していて条件がいまの範囲で成り立ち、前の周と同じ型の再発ではない
- **THEN** G は 1 件を閉じ、もう 1 件の仮の順と根拠を仕分けの PR コメントに記録して `needs-fix-check` で return する

#### Scenario: 1 周目には当てない
- **WHEN** 1 周目の仕分けで止める指摘の条件が成り立つ予定が無い
- **THEN** G はこの段を当てず、仕分け表の順 2〜6 のどれかに当てる

### Requirement: 周の終わりの条件の段で閉じるのは成り立つ予定が無い指摘だけにする

G は、条件が「成り立つ予定が無い」指摘だけを閉じる（MUST）。「条件を書けない」「いまの範囲で成り立つ」「後で成り立つ」の指摘は閉じず、既存の経路に進める（MUST）。止める判定を通った指摘なので、条件を書けないことは閉じる理由にならない。

**閉じない指摘**: 受け入れ条件、またはこの PR が触れる openspec の spec（change の delta spec を含む）の文がその場面の振る舞いを求めている指摘と、主が順 5 で「この PR で直す」と答えた指摘は、閉じてはならない（MUST NOT）。

**根拠**: 根拠は段 B と同じく、エピックと記録先の本文、受け入れ条件、コード、本文の節 `## 条件の答え` の行に限る（MUST）。change の artifact に書かれた想定は根拠にしてはならない（MUST NOT）。

#### Scenario: 条件を書けない指摘は閉じない
- **WHEN** 周の終わりに残った止める指摘の「何が起きるか」が `条件を書けない` である
- **THEN** G は指摘を閉じず、周の終わりの段落どおりに順 6・直し方の判定・順 5 のどれかに当てる

#### Scenario: 文が求める場面の指摘は閉じない
- **WHEN** 周の終わりに残った止める指摘の場面を、運用上は起きないとエピックの本文に書かれていても、delta spec の Scenario がその場面の振る舞いを求めている
- **THEN** G は指摘を閉じず、既存の経路に進める

#### Scenario: 触れる spec の文が求める場面の指摘は閉じない
- **WHEN** 周の終わりに残った止める指摘の根拠が、この PR が触れる main spec の原文で、受け入れ条件と delta spec には再掲されておらず、その文がその場面の振る舞いを求めている
- **THEN** G は指摘を閉じず、既存の経路に進める

#### Scenario: 主が直すと答えた指摘は閉じない
- **WHEN** 前の周の順 5 で主が「この PR で直す」と答えた指摘が、周の終わりにも残っている
- **THEN** G は条件によらず閉じず、既存の経路に進める

### Requirement: 周の終わりの条件を決められない指摘は閉じずに既存の仕分けへ進める

根拠から言い切れなければ、G は「G が決められない」に当て、閉じずに既存の仕分けへ進める（MUST）。この段のために新しい質問も保留も足してはならず、`条件の確認待ち` のコメントも `needs-approval` も使ってはならない（MUST NOT）。後の周の終わりに `## 条件の答え` の行が根拠になれば、G はその行を根拠に閉じてよい（MAY）。

#### Scenario: artifact の想定だけでは閉じない
- **WHEN** 周の終わりに残った止める指摘の条件が成り立たない根拠が、change の design.md の想定にしか無い
- **THEN** G は「決められない」に当てて指摘を閉じず、既存の仕分けへ進め、この段のために `条件の確認待ち` のコメントも `needs-approval` も足さない

#### Scenario: 後の周で主の答えを根拠に閉じる
- **WHEN** 前の周に決められなかった止める指摘が周の終わりに残り、エピックの本文の `## 条件の答え` に、その場面は起きないとする行が足されていて、閉じない指摘の 2 種のどちらにも当たらない
- **THEN** G はその行を根拠に指摘を閉じ、仕分けの PR コメントに条件と理由を 1 行残す

### Requirement: 周の終わりの条件で閉じた指摘を記録する

閉じた指摘は、仕分けの PR コメントに条件と理由を 1 行残し、return の仕分け欄に閉じた指摘とその PR コメントの URL を書く（MUST）。全件を閉じたら「止める指摘が残らなかったとき」と同じ扱いにする（MUST）。

#### Scenario: 成り立つ予定が無い指摘を閉じる
- **WHEN** 2 周目の終わりに止める指摘が 1 件残り、その条件が、記録先の本文が対応しないと書いている OS でだけ成り立ち、閉じない指摘の 2 種のどちらにも当たらない（受け入れ条件とこの PR が触れる openspec の spec の文はその OS の振る舞いを求めておらず、主が順 5 で「この PR で直す」と答えた指摘でもない）
- **THEN** G は指摘を閉じ、仕分けの PR コメントに条件と理由を 1 行残し、`needs-fix-check` も `needs-approval` も返さず、Status `次の段へ`・`次の段: 合格処理` で return する

### Requirement: 周の終わりの条件の段の守備範囲

`skills/pr-review-gate/stages/triage.md` の段落「周の終わりの止める指摘の条件」は、次の守備範囲を書かなければならない（MUST）。この段の守備範囲は、起きる予定の無い場面への止める指摘が、順 6 の裁定・直し方の判定・主への確認を使うことを防ぐことである。想定する入力の出どころは、全周共通の判定を通って周の終わりに残った止める指摘と、根拠に挙げた文書とコードである。拾いたい誤りは、運用上成り立たない条件の指摘で周回と主への確認を増やすことである。通ることを許す入力の例として、根拠から言い切れない条件の指摘は既存の経路で主に上がり、G が根拠を読み違えて「いまの範囲で成り立つ」とした指摘もそのまま既存の経路に進む。判定の誤りが 1 件も無いことをこの段の完了条件にしない。

#### Scenario: 守備範囲が書かれている
- **WHEN** `skills/pr-review-gate/stages/triage.md` の段落「周の終わりの止める指摘の条件」を読む
- **THEN** 防ぐこと・想定する入力の出どころ・拾いたい誤り・通ることを許す入力の例が書かれ、判定の誤りが 1 件も無いことを完了条件にしないと書かれている

## MODIFIED Requirements

### Requirement: 合格条件に判定を明記する

`skills/pr-review-gate/stages/pass.md` の手順 5 は、合格処理の前提として、最後のレビュー結果に全周共通の判定で止まる指摘（`blocking` かつ `confirmed` で、G が引用を照合済みまたは例外 3 種に当たるもの）のうち、主が切り出すと答えて follow-up issue に切ったものと、G が順 3 の集合一致で閉じたものと、G が周の終わりの止める指摘の条件で閉じたもの以外が 0 件であることを書かなければならない（MUST）。切り出しの確認で主が「切り出す」と答え、follow-up issue に切った指摘と、順 3 の集合一致で閉じた指摘（閉じた PR コメントの URL を仕分け欄に残す）と、周の終わりの条件で閉じた指摘（閉じた PR コメントの URL を仕分け欄に残す）は、この 0 件の数に含めない（MUST。順 3 の指摘だけで戻した周は再レビューを行わないので、最後のレビュー結果には閉じた印が付かないため。周の終わりの条件で閉じた指摘も、再レビューを経ずに閉じるので同じである）。

#### Scenario: 手順 5 の合格条件

- **WHEN** `skills/pr-review-gate/stages/pass.md` の手順 5 を読む
- **THEN** 全周共通の判定で止まる指摘（`blocking` かつ `confirmed`、G が引用を照合済み）のうち、主が切り出すと答えて follow-up issue に切ったものと、順 3 の集合一致で閉じたものと、周の終わりの止める指摘の条件で閉じたもの以外が 0 件であることが合格処理の条件として書かれている

#### Scenario: 条件で閉じた指摘だけが残る最後のレビュー結果

- **WHEN** 最後のレビュー結果で止まる指摘が 1 件あり、その指摘を G が周の終わりの条件で閉じて、閉じた PR コメントの URL が仕分け欄にある
- **THEN** 手順 5 の前提は満たされ、ほかの条件が揃えば合格処理に進む
