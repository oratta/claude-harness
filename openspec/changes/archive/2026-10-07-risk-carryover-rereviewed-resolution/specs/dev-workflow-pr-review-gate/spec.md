## MODIFIED Requirements

### Requirement: 前の HEAD の許容を新しい HEAD に引き継いでよい条件

pr-review-gate SKILL.md は、手順 3 で「主のリスク許容が必要」と判定したとき、手順 6 で主に聞く前に、前の HEAD で得た許容を引き継げるかを確かめる手順（手順 3-c。3-b の後ろに置く）を持たなければならない（SHALL）。前の HEAD の宣言は、同じ PR の `## リスク宣言` コメントのうち `主の回答: 許容` で始まる行（引き継ぎの形を含む）と `真正性確認: 済` の行の両方を持つ最新 1 件とし、その `対象 HEAD:` の SHA をスクリプトの前 HEAD に渡さなければならない（MUST）。引き継げるのは次のすべてを満たすときに限る（MUST）: ①`risk-carryover-check.sh` に前の HEAD・新しい HEAD・前の宣言の根拠ファイルを渡して終了コード 0 が返る、または終了コード 3 が返り、新しい HEAD で取り直したレビューが PR 全体を見た周である（最新の `レビュー重量:` コメントの `固定 HEAD:` が新しい HEAD の 40 桁 SHA と一致し、その周がゲートの開始・CI の見張りのあとの取り直し・方式の書き換え後の全体レビューのどれかで、W の修正後の差分限定の再レビューでも、戻した指摘が順 3 だけでレビューをせずに閉じた周でもない。G が周の種類を前の段の Gate Result と PR のコメントから読めないときは満たさないものとする） ②前の HEAD の宣言に根拠ファイルの行がある ③引き継ぎの元の回答が「引き継ぎの元は真正性確認済みの主の直接の回答に限る」Requirement を満たす ④新しい HEAD のリスク宣言の本文が、`対象 HEAD:` 行を除いて前の HEAD の宣言の本文（末尾の `主の回答:` 以降の追記行を除いた部分）と同一である（リスク内容・該当する観点・発生条件・影響範囲と戻し方・根拠ファイルがすべて同じであることをこの一致で確かめる）。1 つでも満たさなければ、従来どおり手順 6 で主に聞かなければならない（MUST）。引き継ぎで省けるのは主への質問だけで、レビュー・動作確認証拠・仕様宣言の取り直しと手順 5 の実測は省いてはならない（MUST NOT）。これは手順 1 の「手順 1 から全工程をやり直す（前回の合格部分を流用しない）」と `gate-runner.md` の再レビューの同趣旨の文に対する唯一の例外であることを、3-c に書かなければならない（SHALL）。

この引き継ぎの判定（スクリプトと G の確認を合わせたもの）の守備範囲は次のとおりとする:

- 入力: G 自身が手順 1 で `git fetch` と main の取り込みを済ませたローカルの git リポジトリ（前の HEAD・新しい HEAD・base）、同じ PR の前の宣言コメント（`- 根拠ファイル:`・`主の回答:`・`真正性確認:` の行）、元の直接の回答リンク。G は協力的だが、列挙漏れと読み違いをする前提で扱う
- 拾いたい誤り: main 以外の commit（W の修正・rebase・force-push による履歴の書き換え）、PR 全体を見たレビューを経ていない、許可リストの条件を満たさない衝突解消（許可リスト外のファイルでの衝突解消、許可リスト内のファイルでの版の行・並べ直し以外の変更、衝突していないファイルへの手入れ）、根拠ファイルの変更、前後どちらの HEAD にも無い根拠ファイル、根拠ファイルの行が無い宣言からの引き継ぎ、引き継ぎの記録そのものを回答リンクにする自己参照、真正性確認のやり直しの省略
- 通ることを許す入力の例: main 側が根拠ファイル以外の PR が触ったファイルを衝突なしで変えた取り込み（リスクの中身が変わるかは条件④で見る）、G が根拠ファイルを列挙し損ねた宣言、`"version"` を含む行の中身、CHANGELOG の並べ直しで項目の属する見出しが変わるもの、主のアカウントで代理投稿された元の回答、新しい HEAD で PR 全体を見たレビューを経た許可リストの条件を満たさない衝突解消（衝突解消の結果は PR の base との差分に現れ、そのレビューで読まれる）
- 範囲外: 代理投稿の見分け、根拠ファイルの列挙の妥当性、merge の仕方の違いによる誤検出（引き継げない側に倒れるだけ）、PR 全体を見たレビューが衝突解消の中身を見落とすこと（レビュー一般の精度の問題として扱う）、差分限定の再レビューの周で main を取り込んだときに引き継げないこと（主に聞く側に倒れるだけ）。これらを塞ぐことは本要件の完了条件にしない

#### Scenario: main の取り込みだけで HEAD が動いた

- **WHEN** 主が許容した PR で、G が手順 1 で main を取り込んで HEAD が動き、スクリプトが終了コード 0 を返し、新しい HEAD のリスクの中身が前と同じである
- **THEN** G は `needs-approval` を付けずに、引き継いだ宣言を投稿して手順 4・5 へ進む

#### Scenario: 根拠ファイルが変わった

- **WHEN** 前の HEAD と新しい HEAD の間で根拠ファイルの diff が空でない
- **THEN** 引き継げず、G は手順 6 で主に聞き直す。質問にはスクリプトの `NG:` 行を添える

#### Scenario: レビューで新しいリスクが見つかった

- **WHEN** スクリプトは終了コード 0 を返したが、新しい HEAD のレビューで観点や根拠ファイルが増え、宣言の本文が `対象 HEAD:` 行を除いて前の宣言と一致しない
- **THEN** 引き継げず、G は手順 6 で主に聞き直す

#### Scenario: 根拠ファイルの行が無い古い宣言

- **WHEN** 前の HEAD の宣言に `- 根拠ファイル:` の行が無い
- **THEN** 引き継げず、G は手順 6 で主に聞き直す

#### Scenario: 引き継いでもレビューは省かない

- **WHEN** SKILL.md の引き継ぎの手順を読む
- **THEN** 省けるのは主への質問だけで、手順 2 のレビュー・手順 4 の証拠・手順 3 の仕様宣言を新しい HEAD で出し直すこと、これが手順 1 の「前回の合格部分を流用しない」の唯一の例外であることが書かれている

#### Scenario: 前の HEAD の宣言の選び方

- **WHEN** 同じ PR に `## リスク宣言` コメントが複数あり、最新のものには `主の回答:` の行が無い
- **THEN** G は `主の回答: 許容` 系の行と `真正性確認: 済` の行の両方を持つ最新 1 件を前の宣言とし、その `対象 HEAD:` の SHA を前 HEAD としてスクリプトに渡す

#### Scenario: 許可リスト外の衝突解消を全体レビューが見た

- **WHEN** 合格処理の取り直しで main を取り込んだ merge commit が `openspec/specs/x/spec.md` の衝突を解いており、スクリプトが終了コード 3 を返し、最新の `レビュー重量:` コメントの `固定 HEAD:` が新しい HEAD で、その周が CI の見張りのあとの取り直し（PR 全体を見たレビュー）で、根拠ファイルの diff が空で、宣言の本文が同一である
- **THEN** G は `needs-approval` を付けずに引き継いだ宣言を投稿し、引き継ぎの根拠行に終了コード 3・許可リスト外のファイル・取り直しのレビューの固定 HEAD と周の種類とその `レビュー重量:` コメントのリンクを書いて手順 4・5 へ進む

#### Scenario: 許可リスト外の衝突解消を差分限定の再レビューしか見ていない

- **WHEN** スクリプトが終了コード 3 を返したが、新しい HEAD を固定 HEAD にした周が W の修正後の差分限定の再レビュー、または戻した指摘が順 3 だけでレビューをせずに閉じた周である
- **THEN** 引き継げず、G は手順 6 で主に聞き直す。質問には `RESOLVED_OUTSIDE_ALLOWLIST=` の行と、PR 全体を見たレビューを経ていないことを理由として添える

#### Scenario: 周の種類が読めない

- **WHEN** スクリプトが終了コード 3 を返したが、G が新しい HEAD の周の種類を前の段の Gate Result と PR のコメントから読めない
- **THEN** 引き継げず、G は手順 6 で主に聞き直す

### Requirement: risk-carryover-check.sh が差分の範囲と根拠ファイルの無変更を判定する

`plugins/dev-workflow/scripts/risk-carryover-check.sh [--base <ref>] <前 HEAD> <新 HEAD> <根拠ファイル>...` は、ローカルの git リポジトリだけを読み、pathspec をリポジトリのルート相対で解釈し（実行時の cwd によらない）、次の 4 つの条件を判定しなければならない（SHALL）: ①前の HEAD が新しい HEAD の祖先である ②`git rev-list <新> ^<前> ^<base>` の全件が 2 親の merge commit で、第 2 親が base の祖先、第 1 親が前の HEAD かこの集合の別の commit である ③各 merge commit の衝突解消したファイル（`git merge-tree --write-tree <第1親> <第2親>` の tree と merge commit の tree で差のあるファイル。rename 検出をせず `git diff --no-renames --name-only` で列挙し、消したファイルと作ったファイルを別々に数える）が許可リストに入り中身の条件を満たす ④根拠ファイルそれぞれについて `git diff <前> <新> -- <ファイル>` が空である。許可リストは、`.claude-plugin/marketplace.json` と `plugins/*/.claude-plugin/plugin.json`（`"version"` を含む行を除いた本文が第 1 親か第 2 親の版と一致する）、および `CHANGELOG.md` とサブディレクトリの `CHANGELOG.md`（merge commit の版のすべての行が第 1 親か第 2 親の版に存在する）に限る（MUST）。`--base` の既定は `origin/main` とする。

①②④のどれかが外れたら、外れた理由ごとに `NG: <理由>` 行を出し、`CARRYOVER=no` で終了コード 1 を返さなければならない（SHALL）。③だけが外れたとき（許可リストの条件を満たさない衝突解消があり、`NG:` 行が無いとき）は、`NG:` 行にせず、許可リストの条件を満たさないファイルごとに `RESOLVED_OUTSIDE_ALLOWLIST=<ファイル>` の行（重複は除く）を出し、`CARRYOVER=if-rereviewed` で終了コード 3 を返さなければならない（SHALL）。ここで「許可リストの条件を満たさない」は、許可リストに無いファイル・許可リストのファイルで中身の条件を満たさないもの・衝突していないファイルへの手入れのすべてを指す。①②④で `NG:` が出たときも、③を満たさないファイルは `RESOLVED_OUTSIDE_ALLOWLIST=` の行に出す（終了コードは 1）。4 つすべてを満たすときは `CARRYOVER=yes` で終了コード 0 を返さなければならない（SHALL）。終了コード 3 は「新しい HEAD で PR 全体を見たレビューを経ていれば引き継げる」を意味し、その確認は G が手順 3-c で行う（スクリプトはレビューの有無を見ない）。

判定の守備範囲は「前の HEAD の許容を新しい HEAD に引き継いでよい条件」Requirement の守備範囲の段落に従う（スクリプトが担うのは、そこに挙げた誤りのうち commit・衝突解消・根拠ファイルの変更と存在に関わるもの）。出力は `CARRYOVER=yes|if-rereviewed|no`・`MAIN_MERGES=<件数>`・`RESOLVED_FILES=<衝突解消したファイル全件のカンマ区切り。無ければ none>`・`RESOLVED_OUTSIDE_ALLOWLIST=<ファイル>`（該当ファイルごとに 1 行。無ければ出さない）と、不可の理由ごとの `NG: <理由>` 行とする。引数不足・SHA が解決できない・根拠ファイルが 1 つも無い・根拠ファイルが前の HEAD にも新しい HEAD にも無い・git が `merge-tree --write-tree` に対応しないときは終了コード 2 を返さなければならない（SHALL）。

#### Scenario: main の取り込みだけで衝突なし

- **WHEN** 前の HEAD に main を衝突なしでマージした commit だけが積まれ、根拠ファイルは変わっていない
- **THEN** 終了コード 0、`CARRYOVER=yes`、`MAIN_MERGES=1`、`RESOLVED_FILES=none` を出す

#### Scenario: 版番号と CHANGELOG の衝突解消だけ

- **WHEN** main のマージで plugin.json の `"version"` 行と CHANGELOG.md が衝突し、版の行の選び直しと CHANGELOG の項目の並べ直しだけで解消した
- **THEN** 終了コード 0 を返し、`RESOLVED_FILES` にその 2 ファイルを出す

#### Scenario: main 側の変更で根拠ファイルが変わった

- **WHEN** main のマージで根拠ファイルの中身が変わった
- **THEN** 終了コード 1、`CARRYOVER=no` と、そのファイルを示す `NG:` 行を出す

#### Scenario: main 以外の commit が積まれた

- **WHEN** 前の HEAD と新しい HEAD の間に、merge commit でない commit（W の修正など）がある
- **THEN** 終了コード 1 と、その commit を示す `NG:` 行を出す

#### Scenario: 許可リスト外のファイルで衝突解消した

- **WHEN** merge commit が許可リストに無いファイル（例 `openspec/specs/x/spec.md`）で自動マージの結果と違う中身になっており、根拠ファイルの diff は空で、ほかに `NG:` に当たるものが無い
- **THEN** 終了コード 3、`CARRYOVER=if-rereviewed`、そのファイルを示す `RESOLVED_OUTSIDE_ALLOWLIST=<ファイル>` の行を出し、`NG:` 行を出さない

#### Scenario: 許可リスト外の衝突解消と根拠ファイルの変更が重なった

- **WHEN** merge commit が許可リストに無いファイルで衝突を解き、同じ取り込みで根拠ファイルの中身も変わった
- **THEN** 終了コード 1、`CARRYOVER=no`、根拠ファイルを示す `NG:` 行を出す（`RESOLVED_OUTSIDE_ALLOWLIST=` の行も出す）

#### Scenario: 衝突していないファイルに merge commit の中で手を入れた

- **WHEN** merge commit が、衝突していないファイルを自動マージの結果と違う中身にしている
- **THEN** 終了コード 3 と、そのファイルを示す `RESOLVED_OUTSIDE_ALLOWLIST=` の行を出す

#### Scenario: 許可リストの JSON で版以外の行を変えた

- **WHEN** merge commit の plugin.json が、`"version"` 行を除いても第 1 親・第 2 親のどちらの版とも一致しない
- **THEN** 終了コード 3 と、その plugin.json を示す `RESOLVED_OUTSIDE_ALLOWLIST=` の行を出す

#### Scenario: CHANGELOG に新しい文を足した

- **WHEN** merge commit の CHANGELOG.md に、第 1 親にも第 2 親にも無い行がある
- **THEN** 終了コード 3 と、その CHANGELOG.md を示す `RESOLVED_OUTSIDE_ALLOWLIST=` の行を出す

#### Scenario: 許可リスト外のファイルを消して似たファイルを作った

- **WHEN** merge commit の中で許可リストに無いファイルを消し、それとよく似た中身のファイルを別の名前で作った（git の rename 検出なら 1 件の rename に見える）
- **THEN** 消したファイルも `RESOLVED_FILES` と `RESOLVED_OUTSIDE_ALLOWLIST=` の行に出る

#### Scenario: 根拠ファイルがどちらの HEAD にも無い

- **WHEN** 前の HEAD にも新しい HEAD にも存在しないパスを根拠ファイルとして渡す（誤字など）
- **THEN** 終了コード 2 を返し、標準エラーにそのパスを出す

#### Scenario: サブディレクトリから実行する

- **WHEN** リポジトリのサブディレクトリを cwd にして、ルート相対の根拠ファイルのパスを渡して呼ぶ
- **THEN** ルートから呼んだときと同じ判定になる（根拠ファイルが変わっていれば終了コード 1）

#### Scenario: 前の HEAD が祖先でない

- **WHEN** 新しい HEAD が前の HEAD を含まない（rebase や force-push で履歴が書き換わった）
- **THEN** 終了コード 1 を返す

#### Scenario: 根拠ファイルが渡されない

- **WHEN** 根拠ファイルを 1 つも渡さずに呼ぶ
- **THEN** 終了コード 2 を返す


### Requirement: 引き継いだ宣言の書式と合格条件

引き継いだ宣言は、前の宣言と同じ本文（行頭 `主のリスク許容が必要。` を含む）を新しい `対象 HEAD:` で出し直し、末尾に `主の回答: 許容（引き継ぎ） — <元の直接の回答リンク>（<日時>）`・`引き継ぎ元: <前の HEAD の 40 桁フル SHA> の宣言 <リンク>`・`引き継ぎの根拠: risk-carryover-check.sh 終了コード <0 または 3> — …`・`真正性確認: 済 — …` の 4 行を追記しなければならない（SHALL）。引き継ぎの根拠の行は、終了コード・main の取り込みの件数・衝突解消したファイル・許可リスト外のファイル（`RESOLVED_OUTSIDE_ALLOWLIST=` に出たもの。無ければ none）・根拠ファイルの diff が空であること・取り直しのレビュー（終了コード 3 のときは、そのレビューの固定 HEAD の 40 桁フル SHA・周の種類・その `レビュー重量:` コメントのリンク。終了コード 0 のときは「不要」）を書く書式でなければならない（SHALL）。手順 5 の合格条件の表は、この 4 行が揃った宣言を許容済みとして扱う行を持たなければならない（SHALL）。手順 6 の復帰の表と `gate-runner.md` の取り直しの節は、手順 3 の引き継ぎの小節を参照しなければならない（SHALL）。

#### Scenario: 書式が SKILL.md にある

- **WHEN** SKILL.md の引き継ぎの小節を読む
- **THEN** `主の回答: 許容（引き継ぎ） — ` で始まる行と、引き継ぎ元・引き継ぎの根拠・真正性確認の行の書式がある

#### Scenario: 引き継ぎの根拠行に取り直しのレビューの固定 HEAD を書く

- **WHEN** 手順 3-c の追記 4 行の書式を読む
- **THEN** 引き継ぎの根拠の行は `引き継ぎの根拠: risk-carryover-check.sh 終了コード ` で始まり、終了コード 0 と 3 の両方を書ける形で、許可リスト外のファイルと、終了コード 3 のときの取り直しのレビューの固定 HEAD・周の種類・`レビュー重量:` コメントのリンクを書く欄がある

#### Scenario: 手順 5 が引き継いだ宣言を許容済みとして扱う

- **WHEN** SKILL.md 手順 5 の合格条件の表を読む
- **THEN** 引き継ぎの 4 行が揃った「主のリスク許容が必要」の宣言を合格可とする行がある

#### Scenario: G の指示書が引き継ぎを参照する

- **WHEN** `gate-runner.md` の取り直しの節を読む
- **THEN** 許容済みの PR で HEAD が動いたときは、主に聞く前に pr-review-gate 手順 3 の引き継ぎの小節を試すことが書かれている
