## Context

背景は proposal.md の Why。親は今、issue の停止の記録（`子の停止:` コメントと状態の記録）だけから報告を書く。子のタブでの主の返事は子の会話ログにしか残らない。

## Goals / Non-Goals

- Goals: 報告の最後に毎回同じ形の表を付け、主が最新の 1 通で全部の子の状態と自分の操作を読める。表が子のタブで進んだ分と食い違わない
- Non-Goals: 子の issue の記録を子が書き直す規則（子の側の手順）の変更。実機のエピックでの確認（マージ後に主が行う）

## Decisions

- 子の最新状態の出どころは会話ログの末尾にする。代案は、子に「主が答えたら記録を書き直す」手順を足すこと。子は主の答えを受けた直後に記録を書き直す保証がなく、子の手順を増やす側は漏れやすいので採らない
- 読む部品は `epic-dispatch.sh` に `child-log` として足す。既存の `wait` の推定が同じ置き場を読んでおり、トランスクリプト置き場の引き方（`transcript_dir`）を再利用できる。要約は LLM に任せず、時刻と冒頭 80 文字だけを出し、意味の判断は表を書く親が行う
- 主の発言の判定は、type が user・内容が文字列かテキストのみ（tool_result を含まない）・`isMeta` でない・`isSidechain` でない、で行い、`親エピック` で始まる返事と最初の `/develop` の指示を除く。完全でなくてよい（親が冒頭を読んで判断する）。spec の守備範囲に書いた。`親エピック #` の返事は除き、`主の返事（親エピック #E 経由）:` は主の発言に数える。最新の会話ログは最後の timestamp が最も新しい 1 本。python3 が無い・記録が一意でないときは `unreadable`
- 状態表は区切りの下に置き、区切りより上の最後の行は答え方のままにする（既存の書き分けを壊さない）。サブエージェント方式の子には会話ログの置き場が独立してない（本体の会話の中）ので `child-log` は使わず、親が自分の会話から状態を書く。channel の答え方の列はチャンネルで返す内容にする

## Risks / Trade-offs

- 会話ログの形式は Claude Code の内部形式で変わりうる。読めなければ `unreadable` と `確かめられなかった` に落ち、誤った状態を書くより安全側に倒れる
- 冒頭 80 文字だけでは状態を取り違えうる。親が必要なら会話ログを自分で読む
