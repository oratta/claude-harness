# Design

## Context

#1238 で `risk-carryover-check.sh` の判定 4 は、根拠ファイルの「PR 自身の差分」（各 HEAD と base の merge-base からその HEAD までの差分）を前後で比べる形になった。比べるのは `-U0` の mode の行と、削除・追加・改行なしの印の行の並びだけで、ハンクの見出し（行番号）と文脈の行は捨てている。main が別の場所を変えても同じと判定できるようにするためで、その代わり行の位置の変化が見えない（proposal.md の Why）。

判定 2 のループ（`git rev-list <新> ^<前> ^<base>` を 1 件ずつ見る）は、merge commit でない commit を `PR_COMMITS=` で数えているだけで、どのファイルに触れたかは見ていない。

## Goals / Non-Goals

**Goals:**

- PR 自身の commit が根拠ファイルの中で行を動かしただけのとき、`EVIDENCE_MAIN_ONLY=` を出さず終了コード 4 にする
- main の取り込みだけで HEAD が動いたとき（#441・#694 の経路）と、根拠ファイルに触れない PR 自身の commit のときは、今までどおり終了コード 0 / 3 で引き継げる

**Non-Goals:**

- merge commit の衝突解消が根拠ファイルの行を動かしただけのときを終了コード 4 にすること（終了コード 3 の全体レビューで受ける。下の Decisions の 3 つ目）
- PR 自身の差分の比べ方（`-U0` の行の並び）を変えること
- 判定役への入力・判定の記録の書式を変えること

## Decisions

### PR 自身の commit が根拠ファイルに触れたら終了コード 4 にする（issue の案 2 を採る）

`git rev-list <新> ^<前> ^<base>` のうち merge commit でない commit のどれかが根拠ファイルに触れていれば（その commit と親の間でそのファイルの中身か mode に差がある）、PR 自身の差分が同じでも `EVIDENCE_PR_CHANGED=` にする。

採らなかった案（issue の案 1）: 前の HEAD の PR 自身の差分を新しい merge-base に載せ直したものと、新しい HEAD の PR 自身の差分を、文脈行つき（`-U3` 以上、行番号だけを除く）で比べる。

- 案 1 は main が PR の変えた行の近く（文脈の 3 行）を変えるだけで不一致になり、#1238 で `EVIDENCE_MAIN_ONLY=` に入れた「main が近くの行を変えた」取り込み（bats の「PR の変えた行の 2 行先を main が変えた」ケース）が終了コード 4 に変わる。受け入れ条件の「main の取り込みだけで HEAD が動いたケースは今までどおり引き継げる」を、main が根拠ファイルの近くを変えたときに満たせない
- 案 1 の「載せ直し」は、前の HEAD の差分を新しい merge-base に当てる処理（`git merge-tree` か `git apply --3way` 相当）が要り、当たらないときの扱いがさらに要る。案 2 は判定 2 の既存のループで触れたファイルを集め、判定 4 で照合するだけで済む
- 案 2 の誤検出（PR 自身の commit が根拠ファイルに触れたが、意味の変わらない触れ方だった）は終了コード 4 → 判定役に回るだけで、引き継げない側か判定役に読ませる側に倒れる。判定役に渡す前後の HEAD の diff には行の移動がそのまま現れる

### 前後の diff が空の根拠ファイルは今までどおり飛ばす

「PR 自身の commit が根拠ファイルを変えて同じ中身に戻した」ケース（bats 既存、終了コード 0）は前後の diff が空なので、触れたかの照合の前に飛ばす。照合するのは前後の diff が空でなく、バイナリでも merge-base の NG でもなく、PR 自身の差分が同じだった根拠ファイルだけにする（`NG:` の優先と既存の出力を崩さない）。変えて戻した上に main が同じファイルを変えたときは終了コード 4 になる（Risks に書く）。

### merge commit は触れた commit に数えない

merge commit の第 1 親との差分には main から入った変更が含まれるので、触れたかの判定に merge commit を入れると、main が根拠ファイルを変えた取り込みがすべて終了コード 4 になり、受け入れ条件の「main の取り込みだけなら引き継げる」を壊す。merge commit の中での手入れ（衝突解消・衝突していないファイルへの手入れ）は判定 3 が `RESOLVED_OUTSIDE_ALLOWLIST=` で拾い、許可リストに無い根拠ファイルなら終了コード 3（PR 全体を見た取り直しのレビューが要る）になる。衝突解消が行の中身を変えたものは今までどおり PR 自身の差分の不一致で終了コード 4 になる。

### 触れたファイルの集め方

判定 2 のループで merge commit でない commit ごとに `git diff --no-renames --name-only <親> <commit>` を取り、触れたパスを集める。`git rev-list -- <path>` は履歴の単純化で main 側に TREESAME な merge の向こうの commit を落としうるので使わない。`--no-renames` で rename は消したパスと作ったパスの両方として数える（判定 3 の列挙と同じ扱い）。mode だけの変更も `--name-only` に出る。

## Risks / Trade-offs

- [PR 自身の commit が根拠ファイルに触れたが PR 自身の差分は同じ（変えて戻した上に main が同じファイルを変えた、など）が終了コード 4 になる] → 判定役に回り、`EVIDENCE_DIFF_LINES=` が上限以下なら「同じ」で引き継げる。頻度は見込みで低い（PR の修正が根拠ファイルに触れて元に戻し、かつ同じ周に main が同じファイルを変える組み合わせ）
- [merge commit の衝突解消が根拠ファイルの行を動かしただけのときは終了コード 4 にならない] → 許可リストに無い根拠ファイルなら終了コード 3 で PR 全体を見たレビューと条件④が残る。許可リストの CHANGELOG を根拠ファイルにして並べ直しで通るものは終了コード 0 のまま（今までと同じ。守備範囲の範囲外に書く）
- [終了コード 4 が増えて判定役の起動が増える] → 起きるのは PR 自身の commit が根拠ファイルに触れたときだけで、その多くは今までも PR 自身の差分が変わって終了コード 4 だった

## Migration Plan

スクリプトと 3-c の文言を同じ PR で入れる。出力の行の形と終了コードの集合は変わらないので、古い 3-c の文面と組み合わせても終了コード 4 は判定役か主に聞く側に倒れるだけ。戻すときはこの PR を revert する。
