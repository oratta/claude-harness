## Why

Claude Code は 1 回の API 応答を、中身のブロック（考えた内容・本文・ツール呼び出し）ごとに別の行として会話ログに書き、どの行にも `usage` を付ける。このうち `usage.output_tokens` は、`stop_reason`（`tool_use` / `end_turn` など）が付いた最後の行だけが応答の確定値で、それより前の行は書いた時点の途中の値（2〜8 など）のままである。cost-ledger は先頭の行だけを事実にするので、サブエージェントの出力トークンを途中の値で数え、額が実際より小さく出る。#693 の検証では haiku のサブエージェント 2 リクエストで、会話ログの 7 と 1 に対して本体（OpenTelemetry の `api_request`）の値は 217 と 255 だった。

規模は実ログで測った（2026-10-07、過去 30 日の会話ログ。コマンドは design の「調べたこと」）。

- サブエージェント側の出力トークン（モデル別。同じ requestId の先頭の行の値の合計 → `stop_reason` 付きの行の値の合計）: opus 4.85M → 30.2M、sonnet 5.96M → 34.1M、fable 0.20M → 3.77M、haiku 0.005M → 0.20M。メイン側は先頭の行から最後の行まで同じ値で、ずれない
- 本体のセッション合計（会話ログ末尾の `cost-state` の `modelUsage.outputTokens`）に対する、いま cost-ledger が数えている割合（サブエージェントを使ったセッション 559 本）: fable 26%、opus 48%、sonnet 23%、haiku 3%。`stop_reason` 付きの行の値を使うと fable 88%、opus 94%、sonnet 95%、haiku 35%
- 確定値が会話ログに無い応答がある。同じ requestId のどの行にも `stop_reason` が付かない応答で、サブエージェント側の応答の 7〜19%（haiku は検証で 7 と 1 のまま残った）。この応答の確定値は、サブエージェントのログにも親セッションのログにも無い（親の `toolUseResult.usage` は最後の 1 回分でしかなく、21/4,351 件にしか無い。`cost-state` はセッション合計で、1 応答の値に割れない）。これは直せないので、README に原因と規模を書く

台帳は書いた時点の値を焼き付けて append-only なので、会話ログ（既定 30 日で消える）が消える前に確定値を足さないと取り戻せない。

## What Changes

- 同じ `requestId` の後続行が `stop_reason` を持ち、その `output_tokens` が、その応答についてすでに台帳に数えた出力トークンより大きいとき、差分を出力トークンに持つ**補足の事実**を足す。入力・キャッシュのトークンは 0（同じ requestId の行どうしで一致している。サブエージェント側の 102,295 応答のうち違うのは 5 件）。`request_id` は今までどおり `<元の requestId>#<その行の uuid>`、`continuation: true`。同じ行が issue 番号か投稿の印も持つときは、同じ 1 つの補足の事実に載せる（1 行につき補足の事実は 1 つ）
- 「すでに数えた出力トークン」は、先頭の行の事実の出力と、その応答の補足の事実の出力の合計。台帳から作り直せる（控えを消しても同じ）。差分が 0 以下なら何も足さない。そのため、複製された会話ログ（resume・fork）から同じ確定行を読んでも、メイン側のように最初から確定値の応答でも、増えない
- 台帳の既存の行は書き換えない。既に台帳にある先頭の行（途中の値のもの）の取りこぼしは、会話ログが残る範囲で `ledger-sync --rescan` が補足の行を**追記**して直す（#695 と同じ手順）
- 確定値が無い応答（`stop_reason` 付きの行が無い）は、今までどおり先頭の行の値のまま。推定で埋めない。README に、直せないこと・原因・規模（実測）を書く
- 補足の事実はメッセージ数に数えない（#695 のまま）。金額と出力トークンの合計には、そのまま足される

## Capabilities

### New Capabilities
なし

### Modified Capabilities
- `cost-ledger-attribution`: 「行から抽出する事実」（出力トークンは応答の確定値であること）と「同じ応答の 2 行目以降の issue と投稿の印」（補足の事実が出力トークンの差分を持つこと）を変える
- `cost-ledger-persistence`: 台帳の行の定義（補足の事実が出力の差分を持つ）と「既存の取りこぼしは追記で補う」（確定値の取りこぼしを `--rescan` で補う）を変える
