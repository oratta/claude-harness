## ADDED Requirements

### Requirement: 仕分けの表はどの部品も漏らさず 1 行ずつ載せる

`docs/public-private-split.md` の仕分けの表は、`rules/*.md` の各ファイル、`output-styles/*.md` の各ファイル、`.claude-plugin/marketplace.json` の `plugins` に載る各プラグイン、リポジトリ直下の `scripts/` の各項目（ファイルとディレクトリ）を、それぞれ 1 行ずつ載せなければならない（MUST）。プラグインの hooks はそのプラグインの行に含める。

#### Scenario: すべての部品が表にある
- **WHEN** `rules/*.md`・`output-styles/*.md`・`marketplace.json` のプラグイン名・直下の `scripts/` の項目を列挙して表の部品の欄と突き合わせる
- **THEN** どの部品も表に 1 行ある

#### Scenario: 部品を足して表を直し忘れる
- **WHEN** `rules/` に新しいファイルを足し、表に行を足さない
- **THEN** `tests/public-private-split.bats` が落ちる

### Requirement: 各行は決めた分類と理由を持つ

表の各行の分類は「公開版」「個人版」「保留（#1123 の後）」のどれかでなければならない（MUST）。ただし 1 つのプラグインの中で行き先が割れるプラグインの行は「分割」とし、その直後にそのプラグインの部品（スキル・スクリプト・hook・スキル本文の節）ごとの行を置き、それぞれに 3 つのどれかを書かなければならない（MUST）。どの行も理由の欄が空であってはならない（MUST NOT）。理由は #1128 の判断の基準（公開版: 誰の環境でも意味がある道具・住人のふるまいに効くもの・営業で見せる動き。個人版: オーナーに固有の業務・アカウント・資格情報の置き場・固有名に依存するもの）のどれに当たるかが読めるように書く。

#### Scenario: 分類の値が決めた値だけである
- **WHEN** 表の分類の欄を読む
- **THEN** すべての値が「公開版」「個人版」「保留（#1123 の後）」「分割」のどれかで、「分割」の行の直後に部品の行が 1 行以上ある

#### Scenario: 理由が空の行がない
- **WHEN** 表の理由の欄を読む
- **THEN** 空の行がない

#### Scenario: 保留の行は何を見て決めるかを書く
- **WHEN** 分類が「保留（#1123 の後）」の行を読む
- **THEN** 理由の欄に、#1123 の結果のどこを見て公開版か個人版かを決めるかが書かれている

### Requirement: capability-registry の扱いを選ばなかった案とともに残す

`docs/public-private-split.md` は capability-registry をどう仕分けたかを、部品ごとの行き先と、選ばなかった案（丸ごと個人版・丸ごと公開版）とその理由とともに書かなければならない（MUST）。

#### Scenario: capability-registry の決定が読める
- **WHEN** 文書の capability-registry の行と説明を読む
- **THEN** browser-guard の hook・スキルの原則と CLI の索引・`fmtoken.sh`・1Password の索引・資格情報の階層の表のそれぞれの行き先と、選ばなかった案の理由が書かれている

### Requirement: 公開版に残る部品の固有記述を一覧にする

`docs/public-private-split.md` は、公開版に残る部品（「分割」の行で公開版になった部品を含む）の中の、固有名（オーナーのプロジェクト名・アカウント名・保管庫名・人名・オーナーのリポジトリ名）とオーナーの環境に依存する記述（オーナーの PC のパス・オーナーだけが持つ環境変数やサービスを前提にした記述）の一覧を持たなければならない（MUST）。一覧の各行は `<リポジトリ相対パス>:<行>`・種別（固有名／環境依存）・書かれている内容・直す issue（#1098 か #1105）を持つ。探すのに使った候補語も文書に書く。

#### Scenario: 一覧のパスは実在し公開版の部品に属する
- **WHEN** 一覧の各行のパスを確かめる
- **THEN** ファイルが実在し、表で公開版（または分割の中の公開版の部品）になっている部品に属する

#### Scenario: 候補語で取りこぼしを確かめられる
- **WHEN** 文書に書かれた候補語で公開版の部品を `grep` する
- **THEN** 当たった行は一覧に載っているか、載せない理由（書式の説明の例など）が文書の除外の基準で説明できる
