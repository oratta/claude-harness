## Context

親は `wait --watch-stopped --resolve <エピック>` を背景で掛け、上限（`cache_ttl_of` が 1 時間か不明なら 3000 秒、5 分なら 21600 秒）で `timeout` を受けると、手順 5 で同じ引数の `wait` を掛け直す。動いている子が全員主の返事待ちで止まり、その質問を主に上げ終えていても、この掛け直しは止まらない。止まりの検知（`detect_stopped`）・再開の検知（`resume_moved`）・声かけ（`keepalive_child`）・判断（`resolve_stopped`）はどれも `wait` のポーリングの中にある。今の main（#1554 の PR #1560、#1555 の PR #1558 を含む 2c7d4a6d）に合わせる。

## Goals / Non-Goals

**Goals:** 主に伝え済みの止まりだけが残るあいだ親の LLM を起こさない。12 時間で見張りを終える出口を作る。声かけの期限を同じ値にそろえる。待っているあいだに判断の材料が変わったら 1 回だけ判断し直す。

**Non-Goals:** 親が主と決めたことをエピック本文から引き取る仕組み（#1395）。作業中の子がいる `wait` の上限と掛け直し。子の側の止まり方（`references/epic-child-stop.md`）。

## Decisions

1. **「主に伝え済み」は子の記録の `told_uuid` に置く。** 親が手順 7・8 で止まりを主に上げる報告を出したあと、新しいサブコマンド `epic-dispatch.sh told <子> <止まりの uuid>` を呼ぶ。`told` は排他の中で、記録の `stop` が `stopped-seen`・`status` が `done` でない・`stop_uuid` が空でなく引数の uuid と同じ、を確かめてから `told_uuid`（その uuid）と `told_at`（UTC の時刻）を書く。uuid を引数で渡すのは、親が報告に使った止まり（`child-log --last` の `.stop_uuid`）と記録の止まりが違うとき（報告のあいだに子が別の発言で止まり直した）に、伝えていない止まりを伝え済みにしないため。
   - 記録を選んだ理由: 記録は子ごと 1 ファイルで、親が排他つきで書く先として既にある。`stop_uuid` と並べて持つので、止まりが変われば（`detect_stopped` が `stop_uuid` を書き換える）比較が外れ、伝え済みが自動で無効になる。`wait` はポーリングごとに記録を読んでいるので、読む先が増えない。
   - 採らなかった案: (a) 子 issue かエピックへのコメント。公開の issue に親の内部の印が並び、`wait` がポーリングごとにコメントを読む `gh` の呼び出しが増え、主や他人のコメントと見分ける規則も要る。(b) `--resolve` が子 issue に書く `親の判断: 主に上げる`。これは判断のモデルの結論で、親が主に報告した事実ではない（親は基準・委任でそのあと自分で通すことがあり、手順 7 の出し直しも拾えない）。(c) 親の会話ログから報告の発言を探す。発言の形に依存し、壊れやすい。
   - `told_uuid`・`told_at` は `done_inferred_at` と同じく任意の項目で、「読めない記録」の判定に加えない。文字列でなければ伝え済みでないとして読む（普通の待ちに倒れる）。`epic-state.sh` の検査は変えない。
   - `stop_uuid` が空の止まり（会話ログを読めなかった止まり）は `told` が `skipped <子> uuid-mismatch` で書かず、長い待ちに入らない（今の動きのまま）。
2. **長い待ちに入る条件。** `--watch-stopped` で位置引数の子が 1 件以上、`--interval` と上限がどちらも 0 より大きく、そのポーリングで出す行が無く（閉じた子・印・止まった子・unrecorded が無い）、失敗したポーリングでなく、位置引数の子の全員の記録が「伝え済みの止まり」（`stop` が `stopped-seen`・`status` が `done` でない・`stop_uuid` が空でなく `told_uuid` と同じ）のとき。一度入ったあとの失敗したポーリング（子 issue の取得の失敗・読めない記録など、今の `fails` に数えるもの）では、入った時刻を保ち、条件を判定し直さず、普通の上限の判定も `expired` の判定もしない（次の成功したポーリングで判定する）。失敗の数え方は今のまま（連続 3 回で `error gh <子>...` か `error workspaces` を exit 1）。上限を明示したとき（`--timeout`・`EPIC_DISPATCH_TIMEOUT`）も同じに扱う（手順 5 は `--timeout` を足さないので、明示は試験と手動の呼び出しだけ。待ちをやめる直前の `--timeout 0` の 1 回の確認は上限 0 なので入らない）。
3. **長い待ちの上限は、その `wait` の中で待ちに入ったときから測る。** 環境変数 `EPIC_DISPATCH_OWNER_WAIT_SEC`（0 以上の整数。既定 43200）。待ちに入っているポーリングでは普通の上限の判定をせず、「待ちに入ってからの経過 >= 上限」か「経過 + 間隔 > 上限」なら `expired <位置引数の子>...` を出して exit 0。成功したポーリングで条件から外れたら入った時刻を捨てる（もう一度入れば測り直す）。失敗したポーリングは条件から外れたことにしない（2 のとおり）。
   - 失敗で入った時刻を捨てない理由: 捨てると、長い待ちが普通の上限を過ぎたあとに `gh` が一度失敗しただけで普通の上限の判定に戻り、止まりが変わっていないのに `timeout` で親が起きる。失敗のあいだ判定を止めるだけにすれば、一時の失敗は次のポーリングで長い待ちに戻り、続く失敗は今の連続失敗の `error` で親に届くので、二つが混ざらない。
   - 採らなかった案: `told_at` から測る。起動し直した親は手順 7 で出し直して `told` を呼び直すので差は小さく、issue の文言（待ちに入ってから）にそろえるほうが説明しやすい。
   - `expired` を exit 0 にしたのは、親が対応する出来事の行（`closed`・`stopped` と同じ）だから。`timeout` の exit 2 と分けるので、手順 5 の掛け直しに誤って入らない。
4. **長い待ちから出たら、普通の上限の判定に戻す。** 止まりの uuid が変われば `stopped`、子 issue が閉じれば `closed` が、今までどおりそのポーリングで出る。主の返事が届いて子が動き出すと、`resume_moved` が記録を `resumed` に書き、条件から外れる。そのとき経過はふつう普通の上限を越えているので、そのポーリングで既存の `timeout` が出る。親は 60 分以上の再開の決まり（`epic.md` の時間分類）か、60 分未満なら手順 5 に従う。新しい行は足さない。
5. **判断し直しの引き金は材料の版。`updated_at` は読む回数を減らす前段にだけ使う。** `--resolve` があるときだけ働く。
   - 材料の版（以下「版」）は、判断のコマンド（`stop-judge.sh`）が読む材料のうち親自身の投稿を除いたものの要約（ハッシュ）とする。エピックと子 issue のそれぞれについて、本文と、投稿者が OWNER・MEMBER・COLLABORATOR のコメントのうち 1 行目が `親の判断: ` で始まらないものの `id` と `updated_at` の並び。`親の判断: ` で始まるコメントは `resolve_stopped` と完了の推定が書く親自身の投稿で、これを版に入れると判断が自分の投稿でもう一度引き金を引く。
   - 長い待ちに入ったポーリングで、エピックと各子の `updated_at` と版を読み、`updated_at` を「前段の基準」、版を「処理済みの版」として持つ。以後のポーリングでは `updated_at` だけを読み、前段の基準と同じなら何もしない。違えば版を読み、処理済みの版と同じなら（親自身の投稿・ラベル・判断の材料でないものの変化）前段の基準だけをその `updated_at` に進める。違えば判断にかける。
   - 判断にかける版は、判断の直前に読んだ版とする。判断のあと、処理済みの版をその「判断の直前に読んだ版」にし、前段の基準はその版と同じときに読んだ `updated_at` にする。判断のあとに読み直した値を基準にはしない。判断のあいだ（`stop-judge.sh` が材料を読んでからモデルの応答を待つあいだ）に主が本文やコメントを足すと、その更新は処理済みの版に入らないので、次のポーリングで版が違ってもう 1 回判断にかかる。判断のコメント（親自身の投稿）だけなら、次のポーリングで `updated_at` は違うが版は同じなので判断しない。
   - 判断の直前に読んでから `stop-judge.sh` が読むまでのあいだの更新は、判断に入るのに処理済みの版には入らないので、判断が 1 回余分に走る。取りこぼすより余分に判断するほうに倒す。
   - エピックの版が変われば全員、子の版が変わればその子だけを、`resolve_stopped` と同じ判断に 1 回かける。判断に渡す止まりの JSON は、`detect_stopped` と同じ切り詰めで記録の会話ログから作る（読めなければ JSON なしで呼ぶ。今の `--resolve` と同じ）。
   - 判断の結果: 通して記録できた・問いではない → 出力に何も足さない（子は動き出し、次のポーリング以降で 4 のとおり返る）。通して記録できなかった → `unrecorded` の行で返る。主に上げる・判断できなかった・送れなかった → 子 issue へのコメントは今までどおりで、`stopped` の行には入れない（主には伝え済みの同じ止まりなので、親を起こさない）。
   - `updated_at` と版を読む `gh` の失敗は、そのポーリングでは判断せず、基準も処理済みの版も変えず、失敗したポーリングにも数えない（`infer_done` の `gh` と同じ扱い）。
   - 採らなかった案: (a) `updated_at` だけを引き金にし、判断のあとに読み直した値を基準にする（前の版）。判断のあいだの主の更新まで処理済みになり、取りこぼす。(b) 判断の前の `updated_at` を基準にする。親自身の判断のコメントで `updated_at` が変わり、同じ判断を繰り返す。(c) 毎ポーリングで版を読む。本文と全コメントを毎回読む。`updated_at` が変わったときだけ読めば、長い待ちのあいだはほとんど読まない。
6. **声かけの期限も `EPIC_DISPATCH_OWNER_WAIT_SEC`。** `keepalive_candidate` の `86400` をこの値に置き換える。基点は今のまま `stop_at`（空なら停止の記録の作成時刻）。理由の語 `expired` はそのまま使い、意味を「止まりから上限以上」に直す。値の誤り（0 以上の整数でない）は、`wait` が `--watch-stopped` のときに待つ前に確かめて使い方を出す。
7. **`epic.md` の親の動き。** 手順 8（主に上げる報告、マージ待ちの子・PR トークン上限の子で主に上げる場合を含む）と手順 7（起動し直した親が主の返事待ちの子を出し直す）で、主に報告を出したら、2 に戻る前に上げた子ごとに `told <子> <止まりの uuid>` を呼ぶ。`expired` で起こされたら、経過は 60 分を越えているので時間分類の 60 分以上の決まりに従ってエピックに再開の記録を残し、主には 1 通だけ「見張りを止めた。子のタブで答えたら `/develop <エピック番号>` で親を再開する」と伝えて `wait` を掛けずに終える。「待ちをやめてよい条件」に (f) として足し、やめる直前の (1)(2) の確認は要らない（止まった子が残ることが分かっている）。

## Risks / Trade-offs

- 親が `told` を呼び忘れると、今までどおり 46 分ごとに起きる（悪くはならない）。
- 長い待ちのあいだに主が親のタブで答えたとき、親は主の発言で起きて `reply` で送る。背景の `wait` はそのあと子の再開で `timeout` を返し、親の最後のリクエストは新しいので手順 5 で掛け直す。
- 判断し直しで「通す」になると、子は動き出して `wait` は `timeout` で返り、親は 60 分以上の決まりで起動し直しの案内をする（issue の「既にある 60 分以上の再開の決まりに任せる」のとおり）。
- `told` から `wait` を掛けるまでのあいだの材料の変化は基準に入ってしまい、判断し直しの引き金にならない。親は `told` の直後に `wait` を掛けるので、間は数秒で受け入れる。
- 主が `親の判断: ` で始まるコメントを書くと、版に入らず判断し直しの引き金にならない。親の投稿と見分ける印がこの行頭しかないので受け入れる。

## 守備範囲

- 入力は子の記録（`stop`・`status`・`stop_uuid`・`told_uuid`）、子 issue とエピックの `state`・`updated_at`・本文・コメント、会話ログ。拾いたい誤りは、伝え済みの止まりだけが残るのに親が 46 分ごとに起きること（一時の取得の失敗で起きることを含む）、主の返事が来ないまま見張りが終わらないこと、伝えていない止まりを伝え済みとして黙って待つこと、材料が変わらないのに判断を繰り返すこと（親自身の判断のコメントで繰り返すことを含む）、判断のあいだに主が足した材料を処理済みにして取りこぼすこと。
- 次は通してよく、止めない: 判断の直前に読んでから `stop-judge.sh` が読むまでの更新で判断が 1 回余分に走ること／主が `親の判断: ` で始まるコメントを書いて判断し直しにならないこと／エピックへのコメントがその子に関係なくても全員の判断が 1 回余分に走ること／長い待ちの上限が `wait` を掛け直すたびに測り直されること／`told` の呼び忘れで今の起き方に戻ること／時刻が秒の単位でずれること。
- 次の穴は残りうるが、塞ぎ切ることを完了条件にしない: 親が `told` を呼び忘れる・間違った uuid で呼ぶ（`told` は記録と一致しなければ書かないが、親が報告に使わなかった止まりの uuid を渡すことまでは見分けない）／判断の材料に、版に入れていない箇所（タイトル・ラベル・配役表など）の変化がある。完了条件は受け入れ条件と tasks の bats が通ることである。
