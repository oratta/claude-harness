## ADDED Requirements

### Requirement: 段 C の子の行で足す前に、その子が作業中かを確かめる

G は、段 C の表の子の行（同じエピックの子 issue の受け入れ条件に足す）で足す前に、その子 issue が作業中かを `in-progress-issue-scope` の判定で確かめなければならない（MUST）。作業中なら、受け入れ条件に足さず、この指摘だけの新しい子 issue を同じエピックの子として作り、本文に作業中の子の番号を書く（MUST）。主には聞かない（MUST NOT。G は指摘の扱いを主に聞かない決まりである）。作業中でなければ、これまでどおり受け入れ条件に足す。

主が切り出すと答えた止める指摘の置き場所は、段 C の表を通る経路なので、同じ確認を通る（MUST）。

#### Scenario: 同じ場所を直す子が作業中

- **WHEN** 段 C の表が子 #A の受け入れ条件に足すと示し、#A に open の PR があり、その本文に `Closes #A` がある
- **THEN** G は #A の受け入れ条件に足さず、この指摘だけの新しい子 issue を同じエピックの子として作り、本文に #A の番号を書く

#### Scenario: 同じ場所を直す子が作業中でない

- **WHEN** 段 C の表が子 #A の受け入れ条件に足すと示し、#A に `develop 開始` か `実行モード:` の行があるコメントも、開いた紐づく PR も無い
- **THEN** G は #A の受け入れ条件に指摘を足す

#### Scenario: 主が切り出すと答えた欠陥を直す子が作業中

- **WHEN** エピックに属する PR で、主が切り出すと答えた止める指摘について、段 C の表がある子の受け入れ条件に足すと示し、その子が作業中である
- **THEN** G はその子に足さず、新しい子 issue を作り、PR コメントに「follow-up issue に切った」と書いて URL を添える（追跡は切れない）

### Requirement: 作業中かの確かめ方は gh の 2 回の呼び出しにする

G は、子 issue が作業中かを `gh issue view <番号> -R <owner>/<name> --json comments`（`develop 開始` か `実行モード:` の行があるコメント）と `gh pr list -R <owner>/<name> --state open --search "<番号> in:body" --json url,body`（本文に `Closes` / `Fixes` / `Refs #<番号>`、大文字小文字不問、がある PR）で確かめなければならない（MUST）。issue の本文だけで作業中でないと判断してはならない（MUST NOT）。判定のためのスクリプトは作らない（MUST NOT）。

#### Scenario: 本文に作業中と書かれていない

- **WHEN** 子 issue の本文に作業中である旨が無い
- **THEN** G は上の 2 つの呼び出しで確かめてから足すかを決める
