## Why

bats のテスト本文の途中に置いた `[[ ... ]]` は、bash 4.1 未満（macOS 標準の `/bin/bash` 3.2.57 など）ではローカル実行時に偽でもテストを落とさない（実測で確認）。落ちるのは本文の最後の 1 文だけなので、複数のアサーションを並べたテストのうち途中の `[[ ]]` は「書いたのに検査されていない」状態になりうる。cost-ledger は #273 で `|| return 1` を付けて対処済みだが、それ以外の 24 本の bats ファイルには同じ穴が残っている。

## What Changes

- 対象 24 ファイル（`git ls-files '*.bats' ':(exclude)_longruns/'` のうち行頭 `[[ ` を含み、`plugins/cost-ledger/` 配下（#273 で対応済み）を除いたもの）で、**単独の文として置かれた `[[ ... ]]` はすべて（本文中の位置を問わず、最後の文も含む）** `|| return 1` を付ける。cost-ledger が #273 で採った形をそのまま踏襲し、新しい依存（bats-assert 等）は導入しない。「最後の文」の判定を無くし全数ガードにすることで、grep 1本で機械照合できるようにする（詳細は design.md「Decisions」）。
- ガードの有無を bash のバージョンに依存せず機械的に検査する常設テストを 1 件追加する（スコープ検査 grep が 0 件であることを確認する）。あわせて、この穴が bash のバージョン依存で実在したことを示す実行時の実演テストも追加する（詳細は design.md）。

## Capabilities

### New Capabilities
- `bats-assertion-guard`: bats テスト本文中の単独文 `[[ ... ]]` アサーションが偽のとき必ずテストを失敗させるための規約（`|| return 1` を付ける）と、その規約を機械的に検査する常設テストを定義する。

### Modified Capabilities
（既存 capability の要件変更なし。今回のテスト修正はいずれも「書いたとおりに検査されるようにする」修正であり、外部から観測される振る舞いの変更ではない）

## Impact

- 対象: `plugins/*/tests/*.bats`・`tests/*.bats` のうち 24 ファイル（`plugins/cost-ledger/` は対象外）。issue #284 本文にある「26 本」との差分は次の実測の内訳による: `git ls-files '*.bats' | xargs grep -lE '^[[:space:]]*\[\[ '`（行頭 `[[ ` を含む bats ファイル）は現在 32 本ある。このうち `_longruns/_archive/` 配下の過去実験の 3 本を除くと 29 本、さらに `plugins/cost-ledger/` の 5 本（#273 で対応済み）を除くと 24 本になる。
- 新規依存なし。既存の `bash scripts/test.sh` 実行方式・bats のバージョンも変更しない。
- ガードを付けた結果として現在 green だが実際は壊れていたアサーションが露呈し落ちるテストが出た場合は、それは実装側の欠陥なので別途 issue を切って対応する（本 change の受け入れ条件外）。
