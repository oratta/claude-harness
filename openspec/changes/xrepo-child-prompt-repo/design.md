# Design

## Context

最初の入力の形に依存しているところは 3 つある。

1. `owner-reply-check.sh` の `DISPATCH_ARGS`（`<command-args>\s*#\d+\s*（エピック #\d+ の子。`）。親が打った起動の指示を主の発言として数えないための判定
2. `epic-child-state.sh` の `startup()`。子のターン状態のフックが、起動の指示を `sender: startup` と分類する。子の側は `/develop (<repo>#|#)<N>` を既に受けるが、エピックの側は `（エピック #<E> の子。` しか受けない。エピックの repo は `エピックのリポジトリ X。` の句から読み、無ければ「子とエピックが同じ repo」と見なす
3. tmux の部品の届いたかの確かめ（送った文の引数の先頭 40 文字で会話ログを照合する）。文字列の比較なので、形が変わっても働く

## Goals / Non-Goals

Goals:
- 別のリポジトリの子の最初の入力と起動し直しの指示で、子もエピックもリポジトリ付きで書かれる
- 主の発言の判定と送り手の分類が、新しい形を起動の指示として扱う
- 同じリポジトリの子の入力は 1 文字も変わらない

Non-Goals:
- 同じリポジトリの子の表記を変えること
- 返事の頭（`親エピック #<E>（<repo>）の判断…`）を変えること

## Decisions

### 両方の番号にリポジトリを付け、`エピックのリポジトリ` の句を外す（採用）

受け入れ条件の例「エピック oratta/claude-harness#1810 の子」に合わせる。句を残すと同じリポジトリ名が 2 回出て、子の側の名前と並ばない分かりにくさが残るので外す。

- launch: `prompt="/develop $crepo#$num （エピック $erepo#$epic の子。親ワークツリー $parent から ${lname_label} で起動）"`
- 起動し直し: `prompt="/develop $(es_get "$rec" repo)#$(es_get "$rec" number) （エピック ${xrepo_epic} の子。返事を受けて起動し直し） $msg"`（`xrepo_epic` は記録の `epic`、`<owner>/<repo>#<E>`）

### `DISPATCH_ARGS` を広げる

`<command-args>\s*(?:[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+)?#\d+\s*（エピック (?:[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+)?#\d+ の子。` にする。番号だけの形は今までどおり当たる。

### `startup()` はエピックの側の `<repo>#` も受け、旧形の句も受け続ける

正規表現を `^/develop (?:([^\s#]+)#|#)([0-9]+) （エピック (?:([^\s#]+)#|#)([0-9]+) の子。([^）]*)）` にする。エピックの repo は、エピック側に付いた repo、無ければ `エピックのリポジトリ` の句、どちらも無ければ子と同じ repo の順で決める。旧形の句を受け続けるのは、この変更の前の親が起動した子が、会話ログの最初の入力に旧形を持っているため。

### 退けた案: 子の番号だけに repo を付け、エピックは句のまま

子が読み違える元は消えるが、受け入れ条件の例「エピック oratta/claude-harness#1810 の子」を満たさない。

## Risks / Trade-offs

- 起動形を読むほかの部品が、この 3 つのほかにあると見落とす。`エピック #` と `/develop #` を grep して、`epic-child-state.sh`・`owner-reply-check.sh`・`child-log-read.py` のほかに無いことを確かめた。`child-log-read.py` は `/develop` で始まる行を丸ごと主の発言から外すので、形によらない
