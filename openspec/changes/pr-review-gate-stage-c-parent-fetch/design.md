## Context

段 C の親の取得を直す。応答は `{"number":896,"repository_url":"https://api.github.com/repos/genetta-inc/flatmate"}`、親が無いときは HTTP 404 `No parent issue found`（終了コード 1）。

## Decisions

- **404 だけを「属さない」と読む**: 親が無いことを示す信号は 404 だけで、それ以外の失敗は親が有るかどうかを教えない。候補探しの「終了コードが 0 でないとき」の倒し方（失敗を空と読まない・1 回だけやり直す・仕分けの PR コメントに書く）に揃える。捨てた案: すべての失敗を「属さない」と読む（現状。完了条件に効く指摘が失われる）／無限にやり直す（レート制限で止まる。歯止めは 1 回）
- **失敗が続いたときは段 E で捨てない**: 段 C を飛ばす経路（段 D・段 E）のうち、段 E の費用対効果の判定で「捨てる」に当たると、本来エピックに効く指摘が消える。段 B を「範囲で成り立つ」で通った指摘は issue にする。エピックの子に足せないので、エピックの外の新しい issue にする
- **別リポジトリの親**: `--epic` は `$R` の番号を取るスクリプトの引数なので、親のリポジトリが `$R` と違うときは付けない。候補は全部 `other` と読む。エピックの本文と `## 条件の答え` は親のリポジトリで読み書きする
- **triage.md と main の spec を食い違わせない方法**: delta spec は MODIFIED で要件の全文を持つ。archive は実装と同じ PR で行うので、triage.md と main の spec が同じ commit に載る。両方に同じ語句（404・1 回やり直・`repository_url`・`--epic` なし・全候補を `other`・段 E で捨てず）を入れ、`pr-review-gate-skill.bats` の段 C の検査に足して食い違いを検出する

## Risks

- 親の取得が 404 以外で恒常的に失敗する環境では、段 C を飛ばしたうえで段 E の issue が増える。仕分けの PR コメントに失敗が残るので気づける
