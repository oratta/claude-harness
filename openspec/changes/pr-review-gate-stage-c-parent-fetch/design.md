## Context

段 C の親の取得を直す。応答は `{"number":896,"repository_url":"https://api.github.com/repos/genetta-inc/flatmate"}`、親が無いときは HTTP 404 `No parent issue found`（終了コード 1）。

## Decisions

- **404 だけを「属さない」と読む**: 親が無いことを示す信号は 404 だけで、それ以外の失敗は親が有るかどうかを教えない。候補探しの「終了コードが 0 でないとき」の倒し方（失敗を空と読まない・1 回だけやり直す・仕分けの PR コメントに書く）に揃える。捨てた案: すべての失敗を「属さない」と読む（現状。完了条件に効く指摘が失われる）／無限にやり直す（レート制限で止まる。歯止めは 1 回）
- **失敗が続いたときの動き（一意に決める）**: 段 C を飛ばし、候補探しは `--epic` なし、段 B の範囲は記録先の issue で読み、「範囲で成り立つ」に当たった指摘は段 D も段 E も通さず、エピックの外の新しい issue にする。段 D を通さない理由: 段 D の参考コメントで終わると、同じ場所を直す issue があるときに指摘が受け入れ条件に入らず、issue の「何が起きるか」が挙げた流れ（参考コメントか捨てるに流れる）がそのまま残るため。段 E を通さない理由: 親が取れず完了条件に効くかを判定できない指摘を、費用対効果で捨てるのは同じ誤りになるため。エピックの子には足せない（親が分からない）ので、外の新しい issue にする
- **親の取得は候補探しの前**: 候補探しは段 C の前に 1 回だけ走り、`--epic` の有無は親で決まる。そのため親の取得と親のリポジトリの判定を候補探しの前に置き、既存の要件 2 つ（候補探しの `--epic` の MUST、段 D・段 E の「捨てて」の MUST）も同じ delta で MODIFIED にする。triage.md ではこのため段 C の段落のほか、表の段 D・段 E の行と候補探しの `--epic` の箇条と段 E の段落の 4 か所に、失敗時の例外または条件を 1 句ずつ足す（受け入れ条件 2 の「段 E で捨てず」に必要な最小の範囲。ほかの段の言い回しは直さない）
- **404 の見分け**: 404 も 5xx も終了コードは 1 なので、出力に `HTTP 404` を含むかで分ける。`No parent issue found` 以外の 404（記録先 issue 自体が見えない等）も「親が無い」と読む。区別すると新しい判定が増えるため、守備範囲で通ることを許す
- **別リポジトリの親**: `--epic` は `$R` の番号を取るスクリプトの引数なので、親のリポジトリが `<owner>/<name>` と小文字にそろえて違うときは付けない。候補は全部 `other` と読む。エピックの本文と `## 条件の答え` は親のリポジトリで読み書きする。子に足す操作は `repos/<親のリポジトリ>/issues/<親の番号>/sub_issues` に対して行い（形は `references/epic.md` の別リポジトリの子の扱いに倣う）、新しい issue は `<owner>/<name>` に作る。すでに親の子である `<owner>/<name>` の issue が `other` になる点は、確かめをしない（sub-issue の一覧を突き合わせる新しい部品になり、受け入れ条件 1 の範囲を超える。実例の少ない経路で、拒否されたら仕分けの PR コメントに書く）
- **権限**: 親のリポジトリの読み書きはそのリポジトリへのトークンの権限が要る。読めない・書けないときは親の取得の失敗と同じに扱う（エピックに属さないと読まず、仕分けの PR コメントに書く）。比較は小文字にそろえる
- **triage.md と main の spec を食い違わせない方法**: delta spec は MODIFIED で 3 つの要件（候補探し・段 C・段 D と段 E）の全文を持つ。「同じ commit」は、PR 内の commit でなく squash マージ後の main の 1 commit と読む（実装は (3a)、archive は (3b) で別の commit になり、`auto-merge.yml` の既定が squash なので、マージ後は 1 commit に載る）。両方に同じ語句（`HTTP 404`・`1 回だけやり直し`・`repository_url`・`--epic` を付けず・全候補を `other`・`sub_issues`・`段 D の参考コメントで済ませず`）を入れ、`pr-review-gate-skill.bats` で triage.md と spec（change の delta があればそれ、なければ main の spec）の両方がこれらの語句を持つことを検査する（既存の 827-828 行と同じ形）
- **他の場所へ広げない**: `## 条件の答え` や「エピックの本文」を書いた triage.md:92・`reviewer-brief.md:9`・`gate-runner.md:114`・develop の `SKILL.md:73` は触らない。受け入れ条件 1 は「段 C に書く」で、段 C が親の取得の正本になる。ほかは「エピック」を段 C の定義で読む。触ると #580 などの範囲と重なる

## Risks

- 親の取得が 404 以外で恒常的に失敗する環境では、段 C を飛ばしたうえで段 E の issue が増える。仕分けの PR コメントに失敗が残るので気づける
