# Design: agent-pr-issue-body-format

## Context

自律開発ループが書く PR / issue 本文には構造化ルールが無く、人間の承認判断に必要な情報（何が変わる / 何が壊れうる / どう確かめる）が欠けている。一方で本文は別セッションの LLM も引き継ぎ資料として読むため、人間向け平易化で技術文脈を削ると LLM 側の理解が欠ける。この二重読者の両立が設計の核心（issue #47。外部調査の判断材料 5 点も同 issue に記録済み）。

## Goals / Non-Goals

**Goals**
- 冒頭 5 行で承認可否が判断できる PR 本文の型を新設し、loops プラグインの正本（reference）として配線する
- issue 本文に承認判断・優先度判断用の 2 節を追加する（既存の LLM 作業指示 4 節は壊さない）
- 形骸化（「特になし」の羅列）と誇張（検証できない効能）への歯止めを型の中に組み込む

**Non-Goals**
- flatmate 本体・workspace 各リポジトリの生成済み `docs/agent-loop.md` への反映（install 再実行が必要。issue #47 チェックリストに残置）
- flatmate 本体への `.github/PULL_REQUEST_TEMPLATE.md` 新設（D-4。別リポジトリ）
- `wt-setup` の Draft PR テンプレ変更（用途が worktree バックアップで異なるため据え置き）
- PR コメントのフォーマット規制（承認要求コメントの 3 行ルールは reference 内に軽く言及するに留める）

## Decisions

1. **二重読者は「書き分け」ではなく「順序と粒度」で解く**。人間向け節を上に置き、LLM 向け（実装メモ）を下に置くが折りたたまない。`<details>` は再生成可能な出力（検証ログ）専用。
   - 却下した代案: 「人間向けを上・LLM 向けを `<details>`」の二層化 — LLM が折りたたみを読み飛ばす実装があり、避けたいはずの理解欠落を自分で作るため。
   - 却下した代案: 人間版/機械版の二重管理（Git trailer 等の機械可読メタデータ、D-2）— 「同じ情報を 2 回書かない」原則と衝突し乖離の温床になるため初版不採用。
2. **正本は `plugins/loops/references/pr-body-format.md` に一本化**（D-1）。テンプレート（agent-loop-template.md）・スキル（issueify / dev-agent-install）・コマンド（work-issue.md）は正本を参照または最小限の複製に留める。dev-workflow 側の効果範囲もこの参照で担保する。
3. **軽量モードはエージェント自己判断＋理由 1 行明記**（D-3、ユーザー決定）。ラベル基盤（`size:small` の全導入先波及）や行数閾値（数行でも危険な変更の誤判定）を避け、理由行を導入後評価の監査点にする。判断に迷う場合はフル 5 節（安全側）。
4. **誇張防止は主張と検証手順の 1:1 紐付けで行う**（D-5）。「動作確認ポイントで検証できないことは効能として書かない」を制約として明記し、チェックリストの各項目を上流セクションと対応させる。
5. **issue 側は既存 4 節を壊さず先頭に 2 節追加**。既存 4 節は LLM の作業指示として機能実績があるため変更しない。追加 2 節（これで何が変わるか / やらないとどうなるか・今のコスト）は着手優先度と承認の判断材料に特化する。

## Risks / Trade-offs

- [形骸化: 欄が増えて「特になし」が並ぶ] → 軽量モード＋ネガティブ欄の根拠必須＋導入後に実 PR 3 本で評価し節を削る運用（issue #47 チェックリスト）
- [誇張: 埋めるために効能を盛る] → D-5 の 1:1 紐付け制約
- [トークン増: 全 PR で本文生成が重くなる] → セクション行数上限＋軽量モード
- [生成済み `docs/agent-loop.md` とのドリフト] → テンプレート更新のみ本 change で行い、反映手段（install 再実行 or 手動 diff）は issue #47 で別途判断

## Migration Plan

1. reference 新設 → テンプレート・スキル・コマンドの参照差し替え → plugin.json バージョン更新（loops 0.17.0 / dev-workflow 1.5.1）
2. 導入先への反映は各リポジトリで `/loops:dev-agent-install` 再実行（本 change のスコープ外）
3. ロールバック: reference への参照を旧一文に戻すだけで復元可能（生成物の後方互換は問題にならない。既存 PR 本文は遡って書き換えない）

## Open Questions

なし（D-1〜D-5 は proposal に記録済み。導入後評価で節を削る判断は運用フェーズ）
