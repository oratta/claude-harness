# Design

## Context

動機は proposal.md の Why。今の判定は `risk-carryover-check.sh` の終了コード（1・4・3・0 の優先順）と、`stages/hold.md` 手順 3-c の条件 1〜4 の組み合わせで決まる。main を取り込む merge commit だけが積まれた場合でも、スクリプトは衝突解消を許可リストと照らして終了コード 3 を返し、衝突解消が根拠ファイルの PR の変更を変えれば終了コード 4 を返す。3-c は終了コード 3 に「新しい HEAD で PR 全体を見た周のレビュー」を、終了コード 4 に判定役の `引き継ぎ判定: 同じ` を求め、どの終了コードでも条件 4（新しい HEAD のレビューから組み立てた宣言本文が前と文の一致で同一）を求める。

スクリプトはすでに `PR_COMMITS=`（前 HEAD のあとに積まれた merge commit でない commit の件数）を数えて出している。main の取り込みだけかどうかはこの値と、履歴の判定（判定 1・2）に `NG:` が無いことで決まる。

## Goals / Non-Goals

**Goals:**

- main の取り込みだけで HEAD が動いた PR は、衝突解消の中身・根拠ファイルの差分・取り直しのレビューの範囲・新しい HEAD の宣言本文によらず、主に聞かずに許容を引き継ぐ
- 判定はスクリプトの終了コード 0 の 1 つで表し、ゲートが「`PR_COMMITS=0` の終了コード 0」を読めば条件 1 と条件 4 を見ずに済むようにする

**Non-Goals:**

- PR 自身の commit（merge commit でないもの）が 1 件以上あるときの判定。終了コード 4 と判定役、終了コード 3 と PR 全体を見た取り直しのレビュー、条件 4 は今のまま
- 衝突解消の正しさの確認。取り直しのレビュー（差分限定でよい）と CI が見るもので、引き継ぎの条件にしない
- 条件 2（前の宣言に根拠ファイルの行がある）と条件 3（元の回答の真正性の確かめ直し）。許容が本当に主のものかは、HEAD の動き方と関係が無いので残す
- 終了コード 4 の判定役・判定の記録・引き継いだ宣言の 4 行の書式・`needs-carryover-judge` の return

## Decisions

### 「main の取り込みだけ」をスクリプトの終了コード 0 で表す

`PR_COMMITS=0` で履歴の `NG:` が無いとき、スクリプトが `CARRYOVER=yes`・終了コード 0 を返す。ゲートは終了コード 0 と `PR_COMMITS=0` の組を読み、条件 4 を外す。

- 採らなかった案: スクリプトは今のまま 3・4 を返し、3-c の側で「`PR_COMMITS=0` なら 3・4 も引き継げる」と読み替える。ゲートの文に終了コードごとの例外が増え、受け入れ条件（main の取り込みだけなら終了コード 0）を満たさない
- 採らなかった案: 新しい終了コードや出力の行（例 `MAIN_ONLY=yes`）を足す。`PR_COMMITS=0` が同じ情報を既に出しており、3-c の呼び方のブロックと引き継ぎの根拠の行に書く値を増やさずに済む

### main の取り込みだけのときは、根拠ファイルの PR 自身の差分を比べない

`PR_COMMITS=0` のときは判定 4（根拠ファイルの前後比較と `EVIDENCE_MAIN_ONLY=` / `EVIDENCE_PR_CHANGED=` の分類）を回さない。そのため、そこから出るバイナリの根拠ファイルの `NG:` と、merge-base が 1 つに決まらないときの `NG:` も出ない。根拠ファイルがどちらの HEAD にも無いときの終了コード 2（引数の不備）は残す。

- 理由: 主の判断は「main の取り込みだけなら根拠ファイルの差分によらず引き継ぐ」で、比べた結果をどれも使わない。比べると、使わない結果のために `NG:`（終了コード 1）で止まる入力が残る（バイナリの根拠ファイルを main が変えた、criss-cross merge で merge-base が 2 つになった）
- 採らなかった案: 比べて `EVIDENCE_*` の行を記録のために出し、終了コードには効かせない。行が出るのに終了コードに効かない状態は、3-c を読む G が「終了コード 4 相当の行がある」と取り違える元になる
- 記録のために残すもの: `MAIN_MERGES=`・`PR_COMMITS=`・`RESOLVED_FILES=`・`RESOLVED_OUTSIDE_ALLOWLIST=`。衝突解消の一覧は判定の計算で既に得ており、引き継ぎの根拠の行に書ける

### 履歴の判定（判定 1・2）は main の取り込みだけでも残す

前 HEAD が新しい HEAD の祖先でない（rebase・force-push）、merge commit が 2 親でない、第 2 親が base の祖先でない（main 以外のブランチの merge）、第 1 親が PR の履歴の外、のどれかなら今どおり終了コード 1。

- 理由: これらは「main の取り込みだけ」であることそのものを確かめる判定で、外すと「main の取り込みだけ」と言えなくなる

### 引き継いだ宣言の本文は前の宣言の本文のまま

条件 4 を外すので、新しい HEAD のレビューから組み立てた本文が前と違っても引き継ぐ。投稿する宣言の本文は、今の 3-c の書き方どおり前の宣言の本文を新しい `対象 HEAD:` で出し直したものにする（新しく組み立てた本文は使わない）。

- 理由: 宣言は主が許容した中身の記録で、引き継ぎを重ねても主が見た本文から離れないようにする。main の取り込みだけなら PR 自身の差分は変わっておらず、新しく組み立てた本文との違いは main から来た変更かレビューの書きぶりの揺れで、どちらも主の判断で聞き直さないもの
- 採らなかった案: 新しく組み立てた本文で投稿する。次の引き継ぎ（PR 自身の commit が積まれたとき）の条件 4 の比較の基準が、主の見ていない本文に置き換わる

### `PR_COMMITS` が 1 以上のときは今のまま

issue の範囲は「前 HEAD から新しい HEAD までが main の取り込みの merge commit だけ」で、PR 自身の commit があるときの扱いは変えないと issue に書かれている。issue の本文には「衝突解消の正しさは引き継ぎの条件にしない」という一般的な文もあるが、外す 3 つの条件はどれも main の取り込みだけの場合として書かれているので、PR 自身の commit と許可リスト外の衝突解消が重なるときの終了コード 3 は残す（狭い方に読む。広げるかは別の issue で決める）。

## Risks / Trade-offs

- [main の取り込みの衝突解消が PR の変更の意味を変えても、主に聞き直さない] → 主の判断で受け入れたリスク。取り直しのレビュー（差分限定でよい）と CI が衝突解消を見る。PR 自身の commit で根拠ファイルを変えたときは今どおり終了コード 4 と判定役に回る
- [merge commit の中に、衝突解消を装った手入れ（衝突していないファイルへの変更）を入れても終了コード 0 になる] → `RESOLVED_OUTSIDE_ALLOWLIST=` の行は出続けるので記録には残る。取り直しのレビューは新しい HEAD で回る。PR を作るのは主の配下のエージェントで、悪意のある投入は守備範囲の外
- [main の取り込みのあとのレビューで新しいリスクが見つかっても、宣言本文は前のまま] → main から来た変更のリスクは main 側のゲートを通っている（今の守備範囲の「範囲外」にも、main 側の変更が PR のリスクの前提を変えることは主の決定で聞き直さないとある）。新しい HEAD のレビュー自体は省かないので、指摘は修正の対象として残る
- [既存の bats のうち、`PR_COMMITS=0` で終了コード 3・4・1 を期待していたテストが落ちる] → 終了コード 3・4 の意味を確かめているテストは、前 HEAD のあとに根拠ファイルに触れない PR 自身の commit を 1 件積む形に直して意味を保つ。main の取り込みだけの場合を確かめるテストは終了コード 0 の期待に直す

## Migration Plan

スクリプトと文書の変更だけで、データの移行は無い。戻すときは PR を revert する（戻すと、main の取り込みだけの場合も条件付きの引き継ぎに戻るだけで、主に聞く側に倒れる）。
