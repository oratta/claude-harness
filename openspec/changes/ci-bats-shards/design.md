## Context

- `.github/workflows/ci.yml` のジョブは `lint`（名前 `shellcheck`）と `test`（名前 `bats suites`）の 2 つ。`test` は bats を導入し、`scripts/test.sh`（全スイートを bats 1 回で実行）と `scripts/test-auto-merge-workflow.sh`（自動マージの安全不変条件の検査。素の sh で bats に乗らない）を順に走らせる
- `.github/workflows/auto-merge.yml` は、PR の HEAD の check-run のうち `REQUIRED_CHECKS`（`shellcheck` / `bats suites`）の名前に一致するものを探し、それぞれ最新の run の conclusion が `success` のときだけマージに進む。名前の一致だけが CI green の判定根拠である
- `scripts/test-auto-merge-workflow.sh` の検査 (2) は、`REQUIRED_CHECKS` の名前の集合と `ci.yml` の `^    name: ` の行の集合が完全一致することを求める。目的は 2 つ: 必須チェック名がジョブ名とずれて永久にマージされなくなるのを防ぐことと、`ci.yml` にジョブを足したのに必須チェックへ入れ忘れ、そのジョブが落ちてもマージされる状態を防ぐこと
- `scripts/test.sh` は `git ls-files -- '*.bats' ':(exclude)_longruns/'` の一覧（133 ファイル）から、位置引数のフィルタ（部分一致・OR）と `TEST_EXCLUDE`（部分一致・OR。除外は件数を表示する）で絞り、実行するスイートを表示してから bats を 1 回呼ぶ。対象が空なら exit 1
- `.github/workflows/` は自動マージの聖域パスなので、この変更の PR は人間がマージする

## Goals / Non-Goals

**Goals:**

- PR の CI の開始から全チェック完了までの時間を縮める（合否の線は引かず、変更の前後を 5 回ずつ測って記録する）
- どのジョブにも入らないスイート・二重に走るスイートが出ない分け方にし、それをテストで確かめる
- スイートを足しても CI の設定を書き換えずに済むようにする
- 自動マージが「bats が全部通った」ことを今と同じ名前 `bats suites` で判定できるようにする
- ローカルの `scripts/test.sh` の使い方を変えない

**Non-Goals:**

- bats の `--jobs`（1 つのジョブの中での並列実行）は使わない。GNU parallel の導入が要るうえ、`scripts/test.sh` の残留プロセス検査が parallel のプロセスを残留と見なすおそれがある（issue #990 の備考）
- 所要時間でジョブを均等に割ることはしない（下の「分け方」）
- `plugins/dev-workflow/templates/auto-merge/` のテンプレートは変えない
- `auto-merge.yml` は変えない（`REQUIRED_CHECKS` を含む）

## Decisions

### 1. 分割指定は環境変数 `TEST_SHARD=k/N` で受ける

`scripts/test.sh` の位置引数は既にフィルタの意味で使われており、`TEST_EXCLUDE` と `TEST_RESIDUAL_GRACE` は環境変数で受けている。同じ形にそろえて `TEST_SHARD=k/N`（k は 1 始まり、1 ≦ k ≦ N）とする。未設定か空文字なら分割しない。

- 退けた案「オプション `--shard k/N` を足す」: 位置引数がフィルタなので、オプション解析を新しく持ち込むことになり、`--shard` で始まる文字列をフィルタとして渡していた呼び出しの意味も変わる
- 形式が `k/N` でない値・0・k > N は、実行せずに exit 1 でメッセージを出す。既定に倒して全件を走らせると、CI の設定を書き間違えたときに各ジョブが全件を実行して「遅いだけで通る」状態になり、気づけない

### 2. 分け方は「`git ls-files` の一覧の i 番目（1 始まり）は、(i − 1) mod N + 1 番目の組に入る」

一覧の並びは `git ls-files` の出力順（追跡ファイルのパス順で、チェックアウトが同じなら決まる）。組の割り当ては**フィルタと `TEST_EXCLUDE` を当てる前の一覧**に対して決め、そのあとで既存のフィルタと除外を当てる。

- 各ファイルは必ず 1 つの組にだけ入るので、漏れと重なりが構造上起きない。スイートを足すと自動でどこかの組に入る
- 割り当てをフィルタの前に決めると、あるファイルがどの組に入るかがフィルタや除外の指定で変わらない。`TEST_EXCLUDE` で除外されたスイートは、それが属する組の実行でだけ「skipped」と数えられる（全ジョブで重ねて数えない）
- 退けた案「ファイルごとの所要時間を記録して均等に割る」: 計測値のファイルを保守する手間が増える。issue #990 の実測で遅いテストに偏りが無い（上位 30 件で全体の 25%）ので、順番に配るだけで大きくは偏らないと見込む。偏りは変更後の 5 回の計測でジョブごとの所要時間として見え、問題があれば別の issue で扱う
- 退けた案「ディレクトリ（プラグイン）ごとにジョブを分ける」: プラグインを足すたびに `ci.yml` を書き換える必要があり、入れ忘れたスイートが走らなくなる
- 分けた結果、その組の対象が 1 件も無いとき（N がファイル数より大きい場合など）は、既存の「対象が空なら exit 1」をそのまま当てる。何も実行せずに成功にはしない

### 3. CI は matrix で分け、分割数は `ci.yml` の 1 か所から決まる形にする

`test` ジョブを matrix（`shard: [1, 2, 3, 4]`）にし、各ジョブが `TEST_SHARD: <shard>/<全体の数>` で `scripts/test.sh` を呼ぶ。`fail-fast: false` にして、1 つの組が落ちても残りの組を最後まで走らせる（1 回の CI で落ちるテストを全部見られるようにする）。

matrix の要素の並びと `TEST_SHARD` の分母がずれると（要素が 1〜3 しか無いのに分母が 4、など）走らない組が出る。これは `ci.yml` を読むテストで確かめる: matrix の要素がちょうど 1〜N の整数で、`TEST_SHARD` の分母が N に等しいこと。

分割数は 4 を出発点にし、変更後の計測を見て決める（issue #990 の備考）。数を変えるときに書き換えるのは `ci.yml` の matrix と分母だけで、テストは `ci.yml` から N を読むので書き換えない。

### 4. 結果をまとめるジョブが `bats suites` の名前を引き継ぐ

分けたジョブを `needs` で待つジョブを 1 つ置き、名前を `bats suites` にする。`if: always()` を付け、`needs` の全ジョブの result が `success` のときだけ成功、それ以外（`failure` / `cancelled` / `skipped`）は exit 1 にする。このジョブは checkout せず、result の判定だけを行う。

- `if: always()` を付けない場合、分けたジョブが落ちるとこのジョブは skipped になる。`auto-merge.yml` は conclusion が `success` のときだけ進むのでマージはされないが、チェックの一覧で「落ちた」ではなく「飛ばされた」と見え、issue #990 の「1 つでも失敗・取り消し・スキップなら失敗にする」を満たさない
- 退けた案「`REQUIRED_CHECKS` に分けたジョブの名前を全部並べる」: `auto-merge.yml` も聖域で、分割数を変えるたびに 2 つの聖域ファイルを同時に直すことになる。入れ忘れた組が落ちてもマージされる状態も作れてしまう
- 分けたジョブの名前は `bats suites` で始めない別の名前にする（`auto-merge.yml` は名前の完全一致で探すので誤って拾われることは無いが、チェックの一覧で見分けやすくする）

### 5. `scripts/test-auto-merge-workflow.sh` の検査 (2) を「全ジョブが必須チェックか、必須チェックが待つジョブ」に置き換える

分けたジョブを足すと、今の「名前の集合が完全一致」は落ちる。次の 3 つを全部満たすことを求める形に置き換える。

1. `REQUIRED_CHECKS` の名前それぞれが、`ci.yml` のちょうど 1 つのジョブの `name:` に一致する
2. `ci.yml` の全ジョブに `name:` がある
3. `ci.yml` のジョブのうち `name:` が `REQUIRED_CHECKS` に無いものは、`REQUIRED_CHECKS` に名前があるジョブの `needs:` にジョブ ID が挙がっている

これで今の検査の 2 つの目的（名前のずれの検知・足したジョブの入れ忘れの検知）がどちらも残る。`needs:` は 1 行の形（`needs: a` か `needs: [a, b]`）だけを読み、読めない形（複数行のリストなど）は検査の失敗にする。

- 退けた案「`REQUIRED_CHECKS` が `ci.yml` のジョブ名の部分集合であればよい、に緩める」: ジョブを足して必須チェックにも `needs` にも入れ忘れたとき、そのジョブが落ちてもマージされる。今の検査が防いでいる事故が素通りする
- 退けた案「分けたジョブに `name:` を書かず、今の検査（`^    name: ` の行だけを拾う）をそのまま通す」: 検査を直さずに済むが、検査に見えないジョブを作って通しているだけで、入れ忘れの検知が効かなくなる
- 「まとめるジョブが `needs` の結果を実際に判定しているか」はこの検査では見ない（`ci.yml` の構造の検査は新しい bats スイートが受け持ち、実際の挙動は 1 件わざと落とした PR で確かめる）
- 置き換えるのはこのリポジトリの `scripts/test-auto-merge-workflow.sh` だけ。配布テンプレートの同名ファイルは既にこのリポジトリの写しと内容が異なり、テンプレートは展開先のジョブが必須チェックと 1 対 1 である前提のまま残す

### 6. `auto-merge workflow invariants` のステップは `shellcheck` のジョブへ移す

このステップは bats を使わない素の sh で、いまは `test` ジョブの最後に置かれている。`test` を matrix にするとそのままでは 4 回走る。

- `shellcheck` のジョブに移すと、bats の導入を待たずに走り、落ちたときは必須チェック `shellcheck` が失敗になる（自動マージが止まる点は今と同じ）
- 退けた案「まとめるジョブで走らせる」: まとめるジョブに checkout が要るようになり、分けたジョブが全部終わるまで不変条件の検査の結果が出ない
- 退けた案「1 番目の組でだけ走らせる（`if: matrix.shard == 1`）」: 動くが、bats の組のうち 1 つだけ役割が違う形になり、分割数を変えるときに読み違えやすい
- 受け入れることになる点: `shellcheck` という名前のチェックが shellcheck 以外の検査も含むようになる。ステップ名は `auto-merge workflow invariants` のまま残すので、落ちたときはステップ名で見分ける

### 7. テストは新しいスイート `tests/ci-bats-shards.bats` に置く

issue #990 は「既存の test.sh 向けスイートに足す」としているが、既存の `tests/test-sh-residual-guard.bats` は残留プロセス検査の専用で、setup と teardown が背景プロセスの回収に特化している。分割のテストは `ci.yml` と `scripts/test-auto-merge-workflow.sh` も読むので、別のスイートにする。

実物のリポジトリで「全部の組の合計が全件と一致する」を確かめるには、内側で本物の bats を走らせずにスイートの一覧だけを得る必要がある。`scripts/test.sh` は実行前に対象を表示するので、何もせず exit 0 する `bats` の代役を PATH の先頭に置いて各組を実行し、表示された一覧を集める（`scripts/test.sh` に一覧だけを出す指定は足さない）。

## Risks / Trade-offs

- [組ごとの所要時間が偏り、いちばん遅い組が全体の時間を決める] → 変更後の 5 回の計測で組ごとの所要時間も記録する。偏りが大きければ分割数の見直しか割り方の変更を別の issue にする。起きる根拠: 順番に配るだけで所要時間を見ていない。頻度: スイートの追加・削除のたびに割り当てが 1 つずつずれるので、偏りは固定されず変動する
- [各組が checkout と bats の導入（約 15 秒）を重ねて行う] → 公開リポジトリなのでランナーの費用は増えない。待ち時間への影響は 1 組ぶんの 15 秒で、今と同じ
- [スイート間で共有している状態に依存するテストがあると、別の組に分かれて落ちる] → 起きる根拠は今のところ無い（各スイートは `BATS_TEST_TMPDIR` を使う作りで、ローカルではフィルタ付きで単独実行されている）。起きた場合は分割後の最初の CI で落ちるので、その場で該当スイートを直す
- [`needs:` を 1 行の形でしか読まない] → 複数行で書くと検査が落ちるので、黙って通ることは無い。落ちたときのメッセージに「1 行の形で書く」と出す

## Migration Plan

1. この PR をマージすると、次の PR から CI が分割後の形で走る。`REQUIRED_CHECKS` は変えないので、`auto-merge.yml` 側の作業は無い
2. 戻すときは PR を revert する（`ci.yml` が元の 1 ジョブに戻り、`scripts/test.sh` は `TEST_SHARD` 未指定で全件を実行する）
3. この PR より前に作られて開いたままの PR は、古い `ci.yml` で `bats suites` を 1 ジョブとして報告する。名前が同じなので自動マージの判定はそのまま働く
