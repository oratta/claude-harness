#### Scenario: リスク許容リンクの真正性確認が存在する

### Requirement: 引き継ぎの元は真正性確認済みの主の直接の回答に限る

pr-review-gate SKILL.md は、引き継ぎで主の許容を捏造できないように、次を条件として書かなければならない（SHALL）: ①前の HEAD の宣言に `主の回答: 許容` または `主の回答: 許容（引き継ぎ）` の行と `真正性確認: 済` の行がある ②引き継いだ宣言の回答リンクは、主が許容を述べた元の直接の回答を指し、引き継ぎの記録（エージェントが書いた宣言コメント）を指さない。引き継ぎが 2 回以上続いても元の直接の回答のままとする ③引き継ぐたびに、元の回答リンクに対して手順 5 の真正性確認をやり直し、新しい宣言に `真正性確認: 済` を追記する。元の直接の回答は会話で受けた回答（`会話で受領` の記録）でもよい（SHALL）。その場合、②の回答リンクの代わりに元の記録の `会話で受領（セッション <セッション ID> / <日時>）原文: <原文>` をそのまま書き、③の真正性確認のやり直しは、元の記録のセッション ID と原文で `owner-reply-check.sh` を回し直して終了コード 0 と同じ timestamp の一致を確かめることとする（MUST）。終了コードが 0 でなければ（会話ログを読めない PC での exit 2 を含む）引き継がず、手順 6 で主に聞かなければならない（MUST）。

#### Scenario: 捏造防止の条件が書かれている

- **WHEN** SKILL.md の引き継ぎの手順を読む
- **THEN** 元の回答が真正性確認済みであること・回答リンクが元の直接の回答を指すこと・引き継ぐたびに真正性確認をやり直すことが条件として書かれている

#### Scenario: 引き継ぎが続く

- **WHEN** 引き継いだ宣言の HEAD から、さらに main の取り込みで HEAD が動いた
- **THEN** 新しい宣言の回答リンクは最初の直接の回答を指し、その回答に対して真正性確認をやり直す

#### Scenario: 元の回答が会話で受けたもの

- **WHEN** 前の HEAD の宣言の回答が `会話で受領` の記録で、引き継ぎの他の条件を満たす
- **THEN** G は元の記録のセッション ID と原文で `owner-reply-check.sh` を回し直し、終了コード 0 なら元の記録を書き写して引き継ぎ、0 でなければ手順 6 で主に聞く

### Requirement: 合格条件は会話で受けた許容を正式な回答として受け付ける

`skills/pr-review-gate/stages/pass.md` の手順 5 は、主の許容の回答の形として、従来の回答リンクに加えて会話で受けた回答（`会話で受領`）を持たなければならない（SHALL）。会話で受けた回答は、手順 3 の宣言コメントに `主の回答: 許容 — 会話で受領（セッション <セッション ID> / <日時>）原文: <原文>` の 1 行で追記しなければならない（MUST。`<日時>` は会話ログのその発言の timestamp の値）。この形の真正性確認は `plugins/dev-workflow/scripts/owner-reply-check.sh <セッション ID> <原文>` の終了コード 0 とし、G は記録の日時と同じ timestamp を持つ `MATCH:` の行の全文で許容の意思を読まなければならない（MUST。記録の原文だけで読まない）。確認の記録は `真正性確認: 済 — 確認者 <エージェント名> / <日時>（owner-reply-check.sh 終了コード 0）` とする（SHALL）。終了コードが 1 または 2 のとき、または同じ timestamp の `MATCH:` が無いときは合格させてはならない（MUST NOT）。exit 2（会話ログを読めない PC を含む）のときは、PR のコメントか、ゲートと同じ PC での `/develop <記録先> 許容する` で受け直す（SHALL）。手順 5 の合格条件の表は、この形を許容済みとして扱わなければならない（SHALL）。Discord など外部サービスの回答リンクの目視確認と、GitHub コメントの `gh api` による投稿者の実測は変えない（MUST）。

#### Scenario: 記録の書式と真正性確認が書かれている

- **WHEN** `grep -n "会話で受領" plugins/dev-workflow/skills/pr-review-gate/stages/pass.md` を実行する
- **THEN** 1 行以上が出て、手順 5 に記録の書式（セッション ID・日時・原文）と `owner-reply-check.sh` の終了コード 0 を真正性確認とする旨がある

#### Scenario: スクリプトが通さない

- **WHEN** `owner-reply-check.sh` が exit 1 か exit 2 を返す
- **THEN** G は合格処理をせず、exit 2 なら PR のコメントかゲートと同じ PC での `/develop` で受け直す
