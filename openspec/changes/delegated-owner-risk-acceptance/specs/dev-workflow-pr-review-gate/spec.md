## ADDED Requirements

### Requirement: 合格条件は主の委任で親経由に受けた許容を、委任の確認と記録で確かめて受け付ける

`skills/pr-review-gate/stages/pass.md` の手順 5 は、主の許容の回答の形に、主の委任で親経由に受けた回答を持たなければならない（SHALL）。宣言コメントに `主の回答: 許容 — 親経由で受領（委任）（親セッション <ID> / 委任の確認 <uuid> / <日時>）委任の記録: <URL> 停止の記録: <URL> 原文: <確認の発言の全文>` を追記する（MUST。`<日時>` と `<原文>` は `--delegated` の `MATCH:` 行のもの）。合格条件の表はこの形を、Scenario の真正性確認を通したときだけ許容済みとして扱う（MUST）。

#### Scenario: 委任の形の真正性確認

- **WHEN** G が `親経由で受領（委任）` の記録を確かめる
- **THEN** G は、停止の記録が記録先の最新の `子の停止: 主の返事待ち`（投稿者が `OWNER`・`MEMBER`・`COLLABORATOR`）で宣言コメントより後に作られていること、委任の記録がエピックの issue のコメントで 1〜4 行目が develop の定型の文ちょうど・投稿者が同じ 3 種・エピックの最新の `主の委任:` で始まるコメント・`lastEditedAt` が null であること、エピックが開いていて記録先がその子であること、停止の記録の `推奨:` が `許容` で始まること、`owner-reply-check.sh --delegated` が exit 0 で `MATCH:` の timestamp が記録の日時と同じで全文から任せる意思が読めること、をすべて確かめ、`真正性確認: 済 — 確認者 <エージェント名> / <日時>（owner-reply-check.sh --delegated 終了コード 0）` を追記する

#### Scenario: どれかを満たさなければ合格させない

- **WHEN** `--delegated` が exit 1（`not-found`・`not-owner`・`not-after`・`not-asked`・`not-direct`・`not-before`）か exit 2 を返す、または委任の記録・停止の記録の確認のどれかを満たさない（取り消し済み・記録の編集・エピックが閉じている・推奨が許容でないを含む）
- **THEN** G は合格処理をせず、手順 6 に戻して主に子のタブで直接返事を打ってもらうよう頼む

#### Scenario: 委任の確認の前の名指しの許容は委任の形で通らない

- **WHEN** 記録の uuid が委任の記録より前の主の発言（例 別の子だけを名指しした `1034は許容`）を指す
- **THEN** `--delegated` が `REASON=not-after` で落ち、G は合格させない

### Requirement: 委任の形の許容の引き継ぎは委任がまだ有効なときだけ行う

`skills/pr-review-gate/stages/hold.md` の手順 3-c は、前の宣言の回答が `親経由で受領（委任）` の記録のとき、元の記録の値で `--delegated` と委任の記録・停止の記録の確認を引き継ぎの時点でやり直し、すべて通るときだけ元の記録を書き写して引き継がなければならない（MUST）。取り消し済み・新しい委任の記録がある・エピックが閉じたときは引き継がない（MUST NOT）。手順 6 の復帰手順の表は、委任の形の記録を追記してから手順 5 の真正性確認に進むことを書く（MUST）。

#### Scenario: 取り消し後は引き継がない

- **WHEN** 前の宣言の回答が `親経由で受領（委任）` で、HEAD が動いたあとにエピックの最新の `主の委任:` で始まるコメントが `主の委任: 取り消し`
- **THEN** G は引き継がず、手順 6 で主に聞き直す

#### Scenario: 引き継いだ宣言の書式

- **WHEN** 委任の形の回答を引き継ぐ
- **THEN** 引き継いだ宣言の 1 行目は `主の回答: 許容（引き継ぎ） — 親経由で受領（委任）（親セッション … / 委任の確認 … / …）委任の記録: … 停止の記録: … 原文: …` の形になる
