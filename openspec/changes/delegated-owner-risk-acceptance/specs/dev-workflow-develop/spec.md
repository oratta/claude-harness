## ADDED Requirements

### Requirement: 親は主の委任を、定型の委任の記録への主の直接の確認で受ける

`references/epic.md` は、別セッション方式の親が、主が親のタブで子のリスク許容を任せる旨を述べたとき、その発言だけを委任として扱わず（MUST NOT）、エピックの issue に定型の委任の記録を投稿し、本文にその URL と範囲・期間の文を書いて、この報告の直後に別の発言を挟まずに親のタブで答えるよう主に問うことを書かなければならない（MUST）。主がその直後に答えた発言を委任の確認とする。確認の全文から任せる意思が読めないときは委任を使わない（MUST）。

委任の記録の書式は次のとおりで、1〜4 行目はこの文字列ちょうど（`<E>` はエピックの番号）とする（MUST）。

```
主の委任: リスク許容
エピック: #<E>
範囲: このエピックの子が pr-review-gate で求めるリスク許容のうち、子の停止の記録の推奨が「許容する」のもの。聖域の変更・破壊的な操作・マージの承認・不許容は含まない
期間: この記録への主の確認の発言から、このエピックに `主の委任:` で始まる次のコメントが付くか、エピックが閉じるまで
きっかけ: <主が任せる旨を述べた発言の全文。無ければ なし>
```

#### Scenario: 主の自由な委任の発言を受けたとき

- **WHEN** 主が親のタブで「このエピックの子の許容は全部答えて」と述べる
- **THEN** 親は委任の記録をエピックに投稿し、本文に記録の URL と範囲・期間の文を書いて主に確認を問い、主の直後の答えを受けるまで委任で返事を送らない

#### Scenario: 確認の前に別の発言が挟まったとき

- **WHEN** 親の問いのあとに主が別の件を話してから「任せる」と答える
- **THEN** 親は問いを本文で出し直してから確認を受け直す（子の `--delegated` は `not-direct` で落ちるため）

### Requirement: 主の委任は取り消しと新しい記録とエピックの終わりで切れる

`references/epic.md` は、主が委任の取り消しを述べたら、親がエピックに 1 行目 `主の委任: 取り消し` のコメントを投稿し、以後は委任で返事を送らないことを書かなければならない（MUST）。委任が効くのは、エピックの `OWNER`・`MEMBER`・`COLLABORATOR` が投稿した最新の `主の委任:` で始まるコメントがその委任の記録で、エピックが開いているあいだだけとする（MUST）。取り消しは主本人の確認を求めない（範囲を狭める向きにしか働かないため）。

#### Scenario: 取り消しのあとは委任で送らない

- **WHEN** エピックの最新の `主の委任:` で始まるコメントが `主の委任: 取り消し`
- **THEN** 親は止まった子を今どおり主に上げ、委任で返事を送らない

### Requirement: 親は有効な委任があり子の推奨が許容のときだけ、委任で許容を送る

`references/epic.md` の手順 8 は、止まった子について次のすべてを満たすときだけ、主に上げずに `epic-dispatch.sh reply --as owner` で `許容する（主の委任による。停止の記録: <URL>） [主の委任: セッション <親のセッション ID> / uuid <確認の uuid> / 記録 <委任の記録の URL>]` を送ることを書かなければならない（MUST）: 委任が有効／子がそのエピックの子／停止の記録が確認より後／子の PR が `主のリスク許容が必要` で止まっている／停止の記録の `推奨:` が `許容` で始まる。送ったらエピックに `主の委任で送った: 子 #<N> <停止の記録の URL>` の 1 行を残す（MUST）。

#### Scenario: 推奨が許容でない止まりは主に上げる

- **WHEN** 有効な委任があるが、子の停止の記録の `推奨:` が `許容しない` で始まる、または止まった理由がマージ待ち・実機操作・方針の選び直し
- **THEN** 親は委任で送らず、今どおり手順 8 の形で主に上げる

#### Scenario: 委任で送った件をエピックに残す

- **WHEN** 親が委任で `reply --as owner` を送り、出力が `sent` か `relaunched`
- **THEN** エピックに `主の委任で送った: 子 #<N> <停止の記録の URL>` の 1 行を投稿する（`親の判断:` では始めない）

### Requirement: 子は委任の返事を確かめてから G に渡す

`references/epic-child-stop.md` の「親から届いた返事」は、末尾が `[主の委任: セッション <ID> / uuid <uuid> / 記録 <URL>]` の返事を受けたら、子が `--delegated <ID> <uuid> <委任の記録の作成日時> <URL> <最新の停止の記録の作成日時>` を回し、exit 0 で全文から任せる意思が読め、委任の記録の確認（Scenario のとおり）をすべて通したときだけ、保留の解除の G に値を渡すことを書かなければならない（MUST）。通らなければ G を起こさず、主に子のタブでの返事を理由付きで頼む（MUST）。

#### Scenario: 委任の記録を GitHub で確かめる

- **WHEN** 子が委任の返事を受け、`--delegated` が exit 0 を返す
- **THEN** 子は、記録がエピックの issue のコメントで 1〜4 行目が定型の文ちょうど、投稿者が `OWNER`・`MEMBER`・`COLLABORATOR`、エピックの最新の `主の委任:` で始まるコメント、`lastEditedAt` が null、エピックが開いている、自分の記録先がそのエピックの子、自分の最新の停止の記録の `推奨:` が `許容` で始まる、をすべて確かめてから G に渡す

#### Scenario: 確かめられない委任の返事では G を起こさない

- **WHEN** `--delegated` が exit 0 でない（`REASON=not-after` などで exit 1、または exit 2）か、委任の記録の確認のどれかを満たさない
- **THEN** 子は G を起こさず、止まる前の記録と印を残してから、主に子のタブでの返事を、確かめられなかった理由（`REASON=` の値か満たさなかった確認）を添えて頼む

#### Scenario: 主の発言の添え書きの経路は変わらない

- **WHEN** 末尾が `[主の発言: セッション <ID> / uuid <uuid>]` の返事を受ける
- **THEN** 子は今どおり `--relayed` で確かめる（`--delegated` を使わない）
