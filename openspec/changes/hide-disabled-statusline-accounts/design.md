## Context

`statusline.sh` は登録簿の全 Claude スロットを配列に保持し、現在は全登録数で複数スロット表示を決め、全ラベルから列幅を求める。非 active のオフスロットは `off` の行を追加する。Codex helper はオフ時に認証・キャッシュへ進まず、描画側へ `off` のセンチネルを返す。#1112 は表示だけを変え、#976 の active 例外と取得停止を維持する。#1006 は同じ statusline README の登録節と dev-workflow README のコマンド例を直す。

## Goals / Non-Goals

**Goals:** 非 active のオフスロットとオフの Codex を表示から除き、残る Claude スロットだけで複数表示と列幅を決める。既定アカウントを先に登録できる、貼って動く README 手順にする。

**Non-Goals:** 登録簿の形、オフの判定、自動選択、使用量取得、リセット権の表示、使用率・経過率の計算を変えない。インストール済みの `~/.claude/statusline.sh` を直接書き換えない。

## Decisions

1. **active を決めてから表示対象数を決める。** active の判定にはオフを含む登録簿の全スロットを使う。その後、active またはオンの Claude スロットだけを表示対象とし、対象数が 2 以上なら複数表示にする。これによりオフの active スロットはライブ値で残り、A が active・B がオフなら A は従来の 1 スロット表示に戻る。登録簿を先にフィルタして active を決める案は、オフで使用中のアカウントを見失うので採らない。
2. **表示対象の名前だけで列幅を決める。** 複数表示の場合も、非 active のオフスロットは名前列とセッション記録の突き合わせから外す。Codex 行が存在すればその名前も幅に含める。非表示のラベルに合わせて余白を残す案は、行を消したのにレイアウトが変わらないため採らない。
3. **Codex helper の `off` センチネルは内部契約として残す。** `statusline.sh` は helper の結果が `off` のとき、列幅の算出より前に Codex の描画行を空にする。helper を空出力へ変更する案は、取得停止の単体テストと既存の内部契約を広く変更するため採らない。既存の `STATUSLINE_CODEX=0` は従来どおり helper を起動しない。
4. **README のコードブロックをシェル単位で完結させる。** dev-workflow の例は定義済み `CLAUDE_HARNESS_SCRIPTS` を明示して呼ぶ。statusline の別ブロックは `$SCRIPTS` の前のブロックへの依存をなくす。既定アカウントの `accounts-init.sh --id a --label A` を `add b` より前に置き、別の既存アカウントの登録例には新しい id を使う。

## Risks / Trade-offs

- オフの B を非表示にすると、A だけが残る場合の名前列・active 目印が消える。これは今回の要望に沿うが、旧レイアウトを前提にした表示比較は更新する。active が B に変われば A と B の 2 行分に戻ることをテストする。
- Codex helper の単体出力は引き続き `off` だが、最終表示には出ない。helper と描画の責務差を仕様とテストに明記する。
- 古いインストール済みコピーはそのままなので、反映には `/statusline:setup` の再実行が必要。実機確認の結果は親エピックへ記録する。

## Migration Plan

リポジトリのコードと README を更新後、利用者が `/statusline:setup` を再実行してステータスラインのコピーを更新する。戻す必要があれば、この変更のコードと仕様の差分を戻して setup を再実行する。登録簿の移行は不要。
