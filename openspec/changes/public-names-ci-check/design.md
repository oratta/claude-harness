## Context

`tests/public-private-split.bats` の #1168 の検索は、検索範囲（`NONDEV_SCOPE`、dev-workflow の公開版のファイル、dev-workflow の 7 ファイルと 2 ファイル）ごとに正規表現で grep し、許可リスト（`ファイル|行に含まれる固定の文字列|基準` の配列）に載った行を除く。許可リストの鮮度は「固定の文字列がファイルに残っているか」で見る。共有スクリプト `forbidden-words-check.sh` は、ファイル一覧を標準入力、`--root`・`--dict`・`--allow` を引数で受け、辞書の語（固定文字列・大文字小文字を区別しない）を本文とパス名に当て、allow の恒久の書式 `<path>:<語>:=<固定の文字列>` を打ち消しに使い、打ち消さない行を「何も打ち消していない」違反にする。この change は前者を後者の呼び出しに置き換える。範囲の決定は呼び出し側（bats）の責務のまま残す。

## Decisions

### 1. 辞書の置き場と分け方: 語の群ごとの小さなファイルを `tests/public-names/dict/` に置く

検索範囲ごとに必要な語が違う（dev-workflow の公開版全体は `moko` だけ、7 ファイルは `new-resident` と `flatmate`、2 ファイルは `CLAUDE_HARNESS_DEV_DIR`）。共有スクリプトは 1 回の呼び出しに 1 つの一覧と辞書の連結を渡す形なので、範囲ごとに必要な語だけを連結して渡す。1 呼び出し用の辞書を丸ごと作ると同じ語が複数の辞書に重複するため、語の群ごとに分け、各語が 1 か所にだけ書かれるようにする。

| 辞書のファイル | 語 |
|---|---|
| `moko.txt` | `moko` |
| `other-projects.txt` | `suimei`、`uranai`、`shukan`、`sns-autopilot` |
| `flatmate.txt` | `flatmate` |
| `owner-pc-path.txt` | `/Users/oratta` |
| `new-resident.txt` | `new-resident` |
| `dev-dir-env.txt` | `CLAUDE_HARNESS_DEV_DIR` |

呼び出し（名前は bats の中の呼び出しの名前。allow は呼び出しごとに 1 本）:

| 呼び出し | 一覧 | 辞書 | allow |
|---|---|---|---|
| nondev | `NONDEV_SCOPE` の公開版のファイル（段階化したコピー。後述 3） | moko・other-projects・flatmate・owner-pc-path | `allow/nondev.txt` |
| nondev-pc-path | 同上 | owner-pc-path | なし |
| devwf-moko | dev-workflow の公開版のファイル | moko | なし |
| devwf-flatmate | 7 ファイル | new-resident・flatmate | なし |
| devwf-dev-dir | 2 ファイル | dev-dir-env | なし |

辞書の語は、今の `tests/public-private-split.bats` にすでに書かれている語だけ。公開側の辞書が新しい固有名の一覧にならないよう、新たな語を足さない（`plugins/dev-workflow/docs/forbidden-words-check.md` の方針どおり）。個人版の辞書は個人版（#1129）が引数で足す。`tests/` は検索範囲の外（`NONDEV_SCOPE` にも dev-workflow の公開版のファイルにも入らない。後者は `plugins/dev-workflow/` の下だけを数える）なので、辞書が自分自身に当たることはない。

dev-workflow の呼び出しの allow は今 0 件なので持たない。1 件目を足すときは `allow/<呼び出しの名前>.txt` を作り、その呼び出しにだけ渡す（1 本の allow を複数の呼び出しに渡すと、別の呼び出しの語で打ち消されない行が「何も打ち消していない」違反になる）。

選ばなかった案: 呼び出しごとに辞書を 1 本ずつ作る（語が複数の辞書に重複し、語を足し忘れる）。辞書を 1 本にして範囲をすべて同じ語で検査する（検索範囲が広がり、今の main で 0 件の保証が変わる）。

### 2. 許可リストの移し方: 各行に語を足して恒久の書式にし、基準はコメント行に書く

今の許可リストの 3 つ組 `ファイル|固定の文字列|基準` は、行ごとに「その行に当たる辞書の語」を足して `<path>:<語>:=<固定の文字列>` にする。固定の文字列はそのまま使うので、許す行の精度（そのファイルの、その文字列を含む行だけ）は変わらない。基準（出典・互換）は各行の直前の `#` のコメント行に書く（スクリプトは検査しない。足りるかは人のレビューが見る）。固定の文字列が `:` や `#` を含む行（`flatmate#320: find -path` など）は、第 3 欄が 2 つ目の `:` から行末までなので、そのまま書ける。許可リストの鮮度の検査（固定の文字列がファイルに残っているか）は、スクリプトの「何も打ち消していない」の違反が引き継ぐ。移し前より厳しく、固定の文字列がファイルにあっても、その行に語が当たらなければ違反になる。

移すとき、固定の文字列が 2 つの語を含む行は、語ごとに 1 行を書く（1 行が 2 語に当たると、語ごとに 1 件の当たりが出るため）。実際に書く行は implement で今の main の当たりから起こす（tasks の 2.3）。

### 3. 範囲の決定は bats に残し、個人版の節だけは段階化したコピーに空行を置く

共有スクリプトは渡されたファイルを丸ごと検査するので、#1168 が「個人版に決まる節」として検索から外している capability-registry の `SKILL.md` の「表記規約」「資格情報の階層」の節（`awk` で飛ばしていた）は、そのまま渡すと当たりが出る。そこで nondev の呼び出しでは、対象のファイルを一時ディレクトリに同じ相対パスでコピーし、`capability-registry/SKILL.md` だけ飛ばす節の行を空行に置き換える（行番号は保たれる。恒久の許可は行の中身で絞るので影響しない）。一時ディレクトリを `--root` にする。dev-workflow の呼び出しは範囲が個人版の節を含まないので、リポジトリをそのまま `--root` にする。ファイル一覧の選定（`git ls-files` と除外のパターン）は今の `nondev_files`・`devwf_public_files` をそのまま使う。

### 4. 置き換えの前後で保つ性質と、変わる 1 点

置き換えの前後で次の 4 つの検出結果を変えない（tasks 4.2 で旧 bats〈origin/main〉と新 bats を同じ操作で比べる）。

- 今の main で当たりが 0 件（許可の行を除く）
- 辞書の語を含む行を公開版の部品に 1 行書き足すと落ちる
- 許可された行は通る
- 同じファイルの別の行に同じ語を書き足すと落ちる

変わる 1 点は、照合が大文字小文字を区別しなくなること。旧 bats の正規表現は大文字小文字を区別したので `Uranai` を拾わなかったが、共有スクリプトは拾う。今の main で新しく当たる行は 2 行（`plugins/worktree/scripts/wt-setup.sh` の `（Uranai で実証）` と `plugins/worktree/skills/wt-setup/SKILL.md` の `（Uranai で実証）`）。どちらも観測した事実の出典として名前を挙げる行で、既存の許可の行と同じ種類（基準「出典」）なので、許可に載せる（文を書き換える案は、書き換えた文の良し悪しを検査が保証しないことと、出典を消す作業が #1168 の範囲を超えることから採らない）。パス名の当たりは今の main で 0 件。

もう 1 点、旧 spec の本文は一部の語を一部の範囲にだけ当てると書いていたが、旧 bats の実際の検索は `NONDEV_SCOPE` 全体に 7 語すべて（`flatmate`・`/Users/oratta` を含む）を当てていた。新しい呼び出しは旧 bats の実際の範囲に合わせる（検査は変わらず、spec の本文を実際の検索に揃える）。

### 5. CI への接続

`.github/workflows/` は触らない（聖域パス）。CI は `scripts/test.sh` で bats の全スイートを回すので、`tests/public-private-split.bats` の検索が共有スクリプトを呼べば、公開版の部品に対する禁止語検査が CI で走り、固有名を 1 つ足すと落ちる。共有スクリプトはリポジトリのファイルとしてパスで直接呼ぶ（`bash "$REPO_ROOT/plugins/dev-workflow/scripts/forbidden-words-check.sh"`）。`FORBIDDEN_WORDS_NO_GH=1` を設定する（allow に期限付きの行が無く、gh を呼ばないため）。

### 6. テストの置き場

新しいテストは `tests/public-private-split.bats` の中に足す（spec の capability がこのファイルを検査の置き場にしており、語の検索の置き換え先だから）。固有名の語は bats に直書きせず、辞書のファイルから読む（例: 辞書の先頭の語を取り出し、段階化したコピーのファイルに 1 行書き足して呼ぶ）。これで「語が bats と辞書の 2 か所に残らない」を保つ。テスト名は ASCII のみ。

## Risks / Trade-offs

- 大文字小文字を区別しなくなったことで、今後 `Moko` のような綴りも拾う。これは意図した強化で、今の main の当たりは上の 2 行だけ（4 で確認済み）。起こる頻度は、大文字始まりで名前を書く文が足されたときだけ
- 辞書が `tests/public-names/dict/` に公開される。語はすでに `tests/public-private-split.bats` に公開されている語と同じで、新しい情報は増えない
- 恒久の許可は固定の文字列で行を絞るため、許可された行の中身を直すと、その許可は「何も打ち消していない」違反になり、許可を直すまで落ちる（旧 bats の鮮度の検査と同じ振る舞い）
