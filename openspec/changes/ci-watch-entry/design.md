## Context

#521 の `pr-state.sh` が PR の観測と次の一手を分類し、#522 の `ci-watch.sh` と `references/ci-watch.md` が待機・再実行・修正の共通手順を持つ。共有手順には #523 の入口から呼ばれる余地と、呼び出し側が決める `ready` の差し込み口が既にある。入口だけが未実装である。

既存の `git-commit-policy.md` はマージに明示承認を要し、ゲート未通過 PR の無承認マージを禁じる。`destructive-git-guard.md` は main への push 等に方法とタイミングを含む事前承認を要する。共有 `ci-watch.md` は呼び出し側による直接の `gh pr merge` と merge API を禁じている。

## Goals / Non-Goals

**Goals:**

- オーナーが指定した PR の CI をメインセッションが見張り、失敗したら共有手順どおり `rerun` / `fix` / `escalate` に進む。
- `ready` 後は既存ゲートを通し、合格後のマージ経路へ接続する。
- 「マージして」の承認範囲を入口に明示する。
- ゲート未通過の PR で CI を落とす実機確認と、PR への結果記録を実装タスクに含める。

**Non-Goals:**

- `ci-watch.sh` / `pr-state.sh` の待機・分類規則を作り直すこと。
- ゲートの合格条件、自動マージ workflow、禁止されている直接マージ操作を変えること。
- サブエージェントに背景の CI 待機をさせること。

## Decisions

### `/ci-watch <PR>` を薄い入口にする

issue #523 が示す `/ci-watch <PR>` の形を採用する。PR の URL または番号を既存の GitHub CLI の対象 PR に解決し、入口は `references/ci-watch.md` の開始判定・コメント・`wait`・`next`・一手の実行をメインセッションで呼ぶ。`wait` の観測で `ci-fail` かつ `retry=false` なら、同 reference の 2 条件を確認し、該当チェック名だけ `next --unrelated` に渡す。これがエピック #512 の「たまに落ちるテストなら 1 回やり直す」の呼び出し側責務である。`pr-state.sh` の同一 HEAD で 1 回という上限を再定義しない。

代替の新しい待機スクリプトや仕分け実装は #522 と二重になり、入口とゲート後で結果がずれるため採らない。新しいスキルも追加せず、コマンドから既存手順を読む。

### `ready` はゲートに接続する

入口からの見張りはゲート未通過 PR を受け入れるが、CI の `ready` だけをマージ可能の証拠としない。`ready` になったら `pr-review-gate` を実施し、合格した場合だけ共有手順の「`ready` を受けたあと」にあるラベル確認・自動マージ待ちまたは人間へのマージ依頼へ進む。ゲートが failed / 保留なら、その通常の修正・保留手順に従う。修正の push 後は同じ見張りの状態ファイルで CI を見張り直す。

### 条件付きマージ依頼の承認範囲

オーナー本人が当該 PR に対して「CI が通ったらマージして」と直接依頼した事実は、**その PR が CI 成功と既存ゲート・リポジトリ運用の条件を満たした後にマージへ進める意思**として扱う。別の PR、別の HEAD に対するリスク許容、ゲート省略、main への直接 push、rebase・force-push、LLM による `gh pr merge` / merge API の実行を承認したものとは扱わない。自動マージが使えない場合とブロックラベルがある場合は、共有手順どおり PR URL を添えて人間にマージを依頼する。これは既存の権限規則を入口に適用したもので、新しいマージ経路は作らない。

## Risks / Trade-offs

- [共有手順の背景待機はメインセッションの生存に依存する] → 既存の開始・終了コメントで見張り中を可視化し、閉じたセッションからの再開は `ci-watch.md` の中断した一手の確認に従う。
- [関係ない失敗を誤判定する] → ログと変更ファイルの 2 条件が揃わなければ `--unrelated` を渡さない。再実行は同じ HEAD で 1 回に限る。
- [CI green をゲート合格と取り違える] → 入口の `ready` 差し込み口でゲートを必ず実施し、合格が確定するまでマージ待ち・依頼に進まない。
