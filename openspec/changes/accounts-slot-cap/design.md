## 決めたこと
- **数え方**: `accounts` 配列の要素数が 8 以上で、追加しようとする id が配列に無いとき拒否する。`read_slots()` は不正な要素を飛ばしてから 8 個で打ち切るが、書き込み側でそれを再現すると読み取り側の規則の二重実装になる。要素が不正なほど配列が長い登録簿は手編集の結果で、拒否が早すぎても利用者が登録簿を直せば済む。単純さを取る
- **終了コード**: 2。`accounts.sh` の「既にある id の add」「使い方の誤り」と同じ区分で、`accounts-init.sh` の引数エラーも 2。登録簿が読めない場合の 1 とは区別する
- **accounts-init.sh の既存 id の上書き**: スロット数が増えないので 8 個でも許す（`enabled` を引き継ぐ要件を壊さないため）
- **accounts.sh add の順序**: 上限の検査は `os.makedirs` の前（python 側で `find` の直後）に置き、拒否時にディレクトリを作らない
- **F1（ハイフン始まり）を含める理由**: 同じ `add` の引数検査の case 1 行・bats 1 例・spec 1 箇所で済み、規模が小さい。ハイフンで始まる id は spec の正規表現上は有効だが、`add` では登録できなくなる（`on` / `off` と `accounts-init.sh` は変えない）。この例外を spec に明記する
