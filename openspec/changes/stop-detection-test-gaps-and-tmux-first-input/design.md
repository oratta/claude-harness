## Decisions

- **境界行は実行ごとの乱数**: 発言が境界行を知って偽装できないように、`stop-judge.sh` が毎回 `openssl rand -hex 8` 相当（無ければ `$RANDOM` の連結）で作る。固定文字列にしない。発言の中に境界と同じ行が現れても外へ出られない（乱数は発言を読む前に作る）
- **Enter の重ね送りの条件を、実機で原因を確かめてから直す**: 重ね送りは 2026-10-21（#1178）から入っているが、#1824 の失敗は 2026-11-26 にその版で 2 回起きた。仮説は、既定のモードでは入力欄に文が入ると `? for shortcuts` が消え、4 秒目の `pane_ready` が失敗して `resend=0` になり Enter を一度も重ねないこと。既存の bats のスタブは plan mode の行（`shift+tab to cycle`）を置くので、この状態を再現できていない。確かめる手順: 実機の既定のモードで入力欄に文が残った `capture-pane` を取り、(1) 最下部に入力待ちの印が出るか、(2) `head20` が画面に出るか、(3) `/develop` の補完候補が `DIALOG_PATTERN` に当たるか、を見る。仮説どおりなら、条件を「確認画面の印が無く、文の先頭が入力欄に残る」に改める（印は条件にしない）。違えば、見つけた原因に合わせて spec の条件と Scenario を直す。spec は仮説どおりの形で先に書いてあり、手順の結果で直す
- 失敗時の案内（`resend_hint`）に、画面とワークツリーが残り、入力欄に文が残りうることを足す
- テストの欠けは、今の main の行ごとに「残っているか」を確かめてから足す。無くなった行（例: `EPIC_DISPATCH_STOP_BG_IDLE_SEC`）は証拠を書いて済みにする

## Risks / Trade-offs

囲む対象は子が書いた文全体（最後の発言と未回答の問い）。停止の記録の本文は別の入力経路で絞られるので囲まない。乱数の境界行は、判断のモデルが読み方の 1 行を守る前提で効く（機械で強制はできない）。親の返事は元から「主の承認ではない」と付くので影響は限られる。
