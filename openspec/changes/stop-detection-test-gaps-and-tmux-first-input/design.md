## Context

3 つの元の issue は互いに独立で、触る場所が離れている。設計の選択は小さく、下の 2 点だけ。

## Decisions

- **境界行は実行ごとの乱数**: 発言が境界行を知って偽装できないように、`stop-judge.sh` が毎回 `openssl rand -hex 8` 相当（無ければ `$RANDOM` の連結）で作る。固定文字列にしない。発言の中に境界と同じ行が現れても外へ出られない（乱数は発言を読む前に作る）
- **Enter の再試行は既存のまま**: 再送は Enter だけ（文は 1 回）、4 秒ごと、入力待ちで確認画面が無く送った文の先頭が入力欄に残るときだけ。main で満たすので動作は変えず、失敗時の案内（`resend_hint`）に「画面（ペイン）と worktree は残っている」を足す
- テストの欠けは、今の main の行ごとに「残っているか」を確かめてから足す。無くなった行（例: `EPIC_DISPATCH_STOP_BG_IDLE_SEC`）は証拠を書いて済みにする

## Risks / Trade-offs

乱数の境界行は、判断のモデルが読み方の 1 行を守る前提で効く（機械で強制はできない）。親の返事は元から「主の承認ではない」と付くので影響は限られる。
