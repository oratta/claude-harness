# Design

## Context

動機と編集範囲は proposal.md を参照。基準 HEAD は `bc753b976d866fb58c0e92c0af8a7415a7b6f01f`。#1682 の OWNER 方針は、動きを変えず場面別の正本とバイト予算を維持すること。必要な道具は Git・GitHub の記録先への権限・OpenSpec CLI・Bats・既存 test/lint スクリプトであり、新しい依存は要らない。

## Goals / Non-Goals

- **Goals**: 読み手が別ファイルへ移った規則を探し直さずに済むこと。利用条件と片付けの説明の欠落を復元すること。
- **Non-Goals**: 閾値・分岐・承認・分類・読込集合の変更、並行 issue の修正、今回の参照修正以外を理由とする予算変更、過去の行番号表の更新。

## Decisions

### 正本のファイル名と節・段落名で案内する

OWNER と #1693 の指定に従う。`epic-loop.md:26,61` は `reply-after-idle.md`「親への適用」、`epic-stop.md:7` の書き分けは `epic-loop.md`「主への報告」、同じ行と `epic-loop.md:71` のマージ待ちは `epic-merge-wait.md`「マージ待ちの子」を指す。数値を重複して残す案や「上・下」を残す案は、移動や正本の変更で再び食い違うので採らない。親の分類を子の環境変数による閾値へ読み替えない。

移った声かけの段落 `epic-keepalive-watch.md:9` の「上の通常の再開判定」は、実在する `reply-after-idle.md:40`「そのまま送るか、起動し直すか（子）」を指す。本体は #1693 の issuecomment-6993166891 で、この移動先も同じ指摘の修正範囲に含めると判断済み。送信条件や再開の判定自体は変えない。

`epic.md:47` のラベルは別セッション方式とサブエージェント方式を明記する。`epic-subagent.md:3–5` には旧表の「いつでも使える」と「kept の後で消す本体 worktree は無い」を戻す。この説明は別セッション方式の片付け操作が不要なことを表し、W の隔離 worktree が不要という意味にはしない。同一 repo 制約や並列枠は変えない。

テストは所在説明のコメントを修正し、既存の要件名を引用した spec 注記・履歴は勝手に改名しない。特に `parent-merge.bats:30` のコメントは `epic-merge-wait.md`「マージ待ちの子」を指す。docs は182行の現行説明だけを `references/epic-loop.md` の「部品ごとの欄」へ合わせ、189行以降の「過去時点の場所の記録」は保つ。

### 一つの参照整合として扱い、場面予算を実測に合わせる

受け入れ条件と機能領域は一つであり、ファイルごとに change を割っても独立した機能や設計判断にはならない。移動先を含めた8ファイルの規模超過についても、本体は上記コメントで分割しないと判断済み。

実装後の本体判断（#1693 issuecomment-6993488451）に従い、`tests/develop-epic-scene-budget.txt` の全11場面を実測に合わせる。旧い参照を実在するファイル名・節名に付け替えた分を反映し、増えた8場面だけでなく減った3場面も下げ、場面ごとの前後の値と理由を変更記録に残す。参照文をさらに削って相殺しない。固定集合・`tests/injection-budget.txt`・他の予算ファイルは維持する。

修正前 HEAD `89808b38` の固定集合を実測すると全11場面の余白は0。R1 は `nested-stop`・`nested-delegated` に各505 bytes の余白と記したが、両場面には `references/child-cache-keepalive.json`（505 bytes）も含む。これを含む合計はそれぞれ57630・64068 bytes で予算と一致する。実装後も同じ固定集合で確認する。

### 検査は既存のテストファイルへ追加する

`epic-dispatch.bats` に対象の参照先・節/段落の実在と、対象位置の旧表現が無いこと、サブエージェント方式の説明があること、docs の現行参照を確かめる回帰テストを追加する。表現の完全一致より意味のあるパス・節名の組合せを確かめ、手順本文の所在は既存の epic 全文集合で調べてよい。

**検査の守備範囲**: 入力は #1693 が指定した現行の対象文、参照先、テストコメント、docs182行相当の現行説明である。拾うのは対象の参照切れ、移動前の所在、重複した時間閾値、説明の欠落である。例えば履歴表に過去の SKILL.md の行番号が残っていても通してよい。無関係な手順書すべてのリンク、文の良し悪し、同量の意味の入れ替えはこの検査で保証せず、抜ける入力をすべて塞ぐことを完了条件にしない。

## Risks / Trade-offs

- 参照を名指すことでバイト数が増える → 本体判断に従い全11場面の予算を実測へ合わせ、変更理由を残し、以後の増大を同じ場面予算で検査する。
- 旧い説明を戻す際に W の worktree まで無いと読める → 本体の片付けと W の隔離を区別して記す。
- 移動先の取り違え → 指摘文の修正元は `epic-keepalive-watch.md:9`、参照先は `reply-after-idle.md` の子の再開判定とし、元のファイルの別段落や親の時間分類は変更しない。

## Migration Plan

R1 のレビューと本体の再開指示を受けてから実装する。対象の旧表現だけに絞った `git grep`、追加回帰テスト、場面予算、`./scripts/test.sh`、`./scripts/lint.sh` を確認する。参照元だけの変更なので移行処理は要らず、戻す場合はこの PR の変更を revert する。マージ判断は今回の工程外。
