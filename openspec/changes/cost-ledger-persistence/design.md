# design — cost-ledger-persistence

## 決定 1: 台帳の場所は環境変数だけで決める

`COST_LEDGER_PATH` に台帳ファイルのパスを書く（`~/.claude/settings.json` の `env` に置く想定）。既定値は持たない。個人のディレクトリ構成をこのリポジトリに残さないためで、`LLM_LOG_DIR` と同じ扱い。

- 未設定のとき、hook は python3 も起動せずに抜ける（hook から利用者には聞けない）。`/cost` は会話ログを直接読む従来の経路で答え、コマンド本文の指示に従ってエージェントが利用者に台帳の場所を聞く
- 台帳の実パス（`realpath`）が、`cost_ledger.py` を含むリポジトリ（無ければプラグインのディレクトリ）の配下なら書かない。marketplace dir は自動更新で再 clone されると untracked ファイルごと消えるため
- 台帳の親ディレクトリが無ければ作る

## 決定 2: 台帳の 1 行は事実そのもの

子1 の `build_fact` が返す辞書を `json.dumps` した 1 行。区間の帰属は次の投稿が来るまで確定しないので、帰属は書かない（`cost-ledger-attribution` の「事実と帰属を分ける」要件のとおり）。リポジトリ識別子は書いた時点で解決済みの値が残るので、あとで worktree が消えても「不明」に落ちない。

1 行の先頭の鍵は `request_id`。重複排除の集合を作るとき、JSON をパースせずに先頭の文字列から取り出せる（パースは形が違う行のときだけ）。

## 決定 3: 差分は会話ログごとの読み終え位置で取り、正しさは requestId で守る

台帳の隣に控えファイル `<台帳>.offsets.json` を置き、会話ログのパスごとに `{offset, ino}` を持つ。hook は会話ログのルートを歩き、サイズが控えの位置より大きいファイルだけを、控えの位置から最後の改行まで読む（書きかけの末尾行は次回に回す）。ファイルが縮んだか inode が変わったら 0 から読み直す。消えたファイルの控えは捨てる。

速さは控えファイルが、正しさは `requestId` の重複排除が持つ。控えが壊れても消えても全件を読み直すだけで、台帳に既にある `requestId` は書かないので台帳は同じになる。台帳に追記してから控えを書くので、その間で落ちても次回の読み直しが重複排除で吸収する。

`requestId` の重複は同じファイル内（1 応答が複数行に分かれる）とファイルをまたいで（resume・fork で履歴が複製される）の両方で起きる。どちらも先に見た 1 行だけを採る（子1 の会話ログ直読みと同じ規則）。

## 決定 4: hook は Stop、同時実行はロックで直列にする

`Stop`（応答が終わるたび）で追記する。その時点で、その応答の行は会話ログに書かれている。サブエージェントの会話ログも同じルートの下にあるので、ルートを歩けば次の `Stop` で拾われる。`SubagentStop` や `SessionEnd` は足さない（取りこぼしの面では `Stop` とルート全体の走査で足りる）。

複数のセッションが同時に `Stop` を迎えるので、`<台帳>.lock` に `flock` の排他ロックを取ってから読み書きする。

hook の抜け方は #276 と揃える。どの失敗でも無出力で `exit 0` し、応答を止めない（`exit 2` を返さない）。

## 決定 5: `/cost` は台帳を読む前に 1 回追記する

`COST_LEDGER_PATH` があるとき、`cost_ledger.py` の集計系サブコマンド（`facts` / `branch` / `intervals` / `issue` / `cost` / `report`）は、読む前に `ledger-sync` と同じ差分追記を 1 回行い、そのあと台帳だけを読む。追記を挟むので、台帳は読む時点で会話ログの上位集合になり、会話ログを直接読んだときと同じ値になる。最後の `Stop` 以降の行（その応答の途中の分）も含まれる。

台帳の読み取りでは、ブランチの絞り込みも重複排除も会話ログ直読みと同じ規則を当てる。

## 計測

- 差分追記 1 回（変化のあったファイルが数本）は 1 秒未満を目標にする。実測は PR に貼る
- 初回（台帳が空）は全履歴を 1 回読むので、会話ログ直読みの `/cost` と同程度かかる。hook の `timeout` は 120 秒にする
