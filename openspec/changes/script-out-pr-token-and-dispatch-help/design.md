## Context

#1686 の 5 候補のうち 2 つを出す。分割判定の根拠は記録先コメント（編集対象が 5 ファイルを超えるので 2 候補に絞る）。touch する capability は 2 つだが、依存順は無く差分が小さい。issue が 1 本の PR を指示しているので 1 つの change に 2 つの spec 差分を入れる。

## Decisions

- **ラッパーは新規ファイル `pr-token-measure.sh`**。`pr-token-budget.sh` に `--repo` を足して中でつなぐ案は、既存スクリプトの引数・exit code を変えるので採らない（変えてはいけないもの）。`codex-records.sh` に集計まで持たせる案も同じ理由で採らない
- **repo は必須引数**。`gh repo view` で推測する案は、通信が 1 つ増え失敗の種類も増えるので採らない。本体は手順書どおり repo を知っている
- **CODEX_HOME の対応表は呼び手が渡す**（`--codex-home` の繰り返し）。ラッパーは本体の環境の既定だけを足す。対応表の場所の解決は codex-develop 側の責務で、ここに持ち込まない
- **`--help` は第 1 引数だけ**。サブコマンドごとの help は、未知のサブコマンドの扱いを変えない範囲に収めるため作らず、1 本の出力で全サブコマンドを説明する
- **`--help` の本文は heredoc で持つ**。実装と食い違わないよう、テストで出力語の一覧（スクリプト内で `echo`/`printf` している語）と `--help` の語を突き合わせる
- **出さない 3 候補**（実行モードの判定、片付け・待ちの前の確認、決める役への入力の列挙）は、この PR では触らず PR 本文に理由とともに挙げ、#1686 で続ける

## Risks / Trade-offs

- `--help` の説明が実装と食い違うと、手順書から説明を消した分だけ本体が誤読する。出力語の突き合わせテストで下げる
- 手順書から文章を消すので `develop-skill.bats` などの文字列断言が落ちる。断言は呼び方と分類表に付け替える
