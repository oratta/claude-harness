## ADDED Requirements

### Requirement: 空の return を受けたら報告を 1 回だけ求め、同じ指示で起こし直さない

本体は、W が `(Subagent completed but returned no output.)` だけを返したとき（`continue: false` による打ち切りで、拒否理由が親に届かない場合を含む）、その W に SendMessage で報告を 1 回だけ求めなければならない（MUST）。本体は、報告の有無によらず `git -C <path> status --porcelain` で作業ツリーの未コミット差分を確かめ、残っていれば引き取らなければならない（MUST）。報告に破壊的 git 操作で打ち切られたとあるときは、同じ指示で W を起こし直してはならず（MUST NOT）、打ち切られた操作と指示の見直しを主に上げなければならない（MUST）。1 回求めても報告が空のとき、または報告から打ち切りの原因が読み取れないときも、同じ指示で W を起こし直してはならず（MUST NOT）、空だったことと作業ツリーの状態を主に上げなければならない（MUST）。`skills/develop/SKILL.md` の「1 ループ」の節に、これらが書かれていなければならない（MUST）。

この要件の対象は W だけである。R1・G・レビュアーなど再開しない役が空で返ったときの扱いは、この要件の範囲外とし、既存の要件（手渡しの許可条件、G が工程中断で返したときの扱い）に従う。

**守備範囲**: 判定する入力は、develop の本体が名前付きで起こした W の return 文字列である。本体は W を名前付きで起こし、Agent はバックグラウンドで返るため、SendMessage で再開できる。拾いたい誤りは、拒否の理由が届かない空の return を「作業が終わった」と読み違えること、および原因が分からないまま同じ指示で W を起こし直して同じ操作に再度当たることの 2 つである。通ってよい入力は、`(Subagent completed but returned no output.)` 以外の通常の return（`工程完了:` `工程中断:` で始まるもの）で、これには従来どおりの扱いを適用する。守らないものは、W が報告で嘘や誤りを書くこと（差分は報告に頼らず `git status` で確かめるに留める）、および空の return の原因が打ち切り以外であるすべての場合（原因が読めなければ主に上げる）である。穴が見つかるたびに判定を増やして塞ぎ切ることは完了条件にしない。

#### Scenario: 報告を 1 回だけ求める

- **WHEN** `skills/develop/SKILL.md` の `returned no output` を含む段落を読む
- **THEN** SendMessage で 1 回だけ報告を求める、と書かれており、`git -C <path> status --porcelain` で未コミット差分を確かめることも書かれている

#### Scenario: 打ち切られたら起こし直さない

- **WHEN** 同じ段落を読む
- **THEN** 報告に破壊的 git 操作で打ち切られたとあれば、同じ指示では起こし直さず主に上げる、と書かれている

#### Scenario: 再報告が空でも起こし直さない

- **WHEN** 同じ段落を読む
- **THEN** 1 回求めても報告が空のとき（または原因が読み取れないとき）も、同じ指示では起こし直さず、空だったことと作業ツリーの状態を主に上げる、と書かれている

#### Scenario: 対象は W だけ

- **WHEN** 同じ段落を読む
- **THEN** 対象が W であり、再開しない役（R1・G・レビュアー）は既存の手順に従う、と書かれている
