## Context

#1133 の仕組み: hook は子への deny のたびに `<base>/denied/<key>.json`（session_id・agent_id・cwd・command 全文）を書き、そのパスを子への理由に載せる。親が `git-guard-permit.sh <記録のパス> <理由>` を実行すると、記録のコマンドが「単純な cd と git だけ」で、触る repo がすべてそのセッションの scratchpad の中にあるとファイルの配置から確かめられたときだけ、15 分・1 回限りの許可が書かれ、その子の拒否の回数が 0 に戻る。hook は使う時点で同じ判定をかけ直す。子がスクリプトを呼ぶと deny。2 回目の拒否で子は `continue: false` で打ち切られ、親には `(Subagent completed but returned no output.)` だけが返る。#1117 は、その W に SendMessage で報告を 1 回求め、同じ指示で起こし直さず主に上げる手順を入れた。

足りないのは本体の側の判断と手順である。機械の判定（場所・コマンドの形）は #1133 のスクリプトが持つので、本体に残る判断は次の 2 つだけにする: (1) 子が自分で作ったものか、(2) 要る理由が「戻す・片付ける」に収まるか。

## Decisions

1. **許可を書く判断を本体の 4 条件にする。** 本体が確かめるのは、報告の 4 項目が揃っていること、報告のコマンドと対象が拒否の記録の command / cwd と同じこと、W が自分で作ったと作ったコマンド付きで報告していて本体が W に渡した指示でその対象を既存のものと名指ししていないこと、要る理由が検証用 repo を戻すことに収まることの 4 つ。場所とコマンドの形はスクリプトの判定に任せ、本体は自分で再判定しない。理由: 場所の判定を 2 か所に書くと食い違う（#1133 の「判定は 1 か所」の線）。
2. **本体は対象の repo に git を実行しない。** 子が作った repo の設定（core.fsmonitor など）でコマンドが動きうるため、#1133 の判定も git を実行しない。本体が「作ったか」を確かめる手段は報告と、自分が渡した指示の照合に限る。守らないものは、W が作ったと嘘を書くこと（消えるのは scratchpad の中だけで、場所の判定が外への影響を止める）。
3. **再開は SendMessage。許可を書けた同じ W だけ。** 許可は `agent_id` に結び付くので、新しく起こした W には使えない。再開の文面には、15 分以内に、同じ cwd から同じコマンドを 1 文字も変えず 1 回だけ打つこと、ほかの操作は許可されていないことを書く。再開の前の `subagent-context.sh` での測定は既存の規則のまま。
4. **オーナーに上げる条件を閉じた列挙にする。** 4 条件のどれかを満たさない／スクリプトが 0 以外で終わった／許可を書いて再開した W が同じ拒否で再び返った／拒否を報告したのが再開しない役（R1・G・レビュアー）。再開後に同じ拒否が来たら、許可は使われたか期限切れかで、同じ操作を再度許可する根拠が本体に無いので 2 回目の許可は書かない。
5. **#1117 の段落を 1 つに保つ。** 規則を 2 か所に書くと食い違う（`worker/common.md` の方針と同じ）ので、拒否の報告の扱いは #1117 の段落に追記し、報告を求める文の項目も 4 項目にそろえる。「報告に破壊的 git 操作で打ち切られたとあれば同じ指示で起こし直さない」は残し、許可を書いた再開は「同じ指示での起こし直し」ではなく、許可つきの続き（SendMessage）として分ける。
6. **オーナーへの文面。** 何を・どのパスに・なぜ、本体が確かめた事実（報告の 4 項目と、満たさなかった条件またはスクリプトの stderr）、推奨（たとえば「W の指示を変えて作り直させる」）を書く。unmanned ならチャンネルで承認を求める。承認されたらオーナーが自分で実行し、本体は代わりに打たない（`rules/destructive-git-guard.md` のとおり）。
7. **報告項目は hook の理由・agents の定義・本体の報告要求の 3 か所で同じ 4 項目にする。** 子は破壊的操作を拒否された時点で hook の理由を読み、定義は作業の前から読まれ、本体の報告要求は打ち切られた子に読まれる。項目名が違うと本体が項目の有無を判定できない。

## Risks / Trade-offs

- 本体が「作ったか」を報告だけで判断する。守りは #1133 の場所の判定（外には許可が書けない）なので、誤った許可で消えるのは scratchpad の中の repo に限られる。この線で足りると見る。
- 許可の期限は 15 分。本体の再開が遅れると使われず、同じ操作がもう一度拒否される。このとき W は再び返り、決定 4 によりオーナーに上がる。
