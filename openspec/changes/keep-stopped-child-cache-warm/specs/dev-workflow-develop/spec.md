## ADDED Requirements

### Requirement: 子への声かけ文と返事の形は一か所の定義を共有する

キャッシュ維持の声かけは、固定文・返事専用の接頭辞・順序付き欄名と区切りを一つの機械可読定義で持ち、送信・子の受信手順・発言の除外が共有しなければならない（MUST）。初期の欄名は #1374 の案の `待ち:`・`次:` とし、欄の意味の確定や調査による失敗検出を追加してはならない（MUST NOT）。返事は専用の接頭辞と各欄の短い値を持つ一行で、値に改行・区切り文字を含めない（SHALL）。

#### Scenario: 欄を追加しても照合が同じ定義に従う
- **WHEN** 共通定義の順序付き欄名を追加・変更して声かけを生成する
- **THEN** 生成した固定文に返事の型が含まれ、その型に従った返事を発言の除外が認識する。別のファイルに同じ固定文や欄名の一覧を持たない

### Requirement: wait は主の返事待ちの子にだけキャッシュ維持の声かけを送る

wait は `--watch-stopped`・位置引数の子・正の interval/timeout を持って通常の待ちを続けるときだけ、既存の親の記録が一意で、worktree が存在し、status が done でなく、stop が stopped-seen の子を声かけ候補としなければならない（MUST）。認められた投稿者の最新の主の返事待ちの停止記録があり、まだ実質的な返事が無いことを確認する（SHALL）。確認できない・起動に失敗した子には送らない（MUST NOT）。

#### Scenario: 返事待ちの子だけに送る
- **WHEN** 同じ親の子に、未回答の主の返事待ち・done・reap 済み・resumed・停止記録無し・別の親の子があり、いずれも時刻等の条件は満たす
- **THEN** 未回答で stop=stopped-seen の子だけに固定文が送られ、他の子の端末は操作されない

#### Scenario: 実際の返事を受けた子には送らない
- **WHEN** stop=stopped-seen のままでも、停止の質問のあとに主の直接の返事・親が中継した主の返事・親の判断のいずれかが届いている
- **THEN** 声かけを送らず、実際の返事の処理を妨げない

#### Scenario: 一回確認と片付け待ちでは送らない
- **WHEN** `wait --interval 0 --timeout 0 --watch-stopped 11`、または位置引数を持たない片付け待ちを実行する
- **THEN** 声かけのための停止記録の読み出し・端末への送信を行わず、従来の stdout/stderr/終了コードの契約を保つ

### Requirement: 子の声かけには最後のリクエストと停止期間の期限を適用する

声かけは、子の最後の成功した CLI リクエストからの経過が 3000 秒以上かつ 3600 秒未満で、同じ停止の記録の作成から 86400 秒未満のときだけ送らなければならない（MUST）。声かけや wait 掛け直しで停止の基点を延ばしてはならない（MUST NOT）。起動し直しの会話量条件に該当する子、時刻・会話量・現行セッションを判定できない子、前の声かけの返事が未着の子には送らない（MUST NOT）。

#### Scenario: 最後のキャッシュ読み出しをリクエストとして扱う
- **WHEN** 1h のキャッシュ書き込みは 2 時間前だが、現在の一意の CLI セッションの最後の有効な assistant usage は cache-read のみで 3000 秒前であり、他の条件も満たす
- **THEN** 固定文を送る。書き込みの時刻をリクエストの時刻として使わない

#### Scenario: 境界とスリープ復帰
- **WHEN** 他の条件を満たす子について最後のリクエストから 2999 秒・3000 秒・3599 秒・3600 秒、またはスリープ等で 1 時間を超える経過をそれぞれ用意する
- **THEN** 3000 秒・3599 秒の場合だけ送る。3600 秒以上では起動も声かけもせず、実際の返事時に #1323 の規則へ渡す

#### Scenario: 同じ停止の 24 時間を超えない
- **WHEN** 最新の停止記録が 86400 秒以上前で、直前の声かけの返事と wait の掛け直しは 3000 秒前である
- **THEN** 固定文を送らず、停止の印を保つ。停止から 86399 秒で他の条件を満たす場合は送る

#### Scenario: 多重送信と起動し直しを避ける
- **WHEN** 前の固定文にまだ返事が無い、または会話量が既存の起動し直し閾値以上である
- **THEN** 固定文を送らず、そのために新しいセッションを起動しない

### Requirement: 子のキャッシュ TTL が五分か不明なら声かけを送らない

子への声かけは、既存の `cache_ttl_of` が子の最後のキャッシュ書き込みを 1h と判定した場合だけ送らなければならない（MUST）。5m または不明なら送らない（MUST NOT）。規則には、overage 等で 5m に縮むと 50 分の声かけは効かず、書き込みを観測するまでは切替を検知できないことを明記する（SHALL）。五分ごとの声かけを追加しない（MUST NOT）。

#### Scenario: 子の TTL を親から独立して判断する
- **WHEN** 親の TTL は 5m で子は 1h、または親は 1h で子は 5m/unknown である
- **THEN** 親の既存の wait 上限は維持され、子が 1h で他の条件を満たす場合だけ声かけが送られる

#### Scenario: timestamp は時刻として比較する
- **WHEN** 20 分前の Z 付き cli/1h、3 分前を -05:00 で表した cli/5m、timestamp が `not a time` の cli/1h の行を親のトランスクリプトに置き、子 11 が closed の環境で上限未指定の `dispatch wait 11` を実行する
- **THEN** stderr に `wait limit 21600 (parent cache 5m)` が出る。時差なしを UTC として同じ時刻関係にした場合も、新しい行を時刻として選び、不正な行を飛ばす

### Requirement: 声かけは入力待ちの既存セッションにだけ届く

Orca/tmux の起動部品は、キャッシュ維持の声かけを、既存の子のセッションが一意に決まり、入力待ちで入力欄が空のときだけ送らなければならない（MUST）。端末無し・曖昧・実行中・選択画面・入力済みは送らない（MUST NOT）。声かけのために端末の起動・再起動・終了・入力の消去をしてはならない（MUST NOT）。送信確認は返事の内容や費用削減の検証と区別する（SHALL）。

#### Scenario: 入力待ちに送って開始を確かめる
- **WHEN** 既存セッションが一意で、入力待ちかつ入力欄が空である
- **THEN** 固定文を送ってターンの開始を確かめる。起動・close は行わない

#### Scenario: 対象の端末を送信できない
- **WHEN** 端末が無い・複数の候補・実行中・主の文字が入力済み・質問ツールや許可の選択画面、の各状態で声かけを試みる
- **THEN** 送信を見送り、端末や入力内容を変えない。通常の主の返事を待てる状態を保つ

### Requirement: 子は声かけにだけ返し停止の状態を保つ

子は、停止前に共通定義を読み、固定文の受信を通常の主の返事や親の判断より先に分類し、定義どおりの一行だけ返さなければならない（MUST）。声かけの受信ターンではツール・調査・作業・mark resumed/stopped・停止コメントの投稿を行ってはならない（MUST NOT）。実際の返事が届いた場合は従来の再開手順に従う（SHALL）。

#### Scenario: 主の返事待ちを継続する
- **WHEN** 質問して止まり、親が停止を受けて stop=stopped-seen になった子に固定文が届く
- **THEN** 子は指定の一行だけ返し、status/stop・最新の停止記録の URL と本文は変わらず、元の質問が未回答のまま残る

#### Scenario: 通常の返事は再開する
- **WHEN** 声かけ後に、主の直接の返事または正規の親からの返事が届く
- **THEN** 子は声かけの返事として扱わず、既存の mark resumed と続きの作業に進む

### Requirement: 声かけは wait を終了させず親の起床を増やさない

wait は声かけの送信・返事だけを理由に stdout の行を追加したり終了したりしてはならない（MUST NOT）。送信の失敗は stderr の診断にとどめ、通常のポーリングを続ける（SHALL）。本当の closed/done/stopped と既存のエラー・timeout は従来どおり扱う（SHALL）。規則に、打ち手が wait であり、親の追加 LLM ターンが不要なことと既存の timeout の掛け直しの費用を記す（SHALL）。

#### Scenario: 声かけの後も timeout まで待つ
- **WHEN** issue は open、status は done でなく、stop=stopped-seen の子が声かけに返し、そのあと状態に変化が無い
- **THEN** wait は声かけの時点では終了せず、既定のポーリングを続け、上限で従来の `timeout <子>` と exit 2 を返す。主の質問とその timestamp は child-log に残る

#### Scenario: 失敗と実際のイベントを区別する
- **WHEN** 声かけの送信に失敗し、後のポーリングで子が新しい mark stopped または done を付ける
- **THEN** 送信失敗だけでは親を起こさず、実際の stopped/done は既存の出力・終了コードで親に届く

### Requirement: 親と子のキャッシュ維持費用を実エピックで比較する

#1383 の完了前に、実装後の実エピック一本と実装前の比較区間を既存 cost-ledger で比べ、親と子を分けて issue に記録しなければならない（MUST）。書き直しの tokens/USD、cache-read、声かけと親の起床を含む費用、件数・会話量・モデル・TTL・比較期間を記す（SHALL）。実測無しや比較不能を費用削減の成功と扱ってはならない（MUST NOT）。

#### Scenario: 親子の費用を分けて記録する
- **WHEN** 実装後の実エピックで一時間以上の主の返事待ちを含むログが得られる
- **THEN** 子の再開区間と親の長い待ち後の起床区間について、声かけ・定期起床を含む区間全体を実装前と比較する。声かけでリクエストの空白が短くなっていても待ち区間に含め、元データの識別子と差異を #1383 に記録する

#### Scenario: 実測が足りない
- **WHEN** 実装後の実エピックが未実行、該当区間がゼロ、または比較できるログが得られない
- **THEN** 理由と不足するデータを記録し、費用比較のタスクは未完了とする

## MODIFIED Requirements

### Requirement: child-log は最新の会話ログと子の発言を決まった規則で選ぶ

最新の会話ログは、置き場の直下の `*.jsonl`（サブエージェントのものを除く）のうち、最後の timestamp が最も新しい 1 本でなければならない（MUST）。子の発言は、type が assistant のテキスト（`isSidechain` でないもの）である。ただし共通定義の固定文に対応し、定義の返事の型に一致する一行の声かけの返事は除く（MUST NOT）。本当の user の割込みや型に合わない assistant で対応を終了し、一般の「了解」や対応しない返事は除外しない（SHALL）。

#### Scenario: 新しい会話ログを選ぶ
- **WHEN** 置き場に最後の timestamp が違う 2 本の `*.jsonl` がある
- **THEN** 最後の timestamp が新しい 1 本のやり取りが出る

#### Scenario: 質問を声かけの返事で上書きしない
- **WHEN** 子の質問と固定文・正しい一行の返事があり、その往復が繰り返される
- **THEN** 最後の子の発言と timestamp は声かけ前の質問のままである

#### Scenario: 本当の発言は隠さない
- **WHEN** 固定文なしの「了解」、固定文と型に合わない新しい質問、固定文のあと主の本当の返事が割り込んだあとの子の発言、がそれぞれ存在する
- **THEN** いずれも従来どおり子の発言として扱い、声かけを理由に隠さない

### Requirement: child-log は主の発言を決まった規則で判定する

主の発言は、type が user で、`isMeta` でも `isSidechain` でもなく、内容が文字列かテキストだけ（`tool_result` を含まない）のものでなければならない（MUST）。次は数えない（MUST NOT）: 頭が `親エピック #` で始まる親の判断の返事（`親エピック #E の判断（主の承認ではない）: `）、`/develop` の最初の指示（内容に `<command-name>` のタグがある、または頭が `/develop` のもの）、共通定義から生成したキャッシュ維持の固定文と本文が完全一致する声かけ。頭が `主の返事（親エピック #E 経由）:` の親が中継した主の返事は数える。

#### Scenario: 親の判断の返事は主の発言に数えない
- **WHEN** 会話ログの最後の user 行が `親エピック #33 の判断（主の承認ではない）: ...` で、その前に主の発言がある
- **THEN** 主の最後の発言はその前の発言で、親の判断の返事ではない

#### Scenario: 中継された主の返事は数える
- **WHEN** 会話ログの最後の user 行が `主の返事（親エピック #33 経由）: ...` である
- **THEN** その行が主の最後の発言として出る

#### Scenario: 固定文を主の回答として数えない
- **WHEN** 主の発言のあとに共通定義の固定文が user として入る
- **THEN** 主の発言と timestamp は元のままであり、似た内容でも固定文に完全一致しない主の入力は除外しない
