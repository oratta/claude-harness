# Design

## Context

目的と範囲は proposal.md、判断記録は #1383 のコメントを参照する。調査時の HEAD は `1b203ef5`。

- `epic-dispatch.sh:1453-1529` の `child_log_line` は最新 JSONL の user/assistant のテキストを読む。現状のままでは声かけと返事が最後の発言になる。
- `:1334-1406` の wait は issue の closed、記録の done、stop=stopped を見る。Orca/tmux の busy/idle は見ない。stop=stopped は一度 stopped-seen に書き換える。
- `:1170-1179` の完了推定は stopped/stopped-seen を先に除く。キャッシュ維持の往復は実際の API 活動なので、キャッシュ時刻や活動の計測からは消さない。
- `:1038-1084` の `cache_ttl_of` は最後のキャッシュ**書き込み**を返す。リクエストの最終時刻ではない。ISO 8601 の時刻比較・読めない行の無視・時差なしを UTC とする契約が正本。
- 起動部品の `deliver` は端末が無いと起動する。声かけにそのまま使うと「起動し直す予定の子へ送らない」を満たせない。
- 子の `epic-child-stop.md` は次のターンで mark resumed を呼ぶ。声かけをこの規則より先に判定する必要がある。

## Goals / Non-Goals

**Goals:** 正常な一行の声かけ往復では質問を保持し、受けた停止の印を保ったまま、既存の入力待ちセッションの会話キャッシュを維持する。受信と発言除外は同じ定義に基づく。

**Non-Goals:** #1374 の欄の意味・失敗検出、#1385 のコンパクト制御、規約の再判断、新しい監視デーモン、独自の費用集計器。声かけは停止解除・承認・作業開始の入力ではない。

## Decisions

### 1. 既存 wait の中で送り、親の起床を増やさない

`--watch-stopped` と位置引数の子を持ち、正の interval/timeout で待つ wait の通常ポーリングに組み込む。通常の closed/done/stopped/error の処理と timeout 判定を優先し、待ちを続けるポーリングでだけ声かけする。`--timeout 0`・`--interval 0` の一回確認と、位置引数の無い片付け待ちは声かけしない。

既存の 300 秒ポーリングで子の期限を個別に見る。声かけの成功/スキップ/失敗を wait の stdout や新しい終了理由に足さない。失敗は stderr の診断だけにし、既存の連続ポーリング失敗カウントには足さず、通常の待ちを続ける。成功を逐次通知しない。親の既存の TTL 別の上限、timeout 後の同じ wait の一回の掛け直しは変えない。

親 LLM が毎回子を調べて送る案は親の呼び出し回数を増やす。専用バックグラウンドループは二重起動や終了管理を増やす。既存 wait は必要な子と状態を既に持つため、そこだけに送信責任を置く。

### 2. 共通定義と対応関係で除外する

`plugins/dev-workflow/references/child-cache-keepalive.json`（新規）を唯一の定義にする。固定の依頼文、返事専用の接頭辞、順序付き欄名（初期案 `待ち`・`次`）、一行の区切りを持つ。送る文はこの定義から固定の説明と返事の型を生成する。依頼の意味は「キャッシュ維持のため、定義の一行だけ返し、ツール・作業・印の変更をせず待ち続ける」。返事の接頭辞は通常の「了解」と区別できる専用文字列にする。欄の値は子の現在の会話からの短い値で、調査や検証を要求しない。値に改行と区切り文字を含めない。

子は停止前に `epic-child-stop.md` とこの定義を読み、以後固定文を受けたときは最初に声かけとして処理する。受信ターンで定義を読み直すツールも呼ばず、指定の一行を返す。受信手順には固定文を複製せず定義を参照させ、送信文自体にも生成した返事の型を含める。

`child-log` は、省略前の user 本文が生成した固定文と完全一致したときだけ、その user を主の発言から除く。同じ user の後から次の実質的な user の前までの、型に一致する assistant の返事だけを子の発言から除く。meta・sidechain・tool_result は対応を切らない。途中の本当の主の返事・親の判断は対応を切る。型に合わない assistant は従来どおり表示し、対応を終了する。単なる「了解」や、声かけと対応しない型の文は除外しない。連続した声かけにも同じ判定を繰り返す。元の主・子の発言の timestamp も保つ。ログの原本は書き換えない。

固定文は予約文とする。主が全く同じ本文を入力した場合も送信元は区別せず、その user と型どおりの返事を除外する。実運用では主がこの文を打つことを想定せず、識別用の ID や送信元記録は追加しない。受け入れ条件 3 の質問保持は、固定文に型どおりの一行が返る正常な往復に限る。複数行・型違いの返事は隠さず表示するため、その返事が最後の子の発言になり、元の質問は最後の発言ではなくなる。この逸脱だけでは status/stop=stopped-seen・停止コメントを変えず、wait を終了させず、親を起こさない。新しい停止として扱わず 24 時間の基点も延ばさない。別途 mark stopped/done や実際の返事があれば既存規則で扱う。

全 assistant をターン単位で隠す案は、予期しない作業や新しい質問まで消すため採用しない。欄を足した場合、送信と照合を同時に変えられる共通定義だけを直す。運用中の旧版の返事を新版の型で隠せなくなることは許容し、誤って実発言を隠す方向には倒さない。

### 3. 対象と時刻は既存の記録・会話から求める

新しい状態項目・タイマーファイルは作らない。送る直前に次を確認する。確認できない子は送らず、既存の wait の観測契約を変えない。

| 条件 | 求め方と境界 |
|---|---|
| 自分の親に属する 1 件の記録 | 既存 child_record。worktree が存在し、status != done、stop=stopped-seen。未起動・片付け済み・起動失敗も対象外 |
| 主の返事待ち | OWNER/MEMBER/COLLABORATOR が投稿した最新の `子の停止: 主の返事待ち` コメント。対応する「通した」が無く、最後の実発言の質問にまだ実質的な user の返事が無い。親の判断・中継した主の返事も実質的な返事に数える |
| 停止から 24 時間未満 | 上記コメントの created_at を基点に `0 <= now - stopped_at < 86400`。声かけ・mark の updated_at・wait 掛け直しでは基点を延ばさない |
| TTL が 1h | 子の worktree に既存 cache_ttl_of を使う。5m/unknown は送らない |
| 最後の成功リクエストから 50 分以上・60 分未満 | 子の現在のトップレベル CLI セッションの最新の有効な assistant usage の時刻で `3000 <= now - last_request < 3600`。cache-read だけの応答も含める。型が cli、sidechain ではなく、input/cache write/cache read の正の合計を持つ行を対象とし、時刻は ISO 8601 で比較する |
| 起動し直す条件でない | #1323 の会話量条件（既存 decide_relaunch と同じ閾値）も確認。超過・計測不能・複数の現行セッションで一意に選べない子には送らない |
| 前の送信が未解決でない | 固定文の user があるのに対応する返事が無い場合は、同じ質問を再送しない。送信の成否が曖昧なら同じポーリングで再試行しない |

最後のリクエストの時刻と TTL の時刻を混同しない。前者には有効な cache-hit の応答も入る。後者は書き込みがある行だけで TTL を判定する。usage の時刻はリクエスト時刻の観測上の代理値であり、10 分の余裕を取る。未来の時刻・不正値を期限内とみなさない。

子が通常の停止手順で新しい質問に停止コメントと停止の印を付けた場合は新しい停止として扱う。声かけへの型違い・複数行の返事だけでは新しい停止にしない。声かけだけで上限が延びることを防ぐため、停止コメントを基点とする。送信直前にローカルの stop/status と新しい実質 user の有無を再確認する。

### 4. 起動部品に既存セッション専用の送信を足す

Orca/tmux の起動部品に `keepalive <worktree> <text>` を足す。dispatch は既存の launcher 選択から呼び、Orca/tmux を直接呼ばない。部品は既存セッションが一意に決まり、入力待ちである場合だけ送信する。端末無し・曖昧・実行中・質問や許可の選択画面・入力欄が空でないときは skipped とし、入力や主の回答を上書きしない。入力待ちを確かめるために子の処理を長く待たない。

端末作成・close・relaunch・文字列の消去は一切行わない。送信後は既存のターン開始確認を利用するが、turn_started は送信確認であり、正しい返事やキャッシュ維持の実証ではない。部品の stdout は `sent` / `skipped <reason>`（ともに exit 0）/ `failed <reason>`（exit 1）の一行だけとし、引数数違いは stdout を空にして使い方を stderr に出し exit 2。dispatch は診断を stderr に扱う。引数・理由の語・許可する操作の正本は、この change の `dev-workflow-epic-state` delta とする。Orca は terminal list/read による観測と既存端末への send、tmux は list-panes/capture-pane と既存ペインへのリテラル送信・ログでの到達確認に限定する。送信前には再観測し、待機状態や入力の消去を作る操作はしない。

両起動部品で同じ限定を満たす。実装の最初に、Orca と tmux の両経路で既存セッションの「入力待ち・空欄」を実際の CLI 出力から観測できるか確かめる。実行中・入力済み・選択画面との区別も確認し、コマンド・版・出力・終了コード・判定根拠を #1383 に記録する。スタブの成功だけでは前提確認としない。既存 CLI で区別できなければ推測でキーを送らず、証拠と不足する観測を本体へ返して依存する実装を止める。

### 5. TTL 5 分・スリープ・上限後は通常の再開へ渡す

3000 秒より前には送らない。3600 秒以上たったスリープ復帰時は、古いキャッシュに新しい書き込み費用を払う声かけをしない。24 時間の上限後も stop は保ち、実際に主の返事が来たときの #1323 の再起動判定に任せる。声かけのためには起動し直さない。

5m の書き込みは overage 等で維持できない観測として使うが、課金状態の確実な検知とは呼ばない。書き込みが起きるまで切替を観測できないので、5m に切り替わった直後の一回の費用を防げない場合がある。unknown は送らない。TTL を固定している人も実際の書き込みを基準にする。5 分ごとの頻回送信は追加しない。規則にこの限界と親の費用の扱いを書く。

## Risks / Trade-offs

- [キャッシュの書き直し削減は未実測] → 後述の実エピック比較を完了条件として残す。既存ログによる模擬だけで合格にしない。
- [主が同じ瞬間に入力する競合] → 既存・入力待ち・空欄だけを対象にし、送信前にも状態を確認する。CLI の確認と送信の間まで原子的にはできず、並行入力を完全には防げない。固定文に一致しない実際の返事は発言除外で隠さず、通常の再開手順へ渡す。完全一致する主の入力は予約文として扱い、型どおりの返事と共に除外する限界がある。子の受信も予約文との一致を先に判定する。
- [質問ツール・許可画面では声かけを打てない] → 対象外として見送り、既存の主への返事と #1323 の再開を保つ。全ての停止方式でキャッシュが残るとは約束しない。
- [API/ログ不明時の見送りでキャッシュが切れる] → 誤送信や再起動を避けるために見送り、次の実際の返事で既存規則へ戻す。
- [実装ファイルが 5 個を超える見込み] → tasks に範囲を記す。独立 capability への機能分割ではないため spec は単一 change。本体は実装を渡す前に規模トリップワイヤーの扱いを決める。本 worker は実装しない。

## Validation and cost comparison

先行する実 CLI 観測確認を終えてから、スタブ Bats は送信条件・時刻境界・除外の対応・停止状態不変・wait の出力を検証する。Orca/tmux の部品は端末無し/実行中/入力済みで新規起動もキー送信もしないことを確認する。時刻は実時間待ちをせず制御する。予約文を主が打つ場合の除外と、型違い・複数行の返事の表示、stop=stopped-seen 不変・wait 継続・24 時間の基点不変も確認する。

#1379 の回帰として、20 分前の Z 付き cli/1h、3 分前の -05:00 付き cli/5m、`not a time` の cli/1h を置く。上限未指定の `dispatch wait 11` が stderr に `wait limit 21600 (parent cache 5m)` を出すことと、時差なしを UTC として比較することを確認する。

実装後のエピック 1 本について、既存 cost-ledger の facts/集計と会話ログから、比較元（#1038 等の実装前エピック）の同種の停止区間と比較する。親と子を分け、session/issue・時間帯・停止時間・モデル・会話量・TTL・リクエスト件数、cache_write_1h/5m・cache_read の tokens と USD、声かけ分と親の定期起床分を含む総費用を #1383 にコメントする。親の「1 時間以上静かだった後の起床」と子の「1 時間以上の返事待ち後の再開」を抽出し、実装後は声かけで空白が短くなっていても同じ待ち区間として数える。

差額は同じ pricing.json で算出し、件数と会話量の差を併記する。親・子それぞれに書き直し費用が減ったかと、維持費用込みではどうかを書く。実エピック未実行・該当区間ゼロ・比較不能ならその理由を明記して測定タスクを未完了にする。架空の計測値や送信の成功だけで受け入れ条件を満たした扱いにしない。

## Migration Plan

R1 APPROVE 後に実装・Bats・lint・実セッションの送受信確認・費用比較を進める。実装前の一回確認コマンドの出力契約を維持する。戻す場合はこの change の実装を revert し、親の #1379 の wait と実際の返事時の #1323 の規則は継続する。新しい常駐プロセスや状態スキーマの移行・削除は不要。
