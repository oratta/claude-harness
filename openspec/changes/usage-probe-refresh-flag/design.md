## Context

`usage-probe.sh` はスロットごとに次の 4 つをすべて満たすときだけ usage API を叩く（判定は `due` を求める python の中）: 鮮度（セッション記録の `observed_at` か snapshot の `fetched_at` が `USAGE_PROBE_STALE` 秒より古い）／間隔（前回の試行から `USAGE_PROBE_INTERVAL` 秒）／429 の待ち（連続 429 回数が 1 以上なら `USAGE_PROBE_INTERVAL × 2^(回数-1)`、上限 86400 秒）／オフでない。間隔と 429 の待ちは同じ `wait` 変数で測っており、回数 0 なら `wait = interval`、1 以上なら倍々の値になる。

手で取り直したい呼び出し元（flatmate #1717 のボタン）は、今は `USAGE_PROBE_STALE=0 USAGE_PROBE_INTERVAL=0` で叩いている。これだと 429 の待ちも 0 になるので、flatmate 側は待ち中のスロットがあると取り直しを諦めている。

## Goals / Non-Goals

**Goals:**

- 429 の待ちとオフの扱いはそのままに、鮮度と間隔の条件だけを外して 1 回取り直す呼び方を用意する
- 引数なしの既存の呼び出し（SessionStart の hook など）の振る舞いを変えない

**Non-Goals:**

- flatmate #1717 の呼び出しの切り替え（flatmate 側の別 issue）
- ロックで弾かれたことを呼び出し元に知らせる仕組み（今も弾かれると黙って exit 0。変えない）
- 429 の待ちの式や上限の変更

## Decisions

**指定は環境変数ではなく引数 `--refresh` にする。** 既存の設定（`USAGE_PROBE_STALE` など）は環境変数だが、環境変数は子プロセスに引き継がれる。手で取り直すための指定が、呼び出し元の環境に残ったまま hook などの別の probe 呼び出しに漏れると、そちらまで毎回取り直す。引数ならその 1 回の実行にだけ効く。既存の `--print-slots` と同じく `$1` で見る。名前は「取り直す」をそのまま表す `--refresh` にした（`--ignore-interval` も考えたが、鮮度の条件も外すので名前と中身がずれる）。

- 案: `USAGE_PROBE_FORCE=1` → 子プロセスへ漏れる。不採用
- 案: `--ignore-interval` → 鮮度も外す中身と合わない。不採用

**鮮度の条件（`USAGE_PROBE_STALE`）も外す。** issue の受け入れ条件は「前回の取得から 3 時間たっていなくても取り直す」で、前回の取得は snapshot の `fetched_at`。`fetched_at` が新しいスロットは鮮度の条件で落ちるので、間隔だけを外しても取り直せない。flatmate #1717 も両方を 0 にして叩いている。

**429 の待ちの長さは `USAGE_PROBE_INTERVAL` を基準のまま測る。** `--refresh` の判定では、連続 429 回数が 0 のスロットは待ち無し、1 以上のスロットは引数なしと同じ式で求めた待ちの中にいれば叩かない。待ちが明けたスロットは鮮度にかかわらず叩く。待ち中で叩かなかったスロットは試行に数えないので、試行状態ファイルのそのスロットの試行時刻と連続 429 回数は変わらない（試行の記録は叩いたスロットだけを書く既存の経路のまま）。

**引数の扱い。** `--refresh` 以外の未知の引数は、今と同じく黙って無視する（引数なしと同じ動き）。`--print-slots` との組み合わせは考えない（`--print-slots` は `$1` のときだけ効き、ロックより前で終わる）。

## Risks / Trade-offs

- [`--refresh` を短い間隔で繰り返し呼ぶと、待ち中でないスロットを何度も叩く] → 呼び出し元は人の操作（ボタン）とチケット使用の直後だけで、429 を受ければ次からは待ちに入る。待ちを破らないことがこの change の目的なので、それ以上の制限は足さない
- [別の probe がロックを持っていると `--refresh` も黙って何もしない] → 今と同じ挙動。呼び出し元は snapshot の `fetched_at` で取り直せたかを確かめられる

## Migration Plan

引数を足すだけで、既存の呼び出しは変わらない。戻すときは commit を revert する。
