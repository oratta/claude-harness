# Spec Delta

## MODIFIED Requirements

### Requirement: マージを止めるかの判定は全周共通にする

SKILL.md は、指摘がマージを止めるかどうかの判定を 1 か所に書かなければならない（MUST）。判定は全周（1 周目・2 周目・主の回答または決める役の裁定で開いた周）で同じでなければならない（MUST）: マージを止めるのは、深刻度が `blocking` で、根拠の引用を G が記録先の受け入れ条件または PR が触れる openspec spec（delta spec を含む）の原文と照合できた（または根拠が例外 3 種＝安全機構の穴・データ破壊・無言の機能不全に当たる）、かつ検証が `confirmed` の指摘だけとする。それ以外の指摘（`should`・`nit`・`plausible`・照合できない `blocking`）はマージを止めず、止めない指摘の振り分け表（「止めない指摘は振り分け表に上から当てる」Requirement）に通す（MUST）。振り分け表を通さずに issue にしてはならない（MUST NOT）。レビュアーが付けた深刻度ラベルは参考にとどめ、G の照合を判定の根拠とする（MUST）。

止める指摘が残ったときの動き方は、仕分け表（「指摘を受け取った G は仕分け表の順に当てる」Requirement）で決めなければならない（MUST）。SKILL.md は「一般則は 1 周目に適用し、2 周目からは収束ルールが優先する」のような、周によって判定を分ける記述を持ってはならない（MUST NOT）。

1 周目で failed にするとき、W に戻す修正対象の一覧には、止める指摘と段 A に当たる指摘だけを載せ、段 A に当たる指摘には「段 A・この PR で直す」と印を付けなければならない（MUST）。段 A に当たらない止めない指摘を、任意・ついで・序での修正候補としても W に渡してはならない（MUST NOT）。その指摘は G の振り分けの記録に残す（MUST）。段 A に当たる指摘の follow-up issue はまだ切らない（MUST）。段 B 以降は G が手順 3 へ進む時点で、未解決の止めない指摘に当て、指摘ごとの段と行き先を PR コメントに記録する（MUST）。

#### Scenario: 1 周目に should と plausible だけが残る

- **WHEN** 1 周目のレビューが `should` の指摘と `plausible` の `blocking` 指摘だけを返す
- **THEN** G は各指摘を止めない指摘の振り分け表に当てる。段 A に当たる指摘が無ければ failed にせず、段 B 以降の結果を PR コメントに記録して手順 3 以降へ進む。段 A に当たる指摘があれば `agent-review:failed` で W に戻す

#### Scenario: 1 周目に止める指摘がある

- **WHEN** 1 周目のレビューが、受け入れ条件の文を引用した `confirmed` の `blocking` 指摘を 1 件返す
- **THEN** G は仕分け表の順 2 に当て、`agent-review:failed` に付け替えて修正サイクルへ戻す

#### Scenario: 引用できない安全機構の穴

- **WHEN** 受け入れ条件と spec のどの文も引用できないが、根拠が安全機構の穴に当たり検証が `confirmed` の `blocking` 指摘が残る
- **THEN** その指摘はマージを止める指摘として扱われる

#### Scenario: 周ごとに判定を分ける文が残っていない

- **WHEN** SKILL.md を読む
- **THEN** 「この一般則は1周目に適用する」の文は無く、判定は 1 か所に書かれ、収束ルールの仕分けはその判定を参照している

#### Scenario: failed の周に修正対象と対象外の指摘が混ざる

- **WHEN** 1 周目に confirmed の止める指摘 B1、段 A に当たる指摘 A1、段 A に当たらない止めない指摘 N1 が届く
- **THEN** G は W に戻す修正対象一覧に B1 と A1 だけを載せ、A1 に「段 A・この PR で直す」と根拠を添え、N1 を「序でに直してよい」とも渡さず G の振り分けの記録に残し、手順 3 に進むときに段 B 以降を当てる

### Requirement: 段 A の直しは周の歯止めの内側だけで戻す

段 A に当たるのは、止めない指摘のうち、直さないと受け入れ条件（記録先の受け入れ条件、またはこの PR の change の delta spec。順 2 と同じ範囲）を満たせない指摘と、例外 3 種（安全機構の穴・データ破壊・無言の機能不全）に当たる指摘だけとする（MUST）。どちらでもない指摘は、直す場所がこの PR の diff が触れたファイルの中でも、直し方の行数が小さくても、今の PR で直さず段 B から当てる（MUST）。G はその指摘を W の修正対象一覧に載せず、「序でに直してよい」「足さなくても止めない」など任意の修正候補としても W に渡してはならない（MUST NOT）。受け入れ条件も delta spec も求めていない新しい部品・機能を足す提案は、行数によらず範囲外とする（MUST）。範囲外の提案を今の PR で直せるのは、例外 3 種に当たるときだけとする（MUST）。

G は 1 周目に段 A に当たる指摘を受け取ったら、止める指摘の有無によらず `agent-review:failed` で W に戻し、failed の PR コメントの一覧でその指摘に「段 A・この PR で直す」と印を付けなければならない（MUST）。止める指摘（順 2〜4）と同じ周なら 1 回の `agent-review:failed` にまとめ、順 5・順 6 との混在では順 2〜4 の指摘と同じに扱う（MUST）。段 A だけで戻した failed では手順 2-2 のモデル昇格を当てず、W のモデルを据え置く（MUST。戻す中身が止めない指摘で、モデルを上げても収束の見込みは変わらないため）。failed の return の原因分類には「段 A だけ（昇格なし）」と書く（MUST）。

2 周目以降の周の終わりには、段 A に当たる指摘が残っていても、それを理由に次の周を開けてはならない（MUST NOT）。その指摘は段 A に当たらないものとして段 B から当てる（MUST）。段 B 以降は、G が手順 3 へ進む時点で、未解決の止めない指摘に当てる（MUST）。

この振り分けの守備範囲は、受け入れ条件に要らない直しが PR に入ることを止めることである。入力は全周共通の判定で止まらなかった指摘（Codex・Task サブエージェントが書き、裏取りが無いものを含む）と、受け入れ条件・delta spec の文で、拾いたい誤りは、受け入れ条件に要らない直しが、触ったファイルの中で直せる・小さいという理由で PR に入ることである。例外 3 種に当たる指摘は、受け入れ条件に要らなくても、diff の外でも、行数によらず通す。例外 3 種の当てはめが甘くて要らない直しが通ることを塞ぎ切ることは完了条件にせず、見落としは PR レビューと周の歯止めで止める。

#### Scenario: 1 周目に段 A の指摘だけが届く

- **WHEN** 1 周目のレビューが、直さないと記録先の受け入れ条件 AC1 を満たせない `plausible` の指摘を 1 件だけ返し、G が AC1 の文と照合してそう読める
- **THEN** G は `agent-review:failed` で W に戻し、failed の PR コメントにその指摘を「段 A・この PR で直す」として載せて AC1 を添え、issue は作らない

#### Scenario: 直さないと delta spec の要件を満たせない指摘は段 A に当たる

- **WHEN** 1 周目のレビューが、この PR の change の delta spec の要件に反する `plausible` の指摘を 1 件だけ返し、その文は記録先の受け入れ条件には無い
- **THEN** G はその指摘を段 A に当てて `agent-review:failed` で W に戻し、failed の PR コメントに delta spec の要件名を添える

#### Scenario: 受け入れ条件に要らない小さな指摘は今の PR で直さない

- **WHEN** 1 周目のレビューが、この PR が変えたファイルの中で 3 行で直せる `should` を 1 件だけ返し、直さなくても受け入れ条件と delta spec の要件をすべて満たせて、例外 3 種にも当たらない
- **THEN** G は `agent-review:failed` にせず、その指摘を段 B から当てて手順 3 以降へ進む

#### Scenario: 新しい部品を足す提案は小さくても範囲外

- **WHEN** 1 周目のレビューが、受け入れ条件も delta spec も求めていない補助スクリプトを 10 行で足す `should` を返し、例外 3 種に当たらない
- **THEN** G はその指摘を範囲外として段 A に当てず、段 B から当てる

#### Scenario: 例外 3 種の止めない指摘は diff の外でも段 A に当たる

- **WHEN** 1 周目のレビューが、この PR が触れていないファイルの安全機構の穴を指摘する `plausible` の `should` を返し、受け入れ条件には要らない
- **THEN** G はその指摘を段 A に当てて `agent-review:failed` で W に戻し、当たる例外 3 種を failed の PR コメントに添える

#### Scenario: 2 周目の終わりに段 A の指摘が残る

- **WHEN** 2 周目の終わりに、段 A に当たる `should` が未解決で残り、止める指摘は無い
- **THEN** G は 3 周目を開けず、その指摘を段 B から当てて、結果を PR コメントに記録して手順 3 以降へ進む

### Requirement: 相乗りの参考コメント（段 D）と費用対効果（段 E）

段 D で、G は同じ場所を直す open の issue の候補があれば、その issue に「参考。この issue の受け入れ条件には足さない」で始まるコメントで指摘の中身と元の PR の URL を入れなければならない（MUST）。候補が複数あるときは、最も近い 1 件にだけ入れる（MUST）。G は、その issue をエピックの子にも配布の前提にも足してはならない（MUST NOT）。ただし、親の取得が失敗し続けたときの「範囲で成り立つ」に当たった指摘は、段 D を通さない（MUST。段 C の要件）。

段 E で、G は起きる見込みと起きたときの影響を、issue 1 件を通す手間（仕様・レビュー・ゲートを 1 回通す分）と比べ、見合えばエピックの外の新しい issue を作り、見合わなければ捨てて PR コメントに理由を 1 行残さなければならない（MUST）。ただし、親の取得が失敗し続けたときの「範囲で成り立つ」に当たった指摘は、この判定をせずエピックの外の新しい issue にする（MUST。段 C の要件）。費用対効果を比べるのは段 E だけとする（MUST。段 B で捨てる指摘は効果そのものが無く、段 D は相乗りで手間がほぼかからないため）。親の注意書きが新しい問題を子 issue にするよう指定していても、段 C で完了条件に効かないとした指摘を、段 E のあとでエピックの子に足してはならない（MUST NOT）。

#### Scenario: 同じ場所の issue に参考として入れる

- **WHEN** エピックの完了条件に効かない止めない指摘の場所のパスについて、スクリプトが同じ場所を直す候補 #886 を返す
- **THEN** G は #886 に「参考。この issue の受け入れ条件には足さない」で始まるコメントを入れ、コメントの URL を PR コメントに記録し、新しい issue を作らない

#### Scenario: 手間に見合わない

- **WHEN** 候補が `(該当なし)` で、指摘が起きても影響がテストの見出しの読みやすさにとどまる
- **THEN** G は issue を作らず、PR コメントに理由を 1 行残す

#### Scenario: 段 C で効かず段 E で見合う指摘は注意書きがあっても外の issue になる

- **WHEN** エピックの子の PR の止めない指摘が段 A に当たらず、段 B でいまの範囲で成り立ち、段 C で完了条件に効かず、段 D の候補が無く、段 E で手間に見合い、親の注意書きに「新しい問題は新しい子 issue」とある
- **THEN** G はエピックの外の新しい issue を作り、段 C・段 E の判定とその URL を仕分けの PR コメントに残し、親の注意書きを理由にその issue をエピックの子には足さない

#### Scenario: 段 C で効かない指摘に参考の候補がある

- **WHEN** 段 C で完了条件に効かないとした指摘に段 D の同じ場所を直す候補があり、親の注意書きは新しい問題を子 issue にするよう指定している
- **THEN** G は候補に受け入れ条件へ足さない参考コメントを残し、注意書きを理由に候補や新しい issue をエピックの子には足さない
