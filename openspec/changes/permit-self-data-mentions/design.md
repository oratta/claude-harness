# Design

## Context

- 動機は proposal.md の Why。今の判定は `git-destructive-guard.sh` の `self_permit = is_child and PERMIT_NAME in command`（776 行付近）で、コマンド文字列に `git-guard-permit` が 1 文字でも入れば `permit-self` になる。`permit-self` は回数に数えられ、2 回目の拒否で子は `continue: false` で打ち切られる
- 名前を見る規則は「シェルの書き方を 1 つずつ読み分けると、塞ぐたびに別の書き方が出る」ために置かれた（archive の 2026-11-10-git-guard-block-child-permit-writes までの経緯。spec の要件「子は許可を書くスクリプトを呼べない」）。この change でも、実行される書き方を数え上げて止める形には戻さない
- git ガードはセキュリティ境界ではない（spec の守備範囲。子・hook・親は同じ uid で動く）。今でも、名前を引用符で割る（`git-guard-perm''it.sh`）・グロブ（`git-guard-p*.sh`）・変数で組み立てる形で、子はスクリプトを名前を書かずに呼べる。許可が効くのは使う時点の一時領域の判定を満たす scratchpad の中の repo だけで、許可を書いたことは `permit-log.jsonl` に残る
- 字句読み（`join_words`〜`judge`。159〜620 行付近）は自動消化の Draft PR #1463 が触っている。この change は字句読みの関数を変えず、呼ぶだけにする

## Goals / Non-Goals

**Goals:**

- harness を直す W が、名前を grep のパターン・`cat` の引数・ヒアドキュメントの本文に書いても止まらない（issue #1166 の受け入れ条件 1）
- `bash <許可スクリプトのパス>` と直接の実行は今までどおり `permit-self` で止まる（受け入れ条件 2）
- 止めなくなる形が、今は止まっていて、今の規則でも名前を書かずに届かない偽造の経路を開かない

**Non-Goals:**

- 名前を書かない呼び方（引用符で割る・グロブ・変数・シンボリックリンク・コピー）を止めること（今も通り、spec の守備範囲で許している）
- 拒否後に親が打ち直しを指示して許可する仕組み（#1173）、`cd` と `rm` の形への親の許可（#1159）
- 子への拒否の理由文の見直し（PR #1615 のレビューの nit。下の決定 5）

## Decisions

### 決定 1: コマンド全体が「読むか表示するだけのコマンド」だけでできているときに限って止めない

コマンドを今の字句読み（`run(lex(...))`）で読み、読み終えた単純コマンドすべて（`$(...)` の中、ヒアドキュメントの引用されていない本文の中の `$(...)` を含む。バッククォートの中身は字句読みが返す並びを同じ規則で読み直す）の先頭の語が一覧に入るときだけ、`self_permit` を偽にする。1 つでも一覧に無い単純コマンドがあれば、名前がどこにあっても今までどおり `permit-self` にする。読み切れないとき（`Unclosed`・`TooMuch`）も `permit-self` にする。

この形なら、名前がどの位置に出ているかを調べなくてよい。一覧のコマンドは引数からほかのプログラムを起動しないので、名前が引数・ヒアドキュメントの本文・here-string・リダイレクトの行き先・コメントのどこにあっても実行されない。シェルの書き方を数え上げるのではなく、通す側を小さく数え上げる（通す側に入らない書き方は、どんな新しい書き方でも止まる側に落ちる）。

字句読みの扱わない構文（プロセス置換・`{`・関数定義・zsh の `(...)` の修飾子）は、字句読みが `(` で単純コマンドを区切り、`{` や修飾子を先頭の語として返すので、一覧に当たらず止まる側に落ちる（試作で `grep x <(bash <パス>)`・`{ grep x <パス>; }`・`f() { bash <パス>; }; f` が止まることを確かめた）。

検討した代案:

- **実行される位置を数え上げて止める**（先頭の語・`bash`/`sh` の引数・`source`・`BASH_ENV=`・`eval`・`xargs`・`find -exec`・パイプの先のシェル・インタプリタ…）: 名前を見る規則を置いた理由そのもの（塞ぐたびに別の書き方が出る）に戻る。採らない
- **名前の出現ごとに位置を見て、引数やヒアドキュメントの本文なら通す**（ほかのコマンドは問わない）: `cat > x.sh <<'EOF'`（本文に `<パス> k ok`）のあとに `bash x.sh` を続ける形や、`echo <パス> | bash` が通る。採らない
- **文字列として出る形を完全一致の型で並べる許可リスト**（`grep ... "<名前>" ...` の形だけ等）: 型から外れる正当なコマンド（`| head` を足す、ヒアドキュメントで書く）が止まり続ける。決定 1 の一覧はこの代案を広げた形にあたる

### 決定 2: 一覧は `grep`・`egrep`・`fgrep`・`cat`・`head`・`tail`・`wc`・`ls`・`echo` の 9 つ。語の一致は文字列ちょうど

入れる条件は「引数・オプション・設定からほかのプログラムを起動せず、シェルの変数も設定しない」。外したもの: `sed`（GNU sed の `e` 命令と `w` 命令）、`awk`（`system()`）、`rg`（`--pre` で前処理のプログラムを起動）、`find`（`-exec`）、`xargs`、`git`（`-c`・リポジトリの設定・alias・pager・外部 diff）、`less`（`LESSOPEN`・`!`）、`printf`（`-v` で変数を設定）、`cd`（それ自体は無害だが、最小の一覧にするため入れない。止めすぎの例として守備範囲に書く）。

先頭の語は字句読みで読んだあとの文字列が一覧の語とちょうど一致するときだけ当たる。パスを付けた形（`/tmp/x/grep` に bash の写しを置く形）・前置き（`command`・`env -S` など）・変数の代入（`PATH=/x/bin grep`）は当たらない。同じコマンドの中で alias や関数を作る形は、`alias`・`f()` が先頭の語になるので止まる。

### 決定 3: 偽造の経路の検討

止めなくなる形ごとに、今の規則で名前を書かずに同じ結果に届くかを見た。

| 止めなくなる形 | 起きうること | 今の規則で名前を書かずに届くか |
|---|---|---|
| `cat <パス>`・`grep ... <パス>` で読む | スクリプトの中身を読む | 届く（`cat /x/scripts/git-guard-p*.sh`）。秘密は無い |
| `echo` / `cat` のヒアドキュメントで、名前を含む中身をファイルに書く（`.sh`・シェルの起動ファイル・`BASH_ENV` に渡すファイル） | 別の呼び出しで、そのファイルを名前を書かずに実行する | 届く（`echo /x/scripts/git-guard-perm''it.sh k ok > x.sh`）。2 回目の呼び出しは今も名前が無いので止まらない |
| リダイレクトの行き先に名前がある（`cat > <パス> <<EOF`） | スクリプトを上書きする | 届く（`cat > /x/scripts/git-guard-p*.sh`・Edit ツール）。プラグインのファイルの書き換えはこの hook の外（git ガード自体も書き換えられる） |
| 同じコマンドの中で書いて実行する | ― | 一覧に無い `bash`・`chmod`・`./x.sh` が要るので、今までどおり止まる |
| 名前を出力してシェルや `xargs` に渡す | ― | 渡す先が一覧に無いので、今までどおり止まる |

名前を書かずに同じスクリプトを実行される経路（`bash -c`・`eval`・`source`・変数・`$(...)`・`xargs`・`find -exec`・`BASH_ENV`・パス指定・シンボリックリンク・コピー・python などのインタプリタ）は、名前を書けば今までどおり止まり、名前を書かなければ今も通る。ほかの層はこれを塞いでいない: Write / Edit の hook（`git-guard-base-write-guard.sh`）は Write / Edit / NotebookEdit だけを見る。要件「子は Bash のコマンドで許可の置き場所を名指しできない」は置き場所の 2 つの名前がコマンドにあるときだけ止め、許可を書くスクリプトは置き場所のパスを拒否の記録のパスから自分で組み立てるので、子のコマンドにその 2 つは出ない。残る歯止めは、許可を使う時点の一時領域の判定（scratchpad の中の repo にしか効かない）と `permit-log.jsonl` の記録で、これはこの change で変わらない。

結論: 止めなくなる形は、どれも今の規則で名前を引用符で割るだけで届く結果にしか届かないので、新しい種類の経路は開かない。開くのは、ルールを読み飛ばした子が「分かりやすく」書いたときに 1 段目で止まらない形のうち、「名前を含む中身をファイルに書いて、別の呼び出しで実行する」2 段の形である。2 段目は名前を含まないので、今も止められていない。

### 決定 4: `permit-self` は打ち切りの数え方に含めたまま

`permit-self` だけに当たった拒否も、今までどおり回数に数え、拒否の記録を書く。

- 読み分けのあとに `permit-self` に当たるのは、一覧に無いコマンドを含み、かつ名前を含むコマンドだけになる。正当な作業で当たるのは、一覧に無いコマンドで名前を文字列として扱う形（`sed -n`・`rg`・`git log`・`cd` のあとの `grep` など）に限られ、子は Read ツールか一覧のコマンドで書き直せる
- 打ち切りは、拒否されたあとも書き方を変えて試す子を親に返すためにある。スクリプトを自分で呼ぼうとした子は、その返すべき子にあたる
- 代案（`permit-store` と同じく数えず、記録も書かない）は、要件「同じ子への拒否の繰り返しを打ち切る」「子への拒否を記録し、親が 1 回だけ通せるようにする」「子は Bash のコマンドで許可の置き場所を名指しできない」の 3 つを書き換える。止めすぎの残りが小さくなったので、この change では採らない。止めすぎが続いて W が打ち切られる例が出たら、別の issue で数え方を変える

### 決定 5: 子への理由文は変えない

PR #1615 のレビューの nit（名指し拒否の理由文が「親の許可を受けられる打ち方の例」と「親もこのコマンドの許可を書けない」を並べる）は、受け入れ条件ではない。直すには spec の要件「拒否理由は承認の取り方を案内する」の MUST（子への拒否の理由に「実パスで単独のコマンド」の文を必ず入れる）を、種類によって外す変更が要る。打ち直しの指示の範囲（#1173）に近いので、この change では触らない。

## Risks / Trade-offs

- [一覧のコマンドが、知らない版や別名でほかのプログラムを起動する] → 一覧は起動の手段が知られていないものに絞った。主の環境の alias（例: `cat` を別のコマンドにする）は子が同じ呼び出しの中で作れない。見つかったら一覧から外す（外す向きは止めすぎにしか倒れない）
- [字句読みの扱わない構文で、一覧のコマンドだけに見えるのに実行される形がある] → 扱わない構文の多くは `(` で区切られて一覧に無い語が先頭に来るので止まる側に落ちる。それでも抜ける形は、名前を引用符で割る形と同じく spec の守備範囲で許す範囲に入る（セキュリティ境界ではない）
- [止めすぎが残る（`sed -n`・`rg`・`git log`・`cd` のあと・テストの実行をつないだもの）] → 守備範囲に止めすぎの例として書く。回数は数えるので、2 回当たると打ち切られる（決定 4）
- [Draft PR #1463 と字句読みの差分が重なる] → 字句読みの関数を変えず、`self_permit` の判定の近く（770〜790 行付近）だけを変える。#1463 が先にマージされたら取り込んでから bats を回す
- [2 回目の字句読みの時間] → 名前を含む子の呼び出しにだけかかる。仕事量の上限（`WORK_LIMIT`）を共有し、超えたら止める側に倒す

## Migration Plan

- 戻すときは `self_permit` の判定を `is_child and PERMIT_NAME in command` に戻し、bats の該当テストを戻すだけでよい（記録や回数の形式は変えない）
