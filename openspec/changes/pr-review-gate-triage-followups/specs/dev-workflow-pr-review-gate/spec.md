### Requirement: 一覧の一致で閉じる（順 3）

SKILL.md は、順 3 の閉じ方を次のとおり規定しなければならない（MUST）。W は、修正前 SHA・検索コマンド・全ヒットに「直した／該当しない理由」を付けた表を 1 つの PR コメントに投稿してから push する。修正前 SHA は、W が修正に着手する直前の HEAD（G が `agent-review:failed` を付けた周の対象 HEAD）の 40 桁フル SHA とする（MUST）。

SKILL.md の順 3 の節は、一覧表の PR コメントの書式を次のとおり明記しなければならない（MUST。worker.md と #355 の照合表が揃える正本）:

- 1 行目 `## 一覧（順 3）`、続けて `修正前 SHA: <40 桁>` の行と `検索コマンド: <コマンド>` の行
- 検索コマンドは、grep の語のときは `git grep -n <語の指定> <rev> -- <パス>` の形で、`<rev>` を含めて書く（G が修正前 SHA と HEAD に置き換えて実行する）。作業ツリーに対する `grep -rn` の形で書いてはならない（MUST NOT）
- grep の語のときの表の列は `| ファイル | 行（修正前 SHA） | ヒットした行の本文 | 扱い |`。場合分けの軸（例: 先頭バイトなら 0x00〜0xFF）のときの表の列は `| 軸の値 | 扱い |`
- 扱いの欄は `直した` か `該当しない: <理由>` のどちらかちょうどとする

G はレビューをせず、次の 2 段で照合する（MUST）。最初に `git merge-base --is-ancestor <修正前 SHA> HEAD` で修正前 SHA が HEAD の祖先であることを確かめ、祖先でなければ W に表の出し直しを求める。

1. 修正前 SHA で検索コマンドを実行し、ヒットの集合が表の全行（扱いを問わない）と一致するかを見る
2. HEAD で同じ検索コマンドを実行し、残ったヒットがすべて、扱いが「該当しない」の行に対応するかを見る。対応は「ファイル」と「ヒットした行の本文」の組で取り、行番号では取らない。同じ組が複数あるときは件数で照合する

場合分けの軸のときは、ヒットの集合がコミットによらず軸の全域で決まるので、G は 1 段目として表の行の集合が軸の全域と一致するかだけを見て、2 段目を行わない。どちらの段でも一致しなければ、その差分（表に無いヒット、ヒットに無い表の行、「該当しない」の行に対応しない HEAD のヒット）だけを W に返す。差し戻し（表の出し直しを求めた場合を含む）は 1 回までとし、2 回目も一致しなければ順 6 の型に落とす（MUST）。検索コマンドや軸の全域を W が書けない指摘は、順 3 に当ててはならない（MUST NOT）。

順 3 の照合はレビューの周に数えない（MUST）。G はレビューをしないため、周回キャップとは別に差し戻し 1 回の上限で止める。同じ failed で W に戻した指摘が順 3 だけなら、集合が一致して閉じたあとに差分限定の再レビューは行わず、周を消費しない（MUST）。順 2・順 4 の指摘が同じ failed に含まれていれば、それらの指摘の差分限定の再レビューは通常どおり行い、周を 1 つ消費する（MUST）。G は順 3 の表の「該当しない理由」の正否を判定しない（集合の一致だけを見る）。

### Requirement: 同じ型の再発は決める役が方式を裁定する（順 6）

SKILL.md は、順 6 に当たった指摘について、決める役（`dev-workflow:decider`）が方式（全部列挙してから直す／切り出す）を裁定することを規定しなければならない（MUST）。決める役が裁定するのは方式だけで、止めるかどうかの判定は G が行う（MUST）。G は孫を持てないので、Status `needs-decider` で return し、本体が決める役を起こして裁定を受け取り、裁定を渡して G を再開する（MUST。本体の動きは `dev-workflow-develop` の「G の needs-decider を受けた本体の動き」Requirement）。決める役のモデルは既存の残量モードの規定に従う。

G は裁定を受け取ったら、裁定の内容を 1 行目 `決める役の裁定: 全部列挙してから直す` または `決める役の裁定: 切り出す` の PR コメントとして記録し、仕分け欄にも同じ内容を書く（MUST）。「PR ごとに 1 回まで」の回数は、G が再 spawn・再開されたときに、1 行目が正規表現 `^決める役の裁定: (全部列挙してから直す|切り出す)$` に完全一致する PR コメントの件数を、`gh api --paginate --slurp` で全ページから数える（MUST。G のコンテキストに回数を持たせない）。1 回目の裁定が「切り出す」だった場合もこの 1 回に数え、2 回目の順 6 は決める役を起こさず「切り出す」として扱う（MUST。厳しい側に倒す意図）。

本体から「裁定なし（入力不足）」を受け取ったら、G は `決める役の裁定:` の PR コメントを残さず（裁定の回数に数えない）、仕分け欄に「決める役の裁定なし（入力不足）」と書き、その指摘を「切り出す」として順 5 と同じ経路で主に聞く（MUST）。

裁定が「全部列挙してから直す」なら、G は `agent-review:failed` に付け替え、W に順 3 と同じ形の一覧を作らせて次の周に入る（MUST）。ただし、同じ周の順 5 の指摘に主がまだ回答していなければ、failed に付け替えずに保留のまま待つ（MUST。処理順は「順 5 と順 6 が同じ周に混ざったときの処理順」Requirement）。この裁定で周を開けるのは PR ごとに 1 回までとし、2 回目の順 6 は「切り出す」として扱う（MUST）。裁定が「切り出す」なら、順 5 と同じ経路で主に聞く（MUST）。決める役の裁定で開いた周は、主の回答で開いた周と同じに扱い、その周の終わりにも仕分け表を適用する（MUST）。
