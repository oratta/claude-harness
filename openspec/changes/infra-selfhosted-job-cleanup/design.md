## Context

flatmate#1563 の掃除は、`scripts/test.sh` が `.test-run/<PID>` に残す記録を `scripts/stop-tests.sh` が読んで、起動時刻が一致する実行とその子孫だけを止める作りで、`ci.yml` の最後の手順 `if: always() && ...` がそれを呼ぶ。この記録とスクリプトは flatmate のリポジトリの中にあり、infra の雛形から CI を入れるリポジトリには無い。そのため「記録で決める」部分は移せず、「ジョブの最後に `always()` で、終わり方によらず走らせる」形と「止める相手をジョブの作業ディレクトリに閉じる」考え方だけを移す。

セルフホストのランナーは 1 本につき作業ディレクトリが 1 つで、同時に走るジョブは 1 つ。ランナーごとに作業ディレクトリが分かれるので、`$GITHUB_WORKSPACE` の下に cwd を持つプロセスは、そのジョブが起こしたものと見なせる。

## Goals / Non-Goals

**Goals:**

- ジョブが成功・失敗・キャンセル・上限超過のどれで終わっても、そのジョブの作業ディレクトリの下に cwd を持つプロセスがランナーの Mac に残らない
- GitHub のランナーでは何もしない
- 同じ Mac で走るほかのジョブのプロセスを止めない

**Non-Goals:**

- cwd が作業ディレクトリの外に移ったプロセス（`cd /` した子など）の掃除
- ランナーのプロセス自体が落ちて、ジョブ終了時の手順が走らなかった場合の掃除（#1567 の見張り）
- 既存リポジトリへの反映そのもの

## Decisions

### 1. 止める相手は「`$GITHUB_WORKSPACE` の下に cwd を持つプロセス」にする

`lsof -a -d cwd -F pn` で全プロセスの cwd を取り、パスが作業ディレクトリと等しいか `<作業ディレクトリ>/` で始まるものを選ぶ。前方一致だけだと隣のディレクトリ（`foo` と `foo-bar`）を巻き込むので、区切りの `/` まで含めて比べる。

退けた案:

- プロセス名で絞る（`pkill -f node` など）。同じ Mac のほかのランナーやほかのジョブを巻き込む。issue の「同じ Mac で走っているほかのジョブを止めない」に反する
- flatmate と同じ記録（`.test-run/`）で決める。記録を書く側（`scripts/test.sh`）が雛形利用先に無い
- ランナーの子孫を辿る。ジョブの終わりには親を失って init の子になっているものが残るので、今回の事故そのものを拾えない

受け入れる制約: cwd を作業ディレクトリの外へ移したプロセスは止まらない。この残りは #1567 の見張りの役割で、足りない実例が出たら別の change で足す。

### 2. 自分自身とその祖先は止めない

手順を走らせているシェルは cwd が作業ディレクトリなので、除外しないと自分を止める。`$$` から親を辿って（`ps -o ppid= -p`）初期プロセスまでの PID を除外リストにする。祖先にはランナーの Worker などが入るが、除外して困ることは無い。

### 3. 止め方は TERM、待ち、残ったものだけ KILL

先に TERM を送ってプロセス自身に後始末（`wrangler dev` の子の終了など）をさせ、5 秒待って、まだ生きているものに KILL を送る。止めたい PID が既に消えているのは正常なので、`kill` の失敗は無視する。

### 4. セルフホスト限定は `runner.environment == 'self-hosted'`

`if: always() && runner.environment == 'self-hosted'`。`runner.environment` は GitHub のランナーで `github-hosted`、セルフホストで `self-hosted` になる実行時の値で、`vars.CI_RUNNER` の値（`self-hosted` 以外のラベルを付けているリポジトリもありうる）に依らない。`always()` は、キャンセルと上限超過のあとにも手順を走らせる。

### 5. 失敗は隠さない。ただし止める相手が無いことは失敗ではない

止める相手が無ければ 0 で終わる。`lsof` が無いときは、掃除ができないことを赤で見せるため非 0 で終わる（`|| true` と `continue-on-error` は付けない）。

### 6. 手順は雛形に直書きし、両ジョブで同じ文面にする

別ファイル（`templates/scripts/` に置いて配る）にすると、雛形から CI を入れるときに配る手順が増え、反映先でファイルが欠ける事故が起こる。数十行なので直書きする。`ci.yml.template` の `test` と `weekly-full.yml.template` の `full` で同じ `run:` にし、bats で 2 つの文面が一致することを検査する。

## Risks / Trade-offs

- `always()` の手順が上限超過のあとに走ることはマージ前のテストでは確かめられない → bats では `if` の式と位置を静的に検査し、止める範囲は偽のプロセスで実際に走らせて検査する。上限超過後の実行は GitHub Actions の仕様として flatmate#1570 で裏付けが取られている
- 作業ディレクトリの外に cwd を移したプロセスは残る → Non-Goals のとおり、見張り（#1567）の役割
- 作業ディレクトリを cwd にして常駐させたい利用者のプロセスがあれば止まる → 作業ディレクトリはジョブごとの置き場なので、常駐は置かない前提。コメントに書く
- 雛形に同じ文面が 2 つあり、片方だけ直す事故が起こりうる → bats で一致を検査する

## Migration Plan

雛形の変更なので、新しく入れるリポジトリは次の `/infra-setup` から効く。既存リポジトリは SKILL.md の手順で手で書き足す。戻すときは差分を戻す。
