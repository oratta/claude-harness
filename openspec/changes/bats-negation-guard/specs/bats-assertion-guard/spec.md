## ADDED Requirements

### Requirement: 単独文の否定検査 `! cmd` はすべてガードされている
`git ls-files '*.bats' ':(exclude)_longruns/'` で見つかる bats ファイルのうち、単独の文として置かれた否定検査 `! cmd`（`! [[ ... ]]` を含む）は、テスト本文中の位置を問わず（最後の文も含む）すべて `|| return 1` などのガードを伴わなければならない（SHALL）。

対象の定義: 行頭（空白のみ）から `!` に続く空白（`! `）で始まる行。次は対象外（数えない）:
- `if`/`while` の条件式として使われる `! cmd`（行が `if`/`while` で始まるため、上記の対象定義に一致しない）
- 複数行にまたがる `! cmd`（継続行 `\` を含む文は対象定義の1行判定に一致しない）
- パイプライン途中に置かれた否定（`cmd1 | ! cmd2` のように行頭が `!` でない形）
- 既に `|| return 1`（末尾コメント可）で終わる行（ガード済み）

対象を `git ls-files '*.bats' ':(exclude)_longruns/' | xargs grep -nE '^[[:space:]]*! '` で実測した結果、35ファイル・179行が該当し、うち `plugins/cost-ledger/tests/gate-report.bats` の13行は既に `! cmd || return 1` の形でガード済みだった。残り34ファイル・166行を対象とし、ヒアドキュメント内の fixture データ・複数行にまたがる `! cmd`・パイプライン途中の否定はいずれも0件だった。

対象166行には `plugins/statusline/tests/statusline-multi-account.bats:215,216,303` の否定形 `[[ ]]`（`! [[ "$line" =~ ... ]]`）を含む（`bats-assertion-guard` の既存要件「単独文の `[[ ]]` アサーションはすべてガードされている」は行頭が `[[ ` で始まる行だけを対象とし、否定形は対象外としていたため、この要件で別途カバーする）。

#### Scenario: ガード無しの対象行が 0 件である
- **WHEN** 次のコマンドを実行する
  ```
  git ls-files '*.bats' ':(exclude)_longruns/' \
    | xargs grep -nE '^[[:space:]]*! ' \
    | grep -vE '\|\| return 1[[:space:]]*(#.*)?$'
  ```
- **THEN** 出力が 0 行である（末尾に `|| return 1` を伴わない対象行が存在しない）

#### Scenario: ガード対象の判定に位置を使わない
- **WHEN** テスト本文の中に単独文の `! cmd` を追加する
- **THEN** それがテスト本文の最後の文であっても、途中の文であっても、ガードが必要である（同じ要件が適用される）

### Requirement: `! cmd` のガード漏れはバッシュのバージョンに関わらず常に検出を素通りする
`!` によるコマンドの反転は POSIX/bash の `errexit`（`set -e`）除外規則のひとつであり、`[[ ]]`/`(( ))` の非ゼロ終了と異なりバージョン依存の修正対象になっていない。したがって、この規約が実際に効いていることを確認する常設テストは、`#284`（`bats-assertion-guard` の `[[ ]]` 向け実演テスト）と異なり bash のバージョンによる分岐を必要としない（SHALL）。

#### Scenario: ガード付き fixture はどの bash バージョンでも fail する
- **WHEN** 途中に `! false`（または相当する必ず失敗する否定検査）を `|| return 1` 付きで置いた fixture テストを子プロセスの bats で実行する
- **THEN** 実行した bash のバージョンに関わらずそのテストは fail する（`not ok` として報告される）

#### Scenario: ガード無し fixture はどの bash バージョンでも素通りする
- **WHEN** 途中に `! false`（または相当する必ず失敗する否定検査）をガード無しで置いた fixture テストを子プロセスの bats で実行する
- **THEN** 実行した bash のバージョンに関わらずそのテストは `ok`（素通り）として報告される（`skip` は発生しない）
