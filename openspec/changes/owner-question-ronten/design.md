## Context

動機は proposal.md の Why を参照。主への確認の型は正本 `output-styles/readable.md` の節 3 にあり、短い版 `rules/communication-style.md` と、型を使って依頼文を組み立てる場所（pr-review-gate の宣言の書式と保留の段、develop の子の停止の記録と親の手順 8、CI の見張りの記録の例）がそれを参照している。pr-review-gate の宣言は文書であると同時に機械が読む入力で、行頭の `リスクなし` / `主のリスク許容が必要`、2 行目の `対象 HEAD:`、主の返事の `主の回答: 許容` を自動マージの判定と `owner-reply-check.sh` が照合している。

## Goals / Non-Goals

**Goals:**
- 主が確認の 1 通目だけで、推奨どおりと一言返せば済む話か、自分の観点を足して決める話かを見分けられるようにする
- 7 分類に当たっただけの変更で、リスク内容の作文と「リスクを許容するか」の問いを生まないようにする

**Non-Goals:**
- 送る前に文面を機械で確かめて書き直させる hook（#1215 の範囲）
- 宣言の照合の仕組み（`owner-reply-check.sh`・自動マージの判定）の変更
- 常時注入の予算の変更

## Decisions

### 論点を「主の側にしか無い観点を足すと結論がよくなる点」と定義する

論点の有無はこの定義だけで決める。「メリットもデメリットも大きい」のような条件を足さない。観点が欠けていればメリットやデメリットの大きさも測れないので、大きさを条件にすると判定がエージェントの見立てに依存する。判断材料がエージェント側にあるもの（コードや設定の細部）と、長い背景説明を共有しないと主が判断できないものは、足りないのが主の観点ではなくエージェント側の情報なので論点なしとし、エージェントが決める。主に情報を渡して議論できる形に仕立てることを、論点を作る手段として認めない。

casting の委任の定義（`openspec/specs/casting-delegation/spec.md` の要件「委任の定義正本」）にも論点の言い方があるが、主の観点を足すと結論が変わる点という向きは同じで、別の定義を立てたものではない。

検討した案: 論点を「議論すべき点」と辞書どおりの広い意味で使う。これだと決まりで聞いている確認にも論点があるように読め、今回の作文の原因が残る。`rules/perspective-casting.md` の手順 2 が広い意味で「論点」を使っていたので、「判断に必要な観点」に言い換えて定義と揃えた。

### 宣言の行頭に 3 つ目の文言を足さず、4 行目で論点の有無を書き分ける

「主のリスク許容が必要」の宣言の 4 行目を `論点なし — 分類に当たったので決まりで主の OK が要る…` と `論点あり — この変更を入れることで新たに生じるリスク: …` のどちらかにする。

検討した案: 宣言の行頭に `リスクなし` / `主のリスク許容が必要` に並ぶ 3 つ目の文言（例: 決まりで主の OK が要る）を足す。採らなかった理由は、行頭の文言を自動マージの判定と `owner-reply-check.sh` が照合しているため。3 つ目を足すと両方の照合とその bats を直す必要があり、照合が新しい文言を知らない環境ではマージ可否の判定が変わる。4 行目なら照合される行に触れずに書き分けられる。

### 主への依頼文は宣言を写さず、正本の型で書く

「この形式以外で主にリスク承認を求めない」を外し、依頼文は正本の節 3 の型で書くとした。宣言は記録と照合のための形で、主が読む文面とは役割が違う。宣言をそのまま主に送ると、手続きの言葉（「リスク宣言を許容するか」）の問いになる。`stages/hold.md` は論点なしの宣言のときは論点なしの 3〜4 行で依頼すると書き、develop の親の手順 8 も「親経由のリスク許容の依頼」という呼び名をやめて正本の型の報告にした。主が答えとして打つ語が子のゲートの照合に使われる点は残す。

### 受け入れるリスクは「推奨を選ぶことで新たに生じるもの」に限る

他の案や何もしない場合には無いものだけを書く。どの変更にも当てはまるもの（見落としがあると壊れる）は比較の役に立たないので書かない。2026-08-10 の融合より前の `rules/communication-style.md` にあった線引きを戻す形になる。

## Risks / Trade-offs

- [常時注入の文が増えて予算を超える] → 正本の節 3 と短い版の文を詰め、`tests/injection-budget.bats` を予算を動かさずに通す
- [論点の判定がエージェントの見立てに寄り、論点ありを論点なしと書く] → 論点なしでも推奨と決まりが何を守るかを書かせ、主が一言で止められる形にする。送る前の機械の確認は #1215 で足す
- [宣言の 4 行目の書き分けを照合が見ないので、書式から外れても止まらない] → `tests/owner-question-style.bats` で雛形の 2 つの形と、外した文が無いことを確かめる
