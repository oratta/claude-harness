## MODIFIED Requirements

### Requirement: 行から抽出する事実
システムは会話ログの各行から、帰属を導く前の**事実だけ**を抽出する段を持 MUST つ。区間の帰属は投稿が来るまで確定しないため、1 行ずつ追記する経路（後続の台帳）が書けるのは導いた帰属ではなく事実に限られる。抽出する事実は次のとおりと SHALL する。

- `requestId`（無ければ `uuid`）— 重複排除の鍵
- `uuid` — その行の `uuid`（無ければ空文字）。同じ応答の複製された先頭の行と後続行を区別する鍵（次の節の Requirement）
- `timestamp` — 区間を並べる鍵
- `sessionId` — 区間を切る単位
- `isSidechain` — サブエージェントの行かどうか
- リポジトリ識別子 — `cwd` から導く（次の Requirement）
- `repo_inferred` — リポジトリ識別子を削除済みの `cwd` の文字列からの推定で決めたときだけ `true` で持つ。それ以外の行は欄を持たない（「リポジトリ識別子と worktree の畳み込み」）
- `gitBranch`
- `message.model`
- トークン 5 種 — 入力 `usage.input_tokens`、出力 `usage.output_tokens`（その行の値。応答の途中の行では暫定値でありうる。通常の事実は先頭の行の値を持ち、応答単位の確定値は、先頭の事実の出力と同じ `requestId` の補足の事実の出力の合計になる。取り方は次々の Requirement）、キャッシュ書込 5m `usage.cache_creation.ephemeral_5m_input_tokens`、キャッシュ書込 1h `usage.cache_creation.ephemeral_1h_input_tokens`、キャッシュ読出 `usage.cache_read_input_tokens`
- 触った issue 番号の列 — その行のツール呼び出しから拾う（次の Requirement）
- 投稿の印 — その行が区間の境界かどうか（次の Requirement）

キャッシュ書込の 5m と 1h がどちらも無い、または両方 0 のとき、システムは `usage.cache_creation_input_tokens` を 5m 扱いで読 MUST む。

守備範囲: 入力は、Claude Code が `CLAUDE_CONFIG_DIR` の配下に書く会話ログの assistant 行（メインとサブエージェントのログ）と、そこから作った台帳の行。拾いたい誤りは、応答の途中の行の暫定の出力トークンだけを数えて、サブエージェントの出力トークンと金額が実際より小さく出ること。通ることを許す入力は、どの行にも `stop_reason` が付かず確定値が会話ログのどこにも無い応答（先頭の行の値のままで、推定で埋めない。実ログでサブエージェント側の応答の 7〜19%）、同じ `requestId` の行どうしで入力・キャッシュのトークンが違う応答（実ログで 102,295 件中 5 件。先頭の行の値を使う）、会話ログに行を持たない呼び出し（分類器など）の分、会話ログが既に消えた期間の応答である。新しく見つかった暫定値や確定値の取りこぼしの穴を塞ぎ切ることを、この要件の完了条件にしない。

#### Scenario: 事実の抽出が帰属を含まない
- **WHEN** 1 行を読んで事実を抽出する
- **THEN** その行だけで確定する事実のみが得られ、区間の帰属先 issue は含まれない

#### Scenario: キャッシュ書込の内訳が無い古い行
- **WHEN** 行の `usage` に `cache_creation` が無く `cache_creation_input_tokens` だけがある
- **THEN** その値はキャッシュ書込 5m として読まれる

#### Scenario: 推定で決めた行だけが repo_inferred を持つ
- **WHEN** `cwd` が存在して `git rev-parse` で識別子の決まる行と、`cwd` が削除済みで推定によって識別子の決まる行から事実を抽出する
- **THEN** 前者の事実は `repo_inferred` の欄を持たず、後者の事実は `repo_inferred: true` を持つ

#### Scenario: 先頭の行が途中の値でも確定値で数える
- **WHEN** 同じ `requestId` の 1 行目（考えた内容）の `usage.output_tokens` が 8、2 行目（`stop_reason` が `tool_use`）が 251 で、入力・キャッシュは同じ
- **THEN** 事実の列の出力トークンの合計は 251 で、金額は出力 251 トークンで計算した値

### Requirement: リポジトリ識別子と worktree の畳み込み
システムは各行の `cwd` から `git -C <cwd> rev-parse --path-format=absolute --git-common-dir` を用いてリポジトリ識別子を求め、worktree のコストを親リポジトリへ畳み込 MUST む。`--path-format=absolute` を省いてはなら MUST NOT ない。省くとメイン worktree で相対の `.git` が返り、識別子が cwd ごとに割れる。

**削除済みの `cwd` からの推定。** `cwd` がディレクトリとして存在しないとき、システムは `cwd` の文字列から次の順でリポジトリを推定 MUST する。`cwd` が存在するのに `git rev-parse` が失敗するときは、推定せず「不明」と SHALL する。

1. `cwd` が `/.claude/worktrees/` を含むなら、最後のその並びの手前のディレクトリを持ち主とする。持ち主が存在すれば、持ち主で `git rev-parse` を行った結果を識別子とし（失敗すれば「不明」）、存在しなければ、持ち主のパスにこの推定を初めから当てた結果を識別子とする
2. 上に当たらなければ、`cwd` の祖先のうち現存する最も近いディレクトリを置き場とする。置き場の直下にある、リンクされた作業ツリー（`.git` がファイルであるディレクトリ）それぞれの識別子を `git rev-parse` で求め（求められないものは除く）、求まった識別子が**ちょうど 1 種類**で、かつ置き場のディレクトリ名が、そのリポジトリのメインの作業ツリーのディレクトリ名か origin の URL のリポジトリ名（`owner/repo` の `repo`）と、大文字と小文字を区別して一致するときだけ、その識別子とする
3. 次のときは「不明」と MUST する: 置き場が `/` である／置き場が git リポジトリの中にある（置き場で `git rev-parse` が成功する）／置き場の直下にリンクされた作業ツリーが 1 つも無い／2 の 2 つの条件のどちらかを満たさない

推定で識別子を決めた行の事実は、`repo_inferred` を `true` で持 MUST つ。`git rev-parse` で決めた行と「不明」の行の事実は、`repo_inferred` の欄を持ってはなら MUST NOT ない（この要件より前に書かれた事実と同じ形のままにするため）。推定は集計を中断してはなら MUST NOT ず、推定のための `git` の起動は、同じ `cwd` と同じ置き場について 1 回の実行の中で繰り返してはなら MUST NOT ない。

守備範囲（推定）: 入力は会話ログの行の `cwd` の文字列と、いまのファイルシステムの状態。拾いたい誤りは、作業が終わって消した作業ツリーの行が、どのリポジトリの行か分からないまま合計から外れること。置き場の名前の一致を求めるのは、複数のリポジトリの作業ツリーを混ぜて置くディレクトリ（名前がどのリポジトリとも一致しない）で、たまたま残っている 1 つのリポジトリに寄せないためである。次のものは誤ったまま通ることを許す: リポジトリ X の名前の置き場に過去に置かれていた別のリポジトリ Y の作業ツリーの行は、X の行になる（削除済みのディレクトリが何だったかを確かめる手段が無い）／置き場の名前がリポジトリ名と違う場合と、置き場ごと消えた場合は「不明」のまま／いまのファイルシステムの状態で決めるので、同じ `cwd` でも実行する時期によって結果が変わりうる（台帳に書いた事実は書き換えない）／`/.claude/worktrees/` の規則は置き場の名前の一致を見ないので、ホームディレクトリが git リポジトリの環境では、削除済みの `~/.claude/worktrees/x` の行はホームのリポジトリの行になる／bare リポジトリにはメインの作業ツリーが無いので、ディレクトリ名の一致は識別子のパスの末尾の名前（`repo.git` など）で比べる。置き場の名前が origin のリポジトリ名と一致しない限り「不明」のままになる。これらの穴を塞ぎ切ることは、この要件の完了条件にしない。

#### Scenario: worktree 上の作業を親リポジトリに寄せる
- **WHEN** `cwd` が親リポジトリの worktree を指している
- **THEN** そのコストは worktree ごとではなく親リポジトリの集計に含まれる

#### Scenario: メイン worktree でも同じ識別子になる
- **WHEN** 同じリポジトリのメイン worktree と副 worktree の両方に行がある
- **THEN** 両方が同一のリポジトリ識別子に畳まれる

#### Scenario: cwd が既に存在せず、推定もできない
- **WHEN** `cwd` のディレクトリが削除済みで、推定の条件を満たさない（置き場の名前がどのリポジトリとも一致しない、など）
- **THEN** 集計は中断せず、その行のリポジトリ識別子は「不明」として記録され、事実は `repo_inferred` の欄を持たない

#### Scenario: 同じ置き場に残っている作業ツリーから推定する
- **WHEN** リポジトリ A（ディレクトリ名 `repo-a`）のメインの作業ツリーは別の場所にあり、git リポジトリでないディレクトリ `<親>/repo-a`（これが置き場）の直下に A の作業ツリー `<親>/repo-a/wt1` が残っていて、行の `cwd` が削除済みの `<親>/repo-a/wt2` である
- **THEN** その行の識別子は A の識別子になり、事実は `repo_inferred: true` を持つ

#### Scenario: 置き場の名前が origin のリポジトリ名と一致する
- **WHEN** origin が `acme/repo-a` のリポジトリ（ディレクトリ名は別の名前）の作業ツリーだけが `repo-a` という名前の置き場の直下に残っていて、行の `cwd` がその置き場の削除済みの子である
- **THEN** その行の識別子はそのリポジトリの識別子になる

#### Scenario: 置き場の名前がリポジトリと一致しなければ推定しない
- **WHEN** リポジトリ A の作業ツリーだけが `workspaces` という名前の置き場の直下に残っていて、行の `cwd` がその置き場の削除済みの子である
- **THEN** その行の識別子は「不明」になる

#### Scenario: 置き場に 2 つのリポジトリの作業ツリーがあれば推定しない
- **WHEN** 置き場の直下にリポジトリ A と B の作業ツリーが 1 つずつ残っていて、行の `cwd` がその置き場の削除済みの子である
- **THEN** その行の識別子は「不明」になる

#### Scenario: 置き場が git リポジトリの中なら推定しない
- **WHEN** 行の `cwd` が、現存するリポジトリの作業ツリーの中の削除済みのサブディレクトリで、`/.claude/worktrees/` を含まない
- **THEN** その行の識別子は「不明」になる

#### Scenario: .claude/worktrees の手前のリポジトリに寄せる
- **WHEN** 行の `cwd` が削除済みの `<リポジトリ A の作業ツリー>/.claude/worktrees/x` で、リポジトリ A の作業ツリーは残っている
- **THEN** その行の識別子は A の識別子になり、事実は `repo_inferred: true` を持つ

#### Scenario: .claude/worktrees の手前も削除済みなら、その手前を推定する
- **WHEN** リポジトリ A（ディレクトリ名 `repo-a`）のメインの作業ツリーは別の場所にあり、git リポジトリでないディレクトリ `<親>/repo-a`（これが置き場）の直下に A の作業ツリー `<親>/repo-a/wt1` が残っていて、行の `cwd` が `<親>/repo-a/wt2/.claude/worktrees/x`、`wt2` は削除済みである
- **THEN** その行の識別子は A の識別子になる

#### Scenario: 別のリポジトリの置き場の行は、そのリポジトリの行になる
- **WHEN** リポジトリ B の置き場の削除済みの `cwd` で issue #42 を触った行と、リポジトリ A の置き場の削除済みの `cwd` で issue #42 を触った行があり、A の作業ディレクトリから issue #42 の合計を求める
- **THEN** 合計に入るのは A の置き場の行だけで、B の置き場の行は合計にも「リポジトリ不明」にも入らない
