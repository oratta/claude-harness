## MODIFIED Requirements

### Requirement: リポジトリ識別子と worktree の畳み込み
システムは各行の `cwd` から `git -C <cwd> rev-parse --path-format=absolute --git-common-dir` を用いてリポジトリ識別子を求め、worktree のコストを親リポジトリへ畳み込 MUST む。`--path-format=absolute` を省いてはなら MUST NOT ない。省くとメイン worktree で相対の `.git` が返り、識別子が cwd ごとに割れる。

**削除済みの `cwd` からの推定。** `cwd` がディレクトリとして存在しないとき、システムは `cwd` の文字列から次の順でリポジトリを推定 MUST する。`cwd` が存在するのに `git rev-parse` が失敗するときは、推定せず「不明」と SHALL する。

1. `cwd` が `/.claude/worktrees/` を含むなら、最後のその並びの手前のディレクトリを持ち主とする。持ち主が存在すれば、持ち主で `git rev-parse` を行った結果を識別子とし（失敗すれば「不明」）、存在しなければ、持ち主のパスにこの推定を初めから当てた結果を識別子とする
2. 上に当たらなければ、`cwd` の祖先のうち現存する最も近いディレクトリを置き場とする。置き場の直下にある、リンクされた作業ツリー（`.git` がファイルであるディレクトリ）それぞれの識別子を `git rev-parse` で求め（求められないものは除く）、求まった識別子が**ちょうど 1 種類**で、かつ置き場のディレクトリ名が、そのリポジトリのメインの作業ツリーのディレクトリ名か origin の URL のリポジトリ名（`owner/repo` の `repo`）と、大文字と小文字を区別して一致するときだけ、その識別子とする
3. 次のときは「不明」と MUST する: 置き場が `/` である／置き場が git リポジトリの中にある（置き場で `git rev-parse` が成功する）／置き場の直下にリンクされた作業ツリーが 1 つも無い／2 の 2 つの条件のどちらかを満たさない

推定で識別子を決めた行の事実は、`repo_inferred` を `true` で持 MUST つ。`git rev-parse` で決めた行と「不明」の行の事実は、`repo_inferred` の欄を持ってはなら MUST NOT ない（この要件より前に書かれた事実と同じ形のままにするため）。推定は集計を中断してはなら MUST NOT ず、推定のための `git` の起動は、同じ `cwd` と同じ置き場について 1 回の実行の中で繰り返してはなら MUST NOT ない。

守備範囲（推定）: 入力は会話ログの行の `cwd` の文字列と、いまのファイルシステムの状態。拾いたい誤りは、作業が終わって消した作業ツリーの行が、どのリポジトリの行か分からないまま合計から外れること。置き場の名前の一致を求めるのは、複数のリポジトリの作業ツリーを混ぜて置くディレクトリ（名前がどのリポジトリとも一致しない）で、たまたま残っている 1 つのリポジトリに寄せないためである。次のものは誤ったまま通ることを許す: リポジトリ X の名前の置き場に過去に置かれていた別のリポジトリ Y の作業ツリーの行は、X の行になる（削除済みのディレクトリが何だったかを確かめる手段が無い）／置き場の名前がリポジトリ名と違う場合と、置き場ごと消えた場合は「不明」のまま／いまのファイルシステムの状態で決めるので、同じ `cwd` でも実行する時期によって結果が変わりうる（台帳に書いた事実は書き換えない）。これらの穴を塞ぎ切ることは、この要件の完了条件にしない。

#### Scenario: worktree 上の作業を親リポジトリに寄せる
- **WHEN** `cwd` が親リポジトリの worktree を指している
- **THEN** そのコストは worktree ごとではなく親リポジトリの集計に含まれる

#### Scenario: メイン worktree でも同じ識別子になる
- **WHEN** 同じリポジトリのメイン worktree と副 worktree の両方に行がある
- **THEN** 両方が同一のリポジトリ識別子に畳まれる

#### Scenario: cwd が既に存在せず、推定もできない
- **WHEN** `cwd` のディレクトリが削除済みで、推定の条件を満たさない（置き場の名前がどのリポジトリとも一致しない、など）
- **THEN** 集計は中断せず、その行のリポジトリ識別子は「不明」として記録され、事実は `repo_inferred` の欄を持たない

#### Scenario: 同じ置き場に残っている作業ツリーから推定する
- **WHEN** リポジトリ A（ディレクトリ名 `repo-a`）の作業ツリーが `<置き場>/repo-a/wt1` に残っていて、行の `cwd` が削除済みの `<置き場>/repo-a/wt2` である
- **THEN** その行の識別子は A の識別子になり、事実は `repo_inferred: true` を持つ

#### Scenario: 置き場の名前が origin のリポジトリ名と一致する
- **WHEN** origin が `acme/repo-a` のリポジトリ（ディレクトリ名は別の名前）の作業ツリーだけが `repo-a` という名前の置き場の直下に残っていて、行の `cwd` がその置き場の削除済みの子である
- **THEN** その行の識別子はそのリポジトリの識別子になる

#### Scenario: 置き場の名前がリポジトリと一致しなければ推定しない
- **WHEN** リポジトリ A の作業ツリーだけが `workspaces` という名前の置き場の直下に残っていて、行の `cwd` がその置き場の削除済みの子である
- **THEN** その行の識別子は「不明」になる

#### Scenario: 置き場に 2 つのリポジトリの作業ツリーがあれば推定しない
- **WHEN** 置き場の直下にリポジトリ A と B の作業ツリーが 1 つずつ残っていて、行の `cwd` がその置き場の削除済みの子である
- **THEN** その行の識別子は「不明」になる

#### Scenario: 置き場が git リポジトリの中なら推定しない
- **WHEN** 行の `cwd` が、現存するリポジトリの作業ツリーの中の削除済みのサブディレクトリである
- **THEN** その行の識別子は「不明」になる

#### Scenario: .claude/worktrees の手前のリポジトリに寄せる
- **WHEN** 行の `cwd` が削除済みの `<リポジトリ A の作業ツリー>/.claude/worktrees/x` で、リポジトリ A の作業ツリーは残っている
- **THEN** その行の識別子は A の識別子になり、事実は `repo_inferred: true` を持つ

#### Scenario: .claude/worktrees の手前も削除済みなら、その手前を推定する
- **WHEN** 行の `cwd` が `<置き場>/repo-a/wt2/.claude/worktrees/x` で、`wt2` は削除済み、同じ置き場にリポジトリ A の作業ツリー `wt1` が残っている
- **THEN** その行の識別子は A の識別子になる

#### Scenario: 別のリポジトリの置き場の行は、そのリポジトリの行になる
- **WHEN** リポジトリ B の置き場の削除済みの `cwd` で issue #42 を触った行と、リポジトリ A の置き場の削除済みの `cwd` で issue #42 を触った行があり、A の作業ディレクトリから issue #42 の合計を求める
- **THEN** 合計に入るのは A の置き場の行だけで、B の置き場の行は合計にも「リポジトリ不明」にも入らない
