## Why

issue の番号でコストを引くとき、`cwd` が削除済みの行はリポジトリを割り出せず「リポジトリ不明」として合計の外に出る。作業ツリー（worktree）は作業が終わると消すので、エピック #272 の `cost 272` では合計 $373.09 に対してリポジトリ不明が 4,042 件 $329.59 になり、合計が実際にかかった額を表さない（issue #750）。

調べた実データは、issue #750 の本文の前提と 3 点で違った。この change はその実データに合わせて作る。

| issue の本文の前提 | 実データ（2026-10-07、読み取りだけで再現） |
|---|---|
| 不明の行は、このリポジトリの削除済み作業ツリーの行 | 不明 4,042 件 $329.59 のうち claude-harness の行は 593 件 $59.06 だけ。残り 3,449 件 $270.53 は別リポジトリ flatmate の同じ番号の issue（#699・#762 など）の行 |
| 台帳へ追記する時点でリポジトリ識別子を焼き付ければ直る | 焼き付けは既に実装済み（`build_fact` が追記時に `RepoResolver.repo_id` を呼ぶ）。不明なのは、台帳を動かし始めた 2026-10-06 より前の会話ログで、初回の取り込みの時点で `cwd` がもう無かった行。台帳全体では 166,406 行 $11,770.73 のうち 108,464 行 $7,950.81 |
| 時間がたつほど増える | 台帳の開始後のメッセージ 9,497 行 $549.05 のうち不明は 12 行 $0.63（0.1%）。今後はほとんど増えない |

したがって直す対象は「追記する前に `cwd` が消えていた行」である。issue の受け入れ条件 1 件目「台帳へ追記したあとで `cwd` を消した行が合計に入る」は現状でも通る見込みなので、回帰テストとして残し、直す対象のテストを別に足す。

## What Changes

- 削除済みの `cwd` の文字列から、リポジトリを推定する規則を足す（`.claude/worktrees/` の手前のディレクトリ、または現存する最も近い祖先の直下にある作業ツリーの持ち主）。条件を満たさない `cwd` は今までどおり不明にする
- 推定で決めた行に `repo_inferred: true` の印を付ける
- 既に台帳にある不明の行は、`ledger-sync --rescan` が「補正行」を追記して直す（既存の行は書き換えない）。補正行は（セッション, ブランチ）の組ごとに 1 行で、その組の会話ログ上の `cwd` がすべて同じ 1 リポジトリに決まるときだけ書く
- 台帳を読むとき、補正行を取り除き、補正が 1 リポジトリに決まる組の不明の行をそのリポジトリの行として読む。同じ組に 2 つのリポジトリの補正行があれば不明のままにする（補正を取り消す手段になる）
- `cost <issue番号>`・エピックの `cost <番号>`・番号なしの `cost` の出力に、推定で数えた件数と額を 1 行（`--json` では鍵 2 つ）で出す
- `ledger-sync --rescan` は主が手で 1 回実行する操作のままにする。hook と通常の `ledger-sync` からは走らせない（セッションを止めないため）。実行前に台帳を控える手順を README に書く

- `cost-ledger-cost-command`: issue・エピック・番号なしの出力に、推定で数えた件数と額の表示を足す
