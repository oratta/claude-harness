## ADDED Requirements

### Requirement: 論点なしのリスク宣言は、親か決める役の確認で合格処理に進める

pr-review-gate の `declarations.md` の手順 3 と `stages/hold.md` の手順 6 は、「主のリスク許容が必要」の宣言が `論点なし — ` の行を持つとき、主の許容を待たずに確認者の確認で合格処理（手順 4・5）に進める経路を書かなければならない（MUST）。確認者は、エピックの子（`scripts/epic-dispatch.sh route` が `nested`）なら親、それ以外のセッションなら決める役（`subagent_type: dev-workflow:decider`）とする。`論点あり — ` の行を持つ宣言は、この経路で通してはならない（MUST NOT）。この経路はマージの経路を変えない。

#### Scenario: エピックの子は親が通す

- **WHEN** エピックの子で、宣言が `論点なし — ` の行を持つ
- **THEN** 子は今の停止の記録（`子の停止: 主の返事待ち`）の手順で止まり、親が `parent-pass-criteria.md` で判断して `親エピック #<E> の判断（主の承認ではない）:` の返事で通す

#### Scenario: それ以外のセッションは決める役が通す

- **WHEN** エピックの子でないセッションで、宣言が `論点なし — ` の行を持つ
- **THEN** 宣言の本文と根拠ファイルの差分だけを渡した決める役が論点なしかを判定する。develop の G は判定役を起こせないので、宣言と `needs-approval` を残して本体に返し、本体が起こす（3-c の `needs-carryover-judge` と同じ分担）

#### Scenario: 論点ありの宣言は主に上がる

- **WHEN** 宣言が `論点あり — ` の行を持つ
- **THEN** この経路は使われず、手順 6 で主の許容を待つ

#### Scenario: 聖域に触れた PR のマージは人間に残る

- **WHEN** 論点なしの確認で合格した PR が聖域のパスに触れている
- **THEN** マージは `auto-merge.yml` のパスによる判定のまま人間のマージに回る（auto-merge 未配備のリポジトリではマージは今どおり主の操作）

### Requirement: 論点なしの確認の記録を宣言コメントに残す

確認者が通したら、宣言コメントに `論点なしの確認: 通す — 確認者 <確認者> / <日時> 根拠: <1 文>` を追記しなければならない（MUST）。`<確認者>` は `親エピック #<E>（セッション <ID>）` か `dev-workflow:decider（<エージェント名>）`。この行の行頭を `主の回答:` にしてはならない（MUST NOT。手順 3-c が主の直接の回答として引き継がないため）。確認者が論点ありと判定したら、宣言を `論点あり — ` の形で投稿し直し、主の許容を待たなければならない（MUST）。

#### Scenario: 通した記録が残る

- **WHEN** 決める役が論点なしと判定する
- **THEN** 宣言コメントに `論点なしの確認: 通す — 確認者 dev-workflow:decider（…）/ <日時> 根拠: …` が追記される

#### Scenario: 確認者が論点ありと判定したら書き直して主に上げる

- **WHEN** 確認者が「この変更で新たに生じるリスクがある」と判定する
- **THEN** 宣言を `論点あり — ` の形で投稿し直し、手順 6 で主の許容を待つ

### Requirement: 合格条件は同じ HEAD の論点なしの確認を許容済みとして扱い、引き継がない

`stages/pass.md` の手順 5 の合格条件の表は、「主のリスク許容が必要」＋ `論点なし — ` の行 ＋ 同じ HEAD の `論点なしの確認: 通す` の追記、を許容済みとして扱わなければならない（MUST）。HEAD が動いたら、手順 3-c はこの追記を引き継ぎの元にしてはならず（MUST NOT）、新しい HEAD の宣言で確認を取り直さなければならない（MUST）。

#### Scenario: HEAD が動いたら確認を取り直す

- **WHEN** `論点なしの確認: 通す` の追記のあとに HEAD が動く
- **THEN** 手順 3-c はこの追記を引き継ぎの元にせず、新しい HEAD の宣言で確認を取り直す

#### Scenario: bats で経路と記録を確かめる

- **WHEN** `bats plugins/dev-workflow/tests/` を実行する
- **THEN** exit 0 で、`declarations.md`・`stages/hold.md`・`stages/pass.md` に論点なしの経路（確認者の 2 通り・記録の行の書式・行頭が `主の回答:` でないこと・論点ありは主に上がること・引き継がないこと）が書かれていることを確かめるテストがある
