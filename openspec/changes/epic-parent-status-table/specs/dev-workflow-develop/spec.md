## ADDED Requirements

### Requirement: エピックの親は主への報告の最後に、全部の子と親自身の状態表を付ける

`references/epic.md` は、エピックの親が主に出す報告すべて（別セッション方式の「親が別セッション方式でターンを終えるときに主に出す発言すべて」と、サブエージェント方式の主への報告）に、次の表を付けると規定しなければならない（MUST）。

- 置き場所: 表・答えが要る子の URL・「前回の報告から片付いたもの」は、報告の区切りより下に置く（MUST）。区切りより上の本文の最後の行は、既存の規定（要件「エピックの親が主に出す発言は、正本の 1 行目の書き分けに従う」）のとおり答え方のまま変えない（MUST NOT 置き換え）。1 行目も変えない（今回いちばん先に答えてほしい 1 件の質問。なければ `主がすること: なし`）
- 表の上に、確かめた時刻（JST）を書く
- 行は、まだ閉じていない全部の子 issue と、親自身（エピックの番号）を 1 行ずつ
- 列は `issue 番号・内容・ステータス・確認内容・推奨・答え方`。確認内容は主に聞いていることの中身、答え方はどの画面で何を打つか。答えが要らない行は `なし`
- 表の下に、答えが要る子の issue（または停止の記録）の URL を 1 行 1 本で置く
- 前回の報告から片付いた件（子のタブで答え済みの件を含む）を「前回の報告から片付いたもの」に書く
- channel モードでは、答え方の列もチャンネルで返す内容にし、チャンネル以外の画面・タブを書かない（MUST NOT。既存の要件「channel モードの主への発言はすべてチャンネルに送り…」に従う）

この要件の守備範囲で入力として扱うのは `references/epic.md` の文面である。拾いたい誤りは、主が最新の 1 通だけで、閉じていない子の状態と自分がすることを読み取れないことである。次は通ってよく、この要件では止めない: 内容・確認内容の文の良し悪し／子が 1 件も残らない報告で表が空になること。書き方の穴を見つけるたびに決まりを足して塞ぎ切ることは、この要件の完了条件としない。

#### Scenario: epic.md が表の列と置き場所を規定する
- **WHEN** `references/epic.md` の別セッション方式の「主に出す発言すべて」の段落とサブエージェント方式を読む
- **THEN** 列 `issue 番号・内容・ステータス・確認内容・推奨・答え方` の表を付けると書かれ、確かめた時刻（JST）・親自身の行・答えが要る子の URL・前回の報告から片付いたものを書くと書かれ、それらは区切りより下に置き、区切りより上の最後の行は答え方のままと書かれている

#### Scenario: channel モードの答え方の列
- **WHEN** `references/epic.md` の表の規定を channel モードについて読む
- **THEN** 答え方の列はチャンネルで返す内容にし、チャンネル以外の画面・タブを書かないと書かれている

### Requirement: 別セッション方式の親は表を書く前に、子の会話ログの末尾で子のタブで進んだ分を確かめる

`references/epic.md` は、別セッション方式（Orca・tmux）の親が状態表を書く前に、閉じていない子ごとに `scripts/epic-dispatch.sh child-log` で会話ログの末尾を読み、子のタブで進んだ分を表に反映すると規定しなければならない（MUST）。子のタブで主が直接答えても子は issue の停止の記録を書き直さないので、記録だけを見て書くと表が子の実際の状態とずれる。会話ログの末尾と issue の記録が食い違うときは会話ログを優先する。`child-log` が `unreadable` を返した子のステータスは `確かめられなかった` と書き、記録から推測して書いてはならない（MUST NOT）。サブエージェント方式の子には独立した会話ログが無いので、`child-log` を使わず、本体が自分の会話から子の状態を書く。

#### Scenario: epic.md が会話ログの確認を表より前に置く
- **WHEN** `references/epic.md` の状態表の規定を読む
- **THEN** 別セッション方式では表を書く前に `child-log` で子の会話ログの末尾を読むこと、食い違えば会話ログを優先すること、読めない子は `確かめられなかった` と書くことが書かれ、サブエージェント方式は本体の会話から書くと書かれている

### Requirement: epic-dispatch.sh child-log は子の会話ログの最後のやり取りを読み取り専用で出す

`epic-dispatch.sh child-log <child>...` は、子ごとに、その子の状態の記録の `worktree` から会話ログの置き場を引き、最新の会話ログの最後の「主の発言」と最後の「子の発言」の時刻と冒頭を 1 行（タブ区切り）で出さなければならない（MUST）。列は `<child>`・主の最後の発言の時刻（JST、`YYYY-MM-DD HH:MM`）・その冒頭（改行を空白にして先頭 80 文字）・子の最後の発言の時刻・その冒頭。該当が無い列は `-`。

- 最新の会話ログ: 置き場の直下の `*.jsonl`（サブエージェントのものを除く）のうち、最後の timestamp が最も新しい 1 本
- 主の発言: type が user で、`isMeta` でも `isSidechain` でもなく、内容が文字列かテキストだけ（`tool_result` を含まない）のもの。次は主の発言に数えない（MUST NOT）: 頭が `親エピック #` で始まる親の判断の返事（`親エピック #E の判断（主の承認ではない）: `）、`/develop` の最初の指示（内容に `<command-name>` のタグがある、または頭が `/develop` のもの）。頭が `主の返事（親エピック #E 経由）:` の親が中継した主の返事は主の発言に数える
- 子の発言: type が assistant のテキスト（`isSidechain` でないもの）
- 読めない子: 記録が無い・読めない（要件「子 1 ファイルの記録は決まった項目を持つ」の読めない記録を含む）・記録が 2 件以上で一意に決まらない、会話ログの置き場が無い・読めない、`python3` が無い、のどれかのとき、`unreadable <child>` を出し、記録に由来するときは stderr にその記録のパスを出して、他の子を続ける
- 記録も会話ログも書き換えてはならず（MUST NOT）、LLM を呼んではならない（MUST NOT）。`jq` が無い・今のワークツリーを読めないときは stdout 空で exit 1、それ以外は exit 0

この要件の守備範囲で入力として扱うのは、Claude Code が書く会話ログ（`*.jsonl`）の user 行と assistant 行、および `epic-state.sh` が書いた状態の記録である。拾いたい誤りは、主が子のタブで答えた最後のやり取りを取り逃がすことと、ツールの結果や親からの機械的な送信を主の発言に数えて、主が答え済みと取り違えることである。次は通ってよく、この要件では止めない: compact の要約や hook が足した user 行を主の発言に数えること／親が中継した主の返事の真偽／冒頭 80 文字で意味が取り違えられること（親が必要なら会話ログを自分で読む）／会話ログの形式が将来変わって `unreadable` になること。判定の穴を見つけるたびに除外を足して塞ぎ切ることは、この要件の完了条件としない。

#### Scenario: 最後のやり取りを出す
- **WHEN** 記録のある子の会話ログに、主の発言 → 子の発言 → ツールの結果、の順の行がある
- **THEN** 主の最後の発言と子の最後の発言の時刻と冒頭が 1 行で出て、ツールの結果は主の発言に数えられない

#### Scenario: 親の判断の返事は主の発言に数えない
- **WHEN** 会話ログの最後の user 行が `親エピック #33 の判断（主の承認ではない）: ...` で、その前に主の発言がある
- **THEN** 主の最後の発言はその前の発言で、親の判断の返事ではない

#### Scenario: 読めない子は unreadable で続ける
- **WHEN** 会話ログの置き場が無い子と読める子を一緒に渡す
- **THEN** 置き場が無い子は `unreadable <child>`、読める子は通常の行が出て、exit 0 である

#### Scenario: 読めない記録の子は unreadable と記録のパス
- **WHEN** 記録が JSON として読めない子を渡す
- **THEN** `unreadable <child>` が stdout に、その記録のパスが stderr に出て、記録は書き換えられない
