# Design

## Context

動機は proposal.md を参照。dispatch の `keepalive_child` は受領済みの主の返事待ちだけを対象にし、`stop_uuid` で本体ログを選ぶ。通常の `作業報告` は実作業待ちと区別できない。Orca 部品は状態記録を持たず、画面を二度観測して一度だけ送信する。既知の `Waiting for N background agents` は現状 busy である。#1792 / #1793 の共有 `background` 定義・受信・ログとフックの除外を前提にする。

## Goals / Non-Goals

**Goals:** 記録と現行会話が同じ作業待ちを示す場合だけ親の既存ポーリングで外部起こしを行う。維持対象を停止済み子と分離し、元作業・実行 ID を保ったまま自己タイマーのリクエストを省く。

**Non-Goals:** 受信側の再設計、#1797、tmux への新しい作業待ち送信、親の待ち時間・起床規則の変更、元作業の監視・結果分類・キャンセル・再起動、費用削減の推測による成功宣言。

## Decisions

### 1. 通常の状態行に明示した作業待ち情報を添える

新たな第4の状態値や summary の自然言語推測は使わない。子の本体は通常ターンの終了時に、引用・コードの外で、最終状態行の直前に次を置く。

```text
作業待ち: <wait-id> <started-at>
状態: 作業報告 — <待っている元作業の要約>
```

`wait-id` は空白を含まない `[A-Za-z0-9][A-Za-z0-9._:-]*` の保持用識別子（元の実行 ID を利用でき、複数作業なら同じ待ちの組を表す識別子）。`started-at` はその待ちの初回開始時刻の UTC `YYYY-MM-DDTHH:MM:SSZ`。子は元作業 ID 群と一緒にこの組を保持し、同じ待ちの延長・通常入力後の待ち直しでも取り直さない。最も早く始めた未回収の作業を引き続き待つ間は同じ待ちとし、追加の作業だけで ID や時刻を更新しない。全回収後の別の待ちだけ新しい組にできる。

既存 Stop フックが状態行・依存待ち情報と同時に `turn_state.background_wait = {id, started_at}` を排他保存する。通常入力の `turn_state: null`、marker の無い通常終了、完了・返事待ちへの遷移は作業待ち情報も無効化する。`dependency_wait: true` との併存、作業報告以外への付与、書式不正は有効な作業待ちにしない。予約文の往復は既存除外をそのまま使い、この組・入力世代・保存時刻を書き換えない。

新しい情報は任意拡張。旧記録は引き続き読めるが作業待ちには格上げしない。親側の基本 schema=1 検査は変えず、作業待ち送信の判定で厳密に読む。作業待ちの出力に停止コメントや mark stopped を必要としない。

### 2. 停止済み子の判定から分け、同じポーリング内でだけ送る

停止済み子の既存経路は条件・固定文・150k 除外・期限設定を保つ。作業待ちは下の条件を全て満たす場合にだけ別経路で `background` の生成済み固定文を使う。

- 通常の正の interval/timeout、`--watch-stopped`、位置引数の子。片付けだけの `--watch-done`・単発確認・失敗したポーリングは除外。`--resolve` の有無で作業待ちを stopped にしない。
- 同じ親の一意な記録、issue open、status=running、stop が stopped / stopped-seen でない、起動失敗なし、worktree と session がある、launcher=orca。
- 有効な turn_input / turn_state の同世代・同セッションで sender=parent または startup、value=作業報告、dependency_wait が欠落か false、background_wait が正しい。owner ターンの旧情報から送らない。
- `turn_input.transcript_path` の一意な現行 CLI 会話で session_id を照合する。記録の `session` は端末ハンドルなので会話 ID に使わない。最新の通常の子発言が記録と同じ marker と状態行を持ち、その後に通常入力・元作業通知・新たな通常発言が無い。別ログの TTL・質問・古い stop_uuid は使わない。子の発言と usage は sessionId 一致かつ entrypoint=cli の行だけを数え、入力の行は sessionId が別のときだけ除く（sessionId や entrypoint が欠けた入力も数え、送らない側に倒す）。
- その一本から最後の有効な cache creation の TTL=1h と、cache-read を含む最後の成功 CLI リクエスト開始を別々に読む。3000 秒以上 3600 秒未満だけ許し、未来・不明・失効・5m は非送信。停止済み子の会話量上限は適用しないが、usage が読めることは必要。
- 同じ現行会話の前回の作業待ち向け固定文が未応答なら送らない。型違いでも既存どおり返事の到着と表示を扱い、一行・ツールなし・一リクエストの成功とは数えない。正常な一往復は既存の共有読取に従う。

状態→会話→状態と会話の再読→Orca 一覧→二度の画面観測→send 一回、の順で最終確認する。再読で親子・path・launcher・session・世代・状態・待ちの組が変われば見送り、新しい候補として同じポーリング内で取り直して送らない。状態のロックはネットワーク呼び出し中に保持しない。記録の読み取りは dispatch、画面は launcher の責務を保つ。

送信判定結果は既存 `keepalive` に記録し、連続して同じ理由なら時刻を更新しない。新たな無効候補も `skipped not-stopped`、現行会話なしは `no-transcript`、期限と基点不正は `expired`、通常入力・通知・通常発言による失効は `answered`、前回未応答は `pending` を使う。会話の判定で複数に当たるときは expired → path 欠落・読取不能の no-transcript → answered → 作業待ちの発言なしの no-transcript → pending → cache-unknown → cache-future → out-of-window の順で最初の一つを記録する。作業待ちは `too-large` / `no-question` で落とさない。送信・返事・期限到達だけで wait の行や終了理由、停止印を増やさない。

### 3. Orca の背景待機許可は検査済み候補の一呼び出しに限る

既存 `keepalive <worktree> <text>` の引数数・結果語彙・tmux の契約を保つ。dispatch から Orca 部品への一呼び出しだけに `EPIC_DISPATCH_KEEPALIVE_BACKGROUND_WAIT=1` を渡す。停止済み子の経路では明示的に無効にし、親環境から値を継承して誤って有効化しない。部品はこの内部指定でのみ、最後の既知の背景待機行が一意の入力枠より前にあり、その間が空行と recap の行だけのときに限り、待機行による busy を解除できる。部品自身は記録を読まず、固定文の内容から状態を推測しない。

許す範囲は既存の記号＋`Waiting for N background agent(s)`（任意の ` to finish`）だけ。待機行が入力枠内・後方にある、待機行と入力枠の間に会話や未知の行が挟まる（古い待機行）、未知の表示・枠・フッター・一覧、前景スピナーや `esc to interrupt`、dialog、非空の入力領域・draft は許さない。状態が作業待ちでも画面の他の検査を省かない。初回と送信直前の二回とも同じ条件で確かめ、どちらかが外れれば send しない。

送信は一度だけ。`turn_started` または既存の送信後 read で新しい前景実行と空欄を確認する契約を保ち、背景待機行自体を到達の証拠にしない。send 成功は受信の一行応答やリクエスト数の証明ではない。通常 keepalive の既知待機履歴の解除、入力欄検査、非bypassの未観測範囲は変更しない。

### 4. 初回開始から 12 時間で維持だけを打ち切る

作業待ちは `background_wait.started_at` を基点に `0 <= now - started_at < 43200` のときだけ送る。停止済み子の stop_at、更新時刻、声かけ時刻、最初に親が観測した時刻を使わない。親の `EPIC_DISPATCH_OWNER_WAIT_SEC` が短ければその短い上限を作業待ちにも適用し、長く設定されても 43200 秒を超えない。wait の掛け直し・親再開・声かけ・子の延長で基点を更新しない。未来・不明も送らない。上限は実行中作業の timeout や終了ではなく、以後は元の結果通知を待つ。

### 5. 待ちの開始時に経路を選び、受信ターンでは切り替えない

子の本体は専用手順の開始・延長時に一意な自分の記録を既存 epic-state 読取で確認する。nested だけを Orca の証拠にせず、launcher=orca、現行登録セッション、起動失敗なし、さらに今の待ちを始めた入力の送り手（turn_input の送り手）が parent または startup であることを確認できる場合に外部起こしを選ぶ。親の送信対象（decision 2 の sender=parent または startup）と同じ条件で選ぶことで、親が送らない待ちから自己タイマーも外れる穴を作らない。送り手が owner なら外部起こしを選ばず、#1743 の自己通知契約（既存条件どおり）に従う。経路は待ちの準備をする通常ターンごとに選び直す。owner の入力で自己通知へ戻った待ちを、次の parent/startup の入力で外部起こしに戻すときは、待ちの組と初回開始を保持したまま自己タイマーを取り消して marker を出す。逆に外部起こしから自己通知へ切り替えるときも、保持している初回開始を基点にし、切替時刻から12時間をやり直さない。外部起こしでは自己タイマーを作らず、移行前の自己タイマーがあれば通常の待ち準備ターンで自分のものだけを取り消してから marker を出す。取消不明・失敗なら外部起こしの marker を公開せず、二重の維持を成功扱いしない。

tmux、登録を確認できない本体など外部起こしを選べない経路では #1743 の自己タイマー契約と初回タイマー基点を保ち、外部用 marker を出さない。委譲 worker は既存 subagent-waiting のまま。本体の TTL 5m / unknown・45分以内の既存通知・元作業の回収と自己通知の識別も変えない。Orca の一時的な busy・非送信・親 wait 不在を検知するための追加タイマーや監視は作らない。外部起こしの受信ターンは既存一行応答だけで、タイマーの再設置・取消・状態保存をしない。

## Risks / Trade-offs

- **実作業中への誤送信** → 古い作業待ち記録と既知待機行が残る場合や、最終観測後から send までに子が再開した場合は、実作業中に予約文が届き、キュー割り込み・余分な応答やリクエスト・元作業との競合を起こしうる。頻度は未計測。状態と会話の一致、二回の画面観測、前回未応答なら非送信、同じ待ちの12時間上限、一回だけの send で対象を狭めるが原子性は保証しない。後続 PR のリスク宣言にこの影響と未計測を明記して主の許容を取る。W から主への質問はしない。
- **維持できない時間帯** → 親が wait していない・画面不明・TTL 切替・sleep では miss が起きうる。Orca には自己タイマーを重ねず、元作業を保持して一度の再書き込みを受け入れる。維持成功の保証としない。
- **明示記録の誤申告** → 書式が正しくても、実作業が続いているか、同じ待ちかを機械的に証明しない。任意 summary や古い停止印だけの格上げを拒否するところまでを守備範囲にする。仕様側は `dev-workflow-epic-state` の「作業待ちの記録の入力検査に共通の守備範囲」に書き、通してよい入力と完了条件にしないことを明示する。
- **会話量の大きい作業待ち** → 150k 以上でも対象にするため一回の miss の費用は大きい。停止済み子の再起動策を流用すると実行 ID を失うので採らない。総費用半減は主張せず実測を残す。

## Migration Plan

1. #1794 / #1796 を含む main を前提に、状態の任意拡張・送信・待機手順・回帰テストを一つの PR で揃える。稼働中の旧子に marker を親から補わず、次の通常の待ち開始・延長で更新済み子が記録する。
2. 受信正本・共有 JSON・child-log の除外はそのまま利用する。新しい状態付与だけを既存 Stop に足し、予約文除外を作り直さない。
3. 停止済み子と tmux の回帰、作業待ちの境界・競合・画面 fixture を検証する。後続 PR にリスク宣言を含める。
4. マージ後の実エピックで、60分超の作業待ちに対する各声かけと子の一応答・一リクエストを会話ログで照合して #1777 に記録する。送信試行数と誤送信数を分母付きで示し、未観測なら未計測とする。生ログは LLM_LOG_DIR（未設定なら保存先確認）、fixture は匿名化したテストデータだけ。
5. ロールバックは作業待ちの送信拡張と marker の公開を戻す。通常の待ち準備ターンで #1743 の待ち方へ戻し、受信済み予約文から自己タイマーを再設置しない。旧記録と既存受信互換性を保つ。
