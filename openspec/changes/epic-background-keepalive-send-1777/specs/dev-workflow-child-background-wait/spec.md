# Spec Delta

## MODIFIED Requirements

### Requirement: 実作業の待ちは一時間キャッシュを確認して維持する

外部起こしを使えない経路でセッションを保持する子の本体は、自分の現行会話の TTL が 1h、最後の成功リクエストから 3600 秒未満と確認でき、既存の待ちが 45 分以内に本体へ返らない場合に、45 分の有限な自己通知を一つだけ用意しなければならない（MUST）。最初のタイマーを置いた時刻をその待ちの基点として保持し、同じ待ちの再設置で更新してはならない（MUST NOT）。維持の上限はこの基点から12時間とする。外部起こしを選ぶ Orca の子は「外部起こしを選ぶ作業待ちは自己タイマーを持たない」に従い、この自己タイマーを用意しない（MUST）。本体へ制御が戻らない前景呼び出しやツールが使えない環境で維持を保証してはならない（MUST NOT）。判定の守備範囲は「長い待ちの入力判定の守備範囲を共有する」に従う。

#### Scenario: 大きい会話の agent 待ち
- **WHEN** 会話 20 万トークン、TTL 1h の、外部起こしを使えない nested 本体が、60 分を超えうる実行中の agent を保持して待つ
- **THEN** 停止済み子の 150k の除外条件を流用せず、本体自身の有限な自己通知を使い、元の agent を終了・再起動しない

#### Scenario: 既存の期限通知を利用する
- **WHEN** Monitor の期限や有限の前景コマンドが 45 分以内に本体へ返り、次のモデルリクエストが発生する
- **THEN** その通知や返りを利用し、同じ待ちに追加のタイマーを重ねない

#### Scenario: 再設置で維持の基点を延ばさない
- **WHEN** 同じ元作業を待つ間に自己通知を受け、次のタイマーを置く
- **THEN** 最初のタイマーを置いた時刻を保持し、12時間の計測をその再設置時刻からやり直さない

## ADDED Requirements

### Requirement: 外部起こしを選ぶ作業待ちは自己タイマーを持たない

子の本体は通常の待ち開始・延長前に、一意な自分の状態記録で launcher=orca・現行登録セッション・起動失敗なしを確認した場合に外部起こしを選び、維持用自己タイマーを置いてはならない（MUST NOT）。以前の自己タイマーがあれば通常の準備ターンで自分のものだけを取消し、成功確認後に外部用作業待ち行を出す（MUST）。nested だけで Orca と判定せず、取消失敗・不明を移行成功にしてはならない（MUST NOT）。親 wait 不在や一時的な非送信を補う自己タイマー・追加監視を作ってはならない（MUST NOT）。

#### Scenario: Orca の待ち準備でタイマーを省く
- **WHEN** 登録済みの Orca の子の本体が60分超になりうる元作業を保持して待ち、外部起こしを選べる
- **THEN** 受信契約を事前に読み、元作業と実行 ID を保持し、作業待ちの明示行を状態行の直前に出す。自己タイマーは0個である

#### Scenario: 既存タイマーからは通常ターンで移行する
- **WHEN** 元作業と自己タイマーを保持する本体が通常の待ち延長ターンで外部起こしを選ぶ
- **THEN** 自分のタイマーだけを取り消してから外部用 marker を公開する。取消失敗・不明なら公開せず、維持や作業完了を成功宣言しない。予約文の受信ターンでは取消・再設置をしない

#### Scenario: 非送信を追加リクエストで補わない
- **WHEN** Orca の子は外部待ちだが、親が wait していない、前回未応答、画面 busy/不明、TTL 5m/unknown、または期限切れで送信されない
- **THEN** 子は維持専用タイマーや監視を重ねず、元作業を保持する。キャッシュ維持を保証したと報告しない

### Requirement: 外部起こしの基点は同じ未回収作業の初回の待ち開始とする

外部起こしの子は元作業 ID 群と同じ待ちの ID・初回開始 UTC を保持し、通常の作業待ち行に出さなければならない（MUST）。最も早く始めた未回収作業を待ち続ける限り同じ組を使い、作業追加・待ち延長・通常入力後の待ち直し・声かけ・親再開で基点を更新してはならない（MUST NOT）。初回開始から最大12時間の維持後も元作業と実行 ID を保持し、結果を回収しなければならない（MUST）。上限到達だけで元作業を捨てたり、停止・完了・自己通知成功を宣言してはならない（MUST NOT）。

#### Scenario: 同じ作業に新しい待ち時刻を付けない
- **WHEN** 作業待ちの維持後、親の通常入力を処理して同じ未回収作業を待ち直す、または別の作業も待つことになった
- **THEN** 前から待つ未回収作業のある間は同じ待ち ID と初回開始を出し、入力世代が変わっても維持の12時間を延ばさない

#### Scenario: 上限後の回収と新しい別作業を区別する
- **WHEN** 同じ待ちの12時間が過ぎてから元作業が完了し、その全結果を回収したあと別の作業を新たに待つ
- **THEN** 旧待ちは復活させず結果回収時の再書込を受け入れる。全回収後の別作業には新しい待ちの組を使ってよい

### Requirement: 外部起こしを使えない経路は既存の待機契約を保つ

tmux や登録を確認できない本体など外部起こしを使えない経路は、#1743 の現行 CLI TTL 確認・既存45分以内の返りの利用・最大一つの有限な自己通知・初回タイマーから12時間・ID照合・取消契約を保ち、外部送信用の作業待ち行を公開してはならない（MUST NOT）。委譲 worker は本体用タイマーを起動せず既存の subagent-waiting に従う（MUST）。全経路で子所有の実行中作業を依存待ちに偽装せず、受信正本・固定文・一行応答・元作業と自己通知の結果分類を作り直してはならない（MUST NOT）。

#### Scenario: tmux は外部用 marker を出さない
- **WHEN** launcher=tmux の nested 本体が TTL 1h と最近の成功リクエストを確認し、元作業を60分以上待ち、45分以内の既存の返りが無い
- **THEN** 最大一つの既存自己タイマーを使い、初回設置から12時間を保つ。外部用 marker を出さず、親の作業待ち送信は受けない

#### Scenario: worker と旧環境を変えない
- **WHEN** 委譲 worker がコマンドを待つ、または本体の登録経路を確認できない
- **THEN** worker は既存の待機契約、本体は #1743 の適用可能な自己通知契約を使い、未知の経路を Orca とみなさない
