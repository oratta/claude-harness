## Context

W の既定モデルは `sonnet` で、事前分類表に当たる実装だけが 1 周目から `opus` になる。表の正本は worker.md（`dev-workflow-develop` の要件が「1 周目列がすべて `opus`、`fable` 行なし」を規定）。判断は R1・G・決める役（`dev-workflow:decider`）が受け持つので、W を下げても読んで判断する役の品質は変わらない。

## Goals / Non-Goals

**Goals:**
- 3 件の再実行で、Sonnet 5.5 の W が Opus と同等かを判定規則どおりに決める
- 判定と根拠を changes の記録に残し、表を変える場合だけ表・テスト・説明文を揃えて変える

**Non-Goals:**
- R1・G・決める役のモデル、昇格ラダー（`templates/escalation-tripwires.md`）の変更
- W の上限（`opus`）の引き下げ
- Opus 側の再実行（過去の記録で比べる）

## Decisions

- **対象 PR は事前分類に当たる W が opus で実装したものから選ぶ。** 「聖域パス」は事前分類表の 4 分類の意味で扱う。auto-merge の SACRED 定義（`.github/workflows/`・`CLAUDE.md`・`.claude/`・憲法 doc）に当たる最近の PR は W が opus のものが無く、3 件とも「聖域パス非接触」でマージされているため、検証対象を SACRED 定義に限ると 3 件揃わない。代替案は SACRED 定義に限って期間を遡ることだが、W の dispatch 記録（applied model）が残る範囲が最近に限られるので採らない
- **再実行は元の記録先と同じ指示で、GitHub に書かない条件で行う。** 再実行の W は push・issue/PR コメント・PR 作成・ラベル付けをせず、ローカル commit とテスト実行までに留める。既存の記録先を汚さず、費用と副作用を検証の範囲に閉じるため
- **比較は判定規則を先に固定する。** 3 件とも同等なら表を変え、1 件でもトリップワイヤー発火かゲート差し戻しが Opus より増えたら変えない。結果を見てから規則を動かさない
- **spec の差分は 2 段に分ける。** 検証の記録を残す要件は今すぐ足す。表の 1 周目列を変える要件は、検証結果が出てから同じ change に追加する（結果が出る前は変更後の内容が確定しないため）

## Risks / Trade-offs

- 3 件では、まれにしか起きない失敗は見つからない → 表を変えたあとの品質低下は、W が失敗を報告したときの既存の昇格（Opus で再開）で拾う。この点は issue で受け入れ済み
- 再実行の W はゲート（G・レビュアー）を通らないので、ゲート指摘件数は Sonnet 側を本体が別途レビューして数える必要がある → 記録に、Sonnet 側の指摘の数え方（誰がどの観点で見たか）を書く
- worker.md が #610 と衝突する → 表を変える段階で main を取り込み、表の位置を確かめてから編集する
