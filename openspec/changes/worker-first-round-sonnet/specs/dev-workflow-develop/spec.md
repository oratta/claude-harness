## ADDED Requirements

### Requirement: W の 1 周目モデルの変更は過去 PR の再実行による比較記録に基づく

事前分類表（`references/roles/worker.md`）の「1 周目」列のモデルを変える場合は、変更の前に、過去にマージされた PR のうち事前分類に当たる W が元のモデルで実装したもの 3 件を、マージ前の base から新しいモデルの W で再実行し、元の実績と比べた記録を `plugins/dev-workflow/changes/<記録先 issue 番号>.md` に残さなければならない（MUST）。記録には対象 3 件の PR 番号、3 件それぞれのテスト結果（exit code）・ゲート指摘件数（`blocking` と `confirmed` の件数。元 / 新の両方）・トリップワイヤー発火の有無（元 / 新の両方）を並べた表、再実行の W が新しいモデルで動いた証拠（subagent の jsonl の `"model"` 値の検索コマンドと結果）、判定（表を変えるか変えないか）とその根拠を含めなければならない（SHALL）。判定は「3 件とも元と同等なら変える。1 件でもトリップワイヤー発火かゲート差し戻しが元より増えたら変えない」とし、結果を見てから規則を動かしてはならない（MUST NOT）。再実行の W は GitHub に書き込んではならない（MUST NOT。push・issue と PR へのコメント・PR 作成・ラベル付けをせず、ローカル commit とテスト実行までに留める）。変える場合でも W の上限は `opus` のままとし、R1・G・決める役のモデルと昇格ラダーは変えてはならない（MUST NOT）。

#### Scenario: 記録に 3 件の比較表がある
- **WHEN** `plugins/dev-workflow/changes/605.md` を読む
- **THEN** 対象 3 件の PR 番号と、各件のテスト結果・ゲート指摘件数・トリップワイヤー発火の有無が元 / 新の別で並んだ表があり、`grep -cE '^\| *#[0-9]+'` が 3 以上を返す

#### Scenario: 新しいモデルで動いた証拠がある
- **WHEN** 記録の「Sonnet 5.5 で動いた証拠」を読む
- **THEN** 再実行の W の subagent jsonl に対する `grep -o '"model":"claude-sonnet-5-5"'` のコマンドと 1 件以上のヒット結果が書かれている

#### Scenario: 判定が規則どおりに書かれている
- **WHEN** 記録の判定を読む
- **THEN** 「表を変える」か「変えない」かと、3 件の比較結果から規則へ当てはめた根拠が書かれ、変えない場合は事前分類表が従来のままである
