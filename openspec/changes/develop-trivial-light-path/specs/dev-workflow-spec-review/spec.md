## ADDED Requirements

### Requirement: 些細な修正は軽い通し方で新しいテストと W の起動を省く
develop スキルは、仕様化判断が「しない」になる変更のうち、typo・lint 指摘の修正・コメントの修正・フォーマットの変更・ワンライナー fix・挙動を変えない設定値の変更のどれか 1 種類だけでできていて、既存のテストかチェックのコマンドで確かめられる変更に、新しいテストの作成と W の起動を省く通し方（以下「軽い通し方」）を持たなければならない（MUST）。記録先・仕様化判断の記録・pr-review-gate は省いてはならない（MUST NOT）。当てる条件・省くもの・残すものの正本は `references/decision-criteria.md` の Step B の小節に置き（MUST）、記録の書式の正本は `references/roles/spec-reviewer.md` の「判断記録の契約」に置く（MUST）。

#### Scenario: Step B に軽い通し方の小節がある
- **WHEN** `references/decision-criteria.md` の Step B を読む
- **THEN** 「仕様化しない（コード直行）」の小節と同じ並びに軽い通し方の小節があり、当てる条件（6 種類のどれか 1 つだけ・既存のテストかチェックで確かめられる）・省くもの（新しいテストの作成と W の起動）・残すもの（記録先・判断の記録・pr-review-gate）の 3 点が書かれている

#### Scenario: 6 種類に入らない「しない」の変更には当てない
- **WHEN** 変更が振る舞いの変わらない内部リファクタ、依存の版上げ、または受け入れ条件が明記された機械的な振る舞い変更である
- **THEN** 軽い通し方は当たらず、これまでどおり W を起こし、テストを書く

#### Scenario: 確かめる既存のチェックが無い変更には当てない
- **WHEN** 変更は typo の修正だけだが、変更を確かめる既存のテストもチェックのコマンドも無い
- **THEN** 軽い通し方は当たらず、これまでどおり W を起こし、テストを書く

### Requirement: テスト作成の必須の例外は軽い通し方だけにする
`references/decision-criteria.md` の「どの判定でも変えないもの」は、テスト作成が必須であることを残したうえで、例外が軽い通し方だけであることと、軽い通し方では `確かめ方:` の既存のテストかチェックを走らせることが新しいテストの代わりになることを書かなければならない（MUST）。W が起こされる経路では、どの判定でもテスト作成を省いてはならない（MUST NOT）。

#### Scenario: 必須の行に例外が書かれている
- **WHEN** `references/decision-criteria.md` の「どの判定でも変えないもの」を読む
- **THEN** 「テスト作成は全経路で必須」の文と同じ段落に、例外が軽い通し方だけであることと、`確かめ方:` のコマンドを走らせることが代わりになることが書かれている

### Requirement: 軽い通し方の判断は本体が判断のコメントの 2 行目以降に 3 行を足して記録する
軽い通し方では W が起こされないので、本体が仕様化判断を記録先に投稿しなければならない（MUST）。1 行目は `仕様化判断: しない` のまま変えてはならず（MUST NOT）、2 行目以降に `^通し方: 軽い$` に完全一致する行、`^種類: (typo|lint|コメント|フォーマット|ワンライナー fix|設定値)$` に完全一致する行、`^確かめ方: .+` に当たる行（変更を確かめる既存のテストかチェックのコマンド 1 つ）を 1 行ずつ書かなければならない（MUST）。本体は投稿する前に直してはならない（MUST NOT）。

#### Scenario: 判断記録の契約に軽い通し方の行の書式がある
- **WHEN** `references/roles/spec-reviewer.md` の「判断記録の契約」を読む
- **THEN** `通し方: 軽い` の行と `種類:` の行（6 つの値）と `確かめ方:` の行の書式が書かれ、この行がある判断は本体が投稿し、照合側（pr-review-gate の前提確認の段）が最新の仕様化判断のコメントの本文から読むことが書かれている

#### Scenario: 行の無い「しない」はこれまでどおり
- **WHEN** 記録先の最新の仕様化判断のコメントが `仕様化判断: しない` で、`通し方: 軽い` の行を持たない
- **THEN** これまでどおり W がテストを先に書いて実装する判断として扱う

### Requirement: 軽い通し方では本体が直し、仕様宣言までを行ってから G を起こす
軽い通し方では、本体は (1)〜(3) の W を起こさず、判断の記録のあとに自分で直し、`確かめ方:` のコマンドを走らせて終了コード 0 を確かめ、commit・push し、PR を Draft のまま用意し（issue が記録先なら `Closes #<issue>` を本文に書く）、仕様宣言を「変更なし＋理由」形で投稿してから (4) の G を起こさなければならない（MUST）。記録先が無いときは、判断の記録より先に Draft PR を記録先として作らなければならない（MUST）。手順の正本は `references/decision-criteria.md` の Step B の軽い通し方の小節に置く（MUST）。

#### Scenario: 本体の手順が書かれている
- **WHEN** `references/decision-criteria.md` の軽い通し方の小節を読む
- **THEN** 判断の記録・直す・`確かめ方:` のコマンドを走らせる・commit と push・Draft の PR・「変更なし＋理由」形の仕様宣言・G を起こす、の順の手順が書かれている

### Requirement: 軽い通し方を途中で外れたら W を起こして通常の通し方に戻す
本体が直す途中か確かめる途中で軽い通し方の条件を外れると分かったとき（2 種類以上が要る・挙動が変わる・`確かめ方:` のコマンドが 0 で終わらない・確かめる既存のチェックが無い）、本体は手を止め、ここまでの編集を commit してから W を `段: spec` で起こし、起動指示に外れた理由を書かなければならない（MUST）。W は `通し方:` の行の無い仕様化判断を投稿し直し、テストを書いて通常の通し方で進める（SHALL）。条件外と分かった記録先で `通し方: 軽い` を投稿し直してはならない（MUST NOT）。

#### Scenario: 確かめ方のコマンドが落ちた
- **WHEN** 本体が直したあと `確かめ方:` のコマンドを走らせ、終了コードが 0 でない
- **THEN** 本体は編集を commit して W を `段: spec` で起こし、W は `通し方:` の行の無い仕様化判断を投稿し直してテストを書く

### Requirement: 軽い通し方はどのモードでも同じ条件で当て、迷ったら当てない
本体は、W を `段: spec` で起こす前に、記録先の本文から軽い通し方を当てるかを決めなければならない（MUST）。当てるか迷ったら当ててはならず（MUST NOT）、これまでどおり W を起こす。当てるかどうかを主に聞いてはならない（MUST NOT）。interactive・channel・unmanned で同じ条件を使い（SHALL）、unmanned では本体が Draft PR の作成と `agent-review:pending` の付与を行う（SHALL）。

#### Scenario: 迷ったら W を起こす
- **WHEN** 本体が、変更が 6 種類のどれか 1 つに収まるか、既存のチェックで確かめられるかを決めきれない
- **THEN** 本体は主に聞かず、軽い通し方を当てずに W を `段: spec` で起こす

#### Scenario: unmanned でも同じ条件で当たる
- **WHEN** `references/decision-criteria.md` の軽い通し方の小節を読む
- **THEN** interactive・channel・unmanned で同じ条件を使うことと、unmanned では本体が Draft PR の作成と `agent-review:pending` の付与を行うことが書かれている
