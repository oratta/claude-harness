## Context

statusline.sh は登録簿を読む Python 片で `label` を表示幅 8 に切り（`MAX_LABEL_WIDTH`）、スロットごとの表示幅を bash に渡して名前の列を揃える。Codex の行は固定文字列 `Codex`（幅 5）を同じ列に載せている。登録簿に Codex のアカウント名は無い。

## Goals / Non-Goals

**Goals:** 名前を `Claude A` / `Claude B` / `Codex A` に揃える。長い名前でも見分けがつく。1 スロット以下のときの出力を変えない。

**Non-Goals:** Codex オフの行の廃止（#1112）、リセット権（#1115）、ダッシュボード側の名前。

## Decisions

### D1: 切り詰めはアカウント名の部分だけ。サービス名は常に残す

`MAX_LABEL_WIDTH = 8` は登録簿の `label` の規定（`usage-account-registry`）で、そのままアカウント名にだけ掛ける。名前は `サービス名 + " " + 切った label` で、最大 7 + 8 = 15 桁になる。

- 案 A（採用）: アカウント名だけ切る。`Claude A` は 8 桁ちょうどで上限に収まるが、上限を名前全体に掛けると `Claude 仕事`（11 桁）が `Claude 仕` と中途半端に切れ、どのアカウントか分からなくなる。サービス名が残れば、名前を揃える目的（Claude と Codex の行を見分ける）が長いラベルでも保たれる
- 案 B（不採用）: 名前全体を 8 桁に切る。登録簿の規定の読み方は単純だが、上の理由で見分けがつかなくなる。実際のラベルは `A` `B` のような 1〜2 文字が主で、列幅が 15 桁まで広がるのは長いラベルを自分で付けたときだけ

飲むリスク: 長い label を付けた利用者では名前の列が最大 15 桁になり、バーが右へ寄る。全行が同じ幅で揃うので崩れはしない。

### D2: 名前の組み立ては登録簿を読む Python 片の中で行う

Python 片は label の切り詰めと表示幅の計算を既にしている。ここで `Claude ` を前置し、その結果の表示幅を 5 列目として渡す。bash 側の列幅の計算（最大値を取る処理）は、渡された幅をそのまま使うので変えずに済む。スロットが 1 つのときは名前を出さない分岐が既にあるので、1 スロットの出力は変わらない。

### D3: `codex.label` は同じ Python 片が読む

`codex.label` を読む処理は登録簿を読む Python 片に足す（Python の起動を増やさない）。登録簿が無い場合の既定 `A` は bash 側で持つ。読み方は `usage-account-registry` の要件に従う（文字列・空でない・制御文字なし・表示幅 8 に切る。それ以外は `A`）。`statusline-codex.py` の `--read` の出力形式は変えない（`pending` / `off` / 行の形式が壊れると別 issue の範囲に触れるため）。

### D4: Codex の行の固定幅 5 を名前の幅に置き換える

`label_w` を 5 以上にする処理と、`Codex` + パディングの組み立てを、`Codex <label>` の表示幅を使う形にする。Codex の行が無いときは名前の幅に影響しない（出力を変えない）。

## Risks / Trade-offs

- 既存テストが固定文字列 `Codex` を期待している（`  Codex  off` など）。名前が `Codex A` になるので期待値を直す。オフの行の有無・文言（`off`）は変えない
- Codex の行だけがあってスロットが 1 つのとき、Claude の行には名前が付かず Codex の行だけ `Codex A` が付く。これは現行の `Codex` の行と同じ構図で、今回は変えない
