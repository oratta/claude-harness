## Context

`usage-probe.sh` は Anthropic の OAuth usage API を叩き、`parse()` が使用率だけを取り出して `~/.claude/.usage-snapshot`（schema 2）に書く。statusline は jq 1 回で snapshot を読む。Codex の行は `statusline-codex.py` のキャッシュを読み、`statusline.sh` の中で `リセットN回・最短あと…` を組み立てている。ダッシュボード（genetta-inc/flatmate#1654）は snapshot の `accounts.<id>.reset_grants` を読み、数え方（`paused` の束と `resets_left` が 0 の束を除く）は自分で行う。その形は issue #1115 のコメントで決まっている。

制約:
- 実機の応答をまだ誰も見ていない（調査 #1114 は Claude Code のバイナリ内の schema から形を読んだ）。形が合わないときは欄を出さないだけにする
- refresh_token は使わない（既存方針）。非 active アカウントは期限切れで取れないのが常態
- 429 の別枠を避けるため、呼び出し回数と User-Agent は今のまま

## Goals / Non-Goals

**Goals:** ダッシュボードが読む `reset_grants` 欄を契約どおりに書く。statusline の Claude の行に Codex と同じ見た目で出す。欄が無ければ出力が 1 バイトも変わらない。

**Non-Goals:** リセット権を使う操作（`reset_rate_limits`）を叩かない。トークンの更新をしない。ダッシュボード側の実装。`cedar_ember` の他の欄（`cooldown_until` など）を写さない。

## Decisions

### 1. 呼び出しは 1 回のまま、既定の URL にクエリを足す
`ENDPOINT` の既定を `…/api/oauth/usage?cedar_ember=1&skip_spend=1` にする。`USAGE_PROBE_ENDPOINT` で上書きできる点は変えない。代案は使用率用に今の URL、リセット権用に `cedar_ember=1` の 2 回呼ぶ形だが、スロットごとに呼び出しが倍になり 429 の連続を招きやすい。応答に使用率が残るかは未確認なので、残らなかった場合（`parse()` が使用率なしで失敗扱いにする）は、マージ前の実機確認で見つけて 2 回呼ぶ形に切り替える判断を別に行う。この change では 1 回呼びで進める。

### 2. `parse()` が `reset_grants` を返し、欄の寿命は呼び出し側で決める
`parse()` の戻り値に `reset_grants`（欄を出さないときはキー自体を入れない）を足す。写すのは `resets_left`・`ends_at`・`paused` の 3 つだけで、値は変えない。束が dict でなければその束だけ捨てる。条件（`cedar_ember` が dict、`eligible` が true、`grants` が list）を満たさなければ欄を出さない。`FIELDS`（前回値を引き継ぐ対象）には入れず、引き継ぎは明示的に書く。

欄の寿命は次の 3 通り。
| スロットの状態 | `reset_grants` |
|---|---|
| 取得に成功し、パースできた | 応答から作る（条件を満たさなければ欄なし） |
| 取得を試みて失敗した（`<id>.status` が残り、パースできない） | 欄なし。前回の値を写し直さない |
| 取得を試みなかった（間隔内・オフ。`<id>.status` が無い） | 前回の snapshot の値をそのまま保つ（他の項目と同じ。`fetched_at` が古いまま残るので読み手は鮮度が分かる） |

代案は「失敗も試みなしも欄なし」だが、probe は 3 時間に 1 回しか叩かず、1 スロットの取得のたびに他スロットの欄が消えてダッシュボードの表示が点滅する。「試みて失敗」だけを欄なしにするのは、ダッシュボードの契約（取得に失敗したとき前回の値を写し直さない）を守りつつ、これを避ける最小の切り分け。

### 3. statusline は snapshot の欄だけを読み、別のキャッシュを持たない
jq の 1 回の読み出しに、スロットごとの「残数」と「最短期限（epoch）」の 2 列を足す。jq の中で、`resets_left` が 0 より大きい整数で `paused` が true でない束だけを数え、残数は和、最短期限は `ends_at`（小数秒を落として epoch に直す。直せない値は期限なしの扱い）の最小値。有効な束が 1 つも無い場合: `grants` が空配列なら `リセット0回`、束があるのにすべて読めない・使えないなら残数 0 として扱わず区画を出さない（欠測を 0 回と扱わない、という Codex の規則と同じ）。欄が無い・配列でないときも区画を出さない。

代案は statusline 側にもキャッシュを持ち、取得に失敗したら前回の値に取得時刻を添える形（Codex と同じ）。しかし snapshot の欄は「失敗なら出さない」契約なので、この change では snapshot に出ている間だけ表示する。非 active のアカウントはすでに行末に snapshot の経過時間を併記しているので、古い値は経過時間付きで読める。取得に失敗して欄が消えた間は区画が消える（issue 本文の「取得に失敗したら前回の値に取得時刻を添える」からの意図的なずれ。これを飲めるかは本体が主に確かめる）。

### 4. 書式は関数に切り出し、Codex の行も同じ関数を使う
`fmt_reset_credits <残数> <最短期限 epoch または 0>` が、表示文字列と色（DIM / YELLOW / RED）を返す。`期限不明`・`期限経過（更新待ち）`・`あとXdYh`・`あとXhYm` と、24 時間以内は赤・3 日以内は黄の規則は、いま Codex の行の中にある分をそのまま移す。Codex の行の出力は変えない（既存のテストで固める）。

### 5. 置き場所は、そのアカウントの最後の行の末尾
7d の行があるアカウントはその行、5h の行だけのアカウントはその行の末尾。経過時間（`ago`）のあとに ` │ ` 区切りで付ける（Codex の行と同じ並び）。1 スロット構成でも同じ。

## Risks / Trade-offs

- 実応答の形が想定とずれていると、欄が出ない（区画が出ないだけで他は止まらない）。使用率が応答から消える場合は 1 回呼びが使えなくなる → マージ前に実機で確認する
- 取得失敗で欄が消えるあいだ、statusline の区画も消える（上の Decision 3）
