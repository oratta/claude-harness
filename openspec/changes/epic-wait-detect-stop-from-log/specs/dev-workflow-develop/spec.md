## ADDED Requirements

### Requirement: wait は子の会話ログから止まった子を検知する

`epic-dispatch.sh wait --watch-stopped` は、閉じていない位置引数の子のうち、記録の `status` が `done` でなく、記録の `worktree` の会話ログを読めて、次をすべて満たす子を止まった子としなければならない（MUST）。ターンが終わっているか未回答の質問ツールがある／最後の発言が子の発言である／その発言のあとに入力が無い／要件「wait は背景のタスクの有無で止まりとみなす待ち時間を変える」の時間を過ぎている。入力は主の発言と親の返事で、声かけの往復と背景のタスクの通知は数えない（MUST NOT）。判定に LLM を呼んではならない（MUST NOT）。この要件は、要件「epic-dispatch.sh は子が止まった印を付け、wait が止まった子を返す」のうち止まった子を印で決める規定に優先する。

この要件と、要件「wait は背景のタスクの有無で止まりとみなす待ち時間を変える」「wait は印の付いた子をターンの終わりまで待って返す」の守備範囲で入力として扱うのは、子の記録の `worktree` から引く `~/.claude/projects` 配下の `*.jsonl`（Claude Code が書く非公開の形式。発言と入力の判定からサブエージェントのログと `entrypoint` が `cli` でないものを除き、サブエージェントのログは最後の活動の時刻にだけ使う）である。拾いたい誤りは、記録も印も無い止まりを見逃すこと、背景のタスクの終わりを待つだけの子を止まりと数えること、同じ発言で二度判断することの 3 つである。次は通ってよく、この要件では止めない: 背景のタスクの実行中の人待ちが最大 `EPIC_DISPATCH_STOP_BG_IDLE_SEC` 秒遅れること（実測で約 2%）／権限確認の画面の止まり（会話ログに問いが残らない）／会話ログを読めない子（印と記録の経路に残る）／完了報告で止まった子が判断のモデルに回ること／背景のタスクの追跡が取れず「実行中」に残ること／子が質問で止まったあと背景のタスクの通知を受けて同じ問いを言い直すと、別の発言として判断され、主に同じ問いが二度上がること（通知は入力に数えないが、言い直しは新しい子の発言なので、要件「wait は止まりのあとの動きを再開として記録に書く」で `resumed` になり、次の止まりになる）。ログの形の変化や背景のタスクの追跡の穴を見つけるたびに塞ぎ切ることは、この要件の完了条件としない。

#### Scenario: 記録も印も無い子を止まった子として返す
- **WHEN** 子 11 が open で、記録の `stop` が空、子 issue に停止の記録が無く、会話ログの最後が子の質問でターンが終わり、背景のタスクが無く、最後の活動から 120 秒以上たった状態で `wait --interval 0 --timeout 60 --watch-stopped 11` を実行する
- **THEN** 記録の `stop` が `stopped-seen`、`stop_uuid` がその発言の uuid になり、stdout は `stopped 11`、exit 0 である

#### Scenario: ターンの途中の子は返さない
- **WHEN** 子 11 の会話ログの最後の子の発言のあとにターンの終わりの行が無く、未回答の質問ツールも無い
- **THEN** `wait` はその子を止まった子にしない

#### Scenario: 入力のあとの子は返さない
- **WHEN** 子 11 の会話ログで、最後の子の発言のあとに親の返事か主の発言がある
- **THEN** `wait` はその子を止まった子にしない

#### Scenario: 背景のタスクの通知は入力に数えない
- **WHEN** 子 11 の会話ログで、最後の子の発言のあとに背景のタスクの通知の行だけがあり、ほかの条件は満たす
- **THEN** `wait` はその子を止まった子にする

### Requirement: wait は背景のタスクの有無で止まりとみなす待ち時間を変える

`wait` は最後の活動（サブエージェントのログを含む）からの経過を測り、背景のタスクが実行中でなければ `EPIC_DISPATCH_STOP_IDLE_SEC`（既定 120）秒以上、実行中なら `EPIC_DISPATCH_STOP_BG_IDLE_SEC`（既定 1800）秒以上で止まりとみなさなければならない（MUST）。値が数字でなければ既定を使う（SHALL）。未回答の質問ツールがある子は待たずに止まりとみなす（MUST）。背景のタスクの起動と終わりは会話ログから読む（MUST）。

#### Scenario: 背景のタスクの実行中は長く待つ
- **WHEN** 子 11 の会話ログに終わっていない背景のタスクがあり、最後の活動から 600 秒たっている
- **THEN** `wait` はその子を止まった子にしない

#### Scenario: 背景のタスクの実行中でも長い待ち時間を過ぎれば返す
- **WHEN** 子 11 の会話ログに終わっていない背景のタスクがあり、最後の活動から 1800 秒以上たっている
- **THEN** `wait` はその子を止まった子にする

#### Scenario: 質問ツールの回答待ちは待たずに返す
- **WHEN** 子 11 の会話ログの最後が未回答の AskUserQuestion で、最後の活動から 10 秒である
- **THEN** `wait` はその子を止まった子にする

### Requirement: wait は印の付いた子をターンの終わりまで待って返す

`stop` が `stopped` の子の会話ログを読めるとき、`wait` は待ち時間と背景のタスクの条件を飛ばし、ターンが終わるか未回答の質問ツールが現れた時点で止まった子としなければならない（MUST。`mark stopped` は質問文より先に呼ばれるため）。最後の活動から `EPIC_DISPATCH_STOP_BG_IDLE_SEC` 秒を過ぎたらターンの終わりを待たずに返す（MUST）。会話ログを読めない子は今どおり印だけで返し、`stop_uuid` は空にする（MUST）。

#### Scenario: 印のあとターンの途中なら待つ
- **WHEN** 子 11 の `stop` が `stopped` で、会話ログのターンが終わっておらず、最後の活動から 30 秒である
- **THEN** `wait` はその子を止まった子にしない

#### Scenario: 会話ログを読めない印の子は今どおり返す
- **WHEN** 子 11 の `stop` が `stopped` で、会話ログの置き場が無い
- **THEN** 記録の `stop` が `stopped-seen`、`stop_uuid` が空になり、stdout は `stopped 11` である

### Requirement: wait は同じ発言を二度判断しない

`wait` は子を止まった子とするとき、判断の前に記録の `stop` を `stopped-seen` に、`stop_uuid` を最後の子の発言の uuid に、`stop_at` を今の時刻に書かなければならない（MUST）。`stop` が `stopped` でない子は、最後の子の発言の uuid が `stop_uuid` と同じなら止まった子にしてはならない（MUST NOT）。`stop_uuid` が空の `stopped-seen` の子は、会話ログを読めれば親を起こさず今の uuid を埋める（SHALL）。

#### Scenario: 問いではないと判断した発言で再び判断しない
- **WHEN** 子 11 の `stop` が `resumed`、`stop_uuid` が最後の子の発言の uuid で、ほかの条件は満たす
- **THEN** 判断のコマンドは呼ばれず、`wait` はその子を止まった子にしない

#### Scenario: 更新前の止まりは uuid を埋めるだけ
- **WHEN** 子 11 の `stop` が `stopped-seen`、`stop_uuid` が空で、会話ログを読める
- **THEN** 記録の `stop_uuid` が埋まり、`stopped 11` は出ない

### Requirement: wait は止まりのあとの動きを再開として記録に書く

`stop` が `stopped-seen` で `stop_uuid` のある子について、`wait` は位置引数の子と `--watch-done` の子の両方で、会話ログの最後の子の発言か最後の入力がその発言より後になったら、`stop` を `resumed` に書き、Orca の印へ写さなければならない（MUST）。声かけの往復は動きに数えない（MUST NOT）。親を起こしてはならない（MUST NOT）。子の `mark resumed` は残す（MUST）。

#### Scenario: 子の発言が進むと再開になる
- **WHEN** 子 11 の `stop` が `stopped-seen`、`stop_uuid` が `u1` で、会話ログに `u1` のあとの主の発言がある
- **THEN** 記録の `stop` が `resumed` になり、`stopped 11` は出ない

#### Scenario: 声かけの往復では再開にならない
- **WHEN** 子 11 の `stop` が `stopped-seen`、`stop_uuid` が `u1` で、`u1` のあとに固定文と型どおりの一行の返事だけがある
- **THEN** 記録の `stop` は `stopped-seen` のままである

### Requirement: wait・pending-owner・child-log は子の会話ログを同じ読み取りで読む

`wait`・`pending-owner`・`child-log` は、要件「child-log は最新の会話ログと子の発言を決まった規則で選ぶ」と「child-log は主の発言を決まった規則で判定する」の規則を 1 つの部品で読まなければならない（MUST）。部品は会話ログを書き換えず、LLM を呼ばない（MUST NOT）。`child-log <child>...` の 1 行の出力の形は変えてはならない（MUST NOT）。

#### Scenario: 既存の child-log の出力が変わらない
- **WHEN** 既存の `child-log` のテストを実行する
- **THEN** 出力の列と値は変わらず通る

### Requirement: child-log --last は親に最後の発言の全文を出す

`epic-dispatch.sh child-log --last <child>` は、最後の子の発言の全文（末尾を残し、上限は環境変数 `EPIC_DISPATCH_STOP_TEXT_MAX` の文字数）と uuid と時刻、未回答の質問ツールの問い、記録の `stop_uuid` を出さなければならない（MUST）。`EPIC_DISPATCH_STOP_TEXT_MAX` の既定は 8000 で、値が数字でなければ既定を使う（SHALL）。読めない子は `child-log` と同じく `unreadable` を出して exit 0 で終わる（MUST）。

#### Scenario: 親が全文を読める

- **THEN** 500 文字すべてと uuid が出る

### Requirement: 記録の無い止まりを主に上げるときは最後の発言から組み立てる

親は今回の停止の記録が無い止まりを主に上げるとき、`child-log --last` の全文を読み、`~/.claude/output-styles/readable.md` の節 3 の型で説明を組み立て、子の番号と発言の時刻を添えなければならない（MUST）。要件「親は主の答えに発言の場所を添えて送り、子は親の会話ログで確かめてからリスク許容として受け取る」の、本文に停止の記録の URL を書く規定は、記録のある止まりに限る。`stages/pass.md` の親経由の受領は変えない（MUST）。

### Requirement: 親の側は子の発言の本文を公開のコメントに載せない

`wait`・`stop-judge.sh`・親は、子の発言の本文を issue のコメントに自動で投稿してはならない（MUST NOT。公開の issue に作業中の内容が漏れるため）。記録の無い止まりの見分けには uuid だけを書く（MUST）。

- **THEN** 子 issue の `親の判断:` のコメントにその文字列は無く、`止まりの発言:` の uuid と `停止の記録: なし` がある

### Requirement: 親は問いでない止まりを dismiss で再開に戻す

`epic-dispatch.sh` はサブコマンド `dismiss <子>...` を持たなければならない（MUST）。親のセッションが、今回の停止の記録が無く最後の発言が主への問いでないと判断した止まりを、動いている子の状態に戻すために呼ぶ。子の記録は親の見張りの照合で探す（要件「子を owner/repo#番号 で識別し、同じリポジトリの子は番号だけで書く」。capability `dev-workflow-epic-state`）。各子について、排他の中で記録の `stop` が `stopped-seen` で `stop_uuid` が空でないことを確かめ、`stop` を `resumed` に書き、Orca の印へ写して `dismissed <N>` を出さなければならない（MUST）。`stop_uuid` と `stop_at` は変えてはならない（MUST NOT。同じ発言を二度判断しないため）。それ以外の子（記録が無い子を含む）は記録を変えずに `skipped <N> not-stopped` を出す（MUST）。読めない記録は `failed <N> state-unreadable`、照合で 2 件以上なら `failed <N> ambiguous-worktree`、排他が取れない・書けないなら `failed <N>` を出す（MUST）。`failed` が 1 件でもあれば exit 1、無ければ exit 0 で終わる（MUST）。子にも issue にも何も送ってはならない（MUST NOT）。

この要件の守備範囲で入力として扱うのは、親のセッションが渡す子の番号と子の記録で、会話ログは読まない（親は `child-log --last` で読んだあとに呼ぶ）。拾いたい誤りは、問いでないと判断した止まりが `stopped-seen` のまま残って、`infer_done` の完了の推定が止まり、声かけが送られ続け、`pending-owner` が同じ uuid を出し直すことと、子が印を付けた止まりを誤って戻すことの 2 つである。次は通ってよく、この要件では止めない: 親が主への問いを問いでないと誤って戻すこと（同じ発言では再び判断されず、主が気づくのは親の状態表になる）／`stop_uuid` が空の止まりが `skipped` で残ること（更新前の止まりか会話ログを読めない止まりで、今と同じ扱いになる）／`failed` で記録が残り、親の起動し直しで同じ止まりをもう一度判断すること。親が `dismiss` を呼び忘れる場面を見つけるたびに検査を足して塞ぎ切ることは、この要件の完了条件としない。

#### Scenario: 問いでない止まりを再開に戻す
- **WHEN** 子 11 の `stop` が `stopped-seen`、`stop_uuid` が `u1` で、親のワークツリーから `epic-dispatch.sh dismiss 11` を実行する
- **THEN** stdout は `dismissed 11`、exit 0 で、記録の `stop` が `resumed`、`stop_uuid` は `u1` のまま、Orca の印は `epic-resumed` で、子にも issue にも何も送られない

#### Scenario: 受けた止まりでない子は戻さない
- **WHEN** 子 11 の `stop` が `stopped`、子 12 の `stop` が `stopped-seen` で `stop_uuid` が空、子 13 の記録が無い状態で `epic-dispatch.sh dismiss 11 12 13` を実行する
- **THEN** stdout は `skipped 11 not-stopped`・`skipped 12 not-stopped`・`skipped 13 not-stopped`、exit 0 で、記録は変わらない

#### Scenario: 読めない記録は失敗にする
- **WHEN** 子 11 の記録の `stop` が `paused`（表に無い値）の状態で `epic-dispatch.sh dismiss 11` を実行する
- **THEN** stdout は `failed 11 state-unreadable`、exit 1 で、記録は変わらない

#### Scenario: 戻した子は同じ発言で判断されず、出し直されない
- **WHEN** `dismiss 11` のあと、最後の子の発言が `u1` のままで `wait --interval 0 --timeout 60 --watch-stopped --resolve 400 11` と `pending-owner 11` を実行する
- **THEN** 判断のコマンドは呼ばれず、`stopped 11` も `pending 11` も出ない

#### Scenario: 戻した子は完了の推定の対象に戻る
- **WHEN** `dismiss 11` のあと、子 11 が要件どおりの完了の推定の条件を満たした状態で `wait --watch-done 11` を実行する
- **THEN** `stop` が止まりの値でないので完了の推定が働き、`done 11` が出る

## MODIFIED Requirements

### Requirement: エピックの子は止まる前に記録と印を残し、親は stopped を受けて報告する
develop の `references/epic-child-stop.md` は、エピックの子のセッションが主の返事を待って止まるときの手順を、`references/epic.md` は、Orca 経路の親が `stopped` を受けたときの手順を規定しなければならない（MUST）。この要件は、要件「エピックの条件・作り方・回し方・完了条件を規定する」のうち、子が自分のタブでユーザーに質問して止まっている場合は親が気づけないと書く規定に優先する（要件「wait は子の会話ログから止まった子を検知する」で読めない止まりに限って気づけないと書く）。

**子の側**:

- 対象は `scripts/epic-dispatch.sh route`（子の番号なし）が `nested` を返すセッションに限る（MUST）。それ以外のセッションでは記録も印も付けない（MUST NOT）
- 主の返事を待って止まるときは、待ち方で順序を分ける（MUST）。どちらでも印を記録より先に付けてはならない（MUST NOT）
  - **本文で質問してターンを終えるとき**（`needs-approval` を付けた保留で、質問ツールを使わずにターンを終えるときを含む）: ターンを終える前に記録先の issue へ記録を 1 件投稿し、続けてそのターンの最後のツール呼び出しとして `scripts/epic-dispatch.sh mark stopped <記録先の issue 番号>` を呼ぶ。主の返事は次のターンで届くので、そのターンの最初のツール呼び出しとして `scripts/epic-dispatch.sh mark resumed <記録先の issue 番号>` を呼ぶ
  - **質問ツール（AskUserQuestion）の中で待つとき**: 質問ツールを呼ぶ前に記録を投稿し、続けて `mark stopped` を呼んでから質問ツールを呼ぶ。質問ツールは回答が来るまで同じターンの中で待つので、`mark stopped` は最後のツール呼び出しにならない。回答を受けたら、次のツール呼び出しとして `mark resumed` を呼ぶ
- 背景のタスクの終わりを待ってターンを終えるときは記録も印も付けない（MUST NOT）
- 記録は、1 行目を識別用の `^子の停止: 主の返事待ち$` に完全一致させ、2 行目以降は要件「エピックの子の停止の記録は、子の会話を読んでいない読み手が 1 通で読める形で書く」の項目名と並びで書く（MUST）。止まるたびに新しいコメントを投稿し、最新の 1 件を正とする（SHALL）
- 「保留で止まるときの引き継ぎ」を書く場面では、引き継ぎを先に投稿し、そのあとに記録を投稿して、再開に要る途中経過として引き継ぎのコメントの URL を書く（MUST）。引き継ぎの書式（1 行目 `引き継ぎ: 主の返事待ち`）は変えない
- `mark stopped` の出力が `marked` なら何もせず、`skipped` で始まる（`skipped <N> no-workspace`・`skipped <N> not-linked`）か `failed` なら、親が見張る記録に印が付いていないので主への質問に「親に止まったことが伝わっていない」と 1 行添える（SHALL）。`skipped` を何もしない側に置いてはならない（MUST NOT。子の状態の記録が無い・別の子の記録のときも親の `wait --watch-stopped` は止まりを読めず、主が子のタブを見るまで気づかないため）。`mark resumed` は出力によらず止まらない（SHALL）

**親の側（Orca 経路）**:

- 動いている子を待つ `wait` には `--watch-stopped` を付ける（MUST）

### Requirement: epic-dispatch.sh の wait は止まった子を判断し、通すものには返事を送って待ちを続ける
`plugins/dev-workflow/scripts/epic-dispatch.sh wait` は `--resolve <epic>` を受け付けなければならない（MUST）。`<epic>` が数字でなければ使い方を出して exit 1 で終わる（MUST）。`--resolve` は `--watch-stopped` と位置引数の子が 1 件以上あるときだけ働き（SHALL）、それ以外では何もしない。`--resolve` の有無で止まりの検知の条件は変えず、違うのは判断を呼ぶかどうかだけである（MUST）。

`--resolve <epic>` が働くとき、`wait` はポーリングで止まった子（既存の要件のとおり `epic-stopped-seen` に書き換えられた子）ごとに、次を行わなければならない（MUST）。

### Requirement: 子の声かけには最後のリクエストと停止期間の期限を適用する

判定の守備範囲は要件「子への声かけ文と返事の形は一か所の定義を共有する」の「判定要件に共通の守備範囲」に従う。

声かけは、子の最後の成功した CLI リクエストからの経過が 3000 秒以上かつ 3600 秒未満で、記録の `stop_at`（空なら同じ停止の記録の作成時刻）から 86400 秒未満のときだけ送らなければならない（MUST）。声かけや wait 掛け直しで停止の基点を延ばしてはならない（MUST NOT）。起動し直しの会話量条件に該当する子、時刻・会話量・現行セッションを判定できない子、前の声かけの返事が未着の子には送らない（MUST NOT）。

#### Scenario: 最後のキャッシュ読み出しをリクエストとして扱う
- **WHEN** 1h のキャッシュ書き込みは 2 時間前だが、現在の一意の CLI セッションの最後の有効な assistant usage は cache-read のみで 3000 秒前であり、他の条件も満たす
- **THEN** 固定文を送る。書き込みの時刻をリクエストの時刻として使わない

#### Scenario: 境界とスリープ復帰
- **WHEN** 他の条件を満たす子について最後のリクエストから 2999 秒・3000 秒・3599 秒・3600 秒、またはスリープ等で 1 時間を超える経過をそれぞれ用意する
- **THEN** 3000 秒・3599 秒の場合だけ送る。3600 秒以上では起動も声かけもせず、実際の返事時に #1323 の規則へ渡す

#### Scenario: 同じ停止の 24 時間を超えない
- **WHEN** 記録の `stop_at`（空なら最新の停止記録の作成時刻）が 86400 秒以上前で、直前の声かけの返事と wait の掛け直しは 3000 秒前である
- **THEN** 固定文を送らず、停止の印を保つ。停止から 86399 秒で他の条件を満たす場合は送る

#### Scenario: 多重送信と起動し直しを避ける
- **WHEN** 前の固定文にまだ返事が無い、または会話量が既存の起動し直し閾値以上である
- **THEN** 固定文を送らず、そのために新しいセッションを起動しない
