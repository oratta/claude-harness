## ADDED Requirements

### Requirement: 既存 issue の受け入れ条件を足す前に作業中かを確かめる

エージェントは、既存の issue の受け入れ条件を足す前に、その issue が作業中かを確かめなければならない（MUST）。確かめる材料は、`develop 開始` のコメントと、その issue に紐づく PR の 2 つとする。本文だけを読んで作業中でないと判断してはならない（MUST NOT）。別のリポジトリのセッションから足すときも同じである。

この決まりは常時注入の `rules/*.md` に置かなければならない（MUST）。足そうとする瞬間に手順書を読む判断はできないためである。

レビュー指摘の振り分け（`dev-workflow:pr-review-gate` の手順）で受け入れ条件に足す経路は、この要件の対象外とする。

#### Scenario: 本文だけでは作業中かが分からない

- **WHEN** エージェントが open の issue に受け入れ条件を足そうとし、本文には作業中である旨が書かれていない
- **THEN** エージェントは編集の前に、その issue のコメントと紐づく PR を確かめる

#### Scenario: 別のリポジトリのセッションから足す

- **WHEN** 別のリポジトリのエピックを回すセッションが、harness の issue に受け入れ条件を足そうとする
- **THEN** そのセッションにも `rules/*.md` の決まりが載っていて、対象のリポジトリを指定して同じ確認をする

#### Scenario: レビュー指摘の振り分けは対象外

- **WHEN** G が `dev-workflow:pr-review-gate` の振り分けの手順で、指摘を別の子 issue の受け入れ条件に足す
- **THEN** G はこの要件ではなく、その手順の決まりに従う

### Requirement: 作業中なら別 issue に切り出すのを既定にする

確かめた結果、issue が作業中なら、エージェントは足そうとした内容を別の issue に切り出さなければならない（MUST）。例外は、次の要件のとおり主の OK を得て同じ issue に足す場合だけである。切り出すことを主に聞いてはならない（MUST NOT）。

#### Scenario: 作業中の issue に足す内容が見つかった

- **WHEN** issue に `develop 開始` のコメントか、紐づく開いた PR がある
- **THEN** エージェントは元の issue の本文を編集せず、内容を新しい issue に起票し、URL を事後報告する

#### Scenario: 作業中でない

- **WHEN** issue に `develop 開始` のコメントも紐づく PR も無い
- **THEN** この要件は何も求めない。受け入れ条件を足すかどうかは、これまでの判断のとおりに決める

### Requirement: 作業中の issue に足すときは作業中と書いて主に聞く

作業中の issue にどうしても受け入れ条件を足すときは、エージェントは、作業中であること（PR があればその URL）を問いに書いて主の OK を得てから足さなければならない（MUST）。作業中であることを問いに書かずに得た OK で足してはならない（MUST NOT）。

主が作業中と知っていることが主の発言から分かるときは、聞き直さなくてよい（MAY）。

#### Scenario: 同じ issue に足したい

- **WHEN** エージェントが、切り出すより同じ issue に足すほうがよいと判断した
- **THEN** 主への問いに、その issue が作業中であることと PR の URL が書かれていて、主の OK の後に足す

#### Scenario: 主が作業中と知らずに足す指示を出した

- **WHEN** 主が issue に足すよう指示し、その issue が作業中で、主がそれを知っていると発言から分からない
- **THEN** エージェントは足す前に、作業中であることと PR の URL を書いて主に聞く
