## Context

cost-ledger の PostToolUse hook（`scripts/gate-report.sh` → `scripts/gate_report.py`）は、`gh pr comment` などのきっかけを Bash のコマンド文字列から見つけ、裏のプロセスで GitHub に問い合わせて、その PR / issue のコメントへコストの行を積む。いまの守りは 2 つある。

- 全体停止: `COST_LEDGER_GATE_REPORT=off`（`gate-report.sh` の先頭で抜ける）
- 対象のリポジトリが hook の `cwd` の origin（github.com）と一致しなければ書かない（`cost_ledger.py timeline --target-repo` が終了コード 3 を返す。対象の確認の `gh` 1 回は呼ばれる）

どちらも「このリポジトリには書いてよい」という利用者の意思を表さない。プラグインをユーザー全体に入れると、clone して作業した全部のリポジトリで行が付く。

制約:

- エピック #272 の「全体の制約」: LLM のトークンを使わない、hook は無出力、hook の所要時間と `gh` の回数を実測して PR に書く
- 同時に #691（`backfill.py` を足す）と #697（`gate_report.py` のきっかけの検出を触る）が動いている。`gate_report.py` の検出部分（`Lexer`・`find_triggers`・`build_job`）は触らない
- Claude Code は、作業中のリポジトリの `.claude/settings.json` の `env` に書かれた環境変数を、そのセッションの hook に渡す（実機では確かめていない未検証の前提。偽であっても設計は変わらない: 渡らないなら環境変数に一覧を書く案でも安全になるが、ファイルに置く案はどちらの場合でも安全で、issue の受け入れ条件がこの経路を名指ししているため、渡る前提で決める）。プラグインの userConfig の値も `CLAUDE_PLUGIN_OPTION_<名前>` という環境変数で hook に渡る

## Goals / Non-Goals

**Goals:**

- 一覧に載せたリポジトリにだけ書く。既定は書かない
- 一覧に無いリポジトリでは `gh` を 1 回も呼ばない
- 作業中のリポジトリの中のファイルだけでは有効にならない
- 判定を 1 つの関数にまとめ、後から入る書き込み経路も通せるようにする
- 既定（一覧が空）の利用者の hook を、いまより速くする

**Non-Goals:**

- `owner/*` のようなワイルドカード（組織ごとの許可）。issue は `owner/repo` の一覧としており、組織に後から足されたリポジトリが黙って対象になることを避ける
- github.com 以外のホスト
- 既に付いた行を自動で消すこと（README に手で行う手順を書く）
- `/cost` の表示と台帳への追記の制限（GitHub に何も書かない）
- 悪意のあるリポジトリからの防御全般。リポジトリの hook やスクリプトを実行できる相手は何でもできるので、防ぐのは「設定ファイルだけで自分を許可する」ことまで

## Decisions

### 決定 1: 一覧はリポジトリの外のテキストファイルに置く

- 場所: 既定 `$HOME/.config/cost-ledger/write-repos`。環境変数 `COST_LEDGER_WRITE_REPOS_FILE` が空でなければその値
- 書式: UTF-8 のテキスト。1 行に `owner/repo` を 1 つ。前後の空白は除く。空行と `#` で始まる行は読み飛ばす。`[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+` に全体が一致しない行（ホスト付き、ワイルドカード、URL）は、その行だけを無視する。照合は大文字と小文字を区別しない（GitHub のリポジトリ名と同じ）

検討した案と、採らなかった理由:

| 案 | 採らなかった理由 |
|---|---|
| 環境変数に一覧を書く（例 `COST_LEDGER_WRITE_REPOS=a/b,c/d`） | 作業中のリポジトリの `.claude/settings.json` の `env` で設定できる。clone しただけの他人のリポジトリが自分を許可できてしまい、issue の受け入れ条件「リポジトリの中のファイルだけでは有効にならない」を満たせない。hook からは、その環境変数を誰が設定したかを見分けられない |
| プラグインの userConfig に一覧を書く | hook には `CLAUDE_PLUGIN_OPTION_<名前>` という環境変数で届くので、上と同じ経路で設定できる。台帳のパス（`LEDGER_PATH`）が userConfig でよいのは、値が漏れても書き込み先が自分の手元のファイルに限られるからで、GitHub への書き込みの許可とは重みが違う |
| ファイルの場所を固定し、環境変数で変えられなくする | `$HOME` 自体が環境変数なので、固定しても同じ経路で差し替えられる。場所を縛るより、次の決定 2（ファイルがリポジトリの中なら無効）で一律に防ぐ。場所を変えられないと bats が利用者の実ファイルを読むことになる |

戻し方: 一覧をファイルから別の置き場所へ移すときは `write_allow.py` の読み込み部分だけを差し替える（呼び出し側は関数 1 つしか知らない）。許可の仕組み自体をやめるときは、この change の commit を revert する。

### 決定 2: 一覧のファイルが作業中のリポジトリの中にあれば、一覧を空として扱う

環境変数でファイルの場所を変えられるので、作業中のリポジトリが `COST_LEDGER_WRITE_REPOS_FILE` や `HOME` を自分の中のファイルへ向ければ、自分を許可できてしまう。これを防ぐため、一覧のファイルの実体（シンボリックリンクを解決したパス）が次のどちらかの配下にあるときは、一覧を空として扱う。

- hook の `cwd` から親へたどって最初に `.git`（ディレクトリでもファイルでも）が見つかるディレクトリ。見つからなければ `cwd` そのもの
- 環境変数 `CLAUDE_PROJECT_DIR`（プロジェクトの設定が読まれるディレクトリ）から同じようにたどったディレクトリ

`git` は起動せず、ディレクトリをたどるだけで判定する。加えて、ファイルが通常のファイルでない・持ち主が自分でない・自分以外が書ける、のどれかに当たるときも空として扱う（ロックの置き場と同じ基準。共有の一時ディレクトリに他の利用者が置いたファイルを一覧にしない）。

受け入れること: dotfiles のリポジトリで一覧のファイルを管理していて、その dotfiles のリポジトリの中で作業しているあいだは、そのリポジトリには行が付かない（ファイルの実体がリポジトリの中にあるため）。

残る穴: 作業中のリポジトリが、リポジトリの外に既にあるファイルで、たまたま `owner/repo` の形の行を持つものを指した場合は有効になる。リポジトリの中のファイルだけでは起こせない（外のファイルを誰かが用意する必要がある）ので、issue の条件の範囲外として塞がない。

### 決定 3: 判定は `scripts/write_allow.py` の 1 つの関数にまとめる

新しいファイル `plugins/cost-ledger/scripts/write_allow.py` に、次を置く。

- `allowed(repo, cwd)`: github.com の `owner/repo` に書いてよいかを返す。一覧の読み込み、決定 2 の検査、照合はこの関数の中だけで行う
- `origin_repo(cwd)`: `cwd` の origin の URL が github.com なら `owner/repo` を返す（`git remote get-url origin` を 1 回）

`gate_report.py` に書かず別のファイルにする理由は、#697 と #691 が `gate_report.py` を触っていて衝突を避けたいことと、`backfill.py` が `gate_report.py` を読み込まずに同じ関数を使えること。`cost_ledger.py`（12 万バイト）には入れない。読み込みに時間がかかり、判定のためだけに裏のプロセスの起動を遅くするため。

origin の URL の読み方は `cost_ledger.py` の `RepoResolver.origin()` と同じ 3 つの形（`https://`・`git@host:`・`ssh://`）を扱う。同じ規則が 2 か所に書かれることになるので、bats で 3 つの形について両方が同じ答えを返すことを固定する。

### 決定 4: 判定する場所は 3 か所

| 場所 | 何を見るか | 一覧に無いとき |
|---|---|---|
| `gate-report.sh` の先頭（全体停止の次、標準入力を読む前） | 一覧のファイルが無い・大きさ 0 か（`[ -s ]`。シンボリックリンクはたどる） | 標準入力を読まず、`python3` を起動せずに抜ける |
| `gate_report.py` の `work()` の先頭（`gh` を呼ぶ前） | `cwd` の origin のリポジトリが一覧にあるか。コマンドが名指ししたリポジトリ（`-R`、`GH_REPO=` の前置き、URL、`gh api` のパス）が一覧にあるか | origin が無ければ仕事全体を、名指しが無ければその対象を捨てる。`gh` は呼ばない |
| `work()` の対象の確認のあと（ロックと既存コメントの取得の前） | GitHub が返したリポジトリ名が一覧にあるか | その対象を捨てる。これ以降の `gh` は呼ばない |

`gate-report.sh` の検査は速くするためだけの近道で、判定そのものではない。ファイルが空でないことしか見ず、中身と決定 2 の検査は必ず `allowed()` が行う。近道が「空でない」と答えて `allowed()` が「空」と答える食い違い（コメントだけのファイル、リポジトリの中のファイル）は、書かない側に倒れる。

`cwd` の origin を全部の対象について見てよい理由: 既存の要件（`cost-ledger-timeline`「対象の解決」）が、対象のリポジトリが `cwd` の origin と違えば書かないと定めている。origin が一覧に無ければ、どの対象にも書かれないことが決まっているので、`gh` を呼ぶ前に抜けてよい。

同期部分（`build_job`）ではなく裏の処理（`work()`）の先頭に置く理由: 検出部分に手を入れずに済む（#697 と衝突しない）ことと、既存の要件「同期部分はコマンド文字列の判定だけを行う」を変えずに済むこと。代わりに、一覧が空でなく対象が一覧に無い呼び出しでは、何もせずに終わる裏のプロセスが 1 つ起きる（`gh` は呼ばない）。

3 か所目（GitHub が返した名前での再判定）を置く理由: リポジトリの改名や移管で、一覧にある古い名前への問い合わせが新しい名前のリポジトリへ転送されることがある。書き込み先は GitHub が返した名前なので、その名前で判定し直す。

### 決定 5: 全体停止 `COST_LEDGER_GATE_REPORT=off` が常に勝つ

評価の順は、全体停止 → 一覧のファイルが空か → きっかけの文字列の有無 → 検出 → 判定。off のときは一覧に載っていても書かず、一覧のファイルも読まない。全体停止は「一覧に何を書いていても今すぐ全部止める」ための手段として残す。主の環境の `COST_LEDGER_GATE_REPORT=off` は、この変更が入ったあとも効き続ける（外すかどうかは主が決める）。

### 決定 6: 既に付いた行を消す手順は README に書き、スクリプトにしない

リポジトリを公開する前などに、利用者が自分で一覧を見てから消す操作で、繰り返さない。目印（`<!-- cost-ledger:timeline` と、以前の `<!-- cost-ledger:gate-report -->`）を持つ自分のコメントを `gh api --paginate repos/<owner>/<repo>/issues/comments` で一覧し、id を指定して `gh api -X DELETE` で消す 2 段の手順にする。削除は取り消せないことと、通知メールで届いた分は消えないことを添える。

## Risks / Trade-offs

- **更新した直後に行が付かなくなる（確定している性質）** → README の先頭近くと `changes/775.md` に、一覧の作り方を書く。hook は無出力の決まりなので、会話の中では知らせない
- **`cwd` の origin 以外を `gh` が既定のリポジトリに選ぶ場合、一覧に無いリポジトリへ読み取りの問い合わせが 1 回飛ぶことがある** → 起きるのは、origin が一覧にあり、かつ `gh repo set-default` や引き継いだ環境変数 `GH_REPO` で `gh` の既定が origin 以外を指しているときだけ。その問い合わせ先は、利用者が直前に実行した `gh` のコマンド自身が向かった先と同じで、金額もトークン量も送らない。3 か所目の判定で書き込みは必ず止まる。`gh` の既定リポジトリの決め方を自前で再現すると検出部分が膨らむので、塞がない
- **origin の URL の読み方が 2 か所に書かれる** → 決定 3 の bats で食い違いを検出する
- **一覧の行の書き間違い（ホスト付きなど）は黙って無視される** → hook は無出力の決まりなので警告は出せない。README に書式と「行が付かないときに確かめること」を書く
- **所要時間** → 一覧が空の利用者は `python3` を起動しなくなるので速くなる。一覧がある利用者は、きっかけのある呼び出しの裏のプロセスで `git remote get-url` が 1 回増える（同期部分は変わらない）。どちらも実測して PR に書く

## Migration Plan

1. この change をマージする。マージした時点で、一覧を持たない全利用者の書き込みが止まる
2. 書き込みを続けたい利用者は `$HOME/.config/cost-ledger/write-repos` を作り、`owner/repo` を 1 行ずつ書く（README の手順）
3. 主の環境は `COST_LEDGER_GATE_REPORT=off` のままでも動く。行を再開するときは、一覧を作ってから off を外す（順番を逆にしても、一覧が無いあいだは書かれない）
4. #691 の `backfill.py` が先に main へ入っていれば、この change の実装で `allowed()` を通す。後から入るなら、`write-allow.bats` の「`gh` を呼ぶスクリプトは `write_allow` を読み込んでいる」検査が #691 の側で落ちて気づける

戻し方: この change の commit を revert すると、全リポジトリで書き込む元の動きに戻る。一覧のファイルは残っても読まれない。
