# 判例台帳

「観点の配役」フレームワークの判例台帳（git 追跡・追記型）。判例が積まれるほど、主に上げるべき論点は減っていく。

## 書式

1判例1ブロック。見出しは「日付＋論点1行」、本文は次の4フィールドを箇条書きで書く。

- **観点**: 観点カタログ（`~/.claude/plugins/marketplaces/*/plugins/casting/catalog/catalog.md`）にある観点名で書く。複数の観点が絡む判例は「、」で区切って並べる。当てはまる観点が無ければ「カタログ外」（観点追加の起案シグナルになる）
- **経路**: 「主に上げた」／「自走した」のどちらか
- **帰結**: 「論点だった」／「論点じゃなかった」＋一言の理由（判定基準＝主の視線が加わって結論が変わったか）
- **還元**: 配役既定表（project.md / local.md）のどこを変えたか。変更しなければ「なし」

新しい判例はファイル末尾に追記する。既存の判例は書き換えない。

### 2026-08-19 観点スペシャリスト/仲裁のサブエージェント構成 — 汎用2枚か観点別静的生成か（#127）

- 論点: スペシャリスト/仲裁の agent 定義を汎用2枚（casting-specialist / casting-arbiter）にするか、policy を持つ6観点ぶん静的生成するか

- 根拠: injection.md の人格規約（人格・判断基準は注入文書側に属する）と置き場所規約（プラグイン側はテンプレートと規約だけを持つ）、catalog.md 変更手続きの同期点最小方針。過去判例2件（2026-08-19 注入設計）の踏襲
- 判例リンク: 「2026-08-19 観点の注入設計（#122）」「2026-08-19 注入設計への主フィードバック」（本ブロックが「相談の上自走した」の初例）

### 2026-08-21 注記 — 上記「観点スペシャリスト/仲裁のサブエージェント構成」判例の位置づけ

上のブロック（2026-08-19・#127）はプロトコル確定前の dogfood 試行であり、事後報告フォーマット（5要素）の実例としては有効だが、**policy 提供経路は確定版規約の実例ではない**。試行時は「policy 文書が未整備のため、人格ブロックと判断基準はタスク文で仮与した」が、確定版の規約（SKILL.md の fail-closed 第3分岐・casting-specialist.md の「policy 不在は即返す」）では policy 不在の相談は合意にも仲裁にも進めず**主へ上げる**が正しい経路。将来のスペシャリスト起動時にこのブロックを過去判例として渡す場合は、本注記を併せて渡すこと。確定版規約に準拠した相談の実例は、この repo に `.claude/casting/policies/` が整備（判断基準の中身と人格の命名は主に属する）された後の最初の実相談で記録する。
