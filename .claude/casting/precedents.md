# 判例台帳

「観点の配役」フレームワークの判例台帳（git 追跡・追記型）。判例が積まれるほど、主に上げるべき論点は減っていく。

## 書式

1判例1ブロック。見出しは「日付＋論点1行」、本文は次の4フィールドを箇条書きで書く。

- **観点**: catalog.md にある観点名で書く。複数の観点が絡む判例は「、」で区切って並べる。当てはまる観点が無ければ「カタログ外」（観点追加の起案シグナルになる）
- **経路**: 「主に上げた」／「自走した」のどちらか
- **帰結**: 「論点だった」／「論点じゃなかった」＋一言の理由（判定基準＝主の視線が加わって結論が変わったか）
- **還元**: 配役既定表（project.md / local.md）のどこを変えたか。変更しなければ「なし」

新しい判例はファイル末尾に追記する。既存の判例は書き換えない。

## 記入例

### 2026-08-17 API の月額プランを Pro に上げるか

- 観点: 財務・コスト
- 経路: 主に上げた
- 帰結: 論点だった（月額差が閾値を超えており、予算方針文が未整備だったため）
- 還元: project.md の「財務・コスト」行に予算方針文の作成を課題として追記

### 2026-08-19 観点の注入設計（#122）— タイミング語彙8分類・injection.md 新設・カタログ列追加の見送り

- 観点: 技術設計・品質、事業方向性・戦略整合
- 経路: 主に上げた（語彙追加・置き場所・14観点の割当をドラフトとテストまで自走で固め、確定は PR #124 の主承認に回した）
- 帰結: 論点だった（casting の統治設計そのものは「主がいつ相談されるか」を決める自己統治物件であり、主の視線なしに確定してよい性質ではないため）
- 還元: なし（配役表の変更なし。注入設計の正本として catalog/injection.md を新設）
